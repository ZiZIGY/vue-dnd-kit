Статус: **утверждён мейнтейнером 24.10.2026, дополнен решениями от 25.10.2026 и 02.11.2026; 02.11.2026 сверен с кодом 3.0.0-beta.1 перед RC** (что изменилось — раздел 17, ревью API — `0002-api-review.md`). Основа — решения из Q&A от 24.10.2026 и три исследования в папке `0001-v3/`: `dnd-kit.md` (устройство dnd-kit), `virtualization.md` (TanStack Virtual и VueUse), `v2-parity.md` (инвентаризация v2: 24 пробела, 57 багов, ~30 расхождений документации с кодом). ## 0. Цели и не-цели

**Цели**
- Анимации по умолчанию: перестановка соседей, drop, возврат при отмене или отказе, сбор группы при множественном drag и посадка каждого её элемента в свой слот. Любую анимацию можно выключить или заменить функцией.
- Готовые решения для списков, канбана, сеток (в том числе с разными размерами), вложенных sortable, строк таблиц и деревьев. Плейсхолдер настраивается без ручного рендера.
- Работа с виртуализацией (TanStack Virtual, VueUse `useVirtualList`, любая библиотека со стабильными key), включая анимации.
- Производительность: 500 элементов без виртуализации при 60fps, 50k с виртуализацией.
- Доступность: клавиатура по элементам, ARIA-атрибуты, анонсы с позициями и с названиями (`label`).
- Надёжная машина состояний: у каждой сессии ровно одно завершающее событие (раздел 13).
- Собственный drag and drop браузера (HTML5) как drag провайдера: файлы, ссылки и текст из других приложений, вынос элементов за пределы страницы, перенос между окнами приложения (раздел 10.1). *Изменено 02.11.2026: было не-целью.*

**Не-цели 3.0**
- Старые браузеры (база: Chrome/Edge 104+, Safari 15.4+, Firefox 104+).
- iframe.
- Слой совместимости с v2: только migration guide.

## 1. Позиционирование относительно `@dnd-kit/vue`

У dnd-kit вышел официальный `@dnd-kit/vue@0.5.1`: тонкая обёртка над `@dnd-kit/dom`, 22.10.2026. Механизм сортировки у него тот же, что выбрали мы: реальная перестановка DOM и FLIP на `translate`. Чем v3 отличается:

| | `@dnd-kit/vue` 0.5 | vue-dnd-kit v3 |
|---|---|---|
| Множественный drag | нет | группа (список заранее показывает результат), пробелы или стопка; overlay со всеми элементами; анимации сбора, посадки и возврата; из нескольких списков сразу |
| Выделение рамкой | нет | есть |
| Канбан и дерево | примеры в сторибуке, логику пишет пользователь | `makeSortableList({ group })`, `makeSortableTree` из коробки |
| Применение результата | пользователь сам вызывает `move()` в `onDragOver` и `onDragEnd` | библиотека пишет в `Ref`, `onBeforeDrop` (async, частичный приём) |
| Копирование, swap, корзина, перетаскивание извне | вручную | опции списка |
| Виртуализация | пример с TanStack | контракт + `captureLayout`, `activeIndex`, тесты для TanStack и VueUse |
| Вложение в дереве наведением | нет | есть |
| API | обёртка над чужим ядром (классы, плагины) | Vue-нативные composables |

**Вопрос мейнтейнеру (Q1, закрыт: свой движок, раздел 16):** идём дальше своим движком (рекомендую: отличия выше и есть продукт) или делаем v3 слоем поверх `@dnd-kit/dom`? Второй вариант экономит движок, но привязывает нас к чужой 0.x-архитектуре. Например, их overlay поднимает реальный элемент в top layer через `popover`, а мы договорились о клоне.

## 2. Пакет, сборка, Nuxt

- Один пакет `@vue-dnd-kit/core`, один публичный entry, `"sideEffects": false`. Каждый composable и модификатор отрезается tree-shaking'ом. Второй вход `@vue-dnd-kit/core/devtools` — внутренний мост для плагина `@vue-dnd-kit/devtools`, версионируется вместе с ядром и может меняться в любом релизе. Рядом с ядром живут `@vue-dnd-kit/actions` (программные drag: кнопки, меню, тесты — через публичный API сенсоров), `@vue-dnd-kit/devtools` и `@vue-dnd-kit/nuxt`.
- Зависимости: `vue ^3.5` (peer), `@vueuse/core ^14 || ^15` (dependency, external в сборке).
- Форматы: ESM `.js` и CJS `.cjs` (в v2 CJS сломан: файл `.cjs.js` при `"type": "module"`). `exports` с `types`, `publint` и size-limit в CI.
- Без CSS-файлов и без внедрения CSS при импорте. Стили по умолчанию внедряются в рантайме при первом монтировании провайдера через `:where(...)`, то есть с нулевой специфичностью: любой пользовательский CSS их перебивает. На время drag `<html>` получает `data-dnd-dragging="pointer" | "keyboard"` вместо inline-стилей body. Состав:
  - внешний вид в каскадном слое `vue-dnd-kit` (объявлен первым, поэтому слабее слоёв страницы, Tailwind v4 и UI-китов): `opacity: .4` у `[data-dnd-placeholder]` и у оставленных на месте `[data-dnd-dragging]` (мульти-drag `gaps`);
  - поведение вне слоя, с `!important`: `user-select: none` и `overflow-anchor: none` на время drag, при pointer-drag — курсор `var(--dnd-cursor, grabbing)` и `-webkit-touch-callout: none`.

  Отключаются пропом `defaultStyles: false`, и внешний вид, и поведение (ревью A5/B10).
- Нет глобального состояния на уровне модуля: несколько провайдеров на странице работают независимо (в v2 общими были `originalUserSelect` и подобное).
- `packages/utilities` удаляется: привязка к сетке становится модификатором `snapToGrid`, причём от начала контейнера, а не от viewport, как было в v2.
- **Nuxt-модуль v3:**
  - Список экспортов становится статическим манифестом с тестом против `index.ts`. Сканирование собранного бандла через `mlly` сломается на чанках. В ядре такой список уже есть: значения и типы экспортируются по имени, и `types.test.ts` их фиксирует.
  - Регистрируются два компонента: `DnDProvider` и `DragPreview`. В v3 `DragPreview` — клон одного перетаскиваемого элемента для своих overlay (раздел 7), а не рендер overlay, как в v2.
  - Composables автоимпортируются, модификаторы — только опцией (`autoImports.modifiers`), потому что у них общие имена.
  - Типы — через type-импорты.
  - `injectionKey` не автоимпортируется. Пустой `plugin.client.ts` удаляется.
  - SSR-тест на отсутствие hydration mismatch с черновым `v-for`. Peer: `@vue-dnd-kit/core ^3`.

## 3. Архитектура

```
DnDProvider ── Manager (state machine, реестры по id)
   │             ├─ Sensors: pointer (mouse/touch/pen), keyboard; свои — defineSensor/useSensor
   │             ├─ Native bridge: собственный drag and drop браузера (HTML5) как drag провайдера
   │             ├─ Measuring: layout rect без transform/translate, кэш со scroll-delta
   │             ├─ Collision: pointer-first (elementFromPoint, shadow-aware) + приоритеты + защиты от осцилляции
   │             ├─ Accept: type / accept / acceptMode — единый матчер для зон, списков, выделения
   │             ├─ Modifiers → один transform и для overlay, и для collision
   │             ├─ AutoScroll: rAF, innermost-first, scrollBy
   │             ├─ Overlay: клон или слот, Teleport, drop/cancel-анимация
   │             ├─ Animator: FLIP-движок (WAAPI на translate), общий для всех слоёв
   │             └─ A11y: атрибуты, инструкции, live region, фокус
   ├─ makeDraggable / makeDroppable — низкий уровень, свободный drag (игры, зоны)
   ├─ Sortable: группы, черновики, стратегии, режимы, мульти-drag
   │    ├─ makeSortableList / makeSortableItem
   │    └─ makeSortableTree
   ├─ makeSelectionArea — выделение по id
   └─ makeDragArea — правила для drag, начатых внутри области (ось, модификаторы, активация, автоскролл)
```

**Машина состояний:** `idle → activating → dragging → dropping → idle`, плюс `selecting` для рамки.
- `activating`: ждём порог (дистанция или задержка), прогресс доступен для UI.
- `dropping`: ждём `onBeforeDrop` (async) или идёт анимация drop или возврата. Пока drop решается, ввод игнорируется, в том числе второй `pointerup`, Enter или новый `pointerdown`. Посадка overlay новый drag не держит: он стартует сразу, а нажатие на ещё садящийся overlay ловит его элемент в полёте. *Уточнено 02.11.2026: раньше ввод игнорировался до конца анимации.*
  - Пока async `onBeforeDrop` решает, ничего не изменилось: `over`, `isOver` и `isAccepting` остаются как при отпускании, правила приёма продолжают работать. Документ на время ожидания возвращается в обычное состояние (курсор, выделение текста), чтобы диалог подтверждения работал нормально.
  - Как только drop решён (коммит или отмена), состояние drag заканчивается: `over`, `pointer` и `useDnD().active` становятся `null`, правила приёма больше не вычисляются. Иначе UI, производный от drag, смешивал бы старое перетаскивание с уже изменёнными данными (колонка, заполненная до лимита, «отказывала» только что принятой карточке). Overlay и плейсхолдеры доигрывают анимацию; слот overlay получает цель, на которую садится (`over` на момент drop, при отмене `null`).
  - `onBeforeDrop` может ответить `'continue'`: drop не было, `dropping → dragging`, drag продолжается (мониторы получают `onDragResume`). Указатель несёт элемент без зажатой кнопки, следующее отпускание (клик) бросает; тач берёт его заново; клавиатура двигает как раньше. Остальные ответы: `'accept'`/`true`/ничего, `'reject'`/`false`, массив ключей.
  - `onDragSettle` (`@drag-settle`) сообщает, что overlay закончившегося drag сел (после drop-анимации или возврата при отмене); следующий drag к этому моменту уже может идти.

**Идентичность по id.** Активный элемент, выделение, черновики и анонсы живут по ключам, а не по DOM-узлам. Элемент может пересоздаться (переход между колонками, виртуализация), drag это переживает. Слушатели висят на `document`, pointer capture — на `body`.

## 4. Публичный API

### 4.1 Провайдер

```vue
<DnDProvider
  :collision="pointerFirst"
  :modifiers="[restrictToWindowEdges]"
  :animation="{ duration: 200, easing: 'cubic-bezier(0.25, 1, 0.5, 1)' }"  <!-- FLIP по умолчанию -->
  :drop-animation="{ duration: 250, easing: 'ease' }"   <!-- | false | (ctx) => Animation | Promise -->
  :auto-scroll="true"                                    <!-- | false | { threshold, maxSpeed, acceleration } -->
  :activation="{ mouse: { distance: 4 }, touch: { delay: 200, tolerance: 5 }, pen: { distance: 4 } }"
  :keyboard="{ keys: { start: ['Space','Enter'], drop: ['Space','Enter'], cancel: ['Escape'] }, step: 25 }"  <!-- | false -->
  :sensors="[pointerSensor, keyboardSensor]"             <!-- по умолчанию; свои — defineSensor -->
  :haptics="true"                                        <!-- | false | { start, enter, drop, refuse } -->
  :animate-changes="false"                               <!-- по умолчанию для списков: анимировать изменения данных -->
  copy-modifier="Alt"                                    <!-- null — выключить копирование клавишей -->
  overlay-to="body"
  overlay-fit="slot"                                     <!-- 'source' — overlay сохраняет размер исходника -->
  :overlay-previews="5"                                  <!-- | 'all' — сколько клонов снимать при мульти-drag -->
  :overlay-transition="true"                             <!-- | false | props <Transition> — смена компонента overlay -->
  overlay-class="lift"                                   <!-- классы [data-dnd-overlay-content] (раздел 7) -->
  :announcements="customAnnouncements"                   <!-- | false -->
  screen-reader-instructions="…"
  :default-styles="true"
  @drag-start @drag-move @drag-over @drag-end @drag-cancel @drag-settle
>
  <App />
  <template #overlay="{ active, items, over, accepted, status, mode, to }">
    <!-- items: [{ id, item, data, label, type }] — ветвление по типу; over/accepted — смена вида над зоной;
         to — куда drop положит элементы в списке или дереве ({ list, index, parentKey?, depth? } | null) -->
    <Card v-if="items.length === 1" :card="items[0].item" />
    <CardStack v-else :cards="items" />
  </template>
</DnDProvider>
```

У провайдера нет события `@drag-resume`, хотя у монитора `onDragResume` есть (ревью A3).

### 4.2 Низкий уровень и состояние

```ts
const { id, isDragging, transform, selected } = makeDraggable(elRef, {
  id: () => piece.id,            // MaybeRefOrGetter — важно для виртуализации; по умолчанию useId()
  data: () => piece,
  label: () => piece.name,       // что говорят анонсы вместо id («Picked up Tomato»); active.label
  type: 'piece',                 // string | string[]; не задан — подходит куда угодно (как groups: [] в v2)
  disabled: isLocked,            // плюс отключённая область makeDragArea
  handle: handleRef,             // ref или селектор
  activation: { mouse: { distance: 8 } },
  canDrag: (e) => e.shiftKey,    // drag только с зажатой клавишей (замена `modifier` из v2)
  overlay: true,                 // false — двигается сам элемент через `transform`; компонент — свой overlay
  dropAnimation: { duration: 300 },  // как садится overlay этого drag; у цели своя главнее
  modifiers: [restrictToParent], // для drag, начатых здесь; после модификаторов провайдера
  axis: 'y',                     // замок оси после модификаторов
  keyboardMode: 'pixels',        // свободный drag: стрелки по 25px; 'droppables' — переход между подходящими зонами
  attributes: true,              // role/tabindex/aria-*, не перезаписываем заданные пользователем
  native: true,                  // drag мышью — собственный drag браузера, может уйти за страницу (раздел 10.1)
});

const { isOver, isAccepting, placement } = makeDroppable(zoneRef, {
  id: 'trash',
  label: 'Trash',                // анонсы: «over Trash»; over.label
  accept: ['card'],              // | '*' | (ctx) => boolean — синхронно, вычисляется вживую
  acceptMode: 'all',             // 'some' — принять, если подходит хоть один элемент мульти-drag
  priority: 0,
  overOverlay: TrashOverlay,     // вид overlay, пока принятый drag над зоной (свой overlay drag — в слоте)
  overDropAnimation: false,      // как overlay садится сюда; главнее, чем у drag и провайдера
  external: { files: 'image/*' }, // drag извне страницы: файлы, ссылки, текст (раздел 10.1)
  onDragEnter, onDragLeave,
  onBeforeDrop: async (e) => true,   // 'reject'/false — отказ (анимированный возврат); Key[] — подмножество; 'continue'
  onDrop: (e) => e.source?.remove(), // корзина: удалить из исходного списка
});

const dnd = useDnD();  // shallowReadonly:
// status, active { id, ids, items, data, label, type, external?, native? }, over { id, data, label, accepted },
// pointer, position (левый верхний угол бокса в over: left/top для заметки на доске),
// activation { progress }, isAutoScrolling, selection, cancel()
// active/over/pointer — null, как только drop решён (раздел 3), хотя status ещё 'dropping'
useDnDMonitor({
  onDragStart, onDragMove, onDragOver,
  onBeforeDrop,                  // мониторы решают раньше цели: 'reject' отказывает, Key[] — подмножество
  onDragEnd,                     // после записи в Ref; DnDEndEvent { dropped, accepted, droppedOutside? }
  onDragCancel, onDragResume, onDragSettle,
});

// Shadow DOM и отдельные Vue-приложения под одним провайдером (было через injectionKey в v2).
// useDnDContext() возвращает непрозрачный DnDContext: его можно только передать дальше.
provideDnDContext(app, useDnDContext());
```

- **Реактивность опций.** Все опции, которые имеет смысл менять на лету (`activation`, `keyboardMode`, `attributes`, `handle`, `modifiers`, `axis`, `disabled`, `type`, `label`, `acceptMode`, `priority`, `external`, `native` и т. д.), принимают значение, ref или геттер и читаются, когда нужны. `overlay`, `overOverlay`, `dropAnimation`, `overDropAnimation`, `animation` и правила `accept` принимают значение или ref: функция там сама по себе допустимое значение. Опции-колбэки (`canDrag`, `onDrop` и т. п.) остаются функциями.

- **`label`.** Есть у draggable, зоны, sortable-элемента, списка и дерева. Стандартные анонсы говорят его вместо id: «Picked up Tomato at position 2 of 5 in Garden». В событиях он приходит как `active.label`, `items[].label`, `over.label`, а в контексте своих анонсов — как `position.label` списка. Без `label` анонсы говорят id, как раньше.

- **`makeDragArea(el, { axis, modifiers, restrictToArea, autoScroll, activation, disabled })`.** Правила для drag, которые начались внутри элемента (draggable и sortable-элементы), чтобы один провайдер обслуживал всё приложение, а доска, холст и лента тянулись каждая по-своему. Побеждает ближайшая область. Модификаторы области идут после провайдера и до своих модификаторов draggable (или списка); ось и `activation` draggable главнее. `disabled` действует и на вложенные области. Возвращает `isDragging` и `isAutoScrolling`.

- **Зона на sortable-элементе («положить внутрь», как папка в Finder).** `makeDroppable` на элементе списка (или внутри него) считается целью только в средней полосе элемента (25–75% по оси списка). Там drop уходит в зону, а список не переставляется. У краёв список сортирует как обычно. Зона, которая не принимает drag, игнорируется, и над элементом идёт сортировка. Отдельной опции нет. Списки и деревья, вложенные в элемент, остаются списками, а не целями «внутрь».

### 4.3 Сортировка

```ts
const {
  items,          // ComputedRef<T[]> — черновой порядок, рендерить именно его
  isOver, isAccepting, indicator,
  activeKey, activeIndex, activeSize,   // для виртуализаторов
  captureLayout,  // FLIP после перерасчётов, которые вызвала не библиотека (ResizeObserver виртуализатора)
} = makeSortableList(listRef, {
  items: tasks,                         // Ref<T[]> — библиотека запишет результат; или readonly-ref/геттер — тогда пишешь сам (preventDefault)
  getKey: (t) => t.id,                  // по умолчанию item.id
  filter: (t) => t.title.includes(query.value),  // показывать и сортировать только подходящие (ниже)
  id: 'todo',                           // по умолчанию useId()
  label: 'To do',                       // анонсы: «position 2 of 5 in To do»
  group: 'board',                       // | { name, pull: true | false | 'clone', put: true | false | (ctx) => boolean }
  acceptMode: 'all',                    // для мульти-drag из разных типов
  strategy: 'vertical',                 // 'horizontal' | 'grid' (разные размеры тоже)
  behavior: 'sort',                     // 'swap' — живой обмен, в т. ч. между списками группы (для мульти-drag отключён)
  placeholder: 'item',                  // 'indicator' — список не двигается, показываем линию
  multiple: 'group',                    // 'gaps' | 'stack' (раздел 5)
  overlay: TaskCard,                    // компонент overlay для элементов списка (свой overlay элемента главнее)
  overOverlay: DropHere,                // вид overlay, пока принятый drag (откуда угодно) над этим списком
  dropAnimation: { duration: 250 },     // как садится drag элементов этого списка
  overDropAnimation: undefined,         // как садится drag, брошенный в этот список; главнее
  modifiers: [restrictToVerticalAxis],  // для drag элементов списка; модификаторы элемента главнее
  axis: 'y',                            // замок оси для элементов списка, после модификаторов
  sort: true,                           // false — внутри списка не сортируется (палитра)
  clone: (t) => ({ ...t, id: uid() }),  // нужен для pull: 'clone' и копирования по Alt
  createItem: (active) => toTask(active.data),   // приём обычных draggable извне (и drag извне страницы); T | T[]
  external: { files: true },            // drag извне страницы (раздел 10.1), только вместе с createItem
  dropOutside: 'placeholder',           // 'cancel' | 'remove' — что делать при drop мимо всех зон
  animation: { duration: 200 },         // | false | функция
  animateChanges: true,                 // анимировать изменения items, которые сделал не drag (раздел 8)
  animateSize: true,                    // размер списка плавно следует за элементами (раздел 8)
  autoScroll: true,                     // переопределение для списка
  dropzone: columnRef,                  // элемент, который принимает drop за список (вся колонка вокруг короткого списка)
  disabled: false,                      // элементы не тянутся, и список не принимает drop
  onBeforeDrop: async (e) => e.rejected.length ? confirm('Часть не подходит, взять остальные?') : true,
  onDrop: (e) => api.move(e),           // до записи: в Ref старый порядок, новый — в e.result; e.preventDefault() — пишу сам
});
// Опции, кроме id, group и функций, принимают значение, ref или геттер; overlay, overOverlay, dropAnimation,
// overDropAnimation и animation — значение или ref.
// activation у списка нет: провайдер, область (makeDragArea) или элемент (ревью A11).

const { isDragging, isPlaceholder, selected, indicator, index } =
  makeSortableItem(itemRef, { item: () => props.task, label: () => props.task.title, handle: '.grip', type: 'task' });
  // item — ключ берётся через getKey списка; или id: () => props.task.id (id главнее).
  // Автоматического id у элементов нет: ключ обязан идти из данных, иначе перенос в
  // другой список или переиспользование строки виртуализатором потеряют элемент.
  // overlay, dropAnimation, modifiers, axis — как у списка, но для одного элемента;
  // canDrag, attributes, activation, native — как у makeDraggable.
  // indicator — объект { list, index, key, side: 'before' | 'after' | 'inside' | 'swap', depth?, parentKey? }
  // или null; depth и parentKey — в дереве; 'swap' — элемент, с которым drop обменяет перетаскиваемый.
```

- `group` в стиле SortableJS/vuedraggable, эти термины знакомы Vue-разработчикам:
  - строка — списки с одним именем обмениваются элементами;
  - `pull: 'clone'` — палитра;
  - `put` — функция приёма;
  - `type` элементов по умолчанию равен имени группы.
- `SortableDropEvent<T>`: `{ keys, items, accepted, rejected, from: { list, index }, to: { list, index }, sameList, mode: 'move' | 'copy' | 'swap' | 'insert', partner?, external? }`. `partner` (`{ key, item, from, to }`) есть у каждого swap: кто встал на место перетаскиваемого. `external` — данные drag извне страницы (раздел 10.1).
- **`filter`.** Список показывает и сортирует только элементы, для которых функция вернула `true` (поиск, тег); возвращаемые `items` содержат только их. Функция реактивна: то, что она читает (ref запроса), применяется сразу. Drop пишет весь массив: скрытый элемент остаётся после показанного, за которым шёл, а если тот переехал — после ближайшего оставшегося перед ним. `e.to.index`, `activeIndex` и `index` элемента считают только показанные. У дерева `filter` нет (ревью B9).
- **Контролируемый режим.** Порядок drop: `onBeforeDrop` (решает, может быть async) → `onDrop` (синхронно, данные ещё старые) → запись в `Ref` (действие по умолчанию) → анимация → `onDragEnd` мониторов. В событии есть:
  - `e.result` — новые массивы по каждому затронутому списку (`ReadonlyMap<Key, T[]>`): перенос, копия, созданный элемент, частичный приём, swap, дерево;
  - `e.preventDefault()` в любом из двух хуков отменяет запись во все затронутые списки, `e.defaultPrevented` это показывает.

  `items` может быть readonly-ref или геттером. Если такой источник не отменён, в dev-режиме будет предупреждение, и ничего не запишется. Если применить `e.result` в `onDrop` или до ответа async `onBeforeDrop`, overlay садится в новый порядок без мигания. Если отменить и не применить, элемент возвращается. Удаление (корзина, `dropOutside: 'remove'`) вызывает `onDrop` исходного списка с `to.index === -1`.
- **Только composables.** Как и в v2, на каждый элемент нужен свой компонент. Рецепт для v-for без отдельного компонента будет в документации. Список передаёт контекст элементам через `provide`. **Один компонент может создать несколько списков и деревьев** (например, все колонки канбана): элемент присоединяется к самому внутреннему из них, чей элемент содержит его элемент, а пока он не отрендерен — к первому. Выбрано вместо явного компонента-области; dev-предупреждение о двух списках в одном компоненте убрано. *Изменено 02.11.2026: было «конфликтуют, каждый список — в своём компоненте».*
- **Строки таблиц.** Список — `<tbody>`, элементы — `<tr>`. Клон `<tr>` в overlay оборачивается в `<table><tbody>` с шириной колонок.

### 4.6 Модификаторы и collision

```ts
import {
  restrictToVerticalAxis, restrictToHorizontalAxis,
  restrictToWindowEdges, restrictToParent, restrictToFirstScrollableAncestor, restrictToElement,
  snapToGrid, snapCenterToCursor,
  pointerFirst, pointerWithin, closestCenter, closestCorners, rectIntersection,
} from '@vue-dnd-kit/core';

snapToGrid(20)                                            // Math.round от начала контейнера
snapToGrid({ x: 20, y: 10, smooth: { duration: 80 } })   // плавный доезд overlay
snapToGrid({ y: 15 })                                     // одна ось: x свободен (время события в календаре)
snapToGrid({ x: 20, origin: 'delta' })                   // округляется смещение drag: элемент, начавший вне сетки, вне её и остаётся
```

`x` и `y` у `snapToGrid` необязательны: без размера (или с 0) drag по этой оси свободен. `origin: 'container'` (по умолчанию) кладёт левый верхний угол overlay на линии сетки от начала контейнера (`containerRect`: список или родитель), `'delta'` округляет смещение от старта. *Добавлено 02.11.2026.*

Модификаторы применяются один раз, и получившийся transform используется и overlay, и collision, поэтому они не расходятся. «Parent» означает контейнер списка, а не прямой DOM-родитель. Ось фиксируется относительно позиции на старте. В v2 она дрейфовала, потому что бралась от текущей позиции элемента.

- **Свои модификаторы у источника.** Кроме провайдера, `modifiers` есть у draggable, sortable-списка и элемента: они применяются к drag, начатым там, после модификаторов провайдера; модификаторы элемента главнее модификаторов списка. Так один вертикальный список на странице с канбаном держит элементы на оси, не заводя отдельный провайдер (который отрезал бы его от остальных списков). Значение, ref или геттер; читается в момент старта drag.
- **Порядок целиком:** модификаторы провайдера → области (`makeDragArea`) → источника (элемента, иначе списка) → `restrictToArea` области → замок `axis` (элемента, иначе списка, иначе области). `axis: 'x' | 'y'` — сахар для `restrictTo*Axis`, стоящий последним, поэтому держит ось, что бы ни делали остальные.
- `overlayRect` в аргументах модификатора — бокс overlay в том виде, как он показан, с текущим размером (раздел 7, `overlayFit`). `snapCenterToCursor` центрирует этот бокс.

## 5. Модель сортировки

1. **Старт.** Для группы создаются черновики (`shallowRef<Key[]>` на каждый список, новый массив на каждое изменение). Остальные выделенные элементы (в том числе из других списков) ведут себя по `multiple` списка, где начался drag:
   - `group` (по умолчанию): уходят со своих мест и встают вплотную к активному блоком плейсхолдеров в порядке drop (порядок документа). Пока идёт drag, список уже выглядит так, как после drop. Сами элементы FLIP'ом едут в блок.
   - `gaps`: остаются на местах (приглушённые, `data-dnd-dragging`) до drop, как в v2.
   - `stack`: убираются из черновиков, соседи схлопываются, а клоны элементов улетают в overlay (FLIP плюс fade).
   - В дереве убираются потомки активного узла. Мульти-drag в дереве — блок `group` с поддеревьями: выделенные узлы едут вместе с потомками и встают в одну точку на одну глубину, в порядке дерева. Выделенный потомок выделенного узла едет внутри него; если тянуть за такого потомка, он тоже остаётся внутри предка, как в VS Code. `maxDepth` считается по самому глубокому потомку всего блока, `canNest` должен принять каждого.
2. **Движение.**
   - Проекция индекса (раздел 6) меняет черновик не чаще раза за кадр. Блок `group` проецируется как один элемент.
   - Перенос между списками атомарно меняет оба черновика за один тик.
   - Если список не принимает элементы (`put`), он подсвечивается как `isAccepting: false`, и элемент в него не входит.
   - Частичный приём (`group.put` с `acceptMode: 'some'`) виден уже при наведении: в блок входят только принятые элементы, остальные возвращаются на свои места. Если список не берёт сам активный элемент, показывается полный блок.
3. **Drop.** Сначала `onBeforeDrop` мониторов пользователя, затем целевого списка или зоны. Возможные ответы:
   - `'accept'`, `true` или ничего;
   - `'reject'` или `false`;
   - массив ключей — частичный приём: принятые встают на место, отклонённые летят обратно;
   - `'continue'` — drop не было, drag продолжается (раздел 3);
   - `Promise` любого из них.

   Затем итог записывается в `Ref` каждого изменившегося списка, черновики сбрасываются. DOM совпадает с черновиком, поэтому лишнего движения нет. Overlay летит в итоговый слот, при необходимости меняя размер; при мульти-drag каждый клон в overlay садится в свой слот.
4. **Отказ, ошибка в колбэке (это тоже отказ, плюс `console.error`), cancel** (Escape, `pointercancel`, скрытие вкладки, размонтирование провайдера):
   - черновики откатываются, соседи FLIP'ом возвращаются;
   - overlay летит на исходное место, клоны остальных элементов — на свои;
   - в режиме `stack` собранные элементы вылетают из overlay обратно на свои места.

   **Изменение по сравнению с v2:** там `false` из async `onDrop` оставлял элемент «в руке» до следующего клика.
5. **Drop мимо всех зон** решается опцией `dropOutside`:
   - `placeholder` (по умолчанию в режиме `item`, как в Trello): элемент кладётся туда, где стоит плейсхолдер;
   - `cancel` (по умолчанию в режиме `indicator`);
   - `remove`.
6. **Корзина и зоны «внутрь».** `e.source.remove()` в `onDrop` чужой зоны удаляет элементы из исходного `Ref` (при частичном приёме — только принятые). Сами принятые ключи `onDrop` обычной зоны сейчас не получает: в его `DnDEvent` нет `accepted`/`rejected`, а `e.active.items` — весь drag; подмножество есть только в `DnDEndEvent.accepted` мониторов. Форма исправления — решение мейнтейнера (ревью A2, рекомендован `accepted`/`rejected` в событии, как у списка). Overlay втягивается в зону и гаснет. Drop в зону на sortable-элементе работает так же: список не переставляется, элементы уходят в зону.
7. **Копирование.** Источник не меняется. В цель вставляется `clone(item)`; пока идёт drag, в черновике цели виден временный ключ. Включается через `pull: 'clone'` или клавишей `copyModifier` (по умолчанию Alt). Модификатор читается вживую во время drag, и плейсхолдер переключается между перемещением и копией. В дереве `clone(node)` возвращает копию со всем поддеревом, ключи копий берутся через `getKey`. Наведение на собственный оригинал не кладёт копию внутрь него.
8. **Извне.** Обычный draggable над списком или деревом с `createItem` получает временный элемент в черновике (в дереве — узел на спроецированной глубине), он рендерится шаблоном пользователя как плейсхолдер. На drop элемент становится настоящим. `activeKey`/`activeIndex` списка указывают на этот временный элемент (и на копию при копировании), а стрелки двигают его по слотам списка, как обычный элемент. Стрелка снаружи в сторону списка входит в него на уровне drag (то же правило, что при переносе между списками); если списка в этом направлении нет, у draggable остаются свои шаги клавиатуры. Фокус остаётся на draggable. Так же, через `createItem`, список берёт drag извне страницы, а элементы своей группы из другого окна — как свои (раздел 10.1).

Порядок вставки при множественном drag — исходный порядок в документе, а не порядок кликов (у dnd-kit в этом месте баг).

## 6. Стратегии и стабильность

**Общие защиты** (по опыту next-gen dnd-kit):
- Цель пересчитывается только при движении указателя или скролле, никогда из-за одного лишь сдвига layout.
- После перестановки целью считается сам активный слот.
- Гистерезис около 10px: недавно бывший целью элемент не может снова стать целью, пока указатель не сдвинется на 10px.
- Охранник «только что перенесли в другой список» на один кадр плюс «последняя валидная цель».
- Для hit-test берутся только смонтированные элементы, с прямоугольниками, обрезанными видимой областью их скролл-предков. Overscan-строки за краем не попадают. Пустой список — полноценная зона; в v2 пустые зоны никогда не считались видимыми.
- Регрессия v2.4.5 («уход курсора вбок телепортирует элемент в начало или конец списка») закреплена тестом: ближайший элемент ищется по расстоянию до прямоугольника.

**Стратегии:**
- **`vertical` / `horizontal`.** Правило пересечения середины по направлению движения: вниз — указатель ниже центра цели, вверх — выше. Устойчиво при разных размерах: после сдвига центр соседа уходит от указателя.
  - Кадры бывают редкими (быстрый свайп, загруженный поток, WebKit склеивает ввод), и указатель перескакивает элементы. Слот всё равно догоняет: он встаёт рядом с элементом под указателем, с той стороны его центра, где указатель.
  - Указатель в промежутке между двумя элементами того же списка (по главной оси) ставит слот между ними: он уже за центрами обоих. Промежутки рядом с активным слотом или блоком группы и место за смонтированными элементами (виртуализация) позицию не меняют.
- **`grid`.** Элемент под указателем плюс замок на элементе, который только что съехал (снимается, когда указатель его покидает). Работает и для разных размеров. Пустое место после последнего элемента означает «в конец».
- **`swap`.** Живой обмен активного с элементом под указателем, остальные стоят. Ушли с элемента — обмен откатывается. Для мульти-drag отключён (в v2 был групповой обмен, проходит в migration guide).
  - Между двумя списками одной группы, если у обоих `behavior: 'swap'`: партнёр переезжает на исходное место перетаскиваемого в другом списке. Правила проверяются в обе стороны: `put` цели принимает перетаскиваемый элемент, `pull` списка партнёра равен `true`, а `put` исходного списка принимает партнёра. Отказанный партнёр не меняется, а наведение на него отменяет уже сделанный обмен.
  - Сортирующий список, перетаскиваемый в swap-список, вставляет как обычно. Пустой swap-список ничего не делает.
- **Зоны на элементах** (раздел 4.2). Цель «внутрь» действует только в средней полосе элемента. Пока указатель в ней, ничего не переставляется. В сетке края элемента-цели ставят перетаскиваемый до или после него, а не занимают его ячейку, иначе цель уезжала бы от указателя. Блок мульти-drag не обгоняет указатель на таких элементах.
- **Вложенные sortable** (колонки канбана):
  - побеждает самый глубокий список;
  - у элементов приоритет выше, чем у контейнеров;
  - над непустым контейнером выбирается ближайший элемент, над пустым — вставка в начало или конец по середине.
- **Дерево.**
  - Глубина = `round(offsetX / indentation)` в пределах от глубины следующего элемента до глубины предыдущего + 1.
  - При `nesting: 'hover'` средняя полоса строки (25–75% высоты) означает «внутрь», края — до или после.
  - `canNest` и `maxDepth` понижают глубину до допустимой.
  - Блок мульти-drag проецируется как одна строка, на одну глубину; ограничения применяются ко всему блоку.
  - В режиме `indicator` дерево не двигается. Линия встаёт до или после строки под указателем на спроецированной глубине. Середина подходящей папки даёт `side: 'inside'`. Над перетаскиваемыми строками и их поддеревьями линии нет.

## 7. Плейсхолдер и overlay

- **`placeholder: 'item'`.** Активный элемент остаётся в списке с атрибутом `data-dnd-placeholder`. По умолчанию `:where([data-dnd-placeholder]) { opacity: .4 }`. Варианты:
  - пустое место: `visibility: hidden` в CSS;
  - свой компонент: `v-if="isPlaceholder"` внутри элемента;
  - линия: свой узкий плейсхолдер.

  Пока drop уходит в цель внутри элемента (зона «внутрь», папка в сетке файлов), слот только держит место рядом с ней, и атрибут равен `data-dnd-placeholder="into"`: такой слот можно стилизовать отдельно. *Добавлено 02.11.2026.*
- **`placeholder: 'indicator'`.** Список (или дерево) не двигается. Для линии есть `indicator`: на списке `{ list, key, index, side }`, на элементе тот же объект, если линия у него. `side` — `'before' | 'after' | 'inside' | 'swap'` (`'swap'` в списке с `behavior: 'swap'`: отметить сам элемент, с которым будет обмен), в дереве ещё `depth` и `parentKey`, чтобы начать линию с отступа нужной глубины. Линию рисует пользователь, как и плейсхолдер. `placement` на зонах служит для своих индикаторов при свободном drag. Можно не рендерить ничего.
- **Overlay.** Teleport в `overlayTo` (по умолчанию `body`), потому что `transform` строки или `contain` скроллера ломают `position: fixed`. `pointer-events: none`.
  - **Устройство.** Бокс `[data-dnd-overlay]` двигает и меняет в размере библиотека; атрибут говорит, что бокс делает: `dragging`, затем `dropping` (садится или ждёт async `onBeforeDrop`). Внутри — элемент содержимого `[data-dnd-overlay-content]`, заполняющий бокс: его анимирует страница целиком (подъём, наклон, тень). Классы для него — проп провайдера `overlayClass` (строка, объект или массив, как `class`). Переход на нём проигрывается от `@starting-style` при взятии и обратно при посадке (`[data-dnd-overlay='dropping']`), и drop ждёт, пока анимации содержимого закончатся. Обычный CSS достаёт его вне `<style scoped>` (или через `:global(...)`), Tailwind — через `starting:` и `in-data-[dnd-overlay=dragging]:`. Боксы посадки устроены так же: бокс drag продолжает жить как бокс своей посадки, поэтому его содержимое садится в том состоянии, в каком было. *Добавлено 02.11.2026.*
  - Клон снимается синхронно при старте, до перерисовки плейсхолдера, через `cloneNode(true)`, а не `outerHTML`, как было в v2.
  - Гигиена клона:
    - копируются `value` полей ввода и содержимое canvas;
    - у radio переименовываются `name`, удаляются `id` и `data-dnd-*`;
    - не копируются эффекты нажатия UI-китов (ripple Vuetify и Quasar, ink PrimeVue, wave Naive UI) и любые элементы с `data-dnd-no-clone`;
    - переносятся наследуемые стили (font, color, line-height) и фон. CSS custom properties, которые элемент наследует, ставятся на обёртку вокруг клона, а не на сам клон: inline на клоне они перебили бы правила страницы для него в overlay (Tailwind `--tw-ring-shadow` из `in-data-[dnd-overlay]:ring-2`). *Изменено 02.11.2026: раньше копировались на сам клон;*
    - у sortable-элемента без собственного фона клон берёт первый непрозрачный фон предка (строки `v-list`, `v-data-table`, `UTable` иначе просвечивают); у свободных draggable так не делается, чтобы иконки и PNG не получали подложку;
    - `<tr>` оборачивается в таблицу.
  - Клон заполняет бокс overlay (100%), поэтому смена размера бокса перекладывает содержимое, а не растягивает его.
  - **Свой overlay.** По приоритету: компонент `overlay` элемента, затем списка или дерева, затем слот `#overlay` провайдера, затем клон. Слот, который для этого drag ничего не рендерит (`v-if` по типу), отдаёт место клону. Компонент получает `OverlayProps` — те же `{ active, items, over, accepted, status, mode, to }`; необъявленные пропсы не проваливаются в корень как атрибуты. Через них можно ветвить вид по типу элемента и менять вид над зоной. Свой overlay обязателен для канбана и виртуализации, где исходник может размонтироваться.
  - **Overlay цели.** Пока принятый drag над зоной, списком или деревом с `overOverlay`, overlay показывает компонент цели, а собственный overlay drag получает слотом по умолчанию: обернуть или убрать (`<slot />`). Он остаётся, пока drop садится сюда. Смена компонента посреди drag (цель, переключённый ref) анимируется пропом провайдера `overlayTransition`: по умолчанию кроссфейд 150 мс, `false` — сразу, объект — пропсы `<Transition>`.
  - Пока решённый drop анимируется, `over`/`accepted` в слоте — цель, на которую overlay садится (на момент drop); при отмене `null`.
  - **`overlayFit`.** По умолчанию `'slot'`: бокс принимает размер слота, куда сядет элемент (список с другими размерами элементов), и плавно меняет его за 150 мс прямо в цикле кадров, так что collision и модификаторы всегда видят показанный бокс. Бокс меняет размер вокруг точки захвата: доля, в которой указатель держит бокс, фиксируется на первом кадре, и курсор никогда не оказывается за пределами бокса. `'source'` — размер исходника.
  - **Мульти-drag.** В режимах `group` и `gaps` overlay показывает все элементы колонкой вдоль оси списка (в горизонтальном списке и сетке — рядом), с `gap` списка. Бокс остаётся размером активного элемента, остальные клоны стоят рядом с ним, поэтому точка захвата относится к активному. Клонов не больше `overlayPreviews` (по умолчанию 5, `'all'` — все отрендеренные): активный и ближайшие в порядке drop; остальные считаются бейджем «+N». В режиме `stack` — активный элемент с бейджем-счётчиком. У свободных draggable мульти-drag показывается стопкой: активный сверху, до трёх под ним, счётчик.
  - **`DragPreview`.** Компонент `<DragPreview :id="item.id" />` рендерит клон любого перетаскиваемого элемента внутри своего overlay: так строятся свои раскладки (веер, сетка). Для элементов без клона рендерится слот по умолчанию.

## 8. Анимации

- **FLIP-движок**, общий для всех слоёв:
  1. Снимок визуальных прямоугольников по ключу (pre-flush, с учётом идущей анимации).
  2. После post-flush: отменить свои анимации и CSS-переходы `transform`/`translate`, разом прочитать layout, затем WAAPI `translate: dx dy → 0`.
  3. Прерванная анимация стартует с текущей позиции.

  Анимируются только элементы, чей прямоугольник изменился и которые рядом с viewport. При `prefers-reduced-motion` длительность 0.
  Элемент, въезжающий из другого списка (откат swap, возврат), не ловит указатель, пока не встанет на место: иначе hit-test находил его на чужой территории.
- **Drop.** Целевой элемент измеряется после коммита и `nextTick` и ещё раз через кадр: ResizeObserver виртуализатора может прийти позже. Его нет или он невидим — fade-out; если drop ушёл в зону, а не в список (корзина, «внутрь элемента»), overlay втягивается в неё (`DropAnimationContext.into`). Без `scrollIntoView` и без фокуса без `preventScroll`; dnd-kit с виртуальными списками на этом спотыкался.
  - Размер анимируется через width/height, никогда через `scale()`: содержимое перекладывается под новый размер, а не растягивается.
  - Мульти-drag: каждый клон в overlay анимируется относительно бокса с тем же таймингом и садится ровно в свой слот (вертикаль, горизонталь, сетка, другой список). Элементы без клона (сверх лимита, свой overlay) проявляются на месте из приглушённого состояния, а не выскакивают.
  - Сессия не может застрять в `dropping`: ожидание кадра ограничено 100 мс (кадров нет в скрытой вкладке и на перегруженном компоновщике), анимация — длительностью плюс 1 с.
  - Какая `dropAnimation` играет: цели, куда бросили (`overDropAnimation` зоны, списка или дерева), затем самого drag (элемента, иначе его списка; `dropAnimation` draggable), затем провайдера. `false` у цели оставляет overlay там, где его бросили: свою анимацию играет компонент overlay.
- **Сбор группы.** При старте `group` остальные элементы FLIP'ом едут в блок, а их клоны собираются в колонку overlay.
- **Появление и исчезновение:** fade-in для элементов, смонтированных в результате DnD-изменения (возврат группы, копия); scale + fade для удаления в корзину.
- **Изменения данных без drag (`animateChanges`).** У списка и дерева (по умолчанию — проп провайдера `animateChanges`, выключен): элементы, добавленные, удалённые, переставленные (сортировка, перемешивание, перенос между списками группы) или скрытые фильтром и свёрнутым узлом, анимируются. `true` — стандартно: перестановка FLIP'ом, появление fade-in, уход — копия элемента гаснет на старом месте. Объект `{ duration, easing, move, enter, leave }` настраивает или заменяет каждую часть функцией. Анимируются только элементы у видимой области.
- **Размер списка (`animateSize`, по умолчанию `true`).** Когда drag вносит в список элемент или забирает его (и на drop, и для изменений, которые показывает `animateChanges`), список плавно меняет width/height до нового размера с таймингом своей `animation`, а не прыгает; соседний layout едет вместе с ним (элементы внешнего списка в том числе). `false` — прыгает. `animation: false` выключает и это. *Добавлено 02.11.2026.*
- **Плавный snap:** короткая WAAPI-ступенька overlay между позициями сетки, collision работает по уже привязанному значению.
- **Своя анимация:** любой `animation` и `dropAnimation` принимает функцию `(ctx) => Animation | Promise<void> | void`. В контексте FLIP есть `reason` (`'drag'` или `'change'`) и `signal` (прерывание), у drop — `reason: 'drop' | 'cancel'` и `into`; у всех — `reducedMotion`: при `prefers-reduced-motion` свои функции всё равно вызываются и решают сами. В документации будет рецепт для motion-v.

## 9. Виртуализация (контракт)

**Библиотека:**
- Черновик — всегда новый массив; переносы между списками атомарны.
- Идентичность только по `getKey`; `makeSortableItem({ id })` принимает getter.
- Интерруптибельный FLIP и `captureLayout()`. Пока ничего не происходит, он ничего не стоит.
- Цели FLIP и drop перепроверяются 1–2 кадра.
- Размонтирование активного или исходного элемента — штатная ситуация.
- Overlay в `body`.
- Автоскролл только относительными шагами (`scrollBy`). Во время drag на затронутых скроллерах `overflow-anchor: none`.
- `activeKey`, `activeIndex`, `activeSize` на каждом списке. `activeIndex` указывает на захваченный элемент, а в списке с копией или временным элементом — на них. Члены блока `group`, которые не отрендерены, всё равно едут вместе с ним.
- Опциональные хуки адаптера: `scrollToKey(key)` (клавиатура), `getVirtualRect(key)` (цель drop вне DOM).

**Пользователь:**
- Рендерит черновик `items` везде, в том числе в `count` и `getItemKey`.
- Ключует строки по id, а не по индексу. Обе документации, TanStack и VueUse, показывают индекс — это ловушка.
- TanStack: опции передаются как `computed`, который один раз читает `items.value` и создаёт внутри замыкания `getItemKey` и `rangeExtractor` (закрепление активной строки). Плюс `onChange: () => captureLayout()`. Без этого TanStack после перестановки отдаёт устаревшие позиции: проверено экспериментом.
- Overscan ≥ 5. Плейсхолдер того же размера, что элемент (для VueUse `itemHeight` должен быть точным).

Виртуальные компоненты UI-китов (`v-virtual-scroll`, `v-data-table-virtual`, `UTable` с `virtualize`) проверены e2e. Сортировка и drop работают. Закрепить активную строку у них нельзя (нет аналога `rangeExtractor`), поэтому, уйдя из диапазона, она размонтируется, а overlay при drop гаснет. `v-data-table-virtual` к тому же пересоздаёт строки со сменившимся индексом; фокус при клавиатурном drag ядро возвращает. Если строка должна оставаться смонтированной — TanStack `useVirtualizer` с компонентами кита внутри.

В документации будут готовые рецепты для TanStack (список, сетка через `lanes`, колонки канбана) и для `useVirtualList`.

## 10. Сенсоры, клавиатура, доступность

- **Pointer Events.**
  - Учитываются `isPrimary` и `button === 0`, обрабатывается `pointercancel`. Отмена — на `visibilitychange` и Escape.
  - Drag не начинается с интерактивных потомков (input, button, select, textarea, contenteditable), кроме ручки или самого элемента.
  - Клик после drop подавляется, выделение текста блокируется. Исключение — нажатие мышью, после которого drag стартовал сразу (на ручке) и указатель не сдвинулся дальше 3px: оно остаётся кликом по тому, что нажали (кнопка в ручке, меню). Указатель захватывается на `body` только после движения, иначе клик ушёл бы в `body`. Тач, удержанный на месте, кликом не считается. *Добавлено 02.11.2026.*
  - Курсор: во время pointer-drag вся страница показывает курсор захваченного элемента (элемента под указателем внутри draggable), если он свой: `ns-resize` ручки, `move`, картинка. Курсоры, которые только приглашают нажать (`auto`, `default`, `pointer`, `text`, `grab`, `help` и т. п.), сменяются на `grabbing`. Значение кладётся в `--dnd-cursor` на `<html>`, стиль по умолчанию — `cursor: var(--dnd-cursor, grabbing)`. Сохраняется и при `'continue'`. *Добавлено 02.11.2026.*
  - Используется трюк с непассивным `touchmove` для iOS (в v2 эти слушатели были пассивными и ничего не делали). Нативный HTML5 drag на элементах отменяется, кроме drag мышью у `native` (раздел 10.1).
  - Тач-события продолжают приходить на элемент, которого коснулся палец, даже если перенос в другой список его пересоздал. Поэтому `touchmove` блокируется и на самой цели касания, иначе браузер начинает панорамировать и шлёт `pointercancel`.
  - `selectstart` отменяется с момента нажатия: WebKit решает про выделение на `mousedown`, и начатое выделение само скроллит контейнер.
  - Во время pointer-drag `-webkit-touch-callout: none`: drag на таче стартует за 200 мс, раньше, чем iOS показывает меню ссылки и лупу (~500 мс).
- **Активация.** Мышь: 4px, а на ручке сразу. Тач: 200 мс с допуском 5px. Перо: 4px. Ограничения задаются по виду указателя на провайдере, области (`makeDragArea`) или элементе; элемент главнее области, область — провайдера. *Исправлено 02.11.2026: здесь значился и список, но опции `activation` у списка нет (ревью A11).* Задержка в миллисекундах; в v2 код считал её в секундах вопреки документации.
- **Сенсоры.** Ввод превращают в drag сенсоры из пропа `sensors` (по умолчанию `[pointerSensor, keyboardSensor]`). Сенсор только говорит провайдеру «тащи этот элемент отсюда», потом — куда он сдвинулся и что его бросили или отменили (`SensorContext.activate()` → `SensorDrag` с `move`, `step`, `place`, `drop`, `cancel`). Все проверки — один drag за раз, `disabled`, ручка, интерактивные потомки, `canDrag`, ограничения активации — делает провайдер, одинаково для встроенных и своих сенсоров (`defineSensor`, `useSensor`: геймпад, голос, скриптовые drag, `@vue-dnd-kit/actions`). `keyboard: false` выключает drag клавиатурой, но Escape по-прежнему отменяет любой drag. Мост HTML5 (раздел 10.1) работает вне `sensors` (ревью B7).
- **Вибрация (`haptics`).** Только у drag, начатых тачем: по умолчанию короткая при старте после долгого нажатия; объект добавляет `enter`, `drop`, `refuse`; `false` выключает. Где браузер не умеет (iOS Safari) или не разрешает, ничего не происходит.
- **Клавиатура.**
  - Space/Enter берёт и кладёт, Escape отменяет. Клавиши переназначаются, автоповтор (`event.repeat`) игнорируется, в редактируемых полях клавиши не перехватываются.
  - В списках стрелки двигают на одну позицию. В канбане влево-вправо переносят в соседнюю колонку, в дереве меняют уровень, в сетке ищется ближайший элемент в следующем ряду.
  - Стрелка за конец списка вдоль его оси переходит в следующий список в ту же сторону: так вертикальные списки, стоящие друг под другом (и горизонтальные в ряд), проходятся стрелками вверх-вниз. Если списка в эту сторону нет, стрелка ведёт к ближайшей обычной цели (корзина), и drop идёт в неё, а слот возвращается на место, как при указателе. *Добавлено 02.11.2026.*
  - При свободном drag стрелки двигают на 25px (Shift — быстрее) или переходят между подходящими зонами.
  - Фокус восстанавливается по ключу, в том числе посреди drag, если список пересоздал строку.
  - Зона на элементе: стрелка сначала останавливается «на» элементе, повторное нажатие проходит дальше, обратная стрелка выходит. Space/Enter кладёт внутрь.
  - В список или дерево с индикатором клавиатура не вставляет элемент, а двигает линию. В дереве с индикатором вверх-вниз — по промежуткам, влево-вправо — уровень.
  - Слушатель клавиатуры работает в фазе capture и поглощает (`preventDefault` + `stopPropagation`) только те клавиши, на которые drag действует. Иначе UI-киты перехватывали их: кликабельный `v-list-item` съедал Space/Enter, `v-list` переводил фокус стрелками, а Escape закрывал `v-dialog` вокруг списка.
- **ARIA.**
  - `role="button"`, `tabindex="0"`, `aria-roledescription` (`draggable` или `sortable`);
  - `aria-describedby` указывает на инструкции;
  - `aria-pressed` во время drag, `aria-disabled`.

  Заданное пользователем не перезаписывается. Исключение — `aria-describedby`: id инструкций добавляется к существующему значению отдельным токеном, возвращается, если привязка перезаписала атрибут, и при очистке убирается только он. Тултипы UI-китов (Vuetify, Reka) ставят на активатор свой `aria-describedby`, и без этого ссылка на инструкции терялась.
- **Анонсы.** Английские, с позициями («Item X moved to position 3 of 8 in list A»). Вместо id говорят `label` элемента, списка, дерева и зоны, если он задан («Picked up Tomato at position 2 of 5 in Garden»). Анонсы перемещения debounce'ятся на 500 мс. Переопределяются пропом; своим текстам приходит второй аргумент `AnnouncementContext` (`position` с `label` списка, `partner`, `count`, `copy`), чтобы сказать то же на другом языке. Свой анонс, вернувший `undefined`, передаёт слово следующему источнику (анонсы интеграций, затем стандартные); тишина — пустая строка `''`. Цель, найденная под элементом при взятии, не анонсируется как перемещение. Swap называет партнёра и его новую позицию, зона на элементе — «положить внутрь» и «положено внутрь». Ответ `'continue'` анонсируется (`onDragResume`).

### 10.1 Собственный drag and drop браузера

*Добавлено 02.11.2026* (решение 33). Drag библиотеки живут внутри страницы, а drag and drop браузера (HTML5) пересекает её границы. Библиотека ведёт и такие drag — как drag провайдера: цели подсвечиваются (`isOver`, `isAccepting`), списки освобождают место, события и анонсы обычные. Overlay нет: картинку рисует браузер (`active.native === true`).

- **Извне страницы (`external`)** — у `makeDroppable`, `makeSortableList`, `makeSortableTree`: файлы с рабочего стола, ссылка из другой вкладки, текст из другого приложения. `ExternalAccept`:
  - `files` — `true`, MIME-типы и расширения как у `<input accept>` (строка через запятую или список; расширения проверяются при броске) или функция на каждый файл; папки — никогда;
  - `multiple` — по умолчанию `true`, `false` отклоняет drag нескольких файлов;
  - `links` (`text/uri-list`), `text` (`text/plain`), `types` (другие MIME-типы, как их предлагают приложения).

  Цели без `external` такие drag игнорируют, правило `accept` к ним не применяется.
- **Что несёт drag (`ExternalData`, `active.external` и `e.external`).** Пока drag удерживают, браузер говорит только виды данных: `types`, `fileTypes`. Сами `files` (только принятые целью), `urls`, `text`, `html` и `getData(type)` появляются при броске, тогда же `ready: true`.
- **В список.** Список или дерево берёт drag извне только вместе с `createItem` (без него молча не берёт, ревью A10). `createItem` спрашивают дважды: пока drag удерживают — за элементом-плейсхолдером (известны только `types` и `fileTypes`), и при броске — с данными (`active.external.ready`) за тем, что вставится. Список может вернуть массив, тогда вставляется по элементу на файл; дерево возвращает один узел (папку с файлом на ребёнка).
- **Наружу (`native`)** — у `makeDraggable` и `makeSortableItem`: drag мышью становится drag браузера и может уйти на рабочий стол, в другое приложение, вкладку или окно. На странице он работает как обычно. Тач и клавиатура остаются drag библиотеки. `native: true` несёт `label` как `text/plain`; `{ data: (active) => ({ 'text/plain': …, 'text/uri-list': … }), effect }` задаёт данные и `effectAllowed` (по умолчанию `'copyMove'`). Порог активации для мыши задаёт браузер. Сейчас такой drag мышью не спрашивает `canDrag` — дефект, ревью A1.
- **Между окнами приложения.** Sortable-элемент с `native` несёт и себя, с именем своей группы (`ExternalData.group`). Списки той же группы в другом окне берут его как элемент из своего списка — без `external` и `createItem`. Если там его взяли перемещением, он уходит из своего списка здесь.
- **Брошено вне страницы.** `DnDEndEvent.droppedOutside` (`'move' | 'copy' | 'link'`) говорит, что сделало с drag другое место, при `dropped: false`. `'move'` забирает элементы из их sortable-списка (как `e.source.remove()` в корзине), `'copy'` и `'link'` оставляют. Отменённый браузером drag — обычная отмена.
- Браузер ведёт один drag на страницу; уход drag извне за окно отменяет его, а drag своей страницы ждёт снаружи (может вернуться или закончиться `dragend`).

## 11. Автоскролл

- Включён по умолчанию, настраивается на провайдере и списке. Наружу отдаётся `isAutoScrolling`.
- Один rAF-цикл. Скроллеры выбираются от элемента под указателем изнутри наружу, последним идёт окно.
- Порог — 20% размера контейнера, но не меньше 24px и не больше 96px. Скорость ограничена; шаг — `scrollBy` с поправкой на длительность кадра.
- Допуск по поперечной оси 10px: указатель сбоку от контейнера его не скроллит.
- Блок по намерению: направление разрешается только после движения в эту сторону, так что элемент, взятый у края, не уезжает сам.
- Скролл двигает кэшированные прямоугольники через scroll-delta, без перемера.
- На скроллерах со `scroll-snap-type` снаппинг отключается с первого шага автоскролла до конца drag: Chromium снаппит каждый программный `scrollBy` (при `mandatory` — колонку за кадр). Возврат стиля снова снаппит к ближайшей позиции до того, как drop-анимация измерит цель.
- При клавиатурном drag скроллится сама цель: через `scrollToKey` для виртуальных списков, иначе вручную, без `scrollIntoView`.

## 12. Производительность

- Черновики в `shallowRef`, не больше одной мутации за кадр. Пользовательские данные не обходятся глубоко, для больших массивов рекомендуем `shallowRef`.
- Прямоугольники кэшируются на время drag и инвалидируются только у изменившихся списков. Скролл учитывается через scroll-delta. Все чтения DOM — одним проходом за кадр.
- Фильтры collision линейные: в v2 они были O(N²).
- **Бенчмарки в Playwright:**
  - сценарии: 500 элементов без виртуализации, 5k в канбане, 50k с TanStack;
  - метрики: время кадра, long tasks, время перерисовки Vue при перестановке;
  - главный риск — стоимость перерисовки Vue по сравнению с прямыми перемещениями DOM, как у dnd-kit. Если не уложимся, план Б — keyed-перемещение только затронутого диапазона.

## 13. Инварианты надёжности

- Одна активная сессия на провайдер. Ввод, пока drop решается (async `onBeforeDrop`), игнорируется; посадки overlay новый drag не держат (раздел 3). Drag браузера (раздел 10.1) — один на страницу, его ведёт провайдер, к которому он пришёл.
- Элемент нельзя бросить в самого себя: цели внутри любого перетаскиваемого элемента (весь мульти-drag) и внутри слота, куда он сядет (копия, созданный элемент), не считаются целями.
- Каждый путь выхода (drop, отказ, cancel, ошибка в колбэке, `pointercancel`, скрытие вкладки, размонтирование провайдера) возвращает DOM в исходное состояние (стили body, `overflow-anchor`, слушатели) и эмитит **ровно одно** завершающее событие.
- Стили страницы (`touch-action`, `overscroll-behavior`, `user-select`) не перезаписываются вслепую: сохраняются и восстанавливаются только те, что меняли мы. В v2 их затирал любой `mouseup` на странице.
- Реестры чистятся при размонтировании. Выделение хранится по id и переживает размонтирование (виртуализация); ключи, которых уже нет в данных, отфильтровываются при старте drag.
- Компоненты в данных (`render`, слоты) не делаются reactive (`markRaw`).
- Рукописных `.d.ts` нет: все типы живут в `.ts` и проверяются полностью. В v2 в рукописных `.d.ts` были пропущены импорты `Component` и `IPlacement`, и типы молча превращались в `any`. `skipLibCheck: true` нужен только из-за `.d.ts` VueUse 15 (ссылается на Web Bluetooth и Temporal). Регрессии публичных типов ловит `src/types.test.ts`.
- Опции, которые библиотека только читает, типизированы как `MaybeReadonlyRefOrGetter<T>`: принимают readonly-ref из `useTemplateRef`, computed, геттер и `Ref<string>` там, где ожидается `string | number`. Vue-шный `MaybeRefOrGetter` последние два случая не принимает.
- Ссылка на элемент (`MaybeElement`) принимает всё, у чего есть `$el`, а не полный тип экземпляра компонента: иначе `vue-tsc` отвергал ссылки на компоненты UI-китов с типизированными emits (`VListItem`, `UTooltip`). Компонент с fragment-корнем разрешается в первый элемент внутри фрагмента и никогда не выходит за его конец (на соседний элемент).
- Id по умолчанию у draggable, зон, списков и деревьев — `useId()`: одинаковый на сервере и клиенте. Вне компонента (отдельный `effectScope`) — счётчик модуля.

## 14. Миграция с v2

**Ключевое соответствие:**

| v2 | v3 |
|---|---|
| `makeDraggable(ref, opts, () => [index, items])` + `onDrop` с `helpers.suggestSort` | `makeSortableList` + `makeSortableItem`: результат пишется в `Ref`, обработчик не нужен |
| `suggestSwap` / `suggestCopy` / `suggestRemove` | `behavior: 'swap'` / `group.pull: 'clone'` + `clone` / корзина `e.source.remove()` |
| `groups`, `groupMatch`, `onValidate` | `type` / `accept` (`group.put`) / `acceptMode`, частичный приём в `onBeforeDrop` |
| `makeConstraintArea` | модификаторы `restrictToElement`, `restrictToParent`, `restrictTo*Axis` |
| `makeAutoScroll`, `autoScrollViewport` | встроенный автоскролл, `autoScroll` на провайдере и списке |
| `DragPreview`, `render`, `preview.render` | клон по умолчанию + слот `#overlay` / опция `overlay: Component` с `items`, `over`, `accepted`; `<DragPreview :id>` — клон одного элемента для своих раскладок |
| `useDnDProvider()` (внутренние Map) | `useDnD()` (только чтение) + `useDnDMonitor()` |
| `modifier` (drag с зажатой клавишей) | `canDrag: (e) => …` |
| `delay.progress`, `distanceProgress` | `useDnD().activation.progress` |
| `injectionKey` (Shadow DOM) | `provideDnDContext` / `useDnDContext` |
| `previewTo` | `overlayTo` |
| `@vue-dnd-kit/utilities` (snap) | модификатор `snapToGrid` |
| `isDragOver` (placement) на draggable | `indicator` у sortable, `placement` у `makeDroppable` |

**Изменения поведения, которые guide должен назвать явно:**
1. `false` из async-обработчика означает анимированный возврат, а не продолжение drag.
2. Drop мимо зон по умолчанию кладёт элемент в плейсхолдер (`dropOutside`). В v2 это считалось успешным drop без цели.
3. Drag начинается после 4px, на таче после 200 мс; раньше начинался сразу.
4. Задержка активации в мс, как и обещала документация; код v2 считал секунды.
5. Выделение больше не сбрасывается при старте drag и привязано к id.
6. Swap при мульти-drag отключён.
7. Клавиатура двигает по элементам, а не по пикселям (кроме свободного drag).
8. Мульти-drag по умолчанию `multiple: 'group'`: выделенные элементы уходят со своих мест и едут блоком. Поведение v2 (элементы стоят на местах, overlay показывает все) — `multiple: 'gaps'`.

**Убрано:** `DragPreview` v2 (рендер overlay) и `DefaultOverlay`, `collision.throttle` (rAF-батчинг), внутренний конструктор сенсоров, payload-фабрики `[index, items]`. Имя `DragPreview` в v3 занято другим компонентом (клон одного элемента, раздел 7).

Guide описывает **реальное** поведение v2, а не задокументированное: аудит нашёл около 30 расхождений документации с кодом.

**Примеры документации** (подробная таблица в `v2-parity.md` §3):
- около 8 станут тривиальными: сортировка, swap, копирование, группы, ручка, disabled, базовые зоны, snap;
- около 6 устарели или сливаются;
- 14 новых: горизонтальный список, сетки, извне в список, корзина, режимы плейсхолдера, стопка или пробелы, возврат при отказе, TanStack, правила приёма, вложенные sortable в 3 уровня, строки таблиц, Nuxt-стартер, анонсы.

Регресс-тест для Shadow DOM из playground сохраняется.

## 16. Решения по открытым вопросам (24.10.2026)

1. **Движок:** свой. Удачные решения dnd-kit берём как идеи, без зависимости.
2. **Группы:** `group` в стиле SortableJS (`name`/`pull`/`put`) у списков, `type`/`accept`/`acceptMode` у низкоуровневых зон.
3. **Стили по умолчанию:** `:where()`-стили в рантайме, выключаются `defaultStyles: false`.
4. **TanStack:** рецепт в документации с `captureLayout` в `onChange`, без отдельного хелпера и без зависимости.
5. **Drop мимо зон:** по умолчанию `placeholder` (как в Trello); в режиме `indicator` — `cancel`.
6. **Дерево:** по умолчанию `nesting: 'both'`.
7. **RFC:** хранится в репозитории, `rfcs/0001-v3.md`, исследования — в `rfcs/0001-v3/`.

**Решения от 25.10.2026:**

8. **Overlay по размеру слота:** `overlayFit: 'slot'` по умолчанию, `'source'` — опция. Drop анимирует width/height, без `scale()`. При смене размера точка захвата сохраняется пропорционально.
9. **Id:** по умолчанию `useId()`; `id` остаётся опциональным. `makeSortableItem` принимает `{ item }` (ключ через `getKey` списка) или `{ id }`.
10. **Свой overlay:** опция `overlay: Component` у draggable, элемента, списка и дерева, поверх слота `#overlay` провайдера.
11. **UI-киты:** проверяем совместимость на Nuxt UI / Reka UI и Vuetify, с e2e.
12. **Размер:** оптимизация без смены API, затем реальные бюджеты size-limit в CI.
13. **Мульти-drag:** новый режим `group` по умолчанию (превью результата), overlay показывает все элементы колонкой; `gaps` — как в v2; `stack` — карточка со счётчиком. Вид настраивается своим overlay и `DragPreview`.
14. **Состояние drag заканчивается, когда drop решён,** а не когда overlay сел (раздел 3).
15. **Модификаторы у источника:** `modifiers` у draggable, списка и элемента (раздел 4.6). В примерах таблица и одиночные списки зафиксированы по оси.
16. **Фон клона:** sortable-элемент без фона берёт фон предка — оставляем.
17. **`aria-describedby`:** id инструкций добавляется токеном к существующему значению.
18. **Мелкие API-пункты:** обычный курсор и выделение, пока async `onBeforeDrop` решает; `undefined` из своего анонса — откат к следующему источнику, `''` — тишина; dev-предупреждение о двух `makeSortableList` в одном компоненте (*снято решением 29*); стрелки двигают внешний draggable по слотам списка.

**Ревью API перед релизом (25.10.2026, сделано: H1, H2, H3):**

19. **Реактивность опций:** всё, что имеет смысл менять на лету, принимает значение, ref или геттер и читается, когда нужно. Один раз читаются `id` и `group` списков и деревьев. Опции-функции остаются функциями. `overlay`, `animation` и правила `accept` — значение или ref.
20. **Дерево наравне со списком:** `modifiers`, `autoScroll`, `dropOutside`, `acceptMode`, `clone`, `createItem`; возвращает `isAccepting`, `activeIndex`, `activeSize`.
21. **Элемент списка наравне с draggable:** `canDrag`, `attributes`.
22. **Типы:** явный список экспортов; `useDnDContext()` возвращает непрозрачный `DnDContext`, который можно только передать в `provideDnDContext`.
23. **Контролируемый режим:** `onDrop` вызывается до записи; `e.preventDefault()` в `onBeforeDrop` или `onDrop` отменяет запись во все затронутые списки; `e.result` — новые массивы по спискам; `items` может быть readonly (без `preventDefault` — dev-предупреждение). В дереве `e.result` — новое дерево без мутаций (изменённые пути копируются: по умолчанию `{ ...node }` плюс `setChildren` на копии, чтобы не терять данные со своим полем детей; или опция `withChildren`), запись по умолчанию — как раньше.
24. **Overlay:** API без изменений, страница документации с порядком приоритетов.
25. **Два списка в одном компоненте:** только предупреждение и документация. *Заменено решением 29.*
26. **Имена `make*`** остаются.
27. **Мульти-drag в дереве как в VS Code:** потомок выделенной папки остаётся внутри неё, даже если тянуть за него.

**Добавления на время беты (02.11.2026; 28–32 и замысел 33 утверждены мейнтейнером, итоговая форма 33 и пункты 34–35 записаны по коммитам `f77a1de1` и `3dbefc48`):**

28. **`label`** (строка, ref или геттер) у draggable, зоны, sortable-элемента, списка и дерева: стандартные анонсы говорят его вместо ключей, события несут его (`active.label`, `over.label`, `items[].label`, `AnnouncedPosition.label`).
29. **Несколько списков (и деревьев) в одном компоненте:** элемент находит свой список по DOM — самый внутренний, чей элемент его содержит. Выбрано вместо явного компонента-области; предупреждение снято.
30. **`filter` у списка:** показываются и сортируются подходящие элементы; drop пишется в полный массив рядом с видимыми соседями, скрытые остаются на местах.
31. **`snapToGrid` по одной оси:** `x` и `y` необязательны; `origin: 'delta'` описан в документации.
32. **Курсор захваченного элемента:** pointer-drag показывает собственный курсор элемента под указателем (`ns-resize` остаётся), «приглашающие» курсоры сменяются на `grabbing`; через `--dnd-cursor`.
33. **Собственный drag and drop браузера:** вместо задуманных `files: { accept, multiple }` + `onFiles` у `makeDroppable` — общая модель (раздел 10.1). `external` у целей, списков и деревьев (файлы, ссылки, текст, свои типы), `native` у draggable и элементов (вынос за страницу), перенос между окнами по имени группы, `droppedOutside`. `isOver` и `isAccepting` работают и для таких drag.
34. **Элемент содержимого overlay** `[data-dnd-overlay-content]` и проп провайдера `overlayClass`: библиотека двигает и размеряет бокс, страница анимирует содержимое (`@starting-style`, `[data-dnd-overlay='dropping']`), drop ждёт её анимаций.
35. **`animateSize` по умолчанию включён:** список плавно меняет размер, когда drag вносит или забирает элемент, и на drop; `false` — прыгает.
