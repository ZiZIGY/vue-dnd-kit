# RFC: vue-dnd-kit v3

Статус: **утверждён мейнтейнером 24.10.2026, дополнен решениями от 25.10.2026**. Основа — решения из Q&A от 24.10.2026 и три исследования в папке `0001-v3/`: `dnd-kit.md` (устройство dnd-kit), `virtualization.md` (TanStack Virtual и VueUse), `v2-parity.md` (инвентаризация v2: 24 пробела, 57 багов, ~30 расхождений документации с кодом). Открытые вопросы закрыты, итог в разделе 16.

## 0. Цели и не-цели

**Цели**
- Анимации по умолчанию: перестановка соседей, drop, возврат при отмене или отказе, сбор группы при множественном drag и посадка каждого её элемента в свой слот. Любую анимацию можно выключить или заменить функцией.
- Готовые решения для списков, канбана, сеток (в том числе с разными размерами), вложенных sortable, строк таблиц и деревьев. Плейсхолдер настраивается без ручного рендера.
- Работа с виртуализацией (TanStack Virtual, VueUse `useVirtualList`, любая библиотека со стабильными key), включая анимации.
- Производительность: 500 элементов без виртуализации при 60fps, 50k с виртуализацией.
- Доступность: клавиатура по элементам, ARIA-атрибуты, анонсы с позициями.
- Надёжная машина состояний: у каждой сессии ровно одно завершающее событие (раздел 13).

**Не-цели 3.0**
- Старые браузеры (база: Chrome/Edge 104+, Safari 15.4+, Firefox 104+).
- Нативный HTML5 DnD (файлы с рабочего стола), iframe.
- Слой совместимости с v2: только migration guide.

## 1. Позиционирование относительно `@dnd-kit/vue`

У dnd-kit вышел официальный `@dnd-kit/vue@0.5.1`: тонкая обёртка над `@dnd-kit/dom`, 22.10.2026. Механизм сортировки у него тот же, что выбрали мы: реальная перестановка DOM и FLIP на `translate`. Чем v3 отличается:

| | `@dnd-kit/vue` 0.5 | vue-dnd-kit v3 |
|---|---|---|
| Множественный drag | нет | группа (список заранее показывает результат), пробелы или стопка; overlay со всеми элементами; анимации сбора, посадки и возврата; из нескольких списков сразу |
| Выделение рамкой | нет | есть |
| Канбан и дерево | примеры в сторибуке, логику пишет пользователь | `makeSortableList({ group })`, `makeSortableTree` из коробки |
| Применение результата | пользователь сам вызывает `move()` в `onDragOver` и `onDragEnd` | библиотека пишет в `Ref`, `onBeforeDrop` (async, частичный приём) |
| Копирование, swap, корзина, перетаскивание извне | вручную | опции списка |
| Виртуализация | пример с TanStack | контракт + `captureLayout`, `activeIndex`, тесты для TanStack и VueUse |
| Вложение в дереве наведением | нет | есть |
| API | обёртка над чужим ядром (классы, плагины) | Vue-нативные composables |

**Вопрос мейнтейнеру (Q1, закрыт: свой движок, раздел 16):** идём дальше своим движком (рекомендую: отличия выше и есть продукт) или делаем v3 слоем поверх `@dnd-kit/dom`? Второй вариант экономит движок, но привязывает нас к чужой 0.x-архитектуре. Например, их overlay поднимает реальный элемент в top layer через `popover`, а мы договорились о клоне.

## 2. Пакет, сборка, Nuxt

- Один пакет `@vue-dnd-kit/core`, один entry, `"sideEffects": false`. Каждый composable и модификатор отрезается tree-shaking'ом.
- Зависимости: `vue ^3.5` (peer), `@vueuse/core ^14 || ^15` (dependency, external в сборке).
- Форматы: ESM `.js` и CJS `.cjs` (в v2 CJS сломан: файл `.cjs.js` при `"type": "module"`). `exports` с `types`, `publint` и size-limit в CI.
- Без CSS-файлов и без внедрения CSS при импорте. Стили по умолчанию (полупрозрачный плейсхолдер, `user-select: none` во время drag) внедряются в рантайме при первом монтировании провайдера через `:where(...)`, то есть с нулевой специфичностью: любой пользовательский CSS их перебивает. Отключаются пропом `defaultStyles: false`.
- Нет глобального состояния на уровне модуля: несколько провайдеров на странице работают независимо (в v2 общими были `originalUserSelect` и подобное).
- `packages/utilities` удаляется: привязка к сетке становится модификатором `snapToGrid`, причём от начала контейнера, а не от viewport, как было в v2.
- **Nuxt-модуль v3:**
  - Список экспортов становится статическим манифестом с тестом против `index.ts`. Сканирование собранного бандла через `mlly` сломается на чанках.
  - Регистрируются два компонента: `DnDProvider` и `DragPreview`. В v3 `DragPreview` — клон одного перетаскиваемого элемента для своих overlay (раздел 7), а не рендер overlay, как в v2.
  - Composables автоимпортируются, модификаторы — только опцией (`autoImports.modifiers`), потому что у них общие имена.
  - Типы — через type-импорты.
  - `injectionKey` не автоимпортируется. Пустой `plugin.client.ts` удаляется.
  - SSR-тест на отсутствие hydration mismatch с черновым `v-for`. Peer: `@vue-dnd-kit/core ^3`.

## 3. Архитектура

```
DnDProvider ── Manager (state machine, реестры по id)
   │             ├─ Sensors: pointer (mouse/touch/pen), keyboard
   │             ├─ Measuring: layout rect без transform/translate, кэш со scroll-delta
   │             ├─ Collision: pointer-first (elementFromPoint, shadow-aware) + приоритеты + защиты от осцилляции
   │             ├─ Accept: type / accept / acceptMode — единый матчер для зон, списков, выделения
   │             ├─ Modifiers → один transform и для overlay, и для collision
   │             ├─ AutoScroll: rAF, innermost-first, scrollBy
   │             ├─ Overlay: клон или слот, Teleport, drop/cancel-анимация
   │             ├─ Animator: FLIP-движок (WAAPI на translate), общий для всех слоёв
   │             └─ A11y: атрибуты, инструкции, live region, фокус
   ├─ makeDraggable / makeDroppable — низкий уровень, свободный drag (игры, зоны)
   ├─ Sortable: группы, черновики, стратегии, режимы, мульти-drag
   │    ├─ makeSortableList / makeSortableItem
   │    └─ makeSortableTree
   └─ makeSelectionArea — выделение по id
```

**Машина состояний:** `idle → activating → dragging → dropping → idle`, плюс `selecting` для рамки.
- `activating`: ждём порог (дистанция или задержка), прогресс доступен для UI.
- `dropping`: ждём `onBeforeDrop` (async) или идёт анимация drop или возврата. Ввод в этом состоянии игнорируется, в том числе второй `pointerup`, Enter или новый `pointerdown`.
  - Пока async `onBeforeDrop` решает, ничего не изменилось: `over`, `isOver` и `isAccepting` остаются как при отпускании, правила приёма продолжают работать. Документ на время ожидания возвращается в обычное состояние (курсор, выделение текста), чтобы диалог подтверждения работал нормально.
  - Как только drop решён (коммит или отмена), состояние drag заканчивается: `over`, `pointer` и `useDnD().active` становятся `null`, правила приёма больше не вычисляются. Иначе UI, производный от drag, смешивал бы старое перетаскивание с уже изменёнными данными (колонка, заполненная до лимита, «отказывала» только что принятой карточке). Overlay и плейсхолдеры доигрывают анимацию; слот overlay получает цель, на которую садится (`over` на момент drop, при отмене `null`).

**Идентичность по id.** Активный элемент, выделение, черновики и анонсы живут по ключам, а не по DOM-узлам. Элемент может пересоздаться (переход между колонками, виртуализация), drag это переживает. Слушатели висят на `document`, pointer capture — на `body`.

## 4. Публичный API

### 4.1 Провайдер

```vue
<DnDProvider
  :collision="pointerFirst"
  :modifiers="[restrictToWindowEdges]"
  :animation="{ duration: 200, easing: 'cubic-bezier(0.25, 1, 0.5, 1)' }"  <!-- FLIP по умолчанию -->
  :drop-animation="{ duration: 250, easing: 'ease' }"   <!-- | false | (ctx) => Animation | Promise -->
  :auto-scroll="true"                                    <!-- | false | { threshold, maxSpeed, acceleration } -->
  :activation="{ mouse: { distance: 4 }, touch: { delay: 200, tolerance: 5 }, pen: { distance: 4 } }"
  :keyboard="{ keys: { start: ['Space','Enter'], drop: ['Space','Enter'], cancel: ['Escape'] } }"
  copy-modifier="Alt"                                    <!-- null — выключить копирование клавишей -->
  overlay-to="body"
  overlay-fit="slot"                                     <!-- 'source' — overlay сохраняет размер исходника -->
  :announcements="customAnnouncements"
  :default-styles="true"
  @drag-start @drag-move @drag-over @drag-end @drag-cancel
>
  <App />
  <template #overlay="{ active, items, over, accepted, status, mode }">
    <!-- items: [{ id, item, data, type }] — ветвление по типу; over/accepted — смена вида над зоной -->
    <Card v-if="items.length === 1" :card="items[0].item" />
    <CardStack v-else :cards="items" />
  </template>
</DnDProvider>
```

### 4.2 Низкий уровень и состояние

```ts
const { isDragging, transform, selected } = makeDraggable(elRef, {
  id: () => piece.id,            // MaybeRefOrGetter — важно для виртуализации; по умолчанию useId()
  data: () => piece,
  type: 'piece',                 // string | string[]; не задан — подходит куда угодно (как groups: [] в v2)
  disabled: isLocked,            // наследуется от отключённого предка
  handle: handleRef,             // ref или селектор
  activation: { mouse: { distance: 8 } },
  canDrag: (e) => e.shiftKey,    // drag только с зажатой клавишей (замена `modifier` из v2)
  overlay: true,                 // false — двигается сам элемент через `transform`; компонент — свой overlay
  modifiers: [restrictToParent], // для drag, начатых здесь; после модификаторов провайдера
  keyboard: 'pixels',            // свободный drag: стрелки по 25px; 'droppables' — переход между подходящими зонами
  attributes: true,              // role/tabindex/aria-*, не перезаписываем заданные пользователем
});

const { isOver, isAccepting, placement } = makeDroppable(zoneRef, {
  id: 'trash',
  accept: ['card'],              // | '*' | (ctx) => boolean — синхронно, вычисляется вживую
  acceptMode: 'all',             // 'some' — принять, если подходит хоть один элемент мульти-drag
  priority: 0,
  onDragEnter, onDragLeave,
  onBeforeDrop: async (e) => true,   // false — отказ (анимированный возврат); Key[] — принять подмножество
  onDrop: (e) => e.source?.remove(), // корзина: удалить из исходного списка
});

const dnd = useDnD();  // shallowReadonly:
// status, active { id, ids, items, data, type }, over { id, data, accepted }, pointer,
// activation { progress }, isAutoScrolling, selection, cancel()
// active/over/pointer — null, как только drop решён (раздел 3), хотя status ещё 'dropping'
useDnDMonitor({ onDragStart, onDragOver, onDragEnd, onDragCancel });

// Shadow DOM и отдельные Vue-приложения под одним провайдером (было через injectionKey в v2):
provideDnDContext(app, useDnDContext());
```

### 4.3 Сортировка

```ts
const {
  items,          // ComputedRef<T[]> — черновой порядок, рендерить именно его
  isOver, isAccepting, indicator,
  activeKey, activeIndex, activeSize,   // для виртуализаторов
  captureLayout,  // FLIP после перерасчётов, которые вызвала не библиотека (ResizeObserver виртуализатора)
} = makeSortableList(listRef, {
  items: tasks,                         // Ref<T[]>, библиотека сама запишет результат
  getKey: (t) => t.id,                  // по умолчанию item.id
  id: 'todo',                           // по умолчанию useId()
  group: 'board',                       // | { name, pull: true | false | 'clone', put: true | false | (ctx) => boolean }
  acceptMode: 'all',                    // для мульти-drag из разных типов
  strategy: 'vertical',                 // 'horizontal' | 'grid' (разные размеры тоже)
  behavior: 'sort',                     // 'swap' — живой обмен (для мульти-drag отключён)
  placeholder: 'item',                  // 'indicator' — список не двигается, показываем линию
  multiple: 'group',                    // 'gaps' | 'stack' (раздел 5)
  overlay: TaskCard,                    // компонент overlay для элементов списка (свой overlay элемента главнее)
  modifiers: [restrictToVerticalAxis],  // для drag элементов списка; модификаторы элемента главнее
  sort: true,                           // false — внутри списка не сортируется (палитра)
  clone: (t) => ({ ...t, id: uid() }),  // нужен для pull: 'clone' и копирования по Alt
  createItem: (active) => toTask(active.data),   // приём обычных draggable извне
  dropOutside: 'placeholder',           // 'cancel' | 'remove' — что делать при drop мимо всех зон
  animation: { duration: 200 },         // | false | функция
  autoScroll: true,                     // переопределение для списка
  disabled: false,
  onBeforeDrop: async (e) => e.rejected.length ? confirm('Часть не подходит, взять остальные?') : true,
  onDrop: (e) => api.move(e),           // уже после записи в Ref
});

const { isDragging, isPlaceholder, selected, indicator, index } =
  makeSortableItem(itemRef, { item: () => props.task, handle: '.grip', type: 'task' });
  // item — ключ берётся через getKey списка; или id: () => props.task.id (id главнее).
  // Автоматического id у элементов нет: ключ обязан идти из данных, иначе перенос в
  // другой список или переиспользование строки виртуализатором потеряют элемент.
  // overlay, modifiers — как у списка, но для одного элемента.
```

- `group` в стиле SortableJS/vuedraggable, эти термины знакомы Vue-разработчикам:
  - строка — списки с одним именем обмениваются элементами;
  - `pull: 'clone'` — палитра;
  - `put` — функция приёма;
  - `type` элементов по умолчанию равен имени группы.
- `SortableDropEvent<T>`: `{ keys, items, accepted, rejected, from: { list, index }, to: { list, index }, sameList, mode: 'move' | 'copy' | 'swap' | 'insert' }`.
- **Только composables.** Как и в v2, на каждый элемент нужен свой компонент. Рецепт для v-for без отдельного компонента будет в документации. Список передаёт контекст элементам через `provide`, поэтому два `makeSortableList` в одном компоненте конфликтуют (элементы первого молча попадают во второй); в dev-сборке об этом есть предупреждение: каждый список — в своём компоненте.
- **Строки таблиц.** Список — `<tbody>`, элементы — `<tr>`. Клон `<tr>` в overlay оборачивается в `<table><tbody>` с шириной колонок.

### 4.5 Выделение рамкой

```ts
const { isSelecting, style } = makeSelectionArea(areaRef, {
  selection: selectedIds,              // Ref<Set<Key>>; по умолчанию — выделение провайдера
  modifier: { keys: ['Shift'], method: 'some' },
  strategy: 'toggle',                  // 'select'
  accept: ['task'],                    // тот же матчер, что у зон
  onSelected: (ids) => {},
});
```

Выделение — `Set<Key>` (`useDnD().selection` или свой `Ref`). У элементов есть writable `selected`, подходит для чекбоксов. Ctrl/Cmd+клик пользователь вешает сам, рецепт будет в документации. Выделение может охватывать несколько списков, multi-drag забирает элементы из всех.

### 4.6 Модификаторы и collision

```ts
import {
  restrictToVerticalAxis, restrictToHorizontalAxis,
  restrictToWindowEdges, restrictToParent, restrictToFirstScrollableAncestor, restrictToElement,
  snapToGrid, snapCenterToCursor,
  pointerFirst, pointerWithin, closestCenter, closestCorners, rectIntersection,
} from '@vue-dnd-kit/core';

snapToGrid(20)                                            // Math.round от начала контейнера
snapToGrid({ x: 20, y: 10, smooth: { duration: 80 } })   // плавный доезд overlay
```

Модификаторы применяются один раз, и получившийся transform используется и overlay, и collision, поэтому они не расходятся. «Parent» означает контейнер списка, а не прямой DOM-родитель. Ось фиксируется относительно позиции на старте. В v2 она дрейфовала, потому что бралась от текущей позиции элемента.

- **Свои модификаторы у источника.** Кроме провайдера, `modifiers` есть у draggable, sortable-списка и элемента: они применяются к drag, начатым там, после модификаторов провайдера; модификаторы элемента главнее модификаторов списка. Так один вертикальный список на странице с канбаном держит элементы на оси, не заводя отдельный провайдер (который отрезал бы его от остальных списков). Значение, ref или геттер; читается в момент старта drag.
- `overlayRect` в аргументах модификатора — бокс overlay в том виде, как он показан, с текущим размером (раздел 7, `overlayFit`). `snapCenterToCursor` центрирует этот бокс.

## 5. Модель сортировки

1. **Старт.** Для группы создаются черновики (`shallowRef<Key[]>` на каждый список, новый массив на каждое изменение). Остальные выделенные элементы (в том числе из других списков) ведут себя по `multiple` списка, где начался drag:
   - `group` (по умолчанию): уходят со своих мест и встают вплотную к активному блоком плейсхолдеров в порядке drop (порядок документа). Пока идёт drag, список уже выглядит так, как после drop. Сами элементы FLIP'ом едут в блок.
   - `gaps`: остаются на местах (приглушённые, `data-dnd-dragging`) до drop, как в v2.
   - `stack`: убираются из черновиков, соседи схлопываются, а клоны элементов улетают в overlay (FLIP плюс fade).
   - В дереве убираются потомки активного узла (мульти-drag в дереве ведёт себя как `stack`).
2. **Движение.**
   - Проекция индекса (раздел 6) меняет черновик не чаще раза за кадр. Блок `group` проецируется как один элемент.
   - Перенос между списками атомарно меняет оба черновика за один тик.
   - Если список не принимает элементы (`put`), он подсвечивается как `isAccepting: false`, и элемент в него не входит.
   - Частичный приём (`group.put` с `acceptMode: 'some'`) виден уже при наведении: в блок входят только принятые элементы, остальные возвращаются на свои места. Если список не берёт сам активный элемент, показывается полный блок.
3. **Drop.** Сначала `onBeforeDrop` целевого списка или зоны. Возможные ответы:
   - `true`;
   - `false`;
   - массив ключей — частичный приём: принятые встают на место, отклонённые летят обратно;
   - `Promise`.

   Затем итог записывается в `Ref` каждого изменившегося списка, черновики сбрасываются. DOM совпадает с черновиком, поэтому лишнего движения нет. Overlay летит в итоговый слот, при необходимости меняя размер; при мульти-drag каждый клон в overlay садится в свой слот.
4. **Отказ, ошибка в колбэке (это тоже отказ, плюс `console.error`), cancel** (Escape, `pointercancel`, скрытие вкладки, размонтирование провайдера):
   - черновики откатываются, соседи FLIP'ом возвращаются;
   - overlay летит на исходное место, клоны остальных элементов — на свои;
   - в режиме `stack` собранные элементы вылетают из overlay обратно на свои места.

   **Изменение по сравнению с v2:** там `false` из async `onDrop` оставлял элемент «в руке» до следующего клика.
5. **Drop мимо всех зон** решается опцией `dropOutside`:
   - `placeholder` (по умолчанию в режиме `item`, как в Trello): элемент кладётся туда, где стоит плейсхолдер;
   - `cancel` (по умолчанию в режиме `indicator`);
   - `remove`.
6. **Корзина.** `e.source.remove()` в `onDrop` чужой зоны удаляет элементы из исходного `Ref`, overlay анимированно исчезает (scale + fade).
7. **Копирование.** Источник не меняется. В цель вставляется `clone(item)`; пока идёт drag, в черновике цели виден временный ключ. Включается через `pull: 'clone'` или клавишей `copyModifier` (по умолчанию Alt). Модификатор читается вживую во время drag, и плейсхолдер переключается между перемещением и копией.
8. **Извне.** Обычный draggable над списком с `createItem` получает временный элемент в черновике, он рендерится шаблоном пользователя как плейсхолдер. На drop элемент становится настоящим. `activeKey`/`activeIndex` списка указывают на этот временный элемент (и на копию при копировании), а стрелки двигают его по слотам списка, как обычный элемент.

Порядок вставки при множественном drag — исходный порядок в документе, а не порядок кликов (у dnd-kit в этом месте баг).

## 6. Стратегии и стабильность

**Общие защиты** (по опыту next-gen dnd-kit):
- Цель пересчитывается только при движении указателя или скролле, никогда из-за одного лишь сдвига layout.
- После перестановки целью считается сам активный слот.
- Гистерезис около 10px: недавно бывший целью элемент не может снова стать целью, пока указатель не сдвинется на 10px.
- Охранник «только что перенесли в другой список» на один кадр плюс «последняя валидная цель».
- Для hit-test берутся только смонтированные элементы, с прямоугольниками, обрезанными видимой областью их скролл-предков. Overscan-строки за краем не попадают. Пустой список — полноценная зона; в v2 пустые зоны никогда не считались видимыми.
- Регрессия v2.4.5 («уход курсора вбок телепортирует элемент в начало или конец списка») закреплена тестом: ближайший элемент ищется по расстоянию до прямоугольника.

**Стратегии:**
- **`vertical` / `horizontal`.** Правило пересечения середины по направлению движения: вниз — указатель ниже центра цели, вверх — выше. Устойчиво при разных размерах: после сдвига центр соседа уходит от указателя.
  - Кадры бывают редкими (быстрый свайп, загруженный поток, WebKit склеивает ввод), и указатель перескакивает элементы. Слот всё равно догоняет: он встаёт рядом с элементом под указателем, с той стороны его центра, где указатель.
  - Указатель в промежутке между двумя элементами того же списка (по главной оси) ставит слот между ними: он уже за центрами обоих. Промежутки рядом с активным слотом или блоком группы и место за смонтированными элементами (виртуализация) позицию не меняют.
- **`grid`.** Элемент под указателем плюс замок на элементе, который только что съехал (снимается, когда указатель его покидает). Работает и для разных размеров. Пустое место после последнего элемента означает «в конец».
- **`swap`.** Живой обмен активного с элементом под указателем, остальные стоят. Ушли с элемента — обмен откатывается. Для мульти-drag отключён (в v2 был групповой обмен, проходит в migration guide).
- **Вложенные sortable** (колонки канбана):
  - побеждает самый глубокий список;
  - у элементов приоритет выше, чем у контейнеров;
  - над непустым контейнером выбирается ближайший элемент, над пустым — вставка в начало или конец по середине.
- **Дерево.**
  - Глубина = `round(offsetX / indentation)` в пределах от глубины следующего элемента до глубины предыдущего + 1.
  - При `nesting: 'hover'` средняя полоса строки (25–75% высоты) означает «внутрь», края — до или после.
  - `canNest` и `maxDepth` понижают глубину до допустимой.

## 7. Плейсхолдер и overlay

- **`placeholder: 'item'`.** Активный элемент остаётся в списке с атрибутом `data-dnd-placeholder`. По умолчанию `:where([data-dnd-placeholder]) { opacity: .4 }`. Варианты:
  - пустое место: `visibility: hidden` в CSS;
  - свой компонент: `v-if="isPlaceholder"` внутри элемента;
  - линия: свой узкий плейсхолдер.
- **`placeholder: 'indicator'`.** Список не двигается. Для линии есть `indicator`: `{ key, side }` на элементе и `{ index }` на списке. `placement` на зонах служит для своих индикаторов при свободном drag. Можно не рендерить ничего.
- **Overlay.** Teleport в `overlayTo` (по умолчанию `body`), потому что `transform` строки или `contain` скроллера ломают `position: fixed`. `pointer-events: none`.
  - Клон снимается синхронно при старте, до перерисовки плейсхолдера, через `cloneNode(true)`, а не `outerHTML`, как было в v2.
  - Гигиена клона:
    - копируются `value` полей ввода и содержимое canvas;
    - у radio переименовываются `name`, удаляются `id` и `data-dnd-*`;
    - переносятся наследуемые стили (font, color, line-height), фон и CSS custom properties;
    - у sortable-элемента без собственного фона клон берёт первый непрозрачный фон предка (строки `v-list`, `v-data-table`, `UTable` иначе просвечивают); у свободных draggable так не делается, чтобы иконки и PNG не получали подложку;
    - `<tr>` оборачивается в таблицу.
  - Клон заполняет бокс overlay (100%), поэтому смена размера бокса перекладывает содержимое, а не растягивает его.
  - **Свой overlay.** По приоритету: компонент `overlay` элемента, затем списка или дерева, затем слот `#overlay` провайдера, затем клон. Слот, который для этого drag ничего не рендерит (`v-if` по типу), отдаёт место клону. Компонент получает `OverlayProps` — те же `{ active, items, over, accepted, status, mode }`. Через них можно ветвить вид по типу элемента и менять вид над зоной. Свой overlay обязателен для канбана и виртуализации, где исходник может размонтироваться.
  - Пока решённый drop анимируется, `over`/`accepted` в слоте — цель, на которую overlay садится (на момент drop); при отмене `null`.
  - **`overlayFit`.** По умолчанию `'slot'`: бокс принимает размер слота, куда сядет элемент (список с другими размерами элементов), и плавно меняет его за 150 мс прямо в цикле кадров, так что collision и модификаторы всегда видят показанный бокс. Бокс меняет размер вокруг точки захвата: доля, в которой указатель держит бокс, фиксируется на первом кадре, и курсор никогда не оказывается за пределами бокса. `'source'` — размер исходника.
  - **Мульти-drag.** В режимах `group` и `gaps` overlay показывает все элементы колонкой вдоль оси списка (в горизонтальном списке и сетке — рядом), с `gap` списка. Бокс остаётся размером активного элемента, остальные клоны стоят рядом с ним, поэтому точка захвата относится к активному. Клонов не больше 5: активный и 4 ближайших в порядке drop; остальные считаются бейджем «+N». В режиме `stack` — активный элемент с бейджем-счётчиком.
  - **`DragPreview`.** Компонент `<DragPreview :id="item.id" />` рендерит клон любого перетаскиваемого элемента внутри своего overlay: так строятся свои раскладки (веер, сетка). Для элементов без клона рендерится слот по умолчанию.

## 8. Анимации

- **FLIP-движок**, общий для всех слоёв:
  1. Снимок визуальных прямоугольников по ключу (pre-flush, с учётом идущей анимации).
  2. После post-flush: отменить свои анимации и CSS-переходы `transform`/`translate`, разом прочитать layout, затем WAAPI `translate: dx dy → 0`.
  3. Прерванная анимация стартует с текущей позиции.

  Анимируются только элементы, чей прямоугольник изменился и которые рядом с viewport. При `prefers-reduced-motion` длительность 0.
- **Drop.** Целевой элемент измеряется после коммита и `nextTick` и ещё раз через кадр: ResizeObserver виртуализатора может прийти позже. Его нет или он невидим — fade-out. Без `scrollIntoView` и без фокуса без `preventScroll`; dnd-kit с виртуальными списками на этом спотыкался.
  - Размер анимируется через width/height, никогда через `scale()`: содержимое перекладывается под новый размер, а не растягивается.
  - Мульти-drag: каждый клон в overlay анимируется относительно бокса с тем же таймингом и садится ровно в свой слот (вертикаль, горизонталь, сетка, другой список). Элементы без клона (сверх лимита, свой overlay) проявляются на месте из приглушённого состояния, а не выскакивают.
  - Сессия не может застрять в `dropping`: ожидание кадра ограничено 100 мс (кадров нет в скрытой вкладке и на перегруженном компоновщике), анимация — длительностью плюс 1 с.
- **Сбор группы.** При старте `group` остальные элементы FLIP'ом едут в блок, а их клоны собираются в колонку overlay.
- **Появление и исчезновение:** fade-in для элементов, смонтированных в результате DnD-изменения (возврат группы, копия); scale + fade для удаления в корзину.
- **Плавный snap:** короткая WAAPI-ступенька overlay между позициями сетки, collision работает по уже привязанному значению.
- **Своя анимация:** любой `animation` и `dropAnimation` принимает функцию `(ctx) => Animation | Promise<void> | void`. В документации будет рецепт для motion-v.

## 9. Виртуализация (контракт)

**Библиотека:**
- Черновик — всегда новый массив; переносы между списками атомарны.
- Идентичность только по `getKey`; `makeSortableItem({ id })` принимает getter.
- Интерруптибельный FLIP и `captureLayout()`. Пока ничего не происходит, он ничего не стоит.
- Цели FLIP и drop перепроверяются 1–2 кадра.
- Размонтирование активного или исходного элемента — штатная ситуация.
- Overlay в `body`.
- Автоскролл только относительными шагами (`scrollBy`). Во время drag на затронутых скроллерах `overflow-anchor: none`.
- `activeKey`, `activeIndex`, `activeSize` на каждом списке. `activeIndex` указывает на захваченный элемент, а в списке с копией или временным элементом — на них. Члены блока `group`, которые не отрендерены, всё равно едут вместе с ним.
- Опциональные хуки адаптера: `scrollToKey(key)` (клавиатура), `getVirtualRect(key)` (цель drop вне DOM).

**Пользователь:**
- Рендерит черновик `items` везде, в том числе в `count` и `getItemKey`.
- Ключует строки по id, а не по индексу. Обе документации, TanStack и VueUse, показывают индекс — это ловушка.
- TanStack: опции передаются как `computed`, который один раз читает `items.value` и создаёт внутри замыкания `getItemKey` и `rangeExtractor` (закрепление активной строки). Плюс `onChange: () => captureLayout()`. Без этого TanStack после перестановки отдаёт устаревшие позиции: проверено экспериментом.
- Overscan ≥ 5. Плейсхолдер того же размера, что элемент (для VueUse `itemHeight` должен быть точным).

В документации будут готовые рецепты для TanStack (список, сетка через `lanes`, колонки канбана) и для `useVirtualList`.

## 10. Сенсоры, клавиатура, доступность

- **Pointer Events.**
  - Учитываются `isPrimary` и `button === 0`, обрабатывается `pointercancel`. Отмена — на `visibilitychange` и Escape.
  - Drag не начинается с интерактивных потомков (input, button, select, textarea, contenteditable), кроме ручки или самого элемента.
  - Клик после drop подавляется, выделение текста блокируется.
  - Используется трюк с непассивным `touchmove` для iOS (в v2 эти слушатели были пассивными и ничего не делали). Нативный HTML5 drag на элементах отменяется.
  - Тач-события продолжают приходить на элемент, которого коснулся палец, даже если перенос в другой список его пересоздал. Поэтому `touchmove` блокируется и на самой цели касания, иначе браузер начинает панорамировать и шлёт `pointercancel`.
  - `selectstart` отменяется с момента нажатия: WebKit решает про выделение на `mousedown`, и начатое выделение само скроллит контейнер.
  - Во время pointer-drag `-webkit-touch-callout: none`: drag на таче стартует за 200 мс, раньше, чем iOS показывает меню ссылки и лупу (~500 мс).
- **Активация.** Мышь: 4px, а на ручке сразу. Тач: 200 мс с допуском 5px. Перо: 4px. Ограничения задаются на провайдере, списке или элементе. Задержка в миллисекундах; в v2 код считал её в секундах вопреки документации.
- **Клавиатура.**
  - Space/Enter берёт и кладёт, Escape отменяет. Клавиши переназначаются, автоповтор (`event.repeat`) игнорируется, в редактируемых полях клавиши не перехватываются.
  - В списках стрелки двигают на одну позицию. В канбане влево-вправо переносят в соседнюю колонку, в дереве меняют уровень, в сетке ищется ближайший элемент в следующем ряду.
  - При свободном drag стрелки двигают на 25px (Shift — быстрее) или переходят между подходящими зонами.
  - Фокус восстанавливается по ключу.
  - Слушатель клавиатуры работает в фазе capture и поглощает (`preventDefault` + `stopPropagation`) только те клавиши, на которые drag действует. Иначе UI-киты перехватывали их: кликабельный `v-list-item` съедал Space/Enter, `v-list` переводил фокус стрелками, а Escape закрывал `v-dialog` вокруг списка.
- **ARIA.**
  - `role="button"`, `tabindex="0"`, `aria-roledescription` (`draggable` или `sortable`);
  - `aria-describedby` указывает на инструкции;
  - `aria-pressed` во время drag, `aria-disabled`.

  Заданное пользователем не перезаписывается. Исключение — `aria-describedby`: id инструкций добавляется к существующему значению отдельным токеном и при очистке убирается только он. Тултипы UI-китов (Vuetify, Reka) ставят на активатор свой `aria-describedby`, и без этого ссылка на инструкции терялась.
- **Анонсы.** Английские, с позициями («Item X moved to position 3 of 8 in list A»). Анонсы перемещения debounce'ятся на 500 мс. Переопределяются пропом. Свой анонс, вернувший `undefined`, передаёт слово следующему источнику (анонсы интеграций, затем стандартные); тишина — пустая строка `''`.

## 11. Автоскролл

- Включён по умолчанию, настраивается на провайдере и списке. Наружу отдаётся `isAutoScrolling`.
- Один rAF-цикл. Скроллеры выбираются от элемента под указателем изнутри наружу, последним идёт окно.
- Порог — 20% размера контейнера, но не меньше 24px и не больше 96px. Скорость ограничена; шаг — `scrollBy` с поправкой на длительность кадра.
- Допуск по поперечной оси 10px: указатель сбоку от контейнера его не скроллит.
- Блок по намерению: направление разрешается только после движения в эту сторону, так что элемент, взятый у края, не уезжает сам.
- Скролл двигает кэшированные прямоугольники через scroll-delta, без перемера.
- На скроллерах со `scroll-snap-type` снаппинг отключается с первого шага автоскролла до конца drag: Chromium снаппит каждый программный `scrollBy` (при `mandatory` — колонку за кадр). Возврат стиля снова снаппит к ближайшей позиции до того, как drop-анимация измерит цель.
- При клавиатурном drag скроллится сама цель: через `scrollToKey` для виртуальных списков, иначе вручную, без `scrollIntoView`.

## 12. Производительность

- Черновики в `shallowRef`, не больше одной мутации за кадр. Пользовательские данные не обходятся глубоко, для больших массивов рекомендуем `shallowRef`.
- Прямоугольники кэшируются на время drag и инвалидируются только у изменившихся списков. Скролл учитывается через scroll-delta. Все чтения DOM — одним проходом за кадр.
- Фильтры collision линейные: в v2 они были O(N²).
- **Бенчмарки в Playwright:**
  - сценарии: 500 элементов без виртуализации, 5k в канбане, 50k с TanStack;
  - метрики: время кадра, long tasks, время перерисовки Vue при перестановке;
  - главный риск — стоимость перерисовки Vue по сравнению с прямыми перемещениями DOM, как у dnd-kit. Если не уложимся, план Б — keyed-перемещение только затронутого диапазона.

## 13. Инварианты надёжности

- Одна активная сессия на провайдер. Ввод во время `dropping` игнорируется.
- Каждый путь выхода (drop, отказ, cancel, ошибка в колбэке, `pointercancel`, скрытие вкладки, размонтирование провайдера) возвращает DOM в исходное состояние (стили body, `overflow-anchor`, слушатели) и эмитит **ровно одно** завершающее событие.
- Стили страницы (`touch-action`, `overscroll-behavior`, `user-select`) не перезаписываются вслепую: сохраняются и восстанавливаются только те, что меняли мы. В v2 их затирал любой `mouseup` на странице.
- Реестры чистятся при размонтировании. Выделение хранится по id и переживает размонтирование (виртуализация); ключи, которых уже нет в данных, отфильтровываются при старте drag.
- Компоненты в данных (`render`, слоты) не делаются reactive (`markRaw`).
- Рукописных `.d.ts` нет: все типы живут в `.ts` и проверяются полностью. В v2 в рукописных `.d.ts` были пропущены импорты `Component` и `IPlacement`, и типы молча превращались в `any`. `skipLibCheck: true` нужен только из-за `.d.ts` VueUse 15 (ссылается на Web Bluetooth и Temporal). Регрессии публичных типов ловит `src/types.test.ts`.
- Опции, которые библиотека только читает, типизированы как `MaybeReadonlyRefOrGetter<T>`: принимают readonly-ref из `useTemplateRef`, computed, геттер и `Ref<string>` там, где ожидается `string | number`. Vue-шный `MaybeRefOrGetter` последние два случая не принимает.
- Ссылка на элемент (`MaybeElement`) принимает всё, у чего есть `$el`, а не полный тип экземпляра компонента: иначе `vue-tsc` отвергал ссылки на компоненты UI-китов с типизированными emits (`VListItem`, `UTooltip`). Компонент с fragment-корнем разрешается в первый элемент внутри фрагмента и никогда не выходит за его конец (на соседний элемент).
- Id по умолчанию у draggable, зон, списков и деревьев — `useId()`: одинаковый на сервере и клиенте. Вне компонента (отдельный `effectScope`) — счётчик модуля.

## 14. Миграция с v2

**Ключевое соответствие:**

| v2 | v3 |
|---|---|
| `makeDraggable(ref, opts, () => [index, items])` + `onDrop` с `helpers.suggestSort` | `makeSortableList` + `makeSortableItem`: результат пишется в `Ref`, обработчик не нужен |
| `suggestSwap` / `suggestCopy` / `suggestRemove` | `behavior: 'swap'` / `group.pull: 'clone'` + `clone` / корзина `e.source.remove()` |
| `groups`, `groupMatch`, `onValidate` | `type` / `accept` (`group.put`) / `acceptMode`, частичный приём в `onBeforeDrop` |
| `makeConstraintArea` | модификаторы `restrictToElement`, `restrictToParent`, `restrictTo*Axis` |
| `makeAutoScroll`, `autoScrollViewport` | встроенный автоскролл, `autoScroll` на провайдере и списке |
| `DragPreview`, `render`, `preview.render` | клон по умолчанию + слот `#overlay` / опция `overlay: Component` с `items`, `over`, `accepted`; `<DragPreview :id>` — клон одного элемента для своих раскладок |
| `useDnDProvider()` (внутренние Map) | `useDnD()` (только чтение) + `useDnDMonitor()` |
| `modifier` (drag с зажатой клавишей) | `canDrag: (e) => …` |
| `delay.progress`, `distanceProgress` | `useDnD().activation.progress` |
| `injectionKey` (Shadow DOM) | `provideDnDContext` / `useDnDContext` |
| `previewTo` | `overlayTo` |
| `@vue-dnd-kit/utilities` (snap) | модификатор `snapToGrid` |
| `isDragOver` (placement) на draggable | `indicator` у sortable, `placement` у `makeDroppable` |

**Изменения поведения, которые guide должен назвать явно:**
1. `false` из async-обработчика означает анимированный возврат, а не продолжение drag.
2. Drop мимо зон по умолчанию кладёт элемент в плейсхолдер (`dropOutside`). В v2 это считалось успешным drop без цели.
3. Drag начинается после 4px, на таче после 200 мс; раньше начинался сразу.
4. Задержка активации в мс, как и обещала документация; код v2 считал секунды.
5. Выделение больше не сбрасывается при старте drag и привязано к id.
6. Swap при мульти-drag отключён.
7. Клавиатура двигает по элементам, а не по пикселям (кроме свободного drag).
8. Мульти-drag по умолчанию `multiple: 'group'`: выделенные элементы уходят со своих мест и едут блоком. Поведение v2 (элементы стоят на местах, overlay показывает все) — `multiple: 'gaps'`.

**Убрано:** `DragPreview` v2 (рендер overlay) и `DefaultOverlay`, `collision.throttle` (rAF-батчинг), внутренний конструктор сенсоров, payload-фабрики `[index, items]`. Имя `DragPreview` в v3 занято другим компонентом (клон одного элемента, раздел 7).

Guide описывает **реальное** поведение v2, а не задокументированное: аудит нашёл около 30 расхождений документации с кодом.

**Примеры документации** (подробная таблица в `v2-parity.md` §3):
- около 8 станут тривиальными: сортировка, swap, копирование, группы, ручка, disabled, базовые зоны, snap;
- около 6 устарели или сливаются;
- 14 новых: горизонтальный список, сетки, извне в список, корзина, режимы плейсхолдера, стопка или пробелы, возврат при отказе, TanStack, правила приёма, вложенные sortable в 3 уровня, строки таблиц, Nuxt-стартер, анонсы.

Регресс-тест для Shadow DOM из playground сохраняется.

## 16. Решения по открытым вопросам (24.10.2026)

1. **Движок:** свой. Удачные решения dnd-kit берём как идеи, без зависимости.
2. **Группы:** `group` в стиле SortableJS (`name`/`pull`/`put`) у списков, `type`/`accept`/`acceptMode` у низкоуровневых зон.
3. **Стили по умолчанию:** `:where()`-стили в рантайме, выключаются `defaultStyles: false`.
4. **TanStack:** рецепт в документации с `captureLayout` в `onChange`, без отдельного хелпера и без зависимости.
5. **Drop мимо зон:** по умолчанию `placeholder` (как в Trello); в режиме `indicator` — `cancel`.
6. **Дерево:** по умолчанию `nesting: 'both'`.
7. **RFC:** хранится в репозитории, `rfcs/0001-v3.md`, исследования — в `rfcs/0001-v3/`.

**Решения от 25.10.2026:**

8. **Overlay по размеру слота:** `overlayFit: 'slot'` по умолчанию, `'source'` — опция. Drop анимирует width/height, без `scale()`. При смене размера точка захвата сохраняется пропорционально.
9. **Id:** по умолчанию `useId()`; `id` остаётся опциональным. `makeSortableItem` принимает `{ item }` (ключ через `getKey` списка) или `{ id }`.
10. **Свой overlay:** опция `overlay: Component` у draggable, элемента, списка и дерева, поверх слота `#overlay` провайдера.
11. **UI-киты:** проверяем совместимость на Nuxt UI / Reka UI и Vuetify, с e2e.
12. **Размер:** оптимизация без смены API, затем реальные бюджеты size-limit в CI.
13. **Мульти-drag:** новый режим `group` по умолчанию (превью результата), overlay показывает все элементы колонкой; `gaps` — как в v2; `stack` — карточка со счётчиком. Вид настраивается своим overlay и `DragPreview`.
14. **Состояние drag заканчивается, когда drop решён,** а не когда overlay сел (раздел 3).
15. **Модификаторы у источника:** `modifiers` у draggable, списка и элемента (раздел 4.6). В примерах таблица и одиночные списки зафиксированы по оси.
16. **Фон клона:** sortable-элемент без фона берёт фон предка — оставляем.
17. **`aria-describedby`:** id инструкций добавляется токеном к существующему значению.
18. **Мелкие API-пункты:** обычный курсор и выделение, пока async `onBeforeDrop` решает; `undefined` из своего анонса — откат к следующему источнику, `''` — тишина; dev-предупреждение о двух `makeSortableList` в одном компоненте; стрелки двигают внешний draggable по слотам списка.
