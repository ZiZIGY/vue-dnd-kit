Documentação/Guias

Estilização

Cada estado de um arraste, estilizado — atributos data para CSS puro, refs para classes, alvos que dizem sim ou não, o overlay e a página durante o arraste, os estilos padrão, Tailwind e UI kits.

Editar esta página

A página em inglês mudou desde esta tradução. O original está atualizado. Ler o original em inglês

A biblioteca estiliza quase nada. Cada estado de um arraste chega até você de duas formas: como um atributo data-dnd-*, para CSS puro, e como um ref que o composable retorna, para classes e marcação condicional. Use o que combinar com a sua stack, ou os dois.

Os atributos data

As linhas abaixo não têm nenhuma classe de estado: todo visual vem de um atributo. O painel lista os atributos da página conforme eles aparecem e somem. Selecione duas linhas com Ctrl ou Meta e arraste-as: os outros de um multi-drag também aparecem.

AtributoEmQuando
data-dnd-placeholderum item ordenávelEle é a posição em que um item arrastado vai pousar. "into" enquanto o arraste está sobre um alvo de drop dentro de um item: o drop vai para lá, e a posição só guarda o seu lugar.
data-dnd-draggingum item ordenávelEle é arrastado, mas fica no lugar: os outros itens de um multi-drag no modo 'gaps'.
data-dnd-dragging="pointer" ou "keyboard"<html>Durante todo o arraste.
data-dnd-overlay="dragging" ou "dropping"a caixa do overlaySempre. dropping enquanto ela pousa, e enquanto um onBeforeDrop assíncrono espera.
data-dnd-overlay-contento conteúdo do overlaySempre: o elemento que preenche a caixa e contém o que ela mostra. Animá-lo fica por sua conta; ele recebe o overlayClass do provider.
data-dnd-leavinguma cópia deixada por animateEnquanto um item que saiu desaparece aos poucos.
data-dnd-no-clonedefinido por vocêDeixa o elemento fora da cópia do overlay: um tooltip, um menu, um selo.
TaskRow.vue
/* The slot a dragged row will land in: a striped gap. */
.row[data-dnd-placeholder] {
  opacity: 1;
  background: repeating-linear-gradient(-45deg, color-mix(in srgb, #42b883 16%, transparent) 0 6px, transparent 6px 12px);
}

.row[data-dnd-placeholder] > * {
  visibility: hidden;   /* an empty slot of the row's exact size */
}

/* Selected rows left in place by a multi-drag (`multiple: 'gaps'`). */
.row[data-dnd-dragging] {
  opacity: 0.4;
}

/* The copy in the overlay, while it travels. */
[data-dnd-overlay='dragging'] .row {
  box-shadow: 0 0 0 1.5px #42b883, 0 14px 24px -10px rgb(0 0 0 / 0.55);
}
TaskRow.vue
<li ref="el" class="row" :aria-selected="selected">
  <span class="title">{{ task.title }}</span>
  <button type="button" data-dnd-no-clone @click.stop="task.done = !task.done">✓</button>
</li>
  • A cópia de uma linha no overlay mantém as classes e os atributos dela, incluindo o atributo de escopo do Vue, então [data-dnd-overlay] .row funciona no próprio <style scoped> da linha. A cópia não tem marcas data-dnd-* próprias: uma cópia da posição não é uma posição.
  • A seleção não tem atributo. Espelhe o ref selected em um (aria-selected acima), ou use uma classe.
  • Draggables simples e alvos de drop (makeDraggable, makeDroppable) não recebem atributos de estado data-dnd-*: estilize-os com os refs deles.

makeSortableItemisDragging, isPlaceholder, selected, indicator, index
makeSortableList, makeSortableTreeisOver, isAccepting, indicator, activeKey, activeIndex

  • isPlaceholder: este elemento é a posição em que um item arrastado vai pousar. Em um multi-drag no modo 'group', as posições dos itens que viajam junto também são placeholders.
  • isDragging: o item faz parte do arraste: todos os itens arrastados em um multi-drag.
  • isAccepting: algo está sendo arrastado, e este alvo o aceita. Destaque os lugares onde um drop é possível.
  • isOver: o arraste está sobre este alvo, aceitando-o ou não. isOver && !isAccepting é uma recusa: mostre-a.
  • indicator: onde fica a linha de drop no modo indicador.
  • activation.progress: de 0 a 1 enquanto corre um toque longo ou um delay. Preencha um anel com ele.

Alvos de drop: sim e não

Um alvo tem quatro visuais durante um arraste: ele aceita o arraste; aceita e o ponteiro está sobre ele; recusa; recusa e o ponteiro está sobre ele. Mostre os quatro, e diga isso também no item arrastado.

O overlay e a página

Dois atributos cobrem o resto de um arraste: data-dnd-overlay na caixa do overlay, e data-dnd-dragging no <html>, "pointer" ou "keyboard". A barra acima das notas lê o segundo e diz quais teclas funcionam. Ligue o salvamento lento: o overlay fica em dropping onde você soltou, até o onBeforeDrop resolver, e mostra isso.

  • dropping cobre o pouso e a espera de um onBeforeDrop assíncrono. Enquanto ele espera, o <html> sai do modo de arraste: o cursor e a seleção de texto da página voltam, então um diálogo de confirmação funciona como sempre.
  • Estilize o que está dentro da caixa. A biblioteca move a própria caixa com transform e a dimensiona com width e height. O elemento de conteúdo dela, [data-dnd-overlay-content], a preenche e é seu: erga e incline o overlay inteiro ali (veja animações).
  • A raiz da cópia tem transform: none inline: gire-a ou aumente-a com rotate e scale. Transições e keyframes rodam nela: veja animações.
  • A cópia mostra o elemento como ele é e não adivinha fundo nenhum. Uma linha que a lista pinta (um <li> em um <ul> branco, uma linha de tabela) precisa de um: [data-dnd-overlay] .row { background: Canvas; }.
  • A cópia fica em uma <div> que carrega as custom properties que o elemento herdava (cores do tema, --tw-*), então elas continuam valendo no overlay, e as regras da própria cópia (in-data-[dnd-overlay]:ring-2) ainda vencem. Selecione a cópia pela classe, não pela profundidade dela na caixa.

Estilos padrão

O provider injeta algumas regras uma vez por documento. Elas ficam dentro de :where(), então a especificidade delas é zero e qualquer regra sua vence:

:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging]), :where(html[data-dnd-dragging] *) {
  user-select: none !important;
  overflow-anchor: none !important;
}
:where(html[data-dnd-dragging='pointer']), :where(html[data-dnd-dragging='pointer'] *) {
  cursor: var(--dnd-cursor, grabbing) !important;
  -webkit-touch-callout: none !important;
}
RegraPor quê
A posição a 40%Para que uma lista fique certa sem CSS nenhum. Todas as demos acima a sobrescrevem.
Itens deixados para trás a 40%O mesmo, para um multi-drag no modo 'gaps'.
Sem user-selectUm arraste não seleciona o texto pelo qual passa.
Sem overflow-anchorA página não rola para manter uma linha em movimento à vista.
O cursor do arrasteDurante um arraste por ponteiro, em todo lugar. grabbing, a menos que o elemento pego tenha um cursor próprio: o ns-resize de uma alça de redimensionar, um move, uma imagem mantêm o seu durante todo o arraste (grab, pointer e afins ainda viram grabbing). cursor: grab nos itens arrastáveis fica por sua conta. Defina --dnd-cursor no <html> para outro padrão.
Sem touch calloutO iOS não abre o menu de link sob um toque longo.

:default-styles="false" no provider as deixa de fora. A biblioteca ainda marca o <html>, e ainda limpa a seleção quando um arraste começa e impede novas seleções até ele terminar: só o CSS some. As regras são injetadas uma vez, pelo primeiro provider que as quer, e ficam: desligue-as em todos os providers da página.

<DnDProvider :default-styles="false">

Tailwind CSS

Os atributos funcionam como variantes: data-[…] para o próprio elemento, uma variante arbitrária para um ancestral.

TaskRow.vue
<li
  ref="el"
  class="rounded-lg bg-white shadow-sm
         data-[dnd-placeholder]:bg-transparent data-[dnd-placeholder]:opacity-100
         data-[dnd-placeholder]:outline-dashed
         [[data-dnd-overlay=dragging]_&]:shadow-xl"
  :class="{ 'ring-2 ring-emerald-500': selected }"
>
Hint.vue
<p class="hidden [html[data-dnd-dragging=keyboard]_&]:block">Arrows move · Space drops</p>
Os visuais da biblioteca (as opacidades de 40%) ficam em uma cascade layer própria, vue-dnd-kit, declarada antes de qualquer outra. Os utilitários do Tailwind v4 e os UI kits feitos com ele também vivem em layers, e as deles vêm depois, então vencem sem !. CSS fora de layers vence de qualquer jeito.

No Tailwind v4, in-data-[dnd-overlay=dragging]:shadow-xl é um jeito mais curto de escrever a variante de ancestral.

No CSS scoped do Vue, :global() pega o seletor inteiro: :global(html[data-dnd-dragging]) .hint compila só para html[data-dnd-dragging], e esconde a página. Escreva o ancestral sem ele, html[data-dnd-dragging] .hint: o Vue aplica o escopo só à última parte.

UI kits

  • Os composables aceitam um componente assim como um elemento: useTemplateRef no card ou no item de lista de um kit funciona, e a biblioteca lê o elemento raiz dele.
  • Passe o estado para as props do próprio kit quando ele as tiver (:active="selected", :color="isOver ? 'primary' : undefined"), e o resto como classes.
  • Os itens de lista de um kit muitas vezes não têm fundo próprio: a lista o pinta. A cópia deles no overlay fica então transparente. Dê um fundo a ela:
    [data-dnd-overlay] .v-list-item { background: rgb(var(--v-theme-surface)); }
  • A cópia deixa de fora os ripples de pressão do Vuetify, Quasar, PrimeVue e Naive UI. Marque qualquer outra coisa que não deve viajar, um tooltip ou um botão de menu, com data-dnd-no-clone.

O que não fazer

  • Não coloque um transition CSS em transform ou translate de itens ordenáveis: a biblioteca os anima ela mesma, e cancela essas transições enquanto mede.
  • Não envolva itens ordenáveis em <TransitionGroup>: os movimentos seriam animados duas vezes. Use o animate da lista.
  • Não anime height, margin ou padding de linhas em uma lista virtual.
  • Desligue as transições que você adiciona em volta dos arrastes sob prefers-reduced-motion: reduce. A biblioteca já desliga as dela.
