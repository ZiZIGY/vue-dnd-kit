Dokumentation/Leitfäden

Animationen

Elemente gleiten beim Sortieren, der Drop landet auf seinem Slot, und auch Datenänderungen können animiert werden. Stimme jede davon ab, animiere Overlay, Slot und Listen mit CSS oder bring motion oder GSAP mit.

Diese Seite bearbeiten

Diese Seite wurde von KI übersetzt und kann Ungenauigkeiten enthalten. Englisches Original lesen

Drei Dinge animieren von selbst: die Elemente, die beim Sortieren gleiten, das Overlay, das beim Drop landet, und, wenn du es einschaltest, die Änderungen deiner Daten, die kein Drag gemacht hat. Jedes davon nimmt dieselben Werte, am Provider oder näher an dem, was es animiert:

OptionWoStandardWas sie animiert
animationProvider, Liste, Bauman, 200 msElemente, die beim Sortieren, beim Drop und beim Abbrechen an ihre neuen Plätze gleiten.
dropAnimationProvider, ziehbares Element, sortierbares Element, Liste, Baum (overDropAnimation an einem Drop-Ziel)an, 250 msDas Overlay, das auf seinem Slot landet oder beim Abbrechen zurückfliegt.
animateChangesProvider, Liste, BaumausÄnderungen deiner Daten, die kein Drag gemacht hat: hinzugefügte, entfernte, verschobene oder herausgefilterte Elemente, ein- oder ausgeblendete Baumzeilen.

Jede nimmt true (das Standard-Timing), false (aus), { duration, easing } oder eine Funktion, die sie selbst animiert:

<DnDProvider
  :animation="{ duration: 180, easing: 'cubic-bezier(.2, .8, .2, 1)' }"
  :drop-animation="{ duration: 300 }"
  animate-changes
>

Die eigenen animation und animateChanges einer Liste oder eines Baums gewinnen gegen die des Providers; zu dropAnimation siehe Pro Element und pro Ziel. Der Rest der Bewegung gehört dir: Das Overlay, der Slot und die Listen sind Elemente mit Data-Attributen und Refs, und CSS oder eine Animationsbibliothek bewegt sie.

const springy: LayoutAnimation = ({ element, from, to, reducedMotion }) => {
  if (reducedMotion) return;
  return element.animate(
    [{ translate: `${from.left - to.left}px ${from.top - to.top}px` }, { translate: '0 0' }],
    { duration: 500, easing: 'cubic-bezier(.34, 1.56, .64, 1)' },

  dropAnimation,

Es ist FLIP auf der CSS-Eigenschaft translate, über die Web Animations API. translate kombiniert sich mit jedem deiner transform, die Zeilenpositionierung einer virtuellen Liste bleibt also intakt. Wenn sich ein Element erneut bewegt, bevor seine Animation endet, startet die nächste dort, wo es gerade angezeigt wird. Dieselbe Animation bewegt die Elemente beim Drop und beim Abbrechen.

Die animation der Liste nimmt einen Wert oder ein Ref, gelesen bei jeder Bewegung: Ein Ref schaltet sie um, wie oben. Eine Funktion ist dort eine Animation, kein Getter.

Umschließe sortierbare Elemente nicht mit <TransitionGroup>: Jede Bewegung würde doppelt animiert. Für Änderungen, die kein Drag gemacht hat, schalte animateChanges ein.

Der Drop

Beim Drop fliegt das Overlay von dort, wo du losgelassen hast, zum Slot des Elements; beim Abbrechen zurück dorthin, wo das Element gestartet ist. Wähle in der Hand oben eine dropAnimation, ziehe dann eine Karte vom Tisch und lass los: Der Drop wird abgebrochen, und sie fliegt zurück. toss ist eine eigene Funktion:

Hand.vue
/** The overlay arcs to its slot, as if tossed. */
const toss: DropAnimation = ({ overlay, from, to, reducedMotion }) => {
  if (reducedMotion) return;
  // No visible slot to land on: fade out where it is.
  if (!to) return overlay.animate([{ opacity: 1 }, { opacity: 0 }], { duration: 200, fill: 'forwards' });
  const place = (x: number, y: number) => `translate3d(${x}px, ${y}px, 0)`;
  const rise = Math.min(120, Math.hypot(to.left - from.left, to.top - from.top) / 2);
  return overlay.animate(
    [
      { transform: place(from.left, from.top), width: `${from.width}px`, height: `${from.height}px` },
      { transform: place((from.left + to.left) / 2, Math.min(from.top, to.top) - rise), offset: 0.45 },
      { transform: place(to.left, to.top), width: `${to.width}px`, height: `${to.height}px` },
    ],
    { duration: 550, easing: 'ease-in-out', fill: 'forwards' },
  );
};

Die Hand gibt sie ihrer Liste. Am Provider lässt sie jeden Drag landen:

<DnDProvider :drop-animation="toss">
  • Die Box landet mit ihrer Position (transform) und ihrer Größe (width, height): Der Inhalt ordnet sich in der Größe des Slots neu an, nie skaliert.
  • Wenn das Element nach dem Drop keinen sichtbaren Slot hat (weggescrollt oder in einen Ordner oder eine Papierkorb-Zone abgelegt), ist to null. Der Standard blendet das Overlay dann aus und lässt es in die Zone schrumpfen, auf die es abgelegt wurde (into), oder an Ort und Stelle.
  • Bei einem Multi-Drag landen die Klone der anderen Elemente von selbst auf ihren eigenen Slots, mit dem Standard-Timing, wenn dropAnimation eine Funktion ist. In eine Zone gehen sie einer nach dem anderen hinein, und die Box nach ihnen (siehe die Dateien und Ordner).
  • dropAnimation wird bei jedem Drop gelesen: Ein Ref schaltet sie für den nächsten um, wie in der Hand, und ebenso eine an ein Ref gebundene Prop des Providers.
  • Scrollen, während es landet, bringt es nicht vom Kurs ab. Die Box ist position: fixed, sie folgt also dem, worauf sie landet (dem Slot, der Zone, sonst dem Ziel, auf dem sie abgelegt wurde), mit ihrem CSS-translate, zusätzlich zu dem transform, das die Animation bewegt. Animiere in deiner eigenen Animation, wie oben, transform und nicht translate.
  • Der nächste Drag wartet nicht: Jeder Drop landet in einer eigenen Box, während neue Drags laufen. Ein Drücken auf eine landende Box fängt sie im Flug, und der Drag geht von dort weiter, wo sie gerade ist. onDragSettle sagt dir, wann das Overlay eines Drags angekommen ist: Dann schließt der Papierkorb unten seinen Deckel.

Das Overlay nimmt beim Ziehen außerdem die Größe des Slots an, in dem es landen wird (overlayFit: 'slot', der Standard), ein Drop braucht also selten eine Größenänderung. Siehe Das Overlay.

Pro Element und pro Ziel

Die dropAnimation des Providers ist der Standard. Ein ziehbares Element, ein sortierbares Element oder eine Liste (für ihre Elemente) können ihre eigene mitbringen, und ein Drop-Ziel kann das letzte Wort darüber haben, was in ihm landet: makeDroppable(el, { overDropAnimation }), die overDropAnimation einer Liste oder eines Baums. Für jeden Drop gilt die erste, die gesetzt ist:

  1. Die des Ziels (keine beim Abbrechen).
  2. Die eigene des gezogenen Elements.
  3. Die seiner Liste.
  4. Die des Providers.

Unten setzen der Warenkorb, die Vase und das Regal jeweils eine. Das Regal lässt seine Produkte mit einem Federn landen, die Vase hat eine eigene langsame Landung, und der Warenkorb nimmt, was auf ihm abgelegt wird, in sein Symbol auf: Das Produkt bleibt in seinem Regal, sein Slot dort ist also kein Ort zum Landen. Unter dem Regal leuchtet die auf, mit der jeder Drag landet.

const intoCart: DropAnimation = ({ overlay, from, reducedMotion }) => {
  const end = icon.value?.getBoundingClientRect();
  if (!end || reducedMotion) return;
  // Into the icon, shrinking: the box scales around its top left corner.
  const scale = end.height / from.height;
  const animation = overlay.animate(

        opacity: 0,
      },
    ],

  );
  animation.finished.then(() => landed.value++, () => {}); // the icon bounces
  return animation;
};

false zählt als gesetzt: Ein Ziel mit overDropAnimation: false lässt das Overlay dort, wo es abgelegt wurde. Die Funktion bekommt das Ziel als over, so kann eine einzige Funktion Ziele unterschiedlich behandeln.

Standardmäßig aus, animiert animateChanges, was dein Array ohne einen Drag ändert: ein Sortieren, ein Mischen, ein Verschieben zwischen Listen einer Gruppe, ein hinzugefügtes, entferntes oder herausgefiltertes Element. In einem Baum deckt es auch die Zeilen ab, die ein Knoten beim Auf- und Zuklappen zeigt oder verbirgt. <DnDProvider animate-changes> schaltet es für jede Liste und jeden Baum ein.

Seine Teile lassen sich einzeln abstimmen:

animateChanges: { duration: 250, move: true, enter: true, leave: { duration: 150 } },
TeilStandardmäßig
moveElemente, die den Platz gewechselt haben, gleiten, wie bei animation.
enterElemente, die erschienen sind, blenden sich an ihrem Platz ein.
leaveEine Kopie des Elements, das gegangen ist, blendet sich dort aus, wo es war, und schrumpft ein wenig. Sie ist mit data-dnd-leaving markiert und wird entfernt, wenn sie fertig ist.

duration und easing gelten für jeden Teil; jeder Teil nimmt true, Optionen, false oder eine Funktion. Nur Elemente in der Nähe des sichtbaren Bereichs animieren, Zeilen, die eine virtuelle Liste nicht gemountet hat, werden also übersprungen. Die Option wird gelesen, wenn sich items ändert, ein Ref kann sie also umschalten, wie es der Schalter der Demo tut.

Das Overlay: anheben, neigen, ablegen

Die Box des Overlays sagt, was sie gerade tut: data-dnd-overlay="dragging", während sie dem Zeiger folgt, "dropping", während sie landet. Die Bibliothek bewegt die Box und bestimmt ihre Größe. Darin hält data-dnd-overlay-content alles, was das Overlay zeigt – einen Klon oder einen ganzen Stapel –, und das animierst du. Nimm einen Kandidaten auf: Das Overlay hebt sich und neigt sich; lass los: Es legt sich beim Landen wieder flach.

Eigene Animationen

Jede Option nimmt auch eine Funktion. Sie bekommt einen Kontext, startet die Animation und gibt ihre Animation zurück, ein Promise, das sich erfüllt, wenn sie endet, oder nichts. Der Drag endet, wenn die Drop-Animation endet, und eine Kopie, die geht, wird entfernt, wenn ihre Animation endet, aber keines von beiden wartet länger als eine Sekunde über options.duration hinaus (250 ms für den Drop, 200 ms für die anderen).

// animation, animateChanges.move: an item moved from `from` to `to`
({ key, element, from, to, options, reason, signal, reducedMotion }) => Animation | Promise | void
// dropAnimation: `to` is null when there is no visible slot; `into` is the zone it went into
({ overlay, from, to, into, reason, active, options, reducedMotion }) => …
// animateChanges.enter: the element is already in place
({ key, element, to, options, reducedMotion }) => …
// animateChanges.leave: `element` is a copy where the item was, removed when you finish
({ key, element, from, options, reducedMotion }) => …

reason sagt, warum: 'drag' oder 'change' für eine Bewegung, 'drop' oder 'cancel' für das Overlay. options enthält das Timing der Option, eine Funktion kann also der duration folgen, die du daneben setzt.

Drei Regeln halten eigene Animationen im Takt mit der Bibliothek:

  • Animiere translate von from - to auf null, nicht transform. Es kombiniert sich mit Transforms, die virtuelle Listen oder dein CSS auf Zeilen setzen, und Drags messen Elemente ohne es.
  • Beachte signal. Es bricht ab, wenn sich das Element erneut bewegt, bevor die Animation endet. Stoppe deine Animation und entferne ihre Stile sofort: Das Layout wird direkt danach gemessen. Eine zurückgegebene Animation wird für dich abgebrochen.
  • Lande auf einem Slot mit Position und Größe (width, height), nicht mit scale: Der Inhalt des Overlays ordnet sich in der Größe des Slots neu an. Wo es keinen Slot zum Landen gibt, ist Schrumpfen in Ordnung: Der Standard verkleinert das Overlay in die Zone (into), der Warenkorb oben in sein Symbol.

motion

Die Girlande unten läuft mit motion: Die Fähnchen und der Drop federn über die Funktionen des Providers, und die Overlay-Komponente schwingt mit der Geschwindigkeit des Zeigers.

<script setup lang="ts">
import { animate } from 'motion-v';
import { DnDProvider, type DropAnimationContext, type LayoutAnimationContext } from '@vue-dnd-kit/core';
import Garland from './Garland.vue';

const spring = { type: 'spring', duration: 0.5, bounce: 0.3 } as const;

/** Flags spring to their new places, on the CSS `translate` property. */
const move = ({ element, from, to, signal, reducedMotion }: LayoutAnimationContext) => {
  if (reducedMotion) return;
  const controls = animate(element, { translate: [`${from.left - to.left}px ${from.top - to.top}px`, '0px 0px'] }, spring);
  // The flag moves again before it arrives: stop and clear at once, the library measures next.
  signal.addEventListener('abort', () => {
    controls.stop();
    element.style.translate = '';
  });
  return controls.finished;
};

/** The overlay springs onto its slot: its position and its size. */
const drop = ({ overlay, from, to, reducedMotion }: DropAnimationContext) => {
  if (reducedMotion) return;

GSAP

gsap-animations.ts
import gsap from 'gsap';
import type {
  DropAnimationContext,
  EnterAnimationContext,
  LayoutAnimationContext,
  LeaveAnimationContext,
  Rect,
} from '@vue-dnd-kit/core';

const move = ({ element, from, to, signal, reducedMotion }: LayoutAnimationContext) => {
  if (reducedMotion) return;
  const tween = gsap.fromTo(
    element,
    { translate: `${from.left - to.left}px ${from.top - to.top}px` },
    { translate: '0px 0px', duration: 0.4, ease: 'power3.out' },
  );
  signal.addEventListener('abort', () => tween.revert());
  return tween.then();
};

const box = (rect: Rect) => ({ x: rect.left, y: rect.top, width: rect.width, height: rect.height });

const drop = ({ overlay, from, to, reducedMotion }: DropAnimationContext) => {
  if (reducedMotion) return;
  if (!to) return gsap.to(overlay, { opacity: 0, duration: 0.2 }).then();
  return gsap.fromTo(overlay, box(from), { ...box(to), duration: 0.45, ease: 'back.out(1.2)' }).then();
};

const enter = ({ element, reducedMotion }: EnterAnimationContext) =>
  gsap.from(element, reducedMotion ? { opacity: 0, duration: 0.2 } : { opacity: 0, scale: 0.85, duration: 0.35 }).then();

const leave = ({ element, reducedMotion }: LeaveAnimationContext) =>
  gsap.to(element, reducedMotion ? { opacity: 0, duration: 0.2 } : { opacity: 0, scale: 0.85, duration: 0.25 }).then();

export const gsapAnimations = { animation: move, dropAnimation: drop, animateChanges: { move, enter, leave } };

Die vollständigen Typen der Optionen stehen unter Animationen.

Reduzierte Bewegung

Bei prefers-reduced-motion: reduce laufen die eigenen Animationen der Bibliothek nicht: Elemente und das Overlay gehen direkt an ihre Plätze, und das Overlay gleitet nicht zwischen Slot-Größen. Deine Funktionen laufen immer, mit reducedMotion: true, sie entscheiden also: die Bewegung auslassen oder ein kurzes Ausblenden behalten, wie es die Rezepte oben tun.

Dein CSS sicherst du selbst ab. Setz Anheben, Neigen und Pulsieren in @media (prefers-reduced-motion: no-preference), wie es die Demos auf dieser Seite tun, und lass die Farbwechsel außerhalb davon: Sie zeigen, wohin ein Drop geht.

Layoutänderungen, die nicht von der Bibliothek kommen

Wenn etwas anderes während eines Drags Zeilen verschiebt – ein Virtualizer, der neu misst, ein Bild, das lädt –, ruf captureLayout() der Liste direkt vor dem Rendern der Änderung auf. Es misst die Zeilen dort, wo sie sind, und animiert sie nach dem nächsten Rendern an ihre neuen Plätze. Außerhalb eines Drags tut es nichts. Siehe Virtuelle Listen.
