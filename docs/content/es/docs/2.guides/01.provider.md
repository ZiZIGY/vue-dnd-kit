## Un provider para la app {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Pon un `DnDProvider` arriba del todo, en `App.vue` o en un layout, y olvídate de él. Todo
composable (`makeSortableList`, `makeDraggable`, `useDnD`…) busca el provider más cercano por
encima del componente en el que se ejecuta.

::warning
Un composable debe ejecutarse en un componente **renderizado dentro** del provider. Llamarlo en el
componente cuyo propio template contiene `<DnDProvider>` lanza
`No <DnDProvider> found above this component`: el `inject` de Vue solo ve los ancestros.
::

## Qué gestiona {#what-it-owns}

| Parte | Qué hace el provider |
| --- | --- |
| Entrada | Convierte la entrada de puntero, táctil y de teclado en arrastres (`sensors`), de uno en uno. |
| Encontrar el destino | Hace la prueba de colisión con los destinos que hay bajo el arrastre (`collision`) y se lo comunica. |
| El overlay | Renderiza la caja que sigue al puntero, teletransportada a `body`, y la hace aterrizar al soltar. |
| La selección | Un único conjunto de ids seleccionados, compartido por todas las listas y elementos arrastrables que hay debajo. |
| Desplazamiento automático | Desplaza los contenedores y la ventana cuando un arrastre se acerca a sus bordes. |
| La región viva | Anuncia a los lectores de pantalla cuándo se agarra, se mueve, se suelta o se cancela algo. |

No renderiza nada más: tu marcado se queda como está.

## Las opciones de un vistazo {#options-at-a-glance}

Cada opción tiene un valor por defecto que funciona, así que normalmente el provider no recibe
ninguna.

| Prop | Por defecto | Qué ajusta |
| --- | --- | --- |
| `collision` | `pointerFirst` | Cómo se elige el destino bajo el arrastre. |
| `modifiers` | `[]` | Reglas de movimiento para todos los arrastres (ajuste, restricción, …). |
| `animation` / `dropAnimation` | activada | Los ítems que se deslizan al ordenar / el aterrizaje del overlay. |
| `animate` | desactivada | Valor por defecto para listas y árboles: animar los cambios de datos que no vienen de un arrastre. |
| `autoScroll` | activado | Desplazamiento en los bordes: `{ threshold, maxSpeed, acceleration }` o `false`. |
| `activation` | ratón 4 px, táctil 200 ms | Cuándo una pulsación se convierte en arrastre, según el tipo de puntero. |
| `keyboard` | Space / Enter, Escape | Teclas y paso del teclado; `false` desactiva los arrastres con teclado. |
| `sensors` | puntero + teclado | Lo que convierte la entrada en arrastres. |
| `haptics` | una vibración corta al agarrar con el dedo | Vibraciones para los arrastres táctiles, o `false`. |
| `copyModifier` | `'Alt'` | Tecla que, mantenida durante el arrastre, convierte un movimiento en una copia (la lista necesita `clone`). |
| `overlayTo` | `'body'` | Adónde se teletransporta el overlay. |
| `overlayFit` | `'slot'` | Tamaño del overlay: el del hueco donde aterrizará o el del origen. |
| `announcements` | integrados | Textos para lectores de pantalla, o `false`. |
| `defaultStyles` | `true` | Inyecta CSS de especificidad cero para los estados del arrastre. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

La lista completa, con todas las formas, está en la [API de DnDProvider](/docs/api/dnd-provider).
El provider también emite `drag-start`, `drag-move`, `drag-over`, `drag-end` y `drag-cancel`,
los mismos eventos que escucha `useDnDMonitor`.

::tip
Las reglas para una parte de la página (un tablero que se ajusta a una cuadrícula, un feed que
solo se desplaza en vertical) no necesitan un provider propio: envuelve esa parte en un
[área de arrastre](/docs/guides/constraints).
::

## Leer el arrastre: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Arrastra una tarea y observa el estado" height="22rem"}
::

`useDnD()` devuelve el arrastre como estado reactivo, en cualquier componente bajo el provider:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Campo | Qué contiene |
| --- | --- |
| `status` | `'idle'`, `'activating'` (una pulsación larga cargándose), `'dragging'`, `'dropping'` (aterrizando, o esperando un `onBeforeDrop` asíncrono), `'selecting'` (un rectángulo de selección). |
| `active` | Lo que se arrastra: `id`, `ids` (todos los ids arrastrados, empezando por el que se agarró), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` en reposo. |
| `over` | El destino bajo el arrastre: `id`, `data`, `element`, `rect` y `accepted`. `null` cuando no hay nada debajo. |
| `pointer` | El puntero en coordenadas del viewport, tras los modificadores. |
| `activation.progress` | De `0` a `1` mientras se carga una pulsación larga: dibuja un anillo con él. |
| `isAutoScrolling` | El desplazamiento automático está moviendo algo. |
| `selection` | La selección del provider: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. Consulta [multi-drag](/docs/guides/multi-drag). |
| `cancel()` | Cancela el arrastre en curso (los ítems vuelven a su sitio), una pulsación larga que se está cargando o un rectángulo de selección. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

En cuanto se decide un drop, `active`, `over` y `pointer` pasan a valer `null`, aunque el overlay
siga aterrizando (`status` sigue en `'dropping'`). La UI que deriva de ellos nunca muestra el
arrastre anterior junto a los datos nuevos. Mientras espera un `onBeforeDrop` asíncrono, el estado
se queda como estaba al soltar.

## Escuchar todos los arrastres: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

Un monitor escucha todos los arrastres bajo su provider, empiecen donde empiecen. Se detiene
cuando se desmonta el componente que lo llamó.

| Evento | Cuándo |
| --- | --- |
| `onDragStart` | Empieza un arrastre. |
| `onDragMove` | El arrastre se mueve. |
| `onDragOver` | Cambia el destino bajo el arrastre. |
| `onBeforeDrop` | Se suelta el arrastre. Su respuesta decide el drop: consulta [decidir un drop](/docs/guides/drop-decisions). |
| `onDragEnd` | El drop se ha completado. Las listas ordenables ya han ejecutado su `onDrop` y han escrito el nuevo orden. `dropped` es `false` cuando terminó sin ningún destino debajo. |
| `onDragCancel` | Escape, un drop sobre un destino que lo rechaza o un `onBeforeDrop` que respondió `'reject'`. |
| `onDragResume` | `onBeforeDrop` respondió `'continue'`: no se soltó nada y el arrastre continúa. |

Cada evento lleva `active`, `over`, `pointer`, `delta` (el desplazamiento desde el inicio),
`position` (dónde está la caja arrastrada dentro de `over`, consulta
[arrastrar y soltar](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) y, para los ítems
de una lista ordenable, `source`. Las formas completas están en la [API de eventos](/docs/api/events).

::note
`onDragEnd` es el lugar para el trabajo de «después del drop»: guardar, limpiar la selección,
analítica. El `onDrop` propio de una lista se ejecuta **antes** de su escritura, así que todavía
ve el orden antiguo.
::

## Varios providers {#several-providers}

La mayoría de las apps necesitan exactamente uno. Un segundo provider solo tiene sentido para una
parte de la página que necesita sus propios ajustes a nivel de provider (colisión, teclas del
teclado, anuncios) y cuyos ítems nunca salen de ella:

- Los providers son independientes: un arrastre nunca pasa de uno a otro.
- Se permiten providers anidados. **Gana el propietario más cercano**: un ítem pertenece al
  provider más cercano por encima de él, y el provider exterior lo ignora.
- Cada provider tiene su propia selección, su propio overlay y su propia región viva.

Si los ítems no pueden moverse entre dos partes de tu página, comprueba que no estén bajo dos
providers.

::tip
Una app montada en otro sitio, dentro de un shadow root o como una app de Vue independiente, puede
unirse a un provider existente: pasa `useDnDContext()` a `provideDnDContext(app, context)` antes de
montarla.
::

## SSR y Nuxt {#ssr-and-nuxt}

El provider es compatible con SSR. Las listas y los ítems se renderizan en el servidor como
cualquier otro marcado. El overlay y la región viva se teletransportan y se montan solo en el
cliente, así que nunca provocan un error de hidratación. Los ids por defecto salen de `useId()` de
Vue y coinciden entre el servidor y el cliente.

En Nuxt, el módulo registra `DnDProvider` de forma global e importa automáticamente los
composables: consulta la [instalación](/docs/getting-started/installation#nuxt).
