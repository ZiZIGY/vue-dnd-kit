Cambia el eje, la cuadrícula y los límites, y luego arrastra una nota. El tablero fija las reglas
de todos los arrastres que empiezan en él, y cada nota se queda donde la sueltas.

::example{name="constraints" hint="Cambia las reglas y luego arrastra una nota" height="26rem"}
::

## Bloquear un eje {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` solo mueve en horizontal, `'y'` solo en vertical. `makeDraggable`,
`makeSortableList`, `makeSortableTree`, `makeSortableItem` y `makeDragArea` lo aceptan.

- El bloqueo se aplica **después de todos los modificadores**, así que se mantiene hagan lo que
  hagan: un ajuste o un límite no pueden sacar el ítem de su línea.
- El `axis` propio de un ítem tiene prioridad sobre el de su lista o árbol, y el de un elemento
  arrastrable (o el de su lista) tiene prioridad sobre el de su área de arrastre.
- Se lee cuando empieza un arrastre, así que un getter puede activarlo y desactivarlo:
  `axis: () => (locked.value ? 'y' : undefined)`.
- Un árbol bloqueado en `'y'` se sigue anidando: la profundidad sale entonces de pasar sobre el
  centro de una fila.

::tip
Prefiere `axis` a los modificadores `restrictToVerticalAxis` y `restrictToHorizontalAxis`. Hacen lo
mismo, pero como son modificadores normales se ejecutan en mitad de la cadena, y un modificador
posterior (una cuadrícula que ajusta ambos ejes) puede volver a sacar el ítem del eje.
::

## Modificadores {#modifiers}

Un modificador ajusta el desplazamiento del arrastre en cada frame. Su resultado mueve el overlay
**y** es el punto donde se buscan los destinos, así que una lista ordena según la posición
bloqueada, limitada o ajustada.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Modificador | Qué hace |
| --- | --- |
| `restrictToVerticalAxis` | Solo mueve en vertical. Mejor usa `axis: 'y'`. |
| `restrictToHorizontalAxis` | Solo mueve en horizontal. Mejor usa `axis: 'x'`. |
| `restrictToWindowEdges` | Mantiene el overlay dentro de la ventana. |
| `restrictToParent` | Mantiene el overlay dentro del contenedor donde empezó el arrastre: la lista ordenable, o el elemento padre de un elemento arrastrable simple. |
| `restrictToElement(target)` | Mantiene el overlay dentro de un elemento: una ref de plantilla, un getter o el propio elemento. |
| `restrictToFirstScrollableAncestor` | Mantiene el overlay dentro del primer ancestro desplazable del elemento arrastrado. |
| `snapToGrid(size)` | Ajusta el overlay a una cuadrícula (más abajo). |
| `snapCenterToCursor` | Centra el overlay bajo el puntero en lugar de mantener el desplazamiento del agarre. |

`modifiers` es una opción del provider, de las áreas de arrastre, de las listas y los árboles, y de
los elementos arrastrables y los ítems ordenables. Todas salvo la del provider aceptan también una
ref o un getter, que se leen cuando empieza el arrastre.

### Ajustar a una cuadrícula {#snap-to-a-grid}

`snapToGrid(24)` ajusta ambos ejes a celdas de 24 px. Un objeto permite ajustar más cosas:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Opción | Significado |
| --- | --- |
| `x`, `y` | El tamaño de la celda en píxeles, por eje. |
| `origin` | `'container'` (por defecto): la esquina superior izquierda del overlay cae sobre líneas de cuadrícula trazadas desde la esquina superior izquierda del contenedor — la lista ordenable, o el padre de un elemento arrastrable simple. `'delta'`: se redondea el propio desplazamiento, así que un ítem que empezó fuera de la cuadrícula se queda fuera de ella. |
| `smooth` | `true` o `{ duration, easing }`: el overlay se desliza entre celdas (80 ms por defecto). Los destinos usan la posición ajustada al instante. |

### Tu propio modificador {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

Un modificador recibe `transform`, el desplazamiento desde el inicio del arrastre tal como lo
dejaron los modificadores anteriores, y devuelve uno nuevo. También recibe lo que pueda necesitar
para calcularlo: `activeRect` (el elemento arrastrado al inicio), `overlayRect` (el overlay movido
según `transform`), `containerRect`, `windowRect`, `origin` (el puntero al inicio), `active` y
`over`. Consulta [Modificadores](/docs/api/modifiers).

## El orden {#the-order}

Los modificadores de varios sitios se ejecutan uno tras otro, cada uno a partir del resultado del
anterior:

1. los `modifiers` del provider;
2. los `modifiers` del área de arrastre en la que empezó el arrastre;
3. los `modifiers` propios del ítem arrastrado o, si no tiene, los de su lista o árbol;
4. el `restrictToArea` del área de arrastre;
5. el bloqueo de `axis`.

Los `modifiers` de un ítem **sustituyen** a los de su lista; no se suman a ellos. Los límites del
área vienen después del ajuste de los pasos 1–3, así que un ítem ajustado sigue quedándose dentro,
y el bloqueo de eje va el último de todos.

## Las listas con límites conservan sus extremos {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

Un límite retiene el overlay en el borde de la caja mientras el puntero sigue. En cuanto el puntero
ha salido del overlay a lo largo del eje de la lista, la lista pasa a ordenar según el puntero, así
que el primer y el último sitio siguen a tu alcance sujetes como sujetes el ítem. Las cuadrículas
siguen ordenando según el overlay: retenido en el borde, ya cubre la celda del borde.

## Reglas para una parte de la página {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` fija las reglas de los arrastres que **empiezan dentro** de su elemento — tanto
elementos arrastrables simples como ítems ordenables. Mantén un único `DnDProvider` para toda la
app, y da a un tablero, un lienzo o un feed un área propia.

| Opción | Qué hace |
| --- | --- |
| `axis` | Bloquea los arrastres en un eje. Tiene prioridad el `axis` propio de un elemento arrastrable, o el de su lista. |
| `modifiers` | Se ejecutan después de los del provider y antes de los propios del elemento arrastrable. |
| `restrictToArea` | `true`: los arrastres se quedan dentro del elemento del área. |
| `autoScroll` | El desplazamiento automático del contenedor desplazable del área (el elemento, o su ancestro desplazable más cercano). `false` lo desactiva ahí. |
| `activation` | La [activación](/docs/guides/sensors#activation-constraints) según el tipo de puntero. Tiene prioridad la propia del elemento arrastrable; la del provider va la última. |
| `disabled` | No empieza ningún arrastre en el área, ni en las áreas que contiene. Sus elementos arrastrables indican `aria-disabled`. |

Cada opción acepta un valor, una ref o un getter, que se leen cuando empieza una pulsación o un
arrastre. El área devuelve `isDragging` (hay en curso un arrastre que empezó aquí) e
`isAutoScrolling` (el desplazamiento automático está moviendo su contenedor). Referencia completa:
[makeDragArea](/docs/api/make-drag-area).

### Cómo se combinan las áreas {#how-areas-combine}

- Un arrastre sigue al área en la que **empezó**, incluso después de salir de ella. Pasar por encima
  de un área no cambia nada, excepto su `autoScroll`: ese se aplica a todo arrastre que desplace su
  contenedor.
- Las áreas anidadas no se fusionan: gana la más cercana. `disabled` es la excepción, y se hereda:
  un área desactivada desactiva también las áreas que contiene.
- La detección de colisiones, las teclas del teclado y los anuncios siguen siendo a nivel de
  provider.

::note
¿Por qué no un segundo `DnDProvider` alrededor del tablero? Los providers son independientes: un
arrastre nunca pasa de uno a otro, así que los ítems del tablero nunca podrían salir de él. Anida
un provider solo cuando una parte de la página necesita sus propios ajustes a nivel de provider y
sus ítems se quedan dentro. Consulta [El provider](/docs/guides/provider).
::

## Dejarlo donde se suelta {#leave-it-where-its-dropped}

El tablero del ejemplo también es un destino de drop, y cada nota conserva el sitio donde se soltó.
Cada evento de arrastre lleva `position`: la esquina superior izquierda de la caja arrastrada dentro
del destino, desde el borde de su padding y con su scroll — el `left` y el `top` que colocan
un ítem con posición absoluta justo ahí. Se calcula después de los modificadores, así que una nota
ajustada aterriza sobre la cuadrícula.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

Más sobre el arrastre libre y los destinos de drop en [Arrastrar y soltar](/docs/guides/drag-and-drop).
