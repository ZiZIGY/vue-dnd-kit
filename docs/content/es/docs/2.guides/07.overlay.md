Mientras arrastras, una caja sigue al puntero: el **overlay**. El elemento arrastrado se queda
donde estaba, como el hueco en el que aterrizará. Al soltar, el overlay vuela a ese hueco y
desaparece.

El overlay se teletransporta a `body`, fuera de tus componentes. Por defecto muestra un clon del
elemento arrastrado.

::example{name="overlay" hint="Arrastra un mensaje: la copia recibe el fondo de la bandeja de entrada" height="24rem"}
::

## El clon por defecto {#the-default-clone}

El clon se toma al agarrar, antes de que nada se mueva. Es una copia profunda del elemento:

- Se copian los valores de los formularios y los píxeles de los `<canvas>`.
- Se aplican en línea los estilos calculados que el elemento perdería fuera de su lista: fuentes y
  colores heredados, estilos que se aplican a través de ancestros (`.list li { … }`), anchos de
  celdas de tabla. Una fila de tabla viene envuelta en una tabla propia.
- Se eliminan los `id` y los atributos `data-dnd-*`, y el clon es `aria-hidden`.
- Se dejan fuera los ripples y otros efectos de pulsación de los kits de UI (Vuetify, Quasar,
  PrimeVue, Naive UI).

Marca con **`data-dnd-no-clone`** cualquier otra cosa que no deba viajar: un botón de menú, un
tooltip, un badge.

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### Los fondos no se adivinan {#backgrounds-arent-guessed}

El clon muestra el elemento tal como es. Una fila que no tiene fondo propio, porque se lo pinta su
lista (un `<li>` en un `<ul>` blanco, un `v-list-item`, una fila de tabla), da un clon
**transparente**. Dale el fondo de la lista en CSS:

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

El clon conserva las clases y los atributos del elemento, incluido el atributo de scope de Vue, así
que la regla funciona tanto en el estilo scoped de la fila como en una hoja de estilos global. La
otra salida es poner un fondo en la propia fila. Los iconos y las baldosas pensados para flotar,
como los iconos de apps de [listas ordenables](/docs/guides/sortable-lists), se quedan
transparentes a propósito.

## Dar estilo a la caja {#styling-the-box}

La caja es el elemento con `data-dnd-overlay`. Tiene `position: fixed` y `pointer-events: none`, y
su valor indica lo que está haciendo:

| `data-dnd-overlay` | Cuándo |
| --- | --- |
| `"dragging"` | Sigue al puntero. |
| `"dropping"` | Aterriza en su hueco, vuelve a su sitio o espera un `onBeforeDrop` asíncrono. |

Un aspecto elevado mientras se arrastra, que desaparece al aterrizar:

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## Componentes de overlay {#overlay-components}

Para mostrar algo distinto del clon, pasa un componente. Se renderiza dentro de la caja:

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | Qué contiene |
| --- | --- |
| `active` | El arrastre (`id`, `ids`, `data`, `type`, …). |
| `items` | Todos los ítems arrastrados, empezando por el que se agarró: `{ id, item, data, type }`. `item` es el ítem de la lista en los arrastres ordenables. |
| `over` | El destino bajo el arrastre, o aquel en el que aterriza al soltar. `null` cuando no hay nada debajo y mientras un arrastre cancelado vuelve a su sitio. |
| `accepted` | Si `over` acepta el arrastre: tiñe el overlay de rojo cuando no lo acepta. |
| `status` | `'dragging'` o `'dropping'`. |
| `mode` | `'move'`, `'copy'`, `'swap'` o `'insert'`. |

Un componente se puede pasar tal cual, o dentro de una `shallowRef` para poder cambiarlo. No lo
pongas nunca en una `ref` profunda ni en un `reactive`: Vue haría reactivo el componente y lanzaría
un aviso.

La cuadrícula de apps de [listas ordenables](/docs/guides/sortable-lists) usa uno: el icono viaja
solo y se eleva, y el nombre se queda atrás.

## El slot `#overlay` del provider {#the-providers-overlay-slot}

Para cada arrastre sin componente propio, el slot del provider renderiza el overlay:

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

El slot recibe las mismas props que un componente de overlay. Cuando no renderiza nada (el `v-if`
de arriba), el arrastre vuelve a usar el clon.

## Qué tiene prioridad {#what-wins}

Para cada arrastre, el primero que aplique:

1. El `overlay` propio del ítem (`makeSortableItem`, `makeDraggable`).
2. El `overlay` de su lista o árbol.
3. El slot `#overlay` del provider, a menos que no renderice nada.
4. El clon por defecto. En un multi-drag, una columna o una pila de clones: consulta
   [multi-drag](/docs/guides/multi-drag#the-default-overlay).

El componente se elige cuando empieza el arrastre y se mantiene durante todo el arrastre, también
sobre otras listas.

## `DragPreview`: el clon en tu diseño {#dragpreview-the-clone-in-your-layout}

`DragPreview` renderiza el clon que hace la biblioteca de un ítem arrastrado. Úsalo en un
componente de overlay que coloca él mismo varios ítems, o que añade un marco alrededor del clon:

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

Hay clones para el ítem agarrado y para hasta otros cuatro junto a él; para cualquier otro ítem,
`DragPreview` renderiza su slot por defecto. Consulta
[multi-drag](/docs/guides/multi-drag#a-custom-overlay-for-several-items) para una pila de vistas
previas.

## Tamaño: `overlayFit` {#size-overlayfit}

| `overlayFit` (provider) | La caja |
| --- | --- |
| `'slot'` (por defecto) | Toma el tamaño del hueco en el que aterrizará. Sobre una lista de tarjetas más anchas, se ensancha. |
| `'source'` | Mantiene el tamaño del elemento arrastrado. |

Con `'slot'`, la caja cambia de tamaño alrededor del puntero, que se queda en la misma proporción de
la caja. El contenido nunca se escala: se vuelve a maquetar con el nuevo tamaño.

Un drop hace lo mismo con cualquiera de los dos ajustes: la caja vuela hasta el elemento de llegada
y se anima hasta **su** tamaño, y el contenido se vuelve a maquetar por el camino. Cuando un ítem
tiene un aspecto distinto en dos listas (un chip compacto en una paleta, una tarjeta completa en un
tablero), el clon del origen se vuelve a maquetar al tamaño del destino y puede verse aplastado o
estirado. Dos formas de que quede bien:

- Da al ítem el **mismo aspecto** en todas las listas en las que puede aterrizar. Los archivos de
  [arrastrar y soltar](/docs/guides/drag-and-drop) tienen un único tamaño fijo en todas las
  carpetas, así que un drop solo los mueve.
- Renderiza el **aspecto del destino** en un componente de overlay. Recibe `over`, así que puede
  cambiar al aspecto de la lista sobre la que está, y llena la caja a cualquier tamaño.

Un tamaño fijo en la raíz de un componente de overlay mantiene ese tamaño dentro de la caja. Da a la
raíz `width: 100%; height: 100%` para que la siga.

## Dónde se renderiza: `overlayTo` {#where-it-renders-overlayto}

El provider teletransporta el overlay a `body`. Dentro de un `<dialog>` abierto con `showModal()`,
o de un shadow root, el overlay acabaría debajo de la top layer o fuera de los estilos. Apunta
`overlayTo` a un selector o a un elemento de ahí dentro:

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## Sin overlay {#no-overlay}

`makeDraggable(el, { overlay: false })` no tiene ninguna caja: el propio elemento se mueve, mediante
el `transform` devuelto. Consulta [arrastrar y soltar](/docs/guides/drag-and-drop#without-an-overlay).
Cómo aterriza la caja lo decide el `dropAnimation` del provider: consulta
[animaciones](/docs/guides/animations).
