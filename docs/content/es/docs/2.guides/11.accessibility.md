Todo lo de esta página está activado por defecto. Llega con Tab al asa de una canción, pulsa
:kbd{value="Space"}, muévela con las flechas y vuelve a pulsar :kbd{value="Space"} — o
:kbd{value="Escape"} para devolverla a su sitio.

::example{name="lists" hint="Tab hasta un asa, Espacio, flechas, Espacio" height="28rem"}
::

Lo que normalmente te queda a ti: nombres legibles para los ítems, y botones que los muevan para
quien no puede arrastrar en absoluto.

## El teclado {#the-keyboard}

| Tecla | Acción |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Agarrar el ítem con el foco; soltarlo. |
| Flechas | Moverlo: por huecos en las listas, por filas y profundidad en los árboles, `keyboard.step` píxeles en los arrastres libres. |
| :kbd{value="Escape"} | Cancelar el arrastre — también los de puntero. |

- En una lista, una flecha hacia otra lista del mismo grupo mueve el ítem allí.
- En un arrastre libre, :kbd{value="Shift"} agranda los pasos. `makeDraggable(el, { keyboard: 'droppables' })`
  hace que las flechas salten, en cambio, entre los destinos que aceptan el ítem.
- Un arrastre con teclado empieza desde el elemento arrastrable con el foco, o desde su asa — nunca
  desde un botón o un campo que contenga, así que estos conservan sus propias teclas.
- Los arrastres con teclado desplazan el destino hasta que es visible, en lugar de usar el
  desplazamiento automático en los bordes.
- Después del drop, el foco vuelve al ítem, aunque su fila se haya vuelto a renderizar en otra
  lista.

### Otras teclas {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Las asignaciones coinciden con `event.code` (`'Space'`, `'KeyD'`) o con `event.key` (`'Enter'`).
`step` son los píxeles por pulsación de flecha en los arrastres libres (25 por defecto).
`:keyboard="false"` desactiva los arrastres con teclado, y :kbd{value="Escape"} sigue cancelando
cualquier arrastre. Si cambias las teclas, cambia también `screen-reader-instructions`.

## Atributos ARIA {#aria-attributes}

Cada elemento arrastrable e ítem ordenable recibe estos atributos, **a menos que los pongas tú**:

| Atributo | Valor |
| --- | --- |
| `tabindex` | `0`, cuando el elemento no puede recibir el foco ya de por sí. |
| `role` | `button`, excepto en un `<button>`, que ya lo es. |
| `aria-roledescription` | `draggable`, o `sortable` en los ítems ordenables. |
| `aria-describedby` | Las instrucciones del provider, añadidas junto a los ids que ya hay (el de un tooltip se conserva). |
| `aria-disabled` | `true` o `false`: si el ítem está desactivado (también por un área de arrastre desactivada). |
| `aria-pressed` | `true` mientras se arrastra. |

`attributes: false` los desactiva para un ítem; se elimina lo que la biblioteca había puesto.

### Asas: que sean botones de verdad {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

Con un `handle`, los atributos van al asa, y los arrastres con teclado empiezan desde ella. Un
`<button>` puede recibir el foco y ya es un botón, así que no necesita `tabindex` ni `role`. Dale
un `aria-label`: un icono de asa no tiene nombre propio, y «Move Midnight Drive» dice más que
«button».

## Anuncios {#announcements}

Una región viva en el provider anuncia cada agarre, movimiento, drop y cancelación. Las listas
ordenables dicen dónde está el ítem: *"Picked up item t2 at position 2 of 5 in list playlist."* Los
movimientos se anuncian cuando el arrastre lleva 500 ms quieto.

Los textos usan ids. Da a los ítems ids legibles, o escribe tú los textos:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- Un texto sustituye el anuncio del evento; `undefined` mantiene el de por defecto; `''` no dice
  nada. Los eventos que omites también mantienen sus valores por defecto, como las posiciones de
  las listas ordenables para `onDragOver` en el ejemplo de arriba.
- `onDragResume` se anuncia cuando `onBeforeDrop` respondió `'continue'` y el arrastre continúa
  (consulta [Decidir un drop](/docs/guides/drop-decisions)).
- `screenReaderInstructions` es el texto al que apunta cada elemento arrastrable con
  `aria-describedby`.
- `:announcements="false"` silencia la región, por ejemplo cuando anuncias a través de la tuya.

::note
Los textos integrados están en inglés. Para otro idioma, proporciona los cinco textos y las
instrucciones — cada uno que omitas se anuncia en inglés, incluidas las posiciones de las listas
ordenables.
::

## Táctil {#touch}

Los arrastres táctiles empiezan tras una pulsación larga de 200 ms. Si antes el dedo se mueve más
de 5 px, la página se desplaza en su lugar, así que las listas siguen siendo desplazables. Ajusta
ambos valores con `activation` (consulta [Sensores](/docs/guides/sensors#activation-constraints)), y
dibuja un anillo de pulsación larga a partir de `useDnD().activation.progress`.

Un arrastre táctil vibra brevemente al empezar. `:haptics="false"` lo desactiva; un objeto añade
vibraciones al entrar en un destino, al soltar o al ser rechazado:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Solo vibran los arrastres táctiles, y Safari en iOS no puede vibrar en absoluto.

## Movimiento reducido {#reduced-motion}

Con `prefers-reduced-motion: reduce`, las animaciones propias de la biblioteca no se ejecutan. Tus
funciones de animación sí se ejecutan, con `reducedMotion: true`. Consulta
[Animaciones](/docs/guides/animations).

## Mover sin arrastrar {#moving-without-dragging}

Hay personas que no pueden arrastrar en absoluto. WCAG 2.5.7 pide una forma de mover los ítems con
clics simples, como botones de «Subir». `@vue-dnd-kit/actions` convierte cada uno de ellos en un
movimiento real:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` ejecuta un arrastre con teclado de principio a fin: se anuncia, pasa por `onBeforeDrop`
y `onDrop`, se anima y mantiene el foco en el ítem. Se resuelve con `true` cuando el drop se
completa. `index` cuenta los sitios sin el propio ítem, así que «bajar» es `index + 1`. Más en
[Sensores y arrastres programáticos](/docs/guides/sensors#programmatic-drags).
