Arrastra una tarjeta a **Done**. El drop espera tu respuesta: mover la tarjeta, seguir
arrastrándola a otro sitio o cancelar.

::example{name="drop-confirm" hint="Arrastra una tarjeta a Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

Las listas, los árboles, los destinos de drop (`makeDroppable`) y los monitores (`useDnDMonitor`)
aceptan un `onBeforeDrop`. Se ejecuta cuando se suelta el arrastre, antes de que cambie nada, y su
respuesta decide:

| Respuesta | Qué pasa |
| --- | --- |
| `'accept'`, `true` o nada | El drop se completa. |
| `'reject'` o `false` | No hay drop: los ítems vuelven a su sitio. Un error lanzado también lo rechaza. |
| Un array de claves | Solo esos ítems se sueltan; los demás vuelven a su sitio. |
| `'continue'` | No hay drop, y el arrastre continúa. |
| Una promesa de cualquiera de estos | El overlay espera donde se soltó hasta que la promesa se resuelva o se rechace. |

Las reglas propias del destino van primero: el `accept` de un destino de drop, el `group.put` de
una lista. Sobre un destino que rechaza el arrastre, el drop se cancela y no se consulta el
`onBeforeDrop` del destino. `onBeforeDrop` sirve para lo que esas reglas no pueden saber: la
respuesta del usuario, la del servidor o lo que cambiaría el drop.

Las listas y los árboles pasan un `SortableDropEvent`: `keys`, `items`, `from`, `to`, `mode`,
`sameList` y `result`, los nuevos arrays de cada lista que cambia el drop. Los destinos de drop y
los monitores reciben el `DnDEvent` genérico: `active`, `over`, `position` y `source`. Consulta
[Eventos](/docs/api/events).

### Aceptar solo algunos ítems {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

En un [multi-drag](/docs/guides/multi-drag), los ítems cuyas claves devuelves aterrizan y el resto
vuelve de donde vino. Después, `onDrop` los ve en `e.accepted` y `e.rejected`, y su `e.result` es
el definitivo.

## Seguir arrastrando: 'continue' {#keep-dragging-continue}

`'continue'` cancela el drop, no el arrastre. El ítem sigue en la mano desde donde estaba, la página
vuelve al modo de arrastre y el usuario sigue:

- Con un ratón o un lápiz, el ítem sigue al puntero sin ningún botón pulsado. Lo suelta la
  siguiente liberación del botón — un clic —, y ese clic nunca llega a la página de debajo.
- Al tocar, el ítem se vuelve a agarrar donde se apoya el dedo; al levantar el dedo se suelta.
- Un arrastre con teclado continúa: las flechas mueven el ítem, :kbd{value="Space"} o
  :kbd{value="Enter"} lo sueltan.
- :kbd{value="Escape"} lo cancela, como cualquier arrastre.
- El siguiente drop vuelve a consultar `onBeforeDrop`.

Los monitores reciben `onDragResume`, y los lectores de pantalla anuncian que el ítem no se soltó y
que sigue moviéndose (cambia el texto con `announcements.onDragResume` del provider).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## Preguntar al usuario {#asking-the-user}

`onBeforeDrop` puede devolver una promesa. Abre un diálogo y resuelve la promesa con el botón que
elija el usuario:

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Mientras la promesa está pendiente:

- el overlay espera donde se soltó, marcado con `data-dnd-overlay="dropping"`;
- `useDnD()` conserva el estado que tenía al soltar, y `status` es `'dropping'`;
- la página sale del modo de arrastre: el cursor y la selección de texto vuelven, así que un
  diálogo funciona con normalidad.

::tip
Un `<dialog>` modal abierto con `showModal()` está en la top layer, por encima del overlay en
espera. Convierte su evento `cancel` (:kbd{value="Escape"}) en `'reject'`, como hace el ejemplo.
::

## El orden de los hooks {#the-order-of-the-hooks}

1. El `onBeforeDrop` de cada `useDnDMonitor`, por turnos. Un `'reject'` o un `'continue'` termina
   la consulta; las claves acotan el drop.
2. El `onBeforeDrop` del destino: la lista o el árbol al que van los ítems, o el destino de drop.
3. Solo el `onDrop` del destino: no se consulta a la lista que los ítems dejan por otra, y su nuevo
   array está en el `e.result` del destino. Cuando se quitan ítems (una zona de papelera,
   `dropOutside: 'remove'`), se ejecuta el `onDrop` de su lista, con un `to.index` de `-1`.
4. La escritura por defecto: cada lista que cambia el drop recibe su nuevo array.
5. El overlay aterriza. Le siguen el `@drag-end` del provider y el `onDragEnd` de los monitores.

Tus monitores deciden antes que el destino, así que su veto nunca llega después de que una lista
ya haya aplicado un drop por su cuenta.

## onDrop: avisado antes de la escritura {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

El `onDrop` de una lista se ejecuta una vez aceptado el drop, de forma síncrona, justo antes de que
la lista lo escriba. Para actuar después de la escritura, usa el `@drag-end` del provider o
`useDnDMonitor({ onDragEnd })`. En un destino de drop simple, `onDrop` es donde cambias tus datos:
la biblioteca no mueve nada por él.

## Stores y servidores: listas controladas {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

La biblioteca solo escribe un drop en una ref escribible. Un getter, un `computed` o una ref
`readonly` nunca se escriben: llama a `e.preventDefault()` y aplica `e.result` tú mismo — los nuevos
arrays de cada lista que cambia el drop, por id de lista. `preventDefault()` omite la escritura en
todas ellas, ya que escribir solo algunas perdería o duplicaría ítems. Las builds de desarrollo
avisan cuando el drop de una lista de solo lectura se deja en manos de la biblioteca.

### Guardar antes en un servidor {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Aplica `e.result` antes de que se resuelva la promesa, y el overlay aterriza en el nuevo orden. Si
la petición falla, no apliques nada: el drop se completa, no cambia nada y los ítems vuelven a su
sitio.

## Soltar fuera de todo destino {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | Un drop fuera de todo destino… |
| --- | --- |
| `'placeholder'` | Aterriza donde está el placeholder: el último sitio que mostró la lista. Es el valor por defecto. |
| `'cancel'` | Se cancela: los ítems vuelven a su sitio. Es el valor por defecto con `placeholder: 'indicator'`. |
| `'remove'` | Quita los ítems de su lista. Primero se consulta el `onBeforeDrop` de la lista, y su `onDrop` recibe un `to.index` de `-1`. |

Una zona de papelera hace lo mismo, a propósito:
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`. Consulta
[Arrastrar y soltar](/docs/guides/drag-and-drop).
