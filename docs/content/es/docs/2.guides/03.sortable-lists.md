## Una lista y sus filas {#a-list-and-its-rows}

Una lista ordenable necesita dos componentes: la lista y su fila.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

La fila se registra en la lista dentro de la que se renderiza. Por eso también cada lista necesita
su propio componente: dos listas creadas en un mismo componente compartirían sus filas.

## El borrador {#the-draft}

`makeSortableList` devuelve `items`, un **borrador** de tu array. Mientras arrastras, el borrador
se reordena en vivo: la fila arrastrada ocupa su nuevo hueco y las demás se apartan. Tu array no
cambia hasta el drop. Entonces la biblioteca escribe en él el nuevo orden.

::example{name="quick-start" hint="Los ids bajo la lista son tu array: cambian al soltar"}
::

- Renderiza `items`, no tu array. Si renderizas tu array, nada se mueve hasta el drop.
- La escritura ocurre después del `onDrop` de la lista. En `onDrop`, tu array todavía tiene el
  orden antiguo y `e.result` el nuevo.
- `tasks` es una `ref` normal, así que el resto de tu app ve el cambio como cualquier otro.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

Un componente de lista que recibe su array mediante `v-model` pasa el modelo tal cual:

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
¿Un store, estado del servidor o datos inmutables? Pasa un getter o un `computed` en lugar de una
ref. La biblioteca no escribe en una fuente de solo lectura: llama a `e.preventDefault()` y aplica
`e.result` tú mismo. Consulta [decidir un drop](/docs/guides/drop-decisions).
::

## Claves {#keys}

Las filas se identifican con una clave que sale de sus datos, nunca por índice ni con un id
automático. Por defecto la clave es `item.id`, o el propio ítem en el caso de cadenas y números.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Usa la misma clave en `v-for`: `:key="task.uuid"`. Con `:key="index"` se animan las filas
  equivocadas y su estado salta de una fila a otra.
- Las claves deben ser únicas entre todas las listas que intercambian ítems.
- Pasa `item` e `id` como getters, para que una fila se mantenga sincronizada cuando cambien sus
  props.

## Estrategias {#strategies}

| `strategy` | Para |
| --- | --- |
| `'vertical'` (por defecto) | Una columna de filas. |
| `'horizontal'` | Una sola fila: pestañas, chips, una línea de tiempo. |
| `'grid'` | Cuadrículas CSS y filas flex que saltan de línea, también con ítems de distintos tamaños. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Asas {#handles}

Por defecto, toda la fila inicia un arrastre (excepto los botones, inputs y otros controles que
contenga). Pasa `handle` para arrastrar solo desde una parte:

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` es un selector dentro del ítem, o una ref de elemento.
- Un arrastre con ratón empieza desde el asa al instante, sin los 4 px habituales.
- El asa recibe los atributos del arrastre (`role`, `tabindex`, `aria-*`), y los arrastres con
  teclado empiezan desde ella.

Haz que el asa sea un `<button type="button">` con un `aria-label`: puede recibir el foco tal cual
y los lectores de pantalla anuncian su etiqueta. Un simple `<span>` con un icono también funciona
(la biblioteca le da `tabindex="0"` y `role="button"`), pero no tiene un nombre con sentido.

::note
Los arrastres táctiles empiezan tras una pulsación larga de 200 ms, para que la página pueda
seguir desplazándose. Para arrastrar al instante desde un asa, da al asa `touch-action: none` y al
ítem `activation: { touch: { distance: 4 } }`.
::

## Bloquear el eje {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` mantiene el arrastre en el eje vertical, `'x'` en el horizontal. El `axis` propio de un
ítem tiene prioridad sobre el de su lista. Para mantener además el arrastre dentro de la lista,
añade el modificador `restrictToParent`; la playlist de arriba usa los dos. Más en
[restricciones](/docs/guides/constraints).

## Dar estilo al hueco {#style-the-slot}

La fila arrastrada se queda en la lista como el hueco en el que aterrizará y recibe
`data-dnd-placeholder`. El estilo por defecto la atenúa al 40 %, con especificidad cero, así que
cualquier regla tuya gana:

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` devuelve el mismo estado como refs, y algunos más:

| Devuelve | Qué es |
| --- | --- |
| `isPlaceholder` | Esta fila es el hueco en el que aterrizará un ítem arrastrado. |
| `isDragging` | Esta fila se está arrastrando (cada fila arrastrada, en un multi-drag). |
| `index` | Su índice en el borrador: cambia mientras arrastras. |
| `selected` | Escribible, vinculado a la selección del provider. |
| `indicator` | En [modo indicador](/docs/guides/shared-lists#an-insertion-line), dónde va la línea. |

La lista devuelve `isOver` e `isAccepting` para su propio resaltado. Todos los atributos y recetas
están en [estilos](/docs/guides/styling).

## Desactivar cosas {#turning-things-off}

- `disabled` en la lista: no salen arrastres de ella ni entran drops. En un ítem: no se puede
  arrastrar.
- `sort: false`: los ítems no se pueden reordenar dentro de esta lista, pero sí pueden salir de
  ella (una paleta, consulta [listas que comparten ítems](/docs/guides/shared-lists)).

## Animaciones {#animations}

Las filas se deslizan a su nuevo sitio mientras arrastras, y la fila soltada aterriza en su hueco.
Viene activado por defecto y no necesita código. No envuelvas las filas en `<TransitionGroup>`: los
movimientos se animarían dos veces. Para los cambios que no vienen de un arrastre (añadir, quitar,
barajar), activa la opción `animate` de la lista. Consulta [animaciones](/docs/guides/animations).

La lista completa de opciones está en la API de [makeSortableList](/docs/api/make-sortable-list) y
[makeSortableItem](/docs/api/make-sortable-item).
