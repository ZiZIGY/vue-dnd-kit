`@vue-dnd-kit/devtools` añade una pestaña **Vue DnD Kit** a Vue DevTools (`vite-plugin-vue-devtools`)
y a Nuxt DevTools. Muestra cada lista, árbol y destino de drop de la página en un minimapa en vivo,
arrastra cualquier ítem con un joystick, edita opciones mientras la app se ejecuta y registra lo
que hizo cada arrastre. Solo funciona en desarrollo: nada de él llega a una build de producción.

## Instalación {#install}

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` es una peer dependency: los movimientos de la pestaña pasan por él. npm 7+ y
pnpm lo instalan por su cuenta; con Yarn 1, añádelo tú.

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

Con Vite, el plugin sirve la pestaña en `/__vue-dnd-kit-devtools/`, la añade a Vue DevTools y hace
que la página le informe antes de que arranque tu app. No hace falta ningún `app.use()`. Solo actúa
en el servidor de desarrollo (`vite serve`); las builds no se tocan.

Con Nuxt, el módulo `@vue-dnd-kit/nuxt` encuentra el paquete, sirve la pestaña, la añade a Nuxt
DevTools e instala la parte de la página con un plugin de cliente. `vueDndKit: { devtools: false }`
lo desactiva.

### Sin los plugins {#without-the-plugins}

Para un servidor de desarrollo propio, o una página que Vite no sirve desde un `index.html`
(configuraciones con SSR), instala tú la parte de la página:

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

O importa `@vue-dnd-kit/devtools/auto` lo primero en el archivo de entrada. Usa
`vueDnDKitDevtools({ inject: false })` cuando el plugin deba servir la pestaña pero la parte de la
página la instales tú; `serveTab()` de `@vue-dnd-kit/devtools/vite` es el middleware que sirve la
pestaña.

## Abrirla {#open-it}

- **Vue DevTools**: :kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"}, o el botón de Vue en
  la parte inferior de la página, y luego la pestaña **Vue DnD Kit**.
- **Nuxt DevTools**: :kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"}, o el botón de Nuxt,
  y luego **Vue DnD Kit** (en la barra lateral o en su menú de desbordamiento).
- **En una ventana propia**: abre `http://localhost:5173/__vue-dnd-kit-devtools/` en tu servidor de
  desarrollo, o usa el botón ⧉ de la pestaña. Muy práctico en una segunda pantalla.

::warning
Mantén la pestaña en una ventana propia, no en una pestaña del navegador en segundo plano: una
página oculta cancela los arrastres.
::

## Qué muestra la pestaña {#what-the-tab-shows}

### El minimapa {#the-mini-map}

Una tarjeta en vivo por cada lista, árbol y destino de drop, con copias de sus ítems donde están —
los mismos clones que mostraría el overlay. Durante un arrastre marca las listas que aceptan el
arrastre (en azul) o lo rechazan (en rojo), el placeholder, el destino bajo el puntero, la caja del
overlay y la línea de inserción de las listas con `placeholder: 'indicator'`. Un clic elige un ítem;
un doble clic desplaza la página hasta él.

Úsalo cuando un drop no va adonde esperas: muestra de un vistazo qué listas aceptan el arrastre.

### Conducir: el joystick {#drive-the-joystick}

Elige un ítem — en el mapa, en el árbol, o con **Pick**, que toma la siguiente pulsación en la
página — y empuja la palanca del joystick. El ítem se agarra y se mueve en esa dirección, más rápido
cuanto más lejos del centro está la palanca. **Drop** y **Cancel** terminan el arrastre.

Es un arrastre de puntero real de un sensor llamado `devtools`, así que las listas ordenan, los
contenedores se desplazan automáticamente, y `onBeforeDrop` y `onDrop` se ejecutan como en
cualquier arrastre. Los ítems de las listas ordenables también tienen botones: arriba, abajo, al
principio, al final, a otra lista del grupo.

| Tecla, en la pestaña | Hace |
| --- | --- |
| Flechas o :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | Empujar la palanca en esa dirección; con :kbd{value="Shift"}, hasta el tope |
| :kbd{value="G"} | Agarrar el ítem elegido |
| :kbd{value="Space"} / :kbd{value="Enter"} | Soltar |
| :kbd{value="Escape"} | Cancelar |
| :kbd{value="P"} | Elegir en la página |

### Opciones {#options}

Toda opción que no sea un callback se puede editar mientras la app se ejecuta: las del provider
(`collision`, `modifiers`, `overlayFit`, `autoScroll`, animaciones, `activation`, `keyboard`…), las
de una lista (`strategy`, `placeholder`, `behavior`, `multiple`, `dropOutside`, `disabled`…), las
de un árbol, las de un destino de drop y las de un ítem. Elige el nodo y abre **Options**.

Una edición se aplica al instante, solo a esta página, y nunca se escribe en tu código. Dura hasta
que la restableces, se desmonta el provider o se recarga la página.

### Estado {#state}

Lo que sabe cada provider, en forma de árbol: su sesión de arrastre (estado, los ids y el sensor
activos, el destino y si lo acepta, el puntero), sus listas y árboles con su orden y su borrador,
los destinos de drop con sus reglas, y los tipos y datos de los ítems.

### Registro {#log}

Una banda por arrastre: el inicio (ids, sensor, la lista de la que vino), cada `over` y `left` con
su aceptación, la liberación, el veredicto de `onBeforeDrop` — aceptado, aceptado en parte,
rechazado por un hook, rechazado por el `accept` del destino — y el `drop`, con `e.result` y si se
llamó a `preventDefault()`, o el `cancel` y su motivo. Haz clic en una entrada para ver sus datos.

Úsalo cuando se rechaza un drop y no sabes qué lo rechazó, o cuando una lista controlada no cambió:
el registro dice si se ejecutó `preventDefault()` y qué contenía `e.result`.

## Cómo funciona {#how-it-works}

Los providers informan a un hook que instala la parte de la página. Mientras ninguna pestaña observa
la página, solo se registran; después, la página escucha como cualquier monitor y envía a la
pestaña lo que muestra — cada 40 ms durante un arrastre, dos veces por segundo el resto del tiempo —
y se detiene cuando ninguna pestaña la ha observado durante unos segundos. La pestaña habla con la
página mediante un `BroadcastChannel` del origen de la página. No cambia nada salvo lo que pidas:
los arrastres, la selección y las opciones modificadas.
