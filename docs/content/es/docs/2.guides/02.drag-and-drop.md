Usa `makeDraggable` y `makeDroppable` para todo lo que no sea una lista ordenable: archivos en
carpetas, una papelera, un tablero de ajedrez, un calendario, notas en un tablero.

::example{name="drop-zones" hint="Las imágenes van a Images, los documentos a Documents" height="30rem"}
::

## Un elemento arrastrable {#a-draggable}

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

Pasa el id de tus datos, como getter. El id por defecto sale de `useId()` y es nuevo en cada
instancia del componente, así que no significa nada para el resto de tu app.

| Devuelve | Qué es |
| --- | --- |
| `isDragging` | Este elemento se está arrastrando. |
| `selected` | Escribible, vinculado a la [selección](/docs/guides/multi-drag) del provider. |
| `transform` | El desplazamiento del arrastre, para `overlay: false` (más abajo). |
| `id` | El id en uso. |

Los botones, inputs y otros hijos interactivos no inician un arrastre de puntero, así que siguen
funcionando dentro de un elemento arrastrable. Para arrastrar solo desde una parte, pasa un
`handle` (consulta [listas ordenables](/docs/guides/sortable-lists#handles)). Todas las opciones
están en la [API de makeDraggable](/docs/api/make-draggable).

## Un destino de drop {#a-drop-target}

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| Devuelve | `true` cuando |
| --- | --- |
| `isOver` | El arrastre está sobre este destino, lo acepte o no. |
| `isAccepting` | Se está arrastrando algo y este destino lo acepta: resalta las zonas válidas. |
| `placement` | No es un booleano: `{ top, right, bottom, left }`, las mitades del destino en las que está el puntero, o `null` cuando no hay nada encima. Úsalo para «antes / después de esta tarjeta». |

`isOver` sin `isAccepting` significa que el arrastre está sobre un destino que lo rechaza.
Muéstralo, como hacen las carpetas de arriba: un drop ahí se cancela y el ítem vuelve a su sitio.

## Qué arrastres acepta un destino {#which-drags-a-target-takes}

El `type` de un elemento arrastrable se compara con el `accept` de un destino:

| `accept` | Acepta |
| --- | --- |
| omitido o `'*'` | Todo. |
| `'image'` | Elementos arrastrables de tipo `image` y los que no tienen tipo. |
| `['image', 'doc']` | Cualquiera de los dos tipos y los que no tienen tipo. |
| `({ active, items, types }) => boolean` | Lo que diga tu función. |

Un elemento arrastrable sin `type` encaja con cualquier regla de tipo cadena. Para todo lo demás,
usa una función:

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` también puede ser un array (`['image', 'large']`): basta con que coincida un tipo.

Cuando se arrastran varios ítems a la vez, `acceptMode` indica cuántos deben encajar: `'all'`
(por defecto) o `'some'`. Con `'some'`, devuelve desde `onBeforeDrop` los ids que se quedan, y los
demás vuelven a su sitio. Consulta [decidir un drop](/docs/guides/drop-decisions).

## El drop {#the-drop}

El `onDrop` de un destino de drop simple es donde **tú** cambias tus datos. La biblioteca no mueve
nada por su cuenta:

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| Campo del evento | Qué contiene |
| --- | --- |
| `active` | El arrastre: `id`, `ids`, `items` (cada uno `{ id, data, type, item }`), `data`, `type`. |
| `over` | Este destino: `id`, `data`, `element`, `rect`. |
| `pointer`, `delta` | Dónde está el puntero y cuánto se ha movido desde el inicio. |
| `position` | Dónde está la caja arrastrada dentro de este destino (siguiente sección). |
| `source` | Presente cuando los ítems vienen de una lista ordenable: `{ list, remove() }`. |

El orden es `onBeforeDrop` (decidir), `onDrop` (aplicar) y luego el `drag-end` del provider. Para
preguntar antes de un drop, mantener el arrastre o aceptar solo algunos ítems, consulta
[decidir un drop](/docs/guides/drop-decisions).

## Dejarlo donde se soltó {#leave-it-where-it-was-dropped}

Un tablero, un lienzo, un plano: el ítem se queda donde lo sueltas. Cada evento lleva
`position`, el `left` / `top` que coloca un ítem con posición absoluta donde se soltó.

::example{name="constraints" hint="Arrastra una nota y luego bloquea un eje o desactiva la cuadrícula" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` es la esquina superior izquierda de la caja arrastrada dentro de `over`: medida desde
el borde de su padding y sumando su scroll. Vale `null` cuando no hay nada debajo. Con
`overlay: false` es la esquina del propio elemento.

::tip
No calcules el punto a partir de `active.rect` y `delta`: así se pierden el borde y el
scroll del destino. El ajuste a una cuadrícula, los límites y el bloqueo de eje para este
tipo de tableros están en [restricciones](/docs/guides/constraints).
::

## Soltar dentro de un ítem ordenable {#drop-into-a-sortable-item}

Una fila de una lista ordenable también puede ser un destino de drop: una carpeta que acepta
archivos, un grupo que acepta tareas. Pon un droppable en el elemento del ítem:

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

Mientras la lista ordenaría el arrastre, un destino así solo cuenta en el **centro** de su ítem
(del 25 al 75 % a lo largo del eje de la lista). Ahí el drop va dentro del ítem y la lista no se
mueve. Cerca de los bordes, la lista ordena como siempre.

- Un destino cuyo `accept` rechaza el arrastre se ignora: la lista ordena sobre el ítem como sobre
  cualquier otro. Una carpeta que solo acepta archivos deja que las carpetas pasen de largo al
  ordenar.
- Un destino nunca recibe su propio arrastre.
- Si el ítem ya no se muestra después del drop, el overlay se encoge dentro del destino en lugar de
  volver a su sitio.

## Zonas de papelera {#trash-zones}

Un arrastre que empieza en una lista ordenable lleva `e.source`. Llama a `remove()` y la lista
quita los ítems:

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

El `onDrop` propio de la lista se ejecuta entonces con `to.index === -1`, y `e.result` contiene la
lista sin los ítems. Una lista también puede quitar lo que se suelta fuera de todo: consulta
[`dropOutside`](/docs/guides/shared-lists#dropping-outside).

## Sin overlay {#without-an-overlay}

Por defecto, un clon del elemento sigue al puntero y el elemento se queda en su sitio. Con
`overlay: false` no hay clon: mueve el elemento tú mismo con `transform`.

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

Para una vista previa del arrastre personalizada en lugar del clon, consulta [el overlay](/docs/guides/overlay).

## Teclado {#keyboard}

Un elemento arrastrable con el foco se agarra con :kbd{value="Space"} o :kbd{value="Enter"}. Las
flechas lo mueven 25 px (el `keyboard.step` del provider). Con `keyboard: 'droppables'` en el
elemento arrastrable, en cambio, saltan entre los destinos que lo aceptan, lo que encaja con zonas
muy separadas. Más en [accesibilidad](/docs/guides/accessibility).
