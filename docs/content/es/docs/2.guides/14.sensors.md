Un sensor convierte la entrada en arrastres. Solo le dice al provider «arrastra este ítem desde
aquí», luego adónde se ha movido la entrada y si se ha soltado o cancelado. El provider hace el
resto, igual para todos los sensores: un arrastre a la vez, ítems desactivados rechazados,
restricciones de activación, ordenación, desplazamiento automático, anuncios, :kbd{value="Escape"}
y todo el drop.

## Los sensores integrados {#the-built-in-sensors}

| Sensor | Entrada |
| --- | --- |
| `pointerSensor` | Ratón, táctil y lápiz, mediante Pointer Events. Captura el puntero, impide que la página seleccione texto o se desplace bajo un arrastre táctil, y se traga el clic que sigue a un arrastre. |
| `keyboardSensor` | :kbd{value="Space"} y :kbd{value="Enter"} agarran y sueltan, las flechas mueven, :kbd{value="Escape"} cancela — cualquier arrastre, también los de puntero. |

Los dos funcionan por defecto. La prop `sensors` del provider sustituye la lista:

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

Para desactivar los arrastres con teclado, mejor usa `:keyboard="false"` que quitar
`keyboardSensor`: el sensor de teclado es también lo que cancela cualquier arrastre con
:kbd{value="Escape"}. Sus teclas se reasignan con `keyboard.keys` (consulta
[Accesibilidad](/docs/guides/accessibility#the-keyboard)).

## Restricciones de activación {#activation-constraints}

Una pulsación se convierte en arrastre en cuanto cumple su restricción:

| Puntero | Por defecto |
| --- | --- |
| Ratón | Tras moverse 4 px. Al instante al pulsar sobre un `handle`, salvo que definas una restricción para el ratón. |
| Lápiz | Tras moverse 4 px. |
| Táctil | Tras una pulsación de 200 ms. Si antes se mueve más de 5 px, se aborta y la página se desplaza en su lugar. |

Una restricción tiene tres campos:

| Campo | Significado |
| --- | --- |
| `distance` | Los píxeles que debe recorrer el puntero. |
| `delay` | Los milisegundos que debe durar la pulsación. Con los dos, lo que ocurra primero inicia el arrastre. |
| `tolerance` | Con `delay`: cuánto puede moverse el puntero mientras tanto; si se pasa, la pulsación se abandona. |

Defínelas por tipo de puntero — `mouse`, `touch`, `pen` — en el provider, en un área de arrastre o
en el propio ítem. Gana la del ítem, luego la de su área y luego la del provider:

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

Para arrastrar al instante con el dedo desde un asa, da al asa `touch-action: none` (para que el
navegador no desplace la página) y al ítem `activation: { touch: { distance: 4 } }`.

### Un anillo de pulsación larga {#a-long-press-ring}

Mientras una pulsación espera, `useDnD().status` es `'activating'` y `activation.progress` va de 0
a 1:

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### Solo algunas pulsaciones {#only-some-presses}

`canDrag` es un filtro más en los elementos arrastrables y los ítems ordenables. Recibe el evento de
entrada:

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

Los hijos interactivos — botones, inputs, campos editables — nunca inician un arrastre de puntero,
así que siguen funcionando dentro de un elemento arrastrable. Con un `handle`, solo el asa inicia
uno.

## Un sensor propio {#a-sensor-of-your-own}

Un mando, un joystick en pantalla, comandos de voz: cualquier cosa que pueda señalar un ítem y
moverse puede dirigir un arrastre. Aquí tienes un joystick que agarra lo que hay bajo su cursor tras
mantenerlo 300 ms:

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

Añádelo a los `sensors` del provider, o ejecútalo mientras viva un componente con
`useSensor(joystick.sensor)`.

### Qué recibe el sensor {#what-the-sensor-gets}

`setup(context)` recibe la parte del provider:

| Miembro | Qué es |
| --- | --- |
| `props` | Las props del provider (`activation`, `keyboard`…). Léelas cuando las necesites: pueden cambiar. |
| `status` | El estado de arrastre del provider, sea cual sea el sensor que lleve el arrastre. |
| `drag` | El arrastre actual del provider, pendiente o en curso, sea cual sea el sensor que lo inició. `null` cuando no hay ninguno. |
| `activate(options)` | Pide un arrastre. Devuelve un `SensorDrag`, o `null` cuando no puede empezar ningún arrastre. |
| `cancel()` | Cancela el arrastre o la pulsación pendiente del provider. |

`activate()` acepta:

| Opción | Significado |
| --- | --- |
| `target` | Dónde cayó la entrada: un elemento dentro de un elemento arrastrable, o el id de un elemento arrastrable. Un elemento se comprueba como una pulsación real (asa, sin hijo interactivo); un id se salta las comprobaciones. |
| `point` | Dónde empieza el arrastre, en coordenadas del viewport. Por defecto: el centro del elemento arrastrable. |
| `type` | `'pointer'` (por defecto): sigue puntos, hace la prueba de colisión con los destinos, desplaza automáticamente. `'keyboard'`: se mueve de ítem en ítem, hace visibles los destinos, devuelve el foco al final. |
| `activation` | Una restricción (`{ delay: 300 }`), o un tipo de puntero (`'touch'`) para usar la configurada. Por defecto: ninguna, el arrastre empieza al instante. |
| `event` | El evento de entrada, que se pasa al `canDrag` del ítem. Un `pointerType` táctil lo convierte en un arrastre táctil (vibraciones). |
| `onStart(drag)` | El arrastre ha empezado, tras su activación. |
| `onEnd(drag)` | El arrastre ha terminado: abortado, soltado o cancelado — por quien sea. |
| `onResume(drag)` | `onBeforeDrop` respondió `'continue'`: el arrastre continúa, y `move`, `drop` y `cancel` vuelven a aplicarse. |

El `SensorDrag` que devuelve:

| Miembro | Qué hace |
| --- | --- |
| `id`, `type` | El id del ítem arrastrado, y `'pointer'` o `'keyboard'`. |
| `state` | `'pending'` (esperando la activación), `'dragging'` y luego `'ended'`. |
| `started` | El arrastre empezó, aunque ya haya terminado. |
| `move(point)` | La entrada se ha movido. Mientras está pendiente, comprueba la tolerancia; durante el arrastre, mueve el arrastre. |
| `step(direction)` | Arrastres con teclado: un paso de flecha, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | Coloca el ítem en una posición de una lista ordenable, como hacen los movimientos con teclado. Se resuelve con `false` cuando ninguna lista lo acepta ahí. |
| `drop()` | Suelta. Se resuelve con `true` cuando el drop se completa, una vez que ha aterrizado. |
| `cancel()` | Cancela: el ítem vuelve a su sitio, o se abandona una pulsación pendiente. |

Las llamadas que ya no aplican — un movimiento después del final, un segundo `drop()` — se
ignoran. Tipos completos: [Sensores](/docs/api/sensors).

::tip
Para envolver un sensor integrado, ejecuta su `setup` con un contexto propio. Créalo con
`Object.create(context, { activate: { value: myActivate } })` en lugar de con un spread, para que
los getters vivos (`status`, `drag`, `props`) sigan funcionando.
::

## Arrastres programáticos {#programmatic-drags}

`@vue-dnd-kit/actions` mueve ítems desde el código: botones de «Subir», menús, atajos de teclado,
deshacer, recorridos de bienvenida, tests. Está construido sobre la API pública de sensores, y sus
arrastres son reales: se anuncian y se animan, pasan por `onBeforeDrop`, `onDrop`, `e.result` y
`preventDefault()`, y siguen las reglas del provider (un arrastre a la vez, ítems desactivados,
`accept` y `group.put`).

```bash
npm i @vue-dnd-kit/actions
```

### moveItem: una llamada, un movimiento {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` es el `id` de una lista ordenable. Sin él, el ítem se queda en su lista.
- `index` es dónde acaba el ítem, contado sin el propio ítem y limitado a la lista. Sin él, el ítem
  va al final.
- Se resuelve con `true` cuando el drop se completa, y con `false` cuando el ítem no está
  renderizado o está desactivado, ninguna lista lo acepta ahí o el drop se rechazó.
- Las llamadas se encolan: cada una espera a que el provider esté en reposo, así que un segundo clic
  rápido no se pierde.
- Se ejecuta como un arrastre con teclado, así que se anuncia y el foco se queda en el ítem.
- Solo listas: en los árboles, las posiciones también tienen una profundidad.

Consulta [Accesibilidad](/docs/guides/accessibility#moving-without-dragging) para una fila con
botones de mover.

### startDrag: un arrastre programado {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` se resuelve una vez renderizado el movimiento, y `drop` una vez que el drop ha aterrizado.
`startDrag(id, { type: 'keyboard' })` se mueve, en cambio, de ítem en ítem
(`await drag.step('down')`), y el sensor de teclado puede tomar el relevo: una opción de menú
«Mover» que pasa el ítem a las flechas.

### Fuera de los componentes {#outside-components}

`useDnDActions()` ejecuta un sensor, llamado `actions`, en el provider de arriba. Para dirigir un
provider desde un store o desde un entorno de tests, o con un nombre propio, crea las acciones en un
sensor que ejecutes tú:

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

Después, `await tour?.moveItem('card-1', { list: 'done' })` desde cualquier sitio. Durante el
renderizado en el servidor no se arrastra nada: `moveItem` se resuelve con `false` y `startDrag`
devuelve `null`.
