```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider :animation="{ duration: 200 }" @drag-end="save">
    <RouterView />
    <template #overlay="{ items, over, accepted }">
      <!-- optional: a custom overlay for every drag -->
    </template>
  </DnDProvider>
</template>
```

Todo composable debe ejecutarse en un componente renderizado **dentro** de un provider. El
objetivo es un único provider para toda la app: las partes de la página reciben sus propias reglas
con [`makeDragArea`](/docs/api/make-drag-area). Consulta la [guía del provider](/docs/guides/provider).

## Eventos {#events}

| Evento | Payload | Cuándo |
| --- | --- | --- |
| `drag-start` | `DnDEvent` | Ha empezado un arrastre (tras su activación). |
| `drag-move` | `DnDEvent` | El puntero se ha movido durante un arrastre (como mucho una vez por frame). |
| `drag-over` | `DnDEvent` | Ha cambiado el destino bajo el arrastre. |
| `drag-end` | `DnDEndEvent` | Un drop se ha completado y se ha escrito. |
| `drag-cancel` | `DnDEvent` | El arrastre se ha cancelado o el drop se ha rechazado. |

Los mismos eventos, más `onBeforeDrop` y `onDragResume`, están disponibles en cualquier lugar bajo
el provider con [`useDnDMonitor`](/docs/api/use-dnd). Sus payloads están en
[la página de eventos](/docs/api/events).

## Slot `#overlay` {#slot-overlay}

Renderiza lo que sigue al puntero, para cada arrastre que no tiene un componente de overlay propio
(consulta la [guía del overlay](/docs/guides/overlay)). Si no renderiza nada, se vuelve al clon.
