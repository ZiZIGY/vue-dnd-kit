軸、グリッド、境界を切り替えてから、メモをドラッグしてみてください。ボードは、その上で始まるすべてのドラッグのルールを決め、各メモはドロップした場所に留まります。

::example{name="constraints" hint="ルールを切り替えてから、メモをドラッグしてください" height="26rem"}
::

## 軸を固定する {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` は横方向にだけ、`'y'` は縦方向にだけ動きます。`makeDraggable`、`makeSortableList`、`makeSortableTree`、`makeSortableItem`、`makeDragArea` のすべてがこのオプションを受け付けます。

- 固定は**すべてのモディファイアの後**に適用されるため、モディファイアが何をしても固定は保たれます。スナップや境界によってアイテムが線から押し出されることはありません。
- アイテム自身の `axis` はリストやツリーのものより優先され、ドラッグ可能な要素（またはそのリスト）のものはドラッグエリアのものより優先されます。
- ドラッグの開始時に読み取られるため、ゲッターで切り替えられます：`axis: () => (locked.value ? 'y' : undefined)`。
- `'y'` に固定したツリーでもネストできます。その場合、深さは行の中央へのホバーで決まります。

::tip
`restrictToVerticalAxis` や `restrictToHorizontalAxis` モディファイアよりも `axis` を使ってください。効果は同じですが、これらは通常のモディファイアとしてチェーンの途中で実行されるため、その後のモディファイア（両方の軸をスナップするグリッドなど）がアイテムを再び軸から外してしまうことがあります。
::

## モディファイア {#modifiers}

モディファイアは、ドラッグのオフセットを毎フレーム調整します。その結果はオーバーレイを動かす**とともに**、ターゲットを探す地点にもなります。そのため、リストは固定・制限・スナップ後の位置で並べ替えます。

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| モディファイア | 役割 |
| --- | --- |
| `restrictToVerticalAxis` | 縦方向にだけ動かします。`axis: 'y'` を推奨します。 |
| `restrictToHorizontalAxis` | 横方向にだけ動かします。`axis: 'x'` を推奨します。 |
| `restrictToWindowEdges` | オーバーレイをウィンドウ内に留めます。 |
| `restrictToParent` | オーバーレイを、ドラッグが始まったコンテナー（並べ替え可能なリスト、または通常のドラッグ可能な要素の親要素）内に留めます。 |
| `restrictToElement(target)` | オーバーレイを要素内に留めます：テンプレート参照、ゲッター、または要素そのもの。 |
| `restrictToFirstScrollableAncestor` | オーバーレイを、ドラッグ中の要素の最初のスクロール可能な祖先内に留めます。 |
| `snapToGrid(size)` | オーバーレイをグリッドにスナップさせます（後述）。 |
| `snapCenterToCursor` | 掴んだ位置のオフセットを保つ代わりに、オーバーレイの中心をポインターの下に合わせます。 |

`modifiers` は、プロバイダー、ドラッグエリア、リストとツリー、ドラッグ可能な要素と並べ替え可能なアイテムのオプションです。プロバイダー以外のものは ref やゲッターも受け付け、ドラッグの開始時に読み取られます。

### グリッドにスナップする {#snap-to-a-grid}

`snapToGrid(24)` は両方の軸を 24 px のセルにスナップさせます。オブジェクトを渡すと、さらに細かく設定できます。

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| オプション | 意味 |
| --- | --- |
| `x`、`y` | 軸ごとのセルのサイズ（ピクセル）。 |
| `origin` | `'container'`（デフォルト）：オーバーレイの左上の角が、コンテナー（並べ替え可能なリスト、または通常のドラッグ可能な要素の親）の左上から引いたグリッド線に乗ります。`'delta'`：オフセット自体を丸めるため、グリッドから外れた位置で始まったアイテムは外れたままです。 |
| `smooth` | `true` または `{ duration, easing }`：オーバーレイがセルの間を滑らかに移動します（デフォルトは 80 ms）。ターゲットはスナップ後の位置をすぐに使います。 |

### 独自のモディファイア {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

モディファイアは `transform`（それより前のモディファイアが処理した後の、ドラッグ開始位置からのオフセット）を受け取り、新しいオフセットを返します。計算に必要になりうる情報も受け取ります：`activeRect`（開始時のドラッグ中の要素）、`overlayRect`（`transform` だけ動かしたオーバーレイ）、`containerRect`、`windowRect`、`origin`（開始時のポインター）、`active`、`over`。[モディファイア](/docs/api/modifiers)を参照してください。

## 実行順 {#the-order}

複数の場所のモディファイアは、それぞれ前の結果を受けて順番に実行されます。

1. プロバイダーの `modifiers`
2. ドラッグが始まったドラッグエリアの `modifiers`
3. ドラッグ中のアイテム自身の `modifiers`、それがなければリストまたはツリーのもの
4. ドラッグエリアの `restrictToArea`
5. `axis` による固定

アイテムの `modifiers` は、リストのものに追加されるのではなく、それを**置き換え**ます。エリアの境界はステップ 1〜3 のスナップの後に来るため、スナップしたアイテムも内側に留まり、軸の固定はすべての最後に来ます。

## 境界のあるリストでも両端に届く {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

ポインターが進み続けても、境界はオーバーレイをボックスの端で止めます。ポインターがリストの軸方向にオーバーレイから外れると、リストは代わりにポインターの位置で並べ替えるため、アイテムをどう掴んでいても最初と最後の位置に届きます。グリッドは引き続きオーバーレイの位置で並べ替えます。端で止められたオーバーレイは、すでに端のセルに重なっているからです。

## ページの一部に適用するルール {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` は、その要素の**内側で始まる**ドラッグにルールを設定します。通常のドラッグ可能な要素も並べ替え可能なアイテムも同様です。`DnDProvider` はアプリ全体で 1 つにして、ボード、キャンバス、フィードにはそれぞれ専用のエリアを与えてください。

| オプション | 役割 |
| --- | --- |
| `axis` | ドラッグを 1 つの軸に固定します。ドラッグ可能な要素自身の `axis`、またはそのリストのものが優先されます。 |
| `modifiers` | プロバイダーのものの後、ドラッグ可能な要素自身のものの前に実行されます。 |
| `restrictToArea` | `true`：ドラッグはエリアの要素の内側に留まります。 |
| `autoScroll` | エリアのスクロールコンテナー（その要素、または最も近いスクロール可能な祖先）の自動スクロール。`false` でそこでの自動スクロールをオフにします。 |
| `activation` | ポインターの種類ごとの[アクティベーション](/docs/guides/sensors#activation-constraints)。ドラッグ可能な要素自身のものが優先され、プロバイダーのものは最後です。 |
| `disabled` | エリア内では、内側のエリアも含め、ドラッグが始まりません。そのドラッグ可能な要素は `aria-disabled` を報告します。 |

どのオプションも値、ref、ゲッターを受け付け、押下またはドラッグの開始時に読み取られます。エリアは `isDragging`（ここで始まったドラッグが実行中）と `isAutoScrolling`（自動スクロールがコンテナーを動かしている）を返します。完全なリファレンス：[makeDragArea](/docs/api/make-drag-area)。

### エリアの組み合わせ方 {#how-areas-combine}

- ドラッグは、エリアの外に出た後も、**始まった**エリアに従います。エリアの上を通過しても何も変わりませんが、そのエリアの `autoScroll` だけは例外で、コンテナーをスクロールさせるすべてのドラッグに適用されます。
- ネストしたエリアはマージされず、最も近いものが優先されます。`disabled` は例外で、継承されます：オフになっているエリアは、その内側のエリアもオフにします。
- 衝突判定、キーボードのキー、読み上げは、プロバイダー全体の設定のままです。

::note
ボードの周りに 2 つ目の `DnDProvider` を置かないのはなぜでしょうか？プロバイダーは互いに独立しています。ドラッグがあるプロバイダーから別のプロバイダーへまたがることはないため、ボードのアイテムは決してボードの外に出られなくなります。プロバイダーをネストするのは、ページの一部がプロバイダー全体の設定を独自に必要とし、かつそのアイテムがその中に留まる場合だけにしてください。[プロバイダー](/docs/guides/provider)を参照してください。
::

## ドロップした場所に置く {#leave-it-where-its-dropped}

例のボードはドロップターゲットでもあり、各メモはドロップされた場所に留まります。すべてのドラッグイベントは `position` を持っています。これはターゲットの中でのドラッグ中のボックスの左上の角で、ターゲットのパディングの端から測り、スクロール量を含めた値です。つまり、絶対配置したアイテムをまさにその場所に置くための `left` と `top` です。モディファイアの後で計算されるため、スナップしたメモはグリッド上に着地します。

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

自由なドラッグとドロップターゲットについて詳しくは[ドラッグ＆ドロップ](/docs/guides/drag-and-drop)を参照してください。
