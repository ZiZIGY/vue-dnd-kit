## アプリにプロバイダーを 1 つ {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

`DnDProvider` を `App.vue` やレイアウトなど上位の階層に 1 つ置けば、あとは気にする必要はありません。すべてのコンポーザブル（`makeSortableList`、`makeDraggable`、`useDnD`…）は、自分が実行されるコンポーネントより上にある最も近いプロバイダーを探します。

::warning
コンポーザブルは、プロバイダーの**内側に描画される**コンポーネントで実行する必要があります。自身のテンプレートに `<DnDProvider>` を含むコンポーネントで呼び出すと、`No <DnDProvider> found above this component` がスローされます。Vue の `inject` は祖先しか参照できないためです。
::

## プロバイダーが管理するもの {#what-it-owns}

| パーツ | プロバイダーの役割 |
| --- | --- |
| 入力 | ポインター・タッチ・キーボードの入力をドラッグに変換します（`sensors`）。ドラッグは一度に 1 つだけです。 |
| ターゲットの検出 | ドラッグの下にあるドロップターゲットをヒットテストし（`collision`）、それらに通知します。 |
| オーバーレイ | ポインターに追従するボックスを `body` にテレポートして描画し、ドロップ時に着地させます。 |
| 選択 | 選択中の id の集合を 1 つ持ち、配下のすべてのリストとドラッグ可能な要素で共有します。 |
| 自動スクロール | ドラッグが端に近づくと、コンテナーやウィンドウをスクロールします。 |
| ライブリージョン | 持ち上げ、移動、ドロップ、キャンセルをスクリーンリーダーに読み上げます。 |

それ以外は何も描画しません。マークアップはそのままです。

## オプションの概要 {#options-at-a-glance}

すべてのオプションにはそのまま使えるデフォルト値があるため、通常プロバイダーにオプションは不要です。

| Prop | デフォルト | 設定する内容 |
| --- | --- | --- |
| `collision` | `pointerFirst` | ドラッグの下のターゲットをどう選ぶか。 |
| `modifiers` | `[]` | すべてのドラッグに適用する移動ルール（スナップ、制限など）。 |
| `animation` / `dropAnimation` | オン | 並べ替え中のアイテムのスライド / オーバーレイの着地。 |
| `animate` | オフ | リストとツリーのデフォルト：ドラッグ以外によるデータの変更をアニメーションさせます。 |
| `autoScroll` | オン | 端でのスクロール：`{ threshold, maxSpeed, acceleration }` または `false`。 |
| `activation` | マウス 4 px、タッチ 200 ms | 押下がいつドラッグになるか。ポインターの種類ごとに設定します。 |
| `keyboard` | Space / Enter、Escape | キーボードのキーとステップ。`false` でキーボードドラッグをオフにします。 |
| `sensors` | ポインター + キーボード | 何が入力をドラッグに変換するか。 |
| `haptics` | タッチで持ち上げたときに短く振動 | タッチドラッグの振動、または `false`。 |
| `copyModifier` | `'Alt'` | ドラッグ中に押していると移動がコピーになるキー（リストに `clone` が必要）。 |
| `overlayTo` | `'body'` | オーバーレイのテレポート先。 |
| `overlayFit` | `'slot'` | オーバーレイのサイズ：着地する位置のサイズ、または元の要素のサイズ。 |
| `announcements` | 組み込み | スクリーンリーダー用のテキスト、または `false`。 |
| `defaultStyles` | `true` | ドラッグ状態のための詳細度ゼロの CSS を挿入します。 |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

すべての形を含む完全な一覧は [DnDProvider API](/docs/api/dnd-provider) にあります。プロバイダーは `drag-start`、`drag-move`、`drag-over`、`drag-end`、`drag-cancel` も発行します。これは `useDnDMonitor` が受け取るイベントと同じです。

::tip
ページの一部だけのルール（スナップするボード、縦にしかスクロールしないフィード）に専用のプロバイダーは不要です。その部分を[ドラッグエリア](/docs/guides/constraints)で囲んでください。
::

## ドラッグを読み取る：`useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="タスクをドラッグして状態を見てみましょう" height="22rem"}
::

`useDnD()` は、プロバイダーの下にある任意のコンポーネントで、ドラッグをリアクティブな状態として返します。

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| フィールド | 内容 |
| --- | --- |
| `status` | `'idle'`、`'activating'`（長押しをチャージ中）、`'dragging'`、`'dropping'`（着地中、または非同期の `onBeforeDrop` を待機中）、`'selecting'`（範囲選択中）。 |
| `active` | ドラッグされているもの：`id`、`ids`（ドラッグ中のすべての id。掴んだものが先頭）、`items`、`data`、`type`、`element`、`rect`、`sensor`。アイドル時は `null`。 |
| `over` | ドラッグの下のターゲット：`id`、`data`、`element`、`rect`、`accepted`。何もない上では `null`。 |
| `pointer` | ビューポート座標でのポインター位置。モディファイア適用後の値です。 |
| `activation.progress` | 長押しのチャージ中に `0` から `1` へ進みます。これでリングを描けます。 |
| `isAutoScrolling` | 自動スクロールが何かをスクロールしています。 |
| `selection` | プロバイダーの選択：`ids`、`has`、`add`、`delete`、`toggle`、`set`、`clear`。[マルチドラッグ](/docs/guides/multi-drag)を参照してください。 |
| `cancel()` | 実行中のドラッグ（アイテムは元の位置に戻ります）、チャージ中の長押し、または範囲選択をキャンセルします。 |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

ドロップが決まった時点で、オーバーレイがまだ着地中でも（`status` は `'dropping'` のまま）、`active`、`over`、`pointer` は `null` になります。これらから派生した UI が、古いドラッグを新しいデータと並べて表示することはありません。非同期の `onBeforeDrop` が待機している間は、状態は離した時点のまま保たれます。

## すべてのドラッグを監視する：`useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

モニターは、どこで始まったかに関係なく、自分のプロバイダーの下のすべてのドラッグを受け取ります。呼び出したコンポーネントがアンマウントされると停止します。

| イベント | タイミング |
| --- | --- |
| `onDragStart` | ドラッグが始まった。 |
| `onDragMove` | ドラッグが動いた。 |
| `onDragOver` | ドラッグの下のターゲットが変わった。 |
| `onBeforeDrop` | ドラッグが離された。その返り値がドロップを決めます：[ドロップの判断](/docs/guides/drop-decisions)を参照してください。 |
| `onDragEnd` | ドロップが完了した。並べ替え可能なリストは、それぞれの `onDrop` を実行し、新しい順序を書き込み済みです。ターゲットがない場所で終わった場合、`dropped` は `false` です。 |
| `onDragCancel` | Escape、ドロップを拒否するターゲットへのドロップ、または `onBeforeDrop` が `'reject'` を返した。 |
| `onDragResume` | `onBeforeDrop` が `'continue'` を返した：何もドロップされず、ドラッグが続きます。 |

すべてのイベントは、`active`、`over`、`pointer`、`delta`（開始位置からのオフセット）、`position`（ドラッグ中のボックスが `over` の中のどこにあるか。[ドラッグ＆ドロップ](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)を参照）を持ち、並べ替え可能なリストからのアイテムでは `source` も持ちます。完全な形は[イベント API](/docs/api/events) にあります。

::note
「ドロップ後」の処理は `onDragEnd` で行います：保存、選択のクリア、アナリティクスなど。リスト自身の `onDrop` は書き込みの**前**に実行されるため、まだ古い順序が見えています。
::

## 複数のプロバイダー {#several-providers}

ほとんどのアプリに必要なのはちょうど 1 つです。2 つ目のプロバイダーに意味があるのは、ページの一部がプロバイダー全体の設定（衝突判定、キーボードのキー、読み上げ）を独自に必要とし、かつそのアイテムがその外に出ない場合だけです。

- プロバイダーは互いに独立しています。ドラッグがあるプロバイダーから別のプロバイダーへまたがることはありません。
- プロバイダーのネストは可能です。**最も近い所有者が優先**されます。アイテムは自分より上にある最も近いプロバイダーに属し、外側のプロバイダーはそれを無視します。
- 各プロバイダーは独自の選択、オーバーレイ、ライブリージョンを持ちます。

ページの 2 つの部分の間でアイテムを移動できない場合は、それらが 2 つのプロバイダーの下にないか確認してください。

::tip
別の場所にマウントされたアプリ（shadow root の中や、別の Vue アプリとして）も、既存のプロバイダーに参加できます。マウントする前に、`useDnDContext()` を `provideDnDContext(app, context)` に渡してください。
::

## SSR と Nuxt {#ssr-and-nuxt}

プロバイダーは SSR セーフです。リストとアイテムは、ほかのマークアップと同じようにサーバーで描画されます。オーバーレイとライブリージョンはテレポートされ、クライアントでのみマウントされるため、ハイドレーションミスマッチを起こすことはありません。デフォルトの id は Vue の `useId()` から取られ、サーバーとクライアントで一致します。

Nuxt では、モジュールが `DnDProvider` をグローバルに登録し、コンポーザブルを自動インポートします：[インストール](/docs/getting-started/installation#nuxt)を参照してください。
