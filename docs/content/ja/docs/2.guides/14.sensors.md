センサーは入力をドラッグに変換します。センサーがプロバイダーに伝えるのは「このアイテムをここからドラッグする」ということと、その後に入力がどこへ動いたか、ドロップしたかキャンセルしたかだけです。残りはプロバイダーが、どのセンサーに対しても同じように行います：ドラッグは一度に 1 つ、無効なアイテムの拒否、アクティベーション制約、並べ替え、自動スクロール、読み上げ、:kbd{value="Escape"}、そしてドロップの全体です。

## 組み込みのセンサー {#the-built-in-sensors}

| センサー | 入力 |
| --- | --- |
| `pointerSensor` | Pointer Events を通じたマウス、タッチ、ペン。ポインターをキャプチャし、タッチドラッグの下でページがテキストを選択したりスクロールしたりするのを防ぎ、ドラッグの後に続くクリックを握りつぶします。 |
| `keyboardSensor` | :kbd{value="Space"} と :kbd{value="Enter"} で持ち上げとドロップ、矢印キーで移動、:kbd{value="Escape"} でキャンセル。キャンセルはどのドラッグにも効き、ポインタードラッグも含みます。 |

どちらもデフォルトで動作します。プロバイダーの `sensors` はこのリストを置き換えます。

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

キーボードドラッグをオフにするには、`keyboardSensor` を外すより `:keyboard="false"` を使ってください。キーボードセンサーは、:kbd{value="Escape"} でどのドラッグもキャンセルする役割も担っているからです。キーの割り当ては `keyboard.keys` で変更します（[アクセシビリティ](/docs/guides/accessibility#the-keyboard)を参照）。

## アクティベーション制約 {#activation-constraints}

押下は、制約を満たした時点でドラッグになります。

| ポインター | デフォルト |
| --- | --- |
| マウス | 4 px 動いた後。`handle` 上で押した場合は、マウスの制約を設定していない限り即座に。 |
| ペン | 4 px 動いた後。 |
| タッチ | 200 ms 押した後。その前に 5 px を超えて動くと中断され、代わりにページがスクロールします。 |

制約には 3 つのフィールドがあります。

| フィールド | 意味 |
| --- | --- |
| `distance` | ポインターが移動しなければならないピクセル数。 |
| `delay` | 押下が続かなければならないミリ秒数。両方を指定した場合は、先に満たされたほうでドラッグが始まります。 |
| `tolerance` | `delay` と組み合わせて：待っている間にポインターが動いてよい距離。それを超えると押下は破棄されます。 |

ポインターの種類（`mouse`、`touch`、`pen`）ごとに、プロバイダー、ドラッグエリア、またはアイテム自体に設定します。アイテム自身のものが優先され、次にそのエリアのもの、最後にプロバイダーのものです。

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

ハンドルからタッチですぐにドラッグするには、ハンドルに `touch-action: none` を（ブラウザーがスクロールしないように）、アイテムに `activation: { touch: { distance: 4 } }` を指定してください。

### 長押しのリング {#a-long-press-ring}

押下が待機している間、`useDnD().status` は `'activating'` で、`activation.progress` は 0 から 1 へ進みます。

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### 一部の押下だけ {#only-some-presses}

`canDrag` は、ドラッグ可能な要素と並べ替え可能なアイテムに設けられたもう 1 つの関門です。入力イベントを受け取ります。

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

インタラクティブな子要素（ボタン、入力欄、編集可能なフィールド）ではポインタードラッグが始まらないため、ドラッグ可能な要素の中でもそのまま動作します。`handle` がある場合は、ハンドルだけがドラッグを始めます。

## 独自のセンサー {#a-sensor-of-your-own}

ゲームパッド、画面上のジョイスティック、音声コマンド：アイテムを指して動かせるものなら、何でもドラッグを操作できます。次の例は、300 ms 押し続けるとカーソルの下にあるものを持ち上げるジョイスティックです。

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

これをプロバイダーの `sensors` に追加するか、`useSensor(joystick.sensor)` でコンポーネントが生きている間だけ実行してください。

### センサーが受け取るもの {#what-the-sensor-gets}

`setup(context)` はプロバイダー側のインターフェースを受け取ります。

| メンバー | 内容 |
| --- | --- |
| `props` | プロバイダーの props（`activation`、`keyboard`…）。変わる可能性があるため、必要なときに読み取ってください。 |
| `status` | プロバイダーのドラッグの状態。どのセンサーがドラッグを実行していても同じです。 |
| `drag` | プロバイダーの現在のドラッグ（保留中または実行中）。どのセンサーが始めたかは問いません。ない場合は `null`。 |
| `activate(options)` | ドラッグを要求します。`SensorDrag` を返します。ドラッグを始められない場合は `null`。 |
| `cancel()` | プロバイダーのドラッグ、または保留中の押下をキャンセルします。 |

`activate()` が受け取るもの：

| オプション | 意味 |
| --- | --- |
| `target` | 入力が着地した場所：ドラッグ可能な要素の中の要素、またはドラッグ可能な要素の id。要素は本物の押下と同じようにチェックされます（ハンドル、インタラクティブな子要素でないこと）。id ではチェックがスキップされます。 |
| `point` | ドラッグが始まる位置（ビューポート座標）。デフォルト：ドラッグ可能な要素の中心。 |
| `type` | `'pointer'`（デフォルト）：座標を追い、ターゲットをヒットテストし、自動スクロールします。`'keyboard'`：アイテム単位で移動し、ターゲットをスクロールして表示し、終了時にフォーカスを戻します。 |
| `activation` | 制約（`{ delay: 300 }`）、または設定済みのものを使うためのポインターの種類（`'touch'`）。デフォルト：なし。ドラッグはすぐに始まります。 |
| `event` | 入力イベント。アイテムの `canDrag` に渡されます。タッチの `pointerType` を持つと、タッチドラッグ（触覚フィードバック）になります。 |
| `onStart(drag)` | アクティベーションの後、ドラッグが始まった。 |
| `onEnd(drag)` | ドラッグが終わった：中断、ドロップ、またはキャンセル（誰によるものでも）。 |
| `onResume(drag)` | `onBeforeDrop` が `'continue'` を返した：ドラッグが続き、`move`、`drop`、`cancel` が再び有効になります。 |

返される `SensorDrag`：

| メンバー | 役割 |
| --- | --- |
| `id`、`type` | ドラッグ中のアイテムの id と、`'pointer'` または `'keyboard'`。 |
| `state` | `'pending'`（アクティベーション待ち）、`'dragging'`、そして `'ended'`。 |
| `started` | ドラッグが始まった（その後終わっていても）。 |
| `move(point)` | 入力が動いた。保留中は許容範囲をチェックし、ドラッグ中はドラッグを動かします。 |
| `step(direction)` | キーボードドラッグ：矢印キー 1 回分のステップ。`'up' \| 'down' \| 'left' \| 'right'`。 |
| `place({ list, index })` | キーボードでの移動と同じように、アイテムを並べ替え可能なリストの位置に置きます。そこで受け入れるリストがない場合は `false` で resolve します。 |
| `drop()` | ドロップします。ドロップが成立した場合は、着地した後に `true` で resolve します。 |
| `cancel()` | キャンセルします：アイテムは元の位置に戻るか、保留中の押下は破棄されます。 |

もう適用されない呼び出し（終了後の移動、2 回目の `drop()`）は無視されます。完全な型：[センサー](/docs/api/sensors)。

::tip
組み込みのセンサーをラップするには、独自のコンテキストでその `setup` を実行します。コンテキストはスプレッド構文ではなく `Object.create(context, { activate: { value: myActivate } })` で作ってください。そうすれば、ライブなゲッター（`status`、`drag`、`props`）が動作し続けます。
::

## プログラムによるドラッグ {#programmatic-drags}

`@vue-dnd-kit/actions` は、コードからアイテムを動かします：「上へ移動」ボタン、メニュー、キーボードショートカット、元に戻す操作、オンボーディングツアー、テスト。公開されたセンサー API の上に作られており、そのドラッグは本物のドラッグです。読み上げられ、アニメーションし、`onBeforeDrop`、`onDrop`、`e.result`、`preventDefault()` を通り、プロバイダーのルール（ドラッグは一度に 1 つ、無効なアイテム、`accept` と `group.put`）に従います。

```bash
npm i @vue-dnd-kit/actions
```

### moveItem：1 回の呼び出しで 1 回の移動 {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` は並べ替え可能なリストの `id` です。指定しなければ、アイテムは今のリストに留まります。
- `index` はアイテムの最終的な位置で、アイテム自身を除いて数え、リストの範囲内に収められます。指定しなければ、アイテムは末尾に移動します。
- ドロップが成立すると `true` で resolve し、アイテムが描画されていないか無効である、そこで受け入れるリストがない、またはドロップが拒否された場合は `false` です。
- 呼び出しはキューに入ります：それぞれプロバイダーがアイドルになるまで待つため、素早い 2 回目のクリックも失われません。
- キーボードドラッグとして実行されるため、読み上げられ、フォーカスはアイテムに留まります。
- リストのみ：ツリーの位置には深さも含まれるためです。

移動ボタン付きの行については[アクセシビリティ](/docs/guides/accessibility#moving-without-dragging)を参照してください。

### startDrag：スクリプトによるドラッグ {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` は移動が描画された後に、`drop` はドロップが着地した後に resolve します。`startDrag(id, { type: 'keyboard' })` では代わりにアイテム単位で移動し（`await drag.step('down')`）、キーボードセンサーが引き継ぐこともできます。たとえば、アイテムを矢印キーに渡す「移動」メニュー項目です。

### コンポーネントの外で {#outside-components}

`useDnDActions()` は、上にあるプロバイダーで `actions` という名前のセンサーを 1 つ実行します。ストアやテストハーネスからプロバイダーを操作したい場合や、独自の名前を使いたい場合は、自分で実行するセンサーの中で actions を作成してください。

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

あとはどこからでも `await tour?.moveItem('card-1', { list: 'done' })` を呼べます。サーバーレンダリング中は何もドラッグされません：`moveItem` は `false` で resolve し、`startDrag` は `null` を返します。
