カードを **Done** にドラッグしてください。ドロップはあなたの返答を待ちます：カードを移動する、別の場所へドラッグし続ける、またはキャンセルする。

::example{name="drop-confirm" hint="カードを Done にドラッグしてください" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

リスト、ツリー、ドロップターゲット（`makeDroppable`）、モニター（`useDnDMonitor`）は `onBeforeDrop` を受け付けます。これはドラッグが離されたとき、何かが変わる前に実行され、その返り値で結果が決まります。

| 返り値 | 結果 |
| --- | --- |
| `'accept'`、`true`、または何も返さない | ドロップが成立します。 |
| `'reject'` または `false` | ドロップしません：アイテムは元の位置に戻ります。エラーがスローされた場合も拒否になります。 |
| キーの配列 | それらのアイテムだけがドロップされ、ほかは元の位置に戻ります。 |
| `'continue'` | ドロップせず、ドラッグが続きます。 |
| これらのいずれかを返す Promise | Promise が確定するまで、オーバーレイは離された場所で待ちます。 |

ターゲット自身のルールが先に適用されます：ドロップターゲットの `accept`、リストの `group.put`。ドラッグを拒否するターゲットの上ではドロップはキャンセルされ、そのターゲットの `onBeforeDrop` は呼ばれません。`onBeforeDrop` は、そうしたルールでは分からないことのためにあります：ユーザーの返答、サーバーの返答、あるいはドロップによって何が変わるか、などです。

リストとツリーは `SortableDropEvent` を渡します：`keys`、`items`、`from`、`to`、`mode`、`sameList`、そしてドロップで変わるすべてのリストの新しい配列である `result`。ドロップターゲットとモニターは汎用の `DnDEvent` を受け取ります：`active`、`over`、`position`、`source`。[イベント](/docs/api/events)を参照してください。

### 一部のアイテムだけを受け入れる {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

[マルチドラッグ](/docs/guides/multi-drag)では、返したキーのアイテムが着地し、残りは元の場所に戻ります。その後 `onDrop` は、それらを `e.accepted` と `e.rejected` で受け取り、その `e.result` は最終的なものです。

## ドラッグを続ける：'continue' {#keep-dragging-continue}

`'continue'` がキャンセルするのはドロップであって、ドラッグではありません。アイテムはその場所から手に持たれたままで、ページはドラッグモードに戻り、ユーザーは操作を続けます。

- マウスやペンでは、ボタンを押していなくてもアイテムがポインターに追従します。次に離したとき、つまりクリックしたときにドロップされ、そのクリックが下にあるページに届くことはありません。
- タッチでは、指が触れた場所でアイテムをもう一度掴みます。指を離すとドロップされます。
- キーボードドラッグはそのまま続きます：矢印キーでアイテムを動かし、:kbd{value="Space"} または :kbd{value="Enter"} でドロップします。
- :kbd{value="Escape"} は、ほかのドラッグと同じくキャンセルします。
- 次のドロップでは、もう一度 `onBeforeDrop` に問い合わせます。

モニターは `onDragResume` を受け取り、スクリーンリーダーは、アイテムがドロップされずにまだ移動中であることを読み上げます（テキストはプロバイダーの `announcements.onDragResume` で上書きできます）。

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## ユーザーに確認する {#asking-the-user}

`onBeforeDrop` は Promise を返せます。ダイアログを開き、ユーザーが選んだボタンで Promise を resolve してください。

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Promise が保留中の間は：

- オーバーレイは離された場所で待機し、`data-dnd-overlay="dropping"` が付きます。
- `useDnD()` は離した時点の状態を保ち、`status` は `'dropping'` です。
- ページはドラッグモードから抜けています：カーソルとテキスト選択が元に戻るため、ダイアログは通常どおり動作します。

::tip
`showModal()` で開いたモーダルの `<dialog>` はトップレイヤーにあり、待機中のオーバーレイより上に表示されます。例と同じように、その `cancel` イベント（:kbd{value="Escape"}）を `'reject'` に変換してください。
::

## フックの順序 {#the-order-of-the-hooks}

1. 各 `useDnDMonitor` の `onBeforeDrop` を順番に。`'reject'` または `'continue'` で問い合わせは終わり、キーを返すとドロップの対象が絞り込まれます。
2. ターゲットの `onBeforeDrop`：アイテムが入るリストまたはツリー、あるいはドロップターゲット。
3. ターゲットの `onDrop` のみ：アイテムが別のリストへ出ていく側のリストには問い合わせず、その新しい配列はターゲットの `e.result` に入っています。アイテムが取り除かれる場合（ゴミ箱ゾーン、`dropOutside: 'remove'`）は、そのリストの `onDrop` が `to.index` を `-1` として実行されます。
4. デフォルトの書き込み：ドロップで変わる各リストが新しい配列を受け取ります。
5. オーバーレイが着地します。その後にプロバイダーの `@drag-end` とモニターの `onDragEnd` が続きます。

あなたのモニターはターゲットより先に判断するため、リストがすでに独自にドロップを適用した後に拒否が来ることはありません。

## onDrop：書き込みの前に通知される {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

リストの `onDrop` は、ドロップが受け入れられた後、リストが書き込む直前に同期的に実行されます。書き込みの後に何かをするには、プロバイダーの `@drag-end` か `useDnDMonitor({ onDragEnd })` を使ってください。通常のドロップターゲットでは、`onDrop` があなたがデータを変更する場所です：ライブラリはそのために何も動かしません。

## ストアとサーバー：制御されたリスト {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

ライブラリがドロップを書き込むのは、書き込み可能な ref だけです。ゲッター、`computed`、`readonly` の ref には決して書き込みません。`e.preventDefault()` を呼び、`e.result`（ドロップで変わるすべてのリストの新しい配列。リストの id がキー）を自分で適用してください。`preventDefault()` はそのすべてへの書き込みをスキップします。一部だけに書き込むと、アイテムが失われたり重複したりするためです。読み取り専用のリストのドロップをライブラリに任せたままにすると、開発ビルドで警告が出ます。

### 先にサーバーに保存する {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Promise が resolve する前に `e.result` を適用すれば、オーバーレイは新しい順序で着地します。リクエストが失敗したときは何も適用しないでください：ドロップは成立しますが何も変わらず、アイテムは元の位置に戻ります。

## すべてのターゲットの外にドロップする {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | すべてのターゲットの外へのドロップは… |
| --- | --- |
| `'placeholder'` | プレースホルダーのある場所、つまりリストが最後に表示していた位置に着地します。デフォルトです。 |
| `'cancel'` | キャンセルされます：アイテムは元の位置に戻ります。`placeholder: 'indicator'` のときのデフォルトです。 |
| `'remove'` | アイテムをリストから取り除きます。先にリストの `onBeforeDrop` に問い合わせ、その `onDrop` は `to.index` を `-1` として受け取ります。 |

ゴミ箱ゾーンは、同じことを意図的に行います：`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`。[ドラッグ＆ドロップ](/docs/guides/drag-and-drop)を参照してください。
