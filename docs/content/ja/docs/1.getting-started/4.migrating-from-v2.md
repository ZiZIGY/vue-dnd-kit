v3 は v2 を書き直したものです。モデルは同じです：1 つのプロバイダーと、自分の要素に対して呼び出すコンポーザブル。ただし、ほとんどの名前とオプションが変わり、並べ替えはライブラリの中に移り、リストごとに書いていたドロップハンドラーは不要になります。このページでは、v2 の各部分を v3 に対応付け、よくあるケースを移行前と移行後で示します。

## 変更点 {#what-changed}

- **並べ替えは組み込み**です。v2 ではリストはドロップゾーンで、その行は `[index, items]` のペイロードを持つドラッグ可能な要素であり、`onDrop` の中で `e.helpers.suggestSort()` を使って並べ替えていました。v3 では `makeSortableList` と `makeSortableItem` がそれを行います：リストは配列の**ドラフト**を描画し、それがドラッグ中に並べ替わり、ドロップすると新しい配列が ref に書き込まれます。v2 のドロップハンドラーのほとんどは、移植するのではなく削除します。
- **ものは自分で動きます**。行は新しい位置へスライドし（FLIP）、オーバーレイはドロップで自分の位置に着地し、キャンセルで元の位置に戻ります。`<TransitionGroup>` は不要になります。
- **パッケージは今も 1 つ**です。`@vue-dnd-kit/core` にリスト、ツリー、マルチドラッグ、モディファイア、センサー、衝突判定の関数が入っています。Nuxt モジュールは引き続きあり、`@vue-dnd-kit/actions`（プログラムによるドラッグ）と `@vue-dnd-kit/devtools` は新しいオプションのパッケージです。
- **本物のオーバーレイ**です。`body` にテレポートされ、着地する位置と同じサイズのディープクローンを表示します。オーバーレイコンポーネントは、プロバイダーの内部を読む代わりに、ドラッグを props として受け取ります。
- **要素ではなく id**です。選択、イベント、ドラッグの状態は、データの id をキーにしています。読むべき DOM 要素のマップはありません。
- **型と accept ルール**が、通常のドラッグ可能な要素とドロップターゲットの `groups` に代わります。リストは `group` の名前でアイテムをやり取りします。
- **判断はドロップの前に**行います。`onBeforeDrop` が受け入れる、拒否する、ドラッグを続ける、またはアイテムの一部だけを受け取るかを決めます。`onDrop` は適用するだけです。
- **センサー**。ポインターとキーボードの入力はセンサーです。アクティベーションはポインターの種類ごとに設定し、タッチのドラッグは長押しで始まるので、指の下でもリストはスクロールし続けます。
- **エリア**。`makeDragArea` が `makeConstraintArea` と `makeAutoScroll` に代わり、自動スクロールはコードなしですべてのスクロールコンテナーで動きます。
- **アクセシビリティはデフォルトでオン**です：ARIA 属性、ドロップ後に戻ってくるフォーカス、スクリーンリーダーへの読み上げ。

## アップグレード {#upgrade}

::code-group

```bash [npm]
npm i @vue-dnd-kit/core@^3
```

```bash [yarn]
yarn add @vue-dnd-kit/core@^3
```

```bash [pnpm]
pnpm add @vue-dnd-kit/core@^3
```

```bash [bun]
bun add @vue-dnd-kit/core@^3
```

::

| パッケージ | v2 | v3 |
| --- | --- | --- |
| `@vue-dnd-kit/core` | 2.4.x | 3.x |
| `@vue-dnd-kit/nuxt` | 1.x | 3.x |
| `@vue-dnd-kit/actions` | — | 1.x、オプション |
| `@vue-dnd-kit/devtools` | — | 3.x、オプション |

- `package.json` に `"@vue-dnd-kit/core": "^2…"` と書かれたアプリは、範囲を `^3` にするまで v2 のままです。
- Vue **3.5** 以降。v2 には依存関係がありませんでしたが、v3 には `@vueuse/core`（14 または 15）が 1 つあります。
- ブラウザー：Chrome と Edge 104+、Safari 15.4+、Firefox 104+。
- v2 と v3 は同じパッケージ名なので、アプリは一度に v3 へ移行します。互換レイヤーはありません。v2 のドキュメントは、ページ上部のバージョンメニューから引き続き見られます。

おすすめの作業順：

1. パッケージをアップグレードし、プロバイダーの props の名前を変えます（[後述](#the-provider)）。
2. 並べ替え可能なリストをそれぞれ `makeSortableList` と `makeSortableItem` に変え、そのドロップハンドラーを削除します。
3. 通常のドラッグ可能な要素とドロップゾーンを移植します。
4. カスタムプレビューを、オーバーレイコンポーネントかプロバイダーの `#overlay` スロットに移植します。
5. `makeConstraintArea` と `makeAutoScroll` を `makeDragArea` に置き換えるか、何も使わないようにします。
6. v2 のための回避策を削除します：ドラッグ可能な要素の `tabindex` と `aria-grabbed`、アイテム全体の `touch-action: none`、行を囲む `<TransitionGroup>`、プレビューコンポーネントを囲む `markRaw`。

## 新旧の対応 {#old-to-new}

表の中の**対応なし**は、v3 にその名前のものがないことを意味します。代わりに何を使うかはセルに書いてあります。

### ひと目で {#at-a-glance}

| v2 | v3 |
| --- | --- |
| `DnDProvider` | `DnDProvider`。新しい props と `#overlay` スロットがあります。 |
| `makeDraggable` | 自由なドラッグには `makeDraggable`、リストの行には `makeSortableItem`。 |
| `makeDroppable` | 通常のドロップターゲットには `makeDroppable`、リストとツリーには `makeSortableList` または `makeSortableTree`。 |
| `makeSelectionArea` | `makeSelectionArea`。 |
| `makeConstraintArea` | `makeDragArea`。 |
| `makeAutoScroll` | 不要：自動スクロールは自動です。`makeDragArea` かリストの `autoScroll` で調整します。 |
| `useDnDProvider` | 状態には `useDnD`、イベントには `useDnDMonitor`。 |
| `injectionKey` | `useDnDContext()` と `provideDnDContext(app, context)`。 |
| `DragPreview` | `DragPreview`：今はドラッグ中のアイテム 1 つのクローンで、自作のオーバーレイ用です。 |
| `makeSnappedOverlayPosition`、`<DragPreview :grid>` | `snapToGrid` モディファイア。 |
| `e.helpers.suggestSort`、`suggestSwap`、`suggestCopy`、`suggestRemove` | リストに組み込み：[並べ替え](#sorting)を参照。 |

### プロバイダー {#the-provider}

| v2 | v3 |
| --- | --- |
| `autoScrollViewport`、設定しなければオフ | `autoScroll`：**デフォルトでオン**。ウィンドウとすべてのスクロールコンテナーが対象です。`{ threshold, maxSpeed, acceleration }` または `false`。 |
| `previewTo`、デフォルトではプロバイダーの中に描画 | `overlayTo`：セレクターまたは要素。デフォルトは `'body'`。 |
| `#preview="{ preview }"` スロット | ドラッグを props として受け取る `#overlay` スロット：`items`、`active`、`over`、`accepted`、`status`、`mode`、`to`。[オーバーレイ](#the-overlay)を参照。 |
| `keyboard.keys.forDrag`、`forDrop`、`forCancel`（`useDnDProvider()` で設定） | `:keyboard="{ keys: { start, drop, cancel } }"`。 |
| `keyboard.step` | `:keyboard="{ step }"`：デフォルトは 25 px で、自由なドラッグ用です。 |
| `keyboard.keys.forMove`、`forMoveFaster`、`keyboard.moveFaster` | **対応なし**。矢印キーで動かします。:kbd{value="Shift"} で自由なドラッグのステップが 4 倍になります。 |
| `collision.throttle` | **対応なし**。`collision` でターゲットの見つけ方を選びます：`pointerFirst`（デフォルト）、`pointerWithin`、`rectIntersection`、`closestCenter`、`closestCorners`、または自作の関数。 |
| ページに 1 つのプロバイダー、ネストは不可 | ネストできます：アイテムは最も近いプロバイダーのものです。アプリ全体で 1 つのプロバイダーが今も目標です。 |

v2 に対応するものがない新しい props：`activation`、`modifiers`、`sensors`、`animation`、`dropAnimation`、`animateChanges`、`haptics`、`copyModifier`、`overlayFit`、`overlayClass`、`overlayTransition`、`overlayPreviews`、`announcements`、`screenReaderInstructions`、`defaultStyles`。プロバイダーは `drag-start`、`drag-move`、`drag-over`、`drag-end`、`drag-cancel`、`drag-resume`、`drag-settle` も発行します。すべて[プロバイダーのガイド](/docs/guides/provider)にあります。

### `makeDraggable` {#makedraggable}

| v2 | v3 |
| --- | --- |
| `makeDraggable(ref, options, payload)` | `makeDraggable(ref, options)`：第 3 引数はありません。リストの行は `makeSortableItem(ref, { item })` を使います。 |
| `id`、仮想リストで必要 | `id`：データから、ゲッターとして渡します。デフォルトは `useId()` から作られ、コンポーネントのインスタンスごとに新しくなります。 |
| `data: () => card` | `data`：値、ref、またはゲッター。`active.data` と `active.items[i].data` で読み戻します。 |
| `groups: ['dev']` | `type: 'dev'`。ターゲットの `accept` と照合されます。[グループ](#groups)を参照。 |
| `dragHandle: '.handle'` | `handle`：セレクターまたは要素の ref。 |
| `disabled` | `disabled`。 |
| `modifier: { keys, method }` | `canDrag: (event) => event.altKey`：押すたびに通るゲートです。 |
| `activation: { distance, delay }` | ポインターの種類ごとの `activation`：`{ mouse: { distance }, touch: { delay, tolerance }, pen }`。`distance` と `delay` の両方があると、先に満たされた方でドラッグが始まります。 |
| `activation.distance: { x, y, condition }` | **対応なし**。ポインターの種類ごとに `distance` は 1 つです。 |
| `render: markRaw(Preview)` | `overlay: Preview`：コンポーネントはドラッグを props として受け取ります。[オーバーレイ](#the-overlay)を参照。 |
| `placementMargins` | **対応なし**。並べ替え可能なアイテム上のドロップターゲットは、その中央（25〜75%）で判定されます。ツリーは `nesting: 'hover'` でネストします。[並べ替え可能なアイテムへのドロップ](/docs/guides/drag-and-drop#drop-into-a-sortable-item)を参照。 |
| `events.onSelfDragStart`、`onSelfDragMove`、`onSelfDragEnd`、`onSelfDragCancel` | ドラッグ可能な要素には**対応なし**：`useDnDMonitor` か `watch(isDragging)` を使います。[イベント](#events-and-drop-decisions)を参照。 |
| `events.onHover`、`onLeave`、そしてその上を通るドラッグの `onDragStart`… | 同じ要素に `makeDroppable`：`onDragEnter`、`onDragLeave`。 |
| `isDragging`、`selected` を返す | 同じです。 |
| `isDragOver` を返す | 並べ替え可能なアイテムは `indicator`（`placeholder: 'indicator'` のとき）と `isPlaceholder` を返し、ドロップターゲットは `placement` を返します。 |
| `isAllowed` を返す | ドラッグ可能な要素には**対応なし**。ドロップターゲットは `isAccepting` を返します。 |
| — | 新規：`label`、`axis`、`modifiers`、`keyboardMode`、返される `transform` と組み合わせる `overlay: false`、`dropAnimation`、`attributes`、`native`。 |

| v2 | v3 |
| --- | --- |
| `makeDroppable(ref, options, () => items)` | `makeDroppable(ref, options)`。リストを持つゾーンは `makeSortableList` です。 |
| `groups` | `accept`：`'*'`、型、型のリスト、または関数。 |
| `groupMatch: 'every'`、`'some'` | `acceptMode: 'all'`、`'some'`。 |
| `events.onEnter`、`events.onLeave` | `onDragEnter`、`onDragLeave`：それぞれ独立したオプションで、`events` オブジェクトはありません。 |
| `events.onDrop`。`false` や Promise を返せた | `onBeforeDrop` が判断し、`onDrop` が適用します。[ドロップの判断](#events-and-drop-decisions)を参照。 |
| `events.onValidate` | 残す id を返す `onBeforeDrop`。 |
| `data` | `data`。`over.data` で読み戻します。 |
| `disabled` | `disabled`。 |
| `isAllowed` を返す | `isAccepting`。 |
| `isDragOver` を返す：`{ top, right, bottom, left, center }` | `isOver`（真偽値）と `placement`：`{ top, right, bottom, left }`、ポインターがある側の半分。`center` はありません。 |

| --- | --- |

| `e.draggedItems[0].data` | `e.active.data`。 |
| `e.draggedItems[i].index`、`.items` | リスト：`e.from`、`{ list, index }`。 |
| `e.dropZone`：`items`、`placement`、`data` | `e.over`：`id`、`data`、`element`、`rect`、`accepted`。リスト：`e.to`、`{ list, index }`。 |

| `e.helpers.suggestSort()` | リストがドロップを書き込みます。`e.result` には、そのドロップで変わったすべてのリストの新しい配列が入ります。 |
| `e.helpers.suggestSwap()` | リストに `behavior: 'swap'`。`e.partner` は入れ替えた相手のアイテムです。 |
| `e.helpers.suggestCopy()` | `group: { name, pull: 'clone' }` またはコピーキー（:kbd{value="Alt"}）と、リストの `clone`。`e.mode` は `'copy'` です。 |

| `e.helpers.insertAt`、`removeAt`、`removeIndexes`、`swapAt`、`getInsertSide`、`isAtZoneStart`、`isAtZoneEnd` | **対応なし**。リストには不要です。通常のドロップターゲットでは、データを好きなように変更してください。 |
| `e.provider` | `useDnD()`。 |
| — | 新規：`e.pointer`、`e.delta`、`e.position`（ボードにドロップしたアイテムをどこに置くか）、`e.mode`。 |

### 並べ替え {#sorting}

| v2 | v3 |
| --- | --- |
| `() => items` を渡した `makeDroppable` のリスト | `makeSortableList(listRef, { items })`。 |
| `() => [index, items]` を渡した `makeDraggable` の行 | `makeSortableItem(el, { item: () => props.task })`。 |
| 自分の配列を描画 | 返された `items` を描画：ドラッグ中に並べ替わるドラフトです。 |
| `suggestSort('vertical')`、`suggestSort('horizontal')` | `strategy: 'vertical'`（デフォルト）、`'horizontal'`、または `'grid'`。 |
| 参照の比較で元の配列と先の配列を見つけ、`sourceItems` と `targetItems` を代入 | 不要：ドロップが、変わったすべてのリストに書き込みます。 |
| `<TransitionGroup>` | 組み込み。`animateChanges: true` で、ドラッグ以外による変化（追加、削除、シャッフル）をアニメーションします。 |
| `isDragOver.top`、`.bottom` による挿入ライン | `placeholder: 'indicator'` とアイテムの `indicator.side`。[挿入ライン](/docs/guides/sortable-lists#an-insertion-line)を参照。 |
| `suggestSwap()` | `behavior: 'swap'`。 |
| コピー専用のパレット（`suggestCopy()` と `copyOnly` フラグ） | `group: { name, pull: 'clone', put: false }`、`sort: false`、`clone`。 |
| `suggestRemove()` を使うゴミ箱ゾーン | `makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`、または `dropOutside: 'remove'`。 |
| Pinia やイミュータブルなデータ：結果を自分で代入 | `items` をゲッターにして、`onDrop` で `e.preventDefault()` を呼び、`e.result` を適用します。[制御されたリスト](/docs/guides/shared-lists#controlled-lists)を参照。 |
| 再帰的なツリー：フォルダーごとの droppable と `applyToTree` | `makeSortableTree`：コンテナーは 1 つで、行は深さとともにフラットに描画されます。[ツリー](/docs/guides/trees)を参照。 |
| `v-model` を使ったネストしたグループ（グループごとに droppable） | リストの中のリスト。すべて同じ `group` で、それぞれ `items: defineModel()`。 |
| 仮想リスト：すべてのドラッグ可能な要素に `id` | ドラフトを仮想化ライブラリに渡し、行に `id: () => props.item.id`。[仮想リスト](/docs/guides/virtual-lists)を参照。 |

移行前後のコードは[後述](#a-sortable-list)します。リストのすべては[並べ替え可能なリスト](/docs/guides/sortable-lists)と[アイテムを共有するリスト](/docs/guides/shared-lists)にあります。

### グループ {#groups}

v2 にはすべてに使う `groups` オプションが 1 つありました。v3 はそれを 2 つに分けます：

| v2 | v3 |
| --- | --- |
| `makeDraggable(el, { groups: ['dev'] })` | `makeDraggable(el, { type: 'dev' })`。 |
| `makeDroppable(el, { groups: ['dev'] })` | `makeDroppable(el, { accept: 'dev' })`。 |
| ゾーンの `groups: ['dev', 'ops']` | `accept: ['dev', 'ops']`、または関数：`({ active, items, types }) => boolean`。 |
| `groups: []`、または指定なし | `type` や `accept` を省きます。v2 のルールはそのままです：型のないドラッグ可能な要素はどのルールにも合い、`accept` のないターゲットはすべてを受け入れます。 |
| `groupMatch: 'every'`、`'some'` | `acceptMode: 'all'`、`'some'`。 |
| リストのゾーンとその行の `groups` | `makeSortableList` の `group: 'board'`。`group: { name, pull, put }` で、何が出ていけて何が入れるかを指定します。 |
| `makeSelectionArea` の `groups` | `accept`。 |

`group` のないリストはそれだけで 1 つのグループになり、ほかのどのリストともアイテムをやり取りしません。v2 では、groups のないゾーンはすべてを受け入れていました。[ターゲットが受け入れるドラッグ](/docs/guides/drag-and-drop#which-drags-a-target-takes)を参照してください。

### オーバーレイ {#the-overlay}

| v2 | v3 |
| --- | --- |
| プロバイダーの中に描画され、`previewTo` でテレポートされるプレビュー | 常にテレポートされます。行き先は `body` か `overlayTo`。 |
| クローン：同じタグ、その `innerHTML`、そのサイズ | ディープクローン：フォームの値、`<canvas>` のピクセル、継承されたスタイル、表のセルも一緒に来ます。残すものには `data-dnd-no-clone` を付けます。 |
| `render: markRaw(Preview)`。`useDnDProvider().entities` を読む | `overlay: Preview`。`items`、`active`、`over`、`accepted`、`status`、`mode`、`to` を props として受け取ります。`markRaw` は不要で、切り替えるには `shallowRef` を使います。 |
| `preview.position` で位置を決める `#preview` スロット | `#overlay` スロット：ボックスの配置とサイズはライブラリが決めます。何も描画しなければクローンにフォールバックします。 |
| `useDnDProvider().preview.render.value = …` | `#overlay` スロット、または `overlay` として渡す `shallowRef`。 |
| `onEnter` と `onLeave` による、ゾーンの上での見た目の変更 | `makeDroppable` やリストの `overOverlay`、またはオーバーレイコンポーネントで `over` を読みます。[オーバーレイを変えるターゲット](/docs/guides/overlay#targets-that-change-the-overlay)を参照。 |
| `<DragPreview v-slot="{ draggingMap }">` | オーバーレイの props の `items`。`<DragPreview :id="item.id" />` はクローンを 1 つ描画します。 |
| `<DragPreview :grid>`、`makeSnappedOverlayPosition` | `snapToGrid` モディファイア。見た目だけでなく、ターゲットを探す位置とドロップの `position` もスナップします。 |
| `DragPreview` を囲む `<Transition>` や motion の `AnimatePresence` | 持ち上げには `@starting-style` 付きの `overlay-class`、着地には `dropAnimation`、コンポーネント間には `overlayTransition`。[持ち上げ、傾け、落ち着かせる](/docs/guides/animations#the-overlay-lift-tilt-settle)を参照。 |
| `.dnd-kit-preview` | ボックスの `[data-dnd-overlay]`（`"dragging"`、`"dropping"`）と、その中の `[data-dnd-overlay-content]`。 |
| 手作業で更新する `preview.size` | ボックスは着地する位置のサイズになります（`overlayFit`）。 |
| ドロップでプレビューが消える | 自分の位置に着地するか、キャンセルで元の位置に戻ります。 |

詳しくは[オーバーレイのガイド](/docs/guides/overlay)にあります。

### イベントとドロップの判断 {#events-and-drop-decisions}

| v2 | v3 |
| --- | --- |
| ドラッグ可能な要素の `events.onSelfDragStart` | `useDnDMonitor({ onDragStart })` で `active.ids` を確認します。クラスを付けるだけなら `isDragging` で十分です。 |
| `onSelfDragMove` | モニターの `onDragMove`。 |
| `onSelfDragEnd`、ドロップでもキャンセルでも | モニターの `onDragEnd`（ドロップ）と `onDragCancel`。`onDragSettle` はオーバーレイが着地した後に両方を受け取ります。 |
| `onSelfDragCancel` | モニターの `onDragCancel`。 |
| ドラッグ可能な要素の `onHover`、`onLeave`、そしてその上を通るドラッグの `onDragStart`… | その要素に `makeDroppable`：`onDragEnter`、`onDragLeave`。リストの行には何も要りません。 |
| droppable の `events.onEnter`、`onLeave` | `onDragEnter`、`onDragLeave`。 |
| droppable の `events.onDrop` | `onBeforeDrop` が判断し、次に `onDrop` が適用します。`onDrop` は同期で、戻り値は無視されます。 |
| droppable の `events.onValidate` | `acceptMode: 'some'` と組み合わせた `onBeforeDrop`。 |
| — | 新規：プロバイダーの `@drag-start` … `@drag-settle`、そしてモニターの `onDragOver`、`onBeforeDrop`、`onDragResume`。 |

v2 の `onDrop` は、値やその Promise を返してドロップを決められました。v3 ではそれは `onBeforeDrop` の役目で、リスト、ツリー、ドロップターゲット、モニターにあります：

| v2 の `onDrop` の戻り値 | v3 の `onBeforeDrop` の戻り値 |
| --- | --- |
| 何も返さない、または `true`：ドロップが成立する | `'accept'`、`true`、または何も返さない。 |
| `false`：このドロップは見送られ、ドラッグは続く | `'continue'`。**今は `false` でドロップが拒否されます**。 |
| reject された Promise や例外：ドラッグがキャンセルされる | `'reject'` または `false`。例外も拒否になります。 |
| Promise。その間 `state` は `'pending'` | Promise。その間 `status` は `'dropping'` で、オーバーレイは `data-dnd-overlay="dropping"` の状態で待ちます。 |
| `onValidate` が `IDragItem[]` を返す | id の配列：それらだけがドロップされ、ほかは元の位置に戻ります。 |

まずモニターが答え、次にターゲットが答えます。そのあとターゲットの `onDrop` が実行され、リストが新しい配列を書き込み、`onDragEnd` が続きます。詳しくは[ドロップの判断](/docs/guides/drop-decisions)と[イベントの API](/docs/api/events) にあります。

### アイテムを共有するリスト {#lists-that-share-items}

**v2**

```ts [Board.vue]
// Each column's makeDroppable calls this from its onDrop, with its array as the payload.
function applySort(e: IDragEvent) {
  const r = e.helpers.suggestSort('vertical');
  if (!r) return;

  const src = e.draggedItems[0]?.items;
  const tgt = e.hoveredDraggable?.items ?? e.dropZone?.items;

  if (src === todo.value) todo.value = r.sourceItems as Task[];
  else if (src === done.value) done.value = r.sourceItems as Task[];

  if (!r.sameList) {
    if (tgt === todo.value) todo.value = r.targetItems as Task[];
    else if (tgt === done.value) done.value = r.targetItems as Task[];
  }
}
```

```ts [Palette.vue]
makeSortableList(el, {
  items: blocks,
  group: { name: 'board', pull: 'clone', put: false },  // copies go out, nothing comes in
  sort: false,                                          // its own order stays
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),
});
```

Pinia のストアや、直接書き込まないほかの状態では、`items` をゲッターで渡し、`onDrop` で `e.preventDefault()` を呼んで `e.result` を適用します：[制御されたリスト](/docs/guides/shared-lists#controlled-lists)を参照してください。

```ts [TaskItem.vue]
});
```

```vue [TaskOverlay.vue]
<script setup lang="ts">
import { computed } from 'vue';
import type { DragItem, Over } from '@vue-dnd-kit/core';

const props = defineProps<{ items: DragItem[]; over: Over | null; accepted: boolean }>();
const task = computed(() => props.items[0]!.data as Task);
</script>

<template>
  <!-- Fills the overlay box, which takes the size of the slot. -->
  <div class="task-preview" :class="{ refused: over && !accepted }">
    {{ task.title }}
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.task-preview { width: 100%; height: 100%; }
</style>
```

- コンポーネントはドラッグを props として受け取ります：`items`（ドラッグ中のすべてのアイテム、掴んだものが先頭）、`over`、`accepted`、`status`、`mode`、`to`。読むものだけを宣言してください。リストの行では、リストのアイテムは `items[0].item` です。
- そのまま渡します。切り替えるには `shallowRef` を使い、深い `ref` は決して使いません。

プロバイダーのスロットも同じように変わり、コンポーネントが自分で位置を決めることはなくなります：

**v2**

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #preview>
    <MyOverlay />  <!-- moved itself with useDnDProvider().preview.position -->
  </template>
</DnDProvider>
```

**v3**

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, over, accepted }">
    <MyOverlay :items="items" :over="over" :accepted="accepted" />
  </template>
</DnDProvider>
```

`DragPreview` を `<Transition>` で囲んでいたポップインは、`@starting-style` 付きの `overlay-class` になります：[持ち上げ、傾け、落ち着かせる](/docs/guides/animations#the-overlay-lift-tilt-settle)を参照してください。

### 確認してからのドロップ {#a-drop-you-confirm}

**v2**

```ts [Zone.vue]
makeDroppable(el, {
  events: {
    onDrop: (e) =>
      new Promise<void | boolean>((resolve) => {
        if (!window.confirm('Drop here?')) return resolve(false); // keep dragging
        place(e.draggedItems);
        resolve();
      }),
  },
});
```

**v3**

```ts [Zone.vue]
makeDroppable(el, {
  onBeforeDrop: () => (window.confirm('Drop here?') ? 'accept' : 'continue'),
  onDrop: (e) => place(e.active.items),
});
```

リストも同じように尋ね、Promise を使えば自作のダイアログを開けます。Promise が確定するまで、オーバーレイは離した場所で待ちます：

```ts [Column.vue]
makeSortableList(el, {
  items: toRef(props.column, 'tasks'),
  group: 'board',
  // `ask` opens a dialog and resolves 'accept', 'continue' or 'reject'.
  onBeforeDrop: (e) => (e.sameList ? 'accept' : ask(e)),
});
```

混在した選択のうち、一致する部分だけを受け取っていたゾーン（`groupMatch: 'some'`）：

**v2**

```ts [Zone.vue]
makeDroppable(el, {
  groups: ['frontend'],
  groupMatch: 'some',
  events: {
    onDrop: (e) => place(e.draggedItems), // only the items of the group arrive
  },
});
```

**v3**

```ts [Zone.vue]
import type { DragItem } from '@vue-dnd-kit/core';

const fits = (item: DragItem) => item.type.length === 0 || item.type.includes('frontend');

makeDroppable(el, {
  accept: 'frontend',
  acceptMode: 'some',
  onBeforeDrop: (e) => e.active.items.filter(fits).map((item) => item.id), // the others fly back
  onDrop: (e) => place(e.active.items.filter(fits)), // `active.items` still lists every dragged item
});
```

リストはこれをコードなしで行います：`acceptMode: 'some'` にすると、`group.put` が受け入れるアイテムは着地し、ほかは元の位置に戻ります。

## アップグレードの注意点 {#pitfalls-when-upgrading}

- **v3 は範囲を指定してインストールします**。`package.json` に `^3`：`npm update` では `^2` は v2 のままです。
- **ドラフトを描画します**。リストが描画するのは `makeSortableList` が返す `items` で、自分の配列ではありません。自分の配列を描画すると、ドロップするまで何も動きません。
- **二重に並べ替えません**。リストから `suggestSort` のコードを削除してください：リストは `onDrop` の後に、書き込み可能な `items` の ref に各ドロップを書き込みます。自分で適用するには、`e.preventDefault()` を呼んで `e.result` を使います。
- **`false` はドロップを拒否します**。v2 では、`false` で解決した `onDrop` はドラッグを続けました。v3 では `onBeforeDrop` から `'continue'` を返します。`onDrop` から返した Promise は無視されます。
- **リストが共有するのは同じ `group` の中だけです**。`group` のないリストは、ほかのどのリストともやり取りしません。
- **行のキーは id にします**。`:key="index"` では違う行がアニメーションします。id もデータから渡してください：デフォルトの id はコンポーネントのインスタンスごとに新しくなります。
- **`<TransitionGroup>` も、`transform` への `transition` も使いません**。ライブラリが自分で行を動かすので、動きが二重にアニメーションしてしまいます。
- **タッチの回避策を元に戻します**。アイテム全体の `touch-action: none` は、指の下でページがスクロールするのを妨げます。v3 は代わりに長押しでタッチのドラッグを始めます。すぐにドラッグしたいハンドルには、`activation: { touch: { distance: 4 } }` と一緒に残してください。
- **古い属性を削除します**。ライブラリは `tabindex`、`role`、必要な `aria-*` を設定し、自分で付けた属性は決して上書きしません。そのため、残った `role` や `aria-grabbed` は残したままになります。
- **オーバーレイのスタイルを付け直します**。`.dnd-kit-preview` はなくなりました：`[data-dnd-overlay='dragging']` の中身にスタイルを付け、ボックスの `transform` には決して触れません。オーバーレイコンポーネントのルートには `width: 100%; height: 100%` を指定し、レイアウトから `<DragPreview />` を取り除きます。
- **自動スクロールはオンです**。v2 でスクロールしなかった場所には `:auto-scroll="false"` を渡します。
- **選択枠にキーは要りません**。`makeSelectionArea` は、空いている場所を普通に押すだけで描画します。v2 の Ctrl を残すには `modifier` を追加します。
- **プロバイダーは 1 つ、エリアはその中に**。アイテムはプロバイダーをまたげません。ルールを分けるために領域ごとにプロバイダーを使っていたページでは、プロバイダーを 1 つにし、領域ごとに `makeDragArea` を使います。
- **引数は 2 つです**。`makeDraggable` と `makeDroppable` は ref とオプションのオブジェクトを受け取り、ペイロードはありません。
