The library styles almost nothing. Each state of a drag reaches you two ways: as a ref the
composable returns, for classes and conditional markup, and as a `data-dnd-*` attribute, for plain
CSS.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## The returned refs

| Composable | State |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`: this element is the slot a dragged item will land in.
- `isDragging`: the item is part of the drag (every dragged item in a multi-drag).
- `isAccepting`: something is being dragged, and this target takes it — highlight the places
  where a drop is possible.
- `isOver`: the drag is over this target, whether it takes it or not. `isOver && !isAccepting`
  is a refusal, worth showing.
- `over.accepted` from `useDnD()` (`accepted` in overlay props) is `false` over a target that
  refuses the drag: tint the overlay red with it.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## The data attributes

| Attribute | On | When |
| --- | --- | --- |
| `data-dnd-placeholder` | sortable item | It is the slot a dragged item will land in. |
| `data-dnd-dragging` | sortable item | It is dragged but stays in place: the other items of a multi-drag in `'gaps'` mode. |
| `data-dnd-dragging="pointer"` or `"keyboard"` | `<html>` | For the whole drag. |
| `data-dnd-overlay="dragging"` or `"dropping"` | the overlay box | Always. `dropping` while it lands, and while an async `onBeforeDrop` waits. |
| `data-dnd-leaving` | a copy left by `animate` | While an item that left fades out. |
| `data-dnd-no-clone` | **set by you** | Leaves the element out of the overlay's clone: a tooltip, a menu button, a badge. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## Default styles

The provider injects a few rules once per document. They are wrapped in `:where()`, so their
specificity is zero and any rule of yours wins:

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

The slot is dimmed, the page selects no text and doesn't anchor its scroll during a drag, and the
cursor is a grabbing hand during a pointer drag. `:default-styles="false"` turns them off. `cursor: grab` on draggable items
is yours to add.

## Recipes

### An empty slot

Instead of a dimmed copy of the item, show an empty, dashed box where it will land:

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

The pseudo-element covers the content, so the slot keeps the item's exact size. Drag a card here
to see it:

::

### A row the list paints

The default overlay is a clone of the dragged element. It shows the element as it is, and guesses
no background: a row without one of its own — an `<li>` in a white `<ul>`, a table row, a UI kit's
list item — gives a see-through clone. Give it the list's background:

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

The clone keeps the element's classes and attributes — a scoped style's attribute too — so the rule
works in the row's own `<style scoped>`, next to its other styles. Or give the row a background of
its own. Icons and tiles meant to float stay transparent.

### A lifted overlay, only while dragging

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

The shadow is there while the card travels and goes away as the overlay switches to `dropping`, so
the card lands flat in its slot. For a custom overlay component, the same rule targets your
component's root, or read `status` from its props.

### Reduced motion

The library already stops its own animations with `prefers-reduced-motion: reduce`. Do the same
for the transitions you add around drags:

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### Don't

- Don't put CSS `transition` on `transform` or `translate` of sortable items: the library animates
  them itself, and cancels such transitions while it measures.
- Don't animate `height`, `margin` or `padding` of rows in a [virtual list](/docs/guides/virtual-lists).
