Switch the axis, the grid and the bounds, then drag a note. The board sets the rules for every
drag that starts on it, and each note stays where you drop it.

::example{name="constraints" hint="Switch the rules, then drag a note" height="26rem"}
::

## Lock an axis

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` moves only horizontally, `'y'` only vertically. `makeDraggable`, `makeSortableList`,
`makeSortableTree`, `makeSortableItem` and `makeDragArea` all take it.

- The lock runs **after every modifier**, so it holds whatever they do: a snap or a bound can't
  push the item off its line.
- An item's own `axis` wins over its list's or tree's, and a draggable's (or its list's) wins over
  its drag area's.
- It is read when a drag starts, so a getter can toggle it:
  `axis: () => (locked.value ? 'y' : undefined)`.
- A tree locked to `'y'` still nests: the depth then comes from hovering the middle of a row.

::tip
Prefer `axis` to the `restrictToVerticalAxis` and `restrictToHorizontalAxis` modifiers. They do the
same thing, but as ordinary modifiers they run in the middle of the chain, and a modifier after
them (a grid snapping both axes) can move the item off the axis again.
::

## Modifiers

A modifier adjusts the drag's offset on every frame. Its result moves the overlay **and** is the
point where targets are looked for, so a list sorts by the locked, bounded or snapped position.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Modifier | What it does |
| --- | --- |
| `restrictToVerticalAxis` | Moves only vertically. Prefer `axis: 'y'`. |
| `restrictToHorizontalAxis` | Moves only horizontally. Prefer `axis: 'x'`. |
| `restrictToWindowEdges` | Keeps the overlay inside the window. |
| `restrictToParent` | Keeps the overlay inside the container the drag started in: the sortable list, or a plain draggable's parent element. |
| `restrictToElement(target)` | Keeps the overlay inside an element: a template ref, a getter or the element itself. |
| `restrictToFirstScrollableAncestor` | Keeps the overlay inside the first scrollable ancestor of the dragged element. |
| `snapToGrid(size)` | Snaps the overlay to a grid (below). |
| `snapCenterToCursor` | Centers the overlay under the pointer instead of keeping the grab offset. |

`modifiers` is an option of the provider, of drag areas, of lists and trees, and of draggables
and sortable items. Every one but the provider's also takes a ref or a getter, read when the drag
starts.

### Snap to a grid

`snapToGrid(24)` snaps both axes to 24 px cells. An object sets more:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Option | Meaning |
| --- | --- |
| `x`, `y` | The cell size in pixels, per axis. |
| `origin` | `'container'` (default): the overlay's top-left corner lands on grid lines drawn from the container's top-left — the sortable list, or a plain draggable's parent. `'delta'`: the offset itself is rounded, so an item that started off the grid stays off it. |
| `smooth` | `true` or `{ duration, easing }`: the overlay glides between cells (80 ms by default). Targets use the snapped position at once. |

### Your own modifier

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

A modifier gets `transform`, the offset from the drag start as the modifiers before it left it,
and returns a new one. It also gets what it may need to compute it: `activeRect` (the dragged
element at the start), `overlayRect` (the overlay moved by `transform`), `containerRect`,
`windowRect`, `origin` (the pointer at the start), `active` and `over`. See
[Modifiers](/docs/api/modifiers).

## The order

Modifiers from several places run one after another, each from the result of the one before:

1. the provider's `modifiers`;
2. the `modifiers` of the drag area the drag started in;
3. the dragged item's own `modifiers` or, when it has none, its list's or tree's;
4. the drag area's `restrictToArea`;
5. the `axis` lock.

An item's `modifiers` **replace** its list's; they don't add to them. The area's bounds come after
the snapping of steps 1–3, so a snapped item still stays inside, and the axis lock comes last of
all.

## Bounded lists keep their ends

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

A bound holds the overlay at the box's edge while the pointer goes on. Once the pointer has left
the overlay along the list's axis, the list sorts by the pointer instead, so the first and the
last place stay in reach however you hold the item. Grids keep sorting by the overlay: held at the
edge, it already covers the edge cell.

## Rules for a part of the page

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` sets rules for the drags that **start inside** its element — plain draggables and
sortable items alike. Keep one `DnDProvider` for the whole app, and give a board, a canvas or a
feed an area of its own.

| Option | What it does |
| --- | --- |
| `axis` | Locks the drags to one axis. A draggable's own `axis`, or its list's, wins. |
| `modifiers` | Run after the provider's and before the draggable's own. |
| `restrictToArea` | `true`: the drags stay inside the area's element. |
| `autoScroll` | Auto-scroll of the area's scroll container (the element, or its closest scrollable ancestor). `false` turns it off there. |
| `activation` | [Activation](/docs/guides/sensors#activation-constraints) per pointer kind. A draggable's own wins; the provider's comes last. |
| `disabled` | No drag starts in the area, nor in the areas inside it. Its draggables report `aria-disabled`. |

Every option takes a value, a ref or a getter, read when a press or a drag starts. The area
returns `isDragging` (a drag that started here is running) and `isAutoScrolling` (auto-scroll is
moving its container). Full reference: [makeDragArea](/docs/api/make-drag-area).

### How areas combine

- A drag follows the area it **started in**, even after it leaves it. Passing over an area changes
  nothing, except its `autoScroll`: that one applies to every drag that scrolls its container.
- Nested areas don't merge: the closest one wins. `disabled` is the exception, and it is
  inherited: an area that is off turns off the areas inside it too.
- Collision detection, keyboard keys and announcements stay provider-wide.

::note
Why not a second `DnDProvider` around the board? Providers are independent: a drag never crosses
from one to another, so the board's items could never leave it. Nest a provider only when a part
of the page needs provider-wide settings of its own and its items stay inside it. See
[The provider](/docs/guides/provider).
::

## Leave it where it's dropped

The board in the example is also a drop target, and every note keeps the place it was dropped
on. Every drag event carries `position`: the dragged box's top-left corner inside the target, from
its padding edge and with its scroll — the `left` and `top` that put an absolutely positioned item
right there. It comes after the modifiers, so a snapped note lands on the grid.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

More on free dragging and drop targets in [Drag and drop](/docs/guides/drag-and-drop).
