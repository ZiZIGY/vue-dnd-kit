Everything on this page is on by default. Tab to a track's grip, press :kbd{value="Space"}, move it
with the arrow keys and press :kbd{value="Space"} again — or :kbd{value="Escape"} to put it back.

::example{name="lists" hint="Tab to a grip, Space, arrows, Space" height="28rem"}
::

What is usually left to you: readable names for the items, and buttons that move them for people
who can't drag at all.

## The keyboard

| Key | Action |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Pick up the focused item; drop it. |
| Arrows | Move it: by slots in lists, by rows and depth in trees, by `keyboard.step` pixels in free drags. |
| :kbd{value="Escape"} | Cancel the drag — pointer drags too. |

- In a list, an arrow toward another list of the same group moves the item there.
- In a free drag, :kbd{value="Shift"} makes the steps bigger. `makeDraggable(el, { keyboard: 'droppables' })`
  makes the arrows jump between the targets that accept the item instead.
- A keyboard drag starts from the focused draggable, or its handle — never from a button or a
  field inside it, so those keep their own keys.
- Keyboard drags scroll the target into view instead of auto-scrolling at the edges.
- After the drop, focus goes back to the item, even when its row was re-rendered in another list.

### Other keys

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Bindings match `event.code` (`'Space'`, `'KeyD'`) or `event.key` (`'Enter'`). `step` is the pixels
per arrow press in free drags (25 by default). `:keyboard="false"` turns keyboard drags off, and
:kbd{value="Escape"} still cancels any drag. When you change the keys, change the
`screen-reader-instructions` too.

## ARIA attributes

Every draggable and sortable item gets these, **unless you set them yourself**:

| Attribute | Value |
| --- | --- |
| `tabindex` | `0`, when the element isn't focusable already. |
| `role` | `button`, except on a `<button>`, which is one. |
| `aria-roledescription` | `draggable`, or `sortable` on sortable items. |
| `aria-describedby` | The provider's instructions, added next to the ids already there (a tooltip's survives). |
| `aria-disabled` | `true` or `false`: whether the item is disabled (also by a disabled drag area). |
| `aria-pressed` | `true` while it is dragged. |

`attributes: false` turns them off for an item; what the library had set is removed.

### Handles: make them real buttons

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

With a `handle`, the attributes go on the handle, and keyboard drags start from it. A `<button>`
is focusable and a button already, so it needs no `tabindex` or `role`. Give it an `aria-label`: a
grip icon has no name of its own, and "Move Midnight Drive" says more than "button".

## Announcements

A live region in the provider speaks every pickup, move, drop and cancel. Sortable lists say where
the item is: *"Picked up item t2 at position 2 of 5 in list playlist."* Moves are spoken once the
drag has rested for 500 ms.

The texts use ids. Give items readable ids, or write the texts yourself:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- A text replaces the event's announcement; `undefined` keeps the default; `''` says nothing.
  Events you leave out keep their defaults too, such as the positions of sortable lists for
  `onDragOver` above.
- `onDragResume` is spoken when `onBeforeDrop` answered `'continue'` and the drag goes on (see
  [Deciding a drop](/docs/guides/drop-decisions)).
- `screenReaderInstructions` is the text every draggable points to with `aria-describedby`.
- `:announcements="false"` silences the region, e.g. when you announce through your own.

::note
The built-in texts are in English. For another language, give all five texts and the
instructions — each one you leave out is spoken in English, sortable positions included.
::

## Touch

Touch drags start after a 200 ms long press. Moving more than 5 px first scrolls the page
instead, so lists stay scrollable. Tune both with `activation` (see
[Sensors](/docs/guides/sensors#activation-constraints)), and draw a long-press ring from
`useDnD().activation.progress`.

A touch drag vibrates briefly when it starts. `:haptics="false"` turns that off; an object adds
vibrations when entering a target, dropping or being refused:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Only touch drags vibrate, and iOS Safari can't vibrate at all.

## Reduced motion

With `prefers-reduced-motion: reduce`, the library's own animations don't run. Your animation
functions still do, with `reducedMotion: true`. See [Animations](/docs/guides/animations).

## Moving without dragging

Some people can't drag at all. WCAG 2.5.7 asks for a way to move items with single clicks, such as
"Move up" buttons. `@vue-dnd-kit/actions` makes each of them a real move:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` runs a keyboard drag from start to end: it is announced, goes through `onBeforeDrop`
and `onDrop`, animates, and keeps the focus on the item. It resolves `true` when the drop went
through. `index` counts places without the item itself, so "down" is `index + 1`. More in
[Sensors and programmatic drags](/docs/guides/sensors#programmatic-drags).
