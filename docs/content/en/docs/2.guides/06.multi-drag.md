## The selection

Each provider keeps one selection: a reactive set of ids. Dragging a **selected** item
drags every selected item, the grabbed one first. Dragging an item that isn't selected
drags only that item.

The library doesn't decide how people select: the click rules are yours. It never clears
the selection on its own either, and the selection survives unmounts, such as the rows a
virtual list recycles.

### Ctrl/Cmd-click

Every sortable item and draggable returns `selected`, a writable ref bound to the
selection:

```vue [Shot.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ shot: { id: string } }>();
const el = useTemplateRef<HTMLElement>('el');
const { selected } = makeSortableItem(el, { item: () => props.shot });

const onClick = (event: MouseEvent) => {
  if (event.ctrlKey || event.metaKey) selected.value = !selected.value;
};
</script>

<template>
  <div ref="el" :class="{ selected }" @click="onClick">…</div>
</template>
```

The click that ends a drag doesn't reach `@click`, so a drop never toggles the selection
by accident. Use `@click`, not `pointerup`, for item actions.

### From anywhere: `useDnD().selection`

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// A plain click selects only that item, Ctrl/Cmd-click adds or removes it:
const onClick = (event: MouseEvent, id: string) => {
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
};

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

The selection is keyed by id, so it can hold items of several lists: a drag takes every
selected item under the provider.

## Rubber-band selection

`makeSelectionArea` turns an element into an area where a press on the empty space draws
a band, and the items it crosses are selected:

```vue [Gallery.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSelectionArea } from '@vue-dnd-kit/core';
import PhotoGrid from './PhotoGrid.vue';

const area = useTemplateRef<HTMLElement>('area');
const { isSelecting, style } = makeSelectionArea(area);
</script>

<template>
  <div ref="area" class="area">
    <PhotoGrid />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.area {
  position: relative;   /* the band is absolutely positioned inside */
  min-height: 320px;    /* room around the items to start a band */
}

.band {
  border: 1px solid #42b883;
  background: color-mix(in srgb, #42b883 15%, transparent);
}
</style>
```

- You render the band: `style` places it, relative to the area's content.
- The area needs a **non-static position** (`relative` will do), or the band lands
  somewhere else.
- A band starts only from the area itself, so make the area large: the whole panel, with
  space around the items, not a tight wrapper. The gallery above fills its whole box.
- A press on an item drags it. Buttons, fields and the area's scrollbar keep their
  presses.
- The band stays anchored to the content while the area or the page scrolls.
  :kbd{value="Escape"} cancels it and restores the selection.
- `useDnD().status` is `'selecting'` while a band is drawn.

| Option | What it does |
| --- | --- |
| `strategy` | `'toggle'` (default): the items the band crosses flip. `'select'`: only the items inside the band end up selected, so a click on the empty space deselects the area's items. |
| `modifier` | Keys that must be held to draw: `{ keys: ['Shift'], method: 'every' }` (or `'some'`). |
| `accept` | Which draggables the band selects, an [accept rule](/docs/guides/drag-and-drop#which-drags-a-target-takes) matched against their `type`. |
| `disabled` | No band; turning it on cancels a running one. |
| `onSelected(ids)` | Called when a band ends, with the selection. |
| `selection` | A `Ref<Set<Key>>` of your own instead of the provider's selection. |

With areas inside areas, the innermost one takes the press. All options are in the
[makeSelectionArea API](/docs/api/make-selection-area).

## How the other items move: `multiple`

The list where a multi-drag starts decides what the other selected items do while it
runs:

```ts
makeSortableList(listRef, { items: tasks, multiple: 'gaps' });
```

| `multiple` | While dragging | The overlay |
| --- | --- | --- |
| `'group'` (default) | The other items leave their places and travel with the grabbed one as one block of slots, so the list already shows the result of the drop. | A column of up to five dragged items along the list. |
| `'gaps'` | The others stay where they are, faded (`data-dnd-dragging`), until the drop. | The same column. |
| `'stack'` | The others fly into the overlay. | The grabbed item with a count. |

On drop, the items land together at the target index, in the order they had. In
`'group'` and `'gaps'`, each item of the overlay flies to its own slot.

### The default overlay

In `'group'` and `'gaps'`, the overlay is a column of the dragged items as they will land:
the grabbed one under the pointer, the others before and after it in drop order (a row in
horizontal lists). It shows up to five items. The ones past that are counted where they are: `+N` at
the start of the column for the items that land before the shown ones, `+N` at the end for
those after.

In grids, a column of whole cells would cover the page, so the overlay is a pile: up to
three items fanned out behind the grabbed one, with the total count on top.

Plain draggables (`makeDraggable`) show the grabbed item with a count.

### Mixed types

When the selected items have different types, `acceptMode` on a target says whether
`'all'` of them (default) or `'some'` must fit. See
[lists that share items](/docs/guides/shared-lists#limits) and
[drag and drop](/docs/guides/drag-and-drop#which-drags-a-target-takes).

## A custom overlay for several items

Overlay components and the provider's `#overlay` slot get `items`: every dragged item,
the grabbed one first. `DragPreview` renders the library's clone of any of them, so your
layout can reuse the real look:

```vue [PileOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="pile">
    <!-- The grabbed item on top, two more turned behind it -->
    <DragPreview
      v-for="(entry, i) in items.slice(0, 3)"
      :id="entry.id"
      :key="entry.id"
      class="card"
      :style="{ width: '100%', height: '100%', zIndex: 3 - i, rotate: `${i * 4}deg` }"
    >
      <!-- Shown for an item without a clone -->
      <div class="fallback">{{ entry.id }}</div>
    </DragPreview>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.pile { position: relative; width: 100%; height: 100%; }
.card { position: absolute; inset: 0; }
.fallback { width: 100%; height: 100%; border-radius: 8px; background: Canvas; }
.count { position: absolute; top: -8px; right: -8px; z-index: 4; }
</style>
```

```ts
makeSortableList(listRef, { items: photos, strategy: 'grid', overlay: PileOverlay });
```

Clones are taken at pickup: of the grabbed item and of up to four others next to it in
drop order, if they are rendered. For any other item, `DragPreview` renders its default
slot. A preview has its item's size at pickup unless you size it, as the `style` above
does (`class` and `style` fall through). In `'group'` and `'gaps'`, each preview lands on its own item's slot on drop. More
on overlay components in [the overlay](/docs/guides/overlay).

## Trees

In a tree, the selected nodes move as one block, each with its subtree, in document order.
A selected node inside another selected one rides along in its parent's subtree. See
[trees](/docs/guides/trees).
