## A list and its rows

A sortable list takes two components: the list, and its row.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

The row registers with the list it is rendered in. That is also why every list needs a
component of its own: two lists made in one component would share their rows.

## The draft

`makeSortableList` returns `items`, a **draft** of your array. While you drag, the draft
reorders live: the dragged row takes its new slot, and the others slide out of the way.
Your array doesn't change until the drop. Then the library writes the new order into it.

::example{name="quick-start" hint="The ids under the list are your array: they change on drop"}
::

- Render `items`, not your array. Rendering your array, nothing moves until the drop.
- The write happens after the list's `onDrop`. In `onDrop`, your array still holds the
  old order and `e.result` the new one.
- `tasks` is a regular `ref`, so the rest of your app sees the change like any other.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

A list component that takes its array through `v-model` passes the model on:

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
A store, server state or immutable data? Pass a getter or a `computed` instead of a ref.
The library won't write a read-only source: call `e.preventDefault()` and apply `e.result`
yourself. See [drop decisions](/docs/guides/drop-decisions).
::

## Keys

Rows are keyed by their data, never by index or by an automatic id. By default the key is
`item.id`, or the item itself for strings and numbers.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Use the same key in `v-for`: `:key="task.uuid"`. With `:key="index"` the wrong rows
  animate and their state jumps between rows.
- Keys must be unique among all the lists that exchange items.
- Pass `item` and `id` as getters, so a row stays in sync when its props change.

## Strategies

| `strategy` | For |
| --- | --- |
| `'vertical'` (default) | A column of rows. |
| `'horizontal'` | A single row: tabs, chips, a timeline. |
| `'grid'` | CSS grids and wrapping flex rows, with items of different sizes too. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Handles

By default the whole row starts a drag (except buttons, inputs and other controls in it).
Pass `handle` to drag by one part only:

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` is a selector inside the item, or an element ref.
- A mouse drag starts from the handle at once, without the usual 4 px.
- The handle gets the drag's attributes (`role`, `tabindex`, `aria-*`), and keyboard
  drags start from it.

Make the handle a `<button type="button">` with an `aria-label`: it is focusable as is,
and screen readers announce its label. A bare `<span>` with an icon also works (the
library gives it `tabindex="0"` and `role="button"`), but it has no meaningful name.

::note
Touch drags start after a 200 ms long press, so the page can still scroll. To drag at once
from a handle, give the handle `touch-action: none` and the item
`activation: { touch: { distance: 4 } }`.
::

## Lock the axis

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` keeps the drag on the vertical axis, `'x'` on the horizontal one. An item's
own `axis` wins over its list's. To also keep the drag inside the list, add the
`restrictToParent` modifier; the playlist above uses both. More in
[constraints](/docs/guides/constraints).

## Style the slot

The dragged row stays in the list as the slot it will land in, and gets
`data-dnd-placeholder`. The default style fades it to 40%, with zero specificity, so any
rule of yours wins:

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` returns the same state as refs, plus a few more:

| Returns | What it is |
| --- | --- |
| `isPlaceholder` | This row is the slot a dragged item will land in. |
| `isDragging` | This row is being dragged (every dragged row, in a multi-drag). |
| `index` | Its index in the draft: it changes while you drag. |
| `selected` | Writable, bound to the provider's selection. |
| `indicator` | In [indicator mode](/docs/guides/shared-lists#an-insertion-line), where the line goes. |

The list returns `isOver` and `isAccepting` for its own highlight. All attributes and
recipes are in [styling](/docs/guides/styling).

## Turning things off

- `disabled` on the list: no drags out of it, no drops into it. On an item: it can't be
  dragged.
- `sort: false`: items can't be reordered inside this list, but can still leave it (a
  palette, see [lists that share items](/docs/guides/shared-lists)).

## Animations

Rows slide to their new places while you drag, and the dropped row lands on its slot. That
is on by default and needs no code. Don't wrap rows in `<TransitionGroup>`: moves would
animate twice. For changes no drag made (adding, removing, shuffling), turn on the list's
`animate` option. See [animations](/docs/guides/animations).

The full option list is in the [makeSortableList](/docs/api/make-sortable-list) and
[makeSortableItem](/docs/api/make-sortable-item) API.
