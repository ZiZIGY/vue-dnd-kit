Drag a tile, then shuffle, add and remove some. Sorting and the drop animate by default; the
buttons' changes animate because the grid turns on `animate`.

::example{name="animate" hint="Drag, shuffle, add, remove" height="22rem"}
::

## Three animations

| Option | Where | Default | What it animates |
| --- | --- | --- | --- |
| `animation` | provider, list, tree | on, 200 ms | Items sliding to their new places while you sort, on drop and on cancel. |
| `dropAnimation` | provider | on, 250 ms | The overlay landing on its slot, or flying back on cancel. |
| `animate` | provider, list, tree | **off** | Changes of your data that no drag made: items added, removed, moved or filtered, tree rows shown or hidden. |

Each takes `true` (the default timing), `false` (off), `{ duration, easing }`, or a function that
animates it yourself.

```vue
<DnDProvider
  :animation="{ duration: 180, easing: 'cubic-bezier(.2, .8, .2, 1)' }"
  :drop-animation="{ duration: 300 }"
>
```

A list's or tree's own `animation` and `animate` win over the provider's.

## Sorting

While you drag, the draft reorders and the items slide to their new places: FLIP on the CSS
`translate` property, through the Web Animations API. `translate` composes with any `transform` of
yours, so a virtual list's row positioning stays intact. When an item moves again before its
animation ends, the next one starts from where it is shown.

::warning
Don't wrap sortable items in `<TransitionGroup>`: every move would animate twice. For changes no
drag made, turn on `animate`.
::

## The drop

On drop, the overlay flies from where you let go to the item's slot; on cancel, back to where the
item started. When the item has no visible slot after the drop — scrolled away, or dropped into a
folder or a trash zone — the overlay fades out instead, shrinking into the zone it was dropped on.

The overlay also takes the size of the slot it will land in while you drag
(`overlayFit: 'slot'`, the default), so the drop needs no resize. `'source'` keeps the dragged
element's size. See [The overlay](/docs/guides/overlay).

## Data changes: animate

```ts
makeSortableList(listRef, { items: swatches, animate: true });
```

Off by default, `animate` animates what changes your array without a drag: a sort, a shuffle, a
move between lists of one group, an item added, removed or filtered out. In a tree it also covers
the rows a node shows or hides as it expands and collapses. `<DnDProvider animate>` turns it on for
every list and tree.

Its parts can be tuned one by one:

```ts
animate: { duration: 250, move: true, enter: true, leave: { duration: 150 } },
```

| Part | By default |
| --- | --- |
| `move` | Items that changed places slide, as with `animation`. |
| `enter` | Items that appeared fade in where they are. |
| `leave` | A copy of the item that left fades out where it was, shrinking a little. It is marked `data-dnd-leaving` and removed when it's done. |

`duration` and `easing` apply to every part; each part takes `true`, options, `false` or a
function. Only items near the visible area animate, so rows a virtual list hasn't mounted are
skipped. The option is read when `items` changes, so a ref can switch it, as the example's toggle
does.

## Your own animations

Each option also takes a function. It gets a context, starts the animation and returns its
`Animation`, a promise that settles when it ends, or nothing.

```ts
// animation, animate.move: an item moved from `from` to `to`
({ key, element, from, to, options, reason, signal, reducedMotion }) => Animation | Promise | void
// dropAnimation: `to` is null when there is no visible slot; `into` is the zone it went into
({ overlay, from, to, into, reason, active, options, reducedMotion }) => …
// animate.enter: the element is already in place
({ key, element, to, options, reducedMotion }) => …
// animate.leave: `element` is a copy where the item was, removed when you finish
({ key, element, from, options, reducedMotion }) => …
```

A layout function with the Web Animations API, and no library:

```ts
import type { LayoutAnimationContext } from '@vue-dnd-kit/core';

const springy = ({ element, from, to, reducedMotion }: LayoutAnimationContext) => {
  if (reducedMotion) return;
  return element.animate(
    [{ translate: `${from.left - to.left}px ${from.top - to.top}px` }, { translate: '0 0' }],
    { duration: 400, easing: 'cubic-bezier(.34, 1.56, .64, 1)' },
  );
};
```

```vue
<DnDProvider :animation="springy">
```

Three rules keep custom animations in step with the library:

- **Animate `translate`** from `from - to` to zero, not `transform`. It composes with transforms
  that virtual lists or your CSS put on rows, and drags measure items without it.
- **Honor `signal`.** It aborts when the item moves again before the animation ends. Stop your
  animation and clear its styles at once: the layout is measured right after. A returned
  `Animation` is cancelled for you.
- **On the overlay, animate position and size** (`width`, `height`), never `scale`: its content
  re-lays out at the new size.

### GSAP

```ts [gsap-animations.ts]
import gsap from 'gsap';
import type {
  DropAnimationContext,
  EnterAnimationContext,
  LayoutAnimationContext,
  LeaveAnimationContext,
  Rect,
} from '@vue-dnd-kit/core';

const move = ({ element, from, to, signal, reducedMotion }: LayoutAnimationContext) => {
  if (reducedMotion) return;
  const tween = gsap.fromTo(
    element,
    { translate: `${from.left - to.left}px ${from.top - to.top}px` },
    { translate: '0px 0px', duration: 0.4, ease: 'power3.out' },
  );
  signal.addEventListener('abort', () => tween.revert());
  return tween.then();
};

const box = (rect: Rect) => ({ x: rect.left, y: rect.top, width: rect.width, height: rect.height });

const drop = ({ overlay, from, to, reducedMotion }: DropAnimationContext) => {
  if (reducedMotion) return;
  if (!to) return gsap.to(overlay, { opacity: 0, duration: 0.2 }).then();
  return gsap.fromTo(overlay, box(from), { ...box(to), duration: 0.45, ease: 'back.out(1.2)' }).then();
};

const enter = ({ element, reducedMotion }: EnterAnimationContext) =>
  gsap.from(element, reducedMotion ? { opacity: 0, duration: 0.2 } : { opacity: 0, scale: 0.85, duration: 0.35 }).then();

const leave = ({ element, reducedMotion }: LeaveAnimationContext) =>
  gsap.to(element, reducedMotion ? { opacity: 0, duration: 0.2 } : { opacity: 0, scale: 0.85, duration: 0.25 }).then();

export const gsapAnimations = { animation: move, dropAnimation: drop, animate: { move, enter, leave } };
```

```vue
<DnDProvider v-bind="gsapAnimations">
```

### motion

```ts [motion-animations.ts]
import { animate } from 'motion-v';
import type { DropAnimationContext, LayoutAnimationContext } from '@vue-dnd-kit/core';

const spring = { type: 'spring', duration: 0.45, bounce: 0.25 } as const;

const move = ({ element, from, to, signal, reducedMotion }: LayoutAnimationContext) => {
  if (reducedMotion) return;
  const controls = animate(
    element,
    { translate: [`${from.left - to.left}px ${from.top - to.top}px`, '0px 0px'] },
    spring,
  );
  signal.addEventListener('abort', () => {
    controls.stop();
    element.style.translate = '';
  });
  return controls.finished;
};

const drop = ({ overlay, from, to, reducedMotion }: DropAnimationContext) => {
  if (reducedMotion) return;
  if (!to) return animate(overlay, { opacity: 0 }, { duration: 0.18 }).finished;
  return animate(
    overlay,
    { x: [from.left, to.left], y: [from.top, to.top], width: [from.width, to.width], height: [from.height, to.height] },
    spring,
  ).finished;
};
```

The full option types are in [Animations](/docs/api/animations).

## Reduced motion

With `prefers-reduced-motion: reduce`, the library's own animations don't run: items and the
overlay go straight to their places. Your functions always run, with `reducedMotion: true`, so they
decide — skip the motion, or keep a short fade as the recipes above do.

## Layout changes the library didn't cause

When something else moves rows during a drag — a virtualizer re-measuring, an image loading —
call the list's `captureLayout()` right before the change renders. It measures the rows where they
are and animates them to their new places after the next render. Outside a drag it does nothing.
See [Virtual lists](/docs/guides/virtual-lists).
