Sorting is data-driven: the draft `items` is a new array on every reorder, rows are keyed by item,
and the animations only need the rows that are mounted. So any virtualizer that renders from an
array works — feed it the draft instead of your array.

## The rules

1. Give the virtualizer the **draft `items`**, not your source array.
2. **Key rows by the item's key**, never by index. The official TanStack and VueUse examples key by
   index; change that.
3. Pass ids to `makeSortableItem` as a **getter**, `{ id: () => props.item.id }`: the virtualizer
   may hand a row component another item.
4. Hold big arrays in a **`shallowRef`**. The library never deep-traverses your data.
5. Keep the placeholder the same size as the row.
6. Overscan at least 5 rows (VueUse: at least 1), so rows are mounted before auto-scroll reaches
   them.
7. Don't animate rows' `height`, `margin` or `padding`, and don't put `will-change` on the
   scroller.

## TanStack Virtual

```vue [TaskList.vue]
<script setup lang="ts">
import { computed, shallowRef, useTemplateRef } from 'vue';
import { defaultRangeExtractor, useVirtualizer, type Range } from '@tanstack/vue-virtual';
import { makeSortableList } from '@vue-dnd-kit/core';
import Row from './Row.vue';

const ROW = 40;
const tasks = shallowRef(makeRows(10_000));
const scrollRef = useTemplateRef<HTMLElement>('scroll');
const { items, activeIndex, captureLayout } = makeSortableList(scrollRef, { items: tasks });

// One computed that reads the draft once: TanStack memoizes measurements and the range on
// the identity of `getItemKey` and `rangeExtractor`, so they must be new after every reorder.
const virtualizer = useVirtualizer(
  computed(() => {
    const arr = items.value;
    const pin = activeIndex.value;
    return {
      count: arr.length,
      getScrollElement: () => scrollRef.value,
      estimateSize: () => ROW,
      overscan: 8,
      getItemKey: (index: number) => arr[index]!.id,
      // Keep the dragged row mounted while it is scrolled out of range.
      rangeExtractor: (range: Range) => {
        const indexes = defaultRangeExtractor(range);
        return pin < 0 || indexes.includes(pin) ? indexes : [...indexes, pin].sort((a, b) => a - b);
      },
      // Re-measures land after the library's animation pass: animate them too.
      onChange: () => captureLayout(),
    };
  }),
);
const rows = computed(() => virtualizer.value.getVirtualItems());
const measure = (el: unknown) => virtualizer.value.measureElement(el as HTMLElement | null);
</script>

<template>
  <div ref="scroll" style="height: 600px; overflow: auto; contain: strict">
    <div :style="{ height: `${virtualizer.getTotalSize()}px`, position: 'relative' }">
      <div
        v-for="row in rows"
        :key="(row.key as string)"
        :ref="measure"
        :data-index="row.index"
        :style="{ position: 'absolute', top: 0, left: 0, width: '100%', transform: `translateY(${row.start}px)` }"
      >
        <Row :item="items[row.index]!" />
      </div>
    </div>
  </div>
</template>
```

```vue [Row.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ item: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
// A getter: the virtualizer may give this component another item.
makeSortableItem(el, { id: () => props.item.id });
</script>

<template>
  <div ref="el" class="row">{{ item.title }}</div>
</template>
```

- The scroller is the sortable list's element: the library sorts and auto-scrolls it.
- Pinning the dragged row (`rangeExtractor`) needs rows positioned one by one, absolutely, as
  above.
- Keep TanStack's `anchorTo: 'start'`, the default. With `lanes`, use `@tanstack/vue-virtual`
  3.19 or newer.

### Kanban columns

When a card comes in from another column, its height may differ from the column's estimate. Read
`activeSize` in the same computed, and estimate the incoming row at its real size:

```ts
const { items, activeIndex, activeSize, captureLayout } = makeSortableList(scrollRef, {
  id: props.column.id,
  items: props.column.tasks,
  group: 'board',
});

const virtualizer = useVirtualizer(
  computed(() => {
    const arr = items.value;
    const pin = activeIndex.value;
    const size = activeSize.value;
    return {
      count: arr.length,
      getScrollElement: () => scrollRef.value,
      // A card coming from another column gets its real height before it is measured.
      estimateSize: (index: number) => (index === pin && size ? size.height : 72),
      // …getItemKey, rangeExtractor and onChange as above
    };
  }),
);
```

## VueUse useVirtualList

```vue [TaskList.vue]
<script setup lang="ts">
import { shallowRef, useTemplateRef } from 'vue';
import { useVirtualList } from '@vueuse/core';
import { makeSortableList } from '@vue-dnd-kit/core';
import Row from './Row.vue';

const ROW = 40;
const tasks = shallowRef(makeRows(10_000));
// The outer element is the sortable list: `containerProps` owns the scroller's ref.
const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
// A number keeps VueUse's math O(1). It must be the row's real height, borders and margins included.
const { list, containerProps, wrapperProps } = useVirtualList(items, { itemHeight: ROW, overscan: 8 });
</script>

<template>
  <div ref="list">
    <div v-bind="containerProps" style="height: 600px">
      <div v-bind="wrapperProps">
        <!-- Keyed by id, not by index as in VueUse's docs. -->
        <Row v-for="{ data } in list" :key="data.id" :item="data" :style="{ height: `${ROW}px` }" />
      </div>
    </div>
  </div>
</template>
```

VueUse can't pin the dragged row: it unmounts when you scroll it away. That's fine — see below.

## What stays mounted

The dragged row may unmount while you drag: it scrolled out of range, or the virtualizer recycled
its component. The drag survives it. The overlay keeps showing the item, the selection is kept by
id, and the item lands where the draft puts it. Animations only touch the rows that are mounted.

Where the virtualizer can, keep the dragged row mounted anyway, as the TanStack recipe does with
`rangeExtractor`. The list tells you which row that is:

| Returned by the list | What it is for |
| --- | --- |
| `activeIndex` | The index of the row to keep mounted in this list's draft, `-1` when it isn't here. |
| `activeKey` | The key of that row. |
| `activeSize` | The size of the dragged row at the start of the drag: estimate an incoming row with it. |
| `captureLayout()` | Call it right before a layout change the library didn't make (a re-measure). It animates the rows from where they were. Outside a drag it does nothing. |

## Trees

`makeSortableTree` returns a flat `items` of the visible rows, so a tree virtualizes like a list:
keyed by `node.key`, with `activeIndex` and `activeKey` naming the row to keep mounted. See
[Trees](/docs/guides/trees).
