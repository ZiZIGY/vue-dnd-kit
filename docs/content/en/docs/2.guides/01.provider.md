## One provider for the app

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Put one `DnDProvider` high up, in `App.vue` or a layout, and forget about it. Every
composable (`makeSortableList`, `makeDraggable`, `useDnD`…) looks for the closest provider
above the component it runs in.

::warning
A composable must run in a component **rendered inside** the provider. Calling it in the
component whose own template contains `<DnDProvider>` throws
`No <DnDProvider> found above this component`: Vue's `inject` only sees ancestors.
::

## What it owns

| Part | What the provider does |
| --- | --- |
| Input | Turns pointer, touch and keyboard input into drags (`sensors`), one drag at a time. |
| Finding the target | Hit-tests the drop targets under the drag (`collision`) and tells them. |
| The overlay | Renders the box that follows the pointer, teleported to `body`, and lands it on drop. |
| The selection | One set of selected ids, shared by every list and draggable under it. |
| Auto-scroll | Scrolls containers and the window when a drag nears their edges. |
| The live region | Announces pickups, moves, drops and cancels to screen readers. |

It renders nothing else: your markup stays as it is.

## Options at a glance

Every option has a default that works, so the provider usually takes none.

| Prop | Default | What it sets |
| --- | --- | --- |
| `collision` | `pointerFirst` | How the target under the drag is chosen. |
| `modifiers` | `[]` | Movement rules for every drag (snap, restrict, …). |
| `animation` / `dropAnimation` | on | Items sliding while sorting / the overlay landing. |
| `animate` | off | Default for lists and trees: animate data changes no drag made. |
| `autoScroll` | on | Edge scrolling: `{ threshold, maxSpeed, acceleration }` or `false`. |
| `activation` | mouse 4 px, touch 200 ms | When a press becomes a drag, per pointer kind. |
| `keyboard` | Space / Enter, Escape | Keyboard keys and step; `false` turns keyboard drags off. |
| `sensors` | pointer + keyboard | What turns input into drags. |
| `haptics` | a short vibration on touch pickup | Vibrations for touch drags, or `false`. |
| `copyModifier` | `'Alt'` | Key that, held while dragging, turns a move into a copy (the list needs `clone`). |
| `overlayTo` | `'body'` | Where the overlay is teleported. |
| `overlayFit` | `'slot'` | Overlay size: the slot it will land in, or the source's. |
| `announcements` | built-in | Screen reader texts, or `false`. |
| `defaultStyles` | `true` | Injects zero-specificity CSS for drag states. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

The full list with every shape is in the [DnDProvider API](/docs/api/dnd-provider). The
provider also emits `drag-start`, `drag-move`, `drag-over`, `drag-end` and `drag-cancel`,
the same events `useDnDMonitor` hears.

::tip
Rules for one part of the page (a board that snaps, a feed that only scrolls vertically)
don't need a provider of their own: wrap that part in a [drag area](/docs/guides/constraints).
::

## Read the drag: `useDnD()`

::example{name="provider-state" hint="Drag a task and watch the state" height="22rem"}
::

`useDnD()` returns the drag as reactive state, in any component under the provider:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Field | What it holds |
| --- | --- |
| `status` | `'idle'`, `'activating'` (a long press charging), `'dragging'`, `'dropping'` (landing, or waiting for an async `onBeforeDrop`), `'selecting'` (a rubber band). |
| `active` | What is dragged: `id`, `ids` (every dragged id, the grabbed one first), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` when idle. |
| `over` | The target under the drag: `id`, `data`, `element`, `rect` and `accepted`. `null` over nothing. |
| `pointer` | The pointer in viewport coordinates, after modifiers. |
| `activation.progress` | `0` to `1` while a long press charges: draw a ring with it. |
| `isAutoScrolling` | Auto-scroll is moving something. |
| `selection` | The provider's selection: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. See [multi-drag](/docs/guides/multi-drag). |
| `cancel()` | Cancels the running drag (the items fly back), a charging long press, or a selection band. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

As soon as a drop is decided, `active`, `over` and `pointer` read `null`, even while the
overlay is still landing (`status` stays `'dropping'`). UI derived from them never shows
the old drag next to the new data. While an async `onBeforeDrop` waits, the state stays as
it was at release.

## Listen to every drag: `useDnDMonitor()`

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

A monitor hears every drag under its provider, wherever it starts. It stops when the
component that called it unmounts.

| Event | When |
| --- | --- |
| `onDragStart` | A drag starts. |
| `onDragMove` | The drag moves. |
| `onDragOver` | The target under the drag changes. |
| `onBeforeDrop` | The drag is released. Its answer decides the drop: see [drop decisions](/docs/guides/drop-decisions). |
| `onDragEnd` | The drop went through. Sortable lists have already run their `onDrop` and written the new order. `dropped` is `false` when it ended over no target. |
| `onDragCancel` | Escape, a drop on a target that refuses it, or an `onBeforeDrop` that answered `'reject'`. |
| `onDragResume` | `onBeforeDrop` answered `'continue'`: nothing dropped, and the drag goes on. |

Every event carries `active`, `over`, `pointer`, `delta` (the offset from the start),
`position` (where the dragged box sits in `over`, see
[drag and drop](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) and, for items
from a sortable list, `source`. The full shapes are in the [events API](/docs/api/events).

::note
`onDragEnd` is the place for "after the drop" work: saving, clearing the selection,
analytics. A list's own `onDrop` runs **before** its write, so it still sees the old order.
::

## Several providers

Most apps need exactly one. A second provider makes sense only for a part of the page that
needs its own provider-wide settings (collision, keyboard keys, announcements) and whose
items never leave it:

- Providers are independent: a drag never crosses from one to another.
- Nested providers are allowed. The **closest owner wins**: an item belongs to the nearest
  provider above it, and the outer provider ignores it.
- Each provider has its own selection, overlay and live region.

If items can't move between two parts of your page, check that they don't sit under two
providers.

::tip
An app mounted elsewhere, inside a shadow root or as a separate Vue app, can join an
existing provider: pass `useDnDContext()` to `provideDnDContext(app, context)` before
mounting it.
::

## SSR and Nuxt

The provider is SSR-safe. Lists and items render on the server like any other markup. The
overlay and the live region are teleported and mount on the client only, so they never
cause a hydration mismatch. Default ids come from Vue's `useId()` and match between server
and client.

In Nuxt, the module registers `DnDProvider` globally and auto-imports the composables: see
[installation](/docs/getting-started/installation#nuxt).
