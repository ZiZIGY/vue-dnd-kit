While you drag, a box follows the pointer: the **overlay**. The dragged element itself
stays where it was, as the slot it will land in. On drop, the overlay flies to that slot
and disappears.

The overlay is teleported to `body`, outside your components. By default it shows a clone
of the dragged element.

::example{name="overlay" hint="Drag a message: the copy gets the inbox's background" height="24rem"}
::

## The default clone

The clone is taken at pickup, before anything moves. It is a deep copy of the element:

- Form values and `<canvas>` pixels are copied.
- The computed styles the element would lose outside its list are inlined: inherited
  fonts and colors, styles that match through ancestors (`.list li { … }`), table cell
  widths. A table row comes wrapped in a table of its own.
- `id`s and `data-dnd-*` attributes are stripped, and the clone is `aria-hidden`.
- Ripples and other press effects of UI kits (Vuetify, Quasar, PrimeVue, Naive UI) are
  left out.

Mark anything else that shouldn't travel with **`data-dnd-no-clone`**: a menu button, a
tooltip, a badge.

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### Backgrounds aren't guessed

The clone shows the element as it is. A row that has no background of its own, because its
list paints it (an `<li>` in a white `<ul>`, a `v-list-item`, a table row), gives a
**see-through** clone. Give it the list's background in CSS:

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

The clone keeps the element's classes and attributes, Vue's scope attribute included, so
the rule works in the row's scoped style as well as in a global stylesheet. The other way
out is a background on the row itself. Icons and tiles meant to float, like the app icons
in [sortable lists](/docs/guides/sortable-lists), stay transparent on purpose.

## Styling the box

The box is the element with `data-dnd-overlay`. It is `position: fixed` and
`pointer-events: none`, and its value says what it is doing:

| `data-dnd-overlay` | When |
| --- | --- |
| `"dragging"` | It follows the pointer. |
| `"dropping"` | It lands on its slot, flies back, or waits for an async `onBeforeDrop`. |

A lifted look while dragging, gone as it lands:

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## Overlay components

To show something else than the clone, pass a component. It renders inside the box:

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | What it holds |
| --- | --- |
| `active` | The drag (`id`, `ids`, `data`, `type`, …). |
| `items` | Every dragged item, the grabbed one first: `{ id, item, data, type }`. `item` is the list item for sortable drags. |
| `over` | The target under the drag, or the one it lands on while dropping. `null` over nothing and while a cancelled drag flies back. |
| `accepted` | Whether `over` takes the drag: tint the overlay red when it doesn't. |
| `status` | `'dragging'` or `'dropping'`. |
| `mode` | `'move'`, `'copy'`, `'swap'` or `'insert'`. |

A component can be passed as it is, or in a `shallowRef` to switch it. Never put it in a
deep `ref` or `reactive`: Vue would make the component reactive and warn.

The app grid of [sortable lists](/docs/guides/sortable-lists) uses one: the icon travels
alone and lifts, and the name stays behind.

::example{name="lists" hint="Drag an app icon: its overlay is a component" height="28rem"}
::

## The provider's `#overlay` slot

For every drag without a component of its own, the provider's slot renders the overlay:

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

The slot gets the same props as an overlay component. When it renders nothing (the
`v-if` above), the drag falls back to the clone.

## What wins

For each drag, the first one that applies:

1. The item's own `overlay` (`makeSortableItem`, `makeDraggable`).
2. Its list's or tree's `overlay`.
3. The provider's `#overlay` slot, unless it renders nothing.
4. The default clone. In a multi-drag, a column or a pile of clones: see
   [multi-drag](/docs/guides/multi-drag#the-default-overlay).

The component is picked when the drag starts and kept for the whole drag, also over other
lists.

## `DragPreview`: the clone in your layout

`DragPreview` renders the library's clone of one dragged item. Use it in an overlay
component that lays out several items itself, or that adds a frame around the clone:

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

Clones exist for the grabbed item and up to four others next to it; for any other item,
`DragPreview` renders its default slot. See
[multi-drag](/docs/guides/multi-drag#a-custom-overlay-for-several-items) for a pile of
previews.

## Size: `overlayFit`

| `overlayFit` (provider) | The box |
| --- | --- |
| `'slot'` (default) | Takes the size of the slot it will land in. Over a list of wider cards, it widens. |
| `'source'` | Keeps the dragged element's size. |

With `'slot'`, the box resizes around the pointer, which stays at the same fraction of the
box. The content is never scaled: it re-lays out at the new size.

A drop does the same with either setting: the box flies to the landing element and
animates to **its** size, and the content re-lays out on the way. When an item looks
different in two lists (a compact chip in a palette, a full card on a board), the clone of
the source re-lays out at the target's size, and may look squeezed or stretched there. Two
ways to keep it right:

- Give the item the **same look** in every list it can land in. The files in
  [drag and drop](/docs/guides/drag-and-drop) have one fixed size in every folder, so a
  drop only moves them.
- Render the **target's look** in an overlay component. It gets `over`, so it can switch
  to the look of the list it is over, and it fills the box at any size.

A fixed size on an overlay component's root keeps that size inside the box. Give the root
`width: 100%; height: 100%` to follow it.

## Where it renders: `overlayTo`

The provider teleports the overlay to `body`. Inside a `<dialog>` opened with
`showModal()`, or a shadow root, the overlay would end up under the top layer or outside
the styles. Point `overlayTo` at a selector or an element there:

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## No overlay

`makeDraggable(el, { overlay: false })` has no box at all: the element itself moves,
through the returned `transform`. See
[drag and drop](/docs/guides/drag-and-drop#without-an-overlay). How the box lands is the
provider's `dropAnimation`: see [animations](/docs/guides/animations).
