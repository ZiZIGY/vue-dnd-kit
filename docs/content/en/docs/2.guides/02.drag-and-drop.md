Use `makeDraggable` and `makeDroppable` for anything that isn't a sortable list: files into
folders, a trash can, a chess board, a calendar, notes on a board.

::example{name="drop-zones" hint="Images go to Images, documents to Documents" height="30rem"}
::

## A draggable

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

Pass the id from your data, as a getter. The default id comes from `useId()` and is new
for every component instance, so it means nothing to the rest of your app.

| Returns | What it is |
| --- | --- |
| `isDragging` | This element is being dragged. |
| `selected` | Writable, bound to the provider's [selection](/docs/guides/multi-drag). |
| `transform` | The drag offset, for `overlay: false` (below). |
| `id` | The id in use. |

Buttons, inputs and other interactive children don't start a pointer drag, so they keep
working inside a draggable. To drag by one part only, pass a `handle` (see
[sortable lists](/docs/guides/sortable-lists#handles)). All options are in the
[makeDraggable API](/docs/api/make-draggable).

## A drop target

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| Returns | `true` when |
| --- | --- |
| `isOver` | The drag is over this target, whether it takes the drag or not. |
| `isAccepting` | Something is being dragged and this target takes it: light up the valid zones. |
| `placement` | Not a boolean: `{ top, right, bottom, left }`, the halves of the target the pointer is in, or `null` when it isn't hovered. Use it for "before / after this card". |

`isOver` without `isAccepting` means the drag is over a target that refuses it. Show it,
as the folders above do: a drop there is cancelled and the item flies back.

## Which drags a target takes

A draggable's `type` is matched against a target's `accept`:

| `accept` | Takes |
| --- | --- |
| omitted or `'*'` | Everything. |
| `'image'` | Draggables of type `image`, and untyped ones. |
| `['image', 'doc']` | Either type, and untyped ones. |
| `({ active, items, types }) => boolean` | Whatever your function says. |

A draggable without a `type` fits any string rule. Use a function for anything else:

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` can be an array too (`['image', 'large']`): one matching type is enough.

When several items are dragged at once, `acceptMode` says how many must fit: `'all'`
(default) or `'some'`. With `'some'`, return the ids to keep from `onBeforeDrop`, and the
others fly back. See [drop decisions](/docs/guides/drop-decisions).

## The drop

`onDrop` of a plain drop target is where **you** change your data. The library moves
nothing on its own:

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| Event field | What it holds |
| --- | --- |
| `active` | The drag: `id`, `ids`, `items` (`{ id, data, type, item }` each), `data`, `type`. |
| `over` | This target: `id`, `data`, `element`, `rect`. |
| `pointer`, `delta` | Where the pointer is, and how far it moved from the start. |
| `position` | Where the dragged box sits in this target (next section). |
| `source` | Set when the items come from a sortable list: `{ list, remove() }`. |

The order is `onBeforeDrop` (decide), `onDrop` (apply), then the provider's `drag-end`.
To ask before a drop, keep the drag going, or accept only some items, see
[drop decisions](/docs/guides/drop-decisions).

## Leave it where it was dropped

A board, a canvas, a floor plan: the item stays where you let go. Every event carries
`position`, the `left` / `top` that put an absolutely positioned item where it was
dropped.

::example{name="constraints" hint="Drag a note, then lock an axis or turn the grid off" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` is the top-left corner of the dragged box in `over`: measured from its padding
edge, with its scroll added. It is `null` over nothing. With `overlay: false` it is the
element's own corner.

::tip
Don't compute the spot from `active.rect` and `delta`: that misses the target's border
and scroll. Snapping, bounds and axis locks for such boards are in
[constraints](/docs/guides/constraints).
::

## Drop into a sortable item

A row of a sortable list can be a drop target too: a folder that takes files, a group
that takes tasks. Put a droppable on the item's element:

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

While the list would sort the drag, such a target counts only in the **middle** of its
item (25 to 75% along the list's axis). There the drop goes into the item and the list
doesn't move. Near the edges, the list sorts as usual.

- A target whose `accept` refuses the drag is skipped: the list sorts over the item as
  over any other. A folder that takes only files lets folders sort past it.
- A target never receives its own drag.
- If the item is no longer shown after the drop, the overlay shrinks into the target
  instead of flying back.

## Trash zones

A drag that starts in a sortable list carries `e.source`. Call `remove()` and the list
drops the items:

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

The list's own `onDrop` then runs with `to.index === -1`, and `e.result` holds the list
without the items. A list can also remove what is dropped outside of everything: see
[`dropOutside`](/docs/guides/shared-lists#dropping-outside).

## Without an overlay

By default a clone of the element follows the pointer, and the element stays in place.
With `overlay: false` there is no clone: move the element yourself with `transform`.

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

For a custom drag preview instead of the clone, see [the overlay](/docs/guides/overlay).

## Keyboard

A focused draggable picks up with :kbd{value="Space"} or :kbd{value="Enter"}. The arrows
move it by 25 px (the provider's `keyboard.step`). With `keyboard: 'droppables'` on the
draggable, they jump between the targets that accept it instead, which suits zones far
apart. More in [accessibility](/docs/guides/accessibility).
