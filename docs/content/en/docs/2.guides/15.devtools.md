`@vue-dnd-kit/devtools` adds a **Vue DnD Kit** tab to the Vue DevTools (`vite-plugin-vue-devtools`)
and to the Nuxt DevTools. It shows every list, tree and drop target of the page in a live
mini-map, drags any item with a joystick, edits options while the app runs, and logs what each drag
did. It works in development only: nothing of it reaches a production build.

## Install

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` is a peer dependency: the tab's moves go through it. npm 7+ and pnpm install
it by themselves; with Yarn 1, add it.

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

With Vite, the plugin serves the tab at `/__vue-dnd-kit-devtools/`, adds it to the Vue DevTools and
makes the page report to it before your app starts. No `app.use()` is needed. It acts on the dev
server only (`vite serve`); builds are untouched.

With Nuxt, the `@vue-dnd-kit/nuxt` module finds the package, serves the tab, adds it to the Nuxt
DevTools and installs the page's side with a client plugin. `vueDndKit: { devtools: false }` turns
it off.

### Without the plugins

For a dev server of your own, or a page Vite doesn't serve from an `index.html` (SSR setups),
install the page's side yourself:

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

Or import `@vue-dnd-kit/devtools/auto` first in the entry file. Use
`vueDnDKitDevtools({ inject: false })` when the plugin should serve the tab but you install the
page's side yourself; `serveTab()` from `@vue-dnd-kit/devtools/vite` is the middleware that serves
the tab.

## Open it

- **Vue DevTools**: :kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"}, or the Vue button at
  the bottom of the page, then the **Vue DnD Kit** tab.
- **Nuxt DevTools**: :kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"}, or the Nuxt button,
  then **Vue DnD Kit** (in the sidebar or its overflow menu).
- **A window of its own**: open `http://localhost:5173/__vue-dnd-kit-devtools/` on your dev server,
  or the tab's ⧉ button. Handy on a second screen.

::warning
Keep the tab in a window of its own, not in a background browser tab: a hidden page cancels drags.
::

## What the tab shows

### The mini-map

A live card per list, tree and drop target, with copies of their items where they are — the same
clones the overlay would show. During a drag it marks the lists that accept the drag (blue) or
refuse it (red), the placeholder, the target under the pointer, the overlay's box and the insertion
line of `placeholder: 'indicator'` lists. A click chooses an item; a double click scrolls the page
to it.

Use it when a drop doesn't go where you expect: it shows at a glance which lists take the drag.

### Drive: the joystick

Choose an item — on the map, in the tree, or with **Pick**, which takes the next press on the page —
and push the joystick's knob. The item is picked up and moves that way, faster the farther the knob
is from the center. **Drop** and **Cancel** end the drag.

It is a real pointer drag of a sensor named `devtools`, so lists sort, containers auto-scroll, and
`onBeforeDrop` and `onDrop` run as for any drag. Items of sortable lists also get buttons: up,
down, to the start, to the end, to another list of the group.

| Key, in the tab | Does |
| --- | --- |
| Arrows or :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | Push the knob that way; with :kbd{value="Shift"}, all the way |
| :kbd{value="G"} | Pick the chosen item up |
| :kbd{value="Space"} / :kbd{value="Enter"} | Drop |
| :kbd{value="Escape"} | Cancel |
| :kbd{value="P"} | Pick on the page |

### Options

Every option that isn't a callback can be edited while the app runs: the provider's (`collision`,
`modifiers`, `overlayFit`, `autoScroll`, animations, `activation`, `keyboard`…), a list's
(`strategy`, `placeholder`, `behavior`, `multiple`, `dropOutside`, `disabled`…), a tree's, a drop
target's and an item's. Choose the node and open **Options**.

An edit applies at once, to this page only, and is never written to your code. It lasts until you
reset it, the provider unmounts or the page reloads.

### State

What each provider knows, as a tree: its drag session (status, the active ids and sensor, the
target and whether it accepts, the pointer), its lists and trees with their order and draft, drop
targets with their rules, and the items' types and data.

### Log

One band per drag: the start (ids, sensor, the list it came from), each `over` and `left` with
acceptance, the release, the `onBeforeDrop` verdict — accepted, some accepted, rejected by a hook,
refused by the target's `accept` — and the `drop`, with `e.result` and whether `preventDefault()`
was called, or the `cancel` and why. Click an entry for its data.

Use it when a drop is refused and you don't know by what, or when a controlled list didn't change:
the log says whether `preventDefault()` ran and what `e.result` held.

## How it works

Providers report to a hook that the page's side installs. Until a tab watches the page, they are
only recorded; then the page listens like any monitor and sends the tab what it shows — every
40 ms during a drag, twice a second otherwise — and stops once no tab has watched for a few
seconds. The tab talks to the page over a `BroadcastChannel` of the page's origin. It changes
nothing but what you ask for: the drags, the selection and the option overrides.
