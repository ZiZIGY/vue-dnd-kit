## Rendered flat

A tree is rendered as a **flat list** of the visible nodes, in order, each with its
`depth`. You indent the rows yourself. That keeps every row a sibling in one container, so
rows slide and animate like the rows of a list.

```vue [FileTree.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableTree, type Key } from '@vue-dnd-kit/core';
import TreeRow from './TreeRow.vue';

interface FileNode { id: string; name: string; folder?: boolean; children?: FileNode[] }

const files = ref<FileNode[]>([
  { id: 'src', name: 'src', folder: true, children: [{ id: 'main', name: 'main.ts' }] },
  { id: 'readme', name: 'README.md' },
]);
const collapsed = ref(new Set<Key>());
const INDENT = 18;

const root = useTemplateRef<HTMLElement>('root');
const { items } = makeSortableTree(root, {
  items: files,                                  // the root nodes
  indentation: INDENT,                           // px per level: match your row padding
  collapsed,
  canNest: (_node, parent) => !!parent.folder,   // only folders take children
});

const toggle = (key: Key) => (collapsed.value.has(key) ? collapsed.value.delete(key) : collapsed.value.add(key));
</script>

<template>
  <div ref="root">
    <TreeRow v-for="node in items" :key="node.key" :node="node" :indent="INDENT" @toggle="toggle" />
  </div>
</template>
```

```vue [TreeRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem, type FlatNode, type Key } from '@vue-dnd-kit/core';

const props = defineProps<{ node: FlatNode<FileNode>; indent: number }>();
const emit = defineEmits<{ toggle: [key: Key] }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { id: () => props.node.key });
</script>

<template>
  <div ref="el" :style="{ paddingLeft: `${node.depth * indent}px` }">
    <button
      v-if="node.item.folder"
      type="button"
      :aria-expanded="!node.collapsed"
      :aria-label="node.collapsed ? 'Expand' : 'Collapse'"
      @click="emit('toggle', node.key)"
    >
      {{ node.collapsed ? '▸' : '▾' }}
    </button>
    {{ node.item.name }}
  </div>
</template>
```

Rows use `makeSortableItem`, like the rows of a list. `items` holds `FlatNode`s:

| `FlatNode` field | What it holds |
| --- | --- |
| `key` | The node's key (`getKey`, default `node.id`). Use it for `:key` and the row's `id`. |
| `item` | Your node. |
| `depth` | `0` for roots. The dragged node's depth is where it **would** land, so its slot indents live. |
| `parentKey` | The parent's key, `null` for roots. |
| `index` | The index among its siblings. |
| `hasChildren`, `collapsed` | For the expand button. |

Children are read from `node.children` and written there. Other shapes take
`getChildren` and `setChildren`:

```ts
makeSortableTree(root, {
  items: outline,
  getKey: (node) => node.uuid,
  getChildren: (node) => node.nested,
  setChildren: (node, children) => { node.nested = children; },
});
```

## Nesting

A drag changes the depth in two ways, both on by default (`nesting: 'both'`):

- **Sideways** (`'offset'`): drag left or right by `indentation` pixels to go a level up or
  down, as far as the rows around the slot allow.
- **Hover** (`'hover'`): hold the drag over the middle of a row, and the drop goes inside
  it, as its first child.

Set `indentation` to the padding your rows add per level, so the offset follows the
pointer. With `axis: 'y'` the drag can't move sideways, but rows still nest by hovering.

## Collapsed nodes

`collapsed` is a `Set` of keys whose children are hidden (a ref or a getter). Their
children aren't in `items`. A dragged folder takes its whole subtree along, collapsed or
not. With the tree's `animate` option on, the rows a folder shows or hides animate in and out.

## Rules

| Option | Limits |
| --- | --- |
| `canNest(node, parent)` | Whether `node` may go under `parent`. A multi-drag asks for every dragged node. |
| `maxDepth` | The deepest depth allowed, roots being `0`. The dragged node's descendants count: a folder with children and grandchildren goes to depth `maxDepth - 2` at most. |
| `group.put` | Whether the tree takes items from other lists and trees at all. |
| `onBeforeDrop` | Anything else, decided on drop: see [drop decisions](/docs/guides/drop-decisions). |

When a rule refuses a depth, the slot takes the deepest depth that passes. Where none
passes, the slot doesn't move there. Copies and nodes from `createItem` follow `canNest`
and `maxDepth` too.

## Trees and lists in one group

A tree and a list with the same `group` exchange nodes, as two lists do. A folder moved
into the list keeps its subtree, and comes back with it. Copies work as in lists (`clone`,
`pull: 'clone'`, the Alt key), but `clone` must return the copy **with its whole subtree**,
and every node in it needs a new key:

```ts
let count = 0;
const copyNode = (node: FileNode): FileNode => ({
  ...node,
  id: `${node.id}-${++count}`,
  children: node.children?.map(copyNode),
});

makeSortableTree(root, { items: files, group: 'files', clone: copyNode });
```

See [lists that share items](/docs/guides/shared-lists) for groups, copying and
`createItem`.

## An insertion line

With `placeholder: 'indicator'`, the tree doesn't move while you drag. Each row reads its
`indicator` and draws the line, indented to the depth the drop lands at:

```vue [TreeRow.vue]
<script setup lang="ts">
import { computed, useTemplateRef } from 'vue';
import { makeSortableItem, type FlatNode } from '@vue-dnd-kit/core';

const props = defineProps<{ node: FlatNode<FileNode>; indent: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { indicator } = makeSortableItem(el, { id: () => props.node.key });

// 'inside': the drop goes into this row. Otherwise a line before or after it.
const into = computed(() => indicator.value?.side === 'inside');
const line = computed(() => {
  const value = indicator.value;
  if (!value || value.side === 'inside') return null;
  return { side: value.side, left: `${(value.depth ?? 0) * props.indent}px` };
});
</script>

<template>
  <div ref="el" class="row" :class="{ into }" :style="{ paddingLeft: `${node.depth * indent}px` }">
    {{ node.item.name }}
    <span v-if="line" class="line" :class="line.side" :style="{ left: line.left }" />
  </div>
</template>

<style scoped>
.row { position: relative; }
.row.into { background: color-mix(in srgb, #42b883 15%, transparent); }
.line { position: absolute; right: 0; height: 2px; background: #42b883; }
.line.before { top: -1px; }
.line.after { bottom: -1px; }
</style>
```

`indicator` adds `depth` and `parentKey` in trees: the level and the parent the dropped
nodes get. Dragging sideways moves the line between levels. In this mode, a drop outside
the tree cancels.

## The drop

The tree's drop event is a list's, with `parentKey` added to `from` and `to`:

```ts
makeSortableTree(root, {
  items: files,
  onDrop: (e) => {
    console.log(e.keys, e.from.parentKey, '→', e.to.parentKey, e.to.index);
  },
});
```

`to.index` is the position among the new siblings, counted after the node left its old
place. On drop, the library gives the changed nodes their new children (`setChildren`) and
writes a new root array into your ref.

`e.result.get(treeId)` is the new tree as a new root array: the nodes on the changed paths
are copies, untouched subtrees are shared, and your nodes stay as they are. For a store or
immutable data, pass a getter, call `e.preventDefault()` and save `e.result`. Copies are
made with `withChildren(node, children)`, by default `{ ...node }` with the new children;
pass your own for class instances.

## Keyboard and multi-drag

With the keyboard, :kbd{value="ArrowUp"} and :kbd{value="ArrowDown"} move between rows,
:kbd{value="ArrowLeft"} and :kbd{value="ArrowRight"} change the depth where the rows around
allow it.

Selected nodes move together as one block, each with its subtree, in document order. A
selected node inside another selected one rides along in its parent's subtree. See
[multi-drag](/docs/guides/multi-drag).

All options are in the [makeSortableTree API](/docs/api/make-sortable-tree). For trees
with thousands of rows, see [virtual lists](/docs/guides/virtual-lists).
