```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider :animation="{ duration: 200 }" @drag-end="save">
    <RouterView />
    <template #overlay="{ items, over, accepted }">
      <!-- optional: a custom overlay for every drag -->
    </template>
  </DnDProvider>
</template>
```

Chaque composable doit s'exécuter dans un composant rendu **à l'intérieur** d'un provider. L'objectif
est un seul provider pour toute l'application : des parties de la page reçoivent leurs propres
règles avec [`makeDragArea`](/docs/api/make-drag-area). Voir le [guide du provider](/docs/guides/provider).

## Événements {#events}

| Événement | Payload | Quand |
| --- | --- | --- |
| `drag-start` | `DnDEvent` | Un glissement a commencé (après son activation). |
| `drag-move` | `DnDEvent` | Le pointeur a bougé pendant un glissement (au plus une fois par frame). |
| `drag-over` | `DnDEvent` | La cible sous le glissement a changé. |
| `drag-end` | `DnDEndEvent` | Un dépôt a abouti et a été écrit. |
| `drag-cancel` | `DnDEvent` | Le glissement a été annulé ou le dépôt refusé. |

Les mêmes événements, plus `onBeforeDrop` et `onDragResume`, sont disponibles n'importe où sous le
provider avec [`useDnDMonitor`](/docs/api/use-dnd). Leurs payloads sont décrits sur
[la page des événements](/docs/api/events).

## Slot `#overlay` {#slot-overlay}

Rend ce qui suit le pointeur, pour chaque glissement qui n'a pas son propre composant d'overlay
(voir le [guide de l'overlay](/docs/guides/overlay)). S'il ne rend rien, le glissement se rabat sur
le clone.
