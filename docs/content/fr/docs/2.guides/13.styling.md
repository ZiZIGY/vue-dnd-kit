La bibliothèque ne stylise presque rien. Chaque état d'un glissement vous parvient de deux façons :
sous forme de ref renvoyée par le composable, pour les classes et le balisage conditionnel, et
sous forme d'attribut `data-dnd-*`, pour du CSS simple.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## Les refs renvoyées {#the-returned-refs}

| Composable | État |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder` : cet élément est l'emplacement où un item glissé va atterrir.
- `isDragging` : l'item fait partie du glissement (chaque item glissé, en multi-drag).
- `isAccepting` : quelque chose est en cours de glissement, et cette cible l'accepte — mettez en
  évidence les endroits où un dépôt est possible.
- `isOver` : le glissement est au-dessus de cette cible, qu'elle l'accepte ou non.
  `isOver && !isAccepting` est un refus, qui mérite d'être montré.
- `over.accepted` de `useDnD()` (`accepted` dans les props de l'overlay) vaut `false` au-dessus
  d'une cible qui refuse le glissement : servez-vous-en pour teinter l'overlay en rouge.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## Les attributs data {#the-data-attributes}

| Attribut | Sur | Quand |
| --- | --- | --- |
| `data-dnd-placeholder` | item triable | C'est l'emplacement où un item glissé va atterrir. |
| `data-dnd-dragging` | item triable | Il est glissé mais reste en place : les autres items d'un multi-drag en mode `'gaps'`. |
| `data-dnd-dragging="pointer"` ou `"keyboard"` | `<html>` | Pendant tout le glissement. |
| `data-dnd-overlay="dragging"` ou `"dropping"` | la boîte de l'overlay | Toujours. `dropping` pendant l'atterrissage, et pendant qu'un `onBeforeDrop` asynchrone attend. |
| `data-dnd-leaving` | une copie laissée par `animate` | Pendant qu'un item parti disparaît en fondu. |
| `data-dnd-no-clone` | **défini par vous** | Exclut l'élément du clone de l'overlay : une infobulle, un bouton de menu, un badge. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## Styles par défaut {#default-styles}

Le provider injecte quelques règles, une fois par document. Elles sont enveloppées dans `:where()` :
leur spécificité est donc nulle, et n'importe laquelle de vos règles l'emporte :

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

Pendant un glissement, l'emplacement est estompé, la page ne sélectionne pas de texte et n'ancre
pas son défilement, et, pendant un glissement au pointeur, le curseur est une main qui saisit.
`:default-styles="false"` les désactive. C'est à vous d'ajouter `cursor: grab` sur les éléments
déplaçables.

## Recettes {#recipes}

### Un emplacement vide {#an-empty-slot}

Au lieu d'une copie estompée de l'item, affichez une boîte vide en pointillés là où il va
atterrir :

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

Le pseudo-élément recouvre le contenu : l'emplacement garde donc exactement la taille de l'item.
Faites glisser une carte ici pour le voir :

### Une ligne peinte par la liste {#a-row-the-list-paints}

L'overlay par défaut est un clone de l'élément glissé. Il montre l'élément tel qu'il est et ne
devine aucun fond : une ligne qui n'a pas de fond propre — un `<li>` dans un `<ul>` blanc, une
ligne de tableau, l'item de liste d'un kit UI — donne un clone transparent. Donnez-lui le fond de
la liste :

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

Le clone garde les classes et les attributs de l'élément — y compris l'attribut d'un style scoped —,
si bien que la règle fonctionne dans le propre `<style scoped>` de la ligne, à côté de ses autres
styles. Ou donnez à la ligne un fond propre. Les icônes et les tuiles censées flotter restent
transparentes.

### Un overlay soulevé, seulement pendant le glissement {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

L'ombre est présente pendant que la carte voyage et disparaît quand l'overlay passe à `dropping` :
la carte atterrit ainsi à plat dans son emplacement. Pour un composant d'overlay personnalisé, la
même règle cible la racine de votre composant, ou lisez `status` dans ses props.

### Mouvement réduit {#reduced-motion}

La bibliothèque arrête déjà ses propres animations avec `prefers-reduced-motion: reduce`. Faites de
même pour les transitions que vous ajoutez autour des glissements :

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### À éviter {#dont}

- Ne mettez pas de `transition` CSS sur le `transform` ou le `translate` des items triables : la
  bibliothèque les anime elle-même, et annule ces transitions pendant qu'elle mesure.
- N'animez pas la `height`, la `margin` ni le `padding` des lignes d'une [liste virtuelle](/docs/guides/virtual-lists).

Plus de détails sur l'overlay — composants personnalisés, taille, `DragPreview` — dans
[L'overlay](/docs/guides/overlay).
