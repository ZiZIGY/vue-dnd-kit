Pendant le glissement, une boîte suit le pointeur : l'**overlay**. L'élément glissé lui-même reste
là où il était, en tant qu'emplacement où il va atterrir. Au dépôt, l'overlay vole vers cet
emplacement et disparaît.

L'overlay est téléporté dans `body`, hors de vos composants. Par défaut, il affiche un clone de
l'élément glissé.

::example{name="overlay" hint="Faites glisser un message : la copie reçoit le fond de la boîte de réception" height="24rem"}
::

## Le clone par défaut {#the-default-clone}

Le clone est pris à la saisie, avant que quoi que ce soit ne bouge. C'est une copie profonde de
l'élément :

- Les valeurs des formulaires et les pixels des `<canvas>` sont copiés.
- Les styles calculés que l'élément perdrait hors de sa liste sont mis en ligne : polices et
  couleurs héritées, styles qui s'appliquent via les ancêtres (`.list li { … }`), largeurs des
  cellules de tableau. Une ligne de tableau est enveloppée dans son propre tableau.
- Les `id` et les attributs `data-dnd-*` sont retirés, et le clone est `aria-hidden`.
- Les effets d'ondulation et autres effets d'appui des kits UI (Vuetify, Quasar, PrimeVue,
  Naive UI) sont laissés de côté.

Marquez avec **`data-dnd-no-clone`** tout ce qui ne doit pas voyager : un bouton de menu, une
infobulle, un badge.

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### Les fonds ne sont pas devinés {#backgrounds-arent-guessed}

Le clone montre l'élément tel qu'il est. Une ligne qui n'a pas de fond propre, parce que c'est sa
liste qui le peint (un `<li>` dans un `<ul>` blanc, un `v-list-item`, une ligne de tableau), donne
un clone **transparent**. Donnez-lui le fond de la liste en CSS :

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

Le clone garde les classes et les attributs de l'élément, y compris l'attribut de scope de Vue :
la règle fonctionne donc aussi bien dans le style scoped de la ligne que dans une feuille de
style globale. L'autre solution est un fond sur la ligne elle-même. Les icônes et les tuiles
censées flotter, comme les icônes d'applications des [listes triables](/docs/guides/sortable-lists),
restent transparentes à dessein.

## Styliser la boîte {#styling-the-box}

La boîte est l'élément qui porte `data-dnd-overlay`. Elle est en `position: fixed` et
`pointer-events: none`, et la valeur de l'attribut indique ce qu'elle est en train de faire :

| `data-dnd-overlay` | Quand |
| --- | --- |
| `"dragging"` | Elle suit le pointeur. |
| `"dropping"` | Elle atterrit sur son emplacement, revient à sa place, ou attend un `onBeforeDrop` asynchrone. |

Un aspect soulevé pendant le glissement, qui disparaît à l'atterrissage :

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## Composants d'overlay {#overlay-components}

Pour afficher autre chose que le clone, passez un composant. Il est rendu à l'intérieur de la
boîte :

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | Ce qu'il contient |
| --- | --- |
| `active` | Le glissement (`id`, `ids`, `data`, `type`, …). |
| `items` | Tous les items glissés, en commençant par celui qui a été saisi : `{ id, item, data, type }`. `item` est l'item de la liste pour les glissements triables. |
| `over` | La cible sous le glissement, ou celle sur laquelle il atterrit pendant le dépôt. `null` au-dessus de rien, et pendant qu'un glissement annulé revient à sa place. |
| `accepted` | Si `over` accepte le glissement : teintez l'overlay en rouge quand ce n'est pas le cas. |
| `status` | `'dragging'` ou `'dropping'`. |
| `mode` | `'move'`, `'copy'`, `'swap'` ou `'insert'`. |

Un composant peut être passé tel quel, ou dans une `shallowRef` pour pouvoir le changer. Ne le
mettez jamais dans une `ref` profonde ni dans un `reactive` : Vue rendrait le composant réactif et
afficherait un avertissement.

La grille d'applications des [listes triables](/docs/guides/sortable-lists) en utilise un :
l'icône voyage seule et se soulève, et le nom reste en place.

::example{name="lists" hint="Faites glisser une icône d'application : son overlay est un composant" height="28rem"}
::

## Le slot `#overlay` du provider {#the-providers-overlay-slot}

Pour chaque glissement sans composant propre, c'est le slot du provider qui rend l'overlay :

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

Le slot reçoit les mêmes props qu'un composant d'overlay. Quand il ne rend rien (le `v-if`
ci-dessus), le glissement se rabat sur le clone.

## Qui l'emporte {#what-wins}

Pour chaque glissement, le premier qui s'applique :

1. L'`overlay` propre à l'item (`makeSortableItem`, `makeDraggable`).
2. L'`overlay` de sa liste ou de son arbre.
3. Le slot `#overlay` du provider, sauf s'il ne rend rien.
4. Le clone par défaut. En multi-drag, une colonne ou une pile de clones : voir le
   [multi-drag](/docs/guides/multi-drag#the-default-overlay).

Le composant est choisi au début du glissement et conservé pendant tout le glissement, y compris
au-dessus d'autres listes.

## `DragPreview` : le clone dans votre mise en page {#dragpreview-the-clone-in-your-layout}

`DragPreview` rend le clone, fait par la bibliothèque, d'un item glissé. Utilisez-le dans un
composant d'overlay qui dispose lui-même plusieurs items, ou qui ajoute un cadre autour du clone :

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

Des clones existent pour l'item saisi et pour quatre autres au plus, ses voisins ; pour tout autre
item, `DragPreview` rend son slot par défaut. Voir le
[multi-drag](/docs/guides/multi-drag#a-custom-overlay-for-several-items) pour une pile d'aperçus.

## Taille : `overlayFit` {#size-overlayfit}

| `overlayFit` (provider) | La boîte |
| --- | --- |
| `'slot'` (par défaut) | Prend la taille de l'emplacement où elle va atterrir. Au-dessus d'une liste de cartes plus larges, elle s'élargit. |
| `'source'` | Garde la taille de l'élément glissé. |

Avec `'slot'`, la boîte se redimensionne autour du pointeur, qui reste à la même proportion de la
boîte. Le contenu n'est jamais mis à l'échelle : sa mise en page est recalculée à la nouvelle
taille.

Un dépôt fait la même chose quel que soit le réglage : la boîte vole vers l'élément d'arrivée et
s'anime jusqu'à **sa** taille, et la mise en page du contenu est recalculée en chemin. Quand un
item n'a pas le même aspect dans deux listes (une chip compacte dans une palette, une carte
complète sur un tableau), le clone de la source est remis en page à la taille de la cible, et
peut y paraître écrasé ou étiré. Deux façons de garder un bon rendu :

- Donnez à l'item le **même aspect** dans toutes les listes où il peut atterrir. Les fichiers du
  [glisser-déposer](/docs/guides/drag-and-drop) ont une seule taille fixe dans chaque dossier : un
  dépôt ne fait donc que les déplacer.
- Rendez l'**aspect de la cible** dans un composant d'overlay. Il reçoit `over` : il peut donc
  passer à l'aspect de la liste qu'il survole, et il remplit la boîte à n'importe quelle taille.

Une taille fixe sur la racine d'un composant d'overlay garde cette taille à l'intérieur de la
boîte. Donnez à la racine `width: 100%; height: 100%` pour qu'elle suive la boîte.

## Où il est rendu : `overlayTo` {#where-it-renders-overlayto}

Le provider téléporte l'overlay dans `body`. À l'intérieur d'un `<dialog>` ouvert avec
`showModal()`, ou d'un shadow root, l'overlay se retrouverait sous la top layer ou hors des
styles. Faites pointer `overlayTo` vers un sélecteur ou un élément situé à l'intérieur :

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## Sans overlay {#no-overlay}

`makeDraggable(el, { overlay: false })` n'a aucune boîte : c'est l'élément lui-même qui bouge, via
le `transform` renvoyé. Voir le [glisser-déposer](/docs/guides/drag-and-drop#without-an-overlay).
La façon dont la boîte atterrit relève du `dropAnimation` du provider : voir les
[animations](/docs/guides/animations).
