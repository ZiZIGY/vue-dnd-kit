`@vue-dnd-kit/devtools` ajoute un onglet **Vue DnD Kit** aux Vue DevTools (`vite-plugin-vue-devtools`)
et aux Nuxt DevTools. Il affiche chaque liste, chaque arbre et chaque cible de dépôt de la page dans
une mini-carte en direct, fait glisser n'importe quel item avec un joystick, modifie les options
pendant que l'application tourne, et consigne ce que chaque glissement a fait. Il ne fonctionne
qu'en développement : rien de lui n'arrive dans un build de production.

## Installation {#install}

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` est une peer dependency : les déplacements de l'onglet passent par lui. npm 7+
et pnpm l'installent d'eux-mêmes ; avec Yarn 1, ajoutez-le.

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

Avec Vite, le plugin sert l'onglet à `/__vue-dnd-kit-devtools/`, l'ajoute aux Vue DevTools et fait
en sorte que la page lui envoie ses informations avant le démarrage de votre application. Aucun
`app.use()` n'est nécessaire. Il n'agit que sur le serveur de développement (`vite serve`) ; les
builds ne sont pas touchés.

Avec Nuxt, le module `@vue-dnd-kit/nuxt` trouve le paquet, sert l'onglet, l'ajoute aux Nuxt
DevTools et installe le côté page avec un plugin client. `vueDndKit: { devtools: false }` le
désactive.

### Sans les plugins {#without-the-plugins}

Pour votre propre serveur de développement, ou une page que Vite ne sert pas depuis un
`index.html` (configurations SSR), installez vous-même le côté page :

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

Ou importez `@vue-dnd-kit/devtools/auto` en premier dans le fichier d'entrée. Utilisez
`vueDnDKitDevtools({ inject: false })` quand le plugin doit servir l'onglet mais que vous installez
vous-même le côté page ; `serveTab()` de `@vue-dnd-kit/devtools/vite` est le middleware qui sert
l'onglet.

## L'ouvrir {#open-it}

- **Vue DevTools** : :kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"}, ou le bouton Vue en
  bas de la page, puis l'onglet **Vue DnD Kit**.
- **Nuxt DevTools** : :kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"}, ou le bouton Nuxt,
  puis **Vue DnD Kit** (dans la barre latérale ou son menu de débordement).
- **Dans sa propre fenêtre** : ouvrez `http://localhost:5173/__vue-dnd-kit-devtools/` sur votre
  serveur de développement, ou utilisez le bouton ⧉ de l'onglet. Pratique sur un second écran.

::warning
Gardez l'onglet dans sa propre fenêtre, et non dans un onglet de navigateur en arrière-plan : une
page masquée annule les glissements.
::

## Ce que montre l'onglet {#what-the-tab-shows}

### La mini-carte {#the-mini-map}

Une carte en direct par liste, arbre et cible de dépôt, avec des copies de leurs items là où ils se
trouvent — les mêmes clones que ceux que montrerait l'overlay. Pendant un glissement, elle marque
les listes qui acceptent le glissement (en bleu) ou le refusent (en rouge), le placeholder, la cible
sous le pointeur, la boîte de l'overlay et la ligne d'insertion des listes en
`placeholder: 'indicator'`. Un clic choisit un item ; un double clic fait défiler la page jusqu'à
lui.

Servez-vous-en quand un dépôt ne va pas là où vous l'attendez : elle montre d'un coup d'œil quelles
listes acceptent le glissement.

### Pilotage : le joystick {#drive-the-joystick}

Choisissez un item — sur la carte, dans l'arbre, ou avec **Pick**, qui prend le prochain appui sur
la page — et poussez le manche du joystick. L'item est saisi et se déplace dans cette direction,
d'autant plus vite que le manche est loin du centre. **Drop** et **Cancel** terminent le glissement.

C'est un vrai glissement au pointeur, mené par un capteur nommé `devtools` : les listes trient, les
conteneurs défilent automatiquement, et `onBeforeDrop` et `onDrop` s'exécutent comme pour n'importe
quel glissement. Les items des listes triables reçoivent aussi des boutons : vers le haut, vers le
bas, au début, à la fin, vers une autre liste du groupe.

| Touche, dans l'onglet | Effet |
| --- | --- |
| Flèches ou :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | Pousser le manche dans cette direction ; avec :kbd{value="Shift"}, jusqu'au bout |
| :kbd{value="G"} | Saisir l'item choisi |
| :kbd{value="Space"} / :kbd{value="Enter"} | Déposer |
| :kbd{value="Escape"} | Annuler |
| :kbd{value="P"} | Choisir sur la page |

### Options {#options}

Chaque option qui n'est pas un callback peut être modifiée pendant que l'application tourne :
celles du provider (`collision`, `modifiers`, `overlayFit`, `autoScroll`, les animations,
`activation`, `keyboard`…), d'une liste (`strategy`, `placeholder`, `behavior`, `multiple`,
`dropOutside`, `disabled`…), d'un arbre, d'une cible de dépôt et d'un item. Choisissez le nœud et
ouvrez **Options**.

Une modification s'applique immédiatement, à cette page uniquement, et n'est jamais écrite dans
votre code. Elle dure jusqu'à ce que vous la réinitialisiez, que le provider soit démonté ou que la
page soit rechargée.

### État {#state}

Ce que sait chaque provider, sous forme d'arbre : sa session de glissement (statut, ids et capteur
actifs, la cible et si elle accepte, le pointeur), ses listes et ses arbres avec leur ordre et leur
brouillon, les cibles de dépôt avec leurs règles, et les types et données des items.

### Journal {#log}

Une bande par glissement : le début (ids, capteur, liste d'origine), chaque `over` et `left` avec
l'acceptation, le relâchement, le verdict d'`onBeforeDrop` — accepté, partiellement accepté, rejeté
par un hook, refusé par l'`accept` de la cible — et le `drop`, avec `e.result` et le fait que
`preventDefault()` ait été appelé ou non, ou bien le `cancel` et sa raison. Cliquez sur une entrée
pour voir ses données.

Servez-vous-en quand un dépôt est refusé sans que vous sachiez par quoi, ou quand une liste
contrôlée n'a pas changé : le journal indique si `preventDefault()` a été exécuté et ce que
contenait `e.result`.

## Comment ça marche {#how-it-works}

Les providers envoient leurs informations à un hook qu'installe le côté page. Tant qu'aucun onglet
n'observe la page, elles sont seulement enregistrées ; ensuite, la page écoute comme n'importe quel
moniteur et envoie à l'onglet ce qu'il affiche — toutes les 40 ms pendant un glissement, deux fois
par seconde le reste du temps — et s'arrête dès qu'aucun onglet ne l'a observée depuis quelques
secondes. L'onglet communique avec la page via un `BroadcastChannel` de l'origine de la page. Il ne
change rien d'autre que ce que vous demandez : les glissements, la sélection et les options
modifiées.
