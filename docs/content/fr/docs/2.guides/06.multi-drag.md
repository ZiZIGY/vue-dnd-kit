## La sélection {#the-selection}

Chaque provider tient une sélection : un ensemble réactif d'ids. Faire glisser un item
**sélectionné** fait glisser tous les items sélectionnés, en commençant par celui qui a été saisi. Faire
glisser un item qui n'est pas sélectionné ne fait glisser que cet item.

La bibliothèque ne décide pas de la façon dont les gens sélectionnent : les règles de clic vous
appartiennent. Elle n'efface jamais non plus la sélection d'elle-même, et la sélection survit aux
démontages, comme ceux des lignes qu'une liste virtuelle recycle.

### Ctrl/Cmd-clic {#ctrlcmd-click}

Chaque item triable et chaque élément déplaçable renvoie `selected`, une ref modifiable liée à la
sélection :

```vue [Shot.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ shot: { id: string } }>();
const el = useTemplateRef<HTMLElement>('el');
const { selected } = makeSortableItem(el, { item: () => props.shot });

const onClick = (event: MouseEvent) => {
  if (event.ctrlKey || event.metaKey) selected.value = !selected.value;
};
</script>

<template>
  <div ref="el" :class="{ selected }" @click="onClick">…</div>
</template>
```

Le clic qui termine un glissement n'atteint pas `@click` : un dépôt ne modifie donc jamais la
sélection par accident. Utilisez `@click`, et non `pointerup`, pour les actions sur les items.

### Depuis n'importe où : `useDnD().selection` {#from-anywhere-usedndselection}

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// A plain click selects only that item, Ctrl/Cmd-click adds or removes it:
const onClick = (event: MouseEvent, id: string) => {
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
};

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

La sélection est indexée par id : elle peut donc contenir des items de plusieurs listes. Un
glissement emporte tous les items sélectionnés sous le provider.

## Sélection par rectangle {#rubber-band-selection}

`makeSelectionArea` transforme un élément en une zone où un appui sur l'espace vide trace un
rectangle de sélection, et les items qu'il traverse sont sélectionnés :

```vue [Gallery.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSelectionArea } from '@vue-dnd-kit/core';
import PhotoGrid from './PhotoGrid.vue';

const area = useTemplateRef<HTMLElement>('area');
const { isSelecting, style } = makeSelectionArea(area);
</script>

<template>
  <div ref="area" class="area">
    <PhotoGrid />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.area {
  position: relative;   /* the band is absolutely positioned inside */
  min-height: 320px;    /* room around the items to start a band */
}

.band {
  border: 1px solid #42b883;
  background: color-mix(in srgb, #42b883 15%, transparent);
}
</style>
```

- C'est vous qui rendez le rectangle : `style` le positionne, par rapport au contenu de la zone.
- La zone a besoin d'une **position non statique** (`relative` suffit), sinon le rectangle
  atterrit ailleurs.
- Un rectangle ne démarre que depuis la zone elle-même : faites donc une zone grande, tout le
  panneau, avec de l'espace autour des items, et non un conteneur ajusté au plus près. La galerie
  ci-dessus remplit toute sa boîte.
- Un appui sur un item le fait glisser. Les boutons, les champs et la barre de défilement de la
  zone gardent leurs appuis.
- Le rectangle reste ancré au contenu pendant que la zone ou la page défile.
  :kbd{value="Escape"} l'annule et restaure la sélection.
- `useDnD().status` vaut `'selecting'` pendant qu'un rectangle est tracé.

| Option | Ce qu'elle fait |
| --- | --- |
| `strategy` | `'toggle'` (par défaut) : les items que le rectangle traverse changent d'état. `'select'` : seuls les items à l'intérieur du rectangle finissent sélectionnés, si bien qu'un clic sur l'espace vide désélectionne les items de la zone. |
| `modifier` | Les touches à maintenir pour tracer : `{ keys: ['Shift'], method: 'every' }` (ou `'some'`). |
| `accept` | Les éléments déplaçables que le rectangle sélectionne, une [règle d'acceptation](/docs/guides/drag-and-drop#which-drags-a-target-takes) comparée à leur `type`. |
| `disabled` | Pas de rectangle ; l'activer annule un rectangle en cours. |
| `onSelected(ids)` | Appelée quand un rectangle se termine, avec la sélection. |
| `selection` | Votre propre `Ref<Set<Key>>` au lieu de la sélection du provider. |

Avec des zones imbriquées dans des zones, c'est la plus intérieure qui reçoit l'appui. Toutes les
options se trouvent dans l'[API de makeSelectionArea](/docs/api/make-selection-area).

## Comment bougent les autres items : `multiple` {#how-the-other-items-move-multiple}

La liste où commence un multi-drag décide de ce que font les autres items sélectionnés pendant
qu'il se déroule :

```ts
makeSortableList(listRef, { items: tasks, multiple: 'gaps' });
```

| `multiple` | Pendant le glissement | L'overlay |
| --- | --- | --- |
| `'group'` (par défaut) | Les autres items quittent leur place et voyagent avec celui qui a été saisi, comme un seul bloc d'emplacements : la liste montre donc déjà le résultat du dépôt. | Une colonne de jusqu'à cinq items glissés, dans le sens de la liste. |
| `'gaps'` | Les autres restent où ils sont, estompés (`data-dnd-dragging`), jusqu'au dépôt. | La même colonne. |
| `'stack'` | Les autres s'envolent dans l'overlay. | L'item saisi avec un compteur. |

Au dépôt, les items atterrissent ensemble à l'index cible, dans l'ordre qu'ils avaient. En
`'group'` et `'gaps'`, chaque item de l'overlay vole vers son propre emplacement.

### L'overlay par défaut {#the-default-overlay}

En `'group'` et `'gaps'`, l'overlay est une colonne des items glissés tels qu'ils vont atterrir :
celui qui a été saisi sous le pointeur, les autres avant et après lui dans l'ordre du dépôt (une
rangée dans les listes horizontales). Il affiche jusqu'à cinq items. Ceux qui dépassent sont
comptés là où ils se trouvent : `+N` au début de la colonne pour les items qui atterrissent avant
ceux qui sont affichés, `+N` à la fin pour ceux qui atterrissent après.

Dans les grilles, une colonne de cellules entières couvrirait la page : l'overlay est donc une
pile, avec jusqu'à trois items déployés en éventail derrière celui qui a été saisi, et le nombre
total par-dessus.

Les éléments déplaçables simples (`makeDraggable`) affichent l'item saisi avec un compteur.

### Types mélangés {#mixed-types}

Quand les items sélectionnés ont des types différents, `acceptMode` sur une cible indique si
`'all'` (par défaut) ou seulement `'some'` d'entre eux doivent convenir. Voir les
[listes qui partagent des items](/docs/guides/shared-lists#limits) et le
[glisser-déposer](/docs/guides/drag-and-drop#which-drags-a-target-takes).

## Un overlay personnalisé pour plusieurs items {#a-custom-overlay-for-several-items}

Les composants d'overlay et le slot `#overlay` du provider reçoivent `items` : tous les items
glissés, en commençant par celui qui a été saisi. `DragPreview` rend le clone, fait par la bibliothèque,
de n'importe lequel d'entre eux : votre mise en page peut ainsi réutiliser leur vrai rendu.

```vue [PileOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="pile">
    <!-- The grabbed item on top, two more turned behind it -->
    <DragPreview
      v-for="(entry, i) in items.slice(0, 3)"
      :id="entry.id"
      :key="entry.id"
      class="card"
      :style="{ width: '100%', height: '100%', zIndex: 3 - i, rotate: `${i * 4}deg` }"
    >
      <!-- Shown for an item without a clone -->
      <div class="fallback">{{ entry.id }}</div>
    </DragPreview>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.pile { position: relative; width: 100%; height: 100%; }
.card { position: absolute; inset: 0; }
.fallback { width: 100%; height: 100%; border-radius: 8px; background: Canvas; }
.count { position: absolute; top: -8px; right: -8px; z-index: 4; }
</style>
```

```ts
makeSortableList(listRef, { items: photos, strategy: 'grid', overlay: PileOverlay });
```

Les clones sont pris à la saisie : celui de l'item saisi et ceux de quatre autres au plus, voisins
dans l'ordre du dépôt, s'ils sont rendus. Pour tout autre item, `DragPreview` rend son slot par
défaut. Un aperçu a la taille de son item au moment de la saisie, sauf si vous le dimensionnez,
comme le fait le `style` ci-dessus (`class` et `style` sont transmis). En `'group'` et `'gaps'`,
chaque aperçu atterrit au dépôt sur l'emplacement de son propre item. Plus de détails sur les
composants d'overlay dans [l'overlay](/docs/guides/overlay).

## Arbres {#trees}

Dans un arbre, les nœuds sélectionnés se déplacent en un seul bloc, chacun avec son sous-arbre,
dans l'ordre du document. Un nœud sélectionné à l'intérieur d'un autre nœud sélectionné suit dans
le sous-arbre de son parent. Voir les [arbres](/docs/guides/trees).
