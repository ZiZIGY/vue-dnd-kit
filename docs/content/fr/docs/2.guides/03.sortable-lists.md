## Une liste et ses lignes {#a-list-and-its-rows}

Une liste triable demande deux composants : la liste et sa ligne.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

La ligne s'enregistre auprès de la liste dans laquelle elle est rendue. C'est aussi pour cela
que chaque liste a besoin de son propre composant : deux listes créées dans un même composant
partageraient leurs lignes.

## Le brouillon {#the-draft}

`makeSortableList` renvoie `items`, un **brouillon** de votre tableau. Pendant le glissement, le
brouillon se réordonne en direct : la ligne glissée prend son nouvel emplacement, et les autres
s'écartent. Votre tableau ne change pas avant le dépôt. La bibliothèque y écrit alors le nouvel
ordre.

::example{name="quick-start" hint="Les ids sous la liste sont votre tableau : ils changent au dépôt"}
::

- Rendez `items`, pas votre tableau. Si vous rendez votre tableau, rien ne bouge avant le dépôt.
- L'écriture a lieu après le `onDrop` de la liste. Dans `onDrop`, votre tableau contient encore
  l'ancien ordre, et `e.result` le nouveau.
- `tasks` est une `ref` ordinaire : le reste de votre application voit donc le changement comme
  n'importe quel autre.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

Un composant de liste qui reçoit son tableau via `v-model` transmet le modèle :

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
Un store, un état serveur ou des données immuables ? Passez un getter ou un `computed` au lieu
d'une ref. La bibliothèque n'écrit pas dans une source en lecture seule : appelez
`e.preventDefault()` et appliquez `e.result` vous-même. Voir les [décisions de dépôt](/docs/guides/drop-decisions).
::

## Clés {#keys}

Les lignes sont identifiées par une clé issue de leurs données, jamais par l'index ni par un id
automatique. Par défaut, la clé est `item.id`, ou l'item lui-même pour les chaînes et les nombres.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Utilisez la même clé dans `v-for` : `:key="task.uuid"`. Avec `:key="index"`, ce ne sont pas les
  bonnes lignes qui s'animent, et leur état saute d'une ligne à l'autre.
- Les clés doivent être uniques parmi toutes les listes qui s'échangent des items.
- Passez `item` et `id` sous forme de getters, pour qu'une ligne reste synchronisée quand ses
  props changent.

## Stratégies {#strategies}

| `strategy` | Pour |
| --- | --- |
| `'vertical'` (par défaut) | Une colonne de lignes. |
| `'horizontal'` | Une seule rangée : onglets, chips, une frise chronologique. |
| `'grid'` | Les grilles CSS et les rangées flex qui passent à la ligne, y compris avec des items de tailles différentes. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Poignées {#handles}

Par défaut, toute la ligne lance un glissement (sauf les boutons, les champs de saisie et les
autres contrôles qu'elle contient). Passez `handle` pour ne faire glisser que par une partie :

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` est un sélecteur à l'intérieur de l'item, ou une ref d'élément.
- Un glissement à la souris démarre immédiatement depuis la poignée, sans les 4 px habituels.
- La poignée reçoit les attributs du glissement (`role`, `tabindex`, `aria-*`), et les
  glissements au clavier démarrent depuis elle.

Faites de la poignée un `<button type="button">` avec un `aria-label` : il peut recevoir le focus
tel quel, et les lecteurs d'écran annoncent son libellé. Un simple `<span>` avec une icône
fonctionne aussi (la bibliothèque lui donne `tabindex="0"` et `role="button"`), mais il n'a pas
de nom significatif.

::note
Les glissements tactiles démarrent après un appui long de 200 ms, pour que la page puisse encore
défiler. Pour faire glisser immédiatement depuis une poignée, donnez à la poignée
`touch-action: none` et à l'item `activation: { touch: { distance: 4 } }`.
::

## Verrouiller l'axe {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` maintient le glissement sur l'axe vertical, `'x'` sur l'axe horizontal. L'`axis`
propre à un item l'emporte sur celui de sa liste. Pour garder aussi le glissement à l'intérieur
de la liste, ajoutez le modificateur `restrictToParent` ; la playlist ci-dessus utilise les deux.
Plus de détails dans les [contraintes](/docs/guides/constraints).

## Styliser l'emplacement {#style-the-slot}

La ligne glissée reste dans la liste en tant qu'emplacement où elle va atterrir, et reçoit
`data-dnd-placeholder`. Le style par défaut l'estompe à 40 %, avec une spécificité nulle, si bien que
n'importe laquelle de vos règles l'emporte :

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` renvoie le même état sous forme de refs, plus quelques autres :

| Renvoie | Ce que c'est |
| --- | --- |
| `isPlaceholder` | Cette ligne est l'emplacement où un item glissé va atterrir. |
| `isDragging` | Cette ligne est en cours de glissement (chaque ligne glissée, en multi-drag). |
| `index` | Son index dans le brouillon : il change pendant le glissement. |
| `selected` | Modifiable, lié à la sélection du provider. |
| `indicator` | En [mode indicateur](/docs/guides/shared-lists#an-insertion-line), l'endroit où va la ligne. |

La liste renvoie `isOver` et `isAccepting` pour sa propre mise en évidence. Tous les attributs et
toutes les recettes sont décrits dans la [mise en forme](/docs/guides/styling).

## Désactiver {#turning-things-off}

- `disabled` sur la liste : aucun glissement hors d'elle, aucun dépôt dans elle. Sur un item :
  il ne peut pas être glissé.
- `sort: false` : les items ne peuvent pas être réordonnés dans cette liste, mais peuvent encore
  la quitter (une palette, voir les [listes qui partagent des items](/docs/guides/shared-lists)).

## Animations {#animations}

Les lignes glissent vers leur nouvelle place pendant le glissement, et la ligne déposée atterrit
sur son emplacement. C'est activé par défaut et ne demande aucun code. N'enveloppez pas les lignes
dans `<TransitionGroup>` : les déplacements seraient animés deux fois. Pour les changements qui ne
viennent pas d'un glissement (ajout, suppression, mélange), activez l'option `animate` de la
liste. Voir les [animations](/docs/guides/animations).

La liste complète des options se trouve dans l'API de [makeSortableList](/docs/api/make-sortable-list)
et de [makeSortableItem](/docs/api/make-sortable-item).
