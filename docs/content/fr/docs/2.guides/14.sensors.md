Un capteur transforme des entrées en glissements. Il dit seulement au provider « fais glisser cet
item depuis ici », puis où l'entrée s'est déplacée, et si elle a déposé ou annulé. Le provider fait
le reste, de la même façon pour chaque capteur : un glissement à la fois, refus des items
désactivés, contraintes d'activation, tri, défilement automatique, annonces, :kbd{value="Escape"}
et tout le dépôt.

## Les capteurs intégrés {#the-built-in-sensors}

| Capteur | Entrée |
| --- | --- |
| `pointerSensor` | Souris, toucher et stylet, via les Pointer Events. Il capture le pointeur, empêche la page de sélectionner du texte ou de défiler sous un glissement tactile, et avale le clic qui suit un glissement. |
| `keyboardSensor` | :kbd{value="Space"} et :kbd{value="Enter"} saisissent et déposent, les flèches déplacent, :kbd{value="Escape"} annule — n'importe quel glissement, y compris au pointeur. |

Les deux sont actifs par défaut. La prop `sensors` du provider remplace la liste :

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

Pour désactiver les glissements au clavier, préférez `:keyboard="false"` à l'omission de
`keyboardSensor` : le capteur clavier est aussi ce qui annule n'importe quel glissement avec
:kbd{value="Escape"}. Ses touches se réassignent avec `keyboard.keys` (voir
[Accessibilité](/docs/guides/accessibility#the-keyboard)).

## Contraintes d'activation {#activation-constraints}

Un appui devient un glissement dès qu'il satisfait sa contrainte :

| Pointeur | Par défaut |
| --- | --- |
| Souris | Après un déplacement de 4 px. Immédiatement lors d'un appui sur un `handle`, sauf si vous définissez une contrainte pour la souris. |
| Stylet | Après un déplacement de 4 px. |
| Toucher | Après un appui de 200 ms. Un mouvement de plus de 5 px avant cela l'interrompt, et la page défile à la place. |

Une contrainte a trois champs :

| Champ | Signification |
| --- | --- |
| `distance` | Les pixels que le pointeur doit parcourir. |
| `delay` | Les millisecondes que l'appui doit durer. Avec les deux, le premier atteint lance le glissement. |
| `tolerance` | Avec `delay` : de combien le pointeur peut bouger pendant ce temps ; au-delà, l'appui est abandonné. |

Définissez-les par type de pointeur — `mouse`, `touch`, `pen` — sur le provider, une zone de
glissement ou l'item lui-même. Celle de l'item l'emporte, puis celle de sa zone, puis celle du
provider :

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

Pour faire glisser immédiatement au toucher depuis une poignée, donnez à la poignée
`touch-action: none` (pour que le navigateur ne fasse pas défiler la page) et à l'item
`activation: { touch: { distance: 4 } }`.

### Un anneau d'appui long {#a-long-press-ring}

Pendant qu'un appui attend, `useDnD().status` vaut `'activating'` et `activation.progress` va de 0
à 1 :

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### Seulement certains appuis {#only-some-presses}

`canDrag` est un filtre de plus sur les éléments déplaçables et les items triables. Il reçoit
l'événement d'entrée :

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

Les enfants interactifs — boutons, champs de saisie, champs éditables — ne lancent jamais de
glissement au pointeur : ils continuent donc de fonctionner dans un élément déplaçable. Avec un
`handle`, seule la poignée en lance un.

## Votre propre capteur {#a-sensor-of-your-own}

Une manette, un joystick à l'écran, des commandes vocales : tout ce qui peut désigner un item et se
déplacer peut piloter un glissement. Voici un joystick qui saisit ce qui se trouve sous son curseur
après un maintien de 300 ms :

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

Ajoutez-le aux `sensors` du provider, ou faites-le tourner pendant toute la durée de vie d'un
composant avec `useSensor(joystick.sensor)`.

### Ce que reçoit le capteur {#what-the-sensor-gets}

`setup(context)` reçoit le côté provider :

| Membre | Ce que c'est |
| --- | --- |
| `props` | Les props du provider (`activation`, `keyboard`…). Lisez-les au moment où vous en avez besoin : elles peuvent changer. |
| `status` | Le statut de glissement du provider, quel que soit le capteur qui mène le glissement. |
| `drag` | Le glissement actuel du provider, en attente ou en cours, quel que soit le capteur qui l'a lancé. `null` quand il n'y en a pas. |
| `activate(options)` | Demande un glissement. Renvoie un `SensorDrag`, ou `null` quand aucun glissement ne peut commencer. |
| `cancel()` | Annule le glissement ou l'appui en attente du provider. |

`activate()` accepte :

| Option | Signification |
| --- | --- |
| `target` | L'endroit où l'entrée est arrivée : un élément à l'intérieur d'un élément déplaçable, ou l'id d'un élément déplaçable. Un élément est vérifié comme un vrai appui (poignée, pas d'enfant interactif) ; un id saute les vérifications. |
| `point` | Où commence le glissement, en coordonnées du viewport. Par défaut : le centre de l'élément déplaçable. |
| `type` | `'pointer'` (par défaut) : suit des points, teste les collisions avec les cibles, fait défiler automatiquement. `'keyboard'` : déplace d'item en item, rend les cibles visibles, rend le focus à la fin. |
| `activation` | Une contrainte (`{ delay: 300 }`), ou un type de pointeur (`'touch'`) pour utiliser celle qui est configurée. Par défaut : aucune, le glissement commence immédiatement. |
| `event` | L'événement d'entrée, transmis au `canDrag` de l'item. Un `pointerType` tactile en fait un glissement tactile (vibrations). |
| `onStart(drag)` | Le glissement a commencé, après son activation. |
| `onEnd(drag)` | Le glissement est terminé : interrompu, déposé ou annulé — par qui que ce soit. |
| `onResume(drag)` | `onBeforeDrop` a répondu `'continue'` : le glissement continue, et `move`, `drop` et `cancel` s'appliquent de nouveau. |

Le `SensorDrag` qu'elle renvoie :

| Membre | Ce qu'il fait |
| --- | --- |
| `id`, `type` | L'id de l'item glissé, et `'pointer'` ou `'keyboard'`. |
| `state` | `'pending'` (en attente de l'activation), `'dragging'`, puis `'ended'`. |
| `started` | Le glissement a commencé, même s'il s'est terminé depuis. |
| `move(point)` | L'entrée s'est déplacée. En attente, vérifie la tolérance ; pendant le glissement, déplace le glissement. |
| `step(direction)` | Glissements au clavier : un pas de flèche, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | Place l'item à une position d'une liste triable, comme le font les déplacements au clavier. Se résout à `false` quand aucune liste ne l'accepte à cet endroit. |
| `drop()` | Dépose. Se résout à `true` quand le dépôt a abouti, une fois l'atterrissage terminé. |
| `cancel()` | Annule : l'item revient à sa place, ou un appui en attente est abandonné. |

Les appels qui ne s'appliquent plus — un déplacement après la fin, un second `drop()` — sont
ignorés. Types complets : [Capteurs](/docs/api/sensors).

::tip
Pour envelopper un capteur intégré, exécutez son `setup` avec votre propre contexte. Créez-le avec
`Object.create(context, { activate: { value: myActivate } })` plutôt qu'avec une décomposition, pour
que les getters dynamiques (`status`, `drag`, `props`) continuent de fonctionner.
::

## Glissements programmatiques {#programmatic-drags}

`@vue-dnd-kit/actions` déplace des items depuis le code : boutons « Monter », menus, raccourcis
clavier, annulation de la dernière action, visites guidées de prise en main, tests. Il est construit sur l'API publique des
capteurs, et ses glissements sont de vrais glissements : annoncés et animés, en passant par
`onBeforeDrop`, `onDrop`, `e.result` et `preventDefault()`, selon les règles du provider (un
glissement à la fois, items désactivés, `accept` et `group.put`).

::example{name="actions" hint="Les flèches, le mélange et le glissement scripté appellent tous @vue-dnd-kit/actions" height="28rem"}
::

```bash
npm i @vue-dnd-kit/actions
```

### moveItem : un appel, un déplacement {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` est l'`id` d'une liste triable. Sans lui, l'item reste dans sa liste.
- `index` est l'endroit où l'item se retrouve, compté sans l'item lui-même et ramené dans les
  limites de la liste. Sans lui, l'item va à la fin.
- Il se résout à `true` quand le dépôt a abouti, à `false` quand l'item n'est pas rendu ou est
  désactivé, qu'aucune liste ne l'accepte à cet endroit, ou que le dépôt a été refusé.
- Les appels sont mis en file d'attente : chacun attend que le provider soit au repos, et un
  second clic rapide n'est donc pas perdu.
- Il s'exécute comme un glissement au clavier : il est donc annoncé et le focus reste sur l'item.
- Listes uniquement : dans les arbres, les positions ont aussi une profondeur.

Voir [Accessibilité](/docs/guides/accessibility#moving-without-dragging) pour une ligne avec des
boutons de déplacement.

### startDrag : un glissement scripté {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` se résout une fois le déplacement rendu, `drop` une fois le dépôt atterri.
`startDrag(id, { type: 'keyboard' })` déplace plutôt d'item en item (`await drag.step('down')`), et
le capteur clavier peut prendre le relais : une entrée de menu « Déplacer » qui confie l'item aux
flèches du clavier.

### En dehors des composants {#outside-components}

`useDnDActions()` fait tourner un capteur, nommé `actions`, dans le provider au-dessus. Pour piloter
un provider depuis un store ou un harnais de test, ou sous un nom de votre choix, créez les actions
dans un capteur que vous faites tourner vous-même :

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

Ensuite, `await tour?.moveItem('card-1', { list: 'done' })` depuis n'importe où. Pendant le rendu
côté serveur, rien ne glisse : `moveItem` se résout à `false` et `startDrag` renvoie `null`.
