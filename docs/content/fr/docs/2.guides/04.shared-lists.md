## Un groupe {#a-group}

Les listes qui ont le même nom de `group` s'échangent des items. Par défaut, chaque liste forme
un groupe à elle seule.

```vue [Column.vue]
<script setup lang="ts">
import { toRef, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import Card from './Card.vue';

type Task = { id: string; title: string };
const props = defineProps<{ column: { id: string; title: string; cards: Task[] } }>();

const zone = useTemplateRef<HTMLElement>('zone');
const list = useTemplateRef<HTMLElement>('list');
const { items, isOver } = makeSortableList(list, {
  id: props.column.id,                   // names the list in drop events
  items: toRef(props.column, 'cards'),   // a writable ref into the reactive column
  group: 'board',                        // same name: cards move between these lists
  dropzone: zone,                        // the whole column takes drops
});
</script>

<template>
  <section ref="zone" :class="{ over: isOver }">
    <h3>{{ column.title }}</h3>
    <ul ref="list">
      <Card v-for="card in items" :key="card.id" :card="card" />
    </ul>
  </section>
</template>
```

```vue [Board.vue]
<script setup lang="ts">
import { reactive } from 'vue';
import Column from './Column.vue';

const columns = reactive([
  { id: 'todo', title: 'To do', cards: [{ id: 'vdk-12', title: 'Pick a palette' }] },
  { id: 'done', title: 'Done', cards: [] },
]);
</script>

<template>
  <Column v-for="column in columns" :key="column.id" :column="column" />
</template>
```

- Chaque colonne est un composant à part entière : une liste par composant.
- `toRef(props.column, 'cards')` est modifiable, car le parent passe un objet réactif. Le dépôt
  écrit dans les deux tableaux, celui que la carte a quitté et celui où elle est entrée.
- `id` apparaît dans les événements de dépôt sous la forme `from.list` et `to.list`, et sert de
  clé à `e.result`, les nouveaux tableaux de chaque liste modifiée par le dépôt. `id` et `group`
  sont lus une seule fois.
- Les clés doivent être uniques dans tout le groupe.

Le `onDrop` d'une liste s'exécute pour les dépôts **dans** cette liste. Un déplacement de `todo`
vers `done` appelle le `onDrop` de la liste `done`, et son `e.result` contient les nouveaux
tableaux des deux listes.

## Toute la colonne accepte les dépôts : `dropzone` {#the-whole-column-takes-drops-dropzone}

Une liste courte dans une colonne haute laisse un espace vide sous la dernière carte. Avec
`dropzone: zone`, l'élément de la colonne reçoit les dépôts pour la liste : une carte lâchée
sous la dernière atterrit à la fin. Les cartes restent dans le `<ul>` ; seule la zone qui reçoit
les dépôts s'agrandit.

::tip
Sans `dropzone`, une liste vide a quand même besoin d'une taille pour recevoir des dépôts :
donnez-lui une `min-height`.
::

## Ce qui entre et ce qui sort : `pull` et `put` {#what-goes-in-and-out-pull-and-put}

`group` accepte aussi un objet :

```ts
group: { name: 'board', pull: true, put: true }
```

| Option | Valeurs |
| --- | --- |
| `pull` | `true` (par défaut) : les items peuvent sortir. `false` : ils ne le peuvent pas. `'clone'` : des copies sortent, les items restent. |
| `put` | `true` (par défaut) : les items peuvent entrer. `false` : rien n'entre. Une fonction : vous décidez pour chaque glissement. |

Une fonction `put` reçoit `{ keys, items, types, from, to }`. `from` est la liste d'où viennent
les items, `null` pour les éléments déplaçables simples. Les déplacements à l'intérieur d'une
liste sont toujours autorisés.

### Limites {#limits}

Une colonne qui contient au plus trois cartes :

```ts
makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'cards'),
  group: {
    name: 'board',
    put: ({ keys }) => props.column.cards.length + keys.length <= 3,
  },
});
```

Au-dessus d'une liste qui refuse le glissement, l'emplacement revient là où le glissement a
commencé : les listes montrent ainsi ce que ferait un dépôt, c'est-à-dire rien. Un dépôt à cet
endroit est annulé et la carte revient à sa place. Le `isAccepting` de la liste vaut `false`
pendant un tel glissement : servez-vous-en pour atténuer la colonne.

Quand plusieurs items sélectionnés de types différents sont glissés, `acceptMode` indique si
`'all'` (par défaut) ou seulement `'some'` d'entre eux doivent passer `put`. Avec `'some'`, ceux
qui passent atterrissent et les autres reviennent à leur place.

## Copier : palettes et touche Alt {#copy-palettes-and-the-alt-key}

::example{name="palette" hint="Faites glisser depuis la palette ; Alt + glisser copie ; déposez hors de la page pour supprimer" height="24rem"}
::

```ts [Palette.vue]
makeSortableList(list, {
  items: templates,
  group: { name: 'blocks', pull: 'clone', put: false },  // copies go out, nothing comes in
  sort: false,                                           // its own order stays
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),
});
```

```ts [Sheet.vue]
makeSortableList(list, {
  items: blocks,
  group: 'blocks',
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),  // for Alt-drags
});
```

- `pull: 'clone'` copie chaque glissement qui sort de la liste. L'original reste, et c'est la
  copie qui se déplace et atterrit.
- Maintenir :kbd{value="Alt"} pendant le glissement copie aussi, depuis n'importe quelle liste.
  Changez la touche avec le `copyModifier` du provider, ou désactivez-la avec `null`.
- Dans les deux cas, la liste d'où vient l'item a besoin de `clone`. Cette fonction doit renvoyer
  la copie avec une **nouvelle clé**. Sans `clone`, rien n'est copié.
- L'événement de dépôt contient `mode: 'copy'`, et `e.items` sont les copies. Un composant
  d'overlay reçoit aussi `mode`, pour afficher un « + » pendant la copie (voir [l'overlay](/docs/guides/overlay)).

## Des éléments déplaçables simples dans une liste {#plain-draggables-into-a-list}

Une liste accueille les items glissés avec `makeDraggable` quand elle sait en faire un item :

```ts
makeSortableList(list, {
  items: tasks,
  createItem: (active) => ({ id: crypto.randomUUID(), title: (active.data as Chip).title }),
});
```

Pendant que l'élément déplaçable est au-dessus de la liste, l'item créé se trouve dans le
brouillon et votre template le rend comme n'importe quelle autre ligne. Il devient réel au dépôt
(`mode: 'insert'`, `from.list === null`). Renvoyez `undefined` pour refuser. Les listes sans
`createItem` ignorent les éléments déplaçables simples. Au clavier, une flèche en direction de la
liste y fait entrer l'élément déplaçable.

## Échanger au lieu de décaler {#swap-instead-of-shift}

```ts
makeSortableList(grid, { items: tiles, strategy: 'grid', behavior: 'swap' });
```

L'item glissé échange sa place avec celui qui se trouve en dessous, et les autres ne bougent pas.
L'échange se fait en direct : revenir en arrière, ou sortir de la liste, l'annule. L'événement de
dépôt contient `mode: 'swap'` et `partner`, l'item avec lequel il a été échangé.

- Deux listes d'un même groupe font des échanges entre elles quand elles ont toutes les deux
  `behavior: 'swap'`. L'item survolé passe dans l'autre liste : il doit donc avoir le droit de
  sortir (`pull: true`) et d'entrer (`put`).
- Un multi-drag trie au lieu d'échanger.

## Une ligne d'insertion {#an-insertion-line}

Avec `placeholder: 'indicator'`, la liste reste immobile pendant le glissement, et une ligne
indique où ira le dépôt. C'est vous qui dessinez la ligne :

```ts [TaskList.vue]
const { items, indicator } = makeSortableList(listRef, { items: tasks, placeholder: 'indicator' });
```

```vue [TaskRow.vue]
<script setup lang="ts">
const { indicator } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" :class="indicator && `drop-${indicator.side}`">{{ task.title }}</li>
</template>

<style scoped>
.drop-before { box-shadow: inset 0 2px 0 #42b883; }
.drop-after { box-shadow: inset 0 -2px 0 #42b883; }
</style>
```

| Champ de `indicator` | Ce qu'il contient |
| --- | --- |
| `list` | La liste dans laquelle va le dépôt. |
| `index` | L'index d'insertion dans la liste telle qu'elle est rendue. |
| `key` | L'item auquel la ligne est rattachée ; `null` dans une liste vide (dessinez-la alors dans la liste). |
| `side` | `'before'` ou `'after'` par rapport à cet item. Les arbres ajoutent `'inside'`. |
| `depth`, `parentKey` | Arbres uniquement : où atterrit le dépôt. Voir les [arbres](/docs/guides/trees#an-insertion-line). |

L'`indicator` de la liste est défini tant que la ligne se trouve dans cette liste, et
l'`indicator` d'un item tant qu'elle est rattachée à cet item. Le clavier déplace aussi la ligne.

## Déposer à l'extérieur {#dropping-outside}

Ce qui se passe quand un glissement se termine au-dessus d'aucune cible est décidé par le
`dropOutside` de la liste :

| `dropOutside` | Les items |
| --- | --- |
| `'placeholder'` (par défaut) | Atterrissent là où l'emplacement a été affiché pour la dernière fois. |
| `'cancel'` | Reviennent à leur place. C'est la valeur par défaut avec `placeholder: 'indicator'`. |
| `'remove'` | Quittent leur liste : faites glisser à l'extérieur pour supprimer. |

`'remove'` consulte d'abord le `onBeforeDrop` de la liste. Ensuite, le `onDrop` de la liste
s'exécute avec `to.index === -1`, et `e.result` contient la liste sans les items. Une corbeille
qui accepte les dépôts fonctionne de la même façon : voir les [zones de corbeille](/docs/guides/drag-and-drop#trash-zones).

Pour confirmer un déplacement, l'enregistrer d'abord sur un serveur, ou appliquer vous-même les
dépôts à un store, voir les [décisions de dépôt](/docs/guides/drop-decisions). Toutes les options
de liste se trouvent dans l'[API de makeSortableList](/docs/api/make-sortable-list).
