## Rendu à plat {#rendered-flat}

Un arbre est rendu comme une **liste plate** des nœuds visibles, dans l'ordre, chacun avec sa
`depth`. C'est vous qui indentez les lignes. Ainsi, toutes les lignes sont sœurs dans un même
conteneur, et elles glissent et s'animent comme les lignes d'une liste.

```vue [FileTree.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableTree, type Key } from '@vue-dnd-kit/core';
import TreeRow from './TreeRow.vue';

interface FileNode { id: string; name: string; folder?: boolean; children?: FileNode[] }

const files = ref<FileNode[]>([
  { id: 'src', name: 'src', folder: true, children: [{ id: 'main', name: 'main.ts' }] },
  { id: 'readme', name: 'README.md' },
]);
const collapsed = ref(new Set<Key>());
const INDENT = 18;

const root = useTemplateRef<HTMLElement>('root');
const { items } = makeSortableTree(root, {
  items: files,                                  // the root nodes
  indentation: INDENT,                           // px per level: match your row padding
  collapsed,
  canNest: (_node, parent) => !!parent.folder,   // only folders take children
});

const toggle = (key: Key) => (collapsed.value.has(key) ? collapsed.value.delete(key) : collapsed.value.add(key));
</script>

<template>
  <div ref="root">
    <TreeRow v-for="node in items" :key="node.key" :node="node" :indent="INDENT" @toggle="toggle" />
  </div>
</template>
```

```vue [TreeRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem, type FlatNode, type Key } from '@vue-dnd-kit/core';

const props = defineProps<{ node: FlatNode<FileNode>; indent: number }>();
const emit = defineEmits<{ toggle: [key: Key] }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { id: () => props.node.key });
</script>

<template>
  <div ref="el" :style="{ paddingLeft: `${node.depth * indent}px` }">
    <button
      v-if="node.item.folder"
      type="button"
      :aria-expanded="!node.collapsed"
      :aria-label="node.collapsed ? 'Expand' : 'Collapse'"
      @click="emit('toggle', node.key)"
    >
      {{ node.collapsed ? '▸' : '▾' }}
    </button>
    {{ node.item.name }}
  </div>
</template>
```

Les lignes utilisent `makeSortableItem`, comme les lignes d'une liste. `items` contient des
`FlatNode` :

| Champ de `FlatNode` | Ce qu'il contient |
| --- | --- |
| `key` | La clé du nœud (`getKey`, par défaut `node.id`). Utilisez-la pour `:key` et pour l'`id` de la ligne. |
| `item` | Votre nœud. |
| `depth` | `0` pour les racines. La profondeur du nœud glissé est celle où il **atterrirait** : son emplacement s'indente donc en direct. |
| `parentKey` | La clé du parent, `null` pour les racines. |
| `index` | L'index parmi ses frères. |
| `hasChildren`, `collapsed` | Pour le bouton de dépliage. |

Les enfants sont lus depuis `node.children` et y sont écrits. Pour d'autres structures, utilisez
`getChildren` et `setChildren` :

```ts
makeSortableTree(root, {
  items: outline,
  getKey: (node) => node.uuid,
  getChildren: (node) => node.nested,
  setChildren: (node, children) => { node.nested = children; },
});
```

## Imbrication {#nesting}

Un glissement change la profondeur de deux façons, toutes deux activées par défaut
(`nesting: 'both'`) :

- **De côté** (`'offset'`) : faites glisser vers la gauche ou la droite de `indentation` pixels
  pour remonter ou descendre d'un niveau, aussi loin que les lignes autour de l'emplacement le
  permettent.
- **Par survol** (`'hover'`) : maintenez le glissement au-dessus du milieu d'une ligne, et le
  dépôt va à l'intérieur, comme son premier enfant.

Réglez `indentation` sur le padding que vos lignes ajoutent à chaque niveau, pour que le
décalage suive le pointeur. Avec `axis: 'y'`, le glissement ne peut pas aller de côté, mais les
lignes s'imbriquent quand même par survol.

## Nœuds repliés {#collapsed-nodes}

`collapsed` est un `Set` de clés dont les enfants sont masqués (une ref ou un getter). Leurs
enfants ne sont pas dans `items`. Un dossier glissé emporte tout son sous-arbre, qu'il soit
replié ou non. Avec l'option `animate` de l'arbre activée, les lignes qu'un dossier affiche ou
masque apparaissent et disparaissent avec une animation.

## Règles {#rules}

| Option | Ce qu'elle limite |
| --- | --- |
| `canNest(node, parent)` | Si `node` peut aller sous `parent`. Un multi-drag pose la question pour chaque nœud glissé. |
| `maxDepth` | La profondeur maximale autorisée, les racines étant à `0`. Les descendants du nœud glissé comptent : un dossier avec des enfants et des petits-enfants va au plus à la profondeur `maxDepth - 2`. |
| `group.put` | Si l'arbre accepte des items venant d'autres listes et arbres. |
| `onBeforeDrop` | Tout le reste, décidé au dépôt : voir les [décisions de dépôt](/docs/guides/drop-decisions). |

Quand une règle refuse une profondeur, l'emplacement prend la profondeur la plus grande qui est
acceptée. Là où aucune ne l'est, l'emplacement ne s'y déplace pas. Les copies et les nœuds issus
de `createItem` respectent aussi `canNest` et `maxDepth`.

## Arbres et listes dans un même groupe {#trees-and-lists-in-one-group}

Un arbre et une liste qui ont le même `group` s'échangent des nœuds, comme deux listes. Un
dossier déplacé dans la liste garde son sous-arbre, et revient avec lui. Les copies fonctionnent
comme dans les listes (`clone`, `pull: 'clone'`, la touche Alt), mais `clone` doit renvoyer la
copie **avec tout son sous-arbre**, et chaque nœud qu'elle contient a besoin d'une nouvelle clé :

```ts
let count = 0;
const copyNode = (node: FileNode): FileNode => ({
  ...node,
  id: `${node.id}-${++count}`,
  children: node.children?.map(copyNode),
});

makeSortableTree(root, { items: files, group: 'files', clone: copyNode });
```

Voir les [listes qui partagent des items](/docs/guides/shared-lists) pour les groupes, la copie et
`createItem`.

## Une ligne d'insertion {#an-insertion-line}

Avec `placeholder: 'indicator'`, l'arbre ne bouge pas pendant le glissement. Chaque ligne lit son
`indicator` et dessine la ligne, indentée à la profondeur où atterrit le dépôt :

```vue [TreeRow.vue]
<script setup lang="ts">
import { computed, useTemplateRef } from 'vue';
import { makeSortableItem, type FlatNode } from '@vue-dnd-kit/core';

const props = defineProps<{ node: FlatNode<FileNode>; indent: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { indicator } = makeSortableItem(el, { id: () => props.node.key });

// 'inside': the drop goes into this row. Otherwise a line before or after it.
const into = computed(() => indicator.value?.side === 'inside');
const line = computed(() => {
  const value = indicator.value;
  if (!value || value.side === 'inside') return null;
  return { side: value.side, left: `${(value.depth ?? 0) * props.indent}px` };
});
</script>

<template>
  <div ref="el" class="row" :class="{ into }" :style="{ paddingLeft: `${node.depth * indent}px` }">
    {{ node.item.name }}
    <span v-if="line" class="line" :class="line.side" :style="{ left: line.left }" />
  </div>
</template>

<style scoped>
.row { position: relative; }
.row.into { background: color-mix(in srgb, #42b883 15%, transparent); }
.line { position: absolute; right: 0; height: 2px; background: #42b883; }
.line.before { top: -1px; }
.line.after { bottom: -1px; }
</style>
```

Dans les arbres, `indicator` ajoute `depth` et `parentKey` : le niveau et le parent que
reçoivent les nœuds déposés. Faire glisser de côté déplace la ligne d'un niveau à l'autre. Dans
ce mode, un dépôt hors de l'arbre annule le glissement.

## Le dépôt {#the-drop}

L'événement de dépôt de l'arbre est celui d'une liste, avec `parentKey` ajouté à `from` et `to` :

```ts
makeSortableTree(root, {
  items: files,
  onDrop: (e) => {
    console.log(e.keys, e.from.parentKey, '→', e.to.parentKey, e.to.index);
  },
});
```

`to.index` est la position parmi les nouveaux frères, comptée après que le nœud a quitté son
ancienne place. Au dépôt, la bibliothèque donne aux nœuds modifiés leurs nouveaux enfants
(`setChildren`) et écrit un nouveau tableau de racines dans votre ref.

`e.result.get(treeId)` est le nouvel arbre sous forme d'un nouveau tableau de racines : les
nœuds sur les chemins modifiés sont des copies, les sous-arbres intacts sont partagés, et vos
nœuds restent tels quels. Pour un store ou des données immuables, passez un getter, appelez
`e.preventDefault()` et enregistrez `e.result`. Les copies sont faites avec
`withChildren(node, children)`, par défaut `{ ...node }` avec les nouveaux enfants ; passez votre
propre fonction pour des instances de classe.

## Clavier et multi-drag {#keyboard-and-multi-drag}

Au clavier, :kbd{value="ArrowUp"} et :kbd{value="ArrowDown"} passent d'une ligne à l'autre,
:kbd{value="ArrowLeft"} et :kbd{value="ArrowRight"} changent la profondeur là où les lignes
autour le permettent.

Les nœuds sélectionnés se déplacent ensemble en un seul bloc, chacun avec son sous-arbre, dans
l'ordre du document. Un nœud sélectionné à l'intérieur d'un autre nœud sélectionné suit dans le
sous-arbre de son parent. Voir le [multi-drag](/docs/guides/multi-drag).

Toutes les options se trouvent dans l'[API de makeSortableTree](/docs/api/make-sortable-tree).
Pour les arbres de plusieurs milliers de lignes, voir les [listes virtuelles](/docs/guides/virtual-lists).
