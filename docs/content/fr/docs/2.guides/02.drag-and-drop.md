Utilisez `makeDraggable` et `makeDroppable` pour tout ce qui n'est pas une liste triable : des
fichiers dans des dossiers, une corbeille, un échiquier, un calendrier, des notes sur un tableau.

::example{name="drop-zones" hint="Les images vont dans Images, les documents dans Documents" height="30rem"}
::

## Un élément déplaçable {#a-draggable}

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

Passez l'id issu de vos données, sous forme de getter. L'id par défaut vient de `useId()` et
change pour chaque instance du composant : il ne signifie donc rien pour le reste de votre
application.

| Renvoie | Ce que c'est |
| --- | --- |
| `isDragging` | Cet élément est en cours de glissement. |
| `selected` | Modifiable, lié à la [sélection](/docs/guides/multi-drag) du provider. |
| `transform` | Le décalage du glissement, pour `overlay: false` (voir plus bas). |
| `id` | L'id utilisé. |

Les boutons, les champs de saisie et les autres enfants interactifs ne lancent pas de
glissement au pointeur : ils continuent donc de fonctionner dans un élément déplaçable. Pour
ne faire glisser que par une partie, passez un `handle` (voir les
[listes triables](/docs/guides/sortable-lists#handles)). Toutes les options se trouvent dans
l'[API de makeDraggable](/docs/api/make-draggable).

## Une cible de dépôt {#a-drop-target}

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| Renvoie | `true` quand |
| --- | --- |
| `isOver` | Le glissement est au-dessus de cette cible, qu'elle l'accepte ou non. |
| `isAccepting` | Quelque chose est en cours de glissement et cette cible l'accepte : mettez en évidence les zones valides. |
| `placement` | Pas un booléen : `{ top, right, bottom, left }`, les moitiés de la cible où se trouve le pointeur, ou `null` quand elle n'est pas survolée. Servez-vous-en pour « avant / après cette carte ». |

`isOver` sans `isAccepting` signifie que le glissement est au-dessus d'une cible qui le refuse.
Montrez-le, comme le font les dossiers ci-dessus : un dépôt à cet endroit est annulé et l'item
revient à sa place.

## Quels glissements une cible accepte {#which-drags-a-target-takes}

Le `type` d'un élément déplaçable est comparé à l'`accept` d'une cible :

| `accept` | Accepte |
| --- | --- |
| omis ou `'*'` | Tout. |
| `'image'` | Les éléments déplaçables de type `image`, et ceux sans type. |
| `['image', 'doc']` | L'un ou l'autre type, et ceux sans type. |
| `({ active, items, types }) => boolean` | Ce que dit votre fonction. |

Un élément déplaçable sans `type` satisfait n'importe quelle règle sous forme de chaîne. Pour
tout le reste, utilisez une fonction :

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` peut aussi être un tableau (`['image', 'large']`) : un seul type correspondant suffit.

Quand plusieurs items sont glissés à la fois, `acceptMode` indique combien doivent convenir :
`'all'` (par défaut) ou `'some'`. Avec `'some'`, renvoyez depuis `onBeforeDrop` les ids à
garder, et les autres reviennent à leur place. Voir les [décisions de dépôt](/docs/guides/drop-decisions).

## Le dépôt {#the-drop}

Le `onDrop` d'une cible de dépôt simple est l'endroit où **vous** modifiez vos données. La
bibliothèque ne déplace rien d'elle-même :

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| Champ de l'événement | Ce qu'il contient |
| --- | --- |
| `active` | Le glissement : `id`, `ids`, `items` (chacun `{ id, data, type, item }`), `data`, `type`. |
| `over` | Cette cible : `id`, `data`, `element`, `rect`. |
| `pointer`, `delta` | Où se trouve le pointeur, et de combien il s'est déplacé depuis le début. |
| `position` | Où se trouve la boîte glissée dans cette cible (section suivante). |
| `source` | Défini quand les items viennent d'une liste triable : `{ list, remove() }`. |

L'ordre est `onBeforeDrop` (décider), `onDrop` (appliquer), puis le `drag-end` du provider.
Pour demander une confirmation avant un dépôt, poursuivre le glissement ou n'accepter qu'une
partie des items, voir les [décisions de dépôt](/docs/guides/drop-decisions).

## Le laisser là où il a été déposé {#leave-it-where-it-was-dropped}

Un tableau, un canevas, un plan d'étage : l'item reste là où vous le lâchez. Chaque événement
transporte `position`, le `left` / `top` qui place un item positionné en absolu là où il a été
déposé.

::example{name="constraints" hint="Faites glisser une note, puis verrouillez un axe ou désactivez la grille" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` est le coin supérieur gauche de la boîte glissée dans `over` : mesuré depuis le bord
de son padding, défilement compris. Il vaut `null` au-dessus de rien. Avec `overlay: false`,
c'est le coin de l'élément lui-même.

::tip
Ne calculez pas l'emplacement à partir de `active.rect` et `delta` : cela ignore la bordure et
le défilement de la cible. L'alignement sur une grille, les limites et le verrouillage d'axe
pour ce genre de tableaux sont décrits dans les [contraintes](/docs/guides/constraints).
::

## Déposer dans un item triable {#drop-into-a-sortable-item}

Une ligne d'une liste triable peut aussi être une cible de dépôt : un dossier qui accepte des
fichiers, un groupe qui accepte des tâches. Placez un droppable sur l'élément de l'item :

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

Là où la liste trierait le glissement, une telle cible ne compte qu'au **milieu** de son item
(de 25 à 75 % le long de l'axe de la liste). À cet endroit, le dépôt va dans l'item et la liste
ne bouge pas. Près des bords, la liste trie comme d'habitude.

- Une cible dont l'`accept` refuse le glissement est ignorée : la liste trie au-dessus de cet
  item comme au-dessus de n'importe quel autre. Un dossier qui n'accepte que des fichiers laisse
  les dossiers le dépasser.
- Une cible ne reçoit jamais son propre glissement.
- Si l'item n'est plus affiché après le dépôt, l'overlay se réduit dans la cible au lieu de
  revenir à sa place.

## Zones de corbeille {#trash-zones}

Un glissement qui commence dans une liste triable transporte `e.source`. Appelez `remove()` et
la liste retire les items :

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

Le `onDrop` propre à la liste s'exécute alors avec `to.index === -1`, et `e.result` contient la
liste sans les items. Une liste peut aussi retirer ce qui est déposé en dehors de tout : voir
[`dropOutside`](/docs/guides/shared-lists#dropping-outside).

## Sans overlay {#without-an-overlay}

Par défaut, un clone de l'élément suit le pointeur, et l'élément reste en place. Avec
`overlay: false`, il n'y a pas de clone : déplacez l'élément vous-même avec `transform`.

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

Pour un aperçu de glissement personnalisé à la place du clone, voir [l'overlay](/docs/guides/overlay).

## Clavier {#keyboard}

Un élément déplaçable qui a le focus se saisit avec :kbd{value="Space"} ou :kbd{value="Enter"}.
Les flèches le déplacent de 25 px (le `keyboard.step` du provider). Avec `keyboard: 'droppables'`
sur l'élément déplaçable, elles sautent plutôt d'une cible qui l'accepte à l'autre, ce qui
convient aux zones éloignées les unes des autres. Plus de détails dans
l'[accessibilité](/docs/guides/accessibility).
