Faites glisser une carte dans **Done**. Le dépôt attend votre réponse : déplacer la carte, continuer
à la faire glisser ailleurs, ou annuler.

::example{name="drop-confirm" hint="Faites glisser une carte dans Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

Les listes, les arbres, les cibles de dépôt (`makeDroppable`) et les moniteurs (`useDnDMonitor`)
acceptent un `onBeforeDrop`. Il s'exécute quand le glissement est relâché, avant que quoi que ce
soit ne change, et sa réponse décide :

| Réponse | Ce qui se passe |
| --- | --- |
| `'accept'`, `true` ou rien | Le dépôt a lieu. |
| `'reject'` ou `false` | Pas de dépôt : les items reviennent à leur place. Une erreur levée refuse aussi le dépôt. |
| Un tableau de clés | Seuls ces items sont déposés ; les autres reviennent à leur place. |
| `'continue'` | Pas de dépôt, et le glissement continue. |
| Une promesse de l'une de ces valeurs | L'overlay attend là où il a été relâché jusqu'à ce que la promesse soit résolue ou rejetée. |

Les règles propres à la cible passent en premier : l'`accept` d'une cible de dépôt, le `group.put`
d'une liste. Au-dessus d'une cible qui refuse le glissement, le dépôt est annulé et le
`onBeforeDrop` de la cible n'est pas consulté. `onBeforeDrop` sert à ce que ces règles ne peuvent
pas savoir : la réponse de l'utilisateur, celle du serveur, ou ce que le dépôt changerait.

Les listes et les arbres passent un `SortableDropEvent` : `keys`, `items`, `from`, `to`, `mode`,
`sameList` et `result`, les nouveaux tableaux de chaque liste modifiée par le dépôt. Les cibles de
dépôt et les moniteurs reçoivent le `DnDEvent` générique : `active`, `over`, `position` et
`source`. Voir [Événements](/docs/api/events).

### Accepter une partie des items {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

Dans un [multi-drag](/docs/guides/multi-drag), les items dont vous renvoyez les clés atterrissent,
et les autres reviennent d'où ils viennent. `onDrop` les voit ensuite dans `e.accepted` et `e.rejected`,
et son `e.result` est le résultat final.

## Continuer le glissement : 'continue' {#keep-dragging-continue}

`'continue'` annule le dépôt, pas le glissement. L'item reste en main là où il était, la page
repasse en mode glissement, et l'utilisateur poursuit :

- À la souris ou au stylet, l'item suit le pointeur sans qu'aucun bouton ne soit maintenu. Le
  relâchement suivant — un clic — le dépose, et ce clic n'atteint jamais la page en dessous.
- Au toucher, l'item est repris là où le doigt se pose ; lever le doigt le dépose.
- Un glissement au clavier continue : les flèches déplacent l'item, :kbd{value="Space"} ou
  :kbd{value="Enter"} le déposent.
- :kbd{value="Escape"} l'annule, comme n'importe quel glissement.
- Le dépôt suivant consulte de nouveau `onBeforeDrop`.

Les moniteurs entendent `onDragResume`, et les lecteurs d'écran annoncent que l'item n'a pas été
déposé et qu'il est toujours en mouvement (remplacez le texte avec `announcements.onDragResume` du
provider).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## Demander à l'utilisateur {#asking-the-user}

`onBeforeDrop` peut renvoyer une promesse. Ouvrez une boîte de dialogue, et résolvez la promesse
avec le bouton que l'utilisateur choisit :

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Tant que la promesse est en attente :

- l'overlay attend là où il a été relâché, marqué `data-dnd-overlay="dropping"` ;
- `useDnD()` garde l'état qu'il avait au relâchement, et `status` vaut `'dropping'` ;
- la page est sortie du mode glissement : le curseur et la sélection de texte sont revenus, et une
  boîte de dialogue fonctionne donc normalement.

::tip
Un `<dialog>` modal ouvert avec `showModal()` se trouve dans la top layer, au-dessus de l'overlay
en attente. Transformez son événement `cancel` (:kbd{value="Escape"}) en `'reject'`, comme le fait
l'exemple.
::

## L'ordre des hooks {#the-order-of-the-hooks}

1. Le `onBeforeDrop` de chaque `useDnDMonitor`, tour à tour. Un `'reject'` ou un `'continue'` met
   fin aux consultations ; des clés restreignent le dépôt.
2. Le `onBeforeDrop` de la cible : la liste ou l'arbre où vont les items, ou la cible de dépôt.
3. Le `onDrop` de la cible uniquement : une liste que des items quittent pour une autre n'est pas
   consultée, et son nouveau tableau se trouve dans le `e.result` de la cible. Quand des items sont
   retirés (une zone de corbeille, `dropOutside: 'remove'`), le `onDrop` de leur liste s'exécute,
   avec un `to.index` de `-1`.
4. L'écriture par défaut : chaque liste modifiée par le dépôt reçoit son nouveau tableau.
5. L'overlay atterrit. Le `@drag-end` du provider et le `onDragEnd` des moniteurs suivent.

Vos moniteurs décident avant la cible : leur veto n'arrive donc jamais après qu'une liste a déjà
appliqué un dépôt de son côté.

## onDrop : prévenu avant l'écriture {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

Le `onDrop` d'une liste s'exécute une fois le dépôt accepté, de manière synchrone, juste avant que
la liste ne l'écrive. Pour agir après l'écriture, utilisez le `@drag-end` du provider ou
`useDnDMonitor({ onDragEnd })`. Sur une cible de dépôt simple, `onDrop` est l'endroit où vous
modifiez vos données : la bibliothèque ne déplace rien à sa place.

## Stores et serveurs : listes contrôlées {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

La bibliothèque n'écrit un dépôt que dans une ref modifiable. Un getter, un `computed` ou une ref
`readonly` ne sont jamais écrits : appelez `e.preventDefault()` et appliquez `e.result` vous-même —
les nouveaux tableaux de chaque liste modifiée par le dépôt, par id de liste. `preventDefault()`
empêche l'écriture dans toutes ces listes, car n'en écrire qu'une partie perdrait ou dupliquerait
des items. Les builds de développement affichent un avertissement quand le dépôt d'une liste en
lecture seule est laissé à la bibliothèque.

### Enregistrer d'abord sur un serveur {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Appliquez `e.result` avant que la promesse ne soit résolue, et l'overlay atterrit dans le nouvel
ordre. Si la requête échoue, n'appliquez rien : le dépôt a lieu, ne change rien, et les items
reviennent à leur place.

## Déposer hors de toute cible {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | Un dépôt hors de toute cible… |
| --- | --- |
| `'placeholder'` | Atterrit là où se trouve le placeholder : la dernière place affichée par la liste. C'est la valeur par défaut. |
| `'cancel'` | Est annulé : les items reviennent à leur place. C'est la valeur par défaut avec `placeholder: 'indicator'`. |
| `'remove'` | Retire les items de leur liste. Le `onBeforeDrop` de la liste est consulté d'abord, et son `onDrop` reçoit un `to.index` de `-1`. |

Une zone de corbeille fait la même chose, délibérément :
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`. Voir
[Glisser-déposer](/docs/guides/drag-and-drop).
