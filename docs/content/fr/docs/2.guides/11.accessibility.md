Tout ce qui est décrit sur cette page est activé par défaut. Atteignez la poignée d'un morceau avec
Tab, appuyez sur :kbd{value="Space"}, déplacez-le avec les flèches et appuyez de nouveau sur
:kbd{value="Space"} — ou sur :kbd{value="Escape"} pour le remettre à sa place.

::example{name="lists" hint="Tab jusqu'à une poignée, Espace, flèches, Espace" height="28rem"}
::

Ce qui vous revient d'habitude : des noms lisibles pour les items, et des boutons qui les déplacent
pour les personnes qui ne peuvent pas du tout faire glisser.

## Le clavier {#the-keyboard}

| Touche | Action |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Saisir l'item qui a le focus ; le déposer. |
| Flèches | Le déplacer : par emplacements dans les listes, par lignes et par profondeur dans les arbres, de `keyboard.step` pixels dans les glissements libres. |
| :kbd{value="Escape"} | Annuler le glissement — y compris un glissement au pointeur. |

- Dans une liste, une flèche en direction d'une autre liste du même groupe y déplace l'item.
- Dans un glissement libre, :kbd{value="Shift"} agrandit les pas. `makeDraggable(el, { keyboard: 'droppables' })`
  fait plutôt sauter les flèches d'une cible qui accepte l'item à l'autre.
- Un glissement au clavier démarre depuis l'élément déplaçable qui a le focus, ou depuis sa
  poignée — jamais depuis un bouton ou un champ qu'il contient : ceux-ci gardent donc leurs propres
  touches.
- Les glissements au clavier font défiler la cible jusqu'à ce qu'elle soit visible, au lieu du
  défilement automatique aux bords.
- Après le dépôt, le focus revient sur l'item, même si sa ligne a été re-rendue dans une autre
  liste.

### Autres touches {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Les raccourcis correspondent à `event.code` (`'Space'`, `'KeyD'`) ou à `event.key` (`'Enter'`).
`step` est le nombre de pixels par appui sur une flèche dans les glissements libres (25 par
défaut). `:keyboard="false"` désactive les glissements au clavier, et :kbd{value="Escape"} annule
toujours n'importe quel glissement. Quand vous changez les touches, changez aussi
`screen-reader-instructions`.

## Attributs ARIA {#aria-attributes}

Chaque élément déplaçable et chaque item triable reçoit ces attributs, **sauf si vous les
définissez vous-même** :

| Attribut | Valeur |
| --- | --- |
| `tabindex` | `0`, quand l'élément ne peut pas déjà recevoir le focus. |
| `role` | `button`, sauf sur un `<button>`, qui en est déjà un. |
| `aria-roledescription` | `draggable`, ou `sortable` sur les items triables. |
| `aria-describedby` | Les instructions du provider, ajoutées à côté des ids déjà présents (celui d'une infobulle est conservé). |
| `aria-disabled` | `true` ou `false` : si l'item est désactivé (y compris par une zone de glissement désactivée). |
| `aria-pressed` | `true` pendant qu'il est glissé. |

`attributes: false` les désactive pour un item ; ce que la bibliothèque avait défini est retiré.

### Poignées : faites-en de vrais boutons {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

Avec un `handle`, les attributs vont sur la poignée, et les glissements au clavier démarrent depuis
elle. Un `<button>` peut recevoir le focus et est déjà un bouton : il n'a donc besoin ni de
`tabindex` ni de `role`. Donnez-lui un `aria-label` : une icône de poignée n'a pas de nom propre, et
« Move Midnight Drive » en dit plus que « button ».

## Annonces {#announcements}

Une région live dans le provider énonce chaque saisie, déplacement, dépôt et annulation. Les listes
triables disent où se trouve l'item : *"Picked up item t2 at position 2 of 5 in list playlist."*
Les déplacements sont énoncés une fois que le glissement est resté immobile 500 ms.

Les textes utilisent les ids. Donnez aux items des ids lisibles, ou écrivez les textes vous-même :

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- Un texte remplace l'annonce de l'événement ; `undefined` garde celle par défaut ; `''` ne dit
  rien. Les événements que vous omettez gardent aussi leur annonce par défaut, comme les positions
  des listes triables pour `onDragOver` ci-dessus.
- `onDragResume` est énoncé quand `onBeforeDrop` a répondu `'continue'` et que le glissement
  continue (voir [Décider d'un dépôt](/docs/guides/drop-decisions)).
- `screenReaderInstructions` est le texte vers lequel chaque élément déplaçable pointe avec
  `aria-describedby`.
- `:announcements="false"` rend la région muette, par exemple quand vous faites les annonces avec
  la vôtre.

::note
Les textes intégrés sont en anglais. Pour une autre langue, fournissez les cinq textes et les
instructions — chacun de ceux que vous omettez est énoncé en anglais, positions des listes triables
comprises.
::

## Tactile {#touch}

Les glissements tactiles démarrent après un appui long de 200 ms. Un mouvement de plus de 5 px
avant cela fait défiler la page à la place : les listes restent ainsi défilables. Réglez ces deux
valeurs avec `activation` (voir [Capteurs](/docs/guides/sensors#activation-constraints)), et
dessinez un anneau d'appui long à partir de `useDnD().activation.progress`.

Un glissement tactile vibre brièvement au démarrage. `:haptics="false"` désactive cette vibration ;
un objet ajoute des vibrations à l'entrée dans une cible, au dépôt ou en cas de refus :

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Seuls les glissements tactiles vibrent, et Safari sur iOS ne peut pas vibrer du tout.

## Mouvement réduit {#reduced-motion}

Avec `prefers-reduced-motion: reduce`, les animations propres à la bibliothèque ne s'exécutent pas.
Vos fonctions d'animation, elles, s'exécutent toujours, avec `reducedMotion: true`. Voir
[Animations](/docs/guides/animations).

## Déplacer sans glisser {#moving-without-dragging}

Certaines personnes ne peuvent pas du tout faire glisser. Le critère WCAG 2.5.7 demande un moyen de
déplacer les items par simples clics, par exemple avec des boutons « Monter ».
`@vue-dnd-kit/actions` fait de chacun de ces clics un vrai déplacement :

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` exécute un glissement au clavier du début à la fin : il est annoncé, passe par
`onBeforeDrop` et `onDrop`, s'anime, et garde le focus sur l'item. Il se résout à `true` quand le
dépôt a abouti. `index` compte les places sans l'item lui-même : « descendre » correspond donc à
`index + 1`. Plus de détails dans
[Capteurs et glissements programmatiques](/docs/guides/sensors#programmatic-drags).
