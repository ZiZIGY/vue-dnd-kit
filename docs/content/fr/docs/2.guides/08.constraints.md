Changez l'axe, la grille et les limites, puis faites glisser une note. Le tableau fixe les règles
de chaque glissement qui commence sur lui, et chaque note reste là où vous la déposez.

::example{name="constraints" hint="Changez les règles, puis faites glisser une note" height="26rem"}
::

## Verrouiller un axe {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` ne déplace qu'horizontalement, `'y'` que verticalement. `makeDraggable`,
`makeSortableList`, `makeSortableTree`, `makeSortableItem` et `makeDragArea` l'acceptent tous.

- Le verrouillage s'applique **après tous les modificateurs** : il tient donc quoi qu'ils fassent.
  Un alignement ou une limite ne peut pas faire sortir l'item de sa ligne.
- L'`axis` propre à un item l'emporte sur celui de sa liste ou de son arbre, et celui d'un élément
  déplaçable (ou de sa liste) l'emporte sur celui de sa zone de glissement.
- Il est lu au début d'un glissement, si bien qu'un getter peut l'activer ou le désactiver :
  `axis: () => (locked.value ? 'y' : undefined)`.
- Un arbre verrouillé sur `'y'` s'imbrique quand même : la profondeur vient alors du survol du
  milieu d'une ligne.

::tip
Préférez `axis` aux modificateurs `restrictToVerticalAxis` et `restrictToHorizontalAxis`. Ils font
la même chose, mais, comme ce sont des modificateurs ordinaires, ils s'exécutent au milieu de la
chaîne, et un modificateur placé après eux (une grille qui aligne les deux axes) peut de nouveau
faire sortir l'item de l'axe.
::

## Modificateurs {#modifiers}

Un modificateur ajuste le décalage du glissement à chaque frame. Son résultat déplace l'overlay
**et** constitue le point où les cibles sont recherchées : une liste trie donc selon la position
verrouillée, limitée ou alignée.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Modificateur | Ce qu'il fait |
| --- | --- |
| `restrictToVerticalAxis` | Ne déplace que verticalement. Préférez `axis: 'y'`. |
| `restrictToHorizontalAxis` | Ne déplace qu'horizontalement. Préférez `axis: 'x'`. |
| `restrictToWindowEdges` | Garde l'overlay à l'intérieur de la fenêtre. |
| `restrictToParent` | Garde l'overlay à l'intérieur du conteneur où le glissement a commencé : la liste triable, ou l'élément parent d'un élément déplaçable simple. |
| `restrictToElement(target)` | Garde l'overlay à l'intérieur d'un élément : une ref de template, un getter ou l'élément lui-même. |
| `restrictToFirstScrollableAncestor` | Garde l'overlay à l'intérieur du premier ancêtre défilable de l'élément glissé. |
| `snapToGrid(size)` | Aligne l'overlay sur une grille (voir plus bas). |
| `snapCenterToCursor` | Centre l'overlay sous le pointeur au lieu de garder le décalage de la saisie. |

`modifiers` est une option du provider, des zones de glissement, des listes et des arbres, ainsi
que des éléments déplaçables et des items triables. Toutes, sauf celle du provider, acceptent aussi
une ref ou un getter, lus au début du glissement.

### Aligner sur une grille {#snap-to-a-grid}

`snapToGrid(24)` aligne les deux axes sur des cellules de 24 px. Un objet permet d'en régler
davantage :

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Option | Signification |
| --- | --- |
| `x`, `y` | La taille de cellule en pixels, par axe. |
| `origin` | `'container'` (par défaut) : le coin supérieur gauche de l'overlay atterrit sur des lignes de grille tracées depuis le coin supérieur gauche du conteneur — la liste triable, ou le parent d'un élément déplaçable simple. `'delta'` : c'est le décalage lui-même qui est arrondi, si bien qu'un item qui a commencé hors de la grille y reste. |
| `smooth` | `true` ou `{ duration, easing }` : l'overlay glisse d'une cellule à l'autre (80 ms par défaut). Les cibles utilisent immédiatement la position alignée. |

### Votre propre modificateur {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

Un modificateur reçoit `transform`, le décalage depuis le début du glissement tel que l'ont laissé
les modificateurs précédents, et en renvoie un nouveau. Il reçoit aussi ce dont il peut avoir
besoin pour le calculer : `activeRect` (l'élément glissé au début), `overlayRect` (l'overlay
déplacé de `transform`), `containerRect`, `windowRect`, `origin` (le pointeur au début), `active` et
`over`. Voir [Modificateurs](/docs/api/modifiers).

## L'ordre {#the-order}

Les modificateurs venant de plusieurs endroits s'exécutent l'un après l'autre, chacun à partir du
résultat du précédent :

1. les `modifiers` du provider ;
2. les `modifiers` de la zone de glissement où le glissement a commencé ;
3. les `modifiers` propres à l'item glissé ou, s'il n'en a pas, ceux de sa liste ou de son arbre ;
4. le `restrictToArea` de la zone de glissement ;
5. le verrouillage d'`axis`.

Les `modifiers` d'un item **remplacent** ceux de sa liste ; ils ne s'y ajoutent pas. Les limites de
la zone viennent après l'alignement des étapes 1 à 3 : un item aligné reste donc à l'intérieur, et
le verrouillage d'axe vient en tout dernier.

## Les listes limitées gardent leurs extrémités {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

Une limite retient l'overlay au bord de la boîte pendant que le pointeur continue. Dès que le
pointeur a quitté l'overlay le long de l'axe de la liste, la liste trie selon le pointeur : la
première et la dernière place restent ainsi accessibles, quelle que soit la façon dont vous tenez
l'item. Les grilles continuent de trier selon l'overlay : retenu au bord, il recouvre déjà la
cellule du bord.

## Des règles pour une partie de la page {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` fixe les règles des glissements qui **commencent à l'intérieur** de son élément —
éléments déplaçables simples comme items triables. Gardez un seul `DnDProvider` pour toute
l'application, et donnez à un tableau, un canevas ou un fil sa propre zone.

| Option | Ce qu'elle fait |
| --- | --- |
| `axis` | Verrouille les glissements sur un axe. L'`axis` propre à un élément déplaçable, ou celui de sa liste, l'emporte. |
| `modifiers` | S'exécutent après ceux du provider et avant ceux propres à l'élément déplaçable. |
| `restrictToArea` | `true` : les glissements restent à l'intérieur de l'élément de la zone. |
| `autoScroll` | Le défilement automatique du conteneur défilant de la zone (l'élément, ou son ancêtre défilable le plus proche). `false` le désactive à cet endroit. |
| `activation` | L'[activation](/docs/guides/sensors#activation-constraints) selon le type de pointeur. Celle propre à un élément déplaçable l'emporte ; celle du provider vient en dernier. |
| `disabled` | Aucun glissement ne commence dans la zone, ni dans les zones qu'elle contient. Ses éléments déplaçables indiquent `aria-disabled`. |

Chaque option accepte une valeur, une ref ou un getter, lus au début d'un appui ou d'un
glissement. La zone renvoie `isDragging` (un glissement commencé ici est en cours) et
`isAutoScrolling` (le défilement automatique fait défiler son conteneur). Référence complète :
[makeDragArea](/docs/api/make-drag-area).

### Comment les zones se combinent {#how-areas-combine}

- Un glissement suit la zone où il **a commencé**, même après l'avoir quittée. Passer au-dessus
  d'une zone ne change rien, sauf son `autoScroll` : celui-ci s'applique à tout glissement qui fait
  défiler son conteneur.
- Les zones imbriquées ne fusionnent pas : la plus proche l'emporte. `disabled` fait exception, et
  il est hérité : une zone désactivée désactive aussi les zones qu'elle contient.
- La détection de collision, les touches du clavier et les annonces restent à l'échelle du
  provider.

::note
Pourquoi pas un second `DnDProvider` autour du tableau ? Les providers sont indépendants : un
glissement ne passe jamais de l'un à l'autre, et les items du tableau ne pourraient donc jamais en
sortir. N'imbriquez un provider que lorsqu'une partie de la page a besoin de ses propres réglages à
l'échelle du provider et que ses items restent à l'intérieur. Voir [Le provider](/docs/guides/provider).
::

## Le laisser là où il est déposé {#leave-it-where-its-dropped}

Le tableau de l'exemple est aussi une cible de dépôt, et chaque note garde la place où elle a été
déposée. Chaque événement de glissement transporte `position` : le coin supérieur gauche de la
boîte glissée dans la cible, depuis le bord de son padding et défilement compris — le `left` et le
`top` qui placent un item positionné en absolu exactement à cet endroit. Il est calculé après les
modificateurs : une note alignée atterrit donc sur la grille.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

Plus de détails sur le glissement libre et les cibles de dépôt dans
[Glisser-déposer](/docs/guides/drag-and-drop).
