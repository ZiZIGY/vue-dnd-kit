Во время драга за указателем следует блок — **оверлей**. Сам перетаскиваемый элемент остаётся
на месте в виде слота, в который он приземлится. При броске оверлей летит в этот слот и исчезает.

Оверлей телепортируется в `body`, за пределы ваших компонентов. По умолчанию он показывает клон
перетаскиваемого элемента.

::example{name="overlay" hint="Перетащите письмо: копия получает фон входящих" height="24rem"}
::

## Клон по умолчанию {#the-default-clone}

Клон снимается в момент захвата, до того как что-либо сдвинется. Это глубокая копия элемента:

- Значения полей формы и пиксели `<canvas>` копируются.
- Вычисленные стили, которые элемент потерял бы вне своего списка, встраиваются инлайн:
  унаследованные шрифты и цвета, стили, которые срабатывают через предков (`.list li { … }`),
  ширины ячеек таблицы. Строка таблицы приходит обёрнутой в собственную таблицу.
- Атрибуты `id` и `data-dnd-*` удаляются, а клон получает `aria-hidden`.
- Рябь и другие эффекты нажатия из UI-китов (Vuetify, Quasar, PrimeVue, Naive UI) не
  копируются.

Всё остальное, что не должно ехать вместе с клоном, пометьте **`data-dnd-no-clone`**: кнопку
меню, подсказку, бейдж.

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### Фон не угадывается {#backgrounds-arent-guessed}

Клон показывает элемент как есть. Строка без собственного фона, потому что её закрашивает список
(`<li>` в белом `<ul>`, `v-list-item`, строка таблицы), даёт **прозрачный** клон. Задайте ей фон
списка в CSS:

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

Клон сохраняет классы и атрибуты элемента, включая scope-атрибут Vue, поэтому правило работает
и в scoped-стилях строки, и в глобальной таблице стилей. Другой выход — фон на самой строке.
Иконки и плитки, которые должны парить, как иконки приложений в
[сортируемых списках](/docs/guides/sortable-lists), прозрачны намеренно.

## Стилизация блока {#styling-the-box}

Блок — это элемент с `data-dnd-overlay`. У него `position: fixed` и `pointer-events: none`, а
значение атрибута говорит, что он делает:

| `data-dnd-overlay` | Когда |
| --- | --- |
| `"dragging"` | Он следует за указателем. |
| `"dropping"` | Он приземляется на свой слот, улетает обратно или ждёт асинхронного `onBeforeDrop`. |

Приподнятый вид во время драга, который исчезает при приземлении:

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## Компоненты оверлея {#overlay-components}

Чтобы показать что-то другое вместо клона, передайте компонент. Он рендерится внутри блока:

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | Что содержит |
| --- | --- |
| `active` | Драг (`id`, `ids`, `data`, `type`, …). |
| `items` | Все перетаскиваемые элементы, взятый — первым: `{ id, item, data, type }`. Для драгов из сортируемых списков `item` — элемент списка. |
| `over` | Цель под драгом или та, на которую он приземляется при броске. `null`, если под драгом ничего нет, и пока отменённый драг летит обратно. |
| `accepted` | Принимает ли `over` драг: окрасьте оверлей в красный, если нет. |
| `status` | `'dragging'` или `'dropping'`. |
| `mode` | `'move'`, `'copy'`, `'swap'` или `'insert'`. |

Компонент можно передать как есть или в `shallowRef`, чтобы переключать его. Никогда не кладите
его в глубокий `ref` или `reactive`: Vue сделает компонент реактивным и выдаст предупреждение.

Сетка приложений из [сортируемых списков](/docs/guides/sortable-lists) использует такой
компонент: иконка едет одна и приподнимается, а название остаётся на месте.

::example{name="lists" hint="Перетащите иконку приложения: её оверлей — компонент" height="28rem"}

## Слот `#overlay` провайдера {#the-providers-overlay-slot}

Для каждого драга без собственного компонента оверлей рендерит слот провайдера:

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

Слот получает те же пропсы, что и компонент оверлея. Когда он ничего не рендерит (`v-if`
выше), драг возвращается к клону.

## Что важнее {#what-wins}

Для каждого драга — первое, что подходит:

1. Собственный `overlay` элемента (`makeSortableItem`, `makeDraggable`).
2. `overlay` его списка или дерева.
3. Слот `#overlay` провайдера, если он что-то рендерит.
4. Клон по умолчанию. При мульти-драге — колонка или стопка клонов: см.
   [мульти-драг](/docs/guides/multi-drag#the-default-overlay).

Компонент выбирается в начале драга и сохраняется на весь драг, в том числе над другими
списками.

## `DragPreview`: клон в вашей раскладке {#dragpreview-the-clone-in-your-layout}

`DragPreview` рендерит библиотечный клон одного перетаскиваемого элемента. Используйте его в
компоненте оверлея, который сам раскладывает несколько элементов или добавляет рамку вокруг
клона:

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

Клоны есть у взятого элемента и не более чем у четырёх соседних с ним; для любого другого
элемента `DragPreview` рендерит свой слот по умолчанию. Стопка превью — в разделе
[мульти-драг](/docs/guides/multi-drag#a-custom-overlay-for-several-items).

## Размер: `overlayFit` {#size-overlayfit}

| `overlayFit` (провайдер) | Блок |
| --- | --- |
| `'slot'` (по умолчанию) | Принимает размер слота, в который приземлится. Над списком более широких карточек он расширяется. |
| `'source'` | Сохраняет размер перетаскиваемого элемента. |

С `'slot'` блок меняет размер вокруг указателя, который остаётся в той же доле блока.
Содержимое никогда не масштабируется: оно заново раскладывается под новый размер.

Бросок при любой настройке работает одинаково: блок летит к элементу, на который приземляется, и
анимируется к **его** размеру, а содержимое по пути заново раскладывается. Если элемент выглядит
по-разному в двух списках (компактный чип в палитре, полная карточка на доске), клон источника
раскладывается под размер цели и может выглядеть там сжатым или растянутым. Два способа этого
избежать:

- Дайте элементу **одинаковый вид** во всех списках, куда он может приземлиться. У файлов в
  [drag and drop](/docs/guides/drag-and-drop) один фиксированный размер в каждой папке, так что
  бросок их только перемещает.
- Рендерите **вид цели** в компоненте оверлея. Он получает `over`, поэтому может переключаться
  на вид того списка, над которым находится, и заполняет блок при любом размере.

Фиксированный размер корня компонента оверлея сохраняется внутри блока. Задайте корню
`width: 100%; height: 100%`, чтобы он следовал за блоком.

## Где он рендерится: `overlayTo` {#where-it-renders-overlayto}

Провайдер телепортирует оверлей в `body`. Внутри `<dialog>`, открытого через `showModal()`, или
shadow root оверлей оказался бы под верхним слоем или вне стилей. Укажите в `overlayTo` селектор
или элемент там:

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## Без оверлея {#no-overlay}

У `makeDraggable(el, { overlay: false })` блока нет совсем: двигается сам элемент, через
возвращаемый `transform`. См. [drag and drop](/docs/guides/drag-and-drop#without-an-overlay).
Как блок приземляется, задаёт `dropAnimation` провайдера: см.
[анимации](/docs/guides/animations).
