## Один провайдер на приложение {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Поставьте один `DnDProvider` повыше, в `App.vue` или в лейаут, и забудьте о нём. Каждый
композабл (`makeSortableList`, `makeDraggable`, `useDnD`…) ищет ближайший провайдер над
компонентом, в котором он вызван.

::warning
Композабл должен вызываться в компоненте, **отрендеренном внутри** провайдера. Вызов в
компоненте, чей собственный шаблон содержит `<DnDProvider>`, бросает ошибку
`No <DnDProvider> found above this component`: `inject` во Vue видит только предков.
::

## За что он отвечает {#what-it-owns}

| Часть | Что делает провайдер |
| --- | --- |
| Ввод | Превращает ввод указателем, касанием и с клавиатуры в драги (`sensors`), по одному за раз. |
| Поиск цели | Проверяет, какие цели под драгом (`collision`), и сообщает им об этом. |
| Оверлей | Рендерит блок, который следует за указателем, телепортирует его в `body` и приземляет при броске. |
| Выделение | Один набор выделенных id, общий для всех списков и перетаскиваемых элементов под ним. |
| Автоскролл | Прокручивает контейнеры и окно, когда драг приближается к их краям. |
| Live-регион | Сообщает скринридерам о захватах, перемещениях, бросках и отменах. |

Больше он ничего не рендерит: ваша разметка остаётся как есть.

## Опции вкратце {#options-at-a-glance}

У каждой опции есть рабочее значение по умолчанию, так что обычно провайдер обходится без них.

| Проп | По умолчанию | Что задаёт |
| --- | --- | --- |
| `collision` | `pointerFirst` | Как выбирается цель под драгом. |
| `modifiers` | `[]` | Правила движения для каждого драга (привязка, ограничение, …). |
| `animation` / `dropAnimation` | включено | Сдвиг элементов при сортировке / приземление оверлея. |
| `animate` | выключено | Значение по умолчанию для списков и деревьев: анимировать изменения данных, сделанные не драгом. |
| `autoScroll` | включено | Прокрутка у краёв: `{ threshold, maxSpeed, acceleration }` или `false`. |
| `activation` | мышь 4 px, касание 200 мс | Когда нажатие становится драгом, для каждого типа указателя. |
| `keyboard` | Space / Enter, Escape | Клавиши и шаг; `false` выключает перетаскивание с клавиатуры. |
| `sensors` | указатель + клавиатура | Что превращает ввод в драги. |
| `haptics` | короткая вибрация при захвате касанием | Вибрация при перетаскивании касанием, или `false`. |
| `copyModifier` | `'Alt'` | Клавиша, которая, если держать её во время драга, превращает перемещение в копирование (списку нужен `clone`). |
| `overlayTo` | `'body'` | Куда телепортируется оверлей. |
| `overlayFit` | `'slot'` | Размер оверлея: как у слота, в который он приземлится, или как у источника. |
| `announcements` | встроенные | Тексты для скринридеров, или `false`. |
| `defaultStyles` | `true` | Внедряет CSS с нулевой специфичностью для состояний драга. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

Полный список со всеми формами значений — в [API DnDProvider](/docs/api/dnd-provider). Ещё
провайдер испускает `drag-start`, `drag-move`, `drag-over`, `drag-end` и `drag-cancel` — те же
события, что слышит `useDnDMonitor`.

::tip
Правилам для одной части страницы (доска с привязкой к сетке, лента, которая прокручивается
только по вертикали) не нужен свой провайдер: оберните эту часть в
[область перетаскивания](/docs/guides/constraints).
::

## Чтение драга: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Перетащите задачу и следите за состоянием" height="22rem"}
::

`useDnD()` возвращает драг в виде реактивного состояния в любом компоненте под провайдером:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Поле | Что содержит |
| --- | --- |
| `status` | `'idle'`, `'activating'` (идёт долгое нажатие), `'dragging'`, `'dropping'` (приземление или ожидание асинхронного `onBeforeDrop`), `'selecting'` (рамка выделения). |
| `active` | Что перетаскивается: `id`, `ids` (все перетаскиваемые id, взятый первым), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` в покое. |
| `over` | Цель под драгом: `id`, `data`, `element`, `rect` и `accepted`. `null`, если под драгом ничего нет. |
| `pointer` | Указатель в координатах вьюпорта, после модификаторов. |
| `activation.progress` | От `0` до `1`, пока идёт долгое нажатие: нарисуйте по нему кольцо. |
| `isAutoScrolling` | Автоскролл что-то прокручивает. |
| `selection` | Выделение провайдера: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. См. [мульти-драг](/docs/guides/multi-drag). |
| `cancel()` | Отменяет текущий драг (элементы улетают обратно), идущее долгое нажатие или рамку выделения. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

Как только бросок решён, `active`, `over` и `pointer` возвращают `null`, даже пока оверлей ещё
приземляется (`status` остаётся `'dropping'`). Интерфейс, построенный на них, никогда не покажет
старый драг рядом с новыми данными. Пока ждёт асинхронный `onBeforeDrop`, состояние остаётся
таким, каким было в момент отпускания.

## Подписка на все драги: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

Монитор слышит каждый драг под своим провайдером, где бы тот ни начался. Он отключается, когда
вызвавший его компонент размонтируется.

| Событие | Когда |
| --- | --- |
| `onDragStart` | Драг начинается. |
| `onDragMove` | Драг движется. |
| `onDragOver` | Меняется цель под драгом. |
| `onBeforeDrop` | Драг отпущен. Ответ решает судьбу броска: см. [решения о броске](/docs/guides/drop-decisions). |
| `onDragEnd` | Бросок состоялся. Сортируемые списки уже вызвали свой `onDrop` и записали новый порядок. `dropped` равен `false`, если драг закончился не над целью. |
| `onDragCancel` | Escape, бросок на цель, которая его отклоняет, или `onBeforeDrop`, ответивший `'reject'`. |
| `onDragResume` | `onBeforeDrop` ответил `'continue'`: ничего не брошено, и драг продолжается. |

Каждое событие несёт `active`, `over`, `pointer`, `delta` (смещение от начала),
`position` (где перетаскиваемый блок находится внутри `over`, см.
[drag and drop](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) и, для элементов
сортируемого списка, `source`. Полные формы — в [API событий](/docs/api/events).

::note
`onDragEnd` — место для работы «после броска»: сохранения, сброса выделения, аналитики.
Собственный `onDrop` списка выполняется **до** записи, поэтому он ещё видит старый порядок.
::

## Несколько провайдеров {#several-providers}

Большинству приложений нужен ровно один. Второй провайдер имеет смысл только для части страницы,
которой нужны свои настройки уровня провайдера (определение цели, клавиши, объявления) и чьи
элементы никогда её не покидают:

- Провайдеры независимы: драг никогда не переходит из одного в другой.
- Вложенные провайдеры допустимы. **Побеждает ближайший владелец**: элемент принадлежит
  ближайшему провайдеру над ним, а внешний провайдер его игнорирует.
- У каждого провайдера своё выделение, свой оверлей и свой live-регион.

Если элементы не переносятся между двумя частями страницы, проверьте, не стоят ли они под
двумя разными провайдерами.

::tip
Приложение, смонтированное в другом месте, внутри shadow root или как отдельное Vue-приложение,
может подключиться к существующему провайдеру: передайте `useDnDContext()` в
`provideDnDContext(app, context)` перед монтированием.
::

## SSR и Nuxt {#ssr-and-nuxt}

Провайдер безопасен для SSR. Списки и элементы рендерятся на сервере, как любая другая разметка.
Оверлей и live-регион телепортируются и монтируются только на клиенте, поэтому никогда не
вызывают рассинхронизацию гидрации. Id по умолчанию берутся из `useId()` во Vue и совпадают на
сервере и клиенте.

В Nuxt модуль регистрирует `DnDProvider` глобально и автоимпортирует композаблы: см.
[установку](/docs/getting-started/installation#nuxt).
