## Один провайдер на приложение {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Поставьте один `DnDProvider` повыше, в `App.vue` или в лейаут, и забудьте о нём. Каждый
композабл (`makeSortableList`, `makeDraggable`, `useDnD`…) ищет ближайший провайдер над
компонентом, в котором он вызван.

::warning
Композабл должен вызываться в компоненте, **отрендеренном внутри** провайдера. Вызов в
компоненте, чей собственный шаблон содержит `<DnDProvider>`, бросает ошибку
`No <DnDProvider> found above this component`: `inject` во Vue видит только предков.
::

## За что он отвечает {#what-it-owns}

| Часть | Что делает провайдер |
| --- | --- |
| Ввод | Превращает ввод указателем, касанием и с клавиатуры в драги (`sensors`, `activation`), по одному за раз. |
| Поиск цели | Проверяет, какие цели под драгом (`collision`), и сообщает им об этом. |
| Оверлей | Рендерит блок, который следует за указателем, телепортирует его в `body` и приземляет при броске. |
| Выделение | Один набор выделенных id, общий для всех списков и перетаскиваемых элементов под ним. |
| Автоскролл | Прокручивает контейнеры и окно, когда драг подходит к их краям. |
| Live-регион | Озвучивает для скринридеров захват, перемещения, бросок и отмену. |

Больше он ничего не рендерит: ваша разметка остаётся как есть.

## Опции вкратце {#options-at-a-glance}

У каждой опции есть рабочее значение по умолчанию, так что обычно провайдеру не передают
ничего. Провайдер читает пропсы тогда, когда они ему нужны: демо ниже переключают
`collision`, `activation` и `autoScroll` на лету.

| Проп | По умолчанию | Что задаёт |
| --- | --- | --- |
| `collision` | `pointerFirst` | Как выбирается цель под драгом. [Ниже](#finding-the-target). |
| `activation` | мышь 4 px, касание 200 ms | Когда нажатие становится драгом, для каждого типа указателя. [Ниже](#when-a-press-becomes-a-drag). |
| `autoScroll` | включён | Прокрутка у краёв: `{ threshold, maxSpeed, acceleration }` или `false`. [Ниже](#auto-scroll). |
| `haptics` | короткая вибрация при захвате касанием | Вибрации для драгов касанием, или `false`. [Ниже](#haptics-and-the-copy-key). |
| `copyModifier` | `'Alt'` | Клавиша, которая, если её держать во время драга, превращает перемещение в копирование. |
| `modifiers` | `[]` | Правила движения для каждого драга: см. [ограничения](/docs/guides/constraints). |
| `animation` / `dropAnimation` | включены | Скольжение элементов при сортировке / приземление оверлея: см. [анимации](/docs/guides/animations). |
| `animate` | выключен | Значение по умолчанию для списков и деревьев: анимировать изменения данных, сделанные не драгом. |
| `keyboard` | Space / Enter, Escape | Клавиши и шаг клавиатуры; `false` отключает перетаскивание с клавиатуры. См. [доступность](/docs/guides/accessibility#the-keyboard). |
| `sensors` | указатель + клавиатура | Что превращает ввод в драги: см. [сенсоры](/docs/guides/sensors). |
| `overlayTo` | `'body'` | Куда телепортируется оверлей. |
| `overlayFit` | `'slot'` | Размер оверлея: слота, в который он приземлится, или исходного элемента. См. [оверлей](/docs/guides/overlay). |
| `overlayTransition` | кроссфейд | Как оверлей меняется с одного компонента на другой посреди драга: `false` или пропсы `<Transition>`. См. [цели, которые меняют оверлей](/docs/guides/overlay#targets-that-change-the-overlay). |
| `announcements` | встроенные | Тексты для скринридеров, или `false`. |
| `screenReaderInstructions` | встроенный | Текст, на который каждый перетаскиваемый элемент ссылается через `aria-describedby`. |
| `defaultStyles` | `true` | Внедряет CSS с нулевой специфичностью для состояний драга: см. [стилизацию](/docs/guides/styling). |

Полный список со всеми формами — в [API DnDProvider](/docs/api/dnd-provider). Провайдер также
эмитит `drag-start`, `drag-move`, `drag-over`, `drag-end` и `drag-cancel` — те же события,
что слышит `useDnDMonitor`.

## Читайте драг: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Перетащите задачу и следите за состоянием" height="27rem"}
::

`useDnD()` возвращает драг как реактивное состояние в любом компоненте под провайдером:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Поле | Что в нём |
| --- | --- |
| `status` | `'idle'`, `'activating'` (нажатие ждёт активации), `'dragging'`, `'dropping'` (приземление или ожидание асинхронного `onBeforeDrop`), `'selecting'` (рамка выделения). |
| `active` | Что перетаскивается: `id`, `ids` (все перетаскиваемые id, взятый первым), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` в простое. |
| `over` | Цель под драгом: `id`, `data`, `element`, `rect` и `accepted`. `null`, если под драгом ничего нет. |
| `pointer` | Указатель в координатах вьюпорта, после модификаторов. |
| `activation.progress` | От `0` до `1`, пока нажатие ждёт активации: рисуйте по нему кольцо. |
| `isAutoScrolling` | Автоскролл что-то прокручивает. |
| `selection` | Выделение провайдера: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. См. [мульти-драг](/docs/guides/multi-drag). |
| `cancel()` | Отменяет текущий драг (элементы летят обратно), заряжающееся нажатие или рамку выделения. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

Как только решение о броске принято, `active`, `over` и `pointer` читаются как `null`, даже
пока оверлей ещё приземляется (`status` остаётся `'dropping'`). UI, построенный на них, никогда
не показывает старый драг рядом с новыми данными. Пока ждёт асинхронный `onBeforeDrop`,
состояние остаётся таким, каким было в момент отпускания.

## Слушайте каждый драг: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

Монитор слышит каждый драг под своим провайдером, где бы тот ни начался: панель выше
записывает драги списка, не импортируя его. Монитор останавливается, когда размонтируется
компонент, который его вызвал.

| Событие | Когда |
| --- | --- |
| `onDragStart` | Драг начинается. |
| `onDragMove` | Драг движется. |
| `onDragOver` | Меняется цель под драгом. |
| `onBeforeDrop` | Драг отпущен. Его ответ решает судьбу броска: см. [решение о броске](/docs/guides/drop-decisions). |
| `onDragEnd` | Бросок состоялся. Сортируемые списки уже выполнили свой `onDrop` и записали новый порядок. `dropped` равен `false`, если драг закончился не над целью. |
| `onDragCancel` | Escape, бросок на цель, которая его отклоняет, или `onBeforeDrop`, ответивший `'reject'`. |
| `onDragResume` | `onBeforeDrop` ответил `'continue'`: ничего не брошено, и драг продолжается. |

Каждое событие несёт `active`, `over`, `pointer`, `delta` (смещение от начала),
`position` (где перетаскиваемый блок находится в `over`, см.
[drag and drop](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) и, для элементов
из сортируемого списка, `source`. Полные формы — в [API событий](/docs/api/events).

::note
`onDragEnd` — место для работы «после броска»: сохранения, сброса выделения, аналитики.
Собственный `onDrop` списка выполняется **до** его записи, поэтому видит ещё старый порядок.
::

## Поиск цели {#finding-the-target}

Выберите функцию, затем перетащите булавку или карточку над целями. Бейджи показывают, как
функция ранжирует их на этом кадре; зелёная — цель.

::example{name="collision-lab" hint="Переключите функцию, перетащите над вложенными, маленькими и перекрывающимися целями" height="33rem"}
::

На каждом кадре драга провайдер передаёт `collision` цели в игре, а она возвращает их id,
лучшие первыми. В библиотеке пять функций:

| Функция | Ранжирует | Подходит для |
| --- | --- | --- |
| `pointerFirst` | То, что под указателем; если там ничего нет — то, что перекрывает перетаскиваемый блок. | По умолчанию: точно под указателем, снисходительно в промежутках. |
| `pointerWithin` | Только то, что под указателем, самые внутренние первыми. | Точных целей: бросок в промежуток никуда не попадает. |
| `rectIntersection` | Все цели, которые перекрывает перетаскиваемый блок: выше `priority`, затем глубже вложенность, затем больше перекрытие. | Больших элементов над маленькими целями, когда указатель у края элемента. |
| `closestCenter` | Все цели, по расстоянию от центра блока до их центров. | Случаев, когда кто-то должен победить всегда, даже издалека: сеток и списков из элементов одного размера. |
| `closestCorners` | Все цели, по расстояниям между четырьмя углами. | Колонок, стоящих рядом (канбан), целей очень разной высоты. |

Под указателем проверка попадания учитывает то, что видит пользователь: из перекрывающихся
целей попадает только верхняя (`front`, никогда `back` там, где они перекрываются), а из
вложенных первой идёт самая внутренняя (`subfolder`, затем `folder`).

### Своя функция {#a-function-of-your-own}

```ts [magnet.ts]
import type { CollisionDetection, Coordinates, Rect } from '@vue-dnd-kit/core';

/** How far the point is from the rect: 0 inside it. */
const gap = (rect: Rect, point: Coordinates) =>
  Math.hypot(
    Math.max(rect.left - point.x, 0, point.x - rect.right),
    Math.max(rect.top - point.y, 0, point.y - rect.bottom),
  );

/** What is under the pointer; in a gap, the nearest target within 40px. */
export const magnet: CollisionDetection = ({ hits, pointer, candidates }) => {
  if (hits.length) return hits;
  return candidates
    .filter((candidate) => gap(candidate.rect, pointer) <= 40)
    .sort((a, b) => gap(a.rect, pointer) - gap(b.rect, pointer))
    .map((candidate) => candidate.id);
};
```

| Аргумент | Что в нём |
| --- | --- |
| `pointer` | Указатель, после модификаторов. |
| `overlayRect` | Перетаскиваемый блок в том виде, в каком он показан; `null` без оверлея. |
| `candidates` | Все цели в игре: `id`, `rect` (его видимая часть, обрезанная скролл-контейнерами), `priority`, `depth` (`0` на верхнем уровне, больше при вложенности). |
| `hits` | Цели под указателем, по результатам проверки попадания, лучшие первыми. |

Верните пустой массив, чтобы сказать «цели нет». Отключённые цели, цели внутри
перетаскиваемых элементов и цели, скрытые своими скролл-контейнерами, в функцию не попадают.
Цель, которая отклоняет драг, всё равно участвует: над ней `over.accepted` равен `false`, и
бросок отклоняется (цель внутри сортируемого элемента вместо этого уступает, чтобы список
сортировался над ней). Демо оборачивает выбранную функцию, чтобы записать её ранжирование:
`(args) => (ranked.value = detect(args))`.

::note
Провайдер гасит переключения, которые запрашивает функция. Цель, которую драг только что
покинул, не может снова победить, пока указатель не сдвинется на 10 px, поэтому границы не
мерцают. Между целями, вложенными в одного родителя (промежутки колонки карточек), остаётся
последняя цель.
::

## Когда нажатие становится драгом {#when-a-press-becomes-a-drag}

Нажатие не начинает драг сразу. `activation` задаёт для каждого типа указателя (`mouse`,
`touch`, `pen`), чего оно ждёт: расстояния `distance` в px, задержки `delay` в ms (с допуском
`tolerance`, за которым нажатие сдаётся, чтобы страница могла прокручиваться) или того, что
наступит раньше.

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 300, tolerance: 8 } }">
```

| Указатель | По умолчанию |
| --- | --- |
| `mouse`, `pen` | `{ distance: 4 }`: клик остаётся кликом. Нажатие мышью на `handle` начинает драг сразу. |
| `touch` | `{ delay: 200, tolerance: 5 }`: долгое нажатие, чтобы списки продолжали прокручиваться под пальцем. |

Тип, который вы не указали, сохраняет значение по умолчанию. Собственная `activation`
перетаскиваемого элемента важнее, чем у [области перетаскивания](/docs/guides/constraints), а
та — важнее, чем у провайдера. Пока нажатие ждёт, `useDnD().status` равен `'activating'`, а
`activation.progress` идёт от `0` до `1`; Escape или `useDnD().cancel()` отменяет его.
Попробуйте условия вживую и нарисуйте по прогрессу кольцо долгого нажатия в
[сенсорах](/docs/guides/sensors#activation-constraints).

## Автоскролл {#auto-scroll}

Перетащите канал к верху или к низу списка. Зелёные полосы — краевые зоны: чем глубже в
зону, тем быстрее прокручивается список.

::example{name="auto-scroll-edges" hint="Перетащите канал в зелёные полосы" height="37.5rem"}
::

Любой элемент с `overflow: auto` или `scroll` прокручивается сам, как и окно. Провайдер
сначала прокручивает контейнер под указателем, затем его предков, затем окно.

| Опция | По умолчанию | Что задаёт |
| --- | --- | --- |
| `threshold` | `0.2` | Краевая зона как доля размера контейнера, от 24 до 96 px. |
| `acceleration` | `10` | Скорость у самого края, в px за кадр. Она растёт с квадратом глубины в зоне, поэтому начало медленное и точное. |
| `maxSpeed` | `25` | Максимальная скорость. За краем (указатель вне контейнера) скорость продолжает расти до неё. |

`:auto-scroll="false"` отключает его. Направление прокручивается, только когда указатель
сдвинулся в эту сторону, поэтому элемент, взятый у края, не прокручивает сам по себе.
Списки, деревья и [области перетаскивания](/docs/guides/constraints) принимают собственный
`autoScroll` для своего контейнера:

```ts
makeSortableList(list, { items: channels, autoScroll: { maxSpeed: 10 } });
```

Перетаскивание с клавиатуры никогда не использует автоскролл: вместо этого оно прокручивает
элемент в зону видимости. `isAutoScrolling` (из `useDnD()` или из области перетаскивания)
равен `true`, пока что-то прокручивается.

## Вибрация и клавиша копирования {#haptics-and-the-copy-key}

Драг касанием коротко вибрирует при старте. `:haptics="false"` отключает это; объект
задаёт каждую вибрацию:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

| Ключ | Вибрирует, когда | По умолчанию |
| --- | --- | --- |
| `start` | Долгое нажатие превращается в драг. | `true` (10 ms) |
| `enter` | Драг входит в цель, которая его принимает. | выключено |
| `drop` | Бросок состоялся. | выключено |
| `refuse` | Бросок отклонён, и элементы летят обратно. | выключено |

Каждый принимает `true` (шаблон по умолчанию), длительность в ms, шаблон «вкл/выкл» или
`false`. Вибрируют только драги, начатые касанием, а iOS Safari не умеет вибрировать вовсе.

`copyModifier` — клавиша, которая, если её держать во время драга между списками, превращает
перемещение в копирование: по умолчанию `'Alt'`, любой `KeyboardEvent.key` или `null`, чтобы
её не было. Списку, из которого берутся элементы, нужна функция `clone`; см.
[списки с общими элементами](/docs/guides/shared-lists).

## Несколько провайдеров {#several-providers}

Большинству приложений нужен ровно один. Поместите список желаний под собственный провайдер
и попробуйте перенести книгу: она не может покинуть свой провайдер, а внешний монитор
перестаёт слышать список желаний.

::example{name="provider-nested" hint="Перенесите книгу, затем дайте списку желаний собственный провайдер" height="33.5rem"}
::

```vue
<DnDProvider>
  <Shelf v-model="reading" />
  <DnDProvider>
    <Shelf v-model="wishlist" />
    <EventLog />            <!-- hears the inner provider's drags only -->
  </DnDProvider>
</DnDProvider>
```

- Провайдеры независимы: драг никогда не переходит из одного в другой.
- Вложенные провайдеры допустимы. **Побеждает ближайший владелец**: элемент принадлежит
  ближайшему провайдеру над ним, а внешний провайдер его игнорирует.
- У каждого провайдера своё выделение, оверлей, live-регион и мониторы.

Второй провайдер имеет смысл только для части страницы, которой нужны собственные настройки
на уровне провайдера (определение цели, клавиши клавиатуры, объявления) и элементы которой
никогда её не покидают. Если элементы не переносятся между двумя частями страницы,
проверьте, не стоят ли они под двумя провайдерами.

::tip
Правилам для одной части страницы (доска с привязкой к сетке, лента с более долгим нажатием
касанием, панель, где ничего не перетаскивается) собственный провайдер не нужен:

```ts
makeDragArea(board, { modifiers: [snapToGrid(20)], activation: { touch: { delay: 400 } } });
```

Элементы области остаются в провайдере приложения и по-прежнему могут перемещаться куда угодно.
См. [ограничения](/docs/guides/constraints).
::

Приложение, смонтированное в другом месте, внутри shadow root или как отдельное Vue-приложение,
может присоединиться к существующему провайдеру: передайте `useDnDContext()` в
`provideDnDContext(app, context)` перед монтированием. Проверка попадания и оверлей работают
через границы shadow root.

## SSR и Nuxt {#ssr-and-nuxt}

Провайдер безопасен для SSR. Списки и элементы рендерятся на сервере, как любая другая
разметка. Оверлей и live-регион телепортируются и монтируются только на клиенте, поэтому
никогда не вызывают рассинхронизацию гидрации. Id по умолчанию берутся из `useId()` Vue и
совпадают на сервере и клиенте.

В Nuxt модуль регистрирует `DnDProvider` глобально и автоимпортирует композаблы: см.
[установку](/docs/getting-started/installation#nuxt).
