Библиотека почти ничего не стилизует. Каждое состояние драга доходит до вас двумя путями: в виде
ref, который возвращает композабл, — для классов и условной разметки, и в виде атрибута
`data-dnd-*` — для обычного CSS.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## Возвращаемые ref {#the-returned-refs}

| Композабл | Состояние |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`: этот элемент — слот, в который приземлится перетаскиваемый элемент.
- `isDragging`: элемент участвует в драге (при мульти-драге — каждый перетаскиваемый элемент).
- `isAccepting`: что-то перетаскивается, и эта цель это принимает — подсветите места, куда
  возможен бросок.
- `isOver`: драг находится над этой целью, принимает она его или нет. `isOver && !isAccepting` —
  это отказ, и его стоит показать.
- `over.accepted` из `useDnD()` (`accepted` в пропсах оверлея) равен `false` над целью, которая
  отклоняет драг: окрасьте по нему оверлей в красный.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## Data-атрибуты {#the-data-attributes}

| Атрибут | На чём | Когда |
| --- | --- | --- |
| `data-dnd-placeholder` | элемент сортируемого списка | Он — слот, в который приземлится перетаскиваемый элемент. |
| `data-dnd-dragging` | элемент сортируемого списка | Его перетаскивают, но он остаётся на месте: остальные элементы мульти-драга в режиме `'gaps'`. |
| `data-dnd-dragging="pointer"` или `"keyboard"` | `<html>` | На протяжении всего драга. |
| `data-dnd-overlay="dragging"` или `"dropping"` | блок оверлея | Всегда. `dropping` — пока он приземляется и пока ждёт асинхронный `onBeforeDrop`. |
| `data-dnd-leaving` | копия, оставленная `animate` | Пока растворяется ушедший элемент. |
| `data-dnd-no-clone` | **ставите вы** | Исключает элемент из клона оверлея: подсказку, кнопку меню, бейдж. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## Стили по умолчанию {#default-styles}

Провайдер один раз на документ внедряет несколько правил. Они обёрнуты в `:where()`, поэтому их
специфичность нулевая, и любое ваше правило важнее:

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

Во время драга слот приглушён, страница не выделяет текст и не привязывает прокрутку, а при
драге указателем курсор — сжатая рука. `:default-styles="false"` выключает эти правила.
`cursor: grab` на перетаскиваемых элементах добавляете вы.

## Рецепты {#recipes}

### Пустой слот {#an-empty-slot}

Вместо приглушённой копии элемента покажите пустой блок с пунктирной рамкой там, где он
приземлится:

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

Псевдоэлемент закрывает содержимое, поэтому слот сохраняет точный размер элемента. Перетащите
карточку здесь, чтобы увидеть:

::

### Строка, которую закрашивает список {#a-row-the-list-paints}

Оверлей по умолчанию — клон перетаскиваемого элемента. Он показывает элемент как есть и не
угадывает фон: строка без собственного фона — `<li>` в белом `<ul>`, строка таблицы, элемент
списка из UI-кита — даёт прозрачный клон. Задайте ей фон списка:

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

Клон сохраняет классы и атрибуты элемента — в том числе атрибут scoped-стилей, — поэтому правило
работает в собственном `<style scoped>` строки, рядом с её остальными стилями. Или дайте строке
собственный фон. Иконки и плитки, которые должны парить, остаются прозрачными.

### Приподнятый оверлей, только во время драга {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

Тень есть, пока карточка едет, и исчезает, когда оверлей переключается в `dropping`, так что
карточка ложится в свой слот плоской. Для своего компонента оверлея то же правило нацеливается на
корень компонента — или читайте `status` из его пропсов.

### Уменьшение движения {#reduced-motion}

Библиотека уже останавливает свои анимации при `prefers-reduced-motion: reduce`. Сделайте то же
для переходов, которые вы добавляете вокруг драга:

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### Не делайте так {#dont}

- Не ставьте CSS `transition` на `transform` или `translate` элементов сортируемого списка:
  библиотека анимирует их сама и отменяет такие переходы, пока измеряет.
- Не анимируйте `height`, `margin` или `padding` строк в
  [виртуальном списке](/docs/guides/virtual-lists).
