## Выделение {#the-selection}

Каждый провайдер хранит одно выделение: реактивное множество id. Перетаскивание **выделенного**
элемента тащит все выделенные элементы, взятый — первым. Перетаскивание невыделенного элемента
тащит только его.

Библиотека не решает, как пользователи выделяют: правила кликов задаёте вы. Сама она выделение
тоже никогда не сбрасывает, и оно переживает размонтирование — например, строк, которые
переиспользует виртуальный список.

### Ctrl/Cmd-клик {#ctrlcmd-click}

Каждый элемент сортируемого списка и каждый перетаскиваемый элемент возвращает `selected` —
доступный для записи ref, связанный с выделением:

```vue [Shot.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ shot: { id: string } }>();
const el = useTemplateRef<HTMLElement>('el');
const { selected } = makeSortableItem(el, { item: () => props.shot });

const onClick = (event: MouseEvent) => {
  if (event.ctrlKey || event.metaKey) selected.value = !selected.value;
};
</script>

<template>
  <div ref="el" :class="{ selected }" @click="onClick">…</div>
</template>
```

Клик, которым заканчивается драг, не доходит до `@click`, поэтому бросок никогда случайно не
переключит выделение. Для действий над элементом используйте `@click`, а не `pointerup`.

### Из любого места: `useDnD().selection` {#from-anywhere-usedndselection}

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// A plain click selects only that item, Ctrl/Cmd-click adds or removes it:
const onClick = (event: MouseEvent, id: string) => {
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
};

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

Ключ выделения — id, поэтому в нём могут быть элементы нескольких списков: драг забирает все
выделенные элементы под провайдером.

## Выделение рамкой {#rubber-band-selection}

`makeSelectionArea` превращает элемент в область, где нажатие на пустом месте рисует рамку, и
элементы, которые она пересекает, выделяются:

```vue [Gallery.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSelectionArea } from '@vue-dnd-kit/core';
import PhotoGrid from './PhotoGrid.vue';

const area = useTemplateRef<HTMLElement>('area');
const { isSelecting, style } = makeSelectionArea(area);
</script>

<template>
  <div ref="area" class="area">
    <PhotoGrid />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.area {
  position: relative;   /* the band is absolutely positioned inside */
  min-height: 320px;    /* room around the items to start a band */
}

.band {
  border: 1px solid #42b883;
  background: color-mix(in srgb, #42b883 15%, transparent);
}
</style>
```

- Рамку рендерите вы: `style` размещает её относительно содержимого области.
- Области нужно **нестатическое позиционирование** (подойдёт `relative`), иначе рамка окажется в
  другом месте.
- Рамка начинается только с самой области, так что делайте область большой: целую панель с
  местом вокруг элементов, а не тесную обёртку. Галерея выше заполняет весь свой блок.
- Нажатие на элемент начинает его драг. Кнопки, поля и полоса прокрутки области сохраняют свои
  нажатия.
- Рамка остаётся привязанной к содержимому, пока прокручивается область или страница.
  :kbd{value="Escape"} отменяет её и восстанавливает выделение.
- Пока рисуется рамка, `useDnD().status` равен `'selecting'`.

| Опция | Что делает |
| --- | --- |
| `strategy` | `'toggle'` (по умолчанию): элементы, которые пересекает рамка, меняют состояние на противоположное. `'select'`: выделенными оказываются только элементы внутри рамки, поэтому клик по пустому месту снимает выделение с элементов области. |
| `modifier` | Клавиши, которые нужно держать, чтобы рисовать: `{ keys: ['Shift'], method: 'every' }` (или `'some'`). |
| `accept` | Какие перетаскиваемые элементы выделяет рамка: [правило accept](/docs/guides/drag-and-drop#which-drags-a-target-takes), которое сверяется с их `type`. |
| `disabled` | Рамки нет; включение отменяет уже рисуемую. |
| `onSelected(ids)` | Вызывается, когда рамка завершена, с выделением. |
| `selection` | Собственный `Ref<Set<Key>>` вместо выделения провайдера. |

Если области вложены друг в друга, нажатие забирает самая внутренняя. Все опции — в
[API makeSelectionArea](/docs/api/make-selection-area).

## Как двигаются остальные элементы: `multiple` {#how-the-other-items-move-multiple}

Список, в котором начинается мульти-драг, решает, что во время драга делают остальные
выделенные элементы:

```ts
makeSortableList(listRef, { items: tasks, multiple: 'gaps' });
```

| `multiple` | Во время драга | Оверлей |
| --- | --- | --- |
| `'group'` (по умолчанию) | Остальные элементы покидают свои места и едут вместе со взятым одним блоком слотов, так что список уже показывает результат броска. | Колонка до пяти перетаскиваемых элементов вдоль списка. |
| `'gaps'` | Остальные остаются на своих местах, полупрозрачными (`data-dnd-dragging`), до броска. | Такая же колонка. |
| `'stack'` | Остальные улетают в оверлей. | Взятый элемент со счётчиком. |

При броске элементы приземляются вместе на целевой индекс в том порядке, в котором были. В
`'group'` и `'gaps'` каждый элемент оверлея летит в свой слот.

### Оверлей по умолчанию {#the-default-overlay}

В `'group'` и `'gaps'` оверлей — это колонка перетаскиваемых элементов в том виде, как они
приземлятся: взятый под указателем, остальные до и после него в порядке броска (в
горизонтальных списках — ряд). Показывается до пяти элементов. Те, что не поместились,
подсчитываются там, где находятся: `+N` в начале колонки — для элементов, которые приземлятся
перед показанными, `+N` в конце — для тех, что после.

В сетках колонка целых ячеек закрыла бы страницу, поэтому оверлей — стопка: до трёх элементов
веером позади взятого и общий счётчик сверху.

Обычные перетаскиваемые элементы (`makeDraggable`) показывают взятый элемент со счётчиком.

### Разные типы {#mixed-types}

Когда у выделенных элементов разные типы, `acceptMode` цели определяет, должны подойти `'all'`
(по умолчанию) или `'some'` из них. См.
[списки с общими элементами](/docs/guides/shared-lists#limits) и
[drag and drop](/docs/guides/drag-and-drop#which-drags-a-target-takes).

## Свой оверлей для нескольких элементов {#a-custom-overlay-for-several-items}

Компоненты оверлея и слот `#overlay` провайдера получают `items`: все перетаскиваемые элементы,
взятый — первым. `DragPreview` рендерит библиотечный клон любого из них, так что ваша раскладка
может переиспользовать настоящий внешний вид:

```vue [PileOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="pile">
    <!-- The grabbed item on top, two more turned behind it -->
    <DragPreview
      v-for="(entry, i) in items.slice(0, 3)"
      :id="entry.id"
      :key="entry.id"
      class="card"
      :style="{ width: '100%', height: '100%', zIndex: 3 - i, rotate: `${i * 4}deg` }"
    >
      <!-- Shown for an item without a clone -->
      <div class="fallback">{{ entry.id }}</div>
    </DragPreview>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.pile { position: relative; width: 100%; height: 100%; }
.card { position: absolute; inset: 0; }
.fallback { width: 100%; height: 100%; border-radius: 8px; background: Canvas; }
.count { position: absolute; top: -8px; right: -8px; z-index: 4; }
</style>
```

```ts
makeSortableList(listRef, { items: photos, strategy: 'grid', overlay: PileOverlay });
```

Клоны снимаются в момент захвата: со взятого элемента и с не более чем четырёх соседних с ним
в порядке броска, если они отрендерены. Для любого другого элемента `DragPreview` рендерит свой
слот по умолчанию. Превью имеет размер своего элемента в момент захвата, если вы не задали
размер сами, как это делает `style` выше (`class` и `style` пробрасываются). В `'group'` и
`'gaps'` каждое превью при броске приземляется на слот своего элемента. Подробнее о компонентах
оверлея — в разделе [оверлей](/docs/guides/overlay).

## Деревья {#trees}

В дереве выделенные узлы перемещаются одним блоком, каждый со своим поддеревом, в порядке
документа. Выделенный узел внутри другого выделенного едет в поддереве своего родителя. См.
[деревья](/docs/guides/trees).
