Всё на этой странице включено по умолчанию. Перейдите клавишей Tab к ручке трека, нажмите
:kbd{value="Space"}, передвиньте его стрелками и снова нажмите :kbd{value="Space"} — или
:kbd{value="Escape"}, чтобы вернуть на место.

::example{name="lists" hint="Tab к ручке, Space, стрелки, Space" height="28rem"}
::

Что обычно остаётся за вами: понятные имена элементов и кнопки, которые перемещают элементы, для
тех, кто вообще не может перетаскивать.

## Клавиатура {#the-keyboard}

| Клавиша | Действие |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Взять элемент в фокусе; бросить его. |
| Стрелки | Двигать его: по слотам в списках, по строкам и глубине в деревьях, на `keyboard.step` пикселей при свободном перетаскивании. |
| :kbd{value="Escape"} | Отменить драг — в том числе драг указателем. |

- В списке стрелка в сторону другого списка той же группы переносит элемент туда.
- При свободном перетаскивании :kbd{value="Shift"} увеличивает шаг.
  `makeDraggable(el, { keyboard: 'droppables' })` заставляет стрелки вместо этого перепрыгивать
  между целями, которые принимают элемент.
- Перетаскивание с клавиатуры начинается с перетаскиваемого элемента в фокусе или с его ручки —
  никогда с кнопки или поля внутри него, поэтому у них остаются свои клавиши.
- Перетаскивание с клавиатуры прокручивает цель в зону видимости, а не включает автоскролл у
  краёв.
- После броска фокус возвращается на элемент, даже если его строка заново отрендерилась в другом
  списке.

### Другие клавиши {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Привязки сверяются с `event.code` (`'Space'`, `'KeyD'`) или `event.key` (`'Enter'`). `step` —
количество пикселей на одно нажатие стрелки при свободном перетаскивании (по умолчанию 25).
`:keyboard="false"` выключает перетаскивание с клавиатуры, а :kbd{value="Escape"} всё равно
отменяет любой драг. Меняя клавиши, поменяйте и `screen-reader-instructions`.

## ARIA-атрибуты {#aria-attributes}

Каждый перетаскиваемый элемент и элемент сортируемого списка получает эти атрибуты, **если вы не
задали их сами**:

| Атрибут | Значение |
| --- | --- |
| `tabindex` | `0`, если элемент ещё не фокусируемый. |
| `role` | `button`, кроме `<button>`, который и так кнопка. |
| `aria-roledescription` | `draggable`, или `sortable` у элементов сортируемых списков. |
| `aria-describedby` | Инструкции провайдера, добавленные к уже имеющимся id (id подсказки сохраняется). |
| `aria-disabled` | `true` или `false`: отключён ли элемент (в том числе отключённой областью перетаскивания). |
| `aria-pressed` | `true`, пока элемент перетаскивается. |

`attributes: false` выключает их для элемента; то, что задала библиотека, удаляется.

### Ручки: делайте их настоящими кнопками {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

С `handle` атрибуты ставятся на ручку, и перетаскивание с клавиатуры начинается с неё. `<button>`
и так фокусируемый и уже является кнопкой, поэтому ему не нужны `tabindex` и `role`. Дайте ему
`aria-label`: у иконки-ручки нет своего имени, а «Move Midnight Drive» говорит больше, чем
«button».

## Объявления {#announcements}

Live-регион в провайдере озвучивает каждый захват, перемещение, бросок и отмену. Сортируемые
списки называют позицию элемента: *«Picked up item t2 at position 2 of 5 in list playlist.»*
Перемещения озвучиваются, когда драг замер на 500 мс.

Тексты используют id. Дайте элементам понятные id или напишите тексты сами:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- Текст заменяет объявление события; `undefined` оставляет текст по умолчанию; `''` не говорит
  ничего. События, которые вы не указали, тоже сохраняют тексты по умолчанию — как позиции
  сортируемых списков для `onDragOver` выше.
- `onDragResume` озвучивается, когда `onBeforeDrop` ответил `'continue'` и драг продолжается (см.
  [решение о броске](/docs/guides/drop-decisions)).
- `screenReaderInstructions` — текст, на который каждый перетаскиваемый элемент ссылается через
  `aria-describedby`.
- `:announcements="false"` заглушает регион, например когда вы озвучиваете через свой.

::note
Встроенные тексты — на английском. Для другого языка задайте все пять текстов и инструкции:
каждый пропущенный будет озвучен по-английски, включая позиции в сортируемых списках.
::

## Касание {#touch}

Драг касанием начинается после долгого нажатия в 200 мс. Если сначала сдвинуть палец больше чем
на 5 px, вместо этого прокрутится страница, так что списки остаются прокручиваемыми. Оба
значения настраиваются через `activation` (см. [сенсоры](/docs/guides/sensors#activation-constraints)),
а кольцо долгого нажатия можно нарисовать по `useDnD().activation.progress`.

Драг касанием коротко вибрирует при старте. `:haptics="false"` выключает это; объект добавляет
вибрацию при входе в цель, броске или отказе:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Вибрируют только драги касанием, а iOS Safari не умеет вибрировать вообще.

## Уменьшение движения {#reduced-motion}

При `prefers-reduced-motion: reduce` собственные анимации библиотеки не запускаются. Ваши
функции анимации всё равно вызываются, с `reducedMotion: true`. См.
[анимации](/docs/guides/animations).

## Перемещение без перетаскивания {#moving-without-dragging}

Некоторые люди вообще не могут перетаскивать. WCAG 2.5.7 требует способа перемещать элементы
одиночными кликами — например, кнопками «Вверх». `@vue-dnd-kit/actions` делает каждое такое
действие настоящим перемещением:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` выполняет перетаскивание с клавиатуры от начала до конца: оно озвучивается, проходит
через `onBeforeDrop` и `onDrop`, анимируется и оставляет фокус на элементе. Промис разрешается в
`true`, если бросок состоялся. `index` считает места без самого элемента, поэтому «вниз» — это
`index + 1`. Подробнее — в разделе
[сенсоры и программное перетаскивание](/docs/guides/sensors#programmatic-drags).
