Перетащите карточку в **Done**. Бросок ждёт вашего ответа: перенести карточку, продолжить тащить
её в другое место или отменить.

::example{name="drop-confirm" hint="Перетащите карточку в Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

Списки, деревья, цели (`makeDroppable`) и мониторы (`useDnDMonitor`) принимают
`onBeforeDrop`. Он вызывается, когда драг отпущен, до каких-либо изменений, и его ответ решает:

| Ответ | Что происходит |
| --- | --- |
| `'accept'`, `true` или ничего | Бросок состоится. |
| `'reject'` или `false` | Броска нет: элементы улетают обратно. Выброшенная ошибка тоже отклоняет. |
| Массив ключей | Бросаются только эти элементы; остальные улетают обратно. |
| `'continue'` | Броска нет, а драг продолжается. |
| Промис любого из этих значений | Оверлей ждёт там, где его отпустили, пока промис не завершится. |

Сначала действуют собственные правила цели: `accept` у цели, `group.put` у списка. Над целью,
которая отклоняет драг, бросок отменяется, и `onBeforeDrop` цели не вызывается. `onBeforeDrop`
нужен для того, чего такие правила знать не могут: ответа пользователя, ответа сервера или того,
что бросок изменит.

Списки и деревья передают `SortableDropEvent`: `keys`, `items`, `from`, `to`, `mode`, `sameList`
и `result` — новые массивы всех списков, которые бросок меняет. Цели и мониторы получают общий
`DnDEvent`: `active`, `over`, `position` и `source`. См. [события](/docs/api/events).

### Принять часть элементов {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

При [мульти-драге](/docs/guides/multi-drag) элементы с возвращёнными ключами приземляются, а
остальные улетают туда, откуда пришли. Затем `onDrop` видит их в `e.accepted` и `e.rejected`, а
его `e.result` — окончательный.

## Продолжить драг: 'continue' {#keep-dragging-continue}

`'continue'` отменяет бросок, а не драг. Элемент остаётся в руке с того места, где был, страница
возвращается в режим драга, и пользователь продолжает:

- С мышью или пером элемент следует за указателем без зажатой кнопки. Следующее отпускание —
  клик — бросает его, и этот клик не доходит до страницы под ним.
- При касании элемент снова берётся там, куда опустился палец; когда палец поднимается,
  элемент бросается.
- Перетаскивание с клавиатуры продолжается: стрелки двигают элемент, :kbd{value="Space"} или
  :kbd{value="Enter"} бросают его.
- :kbd{value="Escape"} отменяет его, как любой драг.
- Следующий бросок снова спрашивает `onBeforeDrop`.

Мониторы получают `onDragResume`, а скринридеры слышат, что элемент не брошен и всё ещё
перемещается (текст можно заменить через `announcements.onDragResume` провайдера).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## Спросить пользователя {#asking-the-user}

`onBeforeDrop` может вернуть промис. Откройте диалог и разрешите промис кнопкой, которую выберет
пользователь:

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Пока промис не завершён:

- оверлей ждёт там, где его отпустили, с пометкой `data-dnd-overlay="dropping"`;
- `useDnD()` сохраняет состояние, которое было в момент отпускания, а `status` равен
  `'dropping'`;
- страница выходит из режима драга: курсор и выделение текста возвращаются, так что диалог
  работает как обычно.

::tip
Модальный `<dialog>`, открытый через `showModal()`, находится в верхнем слое, над ожидающим
оверлеем. Превратите его событие `cancel` (:kbd{value="Escape"}) в `'reject'`, как это сделано
в примере.
::

## Порядок хуков {#the-order-of-the-hooks}

1. `onBeforeDrop` каждого `useDnDMonitor` по очереди. `'reject'` или `'continue'` прекращает
   опрос; ключи сужают бросок.
2. `onBeforeDrop` цели: списка или дерева, в которые идут элементы, или обычной цели.
3. `onDrop` только цели: список, из которого элементы уходят в другой, не спрашивается, а его
   новый массив — в `e.result` цели. Когда элементы удаляются (корзина,
   `dropOutside: 'remove'`), вызывается `onDrop` их списка с `to.index`, равным `-1`.
4. Запись по умолчанию: каждый список, который меняет бросок, получает свой новый массив.
5. Оверлей приземляется. За этим следуют `@drag-end` провайдера и `onDragEnd` мониторов.

Ваши мониторы решают раньше цели, поэтому их вето никогда не приходит после того, как список уже
применил бросок сам.

## onDrop: вызывается до записи {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

`onDrop` списка вызывается, когда бросок принят, синхронно, прямо перед тем, как список его
запишет. Чтобы действовать после записи, используйте `@drag-end` провайдера или
`useDnDMonitor({ onDragEnd })`. У обычной цели `onDrop` — то место, где вы меняете свои данные:
библиотека за неё ничего не перемещает.

## Сторы и серверы: управляемые списки {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

Библиотека записывает бросок только в ref, доступный для записи. В геттер, `computed` или
`readonly` ref она никогда не пишет: вызовите `e.preventDefault()` и примените `e.result` сами —
новые массивы всех списков, которые меняет бросок, по id списка. `preventDefault()` пропускает
запись во все из них, ведь запись лишь в часть потеряла бы или задублировала элементы. Dev-сборки
предупреждают, когда бросок в список только для чтения оставлен библиотеке.

### Сначала сохранить на сервер {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Примените `e.result` до того, как промис разрешится, и оверлей приземлится уже в новом порядке.
Если запрос не удался, ничего не применяйте: бросок состоится, ничего не изменит, и элементы
улетят обратно.

## Бросок вне всех целей {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | Бросок вне всех целей… |
| --- | --- |
| `'placeholder'` | Приземляется там, где плейсхолдер: на последнем месте, которое показывал список. По умолчанию. |
| `'cancel'` | Отменяется: элементы улетают обратно. Значение по умолчанию при `placeholder: 'indicator'`. |
| `'remove'` | Удаляет элементы из их списка. Сначала спрашивается `onBeforeDrop` списка, а его `onDrop` получает `to.index`, равный `-1`. |

Корзина делает то же самое намеренно:
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`. См.
[drag and drop](/docs/guides/drag-and-drop).
