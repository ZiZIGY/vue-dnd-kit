Переключите ось, сетку и границы, затем перетащите заметку. Доска задаёт правила для каждого
драга, который на ней начинается, и каждая заметка остаётся там, где её бросили.

::

## Фиксация оси {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` двигает только по горизонтали, `'y'` — только по вертикали. Её принимают
`makeDraggable`, `makeSortableList`, `makeSortableTree`, `makeSortableItem` и `makeDragArea`.

- Фиксация срабатывает **после всех модификаторов**, поэтому держит, что бы они ни делали:
  привязка или граница не могут столкнуть элемент с его линии.
- Собственный `axis` элемента важнее, чем у его списка или дерева, а `axis` перетаскиваемого
  элемента (или его списка) важнее, чем у его области перетаскивания.
- Она читается в начале драга, поэтому её можно переключать геттером:
  `axis: () => (locked.value ? 'y' : undefined)`.
- Дерево, зафиксированное на `'y'`, всё равно вкладывает узлы: глубина тогда определяется
  наведением на середину строки.

::tip
Предпочитайте `axis` модификаторам `restrictToVerticalAxis` и `restrictToHorizontalAxis`. Они
делают то же самое, но как обычные модификаторы выполняются в середине цепочки, и модификатор
после них (сетка, которая привязывает обе оси) может снова сдвинуть элемент с оси.
::

## Модификаторы {#modifiers}

Модификатор корректирует смещение драга на каждом кадре. Его результат двигает оверлей **и**
служит точкой, где ищутся цели, поэтому список сортирует по зафиксированной, ограниченной или
привязанной позиции.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Модификатор | Что делает |
| --- | --- |
| `restrictToVerticalAxis` | Двигает только по вертикали. Лучше `axis: 'y'`. |
| `restrictToHorizontalAxis` | Двигает только по горизонтали. Лучше `axis: 'x'`. |
| `restrictToWindowEdges` | Держит оверлей внутри окна. |
| `restrictToParent` | Держит оверлей внутри контейнера, в котором начался драг: сортируемого списка или родительского элемента обычного перетаскиваемого элемента. |
| `restrictToElement(target)` | Держит оверлей внутри элемента: template ref, геттера или самого элемента. |
| `restrictToFirstScrollableAncestor` | Держит оверлей внутри первого прокручиваемого предка перетаскиваемого элемента. |
| `snapToGrid(size)` | Привязывает оверлей к сетке (см. ниже). |
| `snapCenterToCursor` | Центрирует оверлей под указателем вместо того, чтобы сохранять смещение захвата. |

`modifiers` — опция провайдера, областей перетаскивания, списков и деревьев, перетаскиваемых
элементов и элементов сортируемых списков. Все, кроме провайдера, принимают также ref или
геттер, который читается в начале драга.

### Привязка к сетке {#snap-to-a-grid}

`snapToGrid(24)` привязывает обе оси к ячейкам по 24 px. Объект позволяет задать больше:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Опция | Значение |
| --- | --- |
| `x`, `y` | Размер ячейки в пикселях, по каждой оси. |
| `origin` | `'container'` (по умолчанию): левый верхний угол оверлея встаёт на линии сетки, проведённые от левого верхнего угла контейнера — сортируемого списка или родителя обычного перетаскиваемого элемента. `'delta'`: округляется само смещение, поэтому элемент, который начал не на сетке, так и остаётся вне её. |
| `smooth` | `true` или `{ duration, easing }`: оверлей плавно скользит между ячейками (по умолчанию 80 мс). Цели сразу используют привязанную позицию. |

### Свой модификатор {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

Модификатор получает `transform` — смещение от начала драга в том виде, в каком его оставили
предыдущие модификаторы, — и возвращает новое. Ещё он получает то, что может понадобиться для
вычисления: `activeRect` (перетаскиваемый элемент в начале), `overlayRect` (оверлей, сдвинутый
на `transform`), `containerRect`, `windowRect`, `origin` (указатель в начале), `active` и
`over`. См. [модификаторы](/docs/api/modifiers).

## Порядок {#the-order}

Модификаторы из разных мест выполняются один за другим, каждый — от результата предыдущего:

1. `modifiers` провайдера;
2. `modifiers` области перетаскивания, в которой начался драг;
3. собственные `modifiers` перетаскиваемого элемента или, если их нет, его списка или дерева;
4. `restrictToArea` области перетаскивания;
5. фиксация `axis`.

`modifiers` элемента **заменяют** модификаторы его списка, а не добавляются к ним. Границы
области применяются после привязки из шагов 1–3, поэтому привязанный элемент всё равно остаётся
внутри, а фиксация оси идёт самой последней.

## Ограниченные списки сохраняют свои края {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

Граница держит оверлей у края блока, пока указатель движется дальше. Как только указатель
вышел за оверлей вдоль оси списка, список начинает сортировать по указателю, так что первое и
последнее место остаются достижимыми, как бы вы ни держали элемент. Сетки продолжают сортировать
по оверлею: прижатый к краю, он уже закрывает крайнюю ячейку.

## Правила для части страницы {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` задаёт правила для драгов, которые **начинаются внутри** её элемента, — и для
обычных перетаскиваемых элементов, и для элементов сортируемых списков. Оставьте один
`DnDProvider` на всё приложение, а доске, холсту или ленте дайте собственную область.

| Опция | Что делает |
| --- | --- |
| `axis` | Фиксирует драги на одной оси. Собственный `axis` перетаскиваемого элемента или его списка важнее. |
| `modifiers` | Выполняются после модификаторов провайдера и до собственных модификаторов перетаскиваемого элемента. |
| `restrictToArea` | `true`: драги остаются внутри элемента области. |
| `autoScroll` | Автоскролл скролл-контейнера области (самого элемента или его ближайшего прокручиваемого предка). `false` выключает его там. |
| `activation` | [Активация](/docs/guides/sensors#activation-constraints) для каждого типа указателя. Собственная активация перетаскиваемого элемента важнее; провайдер — в последнюю очередь. |
| `disabled` | В области не начинается ни один драг, как и во вложенных в неё областях. Её перетаскиваемые элементы сообщают `aria-disabled`. |

Каждая опция принимает значение, ref или геттер, который читается в начале нажатия или драга.
Область возвращает `isDragging` (идёт драг, начатый здесь) и `isAutoScrolling` (автоскролл
прокручивает её контейнер). Полный справочник: [makeDragArea](/docs/api/make-drag-area).

### Как сочетаются области {#how-areas-combine}

- Драг следует правилам области, в которой он **начался**, даже когда её покинул. Проход над
  другой областью ничего не меняет, кроме её `autoScroll`: он действует на любой драг, который
  прокручивает её контейнер.
- Вложенные области не объединяются: побеждает ближайшая. Исключение — `disabled`, он
  наследуется: выключенная область выключает и вложенные в неё.
- Определение цели, клавиши и объявления остаются общими для всего провайдера.

::note
Почему не второй `DnDProvider` вокруг доски? Провайдеры независимы: драг никогда не переходит из
одного в другой, поэтому элементы доски никогда не смогли бы её покинуть. Вкладывайте провайдер,
только когда части страницы нужны свои настройки уровня провайдера, а её элементы остаются
внутри. См. [провайдер](/docs/guides/provider).
::

## Оставить там, где бросили {#leave-it-where-its-dropped}

Доска в примере — ещё и цель, и каждая заметка остаётся там, где её бросили. Каждое событие
драга несёт `position`: левый верхний угол перетаскиваемого блока внутри цели, от края её
padding и с учётом прокрутки, — те `left` и `top`, которые ставят абсолютно позиционированный
элемент ровно туда. Позиция вычисляется после модификаторов, поэтому привязанная заметка
приземляется на сетку.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

Подробнее о свободном перетаскивании и целях — в разделе [drag and drop](/docs/guides/drag-and-drop).
