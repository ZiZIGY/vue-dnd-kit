Сенсор превращает ввод в драги. Он лишь сообщает провайдеру «тащи этот элемент отсюда», затем —
куда сдвинулся ввод и чем всё кончилось: броском или отменой. Остальное делает провайдер,
одинаково для любого сенсора: один драг за раз, отказ отключённым элементам, ограничения
активации, сортировка, автоскролл, объявления, :kbd{value="Escape"} и весь бросок.

## Встроенные сенсоры {#the-built-in-sensors}

| Сенсор | Ввод |
| --- | --- |
| `pointerSensor` | Мышь, касание и перо через Pointer Events. Захватывает указатель, не даёт странице выделять текст или прокручиваться под драгом касанием и поглощает клик, который следует за драгом. |
| `keyboardSensor` | :kbd{value="Space"} и :kbd{value="Enter"} берут и бросают, стрелки двигают, :kbd{value="Escape"} отменяет — любой драг, в том числе драг указателем. |

Оба работают по умолчанию. Опция провайдера `sensors` заменяет этот список:

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

Чтобы выключить перетаскивание с клавиатуры, лучше используйте `:keyboard="false"`, чем убирайте
`keyboardSensor`: именно клавиатурный сенсор отменяет любой драг по :kbd{value="Escape"}. Его
клавиши переназначаются через `keyboard.keys` (см.
[доступность](/docs/guides/accessibility#the-keyboard)).

## Ограничения активации {#activation-constraints}

Нажатие становится драгом, когда выполняет своё ограничение:

| Указатель | По умолчанию |
| --- | --- |
| Мышь | После сдвига на 4 px. Сразу, если нажать на `handle`, если только вы не задали ограничение для мыши. |
| Перо | После сдвига на 4 px. |
| Касание | После нажатия в 200 мс. Если сначала сдвинуть палец больше чем на 5 px, активация прерывается, и вместо этого прокручивается страница. |

У ограничения три поля:

| Поле | Значение |
| --- | --- |
| `distance` | Сколько пикселей должен пройти указатель. |
| `delay` | Сколько миллисекунд должно длиться нажатие. Если заданы оба, драг начинает то, что наступит раньше. |
| `tolerance` | Вместе с `delay`: насколько указатель может сдвинуться за это время; если больше — нажатие отбрасывается. |

Задавайте их для каждого типа указателя — `mouse`, `touch`, `pen` — на провайдере, области
перетаскивания или самом элементе. Важнее всего собственное ограничение элемента, затем — его
области, затем — провайдера:

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

Чтобы тащить касанием с ручки сразу, задайте ручке `touch-action: none` (чтобы браузер не
прокручивал страницу), а элементу — `activation: { touch: { distance: 4 } }`.

### Кольцо долгого нажатия {#a-long-press-ring}

Пока нажатие ждёт, `useDnD().status` равен `'activating'`, а `activation.progress` растёт от 0 до 1:

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### Только некоторые нажатия {#only-some-presses}

`canDrag` — ещё один фильтр у перетаскиваемых элементов и элементов сортируемых списков. Он
получает событие ввода:

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

Интерактивные потомки — кнопки, поля ввода, редактируемые поля — никогда не начинают драг
указателем, поэтому внутри перетаскиваемого элемента они продолжают работать. С `handle` драг
начинает только ручка.

## Собственный сенсор {#a-sensor-of-your-own}

Геймпад, экранный джойстик, голосовые команды: всё, что может указать на элемент и двигаться,
может управлять драгом. Вот джойстик, который берёт то, что под его курсором, после удержания в
300 мс:

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

Добавьте его в `sensors` провайдера или запускайте на время жизни компонента через
`useSensor(joystick.sensor)`.

### Что получает сенсор {#what-the-sensor-gets}

`setup(context)` получает сторону провайдера:

| Член | Что это |
| --- | --- |
| `props` | Пропсы провайдера (`activation`, `keyboard`…). Читайте их, когда нужно: они могут измениться. |
| `status` | Статус драга провайдера, какой бы сенсор ни вёл драг. |
| `drag` | Текущий драг провайдера, ожидающий или идущий, какой бы сенсор его ни начал. `null`, если драга нет. |
| `activate(options)` | Запрашивает драг. Возвращает `SensorDrag` или `null`, если драг начать нельзя. |
| `cancel()` | Отменяет драг провайдера или ожидающее нажатие. |

`activate()` принимает:

| Опция | Значение |
| --- | --- |
| `target` | Куда пришёлся ввод: элемент внутри перетаскиваемого элемента или id перетаскиваемого элемента. Элемент проверяется, как настоящее нажатие (ручка, не интерактивный потомок); id пропускает проверки. |
| `point` | Где начинается драг, в координатах вьюпорта. По умолчанию — центр перетаскиваемого элемента. |
| `type` | `'pointer'` (по умолчанию): следует за точками, ищет цели, включает автоскролл. `'keyboard'`: двигает по элементам, прокручивает к целям, в конце возвращает фокус. |
| `activation` | Ограничение (`{ delay: 300 }`) или тип указателя (`'touch'`), чтобы взять настроенное для него. По умолчанию нет: драг начинается сразу. |
| `event` | Событие ввода, передаётся в `canDrag` элемента. `pointerType` касания делает драг драгом касанием (вибрация). |
| `onStart(drag)` | Драг начался, после своей активации. |
| `onEnd(drag)` | Драг окончен: прерван, брошен или отменён — кем угодно. |
| `onResume(drag)` | `onBeforeDrop` ответил `'continue'`: драг продолжается, и `move`, `drop` и `cancel` снова действуют. |

`SensorDrag`, который он возвращает:

| Член | Что делает |
| --- | --- |
| `id`, `type` | Id перетаскиваемого элемента и `'pointer'` или `'keyboard'`. |
| `state` | `'pending'` (ждёт активации), `'dragging'`, затем `'ended'`. |
| `started` | Драг начался, даже если уже закончился. |
| `move(point)` | Ввод сдвинулся. В ожидании проверяет допуск; во время драга двигает драг. |
| `step(direction)` | Для перетаскивания с клавиатуры: один шаг стрелкой, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | Ставит элемент на позицию в сортируемом списке, как это делают перемещения с клавиатуры. Разрешается в `false`, если туда его не принимает ни один список. |
| `drop()` | Бросает. Разрешается в `true`, если бросок состоялся, после приземления. |
| `cancel()` | Отменяет: элемент улетает обратно, или ожидающее нажатие отбрасывается. |

Вызовы, которые уже не имеют смысла — движение после конца, второй `drop()`, —
игнорируются. Полные типы: [сенсоры](/docs/api/sensors).

::tip
Чтобы обернуть встроенный сенсор, запустите его `setup` с собственным контекстом. Создайте его
через `Object.create(context, { activate: { value: myActivate } })`, а не спредом, чтобы живые
геттеры (`status`, `drag`, `props`) продолжали работать.
::

## Программное перетаскивание {#programmatic-drags}

`@vue-dnd-kit/actions` перемещает элементы из кода: кнопки «Вверх», меню, горячие клавиши,
отмена действий, обучающие туры, тесты. Пакет построен на публичном API сенсоров, и его драги —
настоящие: с объявлениями и анимацией, через `onBeforeDrop`, `onDrop`, `e.result` и
`preventDefault()`, по правилам провайдера (один драг за раз, отключённые элементы, `accept` и
`group.put`).

::example{name="actions" hint="Стрелки, перемешивание и драг по сценарию — всё это вызовы @vue-dnd-kit/actions" height="28rem"}
::

```bash
npm i @vue-dnd-kit/actions
```

### moveItem: один вызов — одно перемещение {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` — `id` сортируемого списка. Без него элемент остаётся в своём списке.
- `index` — где элемент окажется, считая без самого элемента, с ограничением по длине списка.
  Без него элемент уходит в конец.
- Промис разрешается в `true`, если бросок состоялся, и в `false`, если элемент не отрендерен
  или отключён, туда его не принимает ни один список или бросок был отклонён.
- Вызовы встают в очередь: каждый ждёт, пока провайдер освободится, так что быстрый второй клик
  не теряется.
- Он выполняется как перетаскивание с клавиатуры, поэтому озвучивается, а фокус остаётся на
  элементе.
- Только для списков: у позиций в дереве есть ещё и глубина.

Строка с кнопками перемещения — в разделе
[доступность](/docs/guides/accessibility#moving-without-dragging).

### startDrag: драг по сценарию {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` разрешается, когда перемещение отрендерено, `drop` — когда бросок приземлился.
`startDrag(id, { type: 'keyboard' })` вместо этого двигает по элементам
(`await drag.step('down')`), и управление может перехватить клавиатурный сенсор: например, пункт
меню «Переместить», который передаёт элемент стрелкам.

### Вне компонентов {#outside-components}

`useDnDActions()` запускает один сенсор с именем `actions` в провайдере выше. Чтобы управлять
провайдером из стора или тестового окружения либо под своим именем, создайте действия в сенсоре,
который запускаете сами:

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

Затем вызывайте `await tour?.moveItem('card-1', { list: 'done' })` откуда угодно. Во время
серверного рендеринга ничего не перетаскивается: `moveItem` разрешается в `false`, а `startDrag`
возвращает `null`.
