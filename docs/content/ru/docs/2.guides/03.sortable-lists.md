## Список и его строки {#a-list-and-its-rows}

Сортируемому списку нужны два компонента: сам список и его строка.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

Строка регистрируется в том списке, внутри которого отрендерена. Поэтому же каждому списку
нужен собственный компонент: у двух списков, созданных в одном компоненте, строки были бы общими.

## Черновик {#the-draft}

`makeSortableList` возвращает `items` — **черновик** вашего массива. Во время драга черновик
перестраивается на лету: перетаскиваемая строка занимает новый слот, а остальные сдвигаются,
освобождая место. Ваш массив не меняется до броска. Тогда библиотека записывает в него новый
порядок.

::example{name="quick-start" hint="Id под списком — это ваш массив: они меняются при броске"}
::

- Рендерите `items`, а не свой массив. Если рендерить массив, ничего не сдвинется до броска.
- Запись происходит после `onDrop` списка. В `onDrop` ваш массив ещё хранит старый порядок, а
  `e.result` — новый.
- `tasks` — обычный `ref`, поэтому остальное приложение видит изменение, как и любое другое.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

Компонент списка, который получает массив через `v-model`, передаёт модель дальше:

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
Стор, серверное состояние или иммутабельные данные? Передайте геттер или `computed` вместо ref.
Библиотека не пишет в источник только для чтения: вызовите `e.preventDefault()` и примените
`e.result` сами. См. [решения о броске](/docs/guides/drop-decisions).
::

## Ключи {#keys}

Строки получают ключи по своим данным — никогда по индексу или автоматическому id. По умолчанию
ключ — `item.id`, а для строк и чисел — сам элемент.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Используйте тот же ключ в `v-for`: `:key="task.uuid"`. С `:key="index"` анимируются не те
  строки, а их состояние перескакивает между строками.
- Ключи должны быть уникальны среди всех списков, которые обмениваются элементами.
- Передавайте `item` и `id` геттерами, чтобы строка оставалась синхронной при изменении пропсов.

## Стратегии {#strategies}

| `strategy` | Для чего |
| --- | --- |
| `'vertical'` (по умолчанию) | Колонка строк. |
| `'horizontal'` | Один ряд: вкладки, чипы, таймлайн. |
| `'grid'` | CSS-сетки и переносящиеся flex-ряды, в том числе с элементами разного размера. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Ручки {#handles}

По умолчанию драг начинается со всей строки (кроме кнопок, полей ввода и других элементов
управления в ней). Передайте `handle`, чтобы тащить только за одну часть:

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` — селектор внутри элемента или ref элемента.
- Драг мышью начинается с ручки сразу, без обычных 4 px.
- Ручка получает атрибуты драга (`role`, `tabindex`, `aria-*`), и перетаскивание с клавиатуры
  начинается с неё.

Сделайте ручку элементом `<button type="button">` с `aria-label`: он и так фокусируемый, а
скринридеры зачитывают его подпись. Голый `<span>` с иконкой тоже работает (библиотека даёт ему
`tabindex="0"` и `role="button"`), но осмысленного имени у него нет.

::note
Драг касанием начинается после долгого нажатия в 200 мс, чтобы страницу по-прежнему можно было
прокручивать. Чтобы тащить с ручки сразу, задайте ручке `touch-action: none`, а элементу —
`activation: { touch: { distance: 4 } }`.
::

## Фиксация оси {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` держит драг на вертикальной оси, `'x'` — на горизонтальной. Собственный `axis`
элемента важнее, чем у его списка. Чтобы ещё и не выпускать драг за пределы списка, добавьте
модификатор `restrictToParent`; плейлист выше использует и то и другое. Подробнее — в разделе
[ограничения](/docs/guides/constraints).

## Стилизация слота {#style-the-slot}

Перетаскиваемая строка остаётся в списке в виде слота, в который она приземлится, и получает
`data-dnd-placeholder`. Стиль по умолчанию снижает её непрозрачность до 40% с нулевой
специфичностью, так что любое ваше правило важнее:

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` возвращает то же состояние в виде ref, и ещё кое-что:

| Возвращает | Что это |
| --- | --- |
| `isPlaceholder` | Эта строка — слот, в который приземлится перетаскиваемый элемент. |
| `isDragging` | Эта строка перетаскивается (при мульти-драге — каждая перетаскиваемая строка). |
| `index` | Её индекс в черновике: он меняется во время драга. |
| `selected` | Доступен для записи, связан с выделением провайдера. |
| `indicator` | В [режиме индикатора](/docs/guides/shared-lists#an-insertion-line) — куда встанет линия. |

Список возвращает `isOver` и `isAccepting` для собственной подсветки. Все атрибуты и рецепты —
в разделе [стилизация](/docs/guides/styling).

## Отключение {#turning-things-off}

- `disabled` на списке: из него нельзя вытащить и в него нельзя бросить. На элементе: его
  нельзя перетащить.
- `sort: false`: элементы нельзя переставлять внутри этого списка, но из него их можно
  вынести (палитра, см. [списки с общими элементами](/docs/guides/shared-lists)).

## Анимации {#animations}

Во время драга строки плавно переезжают на новые места, а брошенная строка приземляется на
свой слот. Это включено по умолчанию и не требует кода. Не оборачивайте строки в
`<TransitionGroup>`: перемещения анимировались бы дважды. Для изменений, сделанных не драгом
(добавление, удаление, перемешивание), включите опцию списка `animate`. См.
[анимации](/docs/guides/animations).

Полный список опций — в API [makeSortableList](/docs/api/make-sortable-list) и
[makeSortableItem](/docs/api/make-sortable-item).
