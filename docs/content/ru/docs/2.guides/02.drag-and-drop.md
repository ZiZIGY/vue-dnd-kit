Используйте `makeDraggable` и `makeDroppable` для всего, что не является сортируемым списком:
файлы в папки, корзина, шахматная доска, календарь, заметки на доске.

::example{name="drop-zones" hint="Изображения — в Images, документы — в Documents" height="30rem"}
::

## Перетаскиваемый элемент {#a-draggable}

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

Передавайте id из своих данных в виде геттера. Id по умолчанию берётся из `useId()` и новый у
каждого экземпляра компонента, так что остальному приложению он ни о чём не говорит.

| Возвращает | Что это |
| --- | --- |
| `isDragging` | Этот элемент сейчас перетаскивается. |
| `selected` | Доступен для записи, связан с [выделением](/docs/guides/multi-drag) провайдера. |
| `transform` | Смещение драга, для `overlay: false` (см. ниже). |
| `id` | Используемый id. |

Кнопки, поля ввода и другие интерактивные потомки не начинают драг указателем, поэтому внутри
перетаскиваемого элемента они продолжают работать. Чтобы тащить только за одну часть,
передайте `handle` (см. [сортируемые списки](/docs/guides/sortable-lists#handles)). Все опции —
в [API makeDraggable](/docs/api/make-draggable).

## Цель {#a-drop-target}

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| Возвращает | `true`, когда |
| --- | --- |
| `isOver` | Драг находится над этой целью — принимает она его или нет. |
| `isAccepting` | Что-то перетаскивается, и эта цель это принимает: подсветите подходящие зоны. |
| `placement` | Не boolean: `{ top, right, bottom, left }` — половины цели, в которых находится указатель, или `null`, когда над целью ничего нет. Используйте для «до / после этой карточки». |

`isOver` без `isAccepting` означает, что драг находится над целью, которая его отклоняет.
Покажите это, как делают папки выше: бросок туда отменяется, и элемент улетает обратно.

## Какие драги принимает цель {#which-drags-a-target-takes}

`type` перетаскиваемого элемента сверяется с `accept` цели:

| `accept` | Принимает |
| --- | --- |
| не задан или `'*'` | Всё. |
| `'image'` | Элементы с типом `image` и элементы без типа. |
| `['image', 'doc']` | Любой из этих типов и элементы без типа. |
| `({ active, items, types }) => boolean` | То, что решит ваша функция. |

Элемент без `type` подходит под любое строковое правило. Для всего остального используйте
функцию:

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` может быть и массивом (`['image', 'large']`): достаточно одного совпавшего типа.

Когда перетаскивается сразу несколько элементов, `acceptMode` определяет, сколько из них должно
подойти: `'all'` (по умолчанию) или `'some'`. С `'some'` верните из `onBeforeDrop` id, которые
нужно оставить, а остальные улетят обратно. См. [решения о броске](/docs/guides/drop-decisions).

## Бросок {#the-drop}

`onDrop` обычной цели — то место, где данные меняете **вы**. Сама библиотека ничего не
перемещает:

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| Поле события | Что содержит |
| --- | --- |
| `active` | Драг: `id`, `ids`, `items` (каждый — `{ id, data, type, item }`), `data`, `type`. |
| `over` | Эта цель: `id`, `data`, `element`, `rect`. |
| `pointer`, `delta` | Где указатель и насколько он сместился от начала. |
| `position` | Где перетаскиваемый блок находится внутри этой цели (следующий раздел). |
| `source` | Задан, когда элементы пришли из сортируемого списка: `{ list, remove() }`. |

Порядок такой: `onBeforeDrop` (решить), `onDrop` (применить), затем `drag-end` провайдера. Как
спросить перед броском, продолжить драг или принять только часть элементов — см.
[решения о броске](/docs/guides/drop-decisions).

## Оставить там, где бросили {#leave-it-where-it-was-dropped}

Доска, холст, план этажа: элемент остаётся там, где вы его отпустили. Каждое событие несёт
`position` — `left` / `top`, которые ставят абсолютно позиционированный элемент туда, где его
бросили.

::example{name="constraints" hint="Перетащите заметку, затем зафиксируйте ось или выключите сетку" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` — это левый верхний угол перетаскиваемого блока внутри `over`: отсчитывается от края
его padding, с учётом прокрутки. Если под драгом ничего нет, он равен `null`. С
`overlay: false` это угол самого элемента.

::tip
Не вычисляйте точку из `active.rect` и `delta`: так теряются рамка и прокрутка цели. Привязка,
границы и фиксация оси для таких досок — в разделе [ограничения](/docs/guides/constraints).
::

## Бросок в элемент сортируемого списка {#drop-into-a-sortable-item}

Строка сортируемого списка тоже может быть целью: папка, которая принимает файлы, группа,
которая принимает задачи. Повесьте droppable на элемент строки:

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

Пока список сортировал бы драг, такая цель срабатывает только в **середине** своего элемента
(от 25 до 75% вдоль оси списка). Там бросок идёт в элемент, а список не сдвигается. У краёв
список сортирует как обычно.

- Цель, чей `accept` отклоняет драг, пропускается: над этим элементом список сортирует, как
  над любым другим. Папка, которая принимает только файлы, пропускает папки мимо себя.
- Цель никогда не получает собственный драг.
- Если после броска элемент больше не показан, оверлей сжимается в цель, а не улетает обратно.

## Корзины {#trash-zones}

Драг, начатый в сортируемом списке, несёт `e.source`. Вызовите `remove()`, и список уберёт
элементы:

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

Затем собственный `onDrop` списка вызывается с `to.index === -1`, а `e.result` содержит список
без этих элементов. Список может также удалять то, что брошено вне всех целей: см.
[`dropOutside`](/docs/guides/shared-lists#dropping-outside).

## Без оверлея {#without-an-overlay}

По умолчанию за указателем следует клон элемента, а сам элемент остаётся на месте. С
`overlay: false` клона нет: двигайте элемент сами с помощью `transform`.

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

Своё превью драга вместо клона — см. [оверлей](/docs/guides/overlay).

## Клавиатура {#keyboard}

Перетаскиваемый элемент в фокусе берётся клавишей :kbd{value="Space"} или :kbd{value="Enter"}.
Стрелки двигают его на 25 px (`keyboard.step` провайдера). С `keyboard: 'droppables'` на
перетаскиваемом элементе они вместо этого перепрыгивают между целями, которые его принимают, —
это удобно для зон, далёких друг от друга. Подробнее — в разделе
[доступность](/docs/guides/accessibility).
