v3 — это переписанная v2. Модель осталась прежней: один провайдер и композаблы, которые вы
вызываете на своих элементах. Но большинство имён и опций изменилось, сортировка переехала в
библиотеку, а обработчик броска, который вы писали для каждого списка, больше не нужен. Эта
страница сопоставляет каждую часть v2 с v3, а затем показывает типичные случаи до и после.

## Что изменилось {#what-changed}

- **Сортировка встроена.** В v2 список был зоной сброса, его строки — перетаскиваемыми
  элементами с данными `[index, items]`, а сортировали вы в `onDrop` через
  `e.helpers.suggestSort()`. В v3 это делают `makeSortableList` и `makeSortableItem`: список
  рендерит **черновик** вашего массива, который перестраивается во время драга, а бросок
  записывает новый массив в ваш ref. Большинство обработчиков броска из v2 удаляются, а не
  переносятся.
- **Всё движется само.** Строки плавно встают на новые места (FLIP), оверлей при броске
  приземляется на свой слот, а при отмене летит обратно. `<TransitionGroup>` больше не нужен.
- **По-прежнему один пакет.** В `@vue-dnd-kit/core` есть списки, деревья, мульти-драг,
  модификаторы, сенсоры и функции определения коллизий. Nuxt-модуль остаётся;
  `@vue-dnd-kit/actions` (программное перетаскивание) и `@vue-dnd-kit/devtools` — новые и
  необязательные.
- **Настоящий оверлей.** Он телепортируется в `body` и показывает глубокий клон размером со
  слот, на который приземлится. Компоненты оверлея получают драг через пропсы, а не читают
  внутренности провайдера.
- **Id, а не элементы.** Выделение, события и состояние драга привязаны к id из ваших данных.
  Никаких карт DOM-элементов читать не нужно.
- **Типы и правила `accept`** заменяют `groups` для обычных перетаскиваемых элементов и целей.
  Списки обмениваются элементами по имени `group`.
- **Решения до броска.** `onBeforeDrop` принимает бросок, отклоняет его, продолжает драг или
  берёт часть элементов. `onDrop` только применяет.
- **Сенсоры.** Ввод указателем и с клавиатуры — это сенсоры. Активация задаётся для каждого типа
  указателя, а драги касанием начинаются с долгого нажатия, поэтому списки продолжают
  прокручиваться под пальцем.
- **Области.** `makeDragArea` заменяет `makeConstraintArea` и `makeAutoScroll`, а автоскролл
  работает в любом скролл-контейнере без кода.
- **Доступность включена по умолчанию**: ARIA-атрибуты, фокус, который возвращается после
  броска, и озвучивание для скринридеров.

## Обновление {#upgrade}

::code-group

```bash [npm]
npm i @vue-dnd-kit/core@^3
```

```bash [yarn]
yarn add @vue-dnd-kit/core@^3
```

```bash [pnpm]
pnpm add @vue-dnd-kit/core@^3
```

```bash [bun]
bun add @vue-dnd-kit/core@^3
```

::

| Пакет | v2 | v3 |
| --- | --- | --- |
| `@vue-dnd-kit/core` | 2.4.x | 3.x |
| `@vue-dnd-kit/nuxt` | 1.x | 3.x |
| `@vue-dnd-kit/actions` | — | 1.x, необязательный |
| `@vue-dnd-kit/devtools` | — | 3.x, необязательный |

- Приложение, у которого в `package.json` стоит `"@vue-dnd-kit/core": "^2…"`, остаётся на v2,
  пока диапазон не станет `^3`.
- Vue **3.5** или новее. У v2 не было зависимостей; у v3 одна — `@vueuse/core` (14 или 15).
- Браузеры: Chrome и Edge 104+, Safari 15.4+, Firefox 104+.
- У v2 и v3 одно имя пакета, поэтому приложение переходит на v3 целиком. Слоя совместимости
  нет. Документация v2 по-прежнему доступна в меню версий вверху страницы.

Хороший порядок работы:

1. Обновите пакеты и переименуйте пропсы провайдера ([ниже](#the-provider)).
2. Превратите каждый сортируемый список в `makeSortableList` и `makeSortableItem` и удалите его
   обработчик броска.
3. Перенесите обычные перетаскиваемые элементы и зоны сброса.
4. Перенесите свои превью в компоненты оверлея или в слот `#overlay` провайдера.
5. Замените `makeConstraintArea` и `makeAutoScroll` на `makeDragArea` или ни на что.
6. Удалите обходные решения v2: `tabindex` и `aria-grabbed` на перетаскиваемых элементах,
   `touch-action: none` на элементах целиком, `<TransitionGroup>` вокруг строк, `markRaw` вокруг
   компонентов превью.

## Старое и новое {#old-to-new}

**Нет аналога** в таблице означает, что в v3 нет ничего с таким именем; в ячейке сказано, что
использовать вместо этого.

### Вкратце {#at-a-glance}

| v2 | v3 |
| --- | --- |
| `DnDProvider` | `DnDProvider`, с новыми пропсами и слотом `#overlay`. |
| `makeDraggable` | `makeDraggable` для свободного перетаскивания; `makeSortableItem` для строк списка. |
| `makeDroppable` | `makeDroppable` для обычных целей; `makeSortableList` или `makeSortableTree` для списков и деревьев. |
| `makeSelectionArea` | `makeSelectionArea`. |
| `makeConstraintArea` | `makeDragArea`. |
| `makeAutoScroll` | Ничего: автоскролл работает сам. Его настраивает `makeDragArea` или `autoScroll` списка. |
| `useDnDProvider` | `useDnD` для состояния, `useDnDMonitor` для событий. |
| `injectionKey` | `useDnDContext()` и `provideDnDContext(app, context)`. |
| `DragPreview` | `DragPreview`: теперь это клон одного перетаскиваемого элемента, для ваших собственных оверлеев. |
| `makeSnappedOverlayPosition`, `<DragPreview :grid>` | Модификатор `snapToGrid`. |
| `e.helpers.suggestSort`, `suggestSwap`, `suggestCopy`, `suggestRemove` | Встроены в списки: см. [сортировку](#sorting). |

### Провайдер {#the-provider}

| v2 | v3 |
| --- | --- |
| `autoScrollViewport`, выключен, пока не задан | `autoScroll`: **включён по умолчанию**, для окна и любого скролл-контейнера. `{ threshold, maxSpeed, acceleration }` или `false`. |
| `previewTo`, по умолчанию рендерится внутри провайдера | `overlayTo`: селектор или элемент, по умолчанию `'body'`. |
| Слот `#preview="{ preview }"` | Слот `#overlay` с драгом в пропсах: `items`, `active`, `over`, `accepted`, `status`, `mode`, `to`. См. [оверлей](#the-overlay). |
| `keyboard.keys.forDrag`, `forDrop`, `forCancel` (задавались в `useDnDProvider()`) | `:keyboard="{ keys: { start, drop, cancel } }"`. |
| `keyboard.step` | `:keyboard="{ step }"`: по умолчанию 25 px, для свободных драгов. |
| `keyboard.keys.forMove`, `forMoveFaster`, `keyboard.moveFaster` | **Нет аналога.** Двигают стрелки; :kbd{value="Shift"} делает шаги свободного драга в четыре раза больше. |
| `collision.throttle` | **Нет аналога.** `collision` выбирает, как находится цель: `pointerFirst` (по умолчанию), `pointerWithin`, `rectIntersection`, `closestCenter`, `closestCorners` или ваша функция. |
| Один провайдер на страницу, никогда не вложенный | Вложение работает: элементом владеет ближайший провайдер. Цель по-прежнему — один провайдер на приложение. |

Новые пропсы, у которых нет аналога в v2: `activation`, `modifiers`, `sensors`, `animation`,
`dropAnimation`, `animateChanges`, `haptics`, `copyModifier`, `overlayFit`, `overlayClass`,
`overlayTransition`, `overlayPreviews`, `announcements`, `screenReaderInstructions` и
`defaultStyles`. Провайдер также эмитит `drag-start`, `drag-move`, `drag-over`, `drag-end`,
`drag-cancel`, `drag-resume` и `drag-settle`. Все они описаны в [руководстве по провайдеру](/docs/guides/provider).

### `makeDraggable` {#makedraggable}

| v2 | v3 |
| --- | --- |
| `makeDraggable(ref, options, payload)` | `makeDraggable(ref, options)`: без третьего аргумента. Строки списка используют `makeSortableItem(ref, { item })`. |
| `id`, нужен в виртуальных списках | `id`: передавайте его из своих данных, геттером. Значение по умолчанию берётся из `useId()` и новое для каждого экземпляра компонента. |
| `data: () => card` | `data`: значение, ref или геттер. Читается обратно как `active.data` и `active.items[i].data`. |
| `groups: ['dev']` | `type: 'dev'`, с которым сверяется `accept` целей. См. [группы](#groups). |
| `dragHandle: '.handle'` | `handle`: селектор или ref элемента. |
| `disabled` | `disabled`. |
| `modifier: { keys, method }` | `canDrag: (event) => event.altKey`: проверка на каждое нажатие. |
| `activation: { distance, delay }` | `activation` для каждого типа указателя: `{ mouse: { distance }, touch: { delay, tolerance }, pen }`. Если заданы и `distance`, и `delay`, драг начинается по тому, что наступит раньше. |
| `activation.distance: { x, y, condition }` | **Нет аналога.** Один `distance` на тип указателя. |
| `render: markRaw(Preview)` | `overlay: Preview`: компонент получает драг через пропсы. См. [оверлей](#the-overlay). |
| `placementMargins` | **Нет аналога.** Цель на сортируемом элементе засчитывается в его середине (от 25 до 75 %); деревья вкладывают через `nesting: 'hover'`. См. [бросок в сортируемый элемент](/docs/guides/drag-and-drop#drop-into-a-sortable-item). |
| `events.onSelfDragStart`, `onSelfDragMove`, `onSelfDragEnd`, `onSelfDragCancel` | **Нет аналога** на перетаскиваемом элементе: `useDnDMonitor` или `watch(isDragging)`. См. [события](#events-and-drop-decisions). |
| `events.onHover`, `onLeave` и его `onDragStart`… для драгов над ним | `makeDroppable` на том же элементе: `onDragEnter`, `onDragLeave`. |
| Возвращает `isDragging`, `selected` | То же самое. |
| Возвращает `isDragOver` | Сортируемые элементы возвращают `indicator` (с `placeholder: 'indicator'`) и `isPlaceholder`; цели возвращают `placement`. |
| Возвращает `isAllowed` | **Нет аналога** у перетаскиваемых элементов. Цели возвращают `isAccepting`. |
| — | Новое: `label`, `axis`, `modifiers`, `keyboardMode`, `overlay: false` с возвращаемым `transform`, `dropAnimation`, `attributes`, `native`. |

| v2 | v3 |
| --- | --- |
| `makeDroppable(ref, options, () => items)` | `makeDroppable(ref, options)`. Зона, в которой лежит список, — это `makeSortableList`. |
| `groups` | `accept`: `'*'`, тип, список типов или функция. |
| `groupMatch: 'every'`, `'some'` | `acceptMode: 'all'`, `'some'`. |
| `events.onEnter`, `events.onLeave` | `onDragEnter`, `onDragLeave`: самостоятельные опции, без объекта `events`. |
| `events.onDrop`, который мог вернуть `false` или промис | `onBeforeDrop` решает, `onDrop` применяет. См. [решения о броске](#events-and-drop-decisions). |
| `events.onValidate` | `onBeforeDrop`, возвращающий id, которые нужно оставить. |
| `data` | `data`, читается обратно как `over.data`. |
| `disabled` | `disabled`. |
| Возвращает `isAllowed` | `isAccepting`. |
| Возвращает `isDragOver`: `{ top, right, bottom, left, center }` | `isOver` (boolean) и `placement`: `{ top, right, bottom, left }` — половины, в которых находится указатель. `center` нет. |
| — | Новое: `id`, `label`, `priority`, `overOverlay`, `overDropAnimation`, `external` (файлы с компьютера). |

### Событие броска {#the-drop-event}

| v2 `IDragEvent` | v3 |
| --- | --- |
| `e.draggedItems` | `e.active.items`: у каждого `{ id, item, data, label, type }`, взятый элемент первым. Списки получают `e.items` и `e.keys`. |
| `e.draggedItems[0].data` | `e.active.data`. |
| `e.draggedItems[i].index`, `.items` | Списки: `e.from`, `{ list, index }`. |
| `e.dropZone`: `items`, `placement`, `data` | `e.over`: `id`, `data`, `element`, `rect`, `accepted`. Списки: `e.to`, `{ list, index }`. |
| `e.hoveredDraggable` | **Нет аналога**: списки сами вычисляют `e.to.index`. |
| `e.helpers.suggestSort()` | Списки записывают бросок; `e.result` содержит новый массив каждого списка, который он меняет. |
| `e.helpers.suggestSwap()` | `behavior: 'swap'` у списка; `e.partner` — элемент, с которым произошёл обмен. |
| `e.helpers.suggestCopy()` | `group: { name, pull: 'clone' }` или клавиша копирования (:kbd{value="Alt"}), вместе с `clone` списка; `e.mode` равен `'copy'`. |
| `e.helpers.suggestRemove()` | `e.source.remove()` в цели или `dropOutside: 'remove'` у списка. |
| `result.sameList` | `e.sameList`. |
| `e.helpers.insertAt`, `removeAt`, `removeIndexes`, `swapAt`, `getInsertSide`, `isAtZoneStart`, `isAtZoneEnd` | **Нет аналога.** Спискам они не нужны; у обычной цели меняйте данные как хотите. |
| `e.provider` | `useDnD()`. |
| — | Новое: `e.pointer`, `e.delta`, `e.position` (куда поставить элемент, брошенный на доску), `e.mode`. |

### Сортировка {#sorting}

| v2 | v3 |
| --- | --- |
| Список на `makeDroppable` с `() => items` | `makeSortableList(listRef, { items })`. |
| Строка на `makeDraggable` с `() => [index, items]` | `makeSortableItem(el, { item: () => props.task })`. |
| Рендерить свой массив | Рендерить возвращённый `items`: черновик, который перестраивается во время драга. |
| `suggestSort('vertical')`, `suggestSort('horizontal')` | `strategy: 'vertical'` (по умолчанию), `'horizontal'` или `'grid'`. |
| Сравнение по ссылке, чтобы найти исходный и целевой массивы, затем присваивание `sourceItems` и `targetItems` | Ничего: бросок записывает каждый список, который меняет. |
| `<TransitionGroup>` | Встроено. `animateChanges: true` анимирует изменения, сделанные не драгом (добавление, удаление, перемешивание). |
| Линия вставки по `isDragOver.top`, `.bottom` | `placeholder: 'indicator'` и `indicator.side` элемента. См. [линию вставки](/docs/guides/sortable-lists#an-insertion-line). |
| `suggestSwap()` | `behavior: 'swap'`. |
| Палитра только для копирования (`suggestCopy()` и флаг `copyOnly`) | `group: { name, pull: 'clone', put: false }`, `sort: false` и `clone`. |
| Зона-корзина с `suggestRemove()` | `makeDroppable(trash, { onDrop: (e) => e.source?.remove() })` или `dropOutside: 'remove'`. |
| Pinia или неизменяемые данные: результат присваиваете сами | `items` как геттер, затем `e.preventDefault()` в `onDrop` и применение `e.result`. См. [управляемые списки](/docs/guides/shared-lists#controlled-lists). |
| Рекурсивное дерево: зона сброса на каждую папку и `applyToTree` | `makeSortableTree`: один контейнер, строки рендерятся плоско со своей глубиной. См. [деревья](/docs/guides/trees). |
| Вложенные группы с `v-model` (зона сброса на каждую группу) | Список внутри списка, все в одной `group`, у каждого `items: defineModel()`. |
| Виртуальные списки: `id` на каждом перетаскиваемом элементе | Передайте черновик виртуализатору, `id: () => props.item.id` на строках. См. [виртуальные списки](/docs/guides/virtual-lists). |

Код до и после — [ниже](#a-sortable-list). Всё о списках — в
[сортируемых списках](/docs/guides/sortable-lists) и [списках с общими элементами](/docs/guides/shared-lists).

### Группы {#groups}

В v2 была одна опция `groups` на всё. v3 разделяет её на две:

| v2 | v3 |
| --- | --- |
| `makeDraggable(el, { groups: ['dev'] })` | `makeDraggable(el, { type: 'dev' })`. |
| `makeDroppable(el, { groups: ['dev'] })` | `makeDroppable(el, { accept: 'dev' })`. |
| `groups: ['dev', 'ops']` на зоне | `accept: ['dev', 'ops']` или функция: `({ active, items, types }) => boolean`. |
| `groups: []` или ничего | `type` или `accept` не заданы. Правила v2 сохраняются: перетаскиваемый элемент без типа подходит под любое правило, а цель без `accept` принимает всё. |
| `groupMatch: 'every'`, `'some'` | `acceptMode: 'all'`, `'some'`. |
| `groups` на зоне списка и его строках | `group: 'board'` у `makeSortableList`. `group: { name, pull, put }` говорит, что может уходить и входить. |
| `groups` у `makeSelectionArea` | `accept`. |

Список без `group` — сам себе группа и не обменивается элементами ни с каким другим списком. В
v2 зона без групп принимала всё. См. [какие драги принимает цель](/docs/guides/drag-and-drop#which-drags-a-target-takes).

### Оверлей {#the-overlay}

| v2 | v3 |
| --- | --- |
| Превью, отрендеренное в провайдере и телепортированное через `previewTo` | Всегда телепортируется: в `body` или в `overlayTo`. |
| Клон: тот же тег, его `innerHTML` и его размер | Глубокий клон: значения полей форм, пиксели `<canvas>`, унаследованные стили и ячейки таблиц переносятся. То, что должно остаться, помечайте `data-dnd-no-clone`. |
| `render: markRaw(Preview)`, который читает `useDnDProvider().entities` | `overlay: Preview`, который получает `items`, `active`, `over`, `accepted`, `status`, `mode` и `to` как пропсы. Без `markRaw`; чтобы переключать его, используйте `shallowRef`. |
| Слот `#preview`, позиционируемый по `preview.position` | Слот `#overlay`: библиотека сама размещает блок и задаёт ему размер. Если ничего не рендерить, используется клон. |
| `useDnDProvider().preview.render.value = …` | Слот `#overlay` или `shallowRef`, переданный как `overlay`. |

### События и решения о броске {#events-and-drop-decisions}

| v2 | v3 |
| --- | --- |
| `events.onSelfDragStart` перетаскиваемого элемента | `useDnDMonitor({ onDragStart })`, с проверкой `active.ids`. Для класса достаточно `isDragging`. |
| `onSelfDragMove` | `onDragMove` монитора. |
| `onSelfDragEnd`, при броске или отмене | `onDragEnd` монитора (бросок) и `onDragCancel`. `onDragSettle` слышит оба, когда оверлей приземлился. |
| `onSelfDragCancel` | `onDragCancel` монитора. |
| `onHover`, `onLeave` перетаскиваемого элемента и его `onDragStart`… для драгов над ним | `makeDroppable` на элементе: `onDragEnter`, `onDragLeave`. Строкам списка ничего не нужно. |
| `events.onEnter`, `onLeave` зоны сброса | `onDragEnter`, `onDragLeave`. |
| `events.onDrop` зоны сброса | `onBeforeDrop` решает, затем `onDrop` применяет. `onDrop` синхронный, и то, что он возвращает, игнорируется. |
| `events.onValidate` зоны сброса | `onBeforeDrop`, с `acceptMode: 'some'`. |
| — | Новое: `@drag-start` … `@drag-settle` провайдера и `onDragOver`, `onBeforeDrop` и `onDragResume` монитора. |

В v2 `onDrop` мог вернуть значение или промис значения, чтобы решить судьбу броска. В v3 это
работа `onBeforeDrop` — у списков, деревьев, целей и мониторов:

| v2: `onDrop` возвращает | v3: `onBeforeDrop` возвращает |
| --- | --- |
| Ничего или `true`: бросок проходит | `'accept'`, `true` или ничего. |
| `false`: этот бросок отклонён, драг остаётся активным | `'continue'`. **Теперь `false` отклоняет бросок.** |
| Отклонённый промис или исключение: драг отменяется | `'reject'` или `false`. Исключение тоже отклоняет. |
| Промис; тем временем `state` равен `'pending'` | Промис; тем временем `status` равен `'dropping'`, а оверлей ждёт с `data-dnd-overlay="dropping"`. |
| `onValidate` возвращает `IDragItem[]` | Массив id: бросаются только они, остальные летят обратно. |

Сначала отвечают мониторы, затем цель. Потом выполняется `onDrop` цели, список записывает свои
новые массивы, и следует `onDragEnd`. Подробнее — в [решении о броске](/docs/guides/drop-decisions)
и в [API событий](/docs/api/events).

### Перетаскиваемый элемент и зона сброса {#a-draggable-and-a-drop-zone}

**v2**

```vue [Card.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ card: Card }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  groups: ['task'],
  dragHandle: '.handle',
  data: () => props.card,
});
</script>

<template>
  <div ref="el" tabindex="0" :class="{ dragging: isDragging }">
    <span class="handle">⋮⋮</span>
    {{ card.title }}
  </div>
</template>
```

```vue [Zone.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const emit = defineEmits<{ drop: [cards: Card[]] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragOver, isAllowed } = makeDroppable(el, {
  groups: ['task'],
  events: {
    onDrop: (e) => emit('drop', e.draggedItems.map((item) => item.data as Card)),
  },

</script>

<template>
```

**v3**

```vue [Card.vue]
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">

    {{ card.title }}
  </div>
</template>
```

```vue [Zone.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const emit = defineEmits<{ drop: [cards: Card[]] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  accept: 'task',
  onDrop: (e) => emit('drop', e.active.items.map((item) => item.data as Card)),
});
</script>
```

- Карточка сама получает `tabindex`, `role` и атрибуты `aria-*`. Ручка-`<button>` получает
  фокус, и драги с клавиатуры начинаются с неё.
- `groups` стал `type` у перетаскиваемого элемента и `accept` у цели. Колбэки ушли из объекта
  `events`.
- `isOver` без `isAccepting` — это цель, которая отказывает драгу: бросок туда летит обратно.

### Сортируемый список {#a-sortable-list}

**v2**

```vue [TaskList.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable, type IDragEvent } from '@vue-dnd-kit/core';
import TaskItem from './TaskItem.vue';

<template>
  <div ref="el">

    </TransitionGroup>
  </div>

```

### Списки с общими элементами {#lists-that-share-items}

**v2**

```ts [Board.vue]
// Each column's makeDroppable calls this from its onDrop, with its array as the payload.
function applySort(e: IDragEvent) {
  const r = e.helpers.suggestSort('vertical');
  if (!r) return;

  const src = e.draggedItems[0]?.items;
  const tgt = e.hoveredDraggable?.items ?? e.dropZone?.items;

  if (src === todo.value) todo.value = r.sourceItems as Task[];
  else if (src === done.value) done.value = r.sourceItems as Task[];

  if (!r.sameList) {
    if (tgt === todo.value) todo.value = r.targetItems as Task[];
    else if (tgt === done.value) done.value = r.targetItems as Task[];
  }
}
```

**v3**

```vue [Column.vue]
const el = useTemplateRef<HTMLElement>('el');

const { items } = makeSortableList(el, {
  id: props.column.id,                   // `from.list` and `to.list` in drop events
  items: toRef(props.column, 'tasks'),   // writable: the parent passes a reactive column
  group: 'board',                        // same name: tasks move between these lists
});
</script>

<template>
  <ul ref="el">
    <TaskItem v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [Board.vue]

import { reactive } from 'vue';
import Column from './Column.vue';

const columns = reactive([
  { id: 'todo', tasks: [{ id: 't1', title: 'Write the docs' }] },
  { id: 'done', tasks: [] },

</script>

<template>
  <Column v-for="column in columns" :key="column.id" :column="column" />
```

Бросок записывает оба массива: тот, который задача покинула, и тот, в который вошла.
`TaskItem.vue` — тот же, что в сортируемом списке выше. Палитра, которая раздаёт копии, была
`suggestCopy()` и флагом `copyOnly`; теперь это список:

```ts [Palette.vue]
makeSortableList(el, {
  items: blocks,
  group: { name: 'board', pull: 'clone', put: false },  // copies go out, nothing comes in
  sort: false,                                          // its own order stays
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),
});
```

Для стора Pinia или другого состояния, которое вы не записываете напрямую, передайте `items`
геттером, вызовите `e.preventDefault()` в `onDrop` и примените `e.result`: см.
[управляемые списки](/docs/guides/shared-lists#controlled-lists).

  первым), `over`, `accepted`, `status`, `mode` и `to`. Объявляйте только те, которые читаете.
  Для строк списка элемент списка — это `items[0].item`.
- Передавайте его как есть. Переключайте его через `shallowRef`, никогда не через глубокий `ref`.

Слот провайдера меняется так же, и ваш компонент больше не позиционирует себя сам:

**v2**

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #preview>
    <MyOverlay />  <!-- moved itself with useDnDProvider().preview.position -->
  </template>
</DnDProvider>
```

**v3**

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, over, accepted }">
    <MyOverlay :items="items" :over="over" :accepted="accepted" />
  </template>
</DnDProvider>
```

Появление, которое оборачивало `DragPreview` в `<Transition>`, становится `overlay-class` с
`@starting-style`: см. [подъём, наклон, посадку](/docs/guides/animations#the-overlay-lift-tilt-settle).

### Бросок, который вы подтверждаете {#a-drop-you-confirm}

**v2**

```ts [Zone.vue]
makeDroppable(el, {
  events: {
    onDrop: (e) =>
      new Promise<void | boolean>((resolve) => {
        if (!window.confirm('Drop here?')) return resolve(false); // keep dragging
        place(e.draggedItems);
        resolve();
      }),
  },
});
```

**v3**

```ts [Zone.vue]
makeDroppable(el, {
  onBeforeDrop: () => (window.confirm('Drop here?') ? 'accept' : 'continue'),
  onDrop: (e) => place(e.active.items),
});
```

Список спрашивает так же, а промис позволяет открыть собственный диалог. Оверлей ждёт там, где
его отпустили, пока промис не завершится:

```ts [Column.vue]
makeSortableList(el, {
  items: toRef(props.column, 'tasks'),
  group: 'board',
  // `ask` opens a dialog and resolves 'accept', 'continue' or 'reject'.
  onBeforeDrop: (e) => (e.sameList ? 'accept' : ask(e)),
});
```

Зона, которая брала только подходящую часть смешанного выделения (`groupMatch: 'some'`):

**v2**

```ts [Zone.vue]
makeDroppable(el, {
  groups: ['frontend'],
  groupMatch: 'some',
  events: {
    onDrop: (e) => place(e.draggedItems), // only the items of the group arrive
  },
});
```

**v3**

```ts [Zone.vue]
import type { DragItem } from '@vue-dnd-kit/core';

const fits = (item: DragItem) => item.type.length === 0 || item.type.includes('frontend');

makeDroppable(el, {
  accept: 'frontend',
  acceptMode: 'some',
  onBeforeDrop: (e) => e.active.items.filter(fits).map((item) => item.id), // the others fly back
  onDrop: (e) => place(e.active.items.filter(fits)), // `active.items` still lists every dragged item
});
```

Списки делают это без кода: с `acceptMode: 'some'` элементы, которые принимает их `group.put`,
приземляются, а остальные летят обратно.

## Подводные камни при обновлении {#pitfalls-when-upgrading}

- **Ставьте v3 с её диапазоном.** `^3` в `package.json`: `npm update` оставляет `^2` на v2.
- **Рендерите черновик.** Список рендерит `items`, который возвращает `makeSortableList`, а не
  ваш массив. Если рендерить ваш массив, до броска ничего не двигается.
- **Не сортируйте дважды.** Удалите из списков код с `suggestSort`: список записывает каждый
  бросок в записываемый ref `items` после своего `onDrop`. Чтобы применить его самим, вызовите
  `e.preventDefault()` и используйте `e.result`.
- **`false` отклоняет бросок.** В v2 `onDrop`, разрешившийся в `false`, продолжал драг. В v3
  верните `'continue'` из `onBeforeDrop`. Промис, возвращённый из `onDrop`, игнорируется.
- **Списки обмениваются только внутри `group`.** Список без неё не обменивается ни с каким
  другим списком.
- **Задавайте строкам ключи по id.** С `:key="index"` анимируются не те строки. Передавайте и id
  из своих данных: id по умолчанию новый для каждого экземпляра компонента.
- **Никакого `<TransitionGroup>` и никакого `transition` на `transform`.** Библиотека двигает
  строки сама, и перемещения анимировались бы дважды.
- **Отмените обходное решение для касаний.** `touch-action: none` на элементе целиком не даёт
  странице прокручиваться под пальцем; v3 вместо этого начинает драги касанием с долгого
  нажатия. Оставьте его на ручке, которая должна тащить сразу, с
  `activation: { touch: { distance: 4 } }`.
- **Уберите устаревшие атрибуты.** Библиотека ставит `tabindex`, `role` и нужные ей `aria-*` и
  никогда не перезаписывает ваши, так что оставшиеся `role` или `aria-grabbed` останутся такими,
  какими вы их оставили.
- **Перестилизуйте оверлей.** `.dnd-kit-preview` больше нет: стилизуйте то, что внутри
  `[data-dnd-overlay='dragging']`, но никогда не `transform` блока. Дайте корню компонента
  оверлея `width: 100%; height: 100%` и уберите `<DragPreview />` из своих лейаутов.
- **Автоскролл включён.** Передайте `:auto-scroll="false"` там, где v2 никогда не прокручивала.
- **Рамке не нужна клавиша.** `makeSelectionArea` рисует от простого нажатия на пустом месте.
  Добавьте `modifier`, чтобы сохранить Ctrl из v2.
- **Один провайдер, области внутри.** Элементы не могут переходить между провайдерами.
  Странице, которая использовала провайдер на каждую область, чтобы разделить их правила, нужен
  один провайдер и `makeDragArea` на каждую область.
- **Два аргумента.** `makeDraggable` и `makeDroppable` принимают ref и объект опций, без
  данных (payload).
