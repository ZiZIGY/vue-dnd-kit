切换轴、网格和边界，然后拖动一张便签。面板为每一次从它上面开始的拖拽设定规则，每张便签都停在你放下的地方。

## 锁定轴向 {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` 只水平移动，`'y'` 只垂直移动。`makeDraggable`、`makeSortableList`、`makeSortableTree`、`makeSortableItem` 和 `makeDragArea` 都接受这个选项。

- 锁定在**所有修饰器之后**执行，所以无论修饰器做什么，锁定都成立：吸附或边界都无法把项推离它的轴线。
- 项自身的 `axis` 优先于其列表或树的，可拖拽元素（或其列表）的优先于其拖拽区域的。
- 它在拖拽开始时读取，所以可以用 getter 来切换：`axis: () => (locked.value ? 'y' : undefined)`。
- 锁定为 `'y'` 的树仍然可以嵌套：此时深度来自悬停在某一行的中间。

::tip
优先使用 `axis`，而不是 `restrictToVerticalAxis` 和 `restrictToHorizontalAxis` 修饰器。它们效果相同，但作为普通修饰器，它们在链条中间运行，排在它们之后的修饰器（比如同时吸附两个轴的网格）可能又把项移离轴线。
::

## 修饰器 {#modifiers}

修饰器在每一帧调整拖拽的偏移量。它的结果既用于移动浮层，**也**是查找目标的点，所以列表会按锁定、限制或吸附之后的位置排序。

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| 修饰器 | 作用 |
| --- | --- |
| `restrictToVerticalAxis` | 只垂直移动。优先使用 `axis: 'y'`。 |
| `restrictToHorizontalAxis` | 只水平移动。优先使用 `axis: 'x'`。 |
| `restrictToWindowEdges` | 把浮层限制在窗口内。 |
| `restrictToParent` | 把浮层限制在拖拽开始时所在的容器内：可排序列表，或普通可拖拽元素的父元素。 |
| `restrictToElement(target)` | 把浮层限制在某个元素内：模板引用、getter 或元素本身。 |
| `restrictToFirstScrollableAncestor` | 把浮层限制在被拖拽元素的第一个可滚动祖先内。 |
| `snapToGrid(size)` | 把浮层吸附到网格上（见下文）。 |
| `snapCenterToCursor` | 让浮层的中心对准指针，而不是保持抓取时的偏移。 |

`modifiers` 是 provider、拖拽区域、列表和树、可拖拽元素和可排序项的选项。除了 provider 的之外，其他的都还可以接收 ref 或 getter，在拖拽开始时读取。

### 吸附到网格 {#snap-to-a-grid}

`snapToGrid(24)` 把两个轴都吸附到 24 px 的格子上。用对象可以设置更多：

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| 选项 | 含义 |
| --- | --- |
| `x`、`y` | 每个轴的格子尺寸，单位为像素。 |
| `origin` | `'container'`（默认）：浮层的左上角落在从容器左上角开始绘制的网格线上——容器是可排序列表，或普通可拖拽元素的父元素。`'delta'`：对偏移量本身取整，因此一开始不在网格上的项会一直不在网格上。 |
| `smooth` | `true` 或 `{ duration, easing }`：浮层在格子之间平滑滑动（默认 80 ms）。目标会立即使用吸附后的位置。 |

### 自定义修饰器 {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

修饰器接收 `transform`，即经过它之前的修饰器处理后、相对拖拽起点的偏移量，并返回一个新的偏移量。它还会收到计算时可能需要的信息：`activeRect`（拖拽开始时的被拖拽元素）、`overlayRect`（按 `transform` 移动后的浮层）、`containerRect`、`windowRect`、`origin`（开始时的指针）、`active` 和 `over`。参见[修饰器](/docs/api/modifiers)。

## 执行顺序 {#the-order}

来自多个地方的修饰器依次运行，每一个都基于前一个的结果：

1. provider 的 `modifiers`；
2. 拖拽开始时所在拖拽区域的 `modifiers`；
3. 被拖拽项自己的 `modifiers`，没有的话则是其列表或树的；
4. 拖拽区域的 `restrictToArea`；
5. `axis` 锁定。

项的 `modifiers` 会**替换**其列表的，而不是追加。区域的边界在第 1–3 步的吸附之后应用，所以吸附后的项仍然留在区域内，而轴锁定排在最后。

## 有边界的列表仍能到达两端 {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

指针继续移动时，边界会把浮层挡在盒子的边缘。一旦指针沿列表轴向离开了浮层，列表就改为按指针排序，因此无论你怎样抓着项，第一个和最后一个位置都能够到。网格仍按浮层排序：浮层被挡在边缘时，已经覆盖了边缘的格子。

## 页面某一部分的规则 {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` 为**在其元素内部开始**的拖拽设定规则——普通可拖拽元素和可排序项都一样。整个应用保留一个 `DnDProvider`，给面板、画布或信息流各自一个区域。

| 选项 | 作用 |
| --- | --- |
| `axis` | 把拖拽锁定在一个轴上。可拖拽元素自身的 `axis`，或其列表的，优先。 |
| `modifiers` | 在 provider 的之后、可拖拽元素自己的之前运行。 |
| `restrictToArea` | `true`：拖拽保持在区域的元素内。 |
| `autoScroll` | 区域的滚动容器（该元素，或离它最近的可滚动祖先）的自动滚动。`false` 在那里关闭自动滚动。 |
| `activation` | 按指针类型设置的[激活](/docs/guides/sensors#activation-constraints)。可拖拽元素自己的优先；provider 的排在最后。 |
| `disabled` | 区域内不会开始任何拖拽，其内部的区域也一样。区域中的可拖拽元素会报告 `aria-disabled`。 |

每个选项都接收值、ref 或 getter，在按下或拖拽开始时读取。区域返回 `isDragging`（从这里开始的拖拽正在进行）和 `isAutoScrolling`（自动滚动正在滚动它的容器）。完整参考：[makeDragArea](/docs/api/make-drag-area)。

### 区域如何组合 {#how-areas-combine}

- 拖拽遵循它**开始时所在**的区域，即使离开了也一样。经过一个区域不会改变任何东西，除了它的 `autoScroll`：它适用于每一次滚动其容器的拖拽。
- 嵌套的区域不会合并：最近的那个优先。`disabled` 是例外，它会被继承：关闭的区域也会关闭其内部的区域。
- 碰撞检测、键盘按键和播报仍然是 provider 级的。

::note
为什么不在面板外再包一个 `DnDProvider`？provider 之间相互独立：拖拽永远不会从一个跨到另一个，所以面板中的项永远无法离开它。只有当页面某一部分需要自己的 provider 级设置，并且其中的项都留在里面时，才嵌套 provider。参见 [Provider](/docs/guides/provider)。
::

## 放在哪就停在哪 {#leave-it-where-its-dropped}

示例中的面板同时也是一个放置目标，每张便签都会停在放下的位置。每个拖拽事件都带有 `position`：被拖拽盒子在目标内的左上角，从目标的内边距边缘量起，并计入其滚动量——也就是能把一个绝对定位的项放到那里的 `left` 和 `top`。它在修饰器之后计算，所以吸附后的便签会落在网格上。

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

关于自由拖拽和放置目标的更多内容见[拖放](/docs/guides/drag-and-drop)。
