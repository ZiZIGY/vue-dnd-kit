`@vue-dnd-kit/devtools` 会在 Vue DevTools（`vite-plugin-vue-devtools`）和 Nuxt DevTools 中添加一个 **Vue DnD Kit** 标签页。它在实时小地图中显示页面上的每个列表、树和放置目标，可以用摇杆拖拽任意项，在应用运行时编辑选项，并记录每次拖拽做了什么。它只在开发环境中工作：它的任何部分都不会进入生产构建。

## 安装 {#install}

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` 是 peer dependency：标签页中的移动操作都通过它完成。npm 7+ 和 pnpm 会自动安装它；使用 Yarn 1 时需要手动添加。

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

使用 Vite 时，插件在 `/__vue-dnd-kit-devtools/` 提供这个标签页，把它添加到 Vue DevTools 中，并让页面在你的应用启动之前开始向它报告。不需要 `app.use()`。它只作用于开发服务器（`vite serve`）；构建不受影响。

使用 Nuxt 时，`@vue-dnd-kit/nuxt` 模块会找到这个包，提供标签页，把它添加到 Nuxt DevTools 中，并通过一个客户端插件安装页面一侧的部分。`vueDndKit: { devtools: false }` 可以关闭它。

### 不使用插件 {#without-the-plugins}

对于你自己的开发服务器，或者 Vite 不通过 `index.html` 提供的页面（SSR 配置），自己安装页面一侧的部分：

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

或者在入口文件中最先导入 `@vue-dnd-kit/devtools/auto`。如果希望插件提供标签页、而页面一侧由你自己安装，使用 `vueDnDKitDevtools({ inject: false })`；`@vue-dnd-kit/devtools/vite` 中的 `serveTab()` 就是提供标签页的中间件。

## 打开它 {#open-it}

- **Vue DevTools**：:kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"}，或页面底部的 Vue 按钮，然后打开 **Vue DnD Kit** 标签页。
- **Nuxt DevTools**：:kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"}，或 Nuxt 按钮，然后打开 **Vue DnD Kit**（在侧边栏或其溢出菜单中）。
- **独立窗口**：在开发服务器上打开 `http://localhost:5173/__vue-dnd-kit-devtools/`，或点击标签页的 ⧉ 按钮。放在第二块屏幕上很方便。

::warning
把标签页放在独立的窗口中，而不是浏览器的后台标签页里：隐藏的页面会取消拖拽。
::

## 标签页显示什么 {#what-the-tab-shows}

### 小地图 {#the-mini-map}

每个列表、树和放置目标对应一张实时卡片，其中的项副本位于它们所在的位置——与浮层会显示的克隆相同。拖拽期间，它会标出接收这次拖拽的列表（蓝色）或拒绝它的列表（红色）、占位、指针下方的目标、浮层的盒子，以及 `placeholder: 'indicator'` 列表的插入线。单击选中一个项；双击会把页面滚动到它所在的位置。

当放置没有落到你预期的地方时就用它：一眼就能看出哪些列表接收这次拖拽。

### 操控：摇杆 {#drive-the-joystick}

选中一个项——在地图上、在树中，或用 **Pick**（它会捕获页面上的下一次按下）——然后推动摇杆的旋钮。项会被拿起并朝那个方向移动，旋钮离中心越远，移动越快。**Drop** 和 **Cancel** 结束拖拽。

这是一个名为 `devtools` 的传感器发起的真正的指针拖拽，所以列表会排序，容器会自动滚动，`onBeforeDrop` 和 `onDrop` 也会像任何拖拽一样运行。可排序列表的项还会有按钮：上移、下移、移到开头、移到末尾、移到同一分组的另一个列表。

| 按键（在标签页中） | 作用 |
| --- | --- |
| 方向键或 :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | 朝那个方向推动旋钮；按住 :kbd{value="Shift"} 时推到底 |
| :kbd{value="G"} | 拿起选中的项 |
| :kbd{value="Space"} / :kbd{value="Enter"} | 放下 |
| :kbd{value="Escape"} | 取消 |
| :kbd{value="P"} | 在页面上选取 |

### 选项 {#options}

每个不是回调的选项都可以在应用运行时编辑：provider 的（`collision`、`modifiers`、`overlayFit`、`autoScroll`、动画、`activation`、`keyboard`……）、列表的（`strategy`、`placeholder`、`behavior`、`multiple`、`dropOutside`、`disabled`……）、树的、放置目标的和项的。选中节点，然后打开 **Options**。

编辑会立即生效，只作用于当前页面，并且永远不会写入你的代码。它会一直保持，直到你重置它、provider 卸载或页面重新加载。

### 状态 {#state}

每个 provider 所知道的一切，以树的形式展示：它的拖拽会话（状态、当前 id 和传感器、目标以及目标是否接收、指针）、它的列表和树及其顺序和草稿、放置目标及其规则，以及项的类型和数据。

### 日志 {#log}

每次拖拽一组记录：开始（id、传感器、来源列表）、每次 `over` 和 `left` 以及是否被接收、松开、`onBeforeDrop` 的裁决——接受、部分接受、被钩子拒绝、被目标的 `accept` 拒绝——以及 `drop`，带有 `e.result` 和是否调用了 `preventDefault()`，或者 `cancel` 及其原因。点击一个条目可以查看它的数据。

当放置被拒绝而你不知道是被什么拒绝的，或者受控列表没有变化时，就用它：日志会告诉你 `preventDefault()` 是否运行过，以及 `e.result` 中是什么。

## 工作原理 {#how-it-works}

provider 向页面一侧安装的一个钩子报告。在有标签页监视页面之前，它们只会被记录下来；之后页面会像任何监听器一样进行监听，并把标签页要显示的内容发送给它——拖拽期间每 40 ms 一次，其他时候每秒两次——在几秒钟内没有标签页监视后就会停止。标签页通过页面所在源的 `BroadcastChannel` 与页面通信。除了你要求的操作之外，它不会改变任何东西：拖拽、选中集合和选项覆盖。
