把一张卡片拖进 **Done**。放置会等待你的回答：移动这张卡片、继续把它拖到别处，或者取消。

::example{name="drop-confirm" hint="把一张卡片拖进 Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

列表、树、放置目标（`makeDroppable`）和监听器（`useDnDMonitor`）都接受 `onBeforeDrop`。它在拖拽被松开时、任何东西发生变化之前运行，它的返回值决定结果：

| 返回值 | 结果 |
| --- | --- |
| `'accept'`、`true` 或不返回 | 放置生效。 |
| `'reject'` 或 `false` | 不放置：项飞回原处。抛出错误也视为拒绝。 |
| key 数组 | 只有这些项被放下；其他项飞回原处。 |
| `'continue'` | 不放置，拖拽继续。 |
| 以上任意值的 Promise | 浮层停在松开的位置等待，直到 Promise 完成。 |

目标自身的规则优先：放置目标的 `accept`、列表的 `group.put`。在拒绝这次拖拽的目标上方，放置会被取消，也不会询问该目标的 `onBeforeDrop`。`onBeforeDrop` 用于处理这些规则无法得知的事情：用户的回答、服务器的回答，或这次放置会改变什么。

列表和树传入的是 `SortableDropEvent`：`keys`、`items`、`from`、`to`、`mode`、`sameList` 和 `result`，即这次放置改变的每个列表的新数组。放置目标和监听器收到的是通用的 `DnDEvent`：`active`、`over`、`position` 和 `source`。参见[事件](/docs/api/events)。

### 只接受部分项 {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

在[多项拖拽](/docs/guides/multi-drag)中，你返回的 key 对应的项会落下，其余的飞回原来的位置。随后 `onDrop` 会在 `e.accepted` 和 `e.rejected` 中看到它们，它的 `e.result` 是最终结果。

## 继续拖拽：'continue' {#keep-dragging-continue}

`'continue'` 取消的是放置，而不是拖拽。项从原处继续留在“手中”，页面回到拖拽模式，用户可以接着拖：

- 使用鼠标或触控笔时，项会跟随指针，不需要按住按键。下一次松开——也就是一次点击——会放下它，而且这次点击永远不会传到下面的页面。
- 使用触摸时，手指落下的地方会重新拿起项；抬起手指即放下。
- 键盘拖拽会继续：方向键移动项，:kbd{value="Space"} 或 :kbd{value="Enter"} 放下它。
- :kbd{value="Escape"} 会取消它，与任何拖拽一样。
- 下一次放置会再次询问 `onBeforeDrop`。

监听器会收到 `onDragResume`，屏幕阅读器会播报这个项没有被放下、仍在移动中（可以用 provider 的 `announcements.onDragResume` 覆盖这段文本）。

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## 询问用户 {#asking-the-user}

`onBeforeDrop` 可以返回一个 Promise。打开一个对话框，用用户点击的按钮来 resolve 这个 Promise：

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

在 Promise 等待期间：

- 浮层停在松开的位置等待，并标记为 `data-dnd-overlay="dropping"`；
- `useDnD()` 保持松开时的状态，`status` 为 `'dropping'`；
- 页面退出拖拽模式：光标和文本选择恢复正常，所以对话框可以照常使用。

::tip
用 `showModal()` 打开的模态 `<dialog>` 位于顶层，在等待中的浮层之上。像示例那样，把它的 `cancel` 事件（:kbd{value="Escape"}）转换为 `'reject'`。
::

## 钩子的执行顺序 {#the-order-of-the-hooks}

1. 依次调用每个 `useDnDMonitor` 的 `onBeforeDrop`。`'reject'` 或 `'continue'` 会结束询问；返回 key 会缩小放置范围。
2. 目标的 `onBeforeDrop`：项要进入的列表或树，或者放置目标。
3. 只调用目标的 `onDrop`：项离开去往另一个列表的那个列表不会被询问，它的新数组在目标的 `e.result` 中。当项被移除时（回收区、`dropOutside: 'remove'`），会运行它们所在列表的 `onDrop`，`to.index` 为 `-1`。
4. 默认写入：这次放置改变的每个列表获得它的新数组。
5. 浮层落位。随后是 provider 的 `@drag-end` 和监听器的 `onDragEnd`。

你的监听器在目标之前做决定，所以它们的否决永远不会出现在某个列表已经自行应用了放置之后。

## onDrop：在写入之前收到通知 {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

列表的 `onDrop` 在放置被接受后同步运行，紧接在列表写入之前。如果要在写入之后执行操作，使用 provider 的 `@drag-end` 或 `useDnDMonitor({ onDragEnd })`。对于普通放置目标，`onDrop` 就是你修改数据的地方：库不会为它移动任何东西。

## Store 与服务器：受控列表 {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

库只会把放置结果写入可写的 ref。getter、`computed` 或 `readonly` ref 永远不会被写入：调用 `e.preventDefault()`，自己应用 `e.result`——即这次放置改变的每个列表的新数组，以列表 id 为键。`preventDefault()` 会跳过对所有这些列表的写入，因为只写入其中一部分会丢失或重复项。如果只读列表的放置被留给库处理，开发构建会发出警告。

### 先保存到服务器 {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

在 Promise resolve 之前应用 `e.result`，浮层就会按新的顺序落位。请求失败时，什么都不应用：放置照常完成，但不改变任何东西，项飞回原处。

## 放在所有目标之外 {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | 放在所有目标之外时…… |
| --- | --- |
| `'placeholder'` | 落到占位所在的地方：列表最后显示的位置。这是默认值。 |
| `'cancel'` | 被取消：项飞回原处。使用 `placeholder: 'indicator'` 时的默认值。 |
| `'remove'` | 把项从它们的列表中移除。会先询问列表的 `onBeforeDrop`，它的 `onDrop` 收到的 `to.index` 为 `-1`。 |

回收区是有意做同样的事情：`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`。参见[拖放](/docs/guides/drag-and-drop)。
