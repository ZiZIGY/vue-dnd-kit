## 选中集合 {#the-selection}

每个 provider 保存一个选中集合：一个响应式的 id 集合。拖拽一个**已选中**的项会拖拽所有选中项，抓起的那个在最前。拖拽一个未选中的项则只拖拽它自己。

库不决定用户如何选择：点击规则由你来定。库也从不自行清空选中集合，而且选中集合在组件卸载后依然保留，比如虚拟列表回收的那些行。

### 点击：Ctrl/Cmd 和 Shift {#clicks-ctrlcmd-and-shift}

每个可排序项和可拖拽元素都返回 `selected`，这是一个绑定到选中集合的可写 ref。把它绑定到 class、复选框（`v-model="selected"`），或在点击处理函数中设置它：

```vue [FileItem.vue]
<script setup lang="ts">
const { selected } = makeSortableItem(el, { item: () => props.file });
</script>

<template>
  <li ref="el" class="file" :class="{ selected }" @click="emit('pick', $event)">…</li>
</template>
```

演示中的列表掌管这些规则：单击选中一个文件，Ctrl/Cmd 单击添加或移除一个，Shift 单击选中从上次点击的文件开始的一段：

```ts [Files.vue]
const { selection } = useDnD();
let anchor: string | null = null;

const pick = (id: string, event: MouseEvent) => {
  const ids = items.value.map((file) => file.id);
  if (event.shiftKey && anchor) {
    const [a, b] = [ids.indexOf(anchor), ids.indexOf(id)];
    selection.set(ids.slice(Math.min(a, b), Math.max(a, b) + 1));
    return;
  }
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
  anchor = id;
};
```

结束拖拽的那次点击不会触发 `@click`，所以放置永远不会意外改变选中集合。项的操作请用 `@click`，而不是 `pointerup`。

### 在任何地方：`useDnD().selection` {#from-anywhere-usedndselection}

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

选中集合以 id 为键，所以它可以包含多个列表的项，也可以包含普通可拖拽元素：一次拖拽会带上 provider 之下的所有选中项。

## 框选 {#rubber-band-selection}

`makeSelectionArea` 把一个元素变成一块区域：在空白处按下会画出选框，选框经过的项会被选中。在这个桌面上，围着几个图标画一个选框，然后拖动其中一个：

::example{name="multi-select" hint="在空白桌面上画一个框，然后拖动一个选中的图标" height="29rem"}
::

```vue [Desktop.vue]
<script setup lang="ts">
const desktop = useTemplateRef<HTMLElement>('desktop');
const { isSelecting, style } = makeSelectionArea(desktop, {
  strategy,                                                          // 'toggle' or 'select'
  modifier: () => (withShift.value ? { keys: ['Shift'], method: 'every' } : undefined),
});
</script>

<template>
  <!-- The area needs a position: the band is placed inside it. -->
  <div ref="desktop" class="desktop">
    <DesktopIcon v-for="icon in icons" :key="icon.id" :icon="icon" :offset="offset" />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.desktop { position: relative; height: 236px; }
.band { border: 1px solid #42b883; background: color-mix(in srgb, #42b883 15%, transparent); }
</style>
```

- 选框由你渲染：`style` 相对于区域的内容来定位它。
- 区域需要一个**非 static 的定位**（`relative` 即可），否则选框会出现在别的地方。
- 选框只能从区域本身开始，所以要让区域足够大：整个面板，项的周围留有空间，而不是一个紧贴的包裹元素。
- 在项上按下会拖拽它。按钮、输入框和区域的滚动条保留它们自己的按下行为。
- 区域或页面滚动时，选框始终锚定在内容上。:kbd{value="Escape"} 取消它并恢复选中集合。
- 画选框期间，`useDnD().status` 为 `'selecting'`：桌面下方的那行文字读取的就是它。

| 选项 | 作用 |
| --- | --- |
| `strategy` | `'toggle'`（默认）：选框经过的项切换选中状态。`'select'`：最终只有选框内的项被选中，所以点击空白处会取消选中该区域的项。 |
| `modifier` | 画选框时必须按住的键：`{ keys: ['Shift'], method: 'every' }`（或 `'some'`）。 |
| `accept` | 选框选中哪些可拖拽元素，是一条与它们的 `type` 匹配的 [accept 规则](/docs/guides/drag-and-drop#which-drags-a-target-takes)。 |
| `disabled` | 不能画选框；开启时会取消正在进行的选框。 |
| `onSelected(ids)` | 选框结束时调用，传入选中集合。 |
| `selection` | 用你自己的 `Ref<Set<Key>>` 代替 provider 的选中集合。 |

`strategy`、`modifier` 和 `disabled` 接受值、ref 或 getter，在按下开始选框时读取。区域嵌套时，由最内层的区域接收按下。所有选项见 [makeSelectionArea API](/docs/api/make-selection-area)。

这些图标是普通可拖拽元素（`makeDraggable`），所以浮层是它们叠成的一叠，抓起的图标在最上面，其他图标留在原处。这里让它们跟着移动：一个监听器把拖拽的 `delta` 交给它们，放置时把每个图标都移动这么多。

```ts [Desktop.vue]
useDnDMonitor({
  onDragMove: ({ delta }) => (offset.value = delta),    // DesktopIcon: `translate` by it while it is dragged
  onDragCancel: () => (offset.value = null),
  onDragEnd({ active, delta, over }) {
    offset.value = null;
    if (over?.id !== 'desktop') return;
    for (const icon of icons.value) {
      if (!active.ids.includes(icon.id)) continue;
      icon.x += delta.x; // the demo also keeps each icon on the desktop
      icon.y += delta.y;
    }
  },
});
```

### 放进文件夹 {#into-a-folder}

在这个窗口里，选框选中文件，文件夹接收它们。浮层是默认的那个：选中文件叠成的一叠。放进文件夹后，它们一个接一个进去，抓起的那个最后进去，文件夹把它们一口吞下。取消时，每个都飞回自己的文件。单击文件夹可以打开它，也可以把文件拖回路径中的 Home。

::example{name="multi-finder" hint="框选几个文件，把它们拖到一个文件夹上" height="33rem"}
::

```vue [index.vue]
<!-- Every picked file gets a clone at pickup: they all go in. -->
<DnDProvider overlay-previews="all">
  <Finder />
</DnDProvider>
```

```ts [FolderTile.vue]
makeDroppable(el, {
  id: () => props.folder.id,
  accept: 'file',
  onDrop: (event) => emit('move', event.active.ids),
});

// The files are in: the folder gulps.
useDnDMonitor({
  onDragSettle: (event) => {
    if ('dropped' in event && event.over?.id === props.folder.id) gulps.value++;
  },
});
```

这就是全部：文件随放置离开窗口，所以除了文件夹，它们无处落位，而默认的放置动画会把多项拖拽一项接一项地送进区域。`overlayPreviews` 决定拿起时有多少项获得克隆（默认 5 个）。每个克隆都会飞：飞进区域、飞到自己的位置，或飞回自己的项。

文件夹是一个按钮：选框从不在按钮和输入框上开始，所以单击会打开它。

## 其他项如何移动：`multiple` {#how-the-other-items-move-multiple}

多项拖拽从哪个列表开始，就由哪个列表决定拖拽期间其他选中项的表现。在本页第一个演示中切换它：

```ts
makeSortableList(listRef, { items: files, multiple: 'gaps' });
```

| `multiple` | 拖拽期间 | 浮层 |
| --- | --- | --- |
| `'group'`（默认） | 其他项离开原位，作为一整块位置随抓起的项一起移动，所以列表已经显示出放置的结果。 | 沿列表方向排列的一列被拖拽项（最多 `overlayPreviews` 个）。 |
| `'gaps'` | 其他项留在原处，被标记为 `data-dnd-dragging`，直到放置。 | 同样的一列。 |
| `'stack'` | 其他项飞进浮层。 | 抓起的项和一个计数。 |

放置时，这些项按原有顺序一起落到目标索引处。在 `'group'` 和 `'gaps'` 中，浮层中的每个项都会飞到自己的位置。该选项在拖拽开始时读取，所以用 ref 或 getter 就能切换它。

为 `'gaps'` 中留下的项设置样式，它们默认会被淡化：

```css
.file[data-dnd-dragging] {
  opacity: 0.35;
}
```

在这个播放队列里，选中的歌曲作为一整块移动（`'group'`，默认）：队列已经显示出它们将落在哪里，浮层则显示全部歌曲。悬停在侧边栏的某个播放列表上时，这一整块会变成一个小标签，说明放置将做什么，落位时小标签会变成该播放列表的那一行。

::example{name="multi-playlist" hint="单击一首歌，Shift 单击另一首，把它们沿队列往下拖，或拖到一个播放列表上" height="34rem"}
::

```ts [PlaylistLink.vue]
makeDroppable(el, {
  id: () => props.playlist.id,
  data: () => props.playlist,
  overlay: AddToPlaylist, // leaves its slot, the column of rows, out
  dropAnimation: intoRow, // takes the row's place and size, and fades into it
  onDrop: (event) => emit('add', event.active.ids),
});
```

### 默认浮层 {#the-default-overlay}

在 `'group'` 和 `'gaps'` 中，浮层是被拖拽项按落位顺序排成的一列：抓起的那个在指针下方，其他的按放置顺序排在它前后（横向列表中则是一行）。它显示的数量由 provider 的 `overlayPreviews` 决定（默认 5 个，`'all'` 表示每个已渲染的项）。超出的项在它们所在的位置计数：列首的 `+N` 表示落在所显示项之前的项，列尾的 `+N` 表示落在之后的项。

在网格中，一列完整的单元格会盖住页面，所以浮层是一叠：最多三个项在抓起的项后面呈扇形展开，顶部显示总数。把演示切换到 Grid 就能看到。

普通可拖拽元素（`makeDraggable`）也会叠成一叠，就像上面的桌面和文件那样。浮层中的每个克隆都各自落位：放置到列表后落到自己的位置上，取消后回到自己的项上，放置进某个区域时依次飞入该区域，盒子最后进入。

## 只接受一部分 {#taking-only-some}

列表的 `onBeforeDrop` 可以接受多项拖拽的一部分：返回它接受的 key，其余的飞回原处。这里 Scheduled 接受有封面的文章：

::example{name="multi-transfer" hint="把选中的三篇草稿拖进 Scheduled" height="28.5rem"}
::

```ts [PostList.vue]
const { items } = makeSortableList(list, {
  id: props.id,
  items: posts,
  group: 'blog',
  onBeforeDrop: (event) => {
    if (!props.needsCover || event.sameList) return true;
    const ready = event.keys.filter((_, index) => event.items[index]!.cover !== null);
    notice.value = `${ready.length} scheduled`;
    return ready; // the keys it takes; an empty list takes none
  },
});
```

- `event.keys` 是被拖拽的 key，`event.items[i]` 是 `event.keys[i]` 对应的项。
- 返回之后，`onDrop` 会收到 `accepted` 和 `rejected`，`event.result` 是部分放置之后各列表的样子。
- `onBeforeDrop` 可以是异步的：浮层在放置处等待。见[决定放置](/docs/guides/drop-decisions)。

### 上限 {#a-limit}

在这个看板上，In progress 和 Review 的卡片数量设有上限。已满的列什么都不接收：它的 `group.put` 会拒绝，那叠卡片在它上方变红。还能容纳部分选中卡片的列，会接收放得下的那些，其余的飞回原处。该列的浮层会在放置前说明这一点。

::example{name="multi-wip" hint="在 To do 中勾选三张卡片，把其中一张拖到 Review 上方，再拖到 In progress 上方" height="31rem"}
::

```ts [WipColumn.vue]
const room = (keys: Key[]) => limit - column.cards.filter((card) => !keys.includes(card.id)).length;

makeSortableList(list, {
  items: cards,
  group: { name: 'board', put: ({ keys, from, to }) => from === to || room(keys) > 0 },
  multiple: 'stack',
  overlay: CardPile, // red where `accepted` is false
  overOverlay: fit,
  onBeforeDrop: (event) => {
    if (event.sameList) return true;
    const free = room(event.keys);
    return free >= event.keys.length || event.keys.slice(0, free);
  },
});
```

`fit` 是一个函数，Vue 会把它当作函数式组件。它把只有这一列才知道的信息，也就是它还剩多少空位，交给 `FitBadge`，并把那叠卡片作为徽标的插槽传下去。

```ts
const fit: FunctionalComponent<OverlayProps> = (overlay, { slots }) =>
  h(FitBadge, { count: overlay.items.length, room: room(overlay.items.map((item) => item.id)), limit }, slots);
```

### 混合类型 {#mixed-types}

列表也可以在放置之前按类型拒绝部分项。使用 `acceptMode: 'some'` 时，会对每个项单独询问 `group.put`：只要至少有一个项符合，列表就接收这次拖拽，其余的在放置时飞回原处。使用 `'all'`（默认）时，每个项都必须符合。

```ts
makeSortableList(gallery, {
  items: photos,
  group: { name: 'files', put: ({ types }) => types.includes('image') },
  acceptMode: 'some',
});
```

普通放置目标同样接受 `acceptMode`。见[共享项的列表](/docs/guides/shared-lists#limits)和[拖放](/docs/guides/drag-and-drop#which-drags-a-target-takes)。

## 多个项的自定义浮层 {#a-custom-overlay-for-several-items}

浮层组件和 provider 的 `#overlay` 插槽会收到 `items`：所有被拖拽的项，抓起的那个在最前。显示一个摘要而不是项本身：这里是数量、第一封邮件的主题，以及放置将做什么。

::example{name="multi-summary" hint="把勾选的邮件拖到 Archive 或 Trash，或单独拖一封" height="26rem"}
::

```vue [MailOverlay.vue]
<script setup lang="ts">
import { computed } from 'vue';
import type { DragItem, Over } from '@vue-dnd-kit/core';

const props = defineProps<{ items: DragItem[]; over: Over | null }>();

const first = computed(() => props.items[0]?.item as Mail);
const count = computed(() => props.items.length);
const action = computed(() => {
  const noun = count.value === 1 ? 'conversation' : 'conversations';
  if (props.over?.id === 'Archive') return `Archive ${count.value} ${noun}`;
  if (props.over?.id === 'Trash') return `Delete ${count.value} ${noun}`;
  return `Move ${count.value} ${noun}`;
});
</script>

<template>
  <!-- The box keeps the row's size; the summary hangs off its middle, by the pointer. -->
  <div class="box">
    <div class="summary" :class="{ stack: count > 1 }">
      <span class="count">{{ count }}</span>
      <strong>{{ action }}</strong>
      <small>{{ first.subject }}{{ count > 1 ? ` and ${count - 1} more` : '' }}</small>
    </div>
  </div>
</template>

<style scoped>
.box { position: relative; width: 100%; height: 100%; }
.summary { position: absolute; top: calc(50% + 10px); left: calc(50% + 10px); width: 230px; }
</style>
```

```ts [Mailbox.vue]
// The box is centered on the pointer, so the summary hangs off the pointer and leaves
// the zone under it in sight.
const { items } = makeSortableList(list, { items: mails, overlay: MailOverlay, modifiers: [snapCenterToCursor] });

// A zone takes the mails out of the inbox.
makeDroppable(archive, {
  id: 'Archive',
  onDrop: (event) => {
    event.source?.remove();
    selection.clear();
  },
});
```

如果要排布真实的项，用 `DragPreview` 渲染它们的克隆：[浮层指南](/docs/guides/overlay#dragpreview-the-clone-in-your-layout)把一叠书扇形展开。克隆在拿起时生成，针对抓起的项以及按放置顺序紧邻它的其他项，数量为 `overlayPreviews`；对于其他任何项，`DragPreview` 渲染它的默认插槽。在 `'group'` 和 `'gaps'` 中，放置时每个预览都会落到它自己那一项的位置上。

这里选中的照片飞进浮层（`'stack'`），以它们的克隆叠成一叠。悬停在相册上时，相册的浮层保留这叠照片（它的插槽），并在下方说明放置将做什么，这叠照片会落进相册的封面。

::example{name="multi-albums" hint="单击几张照片，然后把其中一张拖到相册上" height="30rem"}
::

```vue [PhotoStack.vue]
<template>
  <div class="stack">
    <div v-for="{ entry, angle } in stack" :key="entry.id" class="card" :style="{ rotate: `${angle}deg` }">
      <DragPreview :id="entry.id" :style="{ width: '100%', height: '100%' }" />
    </div>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>
```

```ts [AlbumCard.vue]
makeDroppable(el, {
  id: () => props.album.id,
  data: () => props.album,
  overlay: AddToAlbum, // <slot /> and "+ Add 3 photos to Favorites" under it
  dropAnimation: intoCover,
  onDrop: (event) => emit('add', event.active.ids),
});
```

## 树 {#trees}

在树中，选中的节点作为一个整体移动，每个都带着自己的子树，按文档顺序排列。位于另一个选中节点之内的选中节点，会随父节点的子树一起移动。见[树](/docs/guides/trees)。
