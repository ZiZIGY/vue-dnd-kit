凡是不属于可排序列表的场景，都用 `makeDraggable` 和 `makeDroppable`：把文件拖进文件夹、垃圾桶、棋盘、日历、面板上的便签。

::example{name="drop-zones" hint="图片放进 Images，文档放进 Documents" height="30rem"}
::

## 可拖拽元素 {#a-draggable}

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

以 getter 的形式传入来自你数据的 id。默认 id 来自 `useId()`，每个组件实例都会生成新的，因此对应用的其他部分没有任何意义。

| 返回值 | 含义 |
| --- | --- |
| `isDragging` | 这个元素正在被拖拽。 |
| `selected` | 可写，绑定到 provider 的[选中集合](/docs/guides/multi-drag)。 |
| `transform` | 拖拽偏移量，用于 `overlay: false`（见下文）。 |
| `id` | 正在使用的 id。 |

按钮、输入框和其他可交互的子元素不会触发指针拖拽，所以它们在可拖拽元素内部照常工作。如果只想通过某一部分拖拽，传入 `handle`（参见[可排序列表](/docs/guides/sortable-lists#handles)）。所有选项见 [makeDraggable API](/docs/api/make-draggable)。

## 放置目标 {#a-drop-target}

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| 返回值 | 何时为 `true` |
| --- | --- |
| `isOver` | 拖拽位于这个目标上方，无论它是否接收这次拖拽。 |
| `isAccepting` | 有东西正在被拖拽，并且这个目标接收它：用来高亮可放置的区域。 |
| `placement` | 不是布尔值：`{ top, right, bottom, left }`，表示指针位于目标的哪一半；未悬停时为 `null`。用它实现“放在这张卡片之前 / 之后”。 |

有 `isOver` 而没有 `isAccepting`，意味着拖拽位于一个拒绝它的目标上方。像上面的文件夹那样把这一点显示出来：在那里放下会被取消，项会飞回原处。

## 目标接收哪些拖拽 {#which-drags-a-target-takes}

可拖拽元素的 `type` 会与目标的 `accept` 进行匹配：

| `accept` | 接收 |
| --- | --- |
| 省略或 `'*'` | 全部。 |
| `'image'` | 类型为 `image` 的可拖拽元素，以及没有类型的。 |
| `['image', 'doc']` | 任一类型，以及没有类型的。 |
| `({ active, items, types }) => boolean` | 由你的函数决定。 |

没有 `type` 的可拖拽元素符合任何字符串规则。其他情况都用函数：

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` 也可以是数组（`['image', 'large']`）：匹配其中一个类型就够了。

同时拖拽多个项时，`acceptMode` 规定需要有多少个符合：`'all'`（默认）或 `'some'`。使用 `'some'` 时，从 `onBeforeDrop` 返回要保留的 id，其他项会飞回原处。参见[决定放置](/docs/guides/drop-decisions)。

## 放置 {#the-drop}

普通放置目标的 `onDrop` 是**你**修改数据的地方。库自己不会移动任何东西：

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| 事件字段 | 内容 |
| --- | --- |
| `active` | 这次拖拽：`id`、`ids`、`items`（每项为 `{ id, data, type, item }`）、`data`、`type`。 |
| `over` | 这个目标：`id`、`data`、`element`、`rect`。 |
| `pointer`、`delta` | 指针的位置，以及它相对起点移动了多远。 |
| `position` | 被拖拽的盒子在这个目标中的位置（见下一节）。 |
| `source` | 当项来自可排序列表时存在：`{ list, remove() }`。 |

执行顺序是 `onBeforeDrop`（决定）、`onDrop`（应用），然后是 provider 的 `drag-end`。如果要在放置前询问、让拖拽继续，或只接收部分项，参见[决定放置](/docs/guides/drop-decisions)。

## 放在哪就停在哪 {#leave-it-where-it-was-dropped}

面板、画布、平面图：项停在你松手的地方。每个事件都带有 `position`，即能把一个绝对定位的项放到放置位置上的 `left` / `top`。

::example{name="constraints" hint="拖动一张便签，然后锁定一个轴或关闭网格" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` 是被拖拽盒子在 `over` 中的左上角：从它的内边距边缘量起，并加上它的滚动量。下方没有目标时为 `null`。使用 `overlay: false` 时，它是元素自身的左上角。

::tip
不要用 `active.rect` 和 `delta` 来计算位置：那样会漏掉目标的边框和滚动量。这类面板的吸附、边界和轴锁定见[约束](/docs/guides/constraints)。
::

## 放进可排序项 {#drop-into-a-sortable-item}

可排序列表的一行也可以是放置目标：接收文件的文件夹、接收任务的分组。在项的元素上添加一个 droppable：

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

当列表本会对这次拖拽进行排序时，这样的目标只在项的**中间部分**生效（沿列表轴向的 25% 到 75%）。在那里放下会放进这个项，列表不会移动。靠近边缘时，列表照常排序。

- `accept` 拒绝这次拖拽的目标会被跳过：列表会像对待其他项一样在它上方排序。只接收文件的文件夹会让文件夹从它旁边排序过去。
- 目标永远不会接收它自己的拖拽。
- 如果放置后这个项不再显示，浮层会缩进目标中，而不是飞回原处。

## 回收区 {#trash-zones}

从可排序列表开始的拖拽带有 `e.source`。调用 `remove()`，列表就会移除这些项：

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

随后列表自己的 `onDrop` 会以 `to.index === -1` 运行，`e.result` 中是去掉这些项之后的列表。列表也可以移除那些放在所有目标之外的项：参见 [`dropOutside`](/docs/guides/shared-lists#dropping-outside)。

## 不使用浮层 {#without-an-overlay}

默认情况下，元素的克隆跟随指针，元素本身留在原处。使用 `overlay: false` 时没有克隆：用 `transform` 自己移动元素。

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

如果要用自定义的拖拽预览代替克隆，参见[浮层](/docs/guides/overlay)。

## 键盘 {#keyboard}

获得焦点的可拖拽元素可以用 :kbd{value="Space"} 或 :kbd{value="Enter"} 拿起。方向键每次移动 25 px（provider 的 `keyboard.step`）。在可拖拽元素上设置 `keyboard: 'droppables'` 后，方向键会改为在接收它的目标之间跳转，适合彼此相距较远的放置区。更多内容见[无障碍](/docs/guides/accessibility)。
