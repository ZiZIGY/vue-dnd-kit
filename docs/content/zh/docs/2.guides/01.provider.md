## 整个应用一个 provider {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

在较高的层级放一个 `DnDProvider`，比如 `App.vue` 或某个布局里，然后就不用再管它了。每个组合式函数（`makeSortableList`、`makeDraggable`、`useDnD`……）都会查找它所在组件上方最近的 provider。

::warning
组合式函数必须在**渲染于** provider **内部**的组件中运行。如果在自身模板包含 `<DnDProvider>` 的组件里调用，会抛出 `No <DnDProvider> found above this component`：Vue 的 `inject` 只能看到祖先组件。
::

## 它掌管什么 {#what-it-owns}

| 部分 | provider 做什么 |
| --- | --- |
| 输入 | 把指针、触摸和键盘输入转换为拖拽（`sensors`），同一时间只有一次拖拽。 |
| 查找目标 | 对拖拽下方的放置目标做命中测试（`collision`），并通知它们。 |
| 浮层 | 渲染跟随指针的盒子，传送到 `body`，并在放置时让它落位。 |
| 选中集合 | 一个选中 id 的集合，由其下所有列表和可拖拽元素共享。 |
| 自动滚动 | 拖拽靠近容器和窗口边缘时滚动它们。 |
| 实时区域 | 向屏幕阅读器播报拿起、移动、放置和取消。 |

除此之外它不渲染任何东西：你的标记保持原样。

## 选项一览 {#options-at-a-glance}

每个选项都有可用的默认值，所以 provider 通常不需要任何选项。

| Prop | 默认值 | 设置什么 |
| --- | --- | --- |
| `collision` | `pointerFirst` | 如何选出拖拽下方的目标。 |
| `modifiers` | `[]` | 适用于每次拖拽的移动规则（吸附、限制……）。 |
| `animation` / `dropAnimation` | 开启 | 排序时项的滑动 / 浮层的落位。 |
| `animate` | 关闭 | 列表和树的默认值：为非拖拽引起的数据变化添加动画。 |
| `autoScroll` | 开启 | 边缘滚动：`{ threshold, maxSpeed, acceleration }` 或 `false`。 |
| `activation` | 鼠标 4 px，触摸 200 ms | 按下何时变成拖拽，按指针类型分别设置。 |
| `keyboard` | Space / Enter、Escape | 键盘按键和步长；`false` 关闭键盘拖拽。 |
| `sensors` | 指针 + 键盘 | 由什么把输入转换为拖拽。 |
| `haptics` | 触摸拿起时短暂振动 | 触摸拖拽的振动，或 `false`。 |
| `copyModifier` | `'Alt'` | 拖拽时按住这个键，移动就变成复制（列表需要 `clone`）。 |
| `overlayTo` | `'body'` | 浮层传送到哪里。 |
| `overlayFit` | `'slot'` | 浮层尺寸：它将落入的位置的尺寸，或来源元素的尺寸。 |
| `announcements` | 内置 | 屏幕阅读器文本，或 `false`。 |
| `defaultStyles` | `true` | 为拖拽状态注入零优先级的 CSS。 |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

包含所有类型结构的完整列表见 [DnDProvider API](/docs/api/dnd-provider)。provider 还会触发 `drag-start`、`drag-move`、`drag-over`、`drag-end` 和 `drag-cancel`，与 `useDnDMonitor` 收到的事件相同。

::tip
页面某一部分的规则（一个会吸附的面板、一个只能垂直滚动的信息流）不需要单独的 provider：用[拖拽区域](/docs/guides/constraints)包裹那一部分即可。
::

## 读取拖拽状态：`useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="拖动一个任务，观察状态变化" height="22rem"}
::

在 provider 之下的任何组件中，`useDnD()` 都会以响应式状态返回当前拖拽：

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| 字段 | 内容 |
| --- | --- |
| `status` | `'idle'`、`'activating'`（长按蓄力中）、`'dragging'`、`'dropping'`（落位中，或在等待异步的 `onBeforeDrop`）、`'selecting'`（框选中）。 |
| `active` | 被拖拽的内容：`id`、`ids`（所有被拖拽的 id，抓起的那个在最前）、`items`、`data`、`type`、`element`、`rect`、`sensor`。空闲时为 `null`。 |
| `over` | 拖拽下方的目标：`id`、`data`、`element`、`rect` 和 `accepted`。下方没有目标时为 `null`。 |
| `pointer` | 指针的视口坐标，已经过修饰器处理。 |
| `activation.progress` | 长按蓄力期间从 `0` 到 `1`：可以用它画一个圆环。 |
| `isAutoScrolling` | 自动滚动正在滚动某个元素。 |
| `selection` | provider 的选中集合：`ids`、`has`、`add`、`delete`、`toggle`、`set`、`clear`。参见[多项拖拽](/docs/guides/multi-drag)。 |
| `cancel()` | 取消正在进行的拖拽（项飞回原处）、正在蓄力的长按或框选。 |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

一旦放置结果确定，`active`、`over` 和 `pointer` 就会变为 `null`，即使浮层仍在落位（`status` 保持为 `'dropping'`）。由它们派生的 UI 永远不会把旧的拖拽和新数据显示在一起。在异步的 `onBeforeDrop` 等待期间，状态保持松开时的样子。

## 监听每一次拖拽：`useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

监听器会收到其 provider 之下的每一次拖拽，无论拖拽从哪里开始。调用它的组件卸载时，监听随之停止。

| 事件 | 触发时机 |
| --- | --- |
| `onDragStart` | 拖拽开始。 |
| `onDragMove` | 拖拽移动。 |
| `onDragOver` | 拖拽下方的目标发生变化。 |
| `onBeforeDrop` | 拖拽被松开。它的返回值决定放置结果：参见[决定放置](/docs/guides/drop-decisions)。 |
| `onDragEnd` | 放置已完成。可排序列表已经运行了各自的 `onDrop` 并写入了新顺序。拖拽结束在没有目标的地方时，`dropped` 为 `false`。 |
| `onDragCancel` | 按下 Escape、放到拒绝它的目标上，或 `onBeforeDrop` 返回了 `'reject'`。 |
| `onDragResume` | `onBeforeDrop` 返回了 `'continue'`：什么都没有放下，拖拽继续进行。 |

每个事件都带有 `active`、`over`、`pointer`、`delta`（相对起点的偏移）、`position`（被拖拽的盒子在 `over` 中的位置，参见[拖放](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)），对于来自可排序列表的项还带有 `source`。完整的结构见[事件 API](/docs/api/events)。

::note
“放置之后”的工作放在 `onDragEnd` 中做：保存、清空选中集合、统计分析。列表自己的 `onDrop` 在写入**之前**运行，因此它看到的仍是旧顺序。
::

## 多个 provider {#several-providers}

大多数应用只需要一个。只有当页面的某一部分需要自己的 provider 级设置（碰撞检测、键盘按键、播报），并且其中的项永远不会离开它时，第二个 provider 才有意义：

- provider 之间相互独立：拖拽永远不会从一个 provider 跨到另一个。
- 允许嵌套 provider。**最近的所有者优先**：一个项属于它上方最近的 provider，外层 provider 会忽略它。
- 每个 provider 都有自己的选中集合、浮层和实时区域。

如果项无法在页面的两部分之间移动，检查一下它们是否位于两个不同的 provider 之下。

::tip
挂载在别处的应用（在 shadow root 中，或作为独立的 Vue 应用）可以加入已有的 provider：在挂载之前，把 `useDnDContext()` 传给 `provideDnDContext(app, context)`。
::

## SSR 与 Nuxt {#ssr-and-nuxt}

provider 是 SSR 安全的。列表和项像其他标记一样在服务端渲染。浮层和实时区域通过传送挂载，且只在客户端挂载，所以它们永远不会导致激活不匹配。默认 id 来自 Vue 的 `useId()`，在服务端和客户端之间保持一致。

在 Nuxt 中，模块会全局注册 `DnDProvider` 并自动导入组合式函数：参见[安装](/docs/getting-started/installation#nuxt)。
