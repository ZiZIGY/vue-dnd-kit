拖拽时，一个盒子会跟随指针：这就是**浮层**。被拖拽的元素本身留在原处，作为它将落入的位置。放置时，浮层飞到那个位置然后消失。

浮层被传送到 `body`，位于你的组件之外。默认情况下，它显示被拖拽元素的克隆。

::

## 默认克隆 {#the-default-clone}

克隆在拿起时生成，此时还没有任何东西移动。它是元素的深拷贝：

- 表单值和 `<canvas>` 像素会被复制。
- 元素离开列表后会丢失的计算样式会被内联：继承的字体和颜色、通过祖先匹配的样式（`.list li { … }`）、表格单元格宽度。表格行会被包裹在一个属于它自己的表格中。
- `id` 和 `data-dnd-*` 属性会被去掉，克隆带有 `aria-hidden`。
- UI 库（Vuetify、Quasar、PrimeVue、Naive UI）的水波纹和其他按下效果会被排除。

其他不应该跟着走的东西，用 **`data-dnd-no-clone`** 标记：菜单按钮、提示框、徽标。

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### 背景不会被猜测 {#backgrounds-arent-guessed}

克隆按元素原本的样子显示它。如果一行自己没有背景，因为背景是由列表绘制的（白色 `<ul>` 中的 `<li>`、`v-list-item`、表格行），那么克隆就是**透明的**。用 CSS 给它加上列表的背景：

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

克隆保留元素的类名和属性，包括 Vue 的作用域属性，因此这条规则写在行的 scoped 样式中和写在全局样式表中都有效。另一种办法是直接给行本身设置背景。本就应该浮起来的图标和图块，比如[可排序列表](/docs/guides/sortable-lists)中的应用图标，是有意保持透明的。

## 为盒子设置样式 {#styling-the-box}

盒子是带有 `data-dnd-overlay` 的元素。它是 `position: fixed` 和 `pointer-events: none`，属性值表示它正在做什么：

| `data-dnd-overlay` | 何时 |
| --- | --- |
| `"dragging"` | 它正在跟随指针。 |
| `"dropping"` | 它正在落到自己的位置、飞回原处，或在等待异步的 `onBeforeDrop`。 |

拖拽时呈现抬起的样子，落位时消失：

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## 浮层组件 {#overlay-components}

如果要显示克隆以外的东西，传入一个组件。它会渲染在盒子内部：

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | 内容 |
| --- | --- |
| `active` | 这次拖拽（`id`、`ids`、`data`、`type`……）。 |
| `items` | 所有被拖拽的项，抓起的那个在最前：`{ id, item, data, type }`。对于可排序拖拽，`item` 是列表项。 |
| `over` | 拖拽下方的目标，或在放置过程中它要落到的目标。下方没有目标时，以及被取消的拖拽飞回原处时为 `null`。 |
| `accepted` | `over` 是否接收这次拖拽：不接收时可以把浮层染成红色。 |
| `status` | `'dragging'` 或 `'dropping'`。 |
| `mode` | `'move'`、`'copy'`、`'swap'` 或 `'insert'`。 |

组件可以直接传入，也可以放在 `shallowRef` 中以便切换。永远不要把它放进深层的 `ref` 或 `reactive`：Vue 会把组件变成响应式的并发出警告。

[可排序列表](/docs/guides/sortable-lists)中的应用网格就用了一个浮层组件：图标单独移动并抬起，名称留在原处。

## provider 的 `#overlay` 插槽 {#the-providers-overlay-slot}

对于每一次没有自己组件的拖拽，由 provider 的插槽来渲染浮层：

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

插槽收到的 props 与浮层组件相同。当它什么都不渲染时（上面的 `v-if`），这次拖拽会退回到克隆。

## 优先级 {#what-wins}

对于每次拖拽，使用以下第一个适用的：

1. 项自己的 `overlay`（`makeSortableItem`、`makeDraggable`）。
2. 它所在列表或树的 `overlay`。
3. provider 的 `#overlay` 插槽，除非它什么都不渲染。
4. 默认克隆。在多项拖拽中，是一列或一叠克隆：参见[多项拖拽](/docs/guides/multi-drag#the-default-overlay)。

组件在拖拽开始时选定，并在整个拖拽过程中保持不变，经过其他列表时也是如此。

## `DragPreview`：布局中的克隆 {#dragpreview-the-clone-in-your-layout}

`DragPreview` 渲染库为某一个被拖拽项生成的克隆。在需要自己布局多个项、或要在克隆周围加一个边框的浮层组件中使用它：

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

克隆只为抓起的项以及与它相邻的最多四个其他项生成；对于其他任何项，`DragPreview` 渲染它的默认插槽。一叠预览的示例参见[多项拖拽](/docs/guides/multi-drag#a-custom-overlay-for-several-items)。

## 尺寸：`overlayFit` {#size-overlayfit}

| `overlayFit`（provider） | 盒子 |
| --- | --- |
| `'slot'`（默认） | 采用它将落入的位置的尺寸。经过一个卡片更宽的列表时，它会变宽。 |
| `'source'` | 保持被拖拽元素的尺寸。 |

使用 `'slot'` 时，盒子围绕指针调整尺寸，指针始终位于盒子中相同的比例位置。内容永远不会被缩放：它会按新尺寸重新布局。

无论哪种设置，放置时的表现都一样：盒子飞向落地的元素，并以动画过渡到**该元素的**尺寸，内容在途中重新布局。当一个项在两个列表中外观不同时（面板中是紧凑的标签，看板上是完整的卡片），来源的克隆会按目标的尺寸重新布局，在那里可能显得被挤压或拉伸。有两种办法保持正确：

- 让项在它可能落入的每个列表中都有**相同的外观**。[拖放](/docs/guides/drag-and-drop)中的文件在每个文件夹里都是同一个固定尺寸，所以放置只是移动它们。
- 在浮层组件中渲染**目标的外观**。它会收到 `over`，因此可以切换到它所在列表的外观，并且在任何尺寸下都能填满盒子。

浮层组件根元素上的固定尺寸会在盒子内保持不变。给根元素设置 `width: 100%; height: 100%`，就能跟随盒子的尺寸。

## 渲染位置：`overlayTo` {#where-it-renders-overlayto}

provider 把浮层传送到 `body`。在用 `showModal()` 打开的 `<dialog>` 或 shadow root 中，浮层会被压在顶层之下，或落在样式作用范围之外。把 `overlayTo` 指向那里的一个选择器或元素：

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## 不使用浮层 {#no-overlay}

`makeDraggable(el, { overlay: false })` 完全没有盒子：元素本身通过返回的 `transform` 移动。参见[拖放](/docs/guides/drag-and-drop#without-an-overlay)。盒子如何落位由 provider 的 `dropAnimation` 决定：参见[动画](/docs/guides/animations)。
