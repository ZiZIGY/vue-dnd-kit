## 列表和它的行 {#a-list-and-its-rows}

一个可排序列表需要两个组件：列表和它的行。

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

行会注册到渲染它的那个列表上。这也是每个列表都需要一个独立组件的原因：在同一个组件中创建的两个列表会共享它们的行。

## 草稿 {#the-draft}

`makeSortableList` 返回 `items`，它是你数组的一份**草稿**。拖拽时，草稿实时重新排序：被拖拽的行占据新位置，其他行滑开让路。在放置之前，你的数组不会改变；放置时，库把新顺序写入其中。

::example{name="quick-start" hint="列表下方的 id 就是你的数组：放置时才会变化"}
::

- 渲染 `items`，而不是你的数组。如果渲染你的数组，放置之前什么都不会动。
- 写入发生在列表的 `onDrop` 之后。在 `onDrop` 中，你的数组仍是旧顺序，`e.result` 是新顺序。
- `tasks` 是普通的 `ref`，所以应用的其他部分会像看到任何其他变化一样看到这次变化。

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

通过 `v-model` 接收数组的列表组件，直接把 model 传下去：

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
使用 store、服务端状态或不可变数据？传入 getter 或 `computed` 而不是 ref。库不会写入只读的数据源：调用 `e.preventDefault()`，自己应用 `e.result`。参见[决定放置](/docs/guides/drop-decisions)。
::

## Key {#keys}

行以其数据作为 key，绝不用索引或自动生成的 id。默认的 key 是 `item.id`；对于字符串和数字，key 就是项本身。

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- 在 `v-for` 中使用相同的 key：`:key="task.uuid"`。用 `:key="index"` 的话，动画会出现在错误的行上，行的状态也会在行之间跳来跳去。
- 在所有互相交换项的列表中，key 必须唯一。
- 以 getter 的形式传入 `item` 和 `id`，这样行的 props 变化时它能保持同步。

## 策略 {#strategies}

| `strategy` | 适用于 |
| --- | --- |
| `'vertical'`（默认） | 一列行。 |
| `'horizontal'` | 单独一行：标签页、标签、时间线。 |
| `'grid'` | CSS 网格和自动换行的 flex 行，项的尺寸可以各不相同。 |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## 拖拽手柄 {#handles}

默认情况下，整行都可以开始拖拽（行内的按钮、输入框和其他控件除外）。传入 `handle`，就只能通过其中一部分拖拽：

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` 是项内部的选择器，或一个元素引用。
- 从手柄开始的鼠标拖拽会立即开始，不需要通常的 4 px。
- 手柄会得到拖拽相关的属性（`role`、`tabindex`、`aria-*`），键盘拖拽也从它开始。

把手柄做成带 `aria-label` 的 `<button type="button">`：它本身就可以获得焦点，屏幕阅读器也会读出它的标签。只放一个图标的 `<span>` 也能用（库会给它加上 `tabindex="0"` 和 `role="button"`），但它没有有意义的名称。

::note
触摸拖拽在 200 ms 长按之后才开始，这样页面仍然可以滚动。如果要从手柄立即开始拖拽，给手柄设置 `touch-action: none`，并给项设置 `activation: { touch: { distance: 4 } }`。
::

## 锁定轴向 {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` 让拖拽保持在垂直轴上，`'x'` 则保持在水平轴上。项自身的 `axis` 优先于其列表的。如果还要把拖拽限制在列表内部，再加上 `restrictToParent` 修饰器；上面的播放列表两者都用了。更多内容见[约束](/docs/guides/constraints)。

## 为占位设置样式 {#style-the-slot}

被拖拽的行留在列表中，作为它将落入的位置，并带有 `data-dnd-placeholder`。默认样式把它的透明度降到 40%，且优先级为零，所以你写的任何规则都会生效：

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` 以 ref 的形式返回同样的状态，外加另外几个：

| 返回值 | 含义 |
| --- | --- |
| `isPlaceholder` | 这一行是被拖拽项将落入的位置。 |
| `isDragging` | 这一行正在被拖拽（多项拖拽时，每个被拖拽的行都是）。 |
| `index` | 它在草稿中的索引：拖拽时会变化。 |
| `selected` | 可写，绑定到 provider 的选中集合。 |
| `indicator` | 在[指示器模式](/docs/guides/shared-lists#an-insertion-line)下，插入线的位置。 |

列表会返回 `isOver` 和 `isAccepting`，用于它自己的高亮。所有属性和样式配方见[样式](/docs/guides/styling)。

## 关闭功能 {#turning-things-off}

- 列表上的 `disabled`：不能从中拖出，也不能放入。项上的 `disabled`：它不能被拖拽。
- `sort: false`：项不能在这个列表内部重新排序，但仍然可以离开它（面板，参见[共享项的列表](/docs/guides/shared-lists)）。

## 动画 {#animations}

拖拽时行会滑到新位置，被放下的行会落到它的位置上。这是默认开启的，不需要任何代码。不要用 `<TransitionGroup>` 包裹行：移动会产生两次动画。对于非拖拽引起的变化（添加、删除、打乱），开启列表的 `animate` 选项。参见[动画](/docs/guides/animations)。

完整的选项列表见 [makeSortableList](/docs/api/make-sortable-list) 和 [makeSortableItem](/docs/api/make-sortable-item) API。
