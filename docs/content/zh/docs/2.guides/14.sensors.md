传感器把输入转换为拖拽。它只告诉 provider “从这里拖拽这个项”，然后告诉它输入移动到了哪里，以及是放下了还是取消了。其余的都由 provider 完成，对每个传感器都一样：同一时间只有一次拖拽、拒绝被禁用的项、激活约束、排序、自动滚动、播报、:kbd{value="Escape"}，以及整个放置过程。

## 内置传感器 {#the-built-in-sensors}

| 传感器 | 输入 |
| --- | --- |
| `pointerSensor` | 鼠标、触摸和触控笔，通过 Pointer Events 实现。它会捕获指针，在触摸拖拽时阻止页面选中文本或滚动，并吞掉拖拽之后的那次点击。 |
| `keyboardSensor` | :kbd{value="Space"} 和 :kbd{value="Enter"} 拿起和放下，方向键移动，:kbd{value="Escape"} 取消——任何拖拽都可以，指针拖拽也一样。 |

两者都默认运行。provider 的 `sensors` 会替换这个列表：

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

要关闭键盘拖拽，优先使用 `:keyboard="false"`，而不是去掉 `keyboardSensor`：键盘传感器同时也负责用 :kbd{value="Escape"} 取消任何拖拽。它的按键通过 `keyboard.keys` 重新绑定（参见[无障碍](/docs/guides/accessibility#the-keyboard)）。

## 激活约束 {#activation-constraints}

按下在满足约束后才会变成拖拽：

| 指针 | 默认 |
| --- | --- |
| 鼠标 | 移动 4 px 之后。在 `handle` 上按下时立即开始，除非你为鼠标设置了约束。 |
| 触控笔 | 移动 4 px 之后。 |
| 触摸 | 按住 200 ms 之后。在此之前移动超过 5 px 会中止它，页面改为滚动。 |

约束有三个字段：

| 字段 | 含义 |
| --- | --- |
| `distance` | 指针必须移动的像素数。 |
| `delay` | 按下必须持续的毫秒数。两者都设置时，先满足的那个触发拖拽。 |
| `tolerance` | 与 `delay` 一起使用：等待期间指针可以移动多远；超过后按下会被放弃。 |

按指针类型——`mouse`、`touch`、`pen`——在 provider、拖拽区域或项本身上设置它们。项自己的优先，其次是它所在区域的，最后是 provider 的：

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

要通过触摸从手柄立即开始拖拽，给手柄设置 `touch-action: none`（这样浏览器就不会滚动），并给项设置 `activation: { touch: { distance: 4 } }`。

### 长按进度环 {#a-long-press-ring}

按下处于等待期间，`useDnD().status` 为 `'activating'`，`activation.progress` 从 0 变化到 1：

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### 只允许部分按下 {#only-some-presses}

`canDrag` 是可拖拽元素和可排序项上的又一道关卡。它会收到输入事件：

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

可交互的子元素——按钮、输入框、可编辑字段——永远不会触发指针拖拽，所以它们在可拖拽元素内部照常工作。设置了 `handle` 时，只有手柄能触发拖拽。

## 自定义传感器 {#a-sensor-of-your-own}

游戏手柄、屏幕上的摇杆、语音命令：任何能指向一个项并移动的东西都可以驱动拖拽。下面是一个摇杆，按住 300 ms 后会拿起光标下方的东西：

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

把它加到 provider 的 `sensors` 中，或者用 `useSensor(joystick.sensor)` 让它在某个组件的生命周期内运行。

### 传感器能拿到什么 {#what-the-sensor-gets}

`setup(context)` 接收 provider 一侧的接口：

| 成员 | 含义 |
| --- | --- |
| `props` | provider 的 props（`activation`、`keyboard`……）。在需要时再读取：它们可能会变化。 |
| `status` | provider 的拖拽状态，无论是哪个传感器在执行拖拽。 |
| `drag` | provider 当前的拖拽，等待中或进行中，无论是哪个传感器发起的。没有拖拽时为 `null`。 |
| `activate(options)` | 请求一次拖拽。返回一个 `SensorDrag`；不能开始拖拽时返回 `null`。 |
| `cancel()` | 取消 provider 的拖拽或等待中的按下。 |

`activate()` 接收：

| 选项 | 含义 |
| --- | --- |
| `target` | 输入落在哪里：可拖拽元素内部的某个元素，或可拖拽元素的 id。元素会像真实的按下一样被检查（手柄、不能是可交互的子元素）；id 会跳过这些检查。 |
| `point` | 拖拽开始的位置，视口坐标。默认：可拖拽元素的中心。 |
| `type` | `'pointer'`（默认）：跟随坐标点，对目标做命中测试，自动滚动。`'keyboard'`：按项移动，把目标滚动到视野中，结束时归还焦点。 |
| `activation` | 一个约束（`{ delay: 300 }`），或一种指针类型（`'touch'`）以使用已配置的约束。默认：无，拖拽立即开始。 |
| `event` | 输入事件，会交给项的 `canDrag`。触摸类型的 `pointerType` 会让它成为触摸拖拽（触感反馈）。 |
| `onStart(drag)` | 拖拽已开始，在激活之后。 |
| `onEnd(drag)` | 拖拽已结束：被中止、已放下或已取消——无论由谁导致。 |
| `onResume(drag)` | `onBeforeDrop` 返回了 `'continue'`：拖拽继续，`move`、`drop` 和 `cancel` 再次生效。 |

它返回的 `SensorDrag`：

| 成员 | 作用 |
| --- | --- |
| `id`、`type` | 被拖拽项的 id，以及 `'pointer'` 或 `'keyboard'`。 |
| `state` | `'pending'`（等待激活）、`'dragging'`，然后是 `'ended'`。 |
| `started` | 拖拽已经开始过，即使之后已经结束。 |
| `move(point)` | 输入移动了。等待期间检查容差；拖拽期间移动拖拽。 |
| `step(direction)` | 键盘拖拽：按一次方向键，`'up' \| 'down' \| 'left' \| 'right'`。 |
| `place({ list, index })` | 把项放到可排序列表的某个位置，与键盘移动的方式相同。没有列表在那里接收它时 resolve 为 `false`。 |
| `drop()` | 放下。放置成功时，在落位完成后 resolve 为 `true`。 |
| `cancel()` | 取消：项飞回原处，或放弃等待中的按下。 |

不再适用的调用——结束后的移动、第二次 `drop()`——会被忽略。完整类型：[传感器](/docs/api/sensors)。

::tip
要包装一个内置传感器，用你自己的上下文运行它的 `setup`。用 `Object.create(context, { activate: { value: myActivate } })` 来创建这个上下文，而不是用展开运算符，这样实时的 getter（`status`、`drag`、`props`）才能继续工作。
::

## 程序化拖拽 {#programmatic-drags}

`@vue-dnd-kit/actions` 通过代码移动项：“上移”按钮、菜单、键盘快捷键、撤销、新手引导、测试。它基于公开的传感器 API 构建，它的拖拽都是真实的拖拽：会被播报、有动画，经过 `onBeforeDrop`、`onDrop`、`e.result` 和 `preventDefault()`，并遵守 provider 的规则（同一时间只有一次拖拽、被禁用的项、`accept` 和 `group.put`）。

```bash
npm i @vue-dnd-kit/actions
```

### moveItem：一次调用，一次移动 {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` 是可排序列表的 `id`。不传的话，项留在它所在的列表中。
- `index` 是项最终所在的位置，计算时不包含项本身，并被限制在列表范围内。不传的话，项会移到末尾。
- 放置成功时 resolve 为 `true`；项没有被渲染或被禁用、没有列表在那里接收它，或者放置被拒绝时为 `false`。
- 调用会排队：每次调用都会等到 provider 空闲，所以快速的第二次点击不会丢失。
- 它以键盘拖拽的方式运行，所以会被播报，焦点也会留在项上。
- 仅限列表：树中的位置还包含深度。

带移动按钮的行参见[无障碍](/docs/guides/accessibility#moving-without-dragging)。

### startDrag：脚本驱动的拖拽 {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` 在移动渲染完成后 resolve，`drop` 在放置落位后 resolve。`startDrag(id, { type: 'keyboard' })` 则改为按项移动（`await drag.step('down')`），并且键盘传感器可以接管：比如一个“移动”菜单项，把项交给方向键来操作。

### 在组件之外 {#outside-components}

`useDnDActions()` 会在上方的 provider 中运行一个名为 `actions` 的传感器。如果要从 store 或测试框架中驱动 provider，或者使用自己的名称，就在一个你自己运行的传感器中创建 actions：

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

然后就可以在任何地方调用 `await tour?.moveItem('card-1', { list: 'done' })`。服务端渲染期间不会发生任何拖拽：`moveItem` resolve 为 `false`，`startDrag` 返回 `null`。
