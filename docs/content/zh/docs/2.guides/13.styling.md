库几乎不设置任何样式。拖拽的每种状态都以两种方式提供给你：作为组合式函数返回的 ref，用于类名和条件渲染的标记；以及作为 `data-dnd-*` 属性，用于纯 CSS。

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## 返回的 ref {#the-returned-refs}

| 组合式函数 | 状态 |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`：这个元素是被拖拽项将落入的位置。
- `isDragging`：这个项是本次拖拽的一部分（多项拖拽时，每个被拖拽的项都是）。
- `isAccepting`：有东西正在被拖拽，并且这个目标接收它——高亮可以放置的地方。
- `isOver`：拖拽位于这个目标上方，无论它是否接收。`isOver && !isAccepting` 表示拒绝，值得显示出来。
- 在拒绝这次拖拽的目标上方，`useDnD()` 中的 `over.accepted`（浮层 props 中的 `accepted`）为 `false`：可以用它把浮层染成红色。

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## data 属性 {#the-data-attributes}

| 属性 | 位于 | 何时 |
| --- | --- | --- |
| `data-dnd-placeholder` | 可排序项 | 它是被拖拽项将落入的位置。 |
| `data-dnd-dragging` | 可排序项 | 它正在被拖拽但留在原处：`'gaps'` 模式下多项拖拽中的其他项。 |
| `data-dnd-dragging="pointer"` 或 `"keyboard"` | `<html>` | 整个拖拽期间。 |
| `data-dnd-overlay="dragging"` 或 `"dropping"` | 浮层盒子 | 始终存在。落位时以及异步的 `onBeforeDrop` 等待时为 `dropping`。 |
| `data-dnd-leaving` | `animate` 留下的副本 | 离开的项淡出期间。 |
| `data-dnd-no-clone` | **由你设置** | 把元素排除在浮层的克隆之外：提示框、菜单按钮、徽标。 |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## 默认样式 {#default-styles}

provider 会在每个文档中注入一次几条规则。它们被包裹在 `:where()` 中，所以优先级为零，你写的任何规则都会生效：

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

拖拽期间，占位会变暗，页面不会选中文本，也不会锚定滚动位置；指针拖拽期间，光标是抓取的手形。`:default-styles="false"` 会关闭这些规则。可拖拽项上的 `cursor: grab` 需要你自己添加。

## 配方 {#recipes}

### 空占位 {#an-empty-slot}

在项将落入的地方显示一个空的虚线框，而不是项的半透明副本：

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

伪元素覆盖在内容上，所以占位保持项的精确尺寸。在这里拖动一张卡片看看效果：

### 由列表绘制背景的行 {#a-row-the-list-paints}

默认浮层是被拖拽元素的克隆。它按元素原本的样子显示，不会猜测背景：自己没有背景的行——白色 `<ul>` 中的 `<li>`、表格行、UI 库的列表项——会得到一个透明的克隆。给它加上列表的背景：

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

克隆保留元素的类名和属性——包括 scoped 样式的属性——所以这条规则可以写在行自己的 `<style scoped>` 中，和它的其他样式放在一起。或者给行设置它自己的背景。本就应该浮起来的图标和图块保持透明。

### 只在拖拽时抬起的浮层 {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

卡片移动时阴影存在，浮层切换到 `dropping` 时阴影消失，所以卡片会平平地落到它的位置上。对于自定义浮层组件，同样的规则作用于你组件的根元素，或者从 props 中读取 `status`。

### 减弱动态效果 {#reduced-motion}

在 `prefers-reduced-motion: reduce` 下，库已经会停止它自己的动画。你在拖拽相关元素上添加的过渡也应该这样做：

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### 不要这样做 {#dont}

- 不要给可排序项的 `transform` 或 `translate` 设置 CSS `transition`：库会自己为它们添加动画，并在测量时取消这类过渡。
- 不要为[虚拟列表](/docs/guides/virtual-lists)中行的 `height`、`margin` 或 `padding` 添加动画。

关于浮层的更多内容——自定义组件、尺寸、`DragPreview`——见[浮层](/docs/guides/overlay)。
