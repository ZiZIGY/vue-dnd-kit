Enquanto você arrasta, uma caixa segue o ponteiro: o **overlay**. O próprio elemento arrastado
fica onde estava, como a posição onde vai pousar. No drop, o overlay voa até essa posição e
desaparece.

O overlay é teleportado para `body`, fora dos seus componentes. Por padrão, ele mostra um clone
do elemento arrastado.

::example{name="overlay" hint="Arraste uma mensagem: a cópia ganha o fundo da caixa de entrada" height="24rem"}
::

## O clone padrão {#the-default-clone}

O clone é feito quando o item é pego, antes que qualquer coisa se mova. É uma cópia profunda do
elemento:

- Os valores de formulário e os pixels de `<canvas>` são copiados.
- Os estilos computados que o elemento perderia fora da sua lista são aplicados inline: fontes e
  cores herdadas, estilos que casam por meio de ancestrais (`.list li { … }`), larguras das
  células de tabela. Uma linha de tabela vem envolvida em uma tabela própria.
- Os `id`s e os atributos `data-dnd-*` são removidos, e o clone é `aria-hidden`.
- Ripples e outros efeitos de clique de UI kits (Vuetify, Quasar, PrimeVue, Naive UI) ficam de
  fora.

Marque com **`data-dnd-no-clone`** qualquer outra coisa que não deva ir junto: um botão de menu,
uma tooltip, um badge.

```vue
<li ref="el" class="mail-row">
  {{ mail.subject }}
  <button type="button" aria-label="Archive" data-dnd-no-clone>…</button>
</li>
```

### O fundo não é adivinhado {#backgrounds-arent-guessed}

O clone mostra o elemento como ele é. Uma linha que não tem fundo próprio, porque a lista a
pinta (um `<li>` em um `<ul>` branco, um `v-list-item`, uma linha de tabela), gera um clone
**transparente**. Dê a ela o fundo da lista no CSS:

```vue [MailRow.vue]
<style scoped>
[data-dnd-overlay] .mail-row {
  background: var(--surface);
}
</style>
```

O clone mantém as classes e os atributos do elemento, incluindo o atributo de escopo do Vue,
então a regra funciona tanto no estilo scoped da linha quanto em uma folha de estilos global. A
outra saída é um fundo na própria linha. Ícones e blocos feitos para flutuar, como os ícones de
apps em [listas ordenáveis](/docs/guides/sortable-lists), ficam transparentes de propósito.

## Estilizando a caixa {#styling-the-box}

A caixa é o elemento com `data-dnd-overlay`. Ela é `position: fixed` e
`pointer-events: none`, e o valor do atributo diz o que ela está fazendo:

| `data-dnd-overlay` | Quando |
| --- | --- |
| `"dragging"` | Ela segue o ponteiro. |
| `"dropping"` | Ela pousa na sua posição, volta ao lugar ou espera um `onBeforeDrop` assíncrono. |

Uma aparência elevada durante o arraste, que some ao pousar:

```css
[data-dnd-overlay='dragging'] .mail-row {
  box-shadow: 0 18px 32px -14px rgb(0 0 0 / 0.5);
}
```

## Componentes de overlay {#overlay-components}

Para mostrar algo diferente do clone, passe um componente. Ele é renderizado dentro da caixa:

```vue [CardOverlay.vue]
<script setup lang="ts">
import type { OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <!-- Fill the box: it resizes to the slot and animates on drop. -->
  <div class="card-overlay" :class="{ refused: over && !accepted }">
    {{ (items[0]?.item as Task).title }}
    <small v-if="mode === 'copy'">+ copy</small>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.card-overlay { width: 100%; height: 100%; }
</style>
```

```ts
import CardOverlay from './CardOverlay.vue';

makeSortableList(listRef, { items: tasks, overlay: CardOverlay });          // every item of the list
makeSortableItem(el, { item: () => props.task, overlay: CardOverlay });      // this item
makeDraggable(el, { id: 'chip', overlay: CardOverlay });                     // a plain draggable
```

| `OverlayProps` | O que contém |
| --- | --- |
| `active` | O arraste (`id`, `ids`, `data`, `type`, …). |
| `items` | Todos os itens arrastados, começando pelo item pego: `{ id, item, data, type }`. `item` é o item da lista nos arrastes ordenáveis. |
| `over` | O alvo sob o arraste, ou aquele em que ele pousa durante o drop. `null` quando não há nada embaixo e enquanto um arraste cancelado volta ao lugar. |
| `accepted` | Se `over` aceita o arraste: pinte o overlay de vermelho quando não aceitar. |
| `status` | `'dragging'` ou `'dropping'`. |
| `mode` | `'move'`, `'copy'`, `'swap'` ou `'insert'`. |

Um componente pode ser passado como está, ou em um `shallowRef` para trocá-lo. Nunca o coloque
em um `ref` profundo ou em um `reactive`: o Vue tornaria o componente reativo e emitiria um
aviso.

A grade de apps de [listas ordenáveis](/docs/guides/sortable-lists) usa um: o ícone viaja
sozinho e se eleva, e o nome fica para trás.

::

## O slot `#overlay` do provider {#the-providers-overlay-slot}

Para todo arraste sem um componente próprio, o slot do provider renderiza o overlay:

```vue [App.vue]
<DnDProvider>
  <RouterView />
  <template #overlay="{ items, mode, accepted }">
    <CardOverlay v-if="items[0]?.type.includes('card')" v-bind="{ items, mode, accepted }" />
  </template>
</DnDProvider>
```

O slot recebe as mesmas props que um componente de overlay. Quando ele não renderiza nada (o
`v-if` acima), o arraste volta a usar o clone.

## O que prevalece {#what-wins}

Para cada arraste, vale o primeiro que se aplica:

1. O `overlay` do próprio item (`makeSortableItem`, `makeDraggable`).
2. O `overlay` da lista ou da árvore dele.
3. O slot `#overlay` do provider, a menos que ele não renderize nada.
4. O clone padrão. Em um multi-drag, uma coluna ou uma pilha de clones: veja
   [multi-drag](/docs/guides/multi-drag#the-default-overlay).

O componente é escolhido quando o arraste começa e mantido durante todo o arraste, inclusive
sobre outras listas.

## `DragPreview`: o clone no seu layout {#dragpreview-the-clone-in-your-layout}

`DragPreview` renderiza o clone que a biblioteca fez de um item arrastado. Use-o em um
componente de overlay que organiza vários itens por conta própria, ou que acrescenta uma moldura
ao redor do clone:

```vue [CopyOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="with-badge">
    <DragPreview :id="active.id" :style="{ width: '100%', height: '100%' }" />
    <span v-if="mode === 'copy'" class="badge">+</span>
  </div>
</template>
```

Existem clones do item pego e de até quatro outros ao lado dele; para qualquer outro item,
`DragPreview` renderiza o seu slot padrão. Veja
[multi-drag](/docs/guides/multi-drag#a-custom-overlay-for-several-items) para uma pilha de
prévias.

## Tamanho: `overlayFit` {#size-overlayfit}

| `overlayFit` (provider) | A caixa |
| --- | --- |
| `'slot'` (padrão) | Assume o tamanho da posição onde vai pousar. Sobre uma lista de cards mais largos, ela se alarga. |
| `'source'` | Mantém o tamanho do elemento arrastado. |

Com `'slot'`, a caixa se redimensiona ao redor do ponteiro, que fica na mesma fração da caixa. O
conteúdo nunca é escalado: ele é diagramado de novo no novo tamanho.

Um drop faz o mesmo com qualquer uma das configurações: a caixa voa até o elemento de destino e
anima até o tamanho **dele**, e o conteúdo é diagramado de novo no caminho. Quando um item tem
aparência diferente em duas listas (um chip compacto em uma paleta, um card completo em um
quadro), o clone da origem é diagramado de novo no tamanho do destino, e pode ficar espremido ou
esticado ali. Duas formas de manter isso certo:

- Dê ao item a **mesma aparência** em todas as listas onde ele pode pousar. Os arquivos em
  [arrastar e soltar](/docs/guides/drag-and-drop) têm um tamanho fixo em todas as pastas, então
  um drop só os move.
- Renderize a **aparência do destino** em um componente de overlay. Ele recebe `over`, então
  pode trocar para a aparência da lista sobre a qual está, e preenche a caixa em qualquer
  tamanho.

Um tamanho fixo na raiz de um componente de overlay mantém esse tamanho dentro da caixa. Dê à
raiz `width: 100%; height: 100%` para acompanhá-la.

## Onde ele é renderizado: `overlayTo` {#where-it-renders-overlayto}

O provider teleporta o overlay para `body`. Dentro de um `<dialog>` aberto com `showModal()`,
ou de uma shadow root, o overlay acabaria embaixo da top layer ou fora dos estilos. Aponte
`overlayTo` para um seletor ou um elemento ali dentro:

```vue
<DnDProvider overlay-to="#dialog-overlay">
```

## Sem overlay {#no-overlay}

`makeDraggable(el, { overlay: false })` não tem caixa nenhuma: o próprio elemento se move, por
meio do `transform` retornado. Veja
[arrastar e soltar](/docs/guides/drag-and-drop#without-an-overlay). Como a caixa pousa é
definido pelo `dropAnimation` do provider: veja [animações](/docs/guides/animations).
