## Um provider para o app {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Coloque um `DnDProvider` lá no alto, no `App.vue` ou em um layout, e esqueça dele. Todo
composable (`makeSortableList`, `makeDraggable`, `useDnD`…) procura o provider mais próximo
acima do componente em que roda.

::warning
Um composable precisa rodar em um componente **renderizado dentro** do provider. Chamá-lo no
componente cujo próprio template contém `<DnDProvider>` lança
`No <DnDProvider> found above this component`: o `inject` do Vue só enxerga ancestrais.
::

## O que ele controla {#what-it-owns}

| Parte | O que o provider faz |
| --- | --- |
| Entrada | Transforma a entrada por ponteiro, toque e teclado em arrastes (`sensors`, `activation`), um arraste por vez. |
| Encontrar o alvo | Testa quais alvos de drop estão sob o arraste (`collision`) e avisa a eles. |
| O overlay | Renderiza a caixa que segue o ponteiro, teleportada para o `body`, e a faz pousar no drop. |
| A seleção | Um único conjunto de ids selecionados, compartilhado por todas as listas e draggables abaixo dele. |
| Rolagem automática | Rola os contêineres e a janela quando um arraste chega perto das bordas deles. |
| A live region | Anuncia aos leitores de tela os inícios de arraste, os movimentos, os drops e os cancelamentos. |

Ele não renderiza mais nada: a sua marcação fica como está.

## Opções em resumo {#options-at-a-glance}

Toda opção tem um padrão que funciona, então em geral o provider não recebe nenhuma. O provider
lê as props quando precisa delas: as demos abaixo trocam `collision`, `activation` e
`autoScroll` ao vivo.

| Prop | Padrão | O que define |
| --- | --- | --- |
| `collision` | `pointerFirst` | Como o alvo sob o arraste é escolhido. [Abaixo](#finding-the-target). |
| `activation` | mouse 4 px, toque 200 ms | Quando uma pressão vira arraste, por tipo de ponteiro. [Abaixo](#when-a-press-becomes-a-drag). |
| `autoScroll` | ligado | Rolagem nas bordas: `{ threshold, maxSpeed, acceleration }` ou `false`. [Abaixo](#auto-scroll). |
| `haptics` | uma vibração curta ao pegar por toque | Vibrações para arrastes por toque, ou `false`. [Abaixo](#haptics-and-the-copy-key). |
| `copyModifier` | `'Alt'` | Tecla que, segurada durante o arraste, transforma um movimento em cópia. |
| `modifiers` | `[]` | Regras de movimento para todo arraste: veja [restrições](/docs/guides/constraints). |
| `animation` / `dropAnimation` | ligado | Itens deslizando durante a ordenação / o overlay pousando: veja [animações](/docs/guides/animations). |
| `animate` | desligado | Padrão para listas e árvores: animar mudanças nos dados que nenhum arraste fez. |
| `keyboard` | Space / Enter, Escape | Teclas e passo do teclado; `false` desliga os arrastes por teclado. Veja [acessibilidade](/docs/guides/accessibility#the-keyboard). |
| `sensors` | ponteiro + teclado | O que transforma a entrada em arrastes: veja [sensores](/docs/guides/sensors). |
| `overlayTo` | `'body'` | Para onde o overlay é teleportado. |
| `overlayFit` | `'slot'` | Tamanho do overlay: o da posição em que ele vai pousar, ou o da origem. Veja [o overlay](/docs/guides/overlay). |
| `overlayTransition` | um crossfade | Como o overlay muda de um componente para outro durante o arraste: `false`, ou props de `<Transition>`. Veja [alvos que mudam o overlay](/docs/guides/overlay#targets-that-change-the-overlay). |
| `overlayPreviews` | `5` | Multi-drag: quantos itens arrastados ganham um clone no início do arraste, ou `'all'`. Veja [o overlay padrão](/docs/guides/multi-drag#the-default-overlay). |
| `announcements` | embutidos | Textos para leitores de tela, ou `false`. |
| `screenReaderInstructions` | embutido | O texto que todo draggable aponta com `aria-describedby`. |
| `defaultStyles` | `true` | Injeta CSS de especificidade zero para os estados do arraste: veja [estilização](/docs/guides/styling). |

A lista completa, com todas as formas, está na [API do DnDProvider](/docs/api/dnd-provider). O
provider também emite `drag-start`, `drag-move`, `drag-over`, `drag-end`, `drag-cancel` e `drag-settle`, os
mesmos eventos que o `useDnDMonitor` ouve.

## Ler o arraste: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Arraste uma tarefa e observe o estado" height="27rem"}
::

`useDnD()` retorna o arraste como estado reativo, em qualquer componente abaixo do provider:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Campo | O que contém |
| --- | --- |
| `status` | `'idle'`, `'activating'` (uma pressão esperando a ativação), `'dragging'`, `'dropping'` (nenhum arraste em andamento, mas um overlay ainda está pousando, ou um `onBeforeDrop` assíncrono está decidindo), `'selecting'` (um retângulo de seleção). |
| `active` | O que está sendo arrastado: `id`, `ids` (todos os ids arrastados, o pego primeiro), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` quando parado. |
| `over` | O alvo sob o arraste: `id`, `data`, `element`, `rect` e `accepted`. `null` sobre nada. |
| `pointer` | O ponteiro em coordenadas da viewport, depois dos modificadores. |
| `activation.progress` | De `0` a `1` enquanto uma pressão espera a ativação: desenhe um anel com ele. |
| `isAutoScrolling` | A rolagem automática está movendo alguma coisa. |
| `selection` | A seleção do provider: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. Veja [multi-drag](/docs/guides/multi-drag). |
| `cancel()` | Cancela o arraste em andamento (os itens voltam ao lugar), uma pressão carregando ou um retângulo de seleção. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

Assim que um drop é decidido, `active`, `over` e `pointer` passam a ser `null`, mesmo enquanto o
overlay ainda está pousando (`status` vale `'dropping'`). Uma UI derivada deles nunca mostra o
arraste antigo ao lado dos dados novos. Enquanto um `onBeforeDrop` assíncrono espera, o estado
fica como estava no momento de soltar.

O próximo arraste não espera um pouso: ele começa na hora, e `status` vale `'dragging'`
enquanto o último overlay pousa ao redor dele. Uma pressão sobre um overlay que está pousando o
pega em pleno voo: o arraste continua de onde o overlay está. `onDragSettle` avisa quando o
overlay de um arraste chegou ao seu lugar.

## Ouvir todo arraste: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
  onDragSettle: ({ active, over }) => {},        // its overlay has landed
});
```

Um monitor ouve todo arraste abaixo do seu provider, onde quer que ele comece: o painel acima
registra os arrastes da lista sem importá-la. Ele para quando o componente que o chamou é
desmontado.

| Evento | Quando |
| --- | --- |
| `onDragStart` | Um arraste começa. |
| `onDragMove` | O arraste se move. |
| `onDragOver` | O alvo sob o arraste muda. |
| `onBeforeDrop` | O arraste é solto. A resposta decide o drop: veja [decidindo um drop](/docs/guides/drop-decisions). |
| `onDragEnd` | O drop foi concluído. As listas ordenáveis já rodaram o `onDrop` delas e gravaram a nova ordem. `dropped` é `false` quando o arraste terminou fora de qualquer alvo. |
| `onDragCancel` | Escape, um drop em um alvo que o recusa, ou um `onBeforeDrop` que respondeu `'reject'`. |
| `onDragResume` | `onBeforeDrop` respondeu `'continue'`: nada foi solto, e o arraste continua. |
| `onDragSettle` | O overlay do arraste pousou (ou voltou ao lugar, ou foi pego pelo próximo arraste), com o evento que `onDragEnd` ou `onDragCancel` recebeu. Outros arrastes podem ter começado nesse meio-tempo. |

Todo evento traz `active`, `over`, `pointer`, `delta` (o deslocamento desde o início),
`position` (onde a caixa arrastada fica dentro de `over`, veja
[arrastar e soltar](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) e, para itens de
uma lista ordenável, `source`. As formas completas estão na [API de eventos](/docs/api/events).

::note
`onDragEnd` é o lugar para o trabalho "depois do drop": salvar, limpar a seleção, analytics. O
`onDrop` de uma lista roda **antes** da gravação dela, então ainda vê a ordem antiga.
::

## Encontrar o alvo {#finding-the-target}

Escolha uma função, depois arraste o alfinete ou o card sobre os alvos. Os selos mostram como a
função os classifica neste quadro; o verde é o alvo.

::example{name="collision-lab" hint="Troque a função, arraste sobre os alvos aninhados, pequenos e sobrepostos" height="33rem"}
::

A cada quadro de um arraste, o provider passa para `collision` os alvos de drop em jogo, e ela
retorna os ids deles, do melhor para o pior. Cinco funções vêm com a biblioteca:

| Função | Classifica | Boa para |
| --- | --- | --- |
| `pointerFirst` | O que está sob o ponteiro; quando não há nada, o que a caixa arrastada sobrepõe. | O padrão: preciso sob o ponteiro, tolerante nos vãos. |
| `pointerWithin` | Só o que está sob o ponteiro, o mais interno primeiro. | Alvos precisos: um vão não solta em lugar nenhum. |
| `rectIntersection` | Todo alvo que a caixa arrastada sobrepõe: maior `priority`, depois o aninhamento mais profundo, depois a maior sobreposição. | Itens grandes sobre alvos pequenos, quando o ponteiro está na borda do item. |
| `closestCenter` | Todo alvo, pela distância do centro da caixa até o centro dele. | Sempre alguém vence, mesmo longe: grades e listas de itens do mesmo tamanho. |
| `closestCorners` | Todo alvo, pelas distâncias entre os quatro cantos. | Colunas lado a lado (kanban), alvos com alturas muito diferentes. |

Sob o ponteiro, o teste respeita o que o usuário vê: de alvos sobrepostos, só o de cima é
atingido (`front`, nunca `back` onde eles se sobrepõem), e de alvos aninhados o mais interno vem
primeiro (`subfolder`, depois `folder`).

### Uma função sua {#a-function-of-your-own}

```ts [magnet.ts]
import type { CollisionDetection, Coordinates, Rect } from '@vue-dnd-kit/core';

/** How far the point is from the rect: 0 inside it. */
const gap = (rect: Rect, point: Coordinates) =>
  Math.hypot(
    Math.max(rect.left - point.x, 0, point.x - rect.right),
    Math.max(rect.top - point.y, 0, point.y - rect.bottom),
  );

/** What is under the pointer; in a gap, the nearest target within 40px. */
export const magnet: CollisionDetection = ({ hits, pointer, candidates }) => {
  if (hits.length) return hits;
  return candidates
    .filter((candidate) => gap(candidate.rect, pointer) <= 40)
    .sort((a, b) => gap(a.rect, pointer) - gap(b.rect, pointer))
    .map((candidate) => candidate.id);
};
```

| Argumento | O que contém |
| --- | --- |
| `pointer` | O ponteiro, depois dos modificadores. |
| `overlayRect` | A caixa arrastada como é mostrada, `null` sem overlay. |
| `candidates` | Todo alvo em jogo: `id`, `rect` (a parte visível dele, recortada pelos contêineres de rolagem), `priority`, `depth` (`0` no topo, maior quando aninhado). |
| `hits` | Os alvos sob o ponteiro, segundo o teste, do melhor para o pior. |

Retorne um array vazio para "nenhum alvo". Alvos desativados, alvos dentro dos itens arrastados
e alvos escondidos pelos seus contêineres de rolagem nunca chegam à função. Um alvo que recusa o
arraste continua competindo: sobre ele, `over.accepted` é `false` e o drop é recusado (um alvo
dentro de um item ordenável sai do caminho, para que a lista ordene sobre ele). A demo envolve a
função escolhida para registrar a classificação:
`(args) => (ranked.value = detect(args))`.

::note
O provider amortece as trocas que a função pede. Um alvo que o arraste acabou de deixar não pode
vencer de novo até o ponteiro se mover 10 px, então as fronteiras não piscam. Entre os alvos
aninhados em um pai (os vãos de uma coluna de cards), o último alvo permanece.
::

## Quando uma pressão vira arraste {#when-a-press-becomes-a-drag}

Uma pressão não arrasta na hora. `activation` define, por tipo de ponteiro (`mouse`, `touch`,
`pen`), o que ela espera: uma `distance` em px, um `delay` em ms (com uma `tolerance` além da qual
a pressão desiste, para que a página possa rolar), ou o que vier primeiro dos dois.

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 300, tolerance: 8 } }">
```

| Ponteiro | Padrão |
| --- | --- |
| `mouse`, `pen` | `{ distance: 4 }`: um clique continua sendo um clique. Uma pressão do mouse em um `handle` começa na hora. |
| `touch` | `{ delay: 200, tolerance: 5 }`: um toque longo, para que as listas continuem rolando sob o dedo. |

Um tipo que você omite mantém o seu padrão. A `activation` do próprio draggable vence a de uma
[área de arraste](/docs/guides/constraints), que vence a do provider. Enquanto uma pressão espera,
`useDnD().status` é `'activating'` e `activation.progress` vai de `0` a `1`; Escape ou
`useDnD().cancel()` a cancela. Teste as restrições ao vivo, e desenhe um anel de toque longo a
partir do progresso, em [sensores](/docs/guides/sensors#activation-constraints).

## Rolagem automática {#auto-scroll}

Arraste um canal em direção ao topo ou ao fim da lista. As faixas verdes são as zonas de borda:
quanto mais fundo em uma delas, mais rápido a lista rola.

::example{name="auto-scroll-edges" hint="Arraste um canal para dentro das faixas verdes" height="37.5rem"}
::

Qualquer elemento com `overflow: auto` ou `scroll` rola sozinho, e a janela também. O provider
rola primeiro o contêiner sob o ponteiro, depois os ancestrais dele, depois a janela.

| Opção | Padrão | O que define |
| --- | --- | --- |
| `threshold` | `0.2` | A zona de borda, como fração do tamanho do contêiner, entre 24 e 96 px. |
| `acceleration` | `10` | A velocidade bem na borda, em px por quadro. Ela cresce com o quadrado da profundidade dentro da zona, então o começo é lento e preciso. |
| `maxSpeed` | `25` | A velocidade máxima. Além da borda (o ponteiro fora do contêiner), a velocidade continua crescendo até ela. |

`:auto-scroll="false"` desliga a rolagem. Uma direção só rola depois que o ponteiro se moveu para
aquele lado, então um item pego perto de uma borda não rola sozinho. Listas, árvores e
[áreas de arraste](/docs/guides/constraints) recebem um `autoScroll` próprio para o seu
contêiner:

```ts
makeSortableList(list, { items: channels, autoScroll: { maxSpeed: 10 } });
```

Arrastes por teclado nunca rolam automaticamente: em vez disso, eles rolam o item até ficar
visível. `isAutoScrolling` (do `useDnD()` ou de uma área de arraste) é `true` enquanto algo rola.

## Vibração e a tecla de cópia {#haptics-and-the-copy-key}

Um arraste por toque vibra rapidamente quando começa. `:haptics="false"` desliga isso; um objeto
define cada vibração:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

| Chave | Vibra quando | Padrão |
| --- | --- | --- |
| `start` | O toque longo vira arraste. | `true` (10 ms) |
| `enter` | O arraste entra em um alvo que o aceita. | desligado |
| `drop` | O drop é concluído. | desligado |
| `refuse` | O drop é recusado e os itens voltam ao lugar. | desligado |

Cada uma recebe `true` (o padrão), uma duração em ms, um padrão liga/desliga, ou `false`. Só os
arrastes iniciados por toque vibram, e o Safari do iOS não consegue vibrar.

`copyModifier` é a tecla que, segurada durante um arraste entre listas, transforma o movimento em
cópia: `'Alt'` por padrão, qualquer `KeyboardEvent.key`, ou `null` para nenhuma. A lista de onde os
itens vêm precisa de uma função `clone`; veja [listas que compartilham itens](/docs/guides/shared-lists).

## Vários providers {#several-providers}

A maioria dos apps precisa de exatamente um. Coloque a lista de desejos sob um provider próprio, e
tente mover um livro de um lado para o outro: ele não consegue sair do seu provider, e o monitor
externo deixa de ouvir a lista de desejos.

::example{name="provider-nested" hint="Mova um livro de um lado para o outro, depois dê à lista de desejos um provider próprio" height="33.5rem"}
::

```vue
<DnDProvider>
  <Shelf v-model="reading" />
  <DnDProvider>
    <Shelf v-model="wishlist" />
    <EventLog />            <!-- hears the inner provider's drags only -->
  </DnDProvider>
</DnDProvider>
```

- Os providers são independentes: um arraste nunca passa de um para outro.
- Providers aninhados são permitidos. **Vence o dono mais próximo**: um item pertence ao provider
  mais próximo acima dele, e o provider externo o ignora.
- Cada provider tem a sua própria seleção, overlay, live region e monitores.

Um segundo provider só faz sentido para uma parte da página que precisa das suas próprias
configurações de provider (colisão, teclas do teclado, anúncios) e cujos itens nunca saem dela.
Se os itens não conseguem se mover entre duas partes da página, verifique se eles não estão sob
dois providers.

::tip
Regras para uma parte da página (um quadro que encaixa na grade, um feed com um toque mais longo,
um painel onde nada é arrastado) não precisam de um provider próprio:

```ts
makeDragArea(board, { modifiers: [snapToGrid(20)], activation: { touch: { delay: 400 } } });
```

Os itens dela continuam no provider do app e ainda podem ir para qualquer lugar. Veja
[restrições](/docs/guides/constraints).
::

Um app montado em outro lugar, dentro de uma shadow root ou como um app Vue separado, pode se
juntar a um provider existente: passe `useDnDContext()` para `provideDnDContext(app, context)`
antes de montá-lo. O teste do que está sob o ponteiro e o overlay funcionam através de shadow roots.

## SSR e Nuxt {#ssr-and-nuxt}

O provider é seguro para SSR. Listas e itens são renderizados no servidor como qualquer outra
marcação. O overlay e a live region são teleportados e montados só no cliente, então nunca causam
um hydration mismatch. Os ids padrão vêm do `useId()` do Vue e batem entre servidor e cliente.

No Nuxt, o módulo registra o `DnDProvider` globalmente e importa os composables automaticamente:
veja [instalação](/docs/getting-started/installation#nuxt).
