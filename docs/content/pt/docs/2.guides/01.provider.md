## Um provider para o app {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Coloque um `DnDProvider` lá no alto, no `App.vue` ou em um layout, e esqueça dele. Todo
composable (`makeSortableList`, `makeDraggable`, `useDnD`…) procura o provider mais próximo
acima do componente em que roda.

::warning
Um composable precisa rodar em um componente **renderizado dentro** do provider. Chamá-lo no
componente cujo próprio template contém `<DnDProvider>` lança
`No <DnDProvider> found above this component`: o `inject` do Vue só enxerga ancestrais.
::

## O que ele controla {#what-it-owns}

| Parte | O que o provider faz |
| --- | --- |
| Entrada | Transforma entrada por ponteiro, toque e teclado em arrastes (`sensors`), um arraste por vez. |
| Encontrar o alvo | Testa quais alvos de drop estão sob o arraste (`collision`) e avisa a eles. |
| O overlay | Renderiza a caixa que segue o ponteiro, teleportada para `body`, e a pousa no drop. |
| A seleção | Um único conjunto de ids selecionados, compartilhado por todas as listas e draggables abaixo dele. |
| Rolagem automática | Rola contêineres e a janela quando um arraste se aproxima das bordas deles. |
| A live region | Anuncia aos leitores de tela quando um item é pego, movido, solto ou cancelado. |

Ele não renderiza mais nada: sua marcação fica como está.

## Opções em resumo {#options-at-a-glance}

Toda opção tem um padrão que funciona, então o provider geralmente não recebe nenhuma.

| Prop | Padrão | O que define |
| --- | --- | --- |
| `collision` | `pointerFirst` | Como o alvo sob o arraste é escolhido. |
| `modifiers` | `[]` | Regras de movimento para todo arraste (encaixe, restrição, …). |
| `animation` / `dropAnimation` | ligado | Itens deslizando durante a ordenação / o overlay pousando. |
| `animate` | desligado | Padrão para listas e árvores: animar mudanças de dados que nenhum arraste fez. |
| `autoScroll` | ligado | Rolagem nas bordas: `{ threshold, maxSpeed, acceleration }` ou `false`. |
| `activation` | mouse 4 px, toque 200 ms | Quando um pressionar vira arraste, por tipo de ponteiro. |
| `keyboard` | Space / Enter, Escape | Teclas e passo do teclado; `false` desliga os arrastes por teclado. |
| `sensors` | ponteiro + teclado | O que transforma entrada em arrastes. |
| `haptics` | uma vibração curta ao pegar por toque | Vibrações para arrastes por toque, ou `false`. |
| `copyModifier` | `'Alt'` | Tecla que, segurada durante o arraste, transforma um movimento em cópia (a lista precisa de `clone`). |
| `overlayTo` | `'body'` | Para onde o overlay é teleportado. |
| `overlayFit` | `'slot'` | Tamanho do overlay: o da posição onde vai pousar, ou o do elemento de origem. |
| `announcements` | embutidos | Textos para leitores de tela, ou `false`. |
| `defaultStyles` | `true` | Injeta CSS de especificidade zero para os estados do arraste. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

A lista completa, com todos os formatos, está na [API do DnDProvider](/docs/api/dnd-provider). O
provider também emite `drag-start`, `drag-move`, `drag-over`, `drag-end` e `drag-cancel`,
os mesmos eventos que o `useDnDMonitor` escuta.

::tip
Regras para uma parte da página (um quadro com encaixe, um feed que só rola na vertical)
não precisam de um provider próprio: envolva essa parte em uma [área de arraste](/docs/guides/constraints).
::

## Ler o arraste: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Arraste uma tarefa e observe o estado" height="22rem"}
::

`useDnD()` retorna o arraste como estado reativo, em qualquer componente sob o provider:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Campo | O que contém |
| --- | --- |
| `status` | `'idle'`, `'activating'` (um toque longo carregando), `'dragging'`, `'dropping'` (pousando, ou esperando um `onBeforeDrop` assíncrono), `'selecting'` (um retângulo de seleção). |
| `active` | O que está sendo arrastado: `id`, `ids` (todos os ids arrastados, começando pelo item pego), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` quando ocioso. |
| `over` | O alvo sob o arraste: `id`, `data`, `element`, `rect` e `accepted`. `null` quando não há nada embaixo. |
| `pointer` | O ponteiro em coordenadas da viewport, depois dos modificadores. |
| `activation.progress` | De `0` a `1` enquanto um toque longo carrega: desenhe um anel com ele. |
| `isAutoScrolling` | A rolagem automática está movendo algo. |
| `selection` | A seleção do provider: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. Veja [multi-drag](/docs/guides/multi-drag). |
| `cancel()` | Cancela o arraste em andamento (os itens voltam ao lugar), um toque longo carregando ou um retângulo de seleção. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

Assim que um drop é decidido, `active`, `over` e `pointer` passam a ser `null`, mesmo enquanto
o overlay ainda está pousando (`status` continua `'dropping'`). Uma UI derivada deles nunca
mostra o arraste antigo ao lado dos dados novos. Enquanto um `onBeforeDrop` assíncrono espera, o
estado fica como estava no momento em que o item foi solto.

## Escutar todo arraste: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

Um monitor escuta todo arraste sob o seu provider, onde quer que ele comece. Ele para quando o
componente que o chamou é desmontado.

| Evento | Quando |
| --- | --- |
| `onDragStart` | Um arraste começa. |
| `onDragMove` | O arraste se move. |
| `onDragOver` | O alvo sob o arraste muda. |
| `onBeforeDrop` | O arraste é solto. A resposta dele decide o drop: veja [decisões de drop](/docs/guides/drop-decisions). |
| `onDragEnd` | O drop foi concluído. As listas ordenáveis já rodaram o `onDrop` delas e gravaram a nova ordem. `dropped` é `false` quando terminou sem nenhum alvo embaixo. |
| `onDragCancel` | Escape, um drop em um alvo que o recusa, ou um `onBeforeDrop` que respondeu `'reject'`. |
| `onDragResume` | `onBeforeDrop` respondeu `'continue'`: nada foi solto, e o arraste continua. |

Todo evento traz `active`, `over`, `pointer`, `delta` (o deslocamento desde o início),
`position` (onde a caixa arrastada fica dentro de `over`, veja
[arrastar e soltar](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) e, para itens
de uma lista ordenável, `source`. Os formatos completos estão na [API de eventos](/docs/api/events).

::note
`onDragEnd` é o lugar para o trabalho "depois do drop": salvar, limpar a seleção,
analytics. O próprio `onDrop` de uma lista roda **antes** da gravação, então ainda vê a ordem antiga.
::

## Vários providers {#several-providers}

A maioria dos apps precisa de exatamente um. Um segundo provider só faz sentido para uma parte da
página que precisa das próprias configurações de provider (colisão, teclas, anúncios) e cujos
itens nunca saem dela:

- Providers são independentes: um arraste nunca passa de um para outro.
- Providers aninhados são permitidos. **Vence o dono mais próximo**: um item pertence ao provider
  mais próximo acima dele, e o provider externo o ignora.
- Cada provider tem a sua própria seleção, overlay e live region.

Se os itens não conseguem passar entre duas partes da sua página, verifique se eles não estão sob
dois providers.

::tip
Um app montado em outro lugar, dentro de uma shadow root ou como um app Vue separado, pode se
juntar a um provider existente: passe `useDnDContext()` para `provideDnDContext(app, context)`
antes de montá-lo.
::

## SSR e Nuxt {#ssr-and-nuxt}

O provider é seguro para SSR. Listas e itens são renderizados no servidor como qualquer outra
marcação. O overlay e a live region são teleportados e montados apenas no cliente, então nunca
causam um hydration mismatch. Os ids padrão vêm do `useId()` do Vue e coincidem entre servidor e
cliente.

No Nuxt, o módulo registra `DnDProvider` globalmente e importa os composables automaticamente:
veja [instalação](/docs/getting-started/installation#nuxt).
