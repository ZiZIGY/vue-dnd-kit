Troque o eixo, a grade e os limites, depois arraste uma nota. O quadro define as regras para todo
arraste que começa nele, e cada nota fica onde você a solta.

::example{name="constraints" hint="Troque as regras, depois arraste uma nota" height="26rem"}
::

## Travar um eixo {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` move só na horizontal, `'y'` só na vertical. `makeDraggable`, `makeSortableList`,
`makeSortableTree`, `makeSortableItem` e `makeDragArea` aceitam essa opção.

- A trava roda **depois de todos os modificadores**, então se mantém não importa o que eles
  façam: um encaixe ou um limite não consegue tirar o item da sua linha.
- O `axis` do próprio item prevalece sobre o da lista ou da árvore, e o de um draggable (ou da
  lista dele) prevalece sobre o da área de arraste.
- Ele é lido quando um arraste começa, então um getter pode alterná-lo:
  `axis: () => (locked.value ? 'y' : undefined)`.
- Uma árvore travada em `'y'` ainda aninha: a profundidade passa a vir de pairar sobre o meio de
  uma linha.

::tip
Prefira `axis` aos modificadores `restrictToVerticalAxis` e `restrictToHorizontalAxis`. Eles fazem
a mesma coisa, mas, como modificadores comuns, rodam no meio da cadeia, e um modificador depois
deles (uma grade que encaixa os dois eixos) pode tirar o item do eixo de novo.
::

## Modificadores {#modifiers}

Um modificador ajusta o deslocamento do arraste a cada frame. O resultado dele move o overlay
**e** é o ponto onde os alvos são procurados, então uma lista ordena pela posição travada,
limitada ou encaixada.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Modificador | O que faz |
| --- | --- |
| `restrictToVerticalAxis` | Move só na vertical. Prefira `axis: 'y'`. |
| `restrictToHorizontalAxis` | Move só na horizontal. Prefira `axis: 'x'`. |
| `restrictToWindowEdges` | Mantém o overlay dentro da janela. |
| `restrictToParent` | Mantém o overlay dentro do contêiner onde o arraste começou: a lista ordenável, ou o elemento pai de um draggable simples. |
| `restrictToElement(target)` | Mantém o overlay dentro de um elemento: um template ref, um getter ou o próprio elemento. |
| `restrictToFirstScrollableAncestor` | Mantém o overlay dentro do primeiro ancestral rolável do elemento arrastado. |
| `snapToGrid(size)` | Encaixa o overlay em uma grade (abaixo). |
| `snapCenterToCursor` | Centraliza o overlay sob o ponteiro em vez de manter o deslocamento de onde ele foi pego. |

`modifiers` é uma opção do provider, das áreas de arraste, das listas e árvores, e dos
draggables e itens ordenáveis. Todas, exceto a do provider, também aceitam um ref ou um getter,
lido quando o arraste começa.

### Encaixar em uma grade {#snap-to-a-grid}

`snapToGrid(24)` encaixa os dois eixos em células de 24 px. Um objeto define mais coisas:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Opção | Significado |
| --- | --- |
| `x`, `y` | O tamanho da célula em pixels, por eixo. |
| `origin` | `'container'` (padrão): o canto superior esquerdo do overlay pousa nas linhas de uma grade traçada a partir do canto superior esquerdo do contêiner — a lista ordenável, ou o pai de um draggable simples. `'delta'`: o próprio deslocamento é arredondado, então um item que começou fora da grade continua fora dela. |
| `smooth` | `true` ou `{ duration, easing }`: o overlay desliza entre as células (80 ms por padrão). Os alvos usam a posição encaixada na hora. |

### O seu próprio modificador {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

Um modificador recebe `transform`, o deslocamento desde o início do arraste como os modificadores
anteriores o deixaram, e retorna um novo. Ele também recebe o que pode precisar para calculá-lo:
`activeRect` (o elemento arrastado no início), `overlayRect` (o overlay movido por `transform`),
`containerRect`, `windowRect`, `origin` (o ponteiro no início), `active` e `over`. Veja
[Modificadores](/docs/api/modifiers).

## A ordem {#the-order}

Modificadores de vários lugares rodam um depois do outro, cada um a partir do resultado do
anterior:

1. os `modifiers` do provider;
2. os `modifiers` da área de arraste onde o arraste começou;
3. os `modifiers` do próprio item arrastado ou, quando ele não tem nenhum, os da lista ou da
   árvore dele;
4. o `restrictToArea` da área de arraste;
5. a trava de `axis`.

Os `modifiers` de um item **substituem** os da lista; não se somam a eles. Os limites da área vêm
depois do encaixe dos passos 1–3, então um item encaixado ainda fica dentro, e a trava de eixo
vem por último.

## Listas com limites mantêm as pontas {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

Um limite segura o overlay na borda da caixa enquanto o ponteiro segue em frente. Quando o
ponteiro sai do overlay ao longo do eixo da lista, a lista passa a ordenar pelo ponteiro, então o
primeiro e o último lugar continuam ao alcance não importa como você segure o item. As grades
continuam ordenando pelo overlay: segurado na borda, ele já cobre a célula da borda.

## Regras para uma parte da página {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` define regras para os arrastes que **começam dentro** do seu elemento — tanto
draggables simples quanto itens ordenáveis. Mantenha um único `DnDProvider` para o app inteiro, e
dê a um quadro, a um canvas ou a um feed uma área própria.

| Opção | O que faz |
| --- | --- |
| `axis` | Trava os arrastes em um eixo. O `axis` do próprio draggable, ou da lista dele, prevalece. |
| `modifiers` | Rodam depois dos do provider e antes dos do próprio draggable. |
| `restrictToArea` | `true`: os arrastes ficam dentro do elemento da área. |
| `autoScroll` | Rolagem automática do contêiner de rolagem da área (o elemento, ou o ancestral rolável mais próximo dele). `false` a desliga ali. |
| `activation` | [Ativação](/docs/guides/sensors#activation-constraints) por tipo de ponteiro. A do próprio draggable prevalece; a do provider vem por último. |
| `disabled` | Nenhum arraste começa na área, nem nas áreas dentro dela. Os draggables dela informam `aria-disabled`. |

Toda opção aceita um valor, um ref ou um getter, lido quando um clique ou um arraste começa. A
área retorna `isDragging` (um arraste que começou aqui está em andamento) e `isAutoScrolling` (a
rolagem automática está movendo o contêiner dela). Referência completa:
[makeDragArea](/docs/api/make-drag-area).

### Como as áreas se combinam {#how-areas-combine}

- Um arraste segue a área onde **começou**, mesmo depois de sair dela. Passar sobre uma área não
  muda nada, exceto o `autoScroll` dela: esse vale para todo arraste que rola o contêiner dela.
- Áreas aninhadas não se mesclam: vence a mais próxima. `disabled` é a exceção, e é herdado: uma
  área desligada desliga também as áreas dentro dela.
- A detecção de colisão, as teclas e os anúncios continuam valendo para o provider inteiro.

::note
Por que não um segundo `DnDProvider` ao redor do quadro? Providers são independentes: um arraste
nunca passa de um para outro, então os itens do quadro nunca poderiam sair dele. Aninhe um
provider só quando uma parte da página precisa das próprias configurações de provider e os itens
dela ficam lá dentro. Veja [O provider](/docs/guides/provider).
::

## Deixar onde foi solto {#leave-it-where-its-dropped}

O quadro do exemplo também é um alvo de drop, e cada nota mantém o lugar onde foi solta. Todo
evento de arraste traz `position`: o canto superior esquerdo da caixa arrastada dentro do alvo,
a partir da borda do padding dele e com a rolagem dele — o `left` e o `top` que colocam um item
com posicionamento absoluto exatamente ali. Ele vem depois dos modificadores, então uma nota
encaixada pousa na grade.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

Mais sobre arraste livre e alvos de drop em [Arrastar e soltar](/docs/guides/drag-and-drop).
