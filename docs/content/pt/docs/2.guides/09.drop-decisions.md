Arraste um card para **Done**. O drop espera a sua resposta: mover o card, continuar arrastando-o
para outro lugar ou cancelar.

::example{name="drop-confirm" hint="Arraste um card para Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

Listas, árvores, alvos de drop (`makeDroppable`) e monitores (`useDnDMonitor`) aceitam um
`onBeforeDrop`. Ele roda quando o arraste é solto, antes que qualquer coisa mude, e a resposta
dele decide:

| Resposta | O que acontece |
| --- | --- |
| `'accept'`, `true` ou nada | O drop é concluído. |
| `'reject'` ou `false` | Nenhum drop: os itens voltam ao lugar. Um erro lançado também rejeita. |
| Um array de keys | Só esses itens são soltos; os outros voltam ao lugar. |
| `'continue'` | Nenhum drop, e o arraste continua. |
| Uma promise de qualquer um desses | O overlay espera onde foi solto até a promise ser resolvida. |

As regras do próprio alvo vêm primeiro: o `accept` de um alvo de drop, o `group.put` de uma
lista. Sobre um alvo que recusa o arraste, o drop é cancelado e o `onBeforeDrop` do alvo não é
consultado. `onBeforeDrop` serve para o que essas regras não têm como saber: a resposta do
usuário, a do servidor, ou o que o drop mudaria.

Listas e árvores passam um `SortableDropEvent`: `keys`, `items`, `from`, `to`, `mode`,
`sameList` e `result`, os novos arrays de todas as listas que o drop altera. Alvos de drop e
monitores recebem o `DnDEvent` genérico: `active`, `over`, `position` e `source`. Veja
[Eventos](/docs/api/events).

### Aceitando parte dos itens {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

Em um [multi-drag](/docs/guides/multi-drag), as keys que você retorna pousam e o resto volta para
de onde veio. O `onDrop` então os vê em `e.accepted` e `e.rejected`, e o `e.result` dele é o
final.

## Continuar arrastando: 'continue' {#keep-dragging-continue}

`'continue'` cancela o drop, não o arraste. O item continua na mão a partir de onde estava, a
página volta ao modo de arraste, e o usuário segue em frente:

- Com um mouse ou uma caneta, o item segue o ponteiro sem nenhum botão pressionado. O próximo
  soltar — um clique — solta o item, e esse clique nunca chega à página embaixo.
- Um toque pega o item de novo onde o dedo encosta; levantar o dedo o solta.
- Um arraste por teclado continua: as setas movem o item, :kbd{value="Space"} ou
  :kbd{value="Enter"} o soltam.
- :kbd{value="Escape"} o cancela, como qualquer arraste.
- O próximo drop consulta o `onBeforeDrop` de novo.

Os monitores escutam `onDragResume`, e os leitores de tela ouvem que o item não foi solto e
continua se movendo (substitua o texto com o `announcements.onDragResume` do provider).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## Perguntando ao usuário {#asking-the-user}

`onBeforeDrop` pode retornar uma promise. Abra um diálogo, e resolva a promise com o botão que o
usuário escolher:

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Enquanto a promise está pendente:

- o overlay espera onde foi solto, marcado com `data-dnd-overlay="dropping"`;
- `useDnD()` mantém o estado que tinha no momento em que o item foi solto, e `status` é
  `'dropping'`;
- a página sai do modo de arraste: o cursor e a seleção de texto voltam, então um diálogo
  funciona normalmente.

::tip
Um `<dialog>` modal aberto com `showModal()` fica na top layer, acima do overlay que está
esperando. Transforme o evento `cancel` dele (:kbd{value="Escape"}) em `'reject'`, como o exemplo
faz.
::

## A ordem dos hooks {#the-order-of-the-hooks}

1. O `onBeforeDrop` de cada `useDnDMonitor`, um de cada vez. Um `'reject'` ou um `'continue'`
   encerra as consultas; keys restringem o drop.
2. O `onBeforeDrop` do alvo: a lista ou árvore para onde os itens vão, ou o alvo de drop.
3. O `onDrop` apenas do alvo: uma lista que os itens deixam rumo a outra não é consultada, e o
   novo array dela está no `e.result` do alvo. Quando itens são removidos (uma zona de lixeira,
   `dropOutside: 'remove'`), o `onDrop` da lista deles roda, com `to.index` igual a `-1`.
4. A gravação padrão: cada lista que o drop altera recebe o seu novo array.
5. O overlay pousa. Em seguida vêm o `@drag-end` do provider e o `onDragEnd` dos monitores.

Os seus monitores decidem antes do alvo, então o veto deles nunca chega depois de uma lista já
ter aplicado um drop por conta própria.

## onDrop: avisado antes da gravação {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

O `onDrop` de uma lista roda assim que o drop é aceito, de forma síncrona, logo antes de a lista
gravá-lo. Para agir depois da gravação, use o `@drag-end` do provider ou
`useDnDMonitor({ onDragEnd })`. Em um alvo de drop simples, `onDrop` é onde você altera os seus
dados: a biblioteca não move nada por ele.

## Stores e servidores: listas controladas {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

A biblioteca só grava um drop em um ref gravável. Um getter, um `computed` ou um ref `readonly`
nunca é gravado: chame `e.preventDefault()` e aplique `e.result` você mesmo — os novos arrays de
todas as listas que o drop altera, por id de lista. `preventDefault()` pula a gravação em todas
elas, já que gravar só em algumas perderia ou duplicaria itens. Os builds de desenvolvimento
avisam quando o drop de uma lista somente leitura fica a cargo da biblioteca.

### Salvando primeiro em um servidor {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Aplique `e.result` antes de a promise ser resolvida, e o overlay pousa na nova ordem. Quando a
requisição falha, não aplique nada: o drop é concluído, não muda nada, e os itens voltam ao
lugar.

## Soltar fora de todos os alvos {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | Um drop fora de todos os alvos… |
| --- | --- |
| `'placeholder'` | Pousa onde está o placeholder: o último lugar que a lista mostrou. O padrão. |
| `'cancel'` | É cancelado: os itens voltam ao lugar. O padrão com `placeholder: 'indicator'`. |
| `'remove'` | Remove os itens da lista deles. O `onBeforeDrop` da lista é consultado primeiro, e o `onDrop` dela recebe `to.index` igual a `-1`. |

Uma zona de lixeira faz o mesmo de propósito:
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`. Veja
[Arrastar e soltar](/docs/guides/drag-and-drop).
