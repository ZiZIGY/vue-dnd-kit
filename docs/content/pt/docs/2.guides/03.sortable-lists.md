## Uma lista e suas linhas {#a-list-and-its-rows}

Uma lista ordenável usa dois componentes: a lista e a linha dela.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

A linha se registra na lista dentro da qual é renderizada. É também por isso que cada lista
precisa de um componente próprio: duas listas criadas em um mesmo componente compartilhariam as
linhas.

## O rascunho {#the-draft}

`makeSortableList` retorna `items`, um **rascunho** do seu array. Enquanto você arrasta, o
rascunho se reordena ao vivo: a linha arrastada ocupa a nova posição, e as outras deslizam para
abrir espaço. O seu array não muda até o drop. Aí a biblioteca grava a nova ordem nele.

::example{name="quick-start" hint="Os ids abaixo da lista são o seu array: eles mudam no drop"}
::

- Renderize `items`, não o seu array. Renderizando o seu array, nada se move até o drop.
- A gravação acontece depois do `onDrop` da lista. Em `onDrop`, o seu array ainda tem a ordem
  antiga e `e.result`, a nova.
- `tasks` é um `ref` comum, então o resto do seu app vê a mudança como qualquer outra.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

Um componente de lista que recebe o array via `v-model` repassa o model:

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
Uma store, estado do servidor ou dados imutáveis? Passe um getter ou um `computed` em vez de um
ref. A biblioteca não grava em uma fonte somente leitura: chame `e.preventDefault()` e aplique
`e.result` você mesmo. Veja [decisões de drop](/docs/guides/drop-decisions).
::

## Keys {#keys}

As linhas são identificadas pelos dados, nunca pelo índice nem por um id automático. Por padrão,
a key é `item.id`, ou o próprio item no caso de strings e números.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Use a mesma key no `v-for`: `:key="task.uuid"`. Com `:key="index"`, as linhas erradas são
  animadas e o estado delas pula de uma linha para outra.
- As keys precisam ser únicas entre todas as listas que trocam itens.
- Passe `item` e `id` como getters, para que a linha continue sincronizada quando as props dela
  mudarem.

## Estratégias {#strategies}

| `strategy` | Para |
| --- | --- |
| `'vertical'` (padrão) | Uma coluna de linhas. |
| `'horizontal'` | Uma única linha: abas, chips, uma linha do tempo. |
| `'grid'` | Grids CSS e linhas flex com quebra, inclusive com itens de tamanhos diferentes. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Handles {#handles}

Por padrão, a linha inteira inicia um arraste (exceto botões, inputs e outros controles dentro
dela). Passe `handle` para arrastar só por uma parte:

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` é um seletor dentro do item, ou um ref de elemento.
- Um arraste com o mouse começa pelo handle na hora, sem os 4 px de costume.
- O handle recebe os atributos do arraste (`role`, `tabindex`, `aria-*`), e os arrastes por
  teclado começam por ele.

Faça do handle um `<button type="button">` com um `aria-label`: ele já pode receber foco, e os
leitores de tela anunciam o rótulo dele. Um `<span>` simples com um ícone também funciona (a
biblioteca dá a ele `tabindex="0"` e `role="button"`), mas não tem um nome significativo.

::note
Arrastes por toque começam depois de um toque longo de 200 ms, para que a página ainda possa
rolar. Para arrastar na hora a partir de um handle, dê ao handle `touch-action: none` e ao item
`activation: { touch: { distance: 4 } }`.
::

## Travar o eixo {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` mantém o arraste no eixo vertical, `'x'` no horizontal. O `axis` do próprio item
prevalece sobre o da lista. Para também manter o arraste dentro da lista, adicione o modificador
`restrictToParent`; a playlist acima usa os dois. Mais em
[restrições](/docs/guides/constraints).

## Estilizar a posição {#style-the-slot}

A linha arrastada fica na lista como a posição onde vai pousar, e recebe
`data-dnd-placeholder`. O estilo padrão a deixa com 40% de opacidade, com especificidade zero,
então qualquer regra sua prevalece:

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` retorna o mesmo estado como refs, e mais alguns:

| Retorno | O que é |
| --- | --- |
| `isPlaceholder` | Esta linha é a posição onde um item arrastado vai pousar. |
| `isDragging` | Esta linha está sendo arrastada (todas as linhas arrastadas, em um multi-drag). |
| `index` | O índice dela no rascunho: muda enquanto você arrasta. |
| `selected` | Gravável, ligado à seleção do provider. |
| `indicator` | No [modo indicador](/docs/guides/shared-lists#an-insertion-line), onde fica a linha. |

A lista retorna `isOver` e `isAccepting` para o seu próprio destaque. Todos os atributos e
receitas estão em [estilização](/docs/guides/styling).

## Desligando recursos {#turning-things-off}

- `disabled` na lista: nenhum arraste sai dela, nenhum drop entra nela. Em um item: ele não pode
  ser arrastado.
- `sort: false`: os itens não podem ser reordenados dentro desta lista, mas ainda podem sair dela
  (uma paleta, veja [listas que compartilham itens](/docs/guides/shared-lists)).

## Animações {#animations}

As linhas deslizam para os novos lugares enquanto você arrasta, e a linha solta pousa na sua
posição. Isso vem ligado por padrão e não precisa de código. Não envolva as linhas em
`<TransitionGroup>`: os movimentos seriam animados duas vezes. Para mudanças que nenhum arraste
fez (adicionar, remover, embaralhar), ligue a opção `animate` da lista. Veja
[animações](/docs/guides/animations).

A lista completa de opções está na API de [makeSortableList](/docs/api/make-sortable-list) e de
[makeSortableItem](/docs/api/make-sortable-item).
