`@vue-dnd-kit/devtools` adiciona uma aba **Vue DnD Kit** ao Vue DevTools (`vite-plugin-vue-devtools`)
e ao Nuxt DevTools. Ela mostra todas as listas, árvores e alvos de drop da página em um minimapa ao
vivo, arrasta qualquer item com um joystick, edita opções enquanto o app roda e registra o que cada
arraste fez. Ela só funciona em desenvolvimento: nada dela chega a um build de produção.

## Instalação {#install}

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` é uma peer dependency: os movimentos da aba passam por ele. O npm 7+ e o
pnpm o instalam sozinhos; com o Yarn 1, adicione-o.

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

Com o Vite, o plugin serve a aba em `/__vue-dnd-kit-devtools/`, a adiciona ao Vue DevTools e faz a
página se reportar a ela antes de o seu app iniciar. Não é preciso nenhum `app.use()`. Ele só age
no servidor de desenvolvimento (`vite serve`); os builds ficam intactos.

Com o Nuxt, o módulo `@vue-dnd-kit/nuxt` encontra o pacote, serve a aba, a adiciona ao Nuxt
DevTools e instala o lado da página com um plugin de cliente. `vueDndKit: { devtools: false }` a
desliga.

### Sem os plugins {#without-the-plugins}

Para um servidor de desenvolvimento próprio, ou uma página que o Vite não serve a partir de um
`index.html` (configurações com SSR), instale você mesmo o lado da página:

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

Ou importe `@vue-dnd-kit/devtools/auto` primeiro no arquivo de entrada. Use
`vueDnDKitDevtools({ inject: false })` quando o plugin deve servir a aba mas você mesmo instala o
lado da página; `serveTab()` de `@vue-dnd-kit/devtools/vite` é o middleware que serve a aba.

## Abrindo a aba {#open-it}

- **Vue DevTools**: :kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"}, ou o botão do Vue
  na parte de baixo da página, depois a aba **Vue DnD Kit**.
- **Nuxt DevTools**: :kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"}, ou o botão do
  Nuxt, depois **Vue DnD Kit** (na barra lateral ou no menu de itens extras dela).
- **Uma janela própria**: abra `http://localhost:5173/__vue-dnd-kit-devtools/` no seu servidor de
  desenvolvimento, ou use o botão ⧉ da aba. Prático em uma segunda tela.

::warning
Mantenha a aba em uma janela própria, não em uma aba do navegador em segundo plano: uma página
oculta cancela os arrastes.
::

## O que a aba mostra {#what-the-tab-shows}

### O minimapa {#the-mini-map}

Um card ao vivo por lista, árvore e alvo de drop, com cópias dos itens onde eles estão — os mesmos
clones que o overlay mostraria. Durante um arraste, ele marca as listas que aceitam o arraste
(azul) ou o recusam (vermelho), o placeholder, o alvo sob o ponteiro, a caixa do overlay e a linha
de inserção das listas com `placeholder: 'indicator'`. Um clique escolhe um item; um clique duplo
rola a página até ele.

Use-o quando um drop não vai para onde você espera: ele mostra num relance quais listas aceitam o
arraste.

### Conduzir: o joystick {#drive-the-joystick}

Escolha um item — no mapa, na árvore ou com **Pick**, que pega o próximo clique na página — e
empurre a alavanca do joystick. O item é pego e se move nessa direção, mais rápido quanto mais
longe a alavanca estiver do centro. **Drop** e **Cancel** encerram o arraste.

É um arraste por ponteiro de verdade, de um sensor chamado `devtools`, então as listas ordenam, os
contêineres rolam automaticamente, e `onBeforeDrop` e `onDrop` rodam como em qualquer arraste. Os
itens das listas ordenáveis também ganham botões: para cima, para baixo, para o início, para o
fim, para outra lista do grupo.

| Tecla, na aba | Faz |
| --- | --- |
| Setas ou :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | Empurra a alavanca nessa direção; com :kbd{value="Shift"}, até o fim |
| :kbd{value="G"} | Pega o item escolhido |
| :kbd{value="Space"} / :kbd{value="Enter"} | Solta |
| :kbd{value="Escape"} | Cancela |
| :kbd{value="P"} | Escolhe na página |

### Opções {#options}

Toda opção que não é um callback pode ser editada enquanto o app roda: as do provider
(`collision`, `modifiers`, `overlayFit`, `autoScroll`, animações, `activation`, `keyboard`…), as de
uma lista (`strategy`, `placeholder`, `behavior`, `multiple`, `dropOutside`, `disabled`…), as de
uma árvore, de um alvo de drop e de um item. Escolha o nó e abra **Options**.

Uma edição é aplicada na hora, só nesta página, e nunca é gravada no seu código. Ela dura até você
redefini-la, o provider ser desmontado ou a página recarregar.

### Estado {#state}

O que cada provider sabe, em forma de árvore: a sessão de arraste dele (status, os ids ativos e o
sensor, o alvo e se ele aceita, o ponteiro), as listas e árvores dele com a ordem e o rascunho, os
alvos de drop com as regras deles, e os tipos e dados dos itens.

### Log {#log}

Uma faixa por arraste: o início (ids, sensor, a lista de onde veio), cada `over` e `left` com a
aceitação, o momento de soltar, o veredito do `onBeforeDrop` — aceito, parcialmente aceito,
rejeitado por um hook, recusado pelo `accept` do alvo — e o `drop`, com `e.result` e se
`preventDefault()` foi chamado, ou o `cancel` e o motivo. Clique em uma entrada para ver os dados
dela.

Use-o quando um drop é recusado e você não sabe por quem, ou quando uma lista controlada não
mudou: o log diz se `preventDefault()` rodou e o que `e.result` continha.

## Como funciona {#how-it-works}

Os providers se reportam a um hook que o lado da página instala. Até que uma aba observe a página,
eles só ficam registrados; depois, a página escuta como qualquer monitor e envia à aba o que ela
mostra — a cada 40 ms durante um arraste, duas vezes por segundo no resto do tempo — e para quando
nenhuma aba a observa há alguns segundos. A aba conversa com a página por um `BroadcastChannel` da
origem da página. Ela não muda nada além do que você pede: os arrastes, a seleção e as opções
sobrescritas.
