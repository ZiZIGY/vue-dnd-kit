## A seleção {#the-selection}

Cada provider mantém uma seleção: um conjunto reativo de ids. Arrastar um item **selecionado**
arrasta todos os itens selecionados, começando pelo item pego. Arrastar um item que não está
selecionado arrasta só esse item.

A biblioteca não decide como as pessoas selecionam: as regras de clique são suas. Ela também
nunca limpa a seleção por conta própria, e a seleção sobrevive a desmontagens, como as das linhas
que uma lista virtual recicla.

### Ctrl/Cmd-clique {#ctrlcmd-click}

Todo item ordenável e todo draggable retorna `selected`, um ref gravável ligado à seleção:

```vue [Shot.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ shot: { id: string } }>();
const el = useTemplateRef<HTMLElement>('el');
const { selected } = makeSortableItem(el, { item: () => props.shot });

const onClick = (event: MouseEvent) => {
  if (event.ctrlKey || event.metaKey) selected.value = !selected.value;
};
</script>

<template>
  <div ref="el" :class="{ selected }" @click="onClick">…</div>
</template>
```

O clique que encerra um arraste não chega ao `@click`, então um drop nunca alterna a seleção
por acidente. Use `@click`, não `pointerup`, para as ações dos itens.

### De qualquer lugar: `useDnD().selection` {#from-anywhere-usedndselection}

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// A plain click selects only that item, Ctrl/Cmd-click adds or removes it:
const onClick = (event: MouseEvent, id: string) => {
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
};

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

A seleção é indexada por id, então pode conter itens de várias listas: um arraste leva todos os
itens selecionados sob o provider.

## Seleção por retângulo {#rubber-band-selection}

`makeSelectionArea` transforma um elemento em uma área onde pressionar o espaço vazio desenha um
retângulo, e os itens que ele cruza são selecionados:

```vue [Gallery.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSelectionArea } from '@vue-dnd-kit/core';
import PhotoGrid from './PhotoGrid.vue';

const area = useTemplateRef<HTMLElement>('area');
const { isSelecting, style } = makeSelectionArea(area);
</script>

<template>
  <div ref="area" class="area">
    <PhotoGrid />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.area {
  position: relative;   /* the band is absolutely positioned inside */
  min-height: 320px;    /* room around the items to start a band */
}

.band {
  border: 1px solid #42b883;
  background: color-mix(in srgb, #42b883 15%, transparent);
}
</style>
```

- Você renderiza o retângulo: `style` o posiciona, em relação ao conteúdo da área.
- A área precisa de uma **posição não estática** (`relative` serve), senão o retângulo vai parar
  em outro lugar.
- Um retângulo só começa a partir da própria área, então faça a área grande: o painel inteiro,
  com espaço ao redor dos itens, não um wrapper justo. A galeria acima ocupa a caixa inteira.
- Pressionar um item o arrasta. Botões, campos e a barra de rolagem da área continuam recebendo
  os seus cliques.
- O retângulo fica ancorado ao conteúdo enquanto a área ou a página rolam.
  :kbd{value="Escape"} o cancela e restaura a seleção.
- `useDnD().status` é `'selecting'` enquanto um retângulo é desenhado.

| Opção | O que faz |
| --- | --- |
| `strategy` | `'toggle'` (padrão): os itens que o retângulo cruza se invertem. `'select'`: só os itens dentro do retângulo acabam selecionados, então um clique no espaço vazio desmarca os itens da área. |
| `modifier` | Teclas que precisam estar pressionadas para desenhar: `{ keys: ['Shift'], method: 'every' }` (ou `'some'`). |
| `accept` | Quais draggables o retângulo seleciona, uma [regra de accept](/docs/guides/drag-and-drop#which-drags-a-target-takes) comparada com o `type` deles. |
| `disabled` | Sem retângulo; ligá-lo cancela um que esteja em andamento. |
| `onSelected(ids)` | Chamado quando um retângulo termina, com a seleção. |
| `selection` | Um `Ref<Set<Key>>` seu em vez da seleção do provider. |

Com áreas dentro de áreas, a mais interna recebe o clique. Todas as opções estão na
[API do makeSelectionArea](/docs/api/make-selection-area).

## Como os outros itens se movem: `multiple` {#how-the-other-items-move-multiple}

A lista onde um multi-drag começa decide o que os outros itens selecionados fazem enquanto ele
acontece:

```ts
makeSortableList(listRef, { items: tasks, multiple: 'gaps' });
```

| `multiple` | Durante o arraste | O overlay |
| --- | --- | --- |
| `'group'` (padrão) | Os outros itens saem dos seus lugares e viajam com o que foi pego como um único bloco de posições, então a lista já mostra o resultado do drop. | Uma coluna de até cinco itens arrastados, na direção da lista. |
| `'gaps'` | Os outros ficam onde estão, esmaecidos (`data-dnd-dragging`), até o drop. | A mesma coluna. |
| `'stack'` | Os outros voam para dentro do overlay. | O item pego com um contador. |

No drop, os itens pousam juntos no índice de destino, na ordem que tinham. Em `'group'` e
`'gaps'`, cada item do overlay voa para a sua própria posição.

### O overlay padrão {#the-default-overlay}

Em `'group'` e `'gaps'`, o overlay é uma coluna com os itens arrastados como vão pousar: o que
foi pego sob o ponteiro, os outros antes e depois dele na ordem do drop (uma linha, em listas
horizontais). Ele mostra até cinco itens. Os que passam disso são contados onde estão: `+N` no
início da coluna para os itens que pousam antes dos mostrados, `+N` no fim para os que vêm
depois.

Em grids, uma coluna de células inteiras cobriria a página, então o overlay é uma pilha: até três
itens em leque atrás do que foi pego, com o total por cima.

Draggables simples (`makeDraggable`) mostram o item pego com um contador.

### Tipos mistos {#mixed-types}

Quando os itens selecionados têm tipos diferentes, `acceptMode` em um alvo diz se `'all'`
(padrão) ou `'some'` deles precisam passar. Veja
[listas que compartilham itens](/docs/guides/shared-lists#limits) e
[arrastar e soltar](/docs/guides/drag-and-drop#which-drags-a-target-takes).

## Um overlay personalizado para vários itens {#a-custom-overlay-for-several-items}

Os componentes de overlay e o slot `#overlay` do provider recebem `items`: todos os itens
arrastados, começando pelo item pego. `DragPreview` renderiza o clone que a biblioteca fez de
qualquer um deles, para que o seu layout reaproveite a aparência real:

```vue [PileOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="pile">
    <!-- The grabbed item on top, two more turned behind it -->
    <DragPreview
      v-for="(entry, i) in items.slice(0, 3)"
      :id="entry.id"
      :key="entry.id"
      class="card"
      :style="{ width: '100%', height: '100%', zIndex: 3 - i, rotate: `${i * 4}deg` }"
    >
      <!-- Shown for an item without a clone -->
      <div class="fallback">{{ entry.id }}</div>
    </DragPreview>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.pile { position: relative; width: 100%; height: 100%; }
.card { position: absolute; inset: 0; }
.fallback { width: 100%; height: 100%; border-radius: 8px; background: Canvas; }
.count { position: absolute; top: -8px; right: -8px; z-index: 4; }
</style>
```

```ts
makeSortableList(listRef, { items: photos, strategy: 'grid', overlay: PileOverlay });
```

Os clones são feitos quando o item é pego: do item pego e de até quatro outros ao lado dele na
ordem do drop, se estiverem renderizados. Para qualquer outro item, `DragPreview` renderiza o seu
slot padrão. Uma prévia tem o tamanho que o seu item tinha ao ser pego, a menos que você a
dimensione, como o `style` acima faz (`class` e `style` são repassados). Em `'group'` e
`'gaps'`, cada prévia pousa na posição do seu próprio item no drop. Mais sobre componentes de
overlay em [o overlay](/docs/guides/overlay).

## Árvores {#trees}

Em uma árvore, os nós selecionados se movem como um bloco, cada um com a sua subárvore, na
ordem do documento. Um nó selecionado dentro de outro selecionado vai junto na subárvore do pai.
Veja [árvores](/docs/guides/trees).
