Um sensor transforma entrada em arrastes. Ele só diz ao provider "arraste este item a partir
daqui", depois para onde a entrada se moveu, e se ela soltou ou cancelou. O provider faz o resto,
do mesmo jeito para todo sensor: um arraste por vez, itens desabilitados recusados, restrições de
ativação, ordenação, rolagem automática, anúncios, :kbd{value="Escape"} e o drop inteiro.

## Os sensores embutidos {#the-built-in-sensors}

| Sensor | Entrada |
| --- | --- |
| `pointerSensor` | Mouse, toque e caneta, via Pointer Events. Ele captura o ponteiro, impede que a página selecione texto ou role sob um arraste por toque, e engole o clique que vem depois de um arraste. |
| `keyboardSensor` | :kbd{value="Space"} e :kbd{value="Enter"} pegam e soltam, as setas movem, :kbd{value="Escape"} cancela — qualquer arraste, inclusive os por ponteiro. |

Os dois rodam por padrão. O `sensors` do provider substitui a lista:

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

Para desligar os arrastes por teclado, prefira `:keyboard="false"` a deixar `keyboardSensor` de
fora: o sensor de teclado também é o que cancela qualquer arraste com :kbd{value="Escape"}. As
teclas dele são redefinidas com `keyboard.keys` (veja
[Acessibilidade](/docs/guides/accessibility#the-keyboard)).

## Restrições de ativação {#activation-constraints}

Um pressionar vira arraste assim que atende à sua restrição:

| Ponteiro | Padrão |
| --- | --- |
| Mouse | Depois de mover 4 px. Na hora, ao pressionar um `handle`, a menos que você defina uma restrição para o mouse. |
| Caneta | Depois de mover 4 px. |
| Toque | Depois de pressionar por 200 ms. Mover mais de 5 px antes disso o aborta, e a página rola. |

Uma restrição tem três campos:

| Campo | Significado |
| --- | --- |
| `distance` | Pixels que o ponteiro precisa percorrer. |
| `delay` | Milissegundos que o pressionar precisa durar. Com os dois, o que vier primeiro inicia o arraste. |
| `tolerance` | Com `delay`: quanto o ponteiro pode se mover nesse meio-tempo; passando disso, o pressionar é abandonado. |

Defina-os por tipo de ponteiro — `mouse`, `touch`, `pen` — no provider, em uma área de arraste ou
no próprio item. A do próprio item prevalece, depois a da área dele, depois a do provider:

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

Para arrastar na hora por toque a partir de um handle, dê ao handle `touch-action: none` (para que
o navegador não role) e ao item `activation: { touch: { distance: 4 } }`.

### Um anel de toque longo {#a-long-press-ring}

Enquanto um pressionar espera, `useDnD().status` é `'activating'` e `activation.progress` vai de 0
a 1:

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### Só alguns cliques {#only-some-presses}

`canDrag` é mais uma barreira nos draggables e itens ordenáveis. Ele recebe o evento de entrada:

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

Filhos interativos — botões, inputs, campos editáveis — nunca iniciam um arraste por ponteiro,
então continuam funcionando dentro de um draggable. Com um `handle`, só o handle inicia um.

## Um sensor próprio {#a-sensor-of-your-own}

Um gamepad, um joystick na tela, comandos de voz: qualquer coisa que consiga apontar para um item
e se mover pode conduzir um arraste. Aqui está um joystick que pega o que está sob o seu cursor
depois de segurar por 300 ms:

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

Adicione-o aos `sensors` do provider, ou rode-o enquanto um componente viver com
`useSensor(joystick.sensor)`.

### O que o sensor recebe {#what-the-sensor-gets}

`setup(context)` recebe o lado do provider:

| Membro | O que é |
| --- | --- |
| `props` | As props do provider (`activation`, `keyboard`…). Leia-as quando precisar: elas podem mudar. |
| `status` | O status de arraste do provider, seja qual for o sensor que conduz o arraste. |
| `drag` | O arraste atual do provider, pendente ou em andamento, seja qual for o sensor que o iniciou. `null` quando não há nenhum. |
| `activate(options)` | Pede um arraste. Retorna um `SensorDrag`, ou `null` quando nenhum arraste pode começar. |
| `cancel()` | Cancela o arraste ou o pressionar pendente do provider. |

`activate()` recebe:

| Opção | Significado |
| --- | --- |
| `target` | Onde a entrada caiu: um elemento dentro de um draggable, ou o id de um draggable. Um elemento é verificado como um pressionar de verdade (handle, nenhum filho interativo); um id pula as verificações. |
| `point` | Onde o arraste começa, em coordenadas da viewport. Padrão: o centro do draggable. |
| `type` | `'pointer'` (padrão): segue pontos, testa os alvos sob o ponteiro, rola automaticamente. `'keyboard'`: move de item em item, revela os alvos, devolve o foco no final. |
| `activation` | Uma restrição (`{ delay: 300 }`), ou um tipo de ponteiro (`'touch'`) para usar a restrição configurada. Padrão: nenhuma, o arraste começa na hora. |
| `event` | O evento de entrada, repassado ao `canDrag` do item. Um `pointerType` de toque faz dele um arraste por toque (vibração). |
| `onStart(drag)` | O arraste começou, depois da ativação. |
| `onEnd(drag)` | O arraste acabou: abortado, solto ou cancelado — por quem quer que seja. |
| `onResume(drag)` | `onBeforeDrop` respondeu `'continue'`: o arraste continua, e `move`, `drop` e `cancel` voltam a valer. |

O `SensorDrag` que ele retorna:

| Membro | O que faz |
| --- | --- |
| `id`, `type` | O id do item arrastado, e `'pointer'` ou `'keyboard'`. |
| `state` | `'pending'` (esperando a ativação), `'dragging'`, depois `'ended'`. |
| `started` | O arraste começou, mesmo que já tenha terminado. |
| `move(point)` | A entrada se moveu. Enquanto pendente, verifica a tolerância; durante o arraste, move o arraste. |
| `step(direction)` | Arrastes por teclado: um passo de seta, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | Coloca o item em uma posição de uma lista ordenável, como fazem os movimentos por teclado. Resolve `false` quando nenhuma lista o aceita ali. |
| `drop()` | Solta. Resolve `true` quando o drop é concluído, assim que ele pousa. |
| `cancel()` | Cancela: o item volta ao lugar, ou um pressionar pendente é abandonado. |

Chamadas que não se aplicam mais — um movimento depois do fim, um segundo `drop()` — são
ignoradas. Tipos completos: [Sensores](/docs/api/sensors).

::tip
Para envolver um sensor embutido, rode o `setup` dele com um contexto seu. Crie-o com
`Object.create(context, { activate: { value: myActivate } })` em vez de um spread, para que os
getters ao vivo (`status`, `drag`, `props`) continuem funcionando.
::

## Arrastes programáticos {#programmatic-drags}

`@vue-dnd-kit/actions` move itens a partir do código: botões "Mover para cima", menus, atalhos de
teclado, desfazer, tours de onboarding, testes. Ele é construído sobre a API pública de sensores, e
os arrastes dele são de verdade: anunciados e animados, passando por `onBeforeDrop`, `onDrop`,
`e.result` e `preventDefault()`, sob as regras do provider (um arraste por vez, itens
desabilitados, `accept` e `group.put`).

```bash
npm i @vue-dnd-kit/actions
```

### moveItem: uma chamada, um movimento {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` é o `id` de uma lista ordenável. Sem ele, o item fica na sua lista.
- `index` é onde o item acaba ficando, contado sem o próprio item, e limitado ao tamanho da lista.
  Sem ele, o item vai para o final.
- Ele resolve `true` quando o drop é concluído, `false` quando o item não está renderizado ou está
  desabilitado, nenhuma lista o aceita ali, ou o drop foi recusado.
- As chamadas entram em fila: cada uma espera até o provider ficar ocioso, então um segundo clique
  rápido não se perde.
- Ele roda como um arraste por teclado, então é anunciado e o foco fica no item.
- Só para listas: as posições em árvores também têm uma profundidade.

Veja [Acessibilidade](/docs/guides/accessibility#moving-without-dragging) para uma linha com
botões de mover.

### startDrag: um arraste roteirizado {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` resolve assim que o movimento é renderizado, `drop` assim que o drop pousa.
`startDrag(id, { type: 'keyboard' })` move de item em item (`await drag.step('down')`), e o
sensor de teclado pode assumir: um item de menu "Mover" que entrega o item às setas.

### Fora de componentes {#outside-components}

`useDnDActions()` roda um sensor, chamado `actions`, no provider acima. Para conduzir um provider a
partir de uma store ou de um ambiente de testes, ou com um nome próprio, crie as ações em um sensor
que você mesmo roda:

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

Depois, `await tour?.moveItem('card-1', { list: 'done' })` de qualquer lugar. Durante a
renderização no servidor, nada é arrastado: `moveItem` resolve `false` e `startDrag` retorna
`null`.
