A biblioteca quase não aplica estilos. Cada estado de um arraste chega até você de duas formas:
como um ref retornado pelo composable, para classes e marcação condicional, e como um atributo
`data-dnd-*`, para CSS puro.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## Os refs retornados {#the-returned-refs}

| Composable | Estado |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`: este elemento é a posição onde um item arrastado vai pousar.
- `isDragging`: o item faz parte do arraste (todos os itens arrastados, em um multi-drag).
- `isAccepting`: algo está sendo arrastado, e este alvo o aceita — destaque os lugares onde um
  drop é possível.
- `isOver`: o arraste está sobre este alvo, quer ele o aceite ou não. `isOver && !isAccepting` é
  uma recusa, que vale a pena mostrar.
- `over.accepted` de `useDnD()` (`accepted` nas props do overlay) é `false` sobre um alvo que
  recusa o arraste: use-o para pintar o overlay de vermelho.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## Os atributos data {#the-data-attributes}

| Atributo | Em | Quando |
| --- | --- | --- |
| `data-dnd-placeholder` | item ordenável | Ele é a posição onde um item arrastado vai pousar. |
| `data-dnd-dragging` | item ordenável | Ele está sendo arrastado mas fica no lugar: os outros itens de um multi-drag no modo `'gaps'`. |
| `data-dnd-dragging="pointer"` ou `"keyboard"` | `<html>` | Durante todo o arraste. |
| `data-dnd-overlay="dragging"` ou `"dropping"` | a caixa do overlay | Sempre. `dropping` enquanto ela pousa, e enquanto um `onBeforeDrop` assíncrono espera. |
| `data-dnd-leaving` | uma cópia deixada por `animate` | Enquanto um item que saiu desaparece aos poucos. |
| `data-dnd-no-clone` | **definido por você** | Deixa o elemento fora do clone do overlay: uma tooltip, um botão de menu, um badge. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## Estilos padrão {#default-styles}

O provider injeta algumas regras uma vez por documento. Elas ficam dentro de `:where()`, então a
especificidade delas é zero e qualquer regra sua prevalece:

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

A posição fica esmaecida, a página não seleciona texto nem ancora a rolagem durante um arraste, e
o cursor é uma mão agarrando durante um arraste por ponteiro. `:default-styles="false"` desliga
essas regras. O `cursor: grab` nos itens arrastáveis fica por sua conta.

## Receitas {#recipes}

### Uma posição vazia {#an-empty-slot}

Em vez de uma cópia esmaecida do item, mostre uma caixa vazia e tracejada onde ele vai pousar:

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

O pseudoelemento cobre o conteúdo, então a posição mantém o tamanho exato do item. Arraste um card
aqui para ver:

### Uma linha que a lista pinta {#a-row-the-list-paints}

O overlay padrão é um clone do elemento arrastado. Ele mostra o elemento como ele é, e não
adivinha nenhum fundo: uma linha sem fundo próprio — um `<li>` em um `<ul>` branco, uma linha de
tabela, o item de lista de um UI kit — gera um clone transparente. Dê a ela o fundo da lista:

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

O clone mantém as classes e os atributos do elemento — inclusive o atributo de um estilo scoped
—, então a regra funciona no próprio `<style scoped>` da linha, ao lado dos outros estilos dela.
Ou dê à linha um fundo próprio. Ícones e blocos feitos para flutuar continuam transparentes.

### Um overlay elevado, só durante o arraste {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

A sombra aparece enquanto o card viaja e some quando o overlay passa para `dropping`, então o card
pousa reto na sua posição. Em um componente de overlay personalizado, a mesma regra mira a raiz do
seu componente, ou leia `status` nas props dele.

### Movimento reduzido {#reduced-motion}

A biblioteca já para as próprias animações com `prefers-reduced-motion: reduce`. Faça o mesmo com
as transições que você acrescenta em torno dos arrastes:

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### Não faça {#dont}

- Não coloque `transition` de CSS em `transform` ou `translate` de itens ordenáveis: a biblioteca
  os anima sozinha, e cancela essas transições enquanto faz as medições.
- Não anime `height`, `margin` ou `padding` das linhas de uma [lista virtual](/docs/guides/virtual-lists).

Mais sobre o overlay — componentes personalizados, o tamanho dele, `DragPreview` — em
[O overlay](/docs/guides/overlay).
