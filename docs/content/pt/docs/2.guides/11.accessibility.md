Tudo nesta página vem ligado por padrão. Chegue com Tab à alça de uma faixa, pressione
:kbd{value="Space"}, mova-a com as setas e pressione :kbd{value="Space"} de novo — ou
:kbd{value="Escape"} para devolvê-la ao lugar.

::example{name="lists" hint="Tab até uma alça, Space, setas, Space" height="28rem"}
::

O que normalmente fica por sua conta: nomes legíveis para os itens, e botões que os movem para
quem não consegue arrastar de jeito nenhum.

## O teclado {#the-keyboard}

| Tecla | Ação |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Pegar o item em foco; soltá-lo. |
| Setas | Movê-lo: de posição em posição nas listas, por linhas e profundidade nas árvores, `keyboard.step` pixels nos arrastes livres. |
| :kbd{value="Escape"} | Cancelar o arraste — também os arrastes por ponteiro. |

- Em uma lista, uma seta em direção a outra lista do mesmo grupo move o item para lá.
- Em um arraste livre, :kbd{value="Shift"} aumenta os passos. `makeDraggable(el, { keyboard: 'droppables' })`
  faz as setas saltarem entre os alvos que aceitam o item.
- Um arraste por teclado começa a partir do draggable em foco, ou do handle dele — nunca de um
  botão ou de um campo dentro dele, então esses mantêm as próprias teclas.
- Os arrastes por teclado rolam o alvo até ele ficar visível, em vez de rolar automaticamente nas
  bordas.
- Depois do drop, o foco volta para o item, mesmo quando a linha dele foi renderizada de novo em
  outra lista.

### Outras teclas {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Os atalhos são comparados com `event.code` (`'Space'`, `'KeyD'`) ou com `event.key` (`'Enter'`).
`step` são os pixels por toque de seta nos arrastes livres (25 por padrão). `:keyboard="false"`
desliga os arrastes por teclado, e :kbd{value="Escape"} ainda cancela qualquer arraste. Quando
mudar as teclas, mude também `screen-reader-instructions`.

## Atributos ARIA {#aria-attributes}

Todo draggable e item ordenável recebe estes atributos, **a menos que você mesmo os defina**:

| Atributo | Valor |
| --- | --- |
| `tabindex` | `0`, quando o elemento ainda não pode receber foco. |
| `role` | `button`, exceto em um `<button>`, que já é um. |
| `aria-roledescription` | `draggable`, ou `sortable` nos itens ordenáveis. |
| `aria-describedby` | As instruções do provider, acrescentadas ao lado dos ids que já estão ali (o de uma tooltip é mantido). |
| `aria-disabled` | `true` ou `false`: se o item está desabilitado (inclusive por uma área de arraste desabilitada). |
| `aria-pressed` | `true` enquanto ele é arrastado. |

`attributes: false` os desliga para um item; o que a biblioteca tinha definido é removido.

### Handles: faça deles botões de verdade {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

Com um `handle`, os atributos vão para o handle, e os arrastes por teclado começam por ele. Um
`<button>` já pode receber foco e já é um botão, então não precisa de `tabindex` nem de `role`.
Dê a ele um `aria-label`: um ícone de alça não tem nome próprio, e "Move Midnight Drive" diz mais
do que "botão".

## Anúncios {#announcements}

Uma live region no provider anuncia cada vez que um item é pego, movido, solto ou cancelado. As
listas ordenáveis dizem onde o item está: *"Picked up item t2 at position 2 of 5 in list
playlist."* Os movimentos são anunciados depois que o arraste fica parado por 500 ms.

Os textos usam ids. Dê aos itens ids legíveis, ou escreva os textos você mesmo:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- Um texto substitui o anúncio do evento; `undefined` mantém o padrão; `''` não diz nada. Os
  eventos que você deixa de fora também mantêm os padrões, como as posições das listas ordenáveis
  para `onDragOver` acima.
- `onDragResume` é anunciado quando `onBeforeDrop` respondeu `'continue'` e o arraste continua
  (veja [Decidindo um drop](/docs/guides/drop-decisions)).
- `screenReaderInstructions` é o texto para o qual todo draggable aponta com `aria-describedby`.
- `:announcements="false"` silencia a região, por exemplo quando você faz os anúncios pela sua
  própria.

::note
Os textos embutidos estão em inglês. Para outro idioma, forneça os cinco textos e as instruções —
cada um que você deixar de fora é anunciado em inglês, incluindo as posições das listas
ordenáveis.
::

## Toque {#touch}

Arrastes por toque começam depois de um toque longo de 200 ms. Mover mais de 5 px antes disso
rola a página, para que as listas continuem roláveis. Ajuste os dois com `activation` (veja
[Sensores](/docs/guides/sensors#activation-constraints)), e desenhe um anel de toque longo a
partir de `useDnD().activation.progress`.

Um arraste por toque vibra brevemente quando começa. `:haptics="false"` desliga isso; um objeto
acrescenta vibrações ao entrar em um alvo, ao soltar ou ao ser recusado:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Só os arrastes por toque vibram, e o Safari do iOS não consegue vibrar de jeito nenhum.

## Movimento reduzido {#reduced-motion}

Com `prefers-reduced-motion: reduce`, as animações da própria biblioteca não rodam. As suas
funções de animação ainda rodam, com `reducedMotion: true`. Veja [Animações](/docs/guides/animations).

## Mover sem arrastar {#moving-without-dragging}

Algumas pessoas não conseguem arrastar de jeito nenhum. O WCAG 2.5.7 pede uma forma de mover
itens com cliques simples, como botões "Mover para cima". `@vue-dnd-kit/actions` faz de cada um
deles um movimento de verdade:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` executa um arraste por teclado do início ao fim: ele é anunciado, passa por
`onBeforeDrop` e `onDrop`, é animado e mantém o foco no item. Ele resolve `true` quando o drop é
concluído. `index` conta as posições sem o próprio item, então "para baixo" é `index + 1`. Mais
em [Sensores e arrastes programáticos](/docs/guides/sensors#programmatic-drags).
