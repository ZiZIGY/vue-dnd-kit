```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider :animation="{ duration: 200 }" @drag-end="save">
    <RouterView />
    <template #overlay="{ items, over, accepted }">
      <!-- optional: a custom overlay for every drag -->
    </template>
  </DnDProvider>
</template>
```

Todo composable precisa rodar em um componente renderizado **dentro** de um provider. O objetivo
é um único provider para o app inteiro: partes da página ganham regras próprias com
[`makeDragArea`](/docs/api/make-drag-area). Veja [o guia do provider](/docs/guides/provider).

A maioria das props é lida quando o provider precisa dela: mude uma, e o próximo arraste já a usa.

## Eventos {#events}

| Evento | Payload | Quando |
| --- | --- | --- |
| `drag-start` | `DnDEvent` | Um arraste começou (depois da ativação). |
| `drag-move` | `DnDEvent` | O ponteiro se moveu durante um arraste (no máximo uma vez por frame). |
| `drag-over` | `DnDEvent` | O alvo sob o arraste mudou. |
| `drag-end` | `DnDEndEvent` | Um drop foi concluído e gravado. |
| `drag-cancel` | `DnDEvent` | O arraste foi cancelado ou o drop, recusado. |
| `drag-settle` | `DnDEndEvent` ou `DnDEvent` | O overlay do arraste pousou: o que `drag-end` ou `drag-cancel` recebeu. |

Os mesmos eventos, mais `onBeforeDrop` e `onDragResume`, estão disponíveis em qualquer lugar sob o
provider com [`useDnDMonitor`](/docs/api/use-dnd). Os payloads deles estão na
[página de eventos](/docs/api/events).

## Slot `#overlay` {#slot-overlay}

Renderiza o que segue o ponteiro, para todo arraste que não tem um componente de overlay próprio
(veja [o guia do overlay](/docs/guides/overlay)). Se não renderizar nada, volta a usar o clone.
