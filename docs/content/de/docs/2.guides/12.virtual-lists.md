Das Sortieren ist datengetrieben: Der Entwurf `items` ist bei jeder Neuordnung ein neues Array,
Zeilen haben ihr Element als Schlüssel, und die Animationen brauchen nur die gemounteten Zeilen.
Deshalb funktioniert jeder Virtualizer, der aus einem Array rendert – gib ihm den Entwurf statt
deines Arrays.

## Die Regeln {#the-rules}

1. Gib dem Virtualizer den **Entwurf `items`**, nicht dein Quell-Array.
2. **Gib Zeilen den Schlüssel ihres Elements**, nie den Index. Die offiziellen Beispiele von
   TanStack und VueUse nutzen den Index; ändere das.
3. Übergib IDs an `makeSortableItem` als **Getter**, `{ id: () => props.item.id }`: Der
   Virtualizer kann einer Zeilenkomponente ein anderes Element geben.
4. Halte große Arrays in einem **`shallowRef`**. Die Bibliothek durchläuft deine Daten nie tief.
5. Halte den Platzhalter so groß wie die Zeile.
6. Setze Overscan auf mindestens 5 Zeilen (VueUse: mindestens 1), damit Zeilen gemountet sind,
   bevor Auto-Scroll sie erreicht.
7. Animiere nicht `height`, `margin` oder `padding` von Zeilen, und setze kein `will-change` auf
   den Scroller.

## TanStack Virtual {#tanstack-virtual}

```vue [TaskList.vue]
<script setup lang="ts">
import { computed, shallowRef, useTemplateRef } from 'vue';
import { defaultRangeExtractor, useVirtualizer, type Range } from '@tanstack/vue-virtual';
import { makeSortableList } from '@vue-dnd-kit/core';
import Row from './Row.vue';

const ROW = 40;
const tasks = shallowRef(makeRows(10_000));
const scrollRef = useTemplateRef<HTMLElement>('scroll');
const { items, activeIndex, captureLayout } = makeSortableList(scrollRef, { items: tasks });

// One computed that reads the draft once: TanStack memoizes measurements and the range on
// the identity of `getItemKey` and `rangeExtractor`, so they must be new after every reorder.
const virtualizer = useVirtualizer(
  computed(() => {
    const arr = items.value;
    const pin = activeIndex.value;
    return {
      count: arr.length,
      getScrollElement: () => scrollRef.value,
      estimateSize: () => ROW,
      overscan: 8,
      getItemKey: (index: number) => arr[index]!.id,
      // Keep the dragged row mounted while it is scrolled out of range.
      rangeExtractor: (range: Range) => {
        const indexes = defaultRangeExtractor(range);
        return pin < 0 || indexes.includes(pin) ? indexes : [...indexes, pin].sort((a, b) => a - b);
      },
      // Re-measures land after the library's animation pass: animate them too.
      onChange: () => captureLayout(),
    };
  }),
);
const rows = computed(() => virtualizer.value.getVirtualItems());
const measure = (el: unknown) => virtualizer.value.measureElement(el as HTMLElement | null);
</script>

<template>
  <div ref="scroll" style="height: 600px; overflow: auto; contain: strict">
    <div :style="{ height: `${virtualizer.getTotalSize()}px`, position: 'relative' }">
      <div
        v-for="row in rows"
        :key="(row.key as string)"
        :ref="measure"
        :data-index="row.index"
        :style="{ position: 'absolute', top: 0, left: 0, width: '100%', transform: `translateY(${row.start}px)` }"
      >
        <Row :item="items[row.index]!" />
      </div>
    </div>
  </div>
</template>
```

```vue [Row.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ item: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
// A getter: the virtualizer may give this component another item.
makeSortableItem(el, { id: () => props.item.id });
</script>

<template>
  <div ref="el" class="row">{{ item.title }}</div>
</template>
```

- Der Scroller ist das Element der sortierbaren Liste: Die Bibliothek sortiert ihn und scrollt ihn
  automatisch.
- Die gezogene Zeile festzuhalten (`rangeExtractor`) erfordert Zeilen, die einzeln absolut
  positioniert sind, wie oben.
- Behalte `anchorTo: 'start'` von TanStack bei, den Standard. Mit `lanes` verwende
  `@tanstack/vue-virtual` 3.19 oder neuer.

### Kanban-Spalten {#kanban-columns}

Kommt eine Karte aus einer anderen Spalte, kann ihre Höhe von der Schätzung der Spalte abweichen.
Lies `activeSize` im selben Computed und schätze die eingehende Zeile mit ihrer echten Größe:

```ts
const { items, activeIndex, activeSize, captureLayout } = makeSortableList(scrollRef, {
  id: props.column.id,
  items: props.column.tasks,
  group: 'board',
});

const virtualizer = useVirtualizer(
  computed(() => {
    const arr = items.value;
    const pin = activeIndex.value;
    const size = activeSize.value;
    return {
      count: arr.length,
      getScrollElement: () => scrollRef.value,
      // A card coming from another column gets its real height before it is measured.
      estimateSize: (index: number) => (index === pin && size ? size.height : 72),
      // …getItemKey, rangeExtractor and onChange as above
    };
  }),
);
```

## VueUse useVirtualList {#vueuse-usevirtuallist}

```vue [TaskList.vue]
<script setup lang="ts">
import { shallowRef, useTemplateRef } from 'vue';
import { useVirtualList } from '@vueuse/core';
import { makeSortableList } from '@vue-dnd-kit/core';
import Row from './Row.vue';

const ROW = 40;
const tasks = shallowRef(makeRows(10_000));
// The outer element is the sortable list: `containerProps` owns the scroller's ref.
const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
// A number keeps VueUse's math O(1). It must be the row's real height, borders and margins included.
const { list, containerProps, wrapperProps } = useVirtualList(items, { itemHeight: ROW, overscan: 8 });
</script>

<template>
  <div ref="list">
    <div v-bind="containerProps" style="height: 600px">
      <div v-bind="wrapperProps">
        <!-- Keyed by id, not by index as in VueUse's docs. -->
        <Row v-for="{ data } in list" :key="data.id" :item="data" :style="{ height: `${ROW}px` }" />
      </div>
    </div>
  </div>
</template>
```

VueUse kann die gezogene Zeile nicht festhalten: Sie wird unmountet, wenn du sie wegscrollst. Das
ist in Ordnung – siehe unten.

## Was gemountet bleibt {#what-stays-mounted}

Die gezogene Zeile kann während des Ziehens unmountet werden: Sie wurde aus dem Bereich gescrollt,
oder der Virtualizer hat ihre Komponente wiederverwendet. Der Drag übersteht das. Das Overlay zeigt
das Element weiter, die Auswahl bleibt über die ID erhalten, und das Element landet dort, wo der
Entwurf es hinsetzt. Animationen betreffen nur die gemounteten Zeilen.

Wo der Virtualizer es kann, halte die gezogene Zeile trotzdem gemountet, wie es das
TanStack-Rezept mit `rangeExtractor` tut. Die Liste sagt dir, welche Zeile das ist:

| Rückgabe der Liste | Wofür |
| --- | --- |
| `activeIndex` | Der Index der Zeile, die im Entwurf dieser Liste gemountet bleiben soll, `-1`, wenn sie nicht hier ist. |
| `activeKey` | Der Schlüssel dieser Zeile. |
| `activeSize` | Die Größe der gezogenen Zeile zu Beginn des Drags: Schätze damit eine eingehende Zeile. |
| `captureLayout()` | Rufe es direkt vor einer Layoutänderung auf, die nicht von der Bibliothek kommt (ein erneutes Messen). Es animiert die Zeilen von dort, wo sie waren. Außerhalb eines Drags tut es nichts. |

## Bäume {#trees}

`makeSortableTree` gibt ein flaches `items` der sichtbaren Zeilen zurück, deshalb wird ein Baum wie
eine Liste virtualisiert: mit `node.key` als Schlüssel und mit `activeIndex` und `activeKey`, die
die Zeile nennen, die gemountet bleiben soll. Siehe [Bäume](/docs/guides/trees).
