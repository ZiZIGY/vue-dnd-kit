## Eine Gruppe {#a-group}

Listen mit demselben `group`-Namen tauschen Elemente aus. Standardmäßig ist jede Liste eine eigene
Gruppe.

```vue [Column.vue]
<script setup lang="ts">
import { toRef, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import Card from './Card.vue';

type Task = { id: string; title: string };
const props = defineProps<{ column: { id: string; title: string; cards: Task[] } }>();

const zone = useTemplateRef<HTMLElement>('zone');
const list = useTemplateRef<HTMLElement>('list');
const { items, isOver } = makeSortableList(list, {
  id: props.column.id,                   // names the list in drop events
  items: toRef(props.column, 'cards'),   // a writable ref into the reactive column
  group: 'board',                        // same name: cards move between these lists
  dropzone: zone,                        // the whole column takes drops
});
</script>

<template>
  <section ref="zone" :class="{ over: isOver }">
    <h3>{{ column.title }}</h3>
    <ul ref="list">
      <Card v-for="card in items" :key="card.id" :card="card" />
    </ul>
  </section>
</template>
```

```vue [Board.vue]
<script setup lang="ts">
import { reactive } from 'vue';
import Column from './Column.vue';

const columns = reactive([
  { id: 'todo', title: 'To do', cards: [{ id: 'vdk-12', title: 'Pick a palette' }] },
  { id: 'done', title: 'Done', cards: [] },
]);
</script>

<template>
  <Column v-for="column in columns" :key="column.id" :column="column" />
</template>
```

- Jede Spalte ist eine eigene Komponente: eine Liste pro Komponente.
- `toRef(props.column, 'cards')` ist beschreibbar, weil die Elternkomponente ein reaktives Objekt
  übergibt. Der Drop schreibt beide Arrays: das, das die Karte verlassen hat, und das, in das sie
  gekommen ist.
- `id` erscheint in Drop-Events als `from.list` und `to.list` und ist der Schlüssel in
  `e.result`, den neuen Arrays aller Listen, die der Drop ändert. `id` und `group` werden einmal
  gelesen.
- Schlüssel müssen in der ganzen Gruppe eindeutig sein.

Das `onDrop` einer Liste läuft für die Drops **in** sie hinein. Eine Verschiebung von `todo` nach
`done` ruft das `onDrop` der Liste `done` auf, und dessen `e.result` enthält die neuen Arrays
beider Listen.

## Die ganze Spalte nimmt Drops an: `dropzone` {#the-whole-column-takes-drops-dropzone}

Eine kurze Liste in einer hohen Spalte lässt unter der letzten Karte leeren Platz. Mit
`dropzone: zone` nimmt das Element der Spalte die Drops für die Liste an: Eine Karte, die unter
der letzten losgelassen wird, landet am Ende. Die Karten bleiben im `<ul>`; nur die Fläche, die
Drops annimmt, wächst.

::tip
Ohne `dropzone` braucht eine leere Liste trotzdem eine Größe, um Drops anzunehmen: Gib ihr eine
`min-height`.
::

## Was rein- und rausgeht: `pull` und `put` {#what-goes-in-and-out-pull-and-put}

`group` nimmt auch ein Objekt:

```ts
group: { name: 'board', pull: true, put: true }
```

| Option | Werte |
| --- | --- |
| `pull` | `true` (Standard): Elemente können gehen. `false`: Sie können es nicht. `'clone'`: Kopien gehen, die Elemente bleiben. |
| `put` | `true` (Standard): Elemente können hereinkommen. `false`: Nichts kommt herein. Eine Funktion: Du entscheidest pro Drag. |

Eine `put`-Funktion bekommt `{ keys, items, types, from, to }`. `from` ist die Liste, aus der die
Elemente kommen, `null` bei einfachen ziehbaren Elementen. Verschiebungen innerhalb einer Liste
sind immer erlaubt.

### Limits {#limits}

Eine Spalte, die höchstens drei Karten fasst:

```ts
makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'cards'),
  group: {
    name: 'board',
    put: ({ keys }) => props.column.cards.length + keys.length <= 3,
  },
});
```

Über einer Liste, die den Drag ablehnt, geht der Slot dorthin zurück, wo der Drag begann, sodass
die Listen zeigen, was ein Drop bewirken würde: nichts. Ein Drop dort wird abgebrochen, und die
Karte fliegt zurück. `isAccepting` der Liste ist während eines solchen Drags `false`: Dimme damit
die Spalte.

Werden mehrere ausgewählte Elemente verschiedener Typen gezogen, legt `acceptMode` fest, ob
`'all'` (Standard) oder `'some'` von ihnen `put` bestehen müssen. Bei `'some'` landen die, die
bestehen, und die anderen fliegen zurück.

## Kopieren: Paletten und die Alt-Taste {#copy-palettes-and-the-alt-key}

::example{name="palette" hint="Ziehe aus der Palette; Ziehen mit Alt kopiert; außerhalb der Seite ablegen, um zu entfernen" height="24rem"}
::

```ts [Palette.vue]
makeSortableList(list, {
  items: templates,
  group: { name: 'blocks', pull: 'clone', put: false },  // copies go out, nothing comes in
  sort: false,                                           // its own order stays
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),
});
```

```ts [Sheet.vue]
makeSortableList(list, {
  items: blocks,
  group: 'blocks',
  clone: (block) => ({ ...block, id: crypto.randomUUID() }),  // for Alt-drags
});
```

- `pull: 'clone'` kopiert jeden Drag aus der Liste heraus. Das Original bleibt, und die Kopie
  wandert und landet.
- Hältst du während des Ziehens :kbd{value="Alt"} gedrückt, wird ebenfalls kopiert, aus jeder
  Liste. Ändere die Taste mit `copyModifier` des Providers, oder schalte sie mit `null` ab.
- In beiden Fällen braucht die Liste, aus der das Element kommt, `clone`. Es muss die Kopie mit
  einem **neuen Schlüssel** zurückgeben. Ohne `clone` wird nichts kopiert.
- Das Drop-Event hat `mode: 'copy'`, und `e.items` sind die Kopien. Auch eine Overlay-Komponente
  bekommt `mode`, um beim Kopieren ein „+“ anzuzeigen (siehe [Das Overlay](/docs/guides/overlay)).

## Einfache ziehbare Elemente in eine Liste {#plain-draggables-into-a-list}

Eine Liste nimmt Elemente auf, die mit `makeDraggable` gezogen werden, wenn sie weiß, wie sie
daraus ein Element macht:

```ts
makeSortableList(list, {
  items: tasks,
  createItem: (active) => ({ id: crypto.randomUUID(), title: (active.data as Chip).title }),
});
```

Solange das ziehbare Element über der Liste ist, sitzt das erzeugte Element im Entwurf und wird
von deinem Template wie jede andere Zeile gerendert. Beim Drop wird es echt (`mode: 'insert'`,
`from.list === null`). Gib `undefined` zurück, um abzulehnen. Listen ohne `createItem` ignorieren
einfache ziehbare Elemente. Mit der Tastatur holt eine Pfeiltaste in Richtung der Liste das
ziehbare Element hinein.

## Tauschen statt Verschieben {#swap-instead-of-shift}

```ts
makeSortableList(grid, { items: tiles, strategy: 'grid', behavior: 'swap' });
```

Das gezogene Element tauscht den Platz mit dem darunter, und die anderen bleiben, wo sie sind. Der
Tausch passiert live: Zurückbewegen oder die Liste verlassen macht ihn rückgängig. Das Drop-Event
hat `mode: 'swap'` und `partner`, das Element, mit dem getauscht wurde.

- Zwei Listen einer Gruppe tauschen untereinander, wenn beide `behavior: 'swap'` haben. Das
  Element unter dem Zeiger wechselt in die andere Liste, deshalb muss es hinaus (`pull: true`) und
  hinein (`put`) dürfen.
- Ein Multi-Drag sortiert, statt zu tauschen.

## Eine Einfügelinie {#an-insertion-line}

Mit `placeholder: 'indicator'` bleibt die Liste beim Ziehen still, und eine Linie zeigt, wohin der
Drop geht. Die Linie zeichnest du:

```ts [TaskList.vue]
const { items, indicator } = makeSortableList(listRef, { items: tasks, placeholder: 'indicator' });
```

```vue [TaskRow.vue]
<script setup lang="ts">
const { indicator } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" :class="indicator && `drop-${indicator.side}`">{{ task.title }}</li>
</template>

<style scoped>
.drop-before { box-shadow: inset 0 2px 0 #42b883; }
.drop-after { box-shadow: inset 0 -2px 0 #42b883; }
</style>
```

| `indicator`-Feld | Was es enthält |
| --- | --- |
| `list` | Die Liste, in die der Drop geht. |
| `index` | Der Einfügeindex in der Liste, so wie sie gerendert ist. |
| `key` | Das Element, an dem die Linie hängt; `null` in einer leeren Liste (zeichne sie dann in der Liste). |
| `side` | `'before'` oder `'after'` dieses Elements. Bäume ergänzen `'inside'`. |
| `depth`, `parentKey` | Nur bei Bäumen: wo der Drop landet. Siehe [Bäume](/docs/guides/trees#an-insertion-line). |

`indicator` der Liste ist gesetzt, solange die Linie in dieser Liste ist, und `indicator` eines
Elements, solange sie an diesem Element hängt. Auch die Tastatur bewegt die Linie.

## Außerhalb ablegen {#dropping-outside}

Was passiert, wenn ein Drag über gar keinem Ziel endet, bestimmt `dropOutside` der Liste:

| `dropOutside` | Die Elemente |
| --- | --- |
| `'placeholder'` (Standard) | Landen dort, wo der Slot zuletzt angezeigt wurde. |
| `'cancel'` | Fliegen zurück. Der Standard bei `placeholder: 'indicator'`. |
| `'remove'` | Verlassen ihre Liste: zum Löschen herausziehen. |

`'remove'` fragt zuerst `onBeforeDrop` der Liste. Dann läuft `onDrop` der Liste mit
`to.index === -1`, und `e.result` enthält die Liste ohne die Elemente. Ein Papierkorb, der Drops
annimmt, funktioniert genauso: siehe [Papierkörbe](/docs/guides/drag-and-drop#trash-zones).

Wie du eine Verschiebung bestätigen lässt, sie zuerst auf einem Server speicherst oder Drops
selbst auf einen Store anwendest, steht in [Über einen Drop entscheiden](/docs/guides/drop-decisions).
Alle Optionen der Liste stehen in der [makeSortableList-API](/docs/api/make-sortable-list).
