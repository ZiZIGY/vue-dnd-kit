Nimm `makeDraggable` und `makeDroppable` für alles, was keine sortierbare Liste ist: Dateien in
Ordner, ein Papierkorb, ein Schachbrett, ein Kalender, Notizen auf einem Board.

::example{name="drop-zones" hint="Bilder gehören zu Images, Dokumente zu Documents" height="30rem"}
::

## Ein ziehbares Element {#a-draggable}

```vue [FileCard.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDraggable } from '@vue-dnd-kit/core';

const props = defineProps<{ file: { id: string; name: string; kind: 'image' | 'doc' } }>();
const el = useTemplateRef<HTMLElement>('el');

const { isDragging } = makeDraggable(el, {
  id: () => props.file.id,      // read back as `active.id`
  data: () => props.file,       // anything: `active.data`
  type: () => props.file.kind,  // matched by the targets' `accept`
});
</script>

<template>
  <div ref="el" :class="{ dragging: isDragging }">{{ file.name }}</div>
</template>
```

Übergib die ID aus deinen Daten, als Getter. Die Standard-ID kommt aus `useId()` und ist für jede
Komponenteninstanz neu, deshalb sagt sie dem Rest deiner App nichts.

| Rückgabe | Was es ist |
| --- | --- |
| `isDragging` | Dieses Element wird gerade gezogen. |
| `selected` | Beschreibbar, an die [Auswahl](/docs/guides/multi-drag) des Providers gebunden. |
| `transform` | Der Versatz des Drags, für `overlay: false` (siehe unten). |
| `id` | Die verwendete ID. |

Buttons, Eingabefelder und andere interaktive Kindelemente starten keinen Drag per Zeiger, deshalb
funktionieren sie in einem ziehbaren Element weiter. Um nur an einem Teil zu ziehen, übergib ein
`handle` (siehe [Sortierbare Listen](/docs/guides/sortable-lists#handles)). Alle Optionen stehen
in der [makeDraggable-API](/docs/api/make-draggable).

## Ein Drop-Ziel {#a-drop-target}

```vue [Folder.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDroppable } from '@vue-dnd-kit/core';

const props = defineProps<{ id: string; accept: string }>();
const emit = defineEmits<{ drop: [fileId: string | number] }>();
const el = useTemplateRef<HTMLElement>('el');

const { isOver, isAccepting } = makeDroppable(el, {
  id: props.id,
  accept: props.accept,
  onDrop: (event) => emit('drop', event.active.id),
});
</script>

<template>
  <section ref="el" :class="{ accepting: isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">
    <slot />
  </section>
</template>
```

| Rückgabe | `true` bedeutet |
| --- | --- |
| `isOver` | Der Drag ist über diesem Ziel, ob es ihn annimmt oder nicht. |
| `isAccepting` | Etwas wird gezogen, und dieses Ziel nimmt es an: Hebe die gültigen Zonen hervor. |
| `placement` | Kein Boolean: `{ top, right, bottom, left }`, die Hälften des Ziels, in denen der Zeiger ist, oder `null`, wenn der Zeiger nicht darüber ist. Nutze es für „vor / nach dieser Karte“. |

`isOver` ohne `isAccepting` bedeutet, dass der Drag über einem Ziel ist, das ihn ablehnt. Zeig
das an, wie es die Ordner oben tun: Ein Drop dort wird abgebrochen, und das Element fliegt zurück.

## Welche Drags ein Ziel annimmt {#which-drags-a-target-takes}

Der `type` eines ziehbaren Elements wird mit dem `accept` eines Ziels abgeglichen:

| `accept` | Nimmt an |
| --- | --- |
| weggelassen oder `'*'` | Alles. |
| `'image'` | Ziehbare Elemente vom Typ `image` und solche ohne Typ. |
| `['image', 'doc']` | Jeden der beiden Typen und Elemente ohne Typ. |
| `({ active, items, types }) => boolean` | Was deine Funktion sagt. |

Ein ziehbares Element ohne `type` passt zu jeder String-Regel. Für alles andere nimm eine
Funktion:

```ts
makeDroppable(el, {
  accept: ({ items }) => items.every((item) => (item.data as File).size < 10_000_000),
});
```

`type` kann auch ein Array sein (`['image', 'large']`): Ein passender Typ genügt.

Werden mehrere Elemente auf einmal gezogen, legt `acceptMode` fest, wie viele davon passen müssen:
`'all'` (Standard) oder `'some'`. Bei `'some'` gib aus `onBeforeDrop` die IDs zurück, die bleiben
sollen, und die anderen fliegen zurück. Siehe [Über einen Drop entscheiden](/docs/guides/drop-decisions).

## Der Drop {#the-drop}

Im `onDrop` eines einfachen Drop-Ziels änderst **du** deine Daten. Die Bibliothek verschiebt von
sich aus nichts:

```ts
makeDroppable(el, {
  id: 'archive',
  onDrop: ({ active }) => {
    for (const id of active.ids) archive(id);   // every dragged id, the grabbed one first
  },
});
```

| Event-Feld | Was es enthält |
| --- | --- |
| `active` | Der Drag: `id`, `ids`, `items` (jeweils `{ id, data, type, item }`), `data`, `type`. |
| `over` | Dieses Ziel: `id`, `data`, `element`, `rect`. |
| `pointer`, `delta` | Wo der Zeiger ist und wie weit er sich seit dem Start bewegt hat. |
| `position` | Wo die gezogene Box in diesem Ziel sitzt (nächster Abschnitt). |
| `source` | Gesetzt, wenn die Elemente aus einer sortierbaren Liste kommen: `{ list, remove() }`. |

Die Reihenfolge ist `onBeforeDrop` (entscheiden), `onDrop` (anwenden), dann `drag-end` des
Providers. Wie du vor einem Drop nachfragst, den Drag weiterlaufen lässt oder nur einige Elemente
annimmst, steht in [Über einen Drop entscheiden](/docs/guides/drop-decisions).

## Dort lassen, wo es abgelegt wurde {#leave-it-where-it-was-dropped}

Ein Board, ein Canvas, ein Grundriss: Das Element bleibt, wo du loslässt. Jedes Event enthält
`position`, also `left` / `top`, die ein absolut positioniertes Element dorthin setzen, wo es
abgelegt wurde.

::example{name="constraints" hint="Ziehe eine Notiz, dann sperre eine Achse oder schalte das Raster ab" height="26rem"}
::

```ts [Board.vue]
const board = useTemplateRef<HTMLElement>('board');
makeDroppable(board, { id: 'board' });

useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

```vue [Note.vue]
<div ref="el" class="note" :style="{ left: `${note.x}px`, top: `${note.y}px` }">…</div>
```

`position` ist die linke obere Ecke der gezogenen Box in `over`: gemessen von dessen
Padding-Kante, dessen Scroll-Position eingerechnet. Über keinem Ziel ist es `null`. Mit
`overlay: false` ist es die eigene Ecke des Elements.

::tip
Berechne die Stelle nicht aus `active.rect` und `delta`: Dabei fehlen Border und Scroll-Position
des Ziels. Einrasten, Grenzen und Achsensperren für solche Boards findest du unter
[Achsen, Grenzen und Raster](/docs/guides/constraints).
::

## In ein sortierbares Element ablegen {#drop-into-a-sortable-item}

Auch eine Zeile einer sortierbaren Liste kann ein Drop-Ziel sein: ein Ordner, der Dateien annimmt,
eine Gruppe, die Aufgaben annimmt. Setze eine Drop-Zone auf das Element der Zeile:

```ts [FolderRow.vue]
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.folder });

const { isOver } = makeDroppable(el, {
  accept: 'file',
  onDrop: (e) => {
    props.folder.children.push(...e.active.items.map((entry) => entry.item as FileEntry));
    e.source?.remove();   // take them out of the list they came from
  },
});
```

Solange die Liste den Drag sortieren würde, zählt ein solches Ziel nur in der **Mitte** seines
Elements (25 bis 75 % entlang der Achse der Liste). Dort geht der Drop in das Element, und die
Liste bewegt sich nicht. Nahe den Rändern sortiert die Liste wie gewohnt.

- Ein Ziel, dessen `accept` den Drag ablehnt, wird übersprungen: Die Liste sortiert über dem
  Element wie über jedem anderen. Ein Ordner, der nur Dateien annimmt, lässt Ordner an sich
  vorbeisortieren.
- Ein Ziel bekommt nie seinen eigenen Drag.
- Wird das Element nach dem Drop nicht mehr angezeigt, schrumpft das Overlay in das Ziel, statt
  zurückzufliegen.

## Papierkörbe {#trash-zones}

Ein Drag, der in einer sortierbaren Liste beginnt, enthält `e.source`. Rufe `remove()` auf, und
die Liste entfernt die Elemente:

```ts
makeDroppable(trash, {
  id: 'trash',
  onDrop: (e) => e.source?.remove(),
});
```

Das eigene `onDrop` der Liste läuft dann mit `to.index === -1`, und `e.result` enthält die Liste
ohne die Elemente. Eine Liste kann auch entfernen, was außerhalb von allem abgelegt wird: siehe
[`dropOutside`](/docs/guides/shared-lists#dropping-outside).

## Ohne Overlay {#without-an-overlay}

Standardmäßig folgt ein Klon des Elements dem Zeiger, und das Element bleibt an seinem Platz. Mit
`overlay: false` gibt es keinen Klon: Bewege das Element selbst mit `transform`.

```vue
<script setup lang="ts">
const { transform } = makeDraggable(el, { id: 'piece', overlay: false });
</script>

<template>
  <div ref="el" :style="transform && { transform: `translate3d(${transform.x}px, ${transform.y}px, 0)` }">♞</div>
</template>
```

Für eine eigene Drag-Vorschau statt des Klons siehe [Das Overlay](/docs/guides/overlay).

## Tastatur {#keyboard}

Ein fokussiertes ziehbares Element wird mit :kbd{value="Space"} oder :kbd{value="Enter"}
aufgenommen. Die Pfeiltasten bewegen es um 25 px (`keyboard.step` des Providers). Mit
`keyboard: 'droppables'` am ziehbaren Element springen sie stattdessen zwischen den Zielen, die es
annehmen – das passt zu weit auseinanderliegenden Zonen. Mehr dazu unter
[Barrierefreiheit](/docs/guides/accessibility).
