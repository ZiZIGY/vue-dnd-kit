Alles auf dieser Seite ist standardmäßig an. Springe mit Tab zum Griff eines Tracks, drücke
:kbd{value="Space"}, bewege ihn mit den Pfeiltasten und drücke wieder :kbd{value="Space"} – oder
:kbd{value="Escape"}, um ihn zurückzulegen.

::example{name="lists" hint="Mit Tab zu einem Griff, Space, Pfeiltasten, Space" height="28rem"}
::

Was meist dir überlassen bleibt: lesbare Namen für die Elemente und Buttons, die sie für Menschen
verschieben, die gar nicht ziehen können.

## Die Tastatur {#the-keyboard}

| Taste | Aktion |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | Das fokussierte Element aufnehmen; es ablegen. |
| Pfeiltasten | Es bewegen: in Listen um Slots, in Bäumen um Zeilen und Tiefe, bei freien Drags um `keyboard.step` Pixel. |
| :kbd{value="Escape"} | Den Drag abbrechen – auch Drags per Zeiger. |

- In einer Liste bewegt eine Pfeiltaste in Richtung einer anderen Liste derselben Gruppe das
  Element dorthin.
- Bei einem freien Drag macht :kbd{value="Shift"} die Schritte größer. `makeDraggable(el, { keyboard: 'droppables' })`
  lässt die Pfeiltasten stattdessen zwischen den Zielen springen, die das Element annehmen.
- Ein Drag per Tastatur startet vom fokussierten ziehbaren Element oder seinem Handle – nie von
  einem Button oder Feld darin, sodass diese ihre eigenen Tasten behalten.
- Drags per Tastatur scrollen das Ziel in den sichtbaren Bereich, statt an den Rändern
  automatisch zu scrollen.
- Nach dem Drop geht der Fokus zurück an das Element, auch wenn seine Zeile in einer anderen Liste
  neu gerendert wurde.

### Andere Tasten {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

Belegungen werden mit `event.code` (`'Space'`, `'KeyD'`) oder `event.key` (`'Enter'`)
abgeglichen. `step` sind die Pixel pro Druck auf eine Pfeiltaste bei freien Drags (standardmäßig
25). `:keyboard="false"` schaltet das Ziehen per Tastatur ab, und :kbd{value="Escape"} bricht
trotzdem jeden Drag ab. Wenn du die Tasten änderst, ändere auch die
`screen-reader-instructions`.

## ARIA-Attribute {#aria-attributes}

Jedes ziehbare und sortierbare Element bekommt diese, **außer du setzt sie selbst**:

| Attribut | Wert |
| --- | --- |
| `tabindex` | `0`, wenn das Element nicht schon fokussierbar ist. |
| `role` | `button`, außer bei einem `<button>`, der schon einer ist. |
| `aria-roledescription` | `draggable` oder bei sortierbaren Elementen `sortable`. |
| `aria-describedby` | Die Anleitung des Providers, ergänzt neben den schon vorhandenen IDs (die eines Tooltips bleibt erhalten). |
| `aria-disabled` | `true` oder `false`: ob das Element deaktiviert ist (auch durch einen deaktivierten Drag-Bereich). |
| `aria-pressed` | `true`, während es gezogen wird. |

`attributes: false` schaltet sie für ein Element ab; was die Bibliothek gesetzt hatte, wird
entfernt.

### Handles: Mach sie zu echten Buttons {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

Mit einem `handle` kommen die Attribute auf das Handle, und Drags per Tastatur starten von ihm
aus. Ein `<button>` ist bereits fokussierbar und ein Button, deshalb braucht er weder `tabindex`
noch `role`. Gib ihm ein `aria-label`: Ein Griff-Icon hat keinen eigenen Namen, und
„Move Midnight Drive“ sagt mehr als „button“.

## Ansagen {#announcements}

Eine Live-Region im Provider spricht jedes Aufnehmen, Bewegen, Ablegen und Abbrechen. Sortierbare
Listen sagen, wo das Element ist: *„Picked up item t2 at position 2 of 5 in list playlist.“*
Bewegungen werden angesagt, sobald der Drag 500 ms lang geruht hat.

Die Texte verwenden IDs. Gib Elementen lesbare IDs oder schreib die Texte selbst:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- Ein Text ersetzt die Ansage des Events; `undefined` behält den Standard; `''` sagt nichts.
  Events, die du weglässt, behalten ebenfalls ihre Standards, etwa die Positionen sortierbarer
  Listen für `onDragOver` oben.
- `onDragResume` wird gesprochen, wenn `onBeforeDrop` mit `'continue'` geantwortet hat und der
  Drag weitergeht (siehe [Über einen Drop entscheiden](/docs/guides/drop-decisions)).
- `screenReaderInstructions` ist der Text, auf den jedes ziehbare Element mit `aria-describedby`
  verweist.
- `:announcements="false"` bringt die Region zum Schweigen, z. B. wenn du über deine eigene
  ansagst.

::note
Die eingebauten Texte sind englisch. Für eine andere Sprache gib alle fünf Texte und die Anleitung
an – jeder, den du weglässt, wird englisch gesprochen, die Positionen sortierbarer Listen
eingeschlossen.
::

## Touch {#touch}

Touch-Drags starten nach einem langen Drücken von 200 ms. Eine Bewegung von mehr als 5 px vorher
scrollt stattdessen die Seite, sodass Listen scrollbar bleiben. Passe beides mit `activation` an
(siehe [Sensoren](/docs/guides/sensors#activation-constraints)), und zeichne einen Ring für das
lange Drücken aus `useDnD().activation.progress`.

Ein Touch-Drag vibriert kurz, wenn er beginnt. `:haptics="false"` schaltet das ab; ein Objekt
ergänzt Vibrationen beim Betreten eines Ziels, beim Ablegen oder wenn der Drag abgelehnt wird:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

Nur Touch-Drags vibrieren, und iOS Safari kann überhaupt nicht vibrieren.

## Reduzierte Bewegung {#reduced-motion}

Mit `prefers-reduced-motion: reduce` laufen die eigenen Animationen der Bibliothek nicht. Deine
Animationsfunktionen laufen trotzdem, mit `reducedMotion: true`. Siehe
[Animationen](/docs/guides/animations).

## Verschieben ohne Ziehen {#moving-without-dragging}

Manche Menschen können gar nicht ziehen. WCAG 2.5.7 verlangt eine Möglichkeit, Elemente mit
einzelnen Klicks zu verschieben, etwa mit „Move up“-Buttons. `@vue-dnd-kit/actions` macht aus
jedem davon eine echte Verschiebung:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem` führt einen Drag per Tastatur von Anfang bis Ende aus: Er wird angesagt, durchläuft
`onBeforeDrop` und `onDrop`, wird animiert und lässt den Fokus auf dem Element. Das Promise wird
mit `true` erfüllt, wenn der Drop durchgegangen ist. `index` zählt Plätze ohne das Element selbst,
deshalb ist „nach unten“ `index + 1`. Mehr unter
[Sensoren und programmatisches Ziehen](/docs/guides/sensors#programmatic-drags).
