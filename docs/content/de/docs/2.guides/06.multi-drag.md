## Die Auswahl {#the-selection}

Jeder Provider führt eine Auswahl: eine reaktive Menge von IDs. Ziehst du ein **ausgewähltes**
Element, ziehst du alle ausgewählten Elemente, das gegriffene zuerst. Ziehst du ein Element, das
nicht ausgewählt ist, ziehst du nur dieses Element.

Die Bibliothek entscheidet nicht, wie ausgewählt wird: Die Klickregeln bestimmst du. Sie leert die
Auswahl auch nie von sich aus, und die Auswahl übersteht Unmounts, etwa bei den Zeilen, die eine
virtuelle Liste wiederverwendet.

### Strg/Cmd-Klick {#ctrlcmd-click}

Jedes sortierbare und jedes ziehbare Element gibt `selected` zurück, ein beschreibbares Ref, das an
die Auswahl gebunden ist:

```vue [Shot.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ shot: { id: string } }>();
const el = useTemplateRef<HTMLElement>('el');
const { selected } = makeSortableItem(el, { item: () => props.shot });

const onClick = (event: MouseEvent) => {
  if (event.ctrlKey || event.metaKey) selected.value = !selected.value;
};
</script>

<template>
  <div ref="el" :class="{ selected }" @click="onClick">…</div>
</template>
```

Der Klick, der einen Drag beendet, erreicht `@click` nicht, deshalb schaltet ein Drop die Auswahl
nie versehentlich um. Nutze für Aktionen an Elementen `@click`, nicht `pointerup`.

### Von überall: `useDnD().selection` {#from-anywhere-usedndselection}

```ts
import { useDnD, useDnDMonitor } from '@vue-dnd-kit/core';

const { selection } = useDnD();

selection.has('a');               // is it selected?
selection.add('a', 'b');          // select
selection.delete('a');            // deselect
selection.toggle('a');            // flip it, or force it: toggle('a', true)
selection.set(['a', 'c']);        // exactly these
selection.clear();
selection.ids;                    // a reactive ReadonlySet<Key>

// A plain click selects only that item, Ctrl/Cmd-click adds or removes it:
const onClick = (event: MouseEvent, id: string) => {
  if (event.ctrlKey || event.metaKey) selection.toggle(id);
  else selection.set([id]);
};

// Clear it after every drop, if your UI wants that:
useDnDMonitor({ onDragEnd: () => selection.clear() });
```

Die Auswahl arbeitet mit IDs, deshalb kann sie Elemente mehrerer Listen enthalten: Ein Drag nimmt
alle ausgewählten Elemente unter dem Provider mit.

## Auswahl per Rahmen {#rubber-band-selection}

`makeSelectionArea` macht ein Element zu einem Bereich, in dem ein Drücken auf die freie Fläche
einen Rahmen aufzieht, und die Elemente, die er überstreicht, werden ausgewählt:

```vue [Gallery.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSelectionArea } from '@vue-dnd-kit/core';
import PhotoGrid from './PhotoGrid.vue';

const area = useTemplateRef<HTMLElement>('area');
const { isSelecting, style } = makeSelectionArea(area);
</script>

<template>
  <div ref="area" class="area">
    <PhotoGrid />
    <div v-if="isSelecting" class="band" :style="style" />
  </div>
</template>

<style scoped>
.area {
  position: relative;   /* the band is absolutely positioned inside */
  min-height: 320px;    /* room around the items to start a band */
}

.band {
  border: 1px solid #42b883;
  background: color-mix(in srgb, #42b883 15%, transparent);
}
</style>
```

- Den Rahmen renderst du: `style` positioniert ihn, relativ zum Inhalt des Bereichs.
- Der Bereich braucht eine **nicht statische Position** (`relative` genügt), sonst landet der
  Rahmen woanders.
- Ein Rahmen startet nur im Bereich selbst, mach den Bereich also groß: das ganze Panel, mit Platz
  um die Elemente, keinen eng anliegenden Wrapper. Die Galerie oben füllt ihre ganze Box.
- Ein Drücken auf ein Element zieht es. Buttons, Felder und die Scrollleiste des Bereichs
  reagieren weiterhin selbst auf Drücken.
- Der Rahmen bleibt am Inhalt verankert, während der Bereich oder die Seite scrollt.
  :kbd{value="Escape"} bricht ihn ab und stellt die Auswahl wieder her.
- `useDnD().status` ist `'selecting'`, solange ein Rahmen aufgezogen wird.

| Option | Was sie tut |
| --- | --- |
| `strategy` | `'toggle'` (Standard): Die Elemente, die der Rahmen überstreicht, wechseln ihren Zustand. `'select'`: Nur die Elemente innerhalb des Rahmens sind am Ende ausgewählt, deshalb hebt ein Klick auf die freie Fläche die Auswahl der Elemente des Bereichs auf. |
| `modifier` | Tasten, die zum Aufziehen gehalten werden müssen: `{ keys: ['Shift'], method: 'every' }` (oder `'some'`). |
| `accept` | Welche ziehbaren Elemente der Rahmen auswählt, eine [accept-Regel](/docs/guides/drag-and-drop#which-drags-a-target-takes), die mit ihrem `type` abgeglichen wird. |
| `disabled` | Kein Rahmen; Einschalten bricht einen laufenden ab. |
| `onSelected(ids)` | Wird aufgerufen, wenn ein Rahmen endet, mit der Auswahl. |
| `selection` | Ein eigenes `Ref<Set<Key>>` statt der Auswahl des Providers. |

Bei Bereichen in Bereichen bekommt der innerste das Drücken. Alle Optionen stehen in der
[makeSelectionArea-API](/docs/api/make-selection-area).

## Wie sich die anderen Elemente bewegen: `multiple` {#how-the-other-items-move-multiple}

Die Liste, in der ein Multi-Drag beginnt, entscheidet, was die anderen ausgewählten Elemente tun,
solange er läuft:

```ts
makeSortableList(listRef, { items: tasks, multiple: 'gaps' });
```

| `multiple` | Während des Ziehens | Das Overlay |
| --- | --- | --- |
| `'group'` (Standard) | Die anderen Elemente verlassen ihre Plätze und reisen mit dem gegriffenen als ein Block von Slots, sodass die Liste schon das Ergebnis des Drops zeigt. | Eine Spalte aus bis zu fünf gezogenen Elementen entlang der Liste. |
| `'gaps'` | Die anderen bleiben bis zum Drop, wo sie sind, abgeblendet (`data-dnd-dragging`). | Dieselbe Spalte. |
| `'stack'` | Die anderen fliegen ins Overlay. | Das gegriffene Element mit einer Anzahl. |

Beim Drop landen die Elemente gemeinsam am Zielindex, in ihrer bisherigen Reihenfolge. Bei
`'group'` und `'gaps'` fliegt jedes Element des Overlays zu seinem eigenen Slot.

### Das Standard-Overlay {#the-default-overlay}

Bei `'group'` und `'gaps'` ist das Overlay eine Spalte der gezogenen Elemente, so wie sie landen
werden: das gegriffene unter dem Zeiger, die anderen davor und danach in Drop-Reihenfolge (eine
Reihe in horizontalen Listen). Es zeigt bis zu fünf Elemente. Die übrigen werden dort gezählt, wo
sie sind: `+N` am Anfang der Spalte für die Elemente, die vor den gezeigten landen, `+N` am Ende
für die danach.

In Rastern würde eine Spalte ganzer Zellen die Seite verdecken, deshalb ist das Overlay ein
Stapel: bis zu drei Elemente, hinter dem gegriffenen aufgefächert, mit der Gesamtzahl obendrauf.

Einfache ziehbare Elemente (`makeDraggable`) zeigen das gegriffene Element mit einer Anzahl.

### Gemischte Typen {#mixed-types}

Haben die ausgewählten Elemente verschiedene Typen, legt `acceptMode` an einem Ziel fest, ob
`'all'` (Standard) oder `'some'` von ihnen passen müssen. Siehe
[Listen mit gemeinsamen Elementen](/docs/guides/shared-lists#limits) und
[Drag and Drop](/docs/guides/drag-and-drop#which-drags-a-target-takes).

## Ein eigenes Overlay für mehrere Elemente {#a-custom-overlay-for-several-items}

Overlay-Komponenten und der `#overlay`-Slot des Providers bekommen `items`: jedes gezogene
Element, das gegriffene zuerst. `DragPreview` rendert den Klon der Bibliothek für jedes davon,
sodass dein Layout das echte Aussehen wiederverwenden kann:

```vue [PileOverlay.vue]
<script setup lang="ts">
import { DragPreview, type OverlayProps } from '@vue-dnd-kit/core';

defineProps<OverlayProps>();
</script>

<template>
  <div class="pile">
    <!-- The grabbed item on top, two more turned behind it -->
    <DragPreview
      v-for="(entry, i) in items.slice(0, 3)"
      :id="entry.id"
      :key="entry.id"
      class="card"
      :style="{ width: '100%', height: '100%', zIndex: 3 - i, rotate: `${i * 4}deg` }"
    >
      <!-- Shown for an item without a clone -->
      <div class="fallback">{{ entry.id }}</div>
    </DragPreview>
    <span v-if="items.length > 1" class="count">{{ items.length }}</span>
  </div>
</template>

<style scoped>
.pile { position: relative; width: 100%; height: 100%; }
.card { position: absolute; inset: 0; }
.fallback { width: 100%; height: 100%; border-radius: 8px; background: Canvas; }
.count { position: absolute; top: -8px; right: -8px; z-index: 4; }
</style>
```

```ts
makeSortableList(listRef, { items: photos, strategy: 'grid', overlay: PileOverlay });
```

Klone werden beim Aufnehmen erstellt: vom gegriffenen Element und von bis zu vier weiteren daneben
in Drop-Reihenfolge, sofern sie gerendert sind. Für jedes andere Element rendert `DragPreview`
seinen Default-Slot. Eine Vorschau hat die Größe ihres Elements beim Aufnehmen, außer du gibst ihr
eine Größe, wie es das `style` oben tut (`class` und `style` werden durchgereicht). Bei `'group'`
und `'gaps'` landet jede Vorschau beim Drop auf dem Slot ihres eigenen Elements. Mehr zu
Overlay-Komponenten unter [Das Overlay](/docs/guides/overlay).

## Bäume {#trees}

In einem Baum bewegen sich die ausgewählten Knoten als ein Block, jeder mit seinem Teilbaum, in
Dokumentreihenfolge. Ein ausgewählter Knoten innerhalb eines anderen ausgewählten fährt im
Teilbaum seines Elternknotens mit. Siehe [Bäume](/docs/guides/trees).
