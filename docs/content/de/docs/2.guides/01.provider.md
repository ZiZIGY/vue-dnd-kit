## Ein Provider für die App {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

Setze einen `DnDProvider` weit oben ein, in `App.vue` oder einem Layout, und vergiss ihn. Jedes
Composable (`makeSortableList`, `makeDraggable`, `useDnD`…) sucht den nächstgelegenen Provider
oberhalb der Komponente, in der es läuft.

::warning
Ein Composable muss in einer Komponente laufen, die **im Provider gerendert** wird. Rufst du es
in der Komponente auf, deren eigenes Template `<DnDProvider>` enthält, wird
`No <DnDProvider> found above this component` geworfen: `inject` von Vue sieht nur Vorfahren.
::

## Wofür er zuständig ist {#what-it-owns}

| Teil | Was der Provider tut |
| --- | --- |
| Eingabe | Macht aus Zeiger-, Touch- und Tastatureingaben Drags (`sensors`), immer nur einen gleichzeitig. |
| Das Ziel finden | Prüft per Hit-Test, welche Drop-Ziele unter dem Drag liegen (`collision`), und teilt es ihnen mit. |
| Das Overlay | Rendert die Box, die dem Zeiger folgt, teleportiert sie nach `body` und lässt sie beim Drop landen. |
| Die Auswahl | Eine Menge ausgewählter IDs, die alle Listen und ziehbaren Elemente darunter teilen. |
| Auto-Scroll | Scrollt Container und das Fenster, wenn sich ein Drag ihren Rändern nähert. |
| Die Live-Region | Sagt Screenreadern an, wenn etwas aufgenommen, bewegt, abgelegt oder abgebrochen wird. |

Sonst rendert er nichts: Dein Markup bleibt, wie es ist.

## Optionen im Überblick {#options-at-a-glance}

Jede Option hat einen Standardwert, der funktioniert, deshalb braucht der Provider meist keine.

| Prop | Standard | Was sie festlegt |
| --- | --- | --- |
| `collision` | `pointerFirst` | Wie das Ziel unter dem Drag gewählt wird. |
| `modifiers` | `[]` | Bewegungsregeln für jeden Drag (Einrasten, Begrenzen, …). |
| `animation` / `dropAnimation` | an | Elemente, die beim Sortieren gleiten / das Landen des Overlays. |
| `animate` | aus | Standard für Listen und Bäume: Datenänderungen animieren, die kein Drag ausgelöst hat. |
| `autoScroll` | an | Scrollen an den Rändern: `{ threshold, maxSpeed, acceleration }` oder `false`. |
| `activation` | Maus 4 px, Touch 200 ms | Wann ein Drücken zum Drag wird, je nach Zeigerart. |
| `keyboard` | Space / Enter, Escape | Tasten und Schrittweite für die Tastatur; `false` schaltet das Ziehen per Tastatur ab. |
| `sensors` | Zeiger + Tastatur | Was Eingaben zu Drags macht. |
| `haptics` | eine kurze Vibration beim Aufnehmen per Touch | Vibrationen bei Touch-Drags, oder `false`. |
| `copyModifier` | `'Alt'` | Taste, die, während des Ziehens gehalten, aus einem Verschieben ein Kopieren macht (die Liste braucht `clone`). |
| `overlayTo` | `'body'` | Wohin das Overlay teleportiert wird. |
| `overlayFit` | `'slot'` | Größe des Overlays: die des Slots, in dem es landen wird, oder die der Quelle. |
| `announcements` | eingebaut | Texte für Screenreader, oder `false`. |
| `defaultStyles` | `true` | Fügt CSS mit Spezifität null für die Drag-Zustände ein. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

Die vollständige Liste mit allen Formen steht in der [DnDProvider-API](/docs/api/dnd-provider).
Der Provider löst außerdem `drag-start`, `drag-move`, `drag-over`, `drag-end` und `drag-cancel`
aus – dieselben Events, die `useDnDMonitor` empfängt.

::tip
Regeln für einen Teil der Seite (ein Board, das einrastet, ein Feed, der nur vertikal scrollt)
brauchen keinen eigenen Provider: Umschließe diesen Teil mit einem
[Drag-Bereich](/docs/guides/constraints).
::

## Den Drag lesen: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="Ziehe eine Aufgabe und beobachte den Zustand" height="22rem"}
::

`useDnD()` liefert den Drag als reaktiven Zustand, in jeder Komponente unter dem Provider:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| Feld | Was es enthält |
| --- | --- |
| `status` | `'idle'`, `'activating'` (ein langes Drücken lädt sich auf), `'dragging'`, `'dropping'` (Landen oder Warten auf ein asynchrones `onBeforeDrop`), `'selecting'` (ein Auswahlrahmen). |
| `active` | Was gezogen wird: `id`, `ids` (alle gezogenen IDs, die gegriffene zuerst), `items`, `data`, `type`, `element`, `rect`, `sensor`. `null` im Ruhezustand. |
| `over` | Das Ziel unter dem Drag: `id`, `data`, `element`, `rect` und `accepted`. `null`, wenn darunter nichts ist. |
| `pointer` | Der Zeiger in Viewport-Koordinaten, nach den Modifiern. |
| `activation.progress` | `0` bis `1`, während sich ein langes Drücken auflädt: Zeichne damit einen Ring. |
| `isAutoScrolling` | Auto-Scroll bewegt gerade etwas. |
| `selection` | Die Auswahl des Providers: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. Siehe [Multi-Drag und Auswahl](/docs/guides/multi-drag). |
| `cancel()` | Bricht den laufenden Drag ab (die Elemente fliegen zurück), ein sich aufladendes langes Drücken oder einen Auswahlrahmen. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

Sobald über einen Drop entschieden ist, sind `active`, `over` und `pointer` `null`, auch während
das Overlay noch landet (`status` bleibt `'dropping'`). Eine UI, die daraus abgeleitet ist, zeigt
nie den alten Drag neben den neuen Daten. Während ein asynchrones `onBeforeDrop` wartet, bleibt
der Zustand so, wie er beim Loslassen war.

## Jeden Drag beobachten: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

Ein Monitor bekommt jeden Drag unter seinem Provider mit, egal wo er beginnt. Er endet, wenn die
Komponente, die ihn aufgerufen hat, unmountet wird.

| Event | Wann |
| --- | --- |
| `onDragStart` | Ein Drag beginnt. |
| `onDragMove` | Der Drag bewegt sich. |
| `onDragOver` | Das Ziel unter dem Drag wechselt. |
| `onBeforeDrop` | Der Drag wird losgelassen. Die Antwort entscheidet über den Drop: siehe [Über einen Drop entscheiden](/docs/guides/drop-decisions). |
| `onDragEnd` | Der Drop ist durchgegangen. Sortierbare Listen haben ihr `onDrop` bereits ausgeführt und die neue Reihenfolge geschrieben. `dropped` ist `false`, wenn der Drag über keinem Ziel endete. |
| `onDragCancel` | Escape, ein Drop auf ein Ziel, das ihn ablehnt, oder ein `onBeforeDrop`, das `'reject'` geantwortet hat. |
| `onDragResume` | `onBeforeDrop` hat `'continue'` geantwortet: Nichts wurde abgelegt, und der Drag geht weiter. |

Jedes Event enthält `active`, `over`, `pointer`, `delta` (den Versatz zum Start),
`position` (wo die gezogene Box in `over` sitzt, siehe
[Drag and Drop](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped)) und, bei Elementen
aus einer sortierbaren Liste, `source`. Die vollständigen Formen stehen in der
[Events-API](/docs/api/events).

::note
`onDragEnd` ist der Ort für alles, was „nach dem Drop“ passiert: Speichern, die Auswahl leeren,
Analytics. Das eigene `onDrop` einer Liste läuft **vor** ihrem Schreiben und sieht deshalb noch
die alte Reihenfolge.
::

## Mehrere Provider {#several-providers}

Die meisten Apps brauchen genau einen. Ein zweiter Provider ist nur sinnvoll für einen Teil der
Seite, der eigene providerweite Einstellungen braucht (Kollisionserkennung, Tastaturtasten,
Ansagen) und dessen Elemente ihn nie verlassen:

- Provider sind unabhängig: Ein Drag wechselt nie von einem zum anderen.
- Verschachtelte Provider sind erlaubt. **Der nächste Besitzer gewinnt**: Ein Element gehört zum
  nächstgelegenen Provider über ihm, und der äußere Provider ignoriert es.
- Jeder Provider hat seine eigene Auswahl, sein eigenes Overlay und seine eigene Live-Region.

Wenn sich Elemente nicht zwischen zwei Teilen deiner Seite bewegen lassen, prüfe, ob sie unter
zwei verschiedenen Providern liegen.

::tip
Eine App, die woanders gemountet ist, in einem Shadow Root oder als eigene Vue-App, kann sich
einem bestehenden Provider anschließen: Übergib `useDnDContext()` an
`provideDnDContext(app, context)`, bevor du sie mountest.
::

## SSR und Nuxt {#ssr-and-nuxt}

Der Provider ist SSR-sicher. Listen und Elemente werden auf dem Server gerendert wie jedes andere
Markup. Overlay und Live-Region werden teleportiert und nur auf dem Client gemountet, deshalb
verursachen sie nie einen Hydration-Mismatch. Standard-IDs kommen aus `useId()` von Vue und
stimmen zwischen Server und Client überein.

In Nuxt registriert das Modul `DnDProvider` global und importiert die Composables automatisch:
siehe [Installation](/docs/getting-started/installation#nuxt).
