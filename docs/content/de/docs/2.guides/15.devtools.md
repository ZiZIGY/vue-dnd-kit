`@vue-dnd-kit/devtools` fügt den Vue DevTools (`vite-plugin-vue-devtools`) und den Nuxt DevTools
einen Tab **Vue DnD Kit** hinzu. Er zeigt jede Liste, jeden Baum und jedes Drop-Ziel der Seite in
einer Live-Minikarte, zieht jedes Element mit einem Joystick, bearbeitet Optionen, während die App
läuft, und protokolliert, was jeder Drag getan hat. Er funktioniert nur in der Entwicklung: Nichts
davon gelangt in einen Production-Build.

## Installation {#install}

```bash
npm i -D @vue-dnd-kit/devtools @vue-dnd-kit/actions
```

`@vue-dnd-kit/actions` ist eine Peer-Dependency: Die Verschiebungen des Tabs laufen darüber. npm 7+
und pnpm installieren es selbst; mit Yarn 1 füge es hinzu.

::code-group

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import vueDevTools from 'vite-plugin-vue-devtools';
import { vueDnDKitDevtools } from '@vue-dnd-kit/devtools/vite';

export default defineConfig({
  plugins: [vueDevTools(), vueDnDKitDevtools(), vue()],
});
```

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  // With @vue-dnd-kit/devtools installed, the tab appears in development.
  modules: ['@vue-dnd-kit/nuxt'],
});
```

::

Mit Vite stellt das Plugin den Tab unter `/__vue-dnd-kit-devtools/` bereit, fügt ihn den Vue
DevTools hinzu und sorgt dafür, dass die Seite ihm berichtet, bevor deine App startet. Ein
`app.use()` ist nicht nötig. Es wirkt nur auf dem Dev-Server (`vite serve`); Builds bleiben
unberührt.

Mit Nuxt findet das Modul `@vue-dnd-kit/nuxt` das Paket, stellt den Tab bereit, fügt ihn den Nuxt
DevTools hinzu und installiert den Teil in der Seite mit einem Client-Plugin.
`vueDndKit: { devtools: false }` schaltet es ab.

### Ohne die Plugins {#without-the-plugins}

Für einen eigenen Dev-Server oder eine Seite, die Vite nicht aus einer `index.html` ausliefert
(SSR-Setups), installiere den Teil in der Seite selbst:

```ts [main.ts]
import { createApp } from 'vue';
import { DnDDevtools } from '@vue-dnd-kit/devtools';
import App from './App.vue';

const app = createApp(App);
app.use(DnDDevtools); // before mount: providers set up earlier aren't seen
app.mount('#app');
```

Oder importiere `@vue-dnd-kit/devtools/auto` als Erstes in der Einstiegsdatei. Nutze
`vueDnDKitDevtools({ inject: false })`, wenn das Plugin den Tab bereitstellen soll, du den Teil in
der Seite aber selbst installierst; `serveTab()` aus `@vue-dnd-kit/devtools/vite` ist die
Middleware, die den Tab bereitstellt.

## Öffnen {#open-it}

- **Vue DevTools**: :kbd{value="Alt"} + :kbd{value="Shift"} + :kbd{value="D"} oder der Vue-Button
  unten auf der Seite, dann der Tab **Vue DnD Kit**.
- **Nuxt DevTools**: :kbd{value="Shift"} + :kbd{value="Alt"} + :kbd{value="D"} oder der
  Nuxt-Button, dann **Vue DnD Kit** (in der Seitenleiste oder ihrem Überlaufmenü).
- **Ein eigenes Fenster**: Öffne `http://localhost:5173/__vue-dnd-kit-devtools/` auf deinem
  Dev-Server oder nutze den Button ⧉ des Tabs. Praktisch auf einem zweiten Bildschirm.

::warning
Halte den Tab in einem eigenen Fenster, nicht in einem Browser-Tab im Hintergrund: Eine verborgene
Seite bricht Drags ab.
::

## Was der Tab zeigt {#what-the-tab-shows}

### Die Minikarte {#the-mini-map}

Eine Live-Karte pro Liste, Baum und Drop-Ziel, mit Kopien ihrer Elemente dort, wo sie sind –
dieselben Klone, die das Overlay zeigen würde. Während eines Drags markiert sie die Listen, die den
Drag annehmen (blau) oder ablehnen (rot), den Platzhalter, das Ziel unter dem Zeiger, die Box des
Overlays und die Einfügelinie von Listen mit `placeholder: 'indicator'`. Ein Klick wählt ein
Element; ein Doppelklick scrollt die Seite zu ihm.

Nutze sie, wenn ein Drop nicht dort landet, wo du es erwartest: Sie zeigt auf einen Blick, welche
Listen den Drag annehmen.

### Drive: der Joystick {#drive-the-joystick}

Wähle ein Element – auf der Karte, im Baum oder mit **Pick**, das das nächste Drücken auf der
Seite übernimmt – und schieb den Knopf des Joysticks. Das Element wird aufgenommen und bewegt sich
in diese Richtung, umso schneller, je weiter der Knopf von der Mitte entfernt ist. **Drop** und
**Cancel** beenden den Drag.

Es ist ein echter Drag per Zeiger von einem Sensor namens `devtools`, deshalb sortieren Listen,
Container scrollen automatisch, und `onBeforeDrop` und `onDrop` laufen wie bei jedem Drag. Elemente
sortierbarer Listen bekommen außerdem Buttons: nach oben, nach unten, an den Anfang, ans Ende, in
eine andere Liste der Gruppe.

| Taste im Tab | Aktion |
| --- | --- |
| Pfeiltasten oder :kbd{value="W"} :kbd{value="A"} :kbd{value="S"} :kbd{value="D"} | Den Knopf in diese Richtung schieben; mit :kbd{value="Shift"} bis zum Anschlag |
| :kbd{value="G"} | Das gewählte Element aufnehmen |
| :kbd{value="Space"} / :kbd{value="Enter"} | Ablegen |
| :kbd{value="Escape"} | Abbrechen |
| :kbd{value="P"} | Auf der Seite wählen |

### Options {#options}

Jede Option, die kein Callback ist, lässt sich bearbeiten, während die App läuft: die des Providers
(`collision`, `modifiers`, `overlayFit`, `autoScroll`, Animationen, `activation`, `keyboard`…),
einer Liste (`strategy`, `placeholder`, `behavior`, `multiple`, `dropOutside`, `disabled`…), eines
Baums, eines Drop-Ziels und eines Elements. Wähle den Knoten und öffne **Options**.

Eine Änderung gilt sofort, nur für diese Seite, und wird nie in deinen Code geschrieben. Sie bleibt
bestehen, bis du sie zurücksetzt, der Provider unmountet wird oder die Seite neu lädt.

### State {#state}

Was jeder Provider weiß, als Baum: seine Drag-Sitzung (Status, die aktiven IDs und der Sensor, das
Ziel und ob es annimmt, der Zeiger), seine Listen und Bäume mit ihrer Reihenfolge und ihrem
Entwurf, Drop-Ziele mit ihren Regeln sowie Typen und Daten der Elemente.

### Log {#log}

Ein Block pro Drag: der Start (IDs, Sensor, die Liste, aus der er kam), jedes `over` und `left`
mit Annahme, das Loslassen, das Urteil von `onBeforeDrop` – angenommen, teilweise angenommen, von
einem Hook abgelehnt, vom `accept` des Ziels abgelehnt – und der `drop`, mit `e.result` und ob
`preventDefault()` aufgerufen wurde, oder der `cancel` und warum. Klicke auf einen Eintrag, um
seine Daten zu sehen.

Nutze es, wenn ein Drop abgelehnt wird und du nicht weißt, wodurch, oder wenn sich eine
kontrollierte Liste nicht geändert hat: Das Log sagt, ob `preventDefault()` lief und was
`e.result` enthielt.

## So funktioniert es {#how-it-works}

Provider berichten an einen Hook, den der Teil in der Seite installiert. Solange kein Tab die Seite
beobachtet, werden sie nur aufgezeichnet; dann hört die Seite zu wie jeder Monitor und schickt dem
Tab, was er anzeigt – alle 40 ms während eines Drags, sonst zweimal pro Sekunde –, und hört auf,
sobald einige Sekunden lang kein Tab zugesehen hat. Der Tab spricht mit der Seite über einen
`BroadcastChannel` des Origins der Seite. Er ändert nichts außer dem, worum du bittest: die Drags,
die Auswahl und die überschriebenen Optionen.
