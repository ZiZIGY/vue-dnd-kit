Ziehe eine Karte nach **Done**. Der Drop wartet auf deine Antwort: die Karte verschieben, sie
woandershin weiterziehen oder abbrechen.

::example{name="drop-confirm" hint="Ziehe eine Karte nach Done" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

Listen, Bäume, Drop-Ziele (`makeDroppable`) und Monitore (`useDnDMonitor`) nehmen ein
`onBeforeDrop`. Es läuft, wenn der Drag losgelassen wird, bevor sich etwas ändert, und seine
Antwort entscheidet:

| Antwort | Was passiert |
| --- | --- |
| `'accept'`, `true` oder nichts | Der Drop geht durch. |
| `'reject'` oder `false` | Kein Drop: Die Elemente fliegen zurück. Ein geworfener Fehler lehnt ebenfalls ab. |
| Ein Array von Schlüsseln | Nur diese Elemente werden abgelegt; die anderen fliegen zurück. |
| `'continue'` | Kein Drop, und der Drag geht weiter. |
| Ein Promise mit einer dieser Antworten | Das Overlay wartet dort, wo es losgelassen wurde, bis das Promise abgeschlossen ist. |

Die eigenen Regeln des Ziels kommen zuerst: `accept` eines Drop-Ziels, `group.put` einer Liste.
Über einem Ziel, das den Drag ablehnt, wird der Drop abgebrochen, und `onBeforeDrop` des Ziels
wird nicht gefragt. `onBeforeDrop` ist für das, was solche Regeln nicht wissen können: die Antwort
des Nutzers, die des Servers oder was der Drop ändern würde.

Listen und Bäume übergeben ein `SortableDropEvent`: `keys`, `items`, `from`, `to`, `mode`,
`sameList` und `result`, die neuen Arrays aller Listen, die der Drop ändert. Drop-Ziele und
Monitore bekommen das allgemeine `DnDEvent`: `active`, `over`, `position` und `source`. Siehe
[Events](/docs/api/events).

### Nur einige Elemente annehmen {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

Bei einem [Multi-Drag](/docs/guides/multi-drag) landen die Elemente, deren Schlüssel du
zurückgibst, und der Rest fliegt dorthin zurück, woher er kam. `onDrop` sieht sie dann in
`e.accepted` und `e.rejected`, und sein `e.result` ist das endgültige.

## Weiterziehen: 'continue' {#keep-dragging-continue}

`'continue'` bricht den Drop ab, nicht den Drag. Das Element bleibt dort, wo es war, in der Hand,
die Seite geht zurück in den Drag-Modus, und der Nutzer macht weiter:

- Mit Maus oder Stift folgt das Element dem Zeiger, ohne dass eine Taste gehalten wird. Das
  nächste Loslassen – ein Klick – legt es ab, und dieser Klick erreicht nie die Seite darunter.
- Bei Touch nimmt der Finger das Element dort wieder auf, wo er aufsetzt; hebt sich der Finger,
  wird es abgelegt.
- Ein Drag per Tastatur geht weiter: Die Pfeiltasten bewegen das Element, :kbd{value="Space"} oder
  :kbd{value="Enter"} legen es ab.
- :kbd{value="Escape"} bricht ihn ab, wie jeden Drag.
- Der nächste Drop fragt `onBeforeDrop` erneut.

Monitore empfangen `onDragResume`, und Screenreader sagen an, dass das Element nicht abgelegt wurde
und sich noch bewegt (überschreibe den Text mit `announcements.onDragResume` des Providers).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## Den Nutzer fragen {#asking-the-user}

`onBeforeDrop` darf ein Promise zurückgeben. Öffne einen Dialog und löse das Promise mit dem
Button auf, den der Nutzer wählt:

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Solange das Promise aussteht:

- wartet das Overlay dort, wo es losgelassen wurde, markiert mit `data-dnd-overlay="dropping"`;
- behält `useDnD()` den Zustand vom Loslassen, und `status` ist `'dropping'`;
- ist die Seite nicht mehr im Drag-Modus: Cursor und Textauswahl sind zurück, sodass ein Dialog
  wie gewohnt funktioniert.

::tip
Ein modales `<dialog>`, geöffnet mit `showModal()`, liegt im Top Layer, über dem wartenden
Overlay. Mach aus seinem `cancel`-Event (:kbd{value="Escape"}) ein `'reject'`, wie es das Beispiel
tut.
::

## Die Reihenfolge der Hooks {#the-order-of-the-hooks}

1. `onBeforeDrop` jedes `useDnDMonitor`, nacheinander. Ein `'reject'` oder ein `'continue'` beendet
   das Fragen; Schlüssel grenzen den Drop ein.
2. `onBeforeDrop` des Ziels: der Liste oder des Baums, in die die Elemente gehen, oder des
   Drop-Ziels.
3. Nur `onDrop` des Ziels: Eine Liste, die Elemente an eine andere abgibt, wird nicht gefragt, und
   ihr neues Array steht im `e.result` des Ziels. Werden Elemente entfernt (eine Papierkorb-Zone,
   `dropOutside: 'remove'`), läuft `onDrop` ihrer Liste, mit `to.index` gleich `-1`.
4. Das Standard-Schreiben: Jede Liste, die der Drop ändert, übernimmt ihr neues Array.
5. Das Overlay landet. `@drag-end` des Providers und `onDragEnd` der Monitore folgen.

Deine Monitore entscheiden vor dem Ziel, deshalb kommt ihr Veto nie, nachdem eine Liste schon
selbst einen Drop angewendet hat.

## onDrop: vor dem Schreiben informiert {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

Das `onDrop` einer Liste läuft, sobald der Drop angenommen ist, synchron, direkt bevor die Liste
ihn schreibt. Um nach dem Schreiben zu handeln, nutze `@drag-end` des Providers oder
`useDnDMonitor({ onDragEnd })`. Bei einem einfachen Drop-Ziel änderst du in `onDrop` deine Daten:
Die Bibliothek verschiebt dafür nichts.

## Stores und Server: kontrollierte Listen {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

Die Bibliothek schreibt einen Drop nur in ein beschreibbares Ref. Ein Getter, ein `computed` oder
ein `readonly`-Ref wird nie beschrieben: Rufe `e.preventDefault()` auf und wende `e.result` selbst
an – die neuen Arrays aller Listen, die der Drop ändert, nach Listen-ID. `preventDefault()`
überspringt das Schreiben in alle davon, denn nur einige zu schreiben würde Elemente verlieren oder
verdoppeln. Entwicklungs-Builds warnen, wenn der Drop einer schreibgeschützten Liste der
Bibliothek überlassen wird.

### Zuerst auf einem Server speichern {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Wende `e.result` an, bevor das Promise erfüllt wird, und das Overlay landet in der neuen
Reihenfolge. Schlägt die Anfrage fehl, wende nichts an: Der Drop geht durch, ändert nichts, und
die Elemente fliegen zurück.

## Außerhalb aller Ziele ablegen {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | Ein Drop außerhalb aller Ziele… |
| --- | --- |
| `'placeholder'` | Landet dort, wo der Platzhalter ist: am letzten Platz, den die Liste gezeigt hat. Der Standard. |
| `'cancel'` | Wird abgebrochen: Die Elemente fliegen zurück. Der Standard bei `placeholder: 'indicator'`. |
| `'remove'` | Entfernt die Elemente aus ihrer Liste. Zuerst wird `onBeforeDrop` der Liste gefragt, und ihr `onDrop` bekommt `to.index` gleich `-1`. |

Eine Papierkorb-Zone tut dasselbe gezielt:
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`. Siehe
[Drag and Drop](/docs/guides/drag-and-drop).
