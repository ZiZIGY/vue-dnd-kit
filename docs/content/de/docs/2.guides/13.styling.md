Die Bibliothek stylt fast nichts. Jeder Zustand eines Drags erreicht dich auf zwei Wegen: als Ref,
das das Composable zurückgibt, für Klassen und bedingtes Markup, und als `data-dnd-*`-Attribut,
für reines CSS.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## Die zurückgegebenen Refs {#the-returned-refs}

| Composable | Zustand |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`: Dieses Element ist der Slot, in dem ein gezogenes Element landen wird.
- `isDragging`: Das Element ist Teil des Drags (beim Multi-Drag jedes gezogene Element).
- `isAccepting`: Etwas wird gezogen, und dieses Ziel nimmt es an – hebe die Stellen hervor, an
  denen ein Drop möglich ist.
- `isOver`: Der Drag ist über diesem Ziel, ob es ihn annimmt oder nicht. `isOver && !isAccepting`
  ist eine Ablehnung, die sich anzuzeigen lohnt.
- `over.accepted` aus `useDnD()` (`accepted` in den Overlay-Props) ist `false` über einem Ziel,
  das den Drag ablehnt: Färbe damit das Overlay rot.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## Die Data-Attribute {#the-data-attributes}

| Attribut | An | Wann |
| --- | --- | --- |
| `data-dnd-placeholder` | sortierbares Element | Es ist der Slot, in dem ein gezogenes Element landen wird. |
| `data-dnd-dragging` | sortierbares Element | Es wird gezogen, bleibt aber an seinem Platz: die anderen Elemente eines Multi-Drags im Modus `'gaps'`. |
| `data-dnd-dragging="pointer"` oder `"keyboard"` | `<html>` | Während des ganzen Drags. |
| `data-dnd-overlay="dragging"` oder `"dropping"` | die Overlay-Box | Immer. `dropping`, während sie landet und während ein asynchrones `onBeforeDrop` wartet. |
| `data-dnd-leaving` | eine Kopie, die `animate` zurücklässt | Während ein gegangenes Element ausblendet. |
| `data-dnd-no-clone` | **von dir gesetzt** | Lässt das Element aus dem Klon des Overlays weg: einen Tooltip, einen Menü-Button, ein Badge. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## Standard-Styles {#default-styles}

Der Provider fügt ein paar Regeln einmal pro Dokument ein. Sie sind in `:where()` verpackt,
deshalb ist ihre Spezifität null, und jede deiner Regeln gewinnt:

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

Der Slot wird abgeblendet, die Seite wählt während eines Drags keinen Text aus und verankert ihr
Scrollen nicht, und der Cursor ist während eines Drags per Zeiger eine greifende Hand.
`:default-styles="false"` schaltet sie ab. `cursor: grab` auf ziehbaren Elementen fügst du selbst
hinzu.

## Rezepte {#recipes}

### Ein leerer Slot {#an-empty-slot}

Zeige statt einer abgeblendeten Kopie des Elements eine leere, gestrichelte Box dort, wo es landen
wird:

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

Das Pseudo-Element verdeckt den Inhalt, deshalb behält der Slot genau die Größe des Elements.
Ziehe hier eine Karte, um es zu sehen:

::example{name="kanban" hint="Der Slot einer gezogenen Karte ist eine gestrichelte Box" height="24rem"}
::

### Eine Zeile, die die Liste malt {#a-row-the-list-paints}

Das Standard-Overlay ist ein Klon des gezogenen Elements. Er zeigt das Element, wie es ist, und
errät keinen Hintergrund: Eine Zeile ohne eigenen – ein `<li>` in einem weißen `<ul>`, eine
Tabellenzeile, ein Listeneintrag eines UI-Kits – ergibt einen durchsichtigen Klon. Gib ihm den
Hintergrund der Liste:

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

Der Klon behält die Klassen und Attribute des Elements – auch das Attribut eines Scoped Styles –,
deshalb funktioniert die Regel im eigenen `<style scoped>` der Zeile, neben ihren anderen Styles.
Oder gib der Zeile einen eigenen Hintergrund. Icons und Kacheln, die schweben sollen, bleiben
transparent.

### Ein angehobenes Overlay, nur beim Ziehen {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

Der Schatten ist da, solange die Karte unterwegs ist, und verschwindet, sobald das Overlay auf
`dropping` wechselt, sodass die Karte flach in ihrem Slot landet. Bei einer eigenen
Overlay-Komponente trifft dieselbe Regel das Root-Element deiner Komponente, oder du liest
`status` aus ihren Props.

### Reduzierte Bewegung {#reduced-motion}

Die Bibliothek stoppt ihre eigenen Animationen bei `prefers-reduced-motion: reduce` bereits. Mach
dasselbe für die Transitions, die du rund um Drags hinzufügst:

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### Vermeiden {#dont}

- Setze keine CSS-`transition` auf `transform` oder `translate` sortierbarer Elemente: Die
  Bibliothek animiert sie selbst und bricht solche Transitions ab, während sie misst.
- Animiere nicht `height`, `margin` oder `padding` von Zeilen in einer
  [virtuellen Liste](/docs/guides/virtual-lists).

Mehr zum Overlay – eigene Komponenten, seine Größe, `DragPreview` – unter
[Das Overlay](/docs/guides/overlay).
