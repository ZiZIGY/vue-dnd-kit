## Eine Liste und ihre Zeilen {#a-list-and-its-rows}

Eine sortierbare Liste braucht zwei Komponenten: die Liste und ihre Zeile.

```vue [TaskList.vue]
<script setup lang="ts">
import { ref, useTemplateRef } from 'vue';
import { makeSortableList } from '@vue-dnd-kit/core';
import TaskRow from './TaskRow.vue';

const tasks = ref([
  { id: 1, title: 'Sketch the board' },
  { id: 2, title: 'Write the docs' },
  { id: 3, title: 'Ship v3' },
]);

const listRef = useTemplateRef<HTMLElement>('list');
const { items } = makeSortableList(listRef, { items: tasks });
</script>

<template>
  <ul ref="list">
    <TaskRow v-for="task in items" :key="task.id" :task="task" />
  </ul>
</template>
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ task: { id: number; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el">{{ task.title }}</li>
</template>
```

Die Zeile registriert sich bei der Liste, in der sie gerendert wird. Deshalb braucht auch jede
Liste eine eigene Komponente: Zwei Listen, die in einer Komponente erstellt werden, würden sich
ihre Zeilen teilen.

## Der Entwurf {#the-draft}

`makeSortableList` gibt `items` zurück, einen **Entwurf** deines Arrays. Während du ziehst, ordnet
sich der Entwurf live neu: Die gezogene Zeile nimmt ihren neuen Slot ein, und die anderen gleiten
aus dem Weg. Dein Array ändert sich erst beim Drop. Dann schreibt die Bibliothek die neue
Reihenfolge hinein.

::example{name="quick-start" hint="Die IDs unter der Liste sind dein Array: Sie ändern sich beim Drop"}
::

- Rendere `items`, nicht dein Array. Renderst du dein Array, bewegt sich bis zum Drop nichts.
- Das Schreiben passiert nach dem `onDrop` der Liste. In `onDrop` enthält dein Array noch die
  alte Reihenfolge und `e.result` die neue.
- `tasks` ist ein normales `ref`, deshalb sieht der Rest deiner App die Änderung wie jede andere.

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    console.log(e.from.index, '→', e.to.index, e.result.get(e.to.list));
  },
});
```

Eine Listenkomponente, die ihr Array über `v-model` bekommt, reicht das Model weiter:

```ts
const tasks = defineModel<Task[]>({ required: true });
const { items } = makeSortableList(listRef, { items: tasks });   // the write emits update:modelValue
```

::tip
Ein Store, Serverzustand oder unveränderliche Daten? Übergib einen Getter oder ein `computed`
statt eines Refs. Eine schreibgeschützte Quelle beschreibt die Bibliothek nicht: Rufe
`e.preventDefault()` auf und wende `e.result` selbst an. Siehe
[Über einen Drop entscheiden](/docs/guides/drop-decisions).
::

## Schlüssel {#keys}

Den Schlüssel einer Zeile liefern ihre Daten, nie der Index oder eine automatische ID.
Standardmäßig ist der Schlüssel `item.id`, bei Strings und Zahlen das Element selbst.

```ts
// TaskList.vue: your items have another key
makeSortableList(listRef, { items: tasks, getKey: (task) => task.uuid });

// TaskRow.vue: `item` is keyed with the list's getKey…
makeSortableItem(el, { item: () => props.task });
// …or pass the key yourself
makeSortableItem(el, { id: () => props.task.uuid });
```

- Verwende denselben Schlüssel in `v-for`: `:key="task.uuid"`. Mit `:key="index"` animieren die
  falschen Zeilen, und ihr Zustand springt zwischen den Zeilen hin und her.
- Schlüssel müssen über alle Listen hinweg eindeutig sein, die Elemente austauschen.
- Übergib `item` und `id` als Getter, damit eine Zeile synchron bleibt, wenn sich ihre Props
  ändern.

## Strategien {#strategies}

| `strategy` | Für |
| --- | --- |
| `'vertical'` (Standard) | Eine Spalte aus Zeilen. |
| `'horizontal'` | Eine einzelne Reihe: Tabs, Chips, eine Zeitleiste. |
| `'grid'` | CSS-Grids und umbrechende Flex-Reihen, auch mit unterschiedlich großen Elementen. |

```ts
const { items } = makeSortableList(grid, { items: apps, strategy: 'grid' });
```

## Handles {#handles}

Standardmäßig startet die ganze Zeile einen Drag (außer Buttons, Eingabefeldern und anderen
Bedienelementen darin). Übergib `handle`, um nur an einem Teil zu ziehen:

```vue [Track.vue]
<script setup lang="ts">
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el">
    {{ track.title }}
    <button type="button" class="grip" aria-label="Reorder">⠿</button>
  </li>
</template>
```

- `handle` ist ein Selektor innerhalb des Elements oder ein Element-Ref.
- Ein Drag mit der Maus startet am Handle sofort, ohne die üblichen 4 px.
- Das Handle bekommt die Attribute des Drags (`role`, `tabindex`, `aria-*`), und Drags per
  Tastatur starten von ihm aus.

Mach das Handle zu einem `<button type="button">` mit einem `aria-label`: Er ist von sich aus
fokussierbar, und Screenreader sagen sein Label an. Ein bloßes `<span>` mit einem Icon
funktioniert auch (die Bibliothek gibt ihm `tabindex="0"` und `role="button"`), hat aber keinen
aussagekräftigen Namen.

::note
Touch-Drags starten nach einem langen Drücken von 200 ms, damit die Seite weiterhin scrollen
kann. Um von einem Handle aus sofort zu ziehen, gib dem Handle `touch-action: none` und dem
Element `activation: { touch: { distance: 4 } }`.
::

## Die Achse sperren {#lock-the-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'y'` hält den Drag auf der vertikalen Achse, `'x'` auf der horizontalen. Das eigene `axis`
eines Elements hat Vorrang vor dem seiner Liste. Um den Drag außerdem innerhalb der Liste zu
halten, füge den Modifier `restrictToParent` hinzu; die Playlist oben nutzt beides. Mehr unter
[Achsen, Grenzen und Raster](/docs/guides/constraints).

## Den Slot gestalten {#style-the-slot}

Die gezogene Zeile bleibt als der Slot, in dem sie landen wird, in der Liste und bekommt
`data-dnd-placeholder`. Der Standardstil blendet sie auf 40 % ab, mit Spezifität null, deshalb
gewinnt jede deiner eigenen Regeln:

```css
/* An empty, dashed slot instead of a faded row */
.track[data-dnd-placeholder] {
  opacity: 1;
  position: relative;
}

.track[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

`makeSortableItem` gibt denselben Zustand als Refs zurück, dazu noch ein paar weitere:

| Rückgabe | Was es ist |
| --- | --- |
| `isPlaceholder` | Diese Zeile ist der Slot, in dem ein gezogenes Element landen wird. |
| `isDragging` | Diese Zeile wird gerade gezogen (beim Multi-Drag jede gezogene Zeile). |
| `index` | Ihr Index im Entwurf: Er ändert sich während des Ziehens. |
| `selected` | Beschreibbar, an die Auswahl des Providers gebunden. |
| `indicator` | Im [Indikator-Modus](/docs/guides/shared-lists#an-insertion-line): wohin die Linie kommt. |

Die Liste gibt `isOver` und `isAccepting` für ihre eigene Hervorhebung zurück. Alle Attribute und
Rezepte stehen unter [Styling](/docs/guides/styling).

## Dinge abschalten {#turning-things-off}

- `disabled` an der Liste: keine Drags aus ihr heraus, keine Drops in sie hinein. An einem
  Element: Es lässt sich nicht ziehen.
- `sort: false`: Elemente lassen sich innerhalb dieser Liste nicht neu ordnen, können sie aber
  weiterhin verlassen (eine Palette, siehe
  [Listen mit gemeinsamen Elementen](/docs/guides/shared-lists)).

## Animationen {#animations}

Zeilen gleiten während des Ziehens an ihre neuen Plätze, und die abgelegte Zeile landet auf ihrem
Slot. Das ist standardmäßig an und braucht keinen Code. Umschließe Zeilen nicht mit
`<TransitionGroup>`: Bewegungen würden doppelt animiert. Für Änderungen, die kein Drag ausgelöst
hat (Hinzufügen, Entfernen, Mischen), schalte die Option `animate` der Liste ein. Siehe
[Animationen](/docs/guides/animations).

Die vollständige Liste der Optionen steht in der API von
[makeSortableList](/docs/api/make-sortable-list) und
[makeSortableItem](/docs/api/make-sortable-item).
