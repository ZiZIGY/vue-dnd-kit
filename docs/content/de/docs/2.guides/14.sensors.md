Ein Sensor macht aus Eingaben Drags. Er sagt dem Provider nur „ziehe dieses Element von hier aus“,
dann, wohin sich die Eingabe bewegt hat, und ob abgelegt oder abgebrochen wurde. Den Rest erledigt
der Provider, für jeden Sensor auf dieselbe Weise: nur ein Drag gleichzeitig, deaktivierte Elemente
abgelehnt, Aktivierungsbedingungen, Sortieren, Auto-Scroll, Ansagen, :kbd{value="Escape"} und der
ganze Drop.

## Die eingebauten Sensoren {#the-built-in-sensors}

| Sensor | Eingabe |
| --- | --- |
| `pointerSensor` | Maus, Touch und Stift, über Pointer Events. Er fängt den Zeiger ein, verhindert, dass die Seite unter einem Touch-Drag Text auswählt oder scrollt, und schluckt den Klick, der auf einen Drag folgt. |
| `keyboardSensor` | :kbd{value="Space"} und :kbd{value="Enter"} nehmen auf und legen ab, Pfeiltasten bewegen, :kbd{value="Escape"} bricht ab – jeden Drag, auch Drags per Zeiger. |

Beide laufen standardmäßig. `sensors` des Providers ersetzt die Liste:

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

Um das Ziehen per Tastatur abzuschalten, nimm lieber `:keyboard="false"`, statt `keyboardSensor`
wegzulassen: Der Tastatur-Sensor ist auch das, was jeden Drag mit :kbd{value="Escape"} abbricht.
Seine Tasten belegst du mit `keyboard.keys` neu (siehe
[Barrierefreiheit](/docs/guides/accessibility#the-keyboard)).

## Aktivierungsbedingungen {#activation-constraints}

Ein Drücken wird zum Drag, sobald es seine Bedingung erfüllt:

| Zeiger | Standard |
| --- | --- |
| Maus | Nach 4 px Bewegung. Sofort beim Drücken auf ein `handle`, außer du setzt eine Bedingung für die Maus. |
| Stift | Nach 4 px Bewegung. |
| Touch | Nach 200 ms Drücken. Eine Bewegung von mehr als 5 px vorher bricht es ab, sodass stattdessen die Seite scrollt. |

Eine Bedingung hat drei Felder:

| Feld | Bedeutung |
| --- | --- |
| `distance` | Pixel, die der Zeiger zurücklegen muss. |
| `delay` | Millisekunden, die das Drücken dauern muss. Sind beide gesetzt, startet das, was zuerst eintritt, den Drag. |
| `tolerance` | Mit `delay`: wie weit sich der Zeiger währenddessen bewegen darf; darüber hinaus wird das Drücken verworfen. |

Setze sie je Zeigerart – `mouse`, `touch`, `pen` – am Provider, an einem Drag-Bereich oder am
Element selbst. Die des Elements gewinnt, dann die seines Bereichs, dann die des Providers:

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

Um per Touch sofort von einem Handle aus zu ziehen, gib dem Handle `touch-action: none` (damit der
Browser nicht scrollt) und dem Element `activation: { touch: { distance: 4 } }`.

### Ein Ring für langes Drücken {#a-long-press-ring}

Während ein Drücken wartet, ist `useDnD().status` `'activating'`, und `activation.progress` läuft
von 0 bis 1:

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### Nicht jedes Drücken {#only-some-presses}

`canDrag` ist eine weitere Schranke für ziehbare und sortierbare Elemente. Es bekommt das
Eingabe-Event:

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

Interaktive Kindelemente – Buttons, Eingabefelder, editierbare Felder – starten nie einen Drag per
Zeiger, deshalb funktionieren sie in einem ziehbaren Element weiter. Mit einem `handle` startet nur
das Handle einen.

## Ein eigener Sensor {#a-sensor-of-your-own}

Ein Gamepad, ein Joystick auf dem Bildschirm, Sprachbefehle: Alles, was auf ein Element zeigen und
sich bewegen kann, kann einen Drag steuern. Hier ist ein Joystick, der nach 300 ms Halten aufnimmt,
was unter seinem Cursor ist:

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

Füge ihn zu `sensors` des Providers hinzu oder lass ihn mit `useSensor(joystick.sensor)` so lange
laufen, wie eine Komponente lebt.

### Was der Sensor bekommt {#what-the-sensor-gets}

`setup(context)` bekommt die Seite des Providers:

| Member | Was es ist |
| --- | --- |
| `props` | Die Props des Providers (`activation`, `keyboard`…). Lies sie, wenn du sie brauchst: Sie können sich ändern. |
| `status` | Der Drag-Status des Providers, egal welcher Sensor den Drag führt. |
| `drag` | Der aktuelle Drag des Providers, wartend oder laufend, egal welcher Sensor ihn gestartet hat. `null`, wenn es keinen gibt. |
| `activate(options)` | Fordert einen Drag an. Gibt einen `SensorDrag` zurück oder `null`, wenn kein Drag starten darf. |
| `cancel()` | Bricht den Drag oder das wartende Drücken des Providers ab. |

`activate()` nimmt:

| Option | Bedeutung |
| --- | --- |
| `target` | Wo die Eingabe gelandet ist: ein Element innerhalb eines ziehbaren Elements oder die ID eines ziehbaren Elements. Ein Element wird wie ein echtes Drücken geprüft (Handle, kein interaktives Kindelement); eine ID überspringt die Prüfungen. |
| `point` | Wo der Drag beginnt, in Viewport-Koordinaten. Standard: die Mitte des ziehbaren Elements. |
| `type` | `'pointer'` (Standard): folgt Punkten, prüft Ziele per Hit-Test, scrollt automatisch. `'keyboard'`: bewegt sich um Elemente, macht Ziele sichtbar, gibt am Ende den Fokus zurück. |
| `activation` | Eine Bedingung (`{ delay: 300 }`) oder eine Zeigerart (`'touch'`), um die konfigurierte zu verwenden. Standard: keine, der Drag startet sofort. |
| `event` | Das Eingabe-Event, das an `canDrag` des Elements übergeben wird. Ein Touch-`pointerType` macht daraus einen Touch-Drag (Haptik). |
| `onStart(drag)` | Der Drag hat begonnen, nach seiner Aktivierung. |
| `onEnd(drag)` | Der Drag ist vorbei: verworfen, abgelegt oder abgebrochen – von wem auch immer. |
| `onResume(drag)` | `onBeforeDrop` hat `'continue'` geantwortet: Der Drag geht weiter, und `move`, `drop` und `cancel` gelten wieder. |

Der zurückgegebene `SensorDrag`:

| Member | Was es tut |
| --- | --- |
| `id`, `type` | Die ID des gezogenen Elements und `'pointer'` oder `'keyboard'`. |
| `state` | `'pending'` (wartet auf die Aktivierung), `'dragging'`, dann `'ended'`. |
| `started` | Der Drag hat begonnen, auch wenn er inzwischen beendet ist. |
| `move(point)` | Die Eingabe hat sich bewegt. Im Wartezustand wird die Toleranz geprüft; beim Ziehen wird der Drag bewegt. |
| `step(direction)` | Drags per Tastatur: ein Schritt mit einer Pfeiltaste, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | Setzt das Element an eine Position einer sortierbaren Liste, wie es Bewegungen per Tastatur tun. Liefert `false`, wenn keine Liste es dort annimmt. |
| `drop()` | Legt ab. Liefert `true`, wenn der Drop durchgegangen ist, sobald er gelandet ist. |
| `cancel()` | Bricht ab: Das Element fliegt zurück, oder ein wartendes Drücken wird verworfen. |

Aufrufe, die nicht mehr gelten – eine Bewegung nach dem Ende, ein zweites `drop()` –, werden
ignoriert. Vollständige Typen: [Sensoren](/docs/api/sensors).

::tip
Um einen eingebauten Sensor zu umhüllen, führe sein `setup` mit einem eigenen Kontext aus.
Erzeuge ihn mit `Object.create(context, { activate: { value: myActivate } })` statt mit einem
Spread, damit die Live-Getter (`status`, `drag`, `props`) weiter funktionieren.
::

## Programmatisches Ziehen {#programmatic-drags}

`@vue-dnd-kit/actions` verschiebt Elemente aus Code heraus: „Nach oben“-Buttons, Menüs,
Tastenkürzel, Rückgängig, Onboarding-Touren, Tests. Es baut auf der öffentlichen Sensor-API auf,
und seine Drags sind echte: angesagt und animiert, über `onBeforeDrop`, `onDrop`, `e.result` und
`preventDefault()`, nach den Regeln des Providers (nur ein Drag gleichzeitig, deaktivierte Elemente,
`accept` und `group.put`).

```bash
npm i @vue-dnd-kit/actions
```

### moveItem: ein Aufruf, eine Verschiebung {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list` ist die `id` einer sortierbaren Liste. Ohne sie bleibt das Element in seiner Liste.
- `index` ist der Platz, an dem das Element landet, gezählt ohne das Element selbst und auf die
  Liste begrenzt. Ohne ihn kommt das Element ans Ende.
- Es liefert `true`, wenn der Drop durchgegangen ist, `false`, wenn das Element nicht gerendert
  oder deaktiviert ist, keine Liste es dort annimmt oder der Drop abgelehnt wurde.
- Aufrufe werden in eine Warteschlange gestellt: Jeder wartet, bis der Provider im Leerlauf ist,
  sodass ein schneller zweiter Klick nicht verloren geht.
- Es läuft als Drag per Tastatur, deshalb wird es angesagt, und der Fokus bleibt auf dem Element.
- Nur für Listen: Positionen in Bäumen haben zusätzlich eine Tiefe.

Eine Zeile mit Buttons zum Verschieben zeigt
[Barrierefreiheit](/docs/guides/accessibility#moving-without-dragging).

### startDrag: ein geskripteter Drag {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo` wird erfüllt, sobald die Bewegung gerendert ist, `drop`, sobald der Drop gelandet ist.
`startDrag(id, { type: 'keyboard' })` bewegt stattdessen um Elemente (`await drag.step('down')`),
und der Tastatur-Sensor kann übernehmen: ein Menüpunkt „Verschieben“, der das Element an die
Pfeiltasten übergibt.

### Außerhalb von Komponenten {#outside-components}

`useDnDActions()` betreibt einen Sensor namens `actions` im Provider darüber. Um einen Provider aus
einem Store oder einem Test-Harness zu steuern oder unter einem eigenen Namen, erzeuge die Actions
in einem Sensor, den du selbst betreibst:

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

Dann geht `await tour?.moveItem('card-1', { list: 'done' })` von überall. Beim Server-Rendering
wird nichts gezogen: `moveItem` liefert `false`, und `startDrag` gibt `null` zurück.
