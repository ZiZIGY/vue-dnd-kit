Schalte Achse, Raster und Grenzen um, dann ziehe eine Notiz. Das Board legt die Regeln für jeden
Drag fest, der auf ihm beginnt, und jede Notiz bleibt, wo du sie ablegst.

::example{name="constraints" hint="Schalte die Regeln um, dann ziehe eine Notiz" height="26rem"}
::

## Eine Achse sperren {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'` bewegt nur horizontal, `'y'` nur vertikal. `makeDraggable`, `makeSortableList`,
`makeSortableTree`, `makeSortableItem` und `makeDragArea` kennen es alle.

- Die Sperre läuft **nach jedem Modifier**, deshalb hält sie, egal was diese tun: Ein Einrasten
  oder eine Grenze kann das Element nicht von seiner Linie schieben.
- Das eigene `axis` eines Elements hat Vorrang vor dem seiner Liste oder seines Baums, und das
  eines ziehbaren Elements (oder seiner Liste) hat Vorrang vor dem seines Drag-Bereichs.
- Es wird gelesen, wenn ein Drag beginnt, deshalb kann ein Getter es umschalten:
  `axis: () => (locked.value ? 'y' : undefined)`.
- Ein auf `'y'` gesperrter Baum verschachtelt trotzdem: Die Tiefe ergibt sich dann aus dem Halten
  über der Mitte einer Zeile.

::tip
Bevorzuge `axis` gegenüber den Modifiern `restrictToVerticalAxis` und `restrictToHorizontalAxis`.
Sie tun dasselbe, laufen aber als gewöhnliche Modifier mitten in der Kette, und ein Modifier danach
(ein Raster, das auf beiden Achsen einrastet) kann das Element wieder von der Achse schieben.
::

## Modifier {#modifiers}

Ein Modifier passt den Versatz des Drags in jedem Frame an. Sein Ergebnis bewegt das Overlay
**und** ist der Punkt, an dem nach Zielen gesucht wird, deshalb sortiert eine Liste nach der
gesperrten, begrenzten oder eingerasteten Position.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| Modifier | Was er tut |
| --- | --- |
| `restrictToVerticalAxis` | Bewegt nur vertikal. Besser: `axis: 'y'`. |
| `restrictToHorizontalAxis` | Bewegt nur horizontal. Besser: `axis: 'x'`. |
| `restrictToWindowEdges` | Hält das Overlay im Fenster. |
| `restrictToParent` | Hält das Overlay in dem Container, in dem der Drag begann: der sortierbaren Liste oder dem Elternelement eines einfachen ziehbaren Elements. |
| `restrictToElement(target)` | Hält das Overlay in einem Element: einem Template-Ref, einem Getter oder dem Element selbst. |
| `restrictToFirstScrollableAncestor` | Hält das Overlay im ersten scrollbaren Vorfahren des gezogenen Elements. |
| `snapToGrid(size)` | Lässt das Overlay an einem Raster einrasten (siehe unten). |
| `snapCenterToCursor` | Zentriert das Overlay unter dem Zeiger, statt den Greifversatz beizubehalten. |

`modifiers` ist eine Option des Providers, von Drag-Bereichen, von Listen und Bäumen sowie von
ziehbaren und sortierbaren Elementen. Alle außer der des Providers nehmen auch ein Ref oder einen
Getter, gelesen beim Start des Drags.

### Am Raster einrasten {#snap-to-a-grid}

`snapToGrid(24)` rastet beide Achsen an Zellen von 24 px ein. Ein Objekt legt mehr fest:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| Option | Bedeutung |
| --- | --- |
| `x`, `y` | Die Zellgröße in Pixeln, pro Achse. |
| `origin` | `'container'` (Standard): Die linke obere Ecke des Overlays landet auf Rasterlinien, die von der linken oberen Ecke des Containers aus gezogen sind – der sortierbaren Liste oder dem Elternelement eines einfachen ziehbaren Elements. `'delta'`: Der Versatz selbst wird gerundet, sodass ein Element, das neben dem Raster begann, neben dem Raster bleibt. |
| `smooth` | `true` oder `{ duration, easing }`: Das Overlay gleitet zwischen den Zellen (standardmäßig 80 ms). Ziele nutzen sofort die eingerastete Position. |

### Ein eigener Modifier {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

Ein Modifier bekommt `transform`, den Versatz seit dem Start des Drags, so wie ihn die Modifier
davor hinterlassen haben, und gibt einen neuen zurück. Außerdem bekommt er, was er zur Berechnung
brauchen kann: `activeRect` (das gezogene Element beim Start), `overlayRect` (das um `transform`
verschobene Overlay), `containerRect`, `windowRect`, `origin` (der Zeiger beim Start), `active`
und `over`. Siehe [Modifier und Kollisionserkennung](/docs/api/modifiers).

## Die Reihenfolge {#the-order}

Modifier aus mehreren Quellen laufen nacheinander, jeder auf dem Ergebnis des vorherigen:

1. die `modifiers` des Providers;
2. die `modifiers` des Drag-Bereichs, in dem der Drag begann;
3. die eigenen `modifiers` des gezogenen Elements oder, wenn es keine hat, die seiner Liste oder
   seines Baums;
4. `restrictToArea` des Drag-Bereichs;
5. die Sperre durch `axis`.

Die `modifiers` eines Elements **ersetzen** die seiner Liste; sie kommen nicht hinzu. Die Grenzen
des Bereichs kommen nach dem Einrasten der Schritte 1–3, deshalb bleibt auch ein eingerastetes
Element innerhalb, und die Achsensperre kommt ganz zum Schluss.

## Begrenzte Listen behalten ihre Enden {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

Eine Grenze hält das Overlay am Rand der Box fest, während der Zeiger weiterläuft. Sobald der
Zeiger das Overlay entlang der Achse der Liste verlassen hat, sortiert die Liste stattdessen nach
dem Zeiger, sodass der erste und der letzte Platz erreichbar bleiben, egal wie du das Element
hältst. Raster sortieren weiter nach dem Overlay: Am Rand festgehalten, bedeckt es bereits die
Randzelle.

## Regeln für einen Teil der Seite {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea` legt Regeln für die Drags fest, die **in seinem Element beginnen** – für einfache
ziehbare wie für sortierbare Elemente. Behalte einen `DnDProvider` für die ganze App, und gib
einem Board, einem Canvas oder einem Feed einen eigenen Bereich.

| Option | Was sie tut |
| --- | --- |
| `axis` | Sperrt die Drags auf eine Achse. Das eigene `axis` eines ziehbaren Elements oder das seiner Liste hat Vorrang. |
| `modifiers` | Laufen nach denen des Providers und vor den eigenen des ziehbaren Elements. |
| `restrictToArea` | `true`: Die Drags bleiben im Element des Bereichs. |
| `autoScroll` | Auto-Scroll des Scroll-Containers des Bereichs (das Element oder sein nächster scrollbarer Vorfahr). `false` schaltet es dort ab. |
| `activation` | [Aktivierung](/docs/guides/sensors#activation-constraints) je Zeigerart. Die eigene eines ziehbaren Elements hat Vorrang; die des Providers kommt zuletzt. |
| `disabled` | Im Bereich beginnt kein Drag, auch nicht in den Bereichen darin. Seine ziehbaren Elemente melden `aria-disabled`. |

Jede Option nimmt einen Wert, ein Ref oder einen Getter, gelesen, wenn ein Drücken oder ein Drag
beginnt. Der Bereich gibt `isDragging` (ein hier begonnener Drag läuft) und `isAutoScrolling`
(Auto-Scroll bewegt seinen Container) zurück. Vollständige Referenz:
[makeDragArea](/docs/api/make-drag-area).

### Wie Bereiche zusammenwirken {#how-areas-combine}

- Ein Drag folgt dem Bereich, in dem er **begonnen hat**, auch nachdem er ihn verlassen hat. Über
  einen Bereich hinwegzuziehen ändert nichts, außer bei seinem `autoScroll`: Das gilt für jeden
  Drag, der seinen Container scrollt.
- Verschachtelte Bereiche werden nicht zusammengeführt: Der nächstgelegene gewinnt. `disabled` ist
  die Ausnahme und wird vererbt: Ein abgeschalteter Bereich schaltet auch die Bereiche darin ab.
- Kollisionserkennung, Tastaturtasten und Ansagen bleiben providerweit.

::note
Warum kein zweiter `DnDProvider` um das Board? Provider sind unabhängig: Ein Drag wechselt nie von
einem zum anderen, deshalb könnten die Elemente des Boards es nie verlassen. Verschachtele einen
Provider nur, wenn ein Teil der Seite eigene providerweite Einstellungen braucht und seine
Elemente darin bleiben. Siehe [Der Provider](/docs/guides/provider).
::

## Dort lassen, wo es abgelegt wird {#leave-it-where-its-dropped}

Das Board im Beispiel ist auch ein Drop-Ziel, und jede Notiz behält den Platz, an dem sie abgelegt
wurde. Jedes Drag-Event enthält `position`: die linke obere Ecke der gezogenen Box im Ziel, ab
dessen Padding-Kante und mit seiner Scroll-Position – die `left` und `top`, die ein absolut
positioniertes Element genau dorthin setzen. Es kommt nach den Modifiern, deshalb landet eine
eingerastete Notiz auf dem Raster.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

Mehr zu freiem Ziehen und Drop-Zielen unter [Drag and Drop](/docs/guides/drag-and-drop).
