```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider :animation="{ duration: 200 }" @drag-end="save">
    <RouterView />
    <template #overlay="{ items, over, accepted }">
      <!-- optional: a custom overlay for every drag -->
    </template>
  </DnDProvider>
</template>
```

Jedes Composable muss in einer Komponente laufen, die **innerhalb** eines Providers gerendert
wird. Ziel ist ein einziger Provider für die ganze App: Teile der Seite bekommen mit
[`makeDragArea`](/docs/api/make-drag-area) eigene Regeln. Siehe den Leitfaden
[Der Provider](/docs/guides/provider).

Die meisten Props werden gelesen, wenn der Provider sie braucht: Ändere eine, und der nächste
Drag verwendet sie.

## Events {#events}

| Event | Payload | Wann |
| --- | --- | --- |
| `drag-start` | `DnDEvent` | Ein Drag hat begonnen (nach seiner Aktivierung). |
| `drag-move` | `DnDEvent` | Der Zeiger hat sich während eines Drags bewegt (höchstens einmal pro Frame). |
| `drag-over` | `DnDEvent` | Das Ziel unter dem Drag hat sich geändert. |
| `drag-end` | `DnDEndEvent` | Ein Drop wurde ausgeführt und geschrieben. |
| `drag-cancel` | `DnDEvent` | Der Drag wurde abgebrochen oder der Drop abgelehnt. |

Dieselben Events, dazu `onBeforeDrop` und `onDragResume`, stehen mit
[`useDnDMonitor`](/docs/api/use-dnd) überall unterhalb des Providers zur Verfügung. Ihre Payloads
findest du unter [Events](/docs/api/events).

## Slot `#overlay` {#slot-overlay}

Rendert, was dem Zeiger folgt, für jeden Drag ohne eigene Overlay-Komponente (siehe den Leitfaden
[Das Overlay](/docs/guides/overlay)). Rendert der Slot nichts, kommt der Klon zum Einsatz.
