## 앱에 프로바이더 하나 {#one-provider-for-the-app}

```vue [App.vue]
<script setup lang="ts">
import { DnDProvider } from '@vue-dnd-kit/core';
</script>

<template>
  <DnDProvider>
    <RouterView />
  </DnDProvider>
</template>
```

`DnDProvider` 하나를 `App.vue`나 레이아웃처럼 높은 곳에 두고 잊어도 됩니다. 모든 컴포저블
(`makeSortableList`, `makeDraggable`, `useDnD`…)은 자신이 실행되는 컴포넌트 위에서 가장 가까운
프로바이더를 찾습니다.

::warning
컴포저블은 프로바이더 **안에서 렌더링되는** 컴포넌트에서 실행되어야 합니다. 자기 템플릿에
`<DnDProvider>`를 포함한 컴포넌트에서 호출하면 `No <DnDProvider> found above this component`
에러가 발생합니다. Vue의 `inject`는 조상만 볼 수 있기 때문입니다.
::

## 프로바이더가 맡는 일 {#what-it-owns}

| 부분 | 프로바이더가 하는 일 |
| --- | --- |
| 입력 | 포인터, 터치, 키보드 입력을 드래그로 바꿉니다(`sensors`). 드래그는 한 번에 하나뿐입니다. |
| 대상 찾기 | 드래그 아래에 있는 드롭 대상을 히트 테스트하고(`collision`) 해당 대상에 알립니다. |
| 오버레이 | 포인터를 따라다니는 박스를 `body`로 텔레포트해 렌더링하고, 드롭하면 안착시킵니다. |
| 선택 | 그 아래 모든 리스트와 draggable이 공유하는 선택된 id 집합 하나. |
| 자동 스크롤 | 드래그가 컨테이너나 창의 가장자리에 다가가면 스크롤합니다. |
| 라이브 리전 | 집기, 이동, 드롭, 취소를 스크린 리더에 안내합니다. |

그 밖에는 아무것도 렌더링하지 않습니다. 마크업은 그대로 유지됩니다.

## 옵션 한눈에 보기 {#options-at-a-glance}

모든 옵션에는 잘 동작하는 기본값이 있어서, 프로바이더에는 보통 아무 옵션도 주지 않습니다.

| Prop | 기본값 | 설정하는 것 |
| --- | --- | --- |
| `collision` | `pointerFirst` | 드래그 아래의 대상을 고르는 방법. |
| `modifiers` | `[]` | 모든 드래그에 적용할 이동 규칙(스냅, 제한, …). |
| `animation` / `dropAnimation` | 켜짐 | 정렬 중 항목이 미끄러지는 애니메이션 / 오버레이가 안착하는 애니메이션. |
| `animate` | 꺼짐 | 리스트와 트리의 기본값: 드래그가 아닌 데이터 변경을 애니메이션합니다. |
| `autoScroll` | 켜짐 | 가장자리 스크롤: `{ threshold, maxSpeed, acceleration }` 또는 `false`. |
| `activation` | 마우스 4 px, 터치 200 ms | 누르기가 드래그가 되는 시점(포인터 종류별). |
| `keyboard` | Space / Enter, Escape | 키보드 키와 이동 간격. `false`면 키보드 드래그를 끕니다. |
| `sensors` | 포인터 + 키보드 | 입력을 드래그로 바꾸는 것. |
| `haptics` | 터치로 집을 때 짧은 진동 | 터치 드래그의 진동, 또는 `false`. |
| `copyModifier` | `'Alt'` | 드래그 중에 누르고 있으면 이동을 복사로 바꾸는 키(리스트에 `clone`이 필요합니다). |
| `overlayTo` | `'body'` | 오버레이를 텔레포트할 위치. |
| `overlayFit` | `'slot'` | 오버레이 크기: 안착할 자리의 크기, 또는 원본의 크기. |
| `announcements` | 내장 | 스크린 리더용 문구, 또는 `false`. |
| `defaultStyles` | `true` | 드래그 상태용 명시도 0인 CSS를 주입합니다. |

```vue
<DnDProvider
  :activation="{ touch: { delay: 300, tolerance: 8 } }"
  :auto-scroll="{ maxSpeed: 15 }"
  overlay-fit="source"
  @drag-end="save"
>
  <App />
</DnDProvider>
```

모든 형태를 포함한 전체 목록은 [DnDProvider API](/docs/api/dnd-provider)에 있습니다. 프로바이더는
`drag-start`, `drag-move`, `drag-over`, `drag-end`, `drag-cancel` 이벤트도 내보냅니다.
`useDnDMonitor`가 받는 것과 같은 이벤트입니다.

::tip
페이지 일부에만 적용할 규칙(스냅하는 보드, 세로로만 스크롤하는 피드)에는 별도의 프로바이더가
필요 없습니다. 그 부분을 [드래그 영역](/docs/guides/constraints)으로 감싸세요.
::

## 드래그 읽기: `useDnD()` {#read-the-drag-usednd}

::example{name="provider-state" hint="작업을 드래그하며 상태를 확인하세요" height="22rem"}
::

`useDnD()`는 프로바이더 아래의 어떤 컴포넌트에서든 드래그를 반응형 상태로 반환합니다:

```ts
import { useDnD } from '@vue-dnd-kit/core';

const { status, active, over, pointer, activation, isAutoScrolling, selection, cancel } = useDnD();
```

| 필드 | 담긴 값 |
| --- | --- |
| `status` | `'idle'`, `'activating'`(길게 누르기 충전 중), `'dragging'`, `'dropping'`(안착 중이거나 비동기 `onBeforeDrop`을 기다리는 중), `'selecting'`(선택 사각형). |
| `active` | 드래그 중인 것: `id`, `ids`(드래그 중인 모든 id, 집은 항목이 맨 앞), `items`, `data`, `type`, `element`, `rect`, `sensor`. 유휴 상태에서는 `null`. |
| `over` | 드래그 아래의 대상: `id`, `data`, `element`, `rect`, `accepted`. 아무것도 없으면 `null`. |
| `pointer` | 모디파이어 적용 후의 뷰포트 좌표 기준 포인터. |
| `activation.progress` | 길게 누르기가 충전되는 동안 `0`에서 `1`까지: 이 값으로 링을 그리세요. |
| `isAutoScrolling` | 자동 스크롤이 무언가를 움직이는 중입니다. |
| `selection` | 프로바이더의 선택: `ids`, `has`, `add`, `delete`, `toggle`, `set`, `clear`. [멀티 드래그](/docs/guides/multi-drag)를 참고하세요. |
| `cancel()` | 진행 중인 드래그(항목은 원래 자리로 돌아갑니다), 충전 중인 길게 누르기, 선택 사각형을 취소합니다. |

```vue [DropHint.vue]
<script setup lang="ts">
import { computed } from 'vue';
import { useDnD } from '@vue-dnd-kit/core';

const { status, over } = useDnD();
const refused = computed(() => status.value === 'dragging' && over.value?.accepted === false);
</script>

<template>
  <p v-if="refused" role="status">This list doesn't take that.</p>
</template>
```

드롭이 결정되는 순간 `active`, `over`, `pointer`는 `null`이 됩니다. 오버레이가 아직 안착하는
중이어도 마찬가지입니다(`status`는 `'dropping'`으로 유지됩니다). 그래서 이 값들에서 파생된 UI는
새 데이터 옆에 이전 드래그를 표시하지 않습니다. 비동기 `onBeforeDrop`이 기다리는 동안에는 상태가
놓은 순간 그대로 유지됩니다.

## 모든 드래그 듣기: `useDnDMonitor()` {#listen-to-every-drag-usedndmonitor}

```ts
import { useDnDMonitor } from '@vue-dnd-kit/core';

useDnDMonitor({
  onDragStart: ({ active }) => {},
  onDragMove: ({ pointer, delta }) => {},
  onDragOver: ({ over }) => {},                  // the target changed
  onBeforeDrop: (e) => 'accept',                 // or 'reject', 'continue', some ids; may be async
  onDragEnd: ({ active, over, dropped, accepted, position }) => {},
  onDragCancel: ({ active }) => {},
  onDragResume: ({ active }) => {},              // onBeforeDrop answered 'continue'
});
```

모니터는 어디서 시작했든 프로바이더 아래의 모든 드래그를 듣습니다. 호출한 컴포넌트가 언마운트되면
멈춥니다.

| 이벤트 | 시점 |
| --- | --- |
| `onDragStart` | 드래그가 시작될 때. |
| `onDragMove` | 드래그가 움직일 때. |
| `onDragOver` | 드래그 아래의 대상이 바뀔 때. |
| `onBeforeDrop` | 드래그를 놓았을 때. 이 응답이 드롭을 결정합니다. [드롭 결정](/docs/guides/drop-decisions)을 참고하세요. |
| `onDragEnd` | 드롭이 완료되었을 때. 정렬 가능한 리스트는 이미 `onDrop`을 실행하고 새 순서를 기록했습니다. 대상이 없는 곳에서 끝나면 `dropped`는 `false`입니다. |
| `onDragCancel` | Escape, 드롭을 거부하는 대상에 드롭, 또는 `onBeforeDrop`이 `'reject'`로 응답했을 때. |
| `onDragResume` | `onBeforeDrop`이 `'continue'`로 응답했을 때: 드롭되지 않고 드래그가 계속됩니다. |

모든 이벤트에는 `active`, `over`, `pointer`, `delta`(시작점으로부터의 오프셋),
`position`(드래그 중인 박스가 `over` 안에서 놓인 위치,
[드래그 앤 드롭](/docs/guides/drag-and-drop#leave-it-where-it-was-dropped) 참고)이 들어 있고,
정렬 가능한 리스트에서 온 항목이라면 `source`도 들어 있습니다. 전체 형태는
[이벤트 API](/docs/api/events)에 있습니다.

::note
`onDragEnd`는 "드롭 이후" 작업을 하는 곳입니다. 저장, 선택 해제, 분석 등이 여기에 해당합니다.
리스트 자체의 `onDrop`은 기록 **전에** 실행되므로 아직 이전 순서를 봅니다.
::

## 여러 프로바이더 {#several-providers}

대부분의 앱에는 정확히 하나만 필요합니다. 두 번째 프로바이더는 프로바이더 전체 설정(충돌 감지,
키보드 키, 안내 문구)이 따로 필요하고 그 항목이 밖으로 나가지 않는 페이지 일부에만 의미가 있습니다:

- 프로바이더끼리는 독립적입니다. 드래그는 한 프로바이더에서 다른 프로바이더로 넘어가지 않습니다.
- 프로바이더를 중첩할 수 있습니다. **가장 가까운 소유자가 우선합니다**: 항목은 자신 바로 위의
  가장 가까운 프로바이더에 속하고, 바깥 프로바이더는 그 항목을 무시합니다.
- 각 프로바이더에는 자체 선택, 오버레이, 라이브 리전이 있습니다.

페이지의 두 부분 사이에서 항목이 이동하지 않는다면, 두 부분이 서로 다른 프로바이더 아래에 있지
않은지 확인하세요.

::tip
다른 곳에 마운트된 앱(shadow root 안이나 별도의 Vue 앱)도 기존 프로바이더에 참여할 수 있습니다.
마운트하기 전에 `useDnDContext()`를 `provideDnDContext(app, context)`에 넘기세요.
::

## SSR과 Nuxt {#ssr-and-nuxt}

프로바이더는 SSR에서 안전합니다. 리스트와 항목은 다른 마크업처럼 서버에서 렌더링됩니다. 오버레이와
라이브 리전은 텔레포트되어 클라이언트에서만 마운트되므로 하이드레이션 불일치를 일으키지 않습니다.
기본 id는 Vue의 `useId()`에서 오며 서버와 클라이언트에서 일치합니다.

Nuxt에서는 모듈이 `DnDProvider`를 전역으로 등록하고 컴포저블을 자동 임포트합니다.
[설치](/docs/getting-started/installation#nuxt)를 참고하세요.
