센서는 입력을 드래그로 바꿉니다. 센서가 프로바이더에 알리는 것은 "이 항목을 여기서부터
드래그해", 그다음 입력이 어디로 움직였는지, 그리고 드롭했는지 취소했는지뿐입니다. 나머지는
프로바이더가 모든 센서에 똑같이 처리합니다. 한 번에 하나의 드래그, 비활성 항목 거부, 활성화 조건,
정렬, 자동 스크롤, 안내 문구, :kbd{value="Escape"}, 그리고 드롭 전체입니다.

## 내장 센서 {#the-built-in-sensors}

| 센서 | 입력 |
| --- | --- |
| `pointerSensor` | Pointer Events를 통한 마우스, 터치, 펜. 포인터를 캡처하고, 터치 드래그 중에 페이지가 텍스트를 선택하거나 스크롤하지 않게 하며, 드래그 뒤에 따라오는 클릭을 삼킵니다. |
| `keyboardSensor` | :kbd{value="Space"}와 :kbd{value="Enter"}로 집고 드롭하고, 화살표 키로 옮기고, :kbd{value="Escape"}로 취소합니다. 포인터 드래그를 포함한 모든 드래그에 적용됩니다. |

둘 다 기본으로 실행됩니다. 프로바이더의 `sensors`가 이 목록을 대체합니다:

```vue
<script setup lang="ts">
import { DnDProvider, keyboardSensor, pointerSensor } from '@vue-dnd-kit/core';
import { joystick } from './joystick';
</script>

<template>
  <DnDProvider :sensors="[pointerSensor, keyboardSensor, joystick.sensor]">
    <App />
  </DnDProvider>
</template>
```

키보드 드래그를 끄려면 `keyboardSensor`를 빼기보다 `:keyboard="false"`를 쓰세요. 키보드 센서는
:kbd{value="Escape"}로 모든 드래그를 취소하는 역할도 합니다. 키는 `keyboard.keys`로 다시 지정합니다
([접근성](/docs/guides/accessibility#the-keyboard) 참고).

## 활성화 조건 {#activation-constraints}

누르기는 조건을 충족하면 드래그가 됩니다:

| 포인터 | 기본값 |
| --- | --- |
| 마우스 | 4 px 움직인 뒤. `handle`을 누르면 바로 시작하며, 마우스에 대한 조건을 지정하면 예외입니다. |
| 펜 | 4 px 움직인 뒤. |
| 터치 | 200 ms 동안 누른 뒤. 그 전에 5 px 넘게 움직이면 중단되고 대신 페이지가 스크롤됩니다. |

조건에는 세 가지 필드가 있습니다:

| 필드 | 의미 |
| --- | --- |
| `distance` | 포인터가 이동해야 하는 픽셀 수. |
| `delay` | 누르기가 지속되어야 하는 밀리초. 둘 다 지정하면 먼저 충족되는 쪽이 드래그를 시작합니다. |
| `tolerance` | `delay`와 함께: 기다리는 동안 포인터가 움직여도 되는 거리. 넘어가면 누르기를 포기합니다. |

포인터 종류(`mouse`, `touch`, `pen`)별로 프로바이더, 드래그 영역, 항목 자체에 지정합니다. 항목 자체의
설정이 우선하고, 그다음 영역, 그다음 프로바이더입니다:

```ts
makeSortableItem(el, { item: () => props.task, activation: { touch: { delay: 300, tolerance: 8 } } });
```

```vue
<DnDProvider :activation="{ mouse: { distance: 8 }, touch: { delay: 250, tolerance: 5 } }">
```

핸들에서 터치로 바로 드래그하려면 핸들에 `touch-action: none`을 지정하고(브라우저가 스크롤하지
않도록), 항목에 `activation: { touch: { distance: 4 } }`를 지정하세요.

### 길게 누르기 링 {#a-long-press-ring}

누르기가 기다리는 동안 `useDnD().status`는 `'activating'`이고, `activation.progress`는 0에서 1로
올라갑니다:

```vue [PressRing.vue]
<script setup lang="ts">
import { useDnD } from '@vue-dnd-kit/core';

const { status, activation: { progress } } = useDnD();
</script>

<template>
  <svg v-if="status === 'activating'" class="ring" viewBox="0 0 36 36">
    <circle cx="18" cy="18" r="16" pathLength="1" :stroke-dasharray="`${progress} 1`" />
  </svg>
</template>
```

### 일부 누르기만 허용하기 {#only-some-presses}

`canDrag`는 draggable과 정렬 가능한 항목에 두는 관문 하나를 더합니다. 입력 이벤트를 받습니다:

```ts
// Pointer drags only while Alt is held; keyboard drags as usual.
makeDraggable(el, { canDrag: (event) => event instanceof KeyboardEvent || event.altKey });
```

버튼, 입력 필드, 편집 가능한 필드 같은 상호작용 자식 요소는 포인터 드래그를 시작하지 않으므로,
draggable 안에서도 그대로 동작합니다. `handle`이 있으면 핸들만 드래그를 시작합니다.

## 직접 만드는 센서 {#a-sensor-of-your-own}

게임패드, 화면 위 조이스틱, 음성 명령처럼 항목을 가리키고 움직일 수 있는 것이라면 무엇이든 드래그를
조종할 수 있습니다. 다음은 커서 아래의 항목을 300 ms 누르고 있으면 집는 조이스틱입니다:

```ts [joystick.ts]
import { shallowRef } from 'vue';
import { defineSensor, type Coordinates, type SensorContext, type SensorDrag } from '@vue-dnd-kit/core';

export function createJoystick() {
  const cursor = shallowRef<Coordinates>({ x: 0, y: 0 });
  let context: SensorContext | null = null;
  let drag: SensorDrag | null = null;

  const sensor = defineSensor({
    name: 'joystick', // shows in the DevTools log
    // Runs once per provider, in the browser, in an effect scope: VueUse listeners made
    // here are removed with it. Return a cleanup if you need one.
    setup(ctx) {
      context = ctx;
      return () => {
        context = null;
        drag = null;
      };
    },
  });

  /** "A": drops a running drag, or picks up what is under the cursor after a hold. */
  const press = () => {
    if (drag?.state === 'dragging') return void drag.drop();
    const target = document.elementFromPoint(cursor.value.x, cursor.value.y);
    if (!target || !context) return;
    drag = context.activate({
      target, // an element inside a draggable, or a draggable's id
      point: cursor.value, // where the drag starts, in viewport coordinates
      activation: { delay: 300 }, // or 'mouse' | 'touch' | 'pen' for the configured one
      type: 'pointer', // follows points; 'keyboard' moves by items
      onEnd: (ended) => {
        if (drag === ended) drag = null;
      },
      // onBeforeDrop answered 'continue': the drag goes on, and its calls apply again.
      onResume: (resumed) => {
        drag = resumed;
      },
    }); // null: refused (another drag runs, the item is disabled, a button inside it…)
  };

  const move = (dx: number, dy: number) => {
    cursor.value = { x: cursor.value.x + dx, y: cursor.value.y + dy };
    drag?.move(cursor.value); // pending: checks the tolerance; dragging: moves
  };

  const cancel = () => drag?.cancel();

  return { sensor, cursor, press, move, cancel };
}

export const joystick = createJoystick();
```

프로바이더의 `sensors`에 추가하거나, `useSensor(joystick.sensor)`로 컴포넌트가 살아 있는 동안
실행하세요.

### 센서가 받는 것 {#what-the-sensor-gets}

`setup(context)`는 프로바이더 쪽 정보를 받습니다:

| 멤버 | 설명 |
| --- | --- |
| `props` | 프로바이더의 props(`activation`, `keyboard`…). 바뀔 수 있으므로 필요할 때 읽으세요. |
| `status` | 어떤 센서가 드래그를 진행하든, 프로바이더의 드래그 상태. |
| `drag` | 어떤 센서가 시작했든, 대기 중이거나 진행 중인 프로바이더의 현재 드래그. 없으면 `null`. |
| `activate(options)` | 드래그를 요청합니다. `SensorDrag`를 반환하며, 드래그를 시작할 수 없으면 `null`을 반환합니다. |
| `cancel()` | 프로바이더의 드래그나 대기 중인 누르기를 취소합니다. |

`activate()`가 받는 옵션:

| 옵션 | 의미 |
| --- | --- |
| `target` | 입력이 닿은 곳: draggable 안의 요소, 또는 draggable의 id. 요소는 실제 누르기처럼 검사하고(핸들, 상호작용 자식 요소가 아님), id는 검사를 건너뜁니다. |
| `point` | 드래그가 시작되는 위치(뷰포트 좌표). 기본값: draggable의 중앙. |
| `type` | `'pointer'`(기본값): 지점을 따라가고, 대상을 히트 테스트하고, 자동 스크롤합니다. `'keyboard'`: 항목 단위로 움직이고, 대상이 보이게 하고, 끝나면 포커스를 되돌립니다. |
| `activation` | 조건(`{ delay: 300 }`), 또는 설정된 조건을 쓸 포인터 종류(`'touch'`). 기본값: 없음, 드래그가 바로 시작됩니다. |
| `event` | 입력 이벤트. 항목의 `canDrag`에 전달됩니다. 터치 `pointerType`이면 터치 드래그(진동)가 됩니다. |
| `onStart(drag)` | 활성화 후 드래그가 시작되었습니다. |
| `onEnd(drag)` | 드래그가 끝났습니다. 누가 했든 중단, 드롭, 취소된 경우입니다. |
| `onResume(drag)` | `onBeforeDrop`이 `'continue'`로 응답했습니다. 드래그가 계속되며 `move`, `drop`, `cancel`을 다시 쓸 수 있습니다. |

반환되는 `SensorDrag`:

| 멤버 | 하는 일 |
| --- | --- |
| `id`, `type` | 드래그 중인 항목의 id, 그리고 `'pointer'` 또는 `'keyboard'`. |
| `state` | `'pending'`(활성화 대기 중), `'dragging'`, 그다음 `'ended'`. |
| `started` | 드래그가 시작되었습니다. 이후 끝났더라도 마찬가지입니다. |
| `move(point)` | 입력이 움직였습니다. 대기 중에는 허용 범위를 검사하고, 드래그 중에는 드래그를 옮깁니다. |
| `step(direction)` | 키보드 드래그: 화살표 한 단계, `'up' \| 'down' \| 'left' \| 'right'`. |
| `place({ list, index })` | 키보드 이동처럼 항목을 정렬 가능한 리스트의 특정 위치에 놓습니다. 그 위치에서 받아들이는 리스트가 없으면 `false`로 resolve됩니다. |
| `drop()` | 드롭합니다. 안착한 뒤, 드롭이 완료되었으면 `true`로 resolve됩니다. |
| `cancel()` | 취소합니다. 항목은 원래 자리로 돌아가거나, 대기 중인 누르기를 포기합니다. |

더 이상 적용되지 않는 호출(끝난 뒤의 이동, 두 번째 `drop()`)은 무시됩니다. 전체 타입:
[센서](/docs/api/sensors).

::tip
내장 센서를 감싸려면 직접 만든 컨텍스트로 그 센서의 `setup`을 실행하세요. 컨텍스트는 스프레드가
아니라 `Object.create(context, { activate: { value: myActivate } })`로 만들어야 실시간 getter
(`status`, `drag`, `props`)가 계속 동작합니다.
::

## 프로그래밍 방식 드래그 {#programmatic-drags}

`@vue-dnd-kit/actions`는 코드로 항목을 옮깁니다. "위로 이동" 버튼, 메뉴, 키보드 단축키, 실행 취소,
온보딩 투어, 테스트에 씁니다. 공개 센서 API 위에 만들어졌고, 드래그는 진짜 드래그입니다. 안내되고
애니메이션되며, `onBeforeDrop`, `onDrop`, `e.result`, `preventDefault()`를 거치고, 프로바이더의 규칙
(한 번에 하나의 드래그, 비활성 항목, `accept`와 `group.put`)을 따릅니다.

```bash
npm i @vue-dnd-kit/actions
```

### moveItem: 한 번 호출로 한 번 이동 {#moveitem-one-call-one-move}

```ts
import { useDnDActions } from '@vue-dnd-kit/actions';

const { moveItem } = useDnDActions(); // in setup, under a provider

await moveItem('card-1', { index: 0 }); // to the top of its list
await moveItem('card-1', { list: 'done' }); // to the end of another list
await moveItem('card-1', { list: 'done', index: 2 }); // to a place in another list
```

- `list`는 정렬 가능한 리스트의 `id`입니다. 생략하면 항목은 자기 리스트에 남습니다.
- `index`는 항목이 놓일 위치로, 항목 자신을 빼고 세며 리스트 범위로 제한됩니다. 생략하면 끝으로
  갑니다.
- 드롭이 완료되면 `true`로, 항목이 렌더링되지 않았거나 비활성이거나, 그 위치에서 받아들이는
  리스트가 없거나, 드롭이 거부되면 `false`로 resolve됩니다.
- 호출은 대기열에 쌓입니다. 각 호출은 프로바이더가 유휴 상태가 될 때까지 기다리므로, 빠르게
  두 번 클릭해도 두 번째가 사라지지 않습니다.
- 키보드 드래그로 실행되므로 안내 문구가 나오고 포커스가 항목에 남습니다.
- 리스트 전용입니다. 트리의 위치에는 깊이도 있기 때문입니다.

이동 버튼이 있는 행은 [접근성](/docs/guides/accessibility#moving-without-dragging)을 참고하세요.

### startDrag: 스크립트로 하는 드래그 {#startdrag-a-scripted-drag}

```ts
const { startDrag } = useDnDActions();

const drag = startDrag('card-1'); // null when it can't start now
if (drag) {
  await drag.moveTo(document.querySelector('#trash')!); // onto an element
  await drag.moveTo({ x: 400, y: 120 }); // to a point, in viewport coordinates
  await drag.moveTo({ list: 'done', index: 2 }); // to a list position
  await drag.drop(); // true when the drop went through; or drag.cancel()
}
```

`moveTo`는 이동이 렌더링되면, `drop`은 드롭이 안착하면 resolve됩니다.
`startDrag(id, { type: 'keyboard' })`는 대신 항목 단위로 움직이며(`await drag.step('down')`),
키보드 센서가 이어받을 수 있습니다. 항목을 화살표 키에 넘기는 "이동" 메뉴 항목 같은 경우입니다.

### 컴포넌트 밖에서 {#outside-components}

`useDnDActions()`는 위쪽 프로바이더에서 `actions`라는 센서 하나를 실행합니다. 스토어나 테스트
하네스에서, 또는 원하는 이름으로 프로바이더를 조종하려면 직접 실행하는 센서 안에서 액션을 만드세요:

```ts
import { defineSensor } from '@vue-dnd-kit/core';
import { createDnDActions, type DnDActions } from '@vue-dnd-kit/actions';

export let tour: DnDActions | undefined;
export const tourSensor = defineSensor({
  name: 'tour',
  setup: (context) => void (tour = createDnDActions(context)),
});
```

```vue
<DnDProvider :sensors="[pointerSensor, keyboardSensor, tourSensor]">
```

그러면 어디서든 `await tour?.moveItem('card-1', { list: 'done' })`를 쓸 수 있습니다. 서버 렌더링
중에는 아무것도 드래그되지 않습니다. `moveItem`은 `false`로 resolve되고 `startDrag`는 `null`을
반환합니다.
