이 페이지의 모든 기능은 기본으로 켜져 있습니다. Tab으로 트랙의 그립에 이동해 :kbd{value="Space"}를
누르고, 화살표 키로 옮긴 다음 :kbd{value="Space"}를 다시 누르세요. 원래대로 되돌리려면
:kbd{value="Escape"}를 누르세요.

::example{name="lists" hint="Tab으로 그립에 이동, Space, 화살표 키, Space" height="28rem"}
::

보통 직접 해야 하는 일은 항목에 읽기 쉬운 이름을 붙이는 것, 그리고 드래그를 전혀 할 수 없는
사람을 위해 항목을 옮기는 버튼을 두는 것입니다.

## 키보드 {#the-keyboard}

| 키 | 동작 |
| --- | --- |
| :kbd{value="Space"} / :kbd{value="Enter"} | 포커스된 항목을 집습니다. 다시 누르면 드롭합니다. |
| 화살표 키 | 항목을 옮깁니다. 리스트에서는 자리 단위로, 트리에서는 행과 깊이 단위로, 자유 드래그에서는 `keyboard.step` 픽셀씩 움직입니다. |
| :kbd{value="Escape"} | 드래그를 취소합니다. 포인터 드래그도 취소합니다. |

- 리스트에서 같은 그룹의 다른 리스트 쪽 화살표 키를 누르면 항목이 그 리스트로 옮겨 갑니다.
- 자유 드래그에서는 :kbd{value="Shift"}를 누르면 이동 간격이 커집니다.
  `makeDraggable(el, { keyboard: 'droppables' })`를 쓰면 화살표 키가 대신 항목을 받아들이는 대상
  사이를 건너뜁니다.
- 키보드 드래그는 포커스된 draggable이나 그 핸들에서 시작합니다. 그 안의 버튼이나 입력 필드에서는
  시작하지 않으므로, 그것들은 자기 키를 그대로 씁니다.
- 키보드 드래그는 가장자리에서 자동 스크롤하는 대신 대상이 보이도록 스크롤합니다.
- 드롭 후에는 항목의 행이 다른 리스트에서 다시 렌더링되더라도 포커스가 그 항목으로 돌아갑니다.

### 다른 키 사용하기 {#other-keys}

```vue
<DnDProvider :keyboard="{ keys: { start: ['KeyD'], drop: ['KeyD', 'Enter'], cancel: ['Escape'] }, step: 10 }">
```

키 바인딩은 `event.code`(`'Space'`, `'KeyD'`) 또는 `event.key`(`'Enter'`)와 비교합니다. `step`은
자유 드래그에서 화살표 키를 한 번 누를 때 움직이는 픽셀 수입니다(기본값 25). `:keyboard="false"`는
키보드 드래그를 끄며, 이때도 :kbd{value="Escape"}는 모든 드래그를 취소합니다. 키를 바꾸면
`screen-reader-instructions`도 함께 바꾸세요.

## ARIA 속성 {#aria-attributes}

모든 draggable과 정렬 가능한 항목은 다음 속성을 받습니다. 단, **직접 설정한 속성은 덮어쓰지
않습니다**:

| 속성 | 값 |
| --- | --- |
| `tabindex` | 요소가 아직 포커스할 수 없을 때 `0`. |
| `role` | `button`. 이미 버튼인 `<button>`에는 설정하지 않습니다. |
| `aria-roledescription` | `draggable`, 정렬 가능한 항목에는 `sortable`. |
| `aria-describedby` | 프로바이더의 안내 지침. 이미 있는 id 옆에 추가됩니다(툴팁의 id도 유지됩니다). |
| `aria-disabled` | `true` 또는 `false`: 항목이 비활성 상태인지(비활성 드래그 영역에 의한 경우 포함). |
| `aria-pressed` | 드래그되는 동안 `true`. |

`attributes: false`를 쓰면 해당 항목에서 이 속성들을 끄고, 라이브러리가 설정했던 속성은 제거됩니다.

### 핸들: 진짜 버튼으로 만들기 {#handles-make-them-real-buttons}

```vue [Track.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';

const props = defineProps<{ track: { id: string; title: string } }>();
const el = useTemplateRef<HTMLElement>('el');
makeSortableItem(el, { item: () => props.track, handle: '.grip' });
</script>

<template>
  <li ref="el" class="track">
    {{ track.title }}
    <button type="button" class="grip" :aria-label="`Move ${track.title}`">⠿</button>
  </li>
</template>
```

`handle`이 있으면 속성은 핸들에 설정되고, 키보드 드래그도 핸들에서 시작합니다. `<button>`은 이미
포커스할 수 있는 버튼이므로 `tabindex`나 `role`이 필요 없습니다. `aria-label`을 지정하세요. 그립
아이콘에는 자체 이름이 없고, "Move Midnight Drive"는 "버튼"보다 훨씬 많은 것을 알려 줍니다.

## 안내 문구 {#announcements}

프로바이더의 라이브 리전이 집기, 이동, 드롭, 취소를 모두 읽어 줍니다. 정렬 가능한 리스트는 항목의
위치를 알려 줍니다: *"Picked up item t2 at position 2 of 5 in list playlist."* 이동은 드래그가
500 ms 동안 멈춰 있으면 읽어 줍니다.

문구에는 id가 쓰입니다. 항목에 읽기 쉬운 id를 주거나, 문구를 직접 작성하세요:

```ts
import type { Announcements, Key } from '@vue-dnd-kit/core';

const title = (id: Key) => tasks.value.find((task) => task.id === id)?.title ?? String(id);

const announcements: Partial<Announcements> = {
  onDragStart: ({ active }) => `Picked up ${title(active.id)}.`,
  onDragEnd: ({ active, dropped }) => (dropped ? `Dropped ${title(active.id)}.` : undefined),
  onDragCancel: ({ active }) => `${title(active.id)} went back to its place.`,
  onDragResume: ({ active }) => `${title(active.id)} was not dropped. It is still moving.`,
};
```

```vue
<DnDProvider :announcements="announcements" screen-reader-instructions="Press D to pick up a card…">
```

- 문구는 해당 이벤트의 안내를 대체합니다. `undefined`는 기본 안내를 유지하고, `''`는 아무것도 읽지
  않습니다. 생략한 이벤트도 기본 안내를 유지합니다. 위 예에서 `onDragOver`의 정렬 리스트 위치
  안내가 그렇습니다.
- `onDragResume`은 `onBeforeDrop`이 `'continue'`로 응답해 드래그가 계속될 때 읽어 줍니다
  ([드롭 결정하기](/docs/guides/drop-decisions) 참고).
- `screenReaderInstructions`는 모든 draggable이 `aria-describedby`로 가리키는 문구입니다.
- `:announcements="false"`는 라이브 리전을 조용하게 만듭니다. 예를 들어 직접 만든 리전으로 안내할
  때 사용합니다.

::note
내장 문구는 영어입니다. 다른 언어를 쓰려면 다섯 가지 문구와 안내 지침을 모두 지정하세요. 생략한
문구는 정렬 리스트의 위치 안내를 포함해 영어로 읽힙니다.
::

## 터치 {#touch}

터치 드래그는 200 ms 동안 길게 누른 뒤에 시작됩니다. 그 전에 5 px 넘게 움직이면 대신 페이지가
스크롤되므로 리스트를 계속 스크롤할 수 있습니다. 두 값은 `activation`으로 조정하고
([센서](/docs/guides/sensors#activation-constraints) 참고), `useDnD().activation.progress`로 길게
누르기 링을 그리세요.

터치 드래그는 시작할 때 짧게 진동합니다. `:haptics="false"`로 끌 수 있고, 객체를 넘기면 대상에
들어갈 때, 드롭할 때, 거부될 때의 진동을 추가합니다:

```vue
<DnDProvider :haptics="{ start: true, enter: 10, drop: 10, refuse: [20, 40, 20] }">
```

터치 드래그만 진동하며, iOS Safari는 진동을 전혀 지원하지 않습니다.

## 동작 줄이기 {#reduced-motion}

`prefers-reduced-motion: reduce`이면 라이브러리 자체 애니메이션은 실행되지 않습니다. 직접 만든
애니메이션 함수는 `reducedMotion: true`와 함께 그대로 실행됩니다.
[애니메이션](/docs/guides/animations)을 참고하세요.

## 드래그 없이 옮기기 {#moving-without-dragging}

드래그를 전혀 할 수 없는 사람도 있습니다. WCAG 2.5.7은 "위로 이동" 버튼처럼 단순한 클릭으로 항목을
옮기는 방법을 요구합니다. `@vue-dnd-kit/actions`는 이런 버튼 하나하나를 실제 이동으로 만듭니다:

```bash
npm i @vue-dnd-kit/actions
```

```vue [TaskRow.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeSortableItem } from '@vue-dnd-kit/core';
import { useDnDActions } from '@vue-dnd-kit/actions';

const props = defineProps<{ task: { id: string; title: string }; count: number }>();
const el = useTemplateRef<HTMLElement>('el');
const { index } = makeSortableItem(el, { item: () => props.task });
const { moveItem } = useDnDActions();
</script>

<template>
  <li ref="el">
    {{ task.title }}
    <button type="button" :disabled="index === 0" @click="moveItem(task.id, { index: index - 1 })">
      Move up
    </button>
    <button type="button" :disabled="index === count - 1" @click="moveItem(task.id, { index: index + 1 })">
      Move down
    </button>
    <button type="button" @click="moveItem(task.id, { list: 'done' })">Move to Done</button>
  </li>
</template>
```

`moveItem`은 키보드 드래그를 처음부터 끝까지 실행합니다. 안내 문구가 나오고, `onBeforeDrop`과
`onDrop`을 거치며, 애니메이션되고, 포커스를 항목에 유지합니다. 드롭이 완료되면 `true`로
resolve됩니다. `index`는 항목 자신을 뺀 자리를 세므로, "아래로"는 `index + 1`입니다. 자세한 내용은
[센서와 프로그래밍 방식 드래그](/docs/guides/sensors#programmatic-drags)를 참고하세요.
