카드를 **Done**으로 드래그해 보세요. 드롭은 응답을 기다립니다. 카드를 옮기거나, 다른 곳으로 계속
드래그하거나, 취소할 수 있습니다.

::example{name="drop-confirm" hint="카드를 Done으로 드래그하세요" height="24rem"}
::

## onBeforeDrop {#onbeforedrop}

```ts
makeSortableList(listRef, {
  items: tasks,
  onBeforeDrop: (e) => (e.items.some((task) => task.locked) ? 'reject' : 'accept'),
});
```

리스트, 트리, 드롭 대상(`makeDroppable`), 모니터(`useDnDMonitor`)는 `onBeforeDrop`을 받습니다.
드래그를 놓을 때, 무엇이든 바뀌기 전에 실행되며, 그 응답이 다음을 결정합니다:

| 응답 | 결과 |
| --- | --- |
| `'accept'`, `true`, 또는 아무것도 반환하지 않음 | 드롭이 완료됩니다. |
| `'reject'` 또는 `false` | 드롭하지 않습니다. 항목은 원래 자리로 돌아갑니다. 에러가 발생해도 거부됩니다. |
| key 배열 | 해당 항목만 드롭되고, 나머지는 원래 자리로 돌아갑니다. |
| `'continue'` | 드롭하지 않고 드래그가 계속됩니다. |
| 위 값 중 하나를 담은 Promise | Promise가 처리될 때까지 오버레이가 놓은 자리에서 기다립니다. |

대상 자체의 규칙이 먼저입니다. 드롭 대상의 `accept`, 리스트의 `group.put`이 그렇습니다. 드래그를
거부하는 대상 위에서는 드롭이 취소되며, 그 대상의 `onBeforeDrop`은 호출되지 않습니다.
`onBeforeDrop`은 그런 규칙이 알 수 없는 것을 위한 곳입니다. 사용자의 응답, 서버의 응답, 또는 드롭이
바꿀 내용입니다.

리스트와 트리는 `SortableDropEvent`를 넘깁니다: `keys`, `items`, `from`, `to`, `mode`, `sameList`,
그리고 드롭으로 바뀌는 모든 리스트의 새 배열인 `result`입니다. 드롭 대상과 모니터는 일반적인
`DnDEvent`를 받습니다: `active`, `over`, `position`, `source`. [이벤트](/docs/api/events)를
참고하세요.

### 일부 항목만 수락하기 {#accepting-some-of-the-items}

```ts
onBeforeDrop: (e) => e.items.filter((task) => !task.locked).map((task) => task.id),
```

[멀티 드래그](/docs/guides/multi-drag)에서는 반환한 key의 항목이 안착하고, 나머지는 원래 있던 곳으로
돌아갑니다. 그러면 `onDrop`은 그 항목들을 `e.accepted`와 `e.rejected`에서 보며, `onDrop`의
`e.result`는 최종 결과입니다.

## 드래그 계속하기: 'continue' {#keep-dragging-continue}

`'continue'`는 드래그가 아니라 드롭을 취소합니다. 항목은 그 자리에서 계속 손에 들린 상태가 되고,
페이지는 드래그 모드로 돌아가며, 사용자는 하던 일을 이어 갑니다:

- 마우스나 펜에서는 버튼을 누르지 않아도 항목이 포인터를 따라갑니다. 다음에 놓는 동작, 즉 클릭이
  항목을 드롭하며, 그 클릭은 아래의 페이지에 전달되지 않습니다.
- 터치에서는 손가락이 닿는 곳에서 항목을 다시 집고, 손가락을 떼면 드롭합니다.
- 키보드 드래그는 계속됩니다. 화살표 키로 항목을 옮기고 :kbd{value="Space"} 또는
  :kbd{value="Enter"}로 드롭합니다.
- 다른 드래그와 마찬가지로 :kbd{value="Escape"}로 취소합니다.
- 다음 드롭에서 `onBeforeDrop`을 다시 호출합니다.

모니터는 `onDragResume`을 받고, 스크린 리더는 항목이 드롭되지 않았으며 아직 이동 중이라는 안내를
듣습니다(문구는 프로바이더의 `announcements.onDragResume`으로 바꿀 수 있습니다).

```ts
useDnDMonitor({
  onDragResume() {
    hint.value = 'Still dragging: click to drop, Esc to cancel';
  },
});
```

## 사용자에게 묻기 {#asking-the-user}

`onBeforeDrop`은 Promise를 반환할 수 있습니다. 다이얼로그를 열고, 사용자가 고른 버튼으로 Promise를
resolve하세요:

```ts [Column.vue]
const { items } = makeSortableList(list, {
  id: props.column.id,
  items: toRef(props.column, 'tasks'),
  group: 'release',
  onBeforeDrop: (e) => (props.column.confirm && !e.sameList ? props.ask(e) : 'accept'),
});
```

```ts [Board.vue]
type Answer = 'accept' | 'continue' | 'reject';
const question = shallowRef<{ title: string; resolve: (answer: Answer) => void } | null>(null);

/** Opens the dialog: `onBeforeDrop` waits for the button the user picks. */
const ask = (e: SortableDropEvent<Task>) =>
  new Promise<Answer>((resolve) => {
    question.value = { title: e.items[0]!.title, resolve };
  });
```

Promise가 대기 중인 동안:

- 오버레이는 놓은 자리에서 `data-dnd-overlay="dropping"` 표시를 단 채 기다립니다.
- `useDnD()`는 놓은 순간의 상태를 유지하고, `status`는 `'dropping'`입니다.
- 페이지는 드래그 모드에서 벗어납니다. 커서와 텍스트 선택이 돌아오므로 다이얼로그가 평소처럼
  동작합니다.

::tip
`showModal()`로 연 모달 `<dialog>`는 top layer에 놓이므로 기다리는 오버레이보다 위에 표시됩니다.
예제처럼 `cancel` 이벤트(:kbd{value="Escape"})를 `'reject'`로 바꾸세요.
::

## 훅의 순서 {#the-order-of-the-hooks}

1. 각 `useDnDMonitor`의 `onBeforeDrop`이 차례로 실행됩니다. `'reject'`나 `'continue'`가 나오면 묻기를
   끝내고, key를 반환하면 드롭 범위를 좁힙니다.
2. 대상의 `onBeforeDrop`: 항목이 들어갈 리스트나 트리, 또는 드롭 대상.
3. 대상의 `onDrop`만 실행됩니다. 항목이 다른 리스트로 떠나는 리스트에는 묻지 않으며, 그 리스트의 새
   배열은 대상의 `e.result`에 들어 있습니다. 항목이 제거될 때(휴지통 영역,
   `dropOutside: 'remove'`)는 그 항목이 속한 리스트의 `onDrop`이 `to.index`가 `-1`인 상태로
   실행됩니다.
4. 기본 기록: 드롭으로 바뀌는 각 리스트가 새 배열을 받습니다.
5. 오버레이가 안착합니다. 이어서 프로바이더의 `@drag-end`와 모니터의 `onDragEnd`가 실행됩니다.

모니터가 대상보다 먼저 결정하므로, 리스트가 이미 자체 드롭을 적용한 뒤에 거부가 오는 일은 없습니다.

## onDrop: 기록 전에 알림 {#ondrop-told-before-the-write}

```ts
makeSortableList(listRef, {
  items: tasks,
  onDrop: (e) => {
    // `tasks` still holds the old order, `e.result` the new one.
    console.log(e.keys, e.from, e.to, e.result.get(e.to.list));
  },
});
```

리스트의 `onDrop`은 드롭이 수락되면 리스트가 기록하기 직전에 동기적으로 실행됩니다. 기록 후에
작업하려면 프로바이더의 `@drag-end`나 `useDnDMonitor({ onDragEnd })`를 사용하세요. 일반 드롭
대상에서는 `onDrop`이 데이터를 바꾸는 곳입니다. 라이브러리가 대신 옮겨 주는 것은 없습니다.

## 스토어와 서버: 제어 리스트 {#stores-and-servers-controlled-lists}

```ts
const store = useBoardStore();
const { items } = makeSortableList(listRef, {
  id: 'todo',
  group: 'board',
  items: () => store.lists.todo, // a getter: read-only
  onDrop: (e) => {
    e.preventDefault();
    for (const [listId, next] of e.result) store.setList(listId, next);
  },
});
```

라이브러리는 쓰기 가능한 ref에만 드롭을 기록합니다. getter, `computed`, `readonly` ref에는 기록하지
않습니다. `e.preventDefault()`를 호출하고 `e.result`를 직접 적용하세요. `e.result`에는 드롭으로
바뀌는 모든 리스트의 새 배열이 리스트 id별로 들어 있습니다. 일부에만 기록하면 항목이 사라지거나
중복되므로, `preventDefault()`는 모든 리스트에 대한 기록을 건너뜁니다. 개발 빌드에서는 읽기 전용
리스트의 드롭을 라이브러리에 맡기면 경고합니다.

### 먼저 서버에 저장하기 {#saving-to-a-server-first}

```ts
onBeforeDrop: async (e) => {
  e.preventDefault();
  try {
    await api.move(e.keys, e.to);
    store.apply(e.result);
  } catch {
    // Nothing applied: the items fly back.
  }
  return 'accept';
},
```

Promise가 resolve되기 전에 `e.result`를 적용하면 오버레이가 새 순서대로 안착합니다. 요청이 실패하면
아무것도 적용하지 마세요. 드롭은 완료되지만 아무것도 바뀌지 않고, 항목은 원래 자리로 돌아갑니다.

## 모든 대상 바깥에 드롭하기 {#dropping-outside-every-target}

```ts
makeSortableList(listRef, { items: tasks, dropOutside: 'remove' });
```

| `dropOutside` | 모든 대상 바깥에 드롭하면… |
| --- | --- |
| `'placeholder'` | 플레이스홀더가 있는 곳, 즉 리스트가 마지막으로 보여 준 자리에 안착합니다. 기본값입니다. |
| `'cancel'` | 취소됩니다. 항목은 원래 자리로 돌아갑니다. `placeholder: 'indicator'`일 때의 기본값입니다. |
| `'remove'` | 항목을 리스트에서 제거합니다. 먼저 리스트의 `onBeforeDrop`에 묻고, `onDrop`은 `to.index`로 `-1`을 받습니다. |

휴지통 영역은 같은 일을 의도적으로 합니다:
`makeDroppable(trash, { onDrop: (e) => e.source?.remove() })`.
[드래그 앤 드롭](/docs/guides/drag-and-drop)을 참고하세요.
