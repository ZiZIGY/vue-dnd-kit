축, 그리드, 경계를 바꾼 다음 메모를 드래그해 보세요. 보드는 보드에서 시작하는 모든 드래그의 규칙을
정하고, 메모는 각자 놓은 자리에 그대로 남습니다.

::example{name="constraints" hint="규칙을 바꾼 뒤 메모를 드래그하세요" height="26rem"}
::

## 축 고정 {#lock-an-axis}

```ts
makeSortableList(listRef, { items: tracks, axis: 'y' });
```

`axis: 'x'`는 가로로만, `'y'`는 세로로만 움직입니다. `makeDraggable`, `makeSortableList`,
`makeSortableTree`, `makeSortableItem`, `makeDragArea` 모두 이 옵션을 받습니다.

- 고정은 **모든 모디파이어 다음에** 적용되므로, 모디파이어가 무엇을 하든 유지됩니다. 스냅이나
  경계가 항목을 선 밖으로 밀어낼 수 없습니다.
- 항목 자체의 `axis`가 리스트나 트리의 `axis`보다 우선하고, draggable(또는 그 리스트)의 `axis`가
  드래그 영역의 `axis`보다 우선합니다.
- 드래그가 시작될 때 읽으므로 getter로 켜고 끌 수 있습니다:
  `axis: () => (locked.value ? 'y' : undefined)`.
- `'y'`로 고정한 트리도 여전히 중첩됩니다. 이때 깊이는 행 가운데에 머무르는 것으로 정해집니다.

::tip
`restrictToVerticalAxis`와 `restrictToHorizontalAxis` 모디파이어보다 `axis`를 권장합니다. 하는 일은
같지만, 일반 모디파이어라서 체인 중간에 실행됩니다. 그래서 그 뒤의 모디파이어(두 축 모두 스냅하는
그리드)가 항목을 다시 축 밖으로 옮길 수 있습니다.
::

## 모디파이어 {#modifiers}

모디파이어는 매 프레임 드래그의 오프셋을 조정합니다. 그 결과가 오버레이를 움직이고 **동시에** 대상을
찾는 지점이 되므로, 리스트는 고정되거나 경계 안에 있거나 스냅된 위치를 기준으로 정렬합니다.

```ts
import { restrictToElement, restrictToParent, snapToGrid } from '@vue-dnd-kit/core';

makeSortableList(listRef, { items, modifiers: [restrictToParent] });
makeDraggable(el, { modifiers: [restrictToElement(boardRef)] });
makeDraggable(el, { modifiers: [snapToGrid({ x: 32, y: 32, smooth: true })] });
```

| 모디파이어 | 하는 일 |
| --- | --- |
| `restrictToVerticalAxis` | 세로로만 움직입니다. `axis: 'y'`를 권장합니다. |
| `restrictToHorizontalAxis` | 가로로만 움직입니다. `axis: 'x'`를 권장합니다. |
| `restrictToWindowEdges` | 오버레이를 창 안에 둡니다. |
| `restrictToParent` | 오버레이를 드래그가 시작된 컨테이너 안에 둡니다. 정렬 가능한 리스트, 또는 일반 draggable의 부모 요소입니다. |
| `restrictToElement(target)` | 오버레이를 요소 안에 둡니다. 템플릿 ref, getter, 또는 요소 자체를 받습니다. |
| `restrictToFirstScrollableAncestor` | 오버레이를 드래그 중인 요소의 첫 번째 스크롤 가능한 조상 안에 둡니다. |
| `snapToGrid(size)` | 오버레이를 그리드에 스냅합니다(아래 참고). |
| `snapCenterToCursor` | 집은 위치의 오프셋을 유지하는 대신 오버레이를 포인터 중앙에 맞춥니다. |

`modifiers`는 프로바이더, 드래그 영역, 리스트와 트리, draggable과 정렬 가능한 항목의 옵션입니다.
프로바이더를 제외한 모든 곳에서 ref나 getter도 받으며, 드래그가 시작될 때 읽습니다.

### 그리드에 스냅 {#snap-to-a-grid}

`snapToGrid(24)`는 두 축을 24 px 셀에 스냅합니다. 객체를 넘기면 더 많이 설정할 수 있습니다:

```ts
snapToGrid({ x: 40, y: 24, origin: 'container', smooth: { duration: 120 } });
```

| 옵션 | 의미 |
| --- | --- |
| `x`, `y` | 축별 셀 크기(픽셀). |
| `origin` | `'container'`(기본값): 오버레이의 왼쪽 위 모서리가 컨테이너(정렬 가능한 리스트, 또는 일반 draggable의 부모)의 왼쪽 위 모서리에서 시작하는 그리드 선에 안착합니다. `'delta'`: 오프셋 자체를 반올림하므로, 그리드에서 벗어난 위치에서 시작한 항목은 계속 그리드 밖에 있습니다. |
| `smooth` | `true` 또는 `{ duration, easing }`: 오버레이가 셀 사이를 부드럽게 이동합니다(기본 80 ms). 대상은 스냅된 위치를 즉시 사용합니다. |

### 직접 만드는 모디파이어 {#your-own-modifier}

```ts
import type { Modifier } from '@vue-dnd-kit/core';

/** Lets the item travel at most 160px from where it was picked up. */
const leash: Modifier = ({ transform }) => {
  const length = Math.hypot(transform.x, transform.y);
  const scale = length > 160 ? 160 / length : 1;
  return { x: transform.x * scale, y: transform.y * scale };
};
```

모디파이어는 앞선 모디파이어가 남긴 드래그 시작점 기준의 오프셋인 `transform`을 받아 새 오프셋을
반환합니다. 계산에 필요할 수 있는 값도 함께 받습니다. `activeRect`(시작 시점의 드래그 중인 요소),
`overlayRect`(`transform`만큼 이동한 오버레이), `containerRect`, `windowRect`, `origin`(시작
시점의 포인터), `active`, `over`입니다. [모디파이어](/docs/api/modifiers)를 참고하세요.

## 순서 {#the-order}

여러 곳의 모디파이어는 차례로 실행되며, 각각 앞 단계의 결과에서 시작합니다:

1. 프로바이더의 `modifiers`
2. 드래그가 시작된 드래그 영역의 `modifiers`
3. 드래그 중인 항목 자체의 `modifiers`, 없으면 그 리스트나 트리의 `modifiers`
4. 드래그 영역의 `restrictToArea`
5. `axis` 고정

항목의 `modifiers`는 리스트의 것을 **대체**하며, 더해지지 않습니다. 영역의 경계는 1–3단계의 스냅
다음에 오므로 스냅된 항목도 영역 안에 머물고, 축 고정은 맨 마지막에 옵니다.

## 경계가 있는 리스트도 양 끝에 닿습니다 {#bounded-lists-keep-their-ends}

```ts
// The tracks move on one axis and stay inside their list.
const { items } = makeSortableList(list, { items: tracks, axis: 'y', modifiers: [restrictToParent] });
```

경계는 포인터가 계속 움직여도 오버레이를 박스 가장자리에 붙잡아 둡니다. 포인터가 리스트 축 방향으로
오버레이를 벗어나면 리스트는 대신 포인터를 기준으로 정렬하므로, 항목을 어떻게 잡든 첫 자리와 마지막
자리에 닿을 수 있습니다. 그리드는 계속 오버레이를 기준으로 정렬합니다. 가장자리에 붙잡힌 오버레이가
이미 가장자리 셀을 덮고 있기 때문입니다.

## 페이지 일부에 적용하는 규칙 {#rules-for-a-part-of-the-page}

```vue [Board.vue]
<script setup lang="ts">
import { useTemplateRef } from 'vue';
import { makeDragArea, snapToGrid } from '@vue-dnd-kit/core';

const props = defineProps<{ readonly: boolean }>();
const board = useTemplateRef<HTMLElement>('board');
const { isDragging } = makeDragArea(board, {
  modifiers: [snapToGrid(24)],
  restrictToArea: true,
  autoScroll: { maxSpeed: 15 },
  activation: { touch: { delay: 400 } },
  disabled: () => props.readonly,
});
</script>

<template>
  <div ref="board" class="board" :class="{ busy: isDragging }">
    <slot />
  </div>
</template>
```

`makeDragArea`는 자기 요소 **안에서 시작하는** 드래그의 규칙을 정합니다. 일반 draggable과 정렬
가능한 항목 모두에 적용됩니다. `DnDProvider`는 앱 전체에 하나만 두고, 보드, 캔버스, 피드에는 각각
영역을 주세요.

| 옵션 | 하는 일 |
| --- | --- |
| `axis` | 드래그를 한 축에 고정합니다. draggable 자체의 `axis`나 그 리스트의 `axis`가 우선합니다. |
| `modifiers` | 프로바이더의 모디파이어 다음, draggable 자체의 모디파이어 전에 실행됩니다. |
| `restrictToArea` | `true`: 드래그가 영역 요소 안에 머뭅니다. |
| `autoScroll` | 영역의 스크롤 컨테이너(요소 자체, 또는 가장 가까운 스크롤 가능한 조상)의 자동 스크롤. `false`면 그곳에서 끕니다. |
| `activation` | 포인터 종류별 [활성화](/docs/guides/sensors#activation-constraints). draggable 자체의 설정이 우선하고, 프로바이더의 설정이 마지막입니다. |
| `disabled` | 영역 안에서, 그리고 그 안의 영역에서도 드래그가 시작되지 않습니다. 영역의 draggable은 `aria-disabled`를 알립니다. |

모든 옵션은 값, ref, getter를 받으며, 누르기나 드래그가 시작될 때 읽습니다. 영역은 `isDragging`(여기서
시작한 드래그가 진행 중)과 `isAutoScrolling`(자동 스크롤이 영역의 컨테이너를 움직이는 중)을
반환합니다. 전체 레퍼런스: [makeDragArea](/docs/api/make-drag-area).

### 영역이 결합되는 방식 {#how-areas-combine}

- 드래그는 자신이 **시작된** 영역을 따르며, 그 영역을 벗어난 뒤에도 마찬가지입니다. 다른 영역 위를
  지나가도 아무것도 바뀌지 않지만, `autoScroll`만은 예외입니다. 그 컨테이너를 스크롤하는 모든
  드래그에 적용됩니다.
- 중첩된 영역은 합쳐지지 않으며, 가장 가까운 영역이 우선합니다. 예외는 `disabled`로, 상속됩니다.
  꺼진 영역은 그 안의 영역도 끕니다.
- 충돌 감지, 키보드 키, 안내 문구는 프로바이더 전체에 적용됩니다.

::note
보드를 두 번째 `DnDProvider`로 감싸면 안 되는 이유가 있을까요? 프로바이더끼리는 독립적이라, 드래그가
한 프로바이더에서 다른 프로바이더로 넘어가지 않습니다. 그러면 보드의 항목은 보드를 벗어날 수
없습니다. 페이지 일부에 프로바이더 전체 설정이 따로 필요하고 그 항목이 그 안에만 머물 때만
프로바이더를 중첩하세요. [프로바이더](/docs/guides/provider)를 참고하세요.
::

## 놓은 자리에 그대로 두기 {#leave-it-where-its-dropped}

예제의 보드는 드롭 대상이기도 하며, 각 메모는 놓은 자리를 유지합니다. 모든 드래그 이벤트에는
`position`이 들어 있습니다. 대상 안에서 드래그 중인 박스의 왼쪽 위 모서리로, 대상의 패딩
가장자리부터 측정하고 스크롤 값을 포함합니다. 절대 위치로 배치한 항목을 바로 그 자리에 놓는 `left`와
`top` 값입니다. 모디파이어 다음에 계산되므로, 스냅된 메모는 그리드 위에 안착합니다.

```ts
makeDroppable(board, { id: 'board' });
useDnDMonitor({
  onDragEnd({ active, over, position }) {
    const note = notes.value.find((item) => item.id === active.id);
    if (!note || over?.id !== 'board' || !position) return;
    note.x = Math.round(position.x);
    note.y = Math.round(position.y);
  },
});
```

자유로운 드래그와 드롭 대상에 대한 자세한 내용은 [드래그 앤 드롭](/docs/guides/drag-and-drop)을
참고하세요.
