라이브러리는 거의 아무것도 스타일링하지 않습니다. 드래그의 각 상태는 두 가지 방법으로 전달됩니다.
클래스와 조건부 마크업을 위해서는 컴포저블이 반환하는 ref로, 일반 CSS를 위해서는 `data-dnd-*`
속성으로 전달됩니다.

```vue [TaskRow.vue]
<script setup lang="ts">
const props = defineProps<{ task: Task }>();
const el = useTemplateRef<HTMLElement>('el');
const { isPlaceholder, selected } = makeSortableItem(el, { item: () => props.task });
</script>

<template>
  <li ref="el" class="row" :class="{ hole: isPlaceholder, selected }">{{ task.title }}</li>
</template>
```

## 반환되는 ref {#the-returned-refs}

| 컴포저블 | 상태 |
| --- | --- |
| `makeSortableItem` | `isDragging`, `isPlaceholder`, `selected`, `indicator`, `index` |
| `makeSortableList`, `makeSortableTree` | `isOver`, `isAccepting`, `indicator`, `activeKey` |
| `makeDraggable` | `isDragging`, `selected`, `transform` |
| `makeDroppable` | `isOver`, `isAccepting`, `placement` |
| `makeDragArea` | `isDragging`, `isAutoScrolling` |
| `useDnD()` | `status`, `active`, `over`, `pointer`, `activation.progress` |

- `isPlaceholder`: 이 요소가 드래그 중인 항목이 안착할 자리입니다.
- `isDragging`: 항목이 드래그에 포함되어 있습니다(멀티 드래그에서는 드래그 중인 모든 항목).
- `isAccepting`: 무언가가 드래그되고 있고 이 대상이 그것을 받아들입니다. 드롭할 수 있는 곳을
  강조하세요.
- `isOver`: 대상이 받아들이든 아니든 드래그가 이 대상 위에 있습니다. `isOver && !isAccepting`은
  거부를 뜻하며, 표시해 줄 만합니다.
- `useDnD()`의 `over.accepted`(오버레이 props에서는 `accepted`)는 드래그를 거부하는 대상 위에서
  `false`입니다. 이 값으로 오버레이를 빨갛게 칠하세요.

```vue
<ul ref="list" :class="{ 'can-drop': isAccepting, over: isOver && isAccepting, refused: isOver && !isAccepting }">…</ul>
```

## data 속성 {#the-data-attributes}

| 속성 | 위치 | 시점 |
| --- | --- | --- |
| `data-dnd-placeholder` | 정렬 가능한 항목 | 드래그 중인 항목이 안착할 자리일 때. |
| `data-dnd-dragging` | 정렬 가능한 항목 | 드래그되지만 제자리에 남아 있을 때: `'gaps'` 모드 멀티 드래그의 나머지 항목. |
| `data-dnd-dragging="pointer"` 또는 `"keyboard"` | `<html>` | 드래그하는 동안 내내. |
| `data-dnd-overlay="dragging"` 또는 `"dropping"` | 오버레이 박스 | 항상. 안착하는 동안과 비동기 `onBeforeDrop`이 기다리는 동안에는 `dropping`. |
| `data-dnd-leaving` | `animate`가 남긴 복사본 | 사라진 항목이 서서히 사라지는 동안. |
| `data-dnd-no-clone` | **직접 지정** | 요소를 오버레이의 클론에서 제외합니다: 툴팁, 메뉴 버튼, 배지. |

```css
html[data-dnd-dragging] .drop-hint { display: block; }
html[data-dnd-dragging='keyboard'] .shortcuts { display: block; }
```

## 기본 스타일 {#default-styles}

프로바이더는 문서마다 한 번 몇 가지 규칙을 주입합니다. 규칙은 `:where()`로 감싸져 있어 명시도가
0이므로, 어떤 규칙을 작성해도 그쪽이 우선합니다:

```css
:where([data-dnd-placeholder]) { opacity: 0.4; }
:where([data-dnd-dragging]:not(html)) { opacity: 0.4; }
:where(html[data-dnd-dragging], html[data-dnd-dragging] *) { user-select: none !important; overflow-anchor: none !important; }
:where(html[data-dnd-dragging='pointer'], html[data-dnd-dragging='pointer'] *) { cursor: grabbing !important; }
```

드래그하는 동안 자리는 흐리게 표시되고, 페이지는 텍스트를 선택하지 않으며 스크롤을 고정(anchor)하지
않습니다. 포인터 드래그 중에는 커서가 움켜쥔 손 모양이 됩니다. `:default-styles="false"`로 끌 수
있습니다. 드래그할 수 있는 항목의 `cursor: grab`은 직접 추가하세요.

## 레시피 {#recipes}

### 빈 자리 {#an-empty-slot}

항목의 흐린 복사본 대신, 항목이 안착할 곳에 점선으로 된 빈 박스를 보여 줍니다:

```css
.card {
  position: relative;
}

.card[data-dnd-placeholder] {
  opacity: 1;
}

.card[data-dnd-placeholder]::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 1.5px dashed color-mix(in srgb, currentColor 30%, transparent);
  border-radius: inherit;
  background: Canvas;
}
```

가상 요소가 콘텐츠를 덮으므로 자리는 항목의 크기를 정확히 유지합니다. 여기서 카드를 드래그해
확인해 보세요:

::example{name="kanban" hint="드래그 중인 카드의 자리는 점선 박스입니다" height="24rem"}
::

### 리스트가 칠하는 행 {#a-row-the-list-paints}

기본 오버레이는 드래그 중인 요소의 클론입니다. 요소를 있는 그대로 보여 주며, 배경을 추측하지
않습니다. 자체 배경이 없는 행(흰색 `<ul>` 안의 `<li>`, 표의 행, UI 키트의 리스트 항목)은 투명한
클론이 됩니다. 리스트의 배경을 지정하세요:

```css
[data-dnd-overlay] .row {
  background: var(--surface);
}
```

클론은 요소의 클래스와 속성(scoped 스타일의 속성 포함)을 유지하므로, 이 규칙은 행 자체의
`<style scoped>` 안에서 다른 스타일과 함께 동작합니다. 또는 행에 자체 배경을 주세요. 떠다니도록
만든 아이콘과 타일은 투명하게 둡니다.

### 드래그하는 동안만 떠오르는 오버레이 {#a-lifted-overlay-only-while-dragging}

```css
[data-dnd-overlay='dragging'] .card {
  box-shadow: 0 14px 28px -10px rgb(0 0 0 / 0.45);
}
```

그림자는 카드가 이동하는 동안 보이고, 오버레이가 `dropping`으로 바뀌면 사라지므로 카드는 납작하게
자리에 안착합니다. 커스텀 오버레이 컴포넌트에서는 같은 규칙이 컴포넌트의 루트를 대상으로 하거나,
props의 `status`를 읽으세요.

### 동작 줄이기 {#reduced-motion}

라이브러리는 `prefers-reduced-motion: reduce`이면 이미 자체 애니메이션을 멈춥니다. 드래그 주변에
추가한 트랜지션도 똑같이 처리하세요:

```css
@media (prefers-reduced-motion: reduce) {
  .column {
    transition: none;
  }
}
```

### 하지 말아야 할 것 {#dont}

- 정렬 가능한 항목의 `transform`이나 `translate`에 CSS `transition`을 걸지 마세요. 라이브러리가
  직접 애니메이션하며, 측정하는 동안 그런 트랜지션을 취소합니다.
- [가상 리스트](/docs/guides/virtual-lists)에서 행의 `height`, `margin`, `padding`을 애니메이션하지
  마세요.

오버레이(커스텀 컴포넌트, 크기, `DragPreview`)에 대한 자세한 내용은 [오버레이](/docs/guides/overlay)를
참고하세요.
